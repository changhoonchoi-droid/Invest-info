사용 조건과 채널 정하기

Claude Tag

Claude Tag는 Team·Enterprise 계정에서 쓰는 팀 채널용 Claude입니다. 처음에는 공개 채널 한 곳에서 작게 시작합니다.

따라 하기

  1. 회사가 Claude Team 또는 Enterprise 요금제를 쓰고 있는지 확인합니다(베타 제공).
  2. 처음 써 볼 공개 채널 하나를 고릅니다.
  3. 관리자가 그 채널에 Claude를 추가합니다.
  4. 필요한 도구(Google Drive, Asana 등)를 연결합니다.
  5. 참고해야 할 다른 공개 채널이 있으면 접근 권한을 줍니다.
  • DM과 비공개 채널 내용은 그 안에만 남고, 접근 권한은 공개 채널에만 줄 수 있습니다.
  • Microsoft Teams 등으로 넓힐 계획이 발표됐습니다.

채널에서 Claude 역할 정하기

Claude Tag

Claude는 채널별 지침을 기억합니다. 처음에 채널 성격에 맞게 역할을 분명히 정해 두면 매번 설명하지 않아도 됩니다.

따라 하기

  1. 이 채널에서 Claude가 맡을 일을 정합니다.
  2. 대화에 얼마나 자주 끼어들지 정합니다.
  3. 묻지 않고 스스로 처리해도 되는 범위를 정합니다.
  4. 반복할 지침은 Remember for this channel: ... 형태로 말해 저장시킵니다.
  5. 스타일 가이드나 체크리스트 문서가 있으면 참고하라고 알려 줍니다.
예시 프롬프트
@Claude Remember for this channel: 이 채널은 영업팀 주간 보고 채널이야. 요청이 오면 표로 정리하고, 고객사에 연락하거나 문서를 고치기 전에는 꼭 먼저 물어봐.
  • 알려 준 문서가 바뀌면 기본적으로 최신 내용을 따릅니다.

스레드에서 태그해 일 맡기기

Claude Tag

채팅 창을 오가며 맥락을 복사할 필요 없이, 작업이 필요한 스레드에서 바로 Claude를 태그합니다. 며칠 걸리는 일도 후속 확인까지 이어서 합니다.

따라 하기

  1. 작업이 필요한 스레드에서 Claude를 태그하고 맡길 일을 적습니다.
  2. 작업 하나하나보다 이루고 싶은 목표를 맡깁니다.
  3. 기다리지 말고 다른 일을 합니다.
  4. 같은 스레드에서 다른 팀원도 이어서 추가 지시를 하게 합니다.
  5. 매번 태그하기 번거로우면 이 채널에서는 항상 응답하라고 지시합니다.
예시 프롬프트
@Claude 최근 3일 스레드, Google Drive 회의록, Asana 열린 작업을 확인해서 이번 주 미결 액션 아이템 목록을 만들어 줘.
  • Claude Code 팀원 한 명은 작업의 70~80%를 Tag로 하고 나머지만 직접 다듬는다고 합니다.
  • Slack처럼 공개된 곳에서 지시하면 잘 쓰는 사람의 지시 방식이 동료에게 자연스럽게 퍼집니다.

결과와 변경 기록 검토하기

Claude Tag

Claude는 자기 계정으로 일하고 모든 변경과 요청자를 기록합니다. 완료나 결정 요청 알림이 오면 결과를 확인하고, 기록으로 누가 무엇을 시켰는지 추적합니다.

따라 하기

  1. 완료 알림이나 결정 요청 알림이 오면 확인하고 답합니다.
  2. 기록된 변경 내역과 요청자를 확인합니다.
  3. 정리된 내용의 사실관계는 원문과 직접 맞춰 봅니다.
  4. Claude가 나를 대신해 응답하거나 도구에 접근하려고 권한을 물으면, 내용을 읽고 승인할지 정합니다.
  5. 너무 자주 또는 너무 드물게 끼어들면 개입 빈도를 조정해 달라고 말합니다.
  • 사용자를 대신해 응답하거나 개별 도구에 접근할 때는 매번 권한을 묻도록 설계되어 있습니다.

반복 피드백을 스킬로 쌓기

Skills

Claude에게 같은 지적을 반복하고 있다면 그 기준을 스킬로 저장할 때입니다. 쓸수록 Claude가 팀의 기준에 가까워집니다.

따라 하기

  1. Claude에게 반복해서 주는 피드백과 수정 내용을 모읍니다.
  2. 자주 쓰는 기준을 Claude 계정에서 스킬로 만듭니다(예: /brand-guidelines).
  3. 스킬에는 '무엇을 하라'는 목록보다 '어떻게 판단하라'는 원칙을 적습니다.
  4. 스킬을 쓴 결과에 사람이 덧붙인 수정을 기록해 스킬에 다시 반영합니다.
  • Every는 편집장이 과거에 고친 3만 건으로 교정 스킬을 만들고, 사람이 추가로 고친 내용을 추적해 계속 다듬습니다.
  • 만든 스킬은 Word·Excel 패널이나 Cowork에서도 불러 쓸 수 있습니다.

팀 스킬 관리 규칙 정하기

Skills

여러 사람이 스킬을 쓰기 시작하면, 한 사람 환경에 맞춘 스킬이 다른 사람에게 오류를 낼 수 있습니다. 공개하기 전에 관리 규칙을 정해 둡니다.

따라 하기

  1. 첫 스킬을 내놓기 전에 소유자, 검토자, 폐기 방식, 테스트 방식을 정합니다.
  2. 스킬은 그 업무를 실제로 맡은 사람이 만들거나 검토하게 합니다.
  3. 모든 스킬이 보이도록 한곳에 모으고 태그와 평가를 붙입니다.
  4. 스킬 지침을 바꿀 때는 검토를 거쳐 반영합니다.
  • 비용센터 코드가 고정된 경비 스킬처럼 개인 환경에 맞춘 스킬은 다른 사람에게 오류를 낼 수 있습니다.
  • 검증된 스킬과 커뮤니티 스킬을 구분해 표시하면 고르기 쉽습니다.
