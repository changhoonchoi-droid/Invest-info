Claude 앱

따라 하기

  1. 개인정보가 든 열은 지우거나 자리표시자로 바꾼 CSV를 준비합니다.
  2. Claude 채팅에 CSV를 올리고 눈에 띄는 패턴과 볼 만한 지표를 묻습니다.
  3. 대시보드에 넣을 그래프 3~5개와 필터를 고릅니다.
  4. 웹사이트 제작은 코드에서 한다는 점을 확인합니다(Pro 이상).
예시 프롬프트
첨부한 고객 설문 CSV에서 눈에 띄는 응답 패턴 5가지와, 팀원이 한눈에 봐야 할 지표를 대시보드 그래프 후보로 추천해 줘.

코드 탭에서 작업 폴더 열기

Claude Code

개발이 처음이라면 터미널 대신 Claude 데스크톱 앱의 코드 탭으로 시작합니다. 화면에서 폴더를 고르고 결과를 바로 볼 수 있습니다.

따라 하기

  1. Claude 데스크톱 앱에서 코드 탭으로 들어갑니다.
  2. 새 폴더(예: 대시보드)를 만듭니다.
  3. 로컬 옆 버튼을 눌러 폴더 열기로 그 폴더를 지정합니다.
  4. 워크스페이스 신뢰를 진행합니다.
  • 실행한 폴더와 그 아래 모든 폴더에 접근 권한이 생기므로 전용 폴더를 새로 만들어 쓰세요.
  • 익숙해지면 터미널(CLI)로 넘어가도 됩니다.

질문받으며 요구사항 정하기

Claude Code

처음부터 모든 것을 지정하기보다 Claude가 나에게 질문하며 요구사항을 끌어내게 하면 빠진 부분이 줄어듭니다. 스펙을 먼저 검토하고 나서 만들게 합니다.

따라 하기

  1. 누가 쓸 대시보드인지, 꼭 보여 줄 그래프가 무엇인지만 적습니다.
  2. 결과를 과하게 지정하지 말고 ask user question 도구로 질문하라고 적습니다.
  3. Claude가 띄우는 질문에 차례로 답합니다.
  4. Claude가 쓴 스펙을 읽고 고칠 점을 말합니다.
예시 프롬프트
첨부한 설문 CSV로 팀원들이 보는 대시보드를 만들고 싶어. 대상은 개발 지식 없는 우리 팀원들이야. 결과를 미리 정하지 말고 ask user question 도구로 나에게 하나씩 질문해서 요구사항을 끌어낸 뒤, 검토하기 쉬운 HTML 스펙을 작성해 줘.
  • '더 좋게 만들어' 같은 막연한 프롬프트는 피합니다.
  • 예전 방식: 계획 모드로 읽기 전용 분석과 계획을 먼저 받았습니다. 최신 모델은 질문 인터뷰 방식이 권장됩니다.

대시보드 첫 버전 만들기

Claude Code

스펙이 정해지면 첫 버전을 만들게 합니다. 어떻게 만들지는 AI에게 맡기고, 무엇을 보여 줄지에 집중합니다.

따라 하기

  1. 작업에 쓸 CSV 파일을 첨부합니다.
  2. 스펙대로 만들어 달라고 요청하고 필요한 기능을 풀어 씁니다.
  3. 파일 수정 권한 요청이 나오면 내용을 보고 허용합니다.
  4. 오른쪽 내장 브라우저에서 결과를 확인합니다.
  5. 필요하면 기본 브라우저에서 열기로 크롬에서 엽니다.
예시 프롬프트
첨부한 설문 결과 CSV로 팀원 누구나 브라우저에서 볼 수 있는 대시보드 웹사이트를 만들어 줘. 문항별 응답 비율을 그래프로 보여 주고, 연령대별로 걸러 볼 수 있게 해 줘.
  • 모든 단계를 직접 확인하고 싶으면 기본(승인) 모드를 유지합니다.

브라우저에서 보며 고치기

Claude Code

필터를 눌러 보고 그래프를 읽어 보며 고칠 점을 찾습니다. 같은 지적이 반복되면 CLAUDE.md에 규칙으로 남겨 다시 말하지 않게 합니다.

따라 하기

  1. 필터와 그래프를 직접 눌러 보며 이상한 점을 적습니다.
  2. 고칠 점을 구체적으로 하나씩 요청합니다.
  3. 같은 실수가 반복되면 그 규칙을 CLAUDE.md에 저장하라고 요청합니다.
  4. 전혀 다른 기능을 시작할 때는 /clear로 대화를 비웁니다.
예시 프롬프트
그래프 색을 파랑 계열 한 가지로 통일하고, 응답 비율은 소수점 첫째 자리까지 표시해 줘. 이 두 규칙을 CLAUDE.md에도 저장해 줘.
  • 프롬프트를 너무 짧게 쓰면 Claude가 파일을 더 많이 뒤져 오히려 컨텍스트를 더 씁니다.

Claude가 스스로 검증하게 하기

Claude Code

숫자가 원본과 맞는지, 필터가 제대로 동작하는지 매번 직접 확인하기는 번거롭습니다. 확인 기준을 주고 Claude가 앱을 띄워 직접 확인하고 고치게 합니다.

따라 하기

  1. 무엇이 올바른 결과인지 확인 가능한 기준을 적습니다.
  2. Claude Code에 포함된 verify 스킬로 확인해 달라고 요청합니다.
  3. Claude가 서버를 띄우고 페이지를 열어 클릭·스크린샷하는 과정을 지켜봅니다.
  4. 실패하면 고쳐서 다시 확인하게 합니다.
  5. 성공한 확인 절차가 스킬로 저장됐는지 확인합니다.
예시 프롬프트
연령대 필터를 바꿀 때마다 그래프 숫자가 CSV 원본과 같은지 verify 스킬로 서버를 띄워 클릭과 스크린샷으로 확인해 줘. 다르면 고쳐서 다시 확인해 줘.
  • 기준이 측정 가능할수록 Claude가 혼자 더 오래 일할 수 있습니다.
  • 예전 방식: Playwright MCP를 연결해 화면을 확인했습니다.

팀원에게 공유할 방법 정하기

Claude Code

이 단계는 흐름을 잇기 위해 덧붙인 일반 안내입니다. 모니터링 영상에서 직접 다룬 내용은 아닙니다.

완성한 대시보드를 팀원이 열어 보려면 공유 방법을 정해야 합니다. 팀 환경과 보안 규정을 알려 주고 방법을 추천받은 뒤, 규정에 맞는지 확인하고 공유합니다.

따라 하기

  1. 화면과 파일에 개인정보·민감한 숫자가 남아 있지 않은지 확인합니다.
  2. 팀에서 쓸 수 있는 공유 수단을 Claude에게 알려 주고 방법을 추천받습니다.
  3. 추천된 방법이 회사 보안 규정에 맞는지 확인합니다.
  4. 팀원 한 명에게 먼저 열어 보게 하고 되묻는 점을 반영합니다.
예시 프롬프트
이 대시보드를 개발 지식 없는 팀원들이 브라우저에서 열어 볼 수 있게 공유하고 싶어. 우리 팀은 사내 공유 폴더만 쓸 수 있어. 가능한 공유 방법과 각각의 장단점, 보안상 주의할 점을 알려 줘.
  • 외부 서비스에 올리면 누구나 볼 수 있게 될 수 있으니 회사 규정을 먼저 확인하세요.
