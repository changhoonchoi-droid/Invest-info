Claude Code 설치하고 로그인

Claude Code

새 기능이 가장 먼저 나오는 터미널이나, 화면으로 다루는 데스크톱 앱 중 편한 곳에 설치합니다. 작업할 폴더에서 실행해야 그 폴더에만 접근 권한이 생깁니다.

따라 하기

  1. macOS·Linux·WSL은 공식 안내의 curl 설치 명령을, Windows PowerShell은 안내된 Invoke-RestMethod 명령을 실행합니다.
  2. 터미널이 낯설면 Claude 데스크톱 앱의 코드 탭을 써도 됩니다.
  3. 작업할 프로젝트 폴더로 이동해 Claude Code를 실행합니다.
  4. 처음 실행하면 색상 테마를 고릅니다.
  5. Claude 계정(Pro, Max, Enterprise) 또는 API 키로 로그인합니다.
  • Homebrew나 winget으로 설치하면 자동 업데이트가 되지 않습니다.
  • VS Code·JetBrains를 쓴다면 확장 프로그램·플러그인으로도 쓸 수 있습니다.

하네스 한 번에 세팅하기

Claude Code

CLAUDE.md는 짧은 목차(권고), 스킬은 필요할 때 부르는 절차, 훅은 어길 수 없는 규칙입니다. 새 프로젝트 시작 때 틀을 잡아 두면 이후 작업이 안정적입니다.

따라 하기

  1. 앱 목적, 기술 스택, 디자인 시스템 같은 프로젝트 정보를 정리합니다.
  2. CLAUDE.md는 200줄 이내 목차로, 반복 절차는 스킬로, 반드시 지킬 규칙은 훅으로 만들어 달라고 요청합니다.
  3. 생성된 CLAUDE.md, 스킬, 훅을 직접 읽고 고칩니다.
  4. 세션을 재시작합니다.
  5. /를 입력해 만든 스킬이 프로젝트 범위 스킬로 보이는지 확인합니다.
예시 프롬프트
이 프로젝트에 하네스를 세팅해 줘. CLAUDE.md는 200줄 이내 목차로 만들고, 커밋·리뷰·클린업은 스킬로, 비밀 파일 보호와 편집 후 자동 코드 정리는 훅으로 만들어 줘.
  • 회사 업무 폴더라면 권한 요청을 켜 둔 채 진행하는 편이 안전합니다.
  • AI가 만든 CLAUDE.md는 그대로 두지 말고 사람이 꼭 검수합니다.
  • 배포처럼 위험한 작업은 자동 적용 대신 슬래시로 직접 호출하게 두세요.

인터뷰로 스펙 받기

Claude Code

만들 앱을 처음부터 자세히 지정하는 대신 Claude가 질문하며 요구사항을 끌어내게 합니다. 완성된 스펙을 사람이 먼저 검토한 뒤 다음 단계로 넘어갑니다.

따라 하기

  1. Shift+Tab으로 원하는 모드인지 확인합니다.
  2. /effort로 노력 수준을 정합니다(기본 medium으로 대부분 충분).
  3. 관심 영역과 대상 사용자만 주고 결과는 과하게 지정하지 않습니다.
  4. ask user question 도구로 질문하라고 명시합니다.
  5. 질문에 답한 뒤 Claude가 쓴 스펙을 검토합니다.
예시 프롬프트
팀원끼리 회식비를 나눠 계산하는 앱을 만들고 싶어. 대상 사용자는 회사 동료들이야. 결과를 미리 정하지 말고 ask user question 도구로 나에게 하나씩 질문해서 요구사항을 끌어낸 뒤 스펙을 작성해 줘.
  • 스펙은 긴 마크다운 대신 HTML 파일로 받으면 검토가 쉽습니다.
  • 예전 방식: 계획 모드로 읽기 전용 분석을 거쳐 계획을 먼저 받았습니다.

디자인 시안·프로토타입 보기

Claude Design

코드를 짜기 전에 화면 시안을 여러 개 비교하고 클릭해 볼 수 있는 프로토타입으로 확인하면 방향을 싸게 고칠 수 있습니다. 말로 비교하기 어려운 선택도 직접 보고 고릅니다.

따라 하기

  1. Claude Code에서 작업할 저장소를 연결합니다.
  2. Artifacts 탭에서 새 디자인을 만듭니다.
  3. 현재 앱을 살펴보고 시안을 여러 개 만들어 달라고 요청합니다.
  4. 잘된 점과 아쉬운 점을 댓글로 남기고 필요하면 새 시안을 더 요청합니다.
  5. 클릭해 볼 수 있는 프로토타입을 만들어 달라고 해 직접 써 봅니다.
  6. 만족하면 Claude에게 구현을 지시합니다.
예시 프롬프트
지금 앱을 살펴보고 회식비 앱의 첫 화면 온보딩 시안 3가지를 만들어 줘. 시안마다 장단점을 적고, 내가 고른 시안은 클릭해 볼 수 있는 프로토타입으로 만들어 줘.
  • 결정용 시안은 결정한 뒤 버리는 것이니 최고 모델을 쓸 필요가 없습니다.
  • AI가 고른 안에는 어떤 조건이면 다른 안이 낫는지 물어보세요.

권한 정하고 구현 맡기기

Claude Code

권한 모드로 Claude가 파일 수정·명령 실행을 얼마나 자유롭게 할지 정합니다. 성공 기준을 분명히 주고 맡기면 도중에 방향을 바꾸기도 쉽습니다.

따라 하기

  1. Shift+Tab으로 모드를 바꾸고 입력창 아래 표시로 현재 모드를 확인합니다.
  2. 익숙하지 않다면 기본 모드나 Auto accept edits로 시작합니다.
  3. 스펙과 함께 무엇이 완료인지 성공 기준을 적어 구현을 요청합니다.
  4. 여러 파일을 크게 바꾸는 작업이면 /effort를 high로 올립니다.
  5. 작업 도중에도 내용을 더하거나 중단하거나 방향을 바꿉니다.
예시 프롬프트
스펙대로 회식비 앱의 첫 화면과 금액 나누기 기능을 구현해 줘. 완료 기준은 인원 수와 총액을 넣으면 1원 단위까지 나눈 금액이 표시되고, 나머지는 첫 사람에게 더해지는 거야.
  • 권한 확인을 건너뛰면 실수를 미리 잡기 어려우니 신중하게 씁니다.
  • Opus 5.5의 기본 effort는 medium이며 큰 수정에만 high를 씁니다.

verify로 동작 검증하기

Claude Code

테스트 통과만으로는 실제로 의도대로 보이고 동작하는지 알 수 없습니다. verify 스킬로 Claude가 앱을 실행해 확인하고, 실패하면 고쳐 다시 확인하게 합니다.

따라 하기

  1. Claude Code에 포함된 verify 스킬을 처음 사용합니다.
  2. Claude가 앱을 실행하고 변경 사항을 직접 확인하는 과정을 지켜봅니다.
  3. 성공한 확인 절차가 프로젝트 스킬로 저장되는지 확인합니다.
  4. 스킬에 언제 실행할지, 실패하면 무엇을 할지, 항목별 통과 기준을 적습니다.
  5. 다음 변경부터는 Claude가 스스로 확인하고 고치는지 봅니다.
예시 프롬프트
금액 나누기 화면을 바꾼 뒤 verify 스킬로 서버를 띄워 페이지를 열고, 인원 3명·총액 100,000원을 입력해 결과가 맞게 보이는지 클릭과 스크린샷으로 확인해 줘. 실패하면 고쳐서 다시 확인해 줘.
  • 웹은 브라우저, 모바일은 iOS 시뮬레이터로 확인 절차를 만들 수 있습니다.
  • 검증 명령을 사람과 에이전트가 똑같이 실행할 수 있게 해 두세요.

따라 하기

  3. 새 기능을 시작할 때는 /clear로 비웁니다.
  4. 다음 세션에도 필요한 내용은 CLAUDE.md에 적습니다.
  5. 지금 쓰지 않는 MCP 서버는 끕니다.
예시 프롬프트

  • 답만 필요한 조사는 서브에이전트에 맡겨 요약만 받으면 컨텍스트를 아낍니다.
  • 스킬은 MCP와 달리 이름과 설명만 먼저 불러와 공간을 아낍니다.

Claude Code

큰 수정이나 퇴근 전 맡길 일은 클라우드 세션으로 돌리면 노트북을 닫아도 계속 진행됩니다. 휴대폰에서 질문에 답하고, 끝나면 변경 내용을 검토해 PR을 만듭니다.

따라 하기

  1. GitHub 계정을 연결하고 Claude GitHub App에 접근을 허용할 저장소를 고릅니다.
  2. 데스크톱 앱에서 Local 대신 Cloud를 선택합니다.
  3. 저장소, 환경, 시작할 브랜치를 고르고 작업을 맡깁니다.
  4. 휴대폰 Claude 앱의 Code 탭에서 질문에 답하거나 방향을 조정합니다.
  5. 변경 내용(diff)을 검토하고 문제가 없으면 Create PR을 누릅니다.
예시 프롬프트
회식비 앱에 '지난 정산 기록' 화면을 추가해 줘. 기존 금액 나누기 테스트가 모두 통과해야 하고, 끝나면 변경 요약을 남겨 줘.
  • 클라우드 세션은 커밋·푸시한 내용만 씁니다. 개인 설정이 필요한 작업은 로컬에서 돌리세요.
  • 내 컴퓨터를 켜 둔 채 휴대폰으로 이어가려면 원격 제어(claude remote-control)를 씁니다.
