질문받아 스펙 정하기

Claude Code

앱의 모습을 처음부터 다 정하기보다 Claude의 질문에 답하며 요구사항을 끌어냅니다. 'Claude Code로 첫 작업하기'를 해 본 뒤 시작하면 수월합니다.

따라 하기

  1. 프로젝트 폴더에서 Claude Code를 열고 Shift+Tab으로 auto mode로 바꿉니다.
  2. /effort로 노력 수준을 정합니다.
  3. 프롬프트에는 대상 사용자 같은 관심 영역만 적고, ask user question 도구로 질문해 달라고 명시합니다.
  4. Claude가 띄우는 질문에 차례로 답합니다.
  5. 스펙을 정보가 촘촘한 HTML 파일로 받아 먼저 검토합니다.
  6. 스펙을 빠르게 여러 번 고칠 때는 /fast 모드를 씁니다.
예시 프롬프트
사회초년생을 위한 가계부 앱을 만들고 싶어. ask user question 도구로 나에게 질문해 가며 요구사항을 정리하고, 다 끝나면 스펙을 작성해 줘.
  • '더 좋게 만들어' 같은 막연한 프롬프트는 피합니다.
  • auto mode는 기본적으로 작업 폴더와 git 리모트만 내부로 봅니다. 회사 환경이라면 관리자가 정한 설정을 먼저 확인하세요.
  • 예전 방식: 계획 모드를 먼저 썼지만, 최신 모델에서는 계획 모드 대신 auto mode를 쓴다고 합니다.

디자인 시안 여러 개 받기

Claude Design

코드로 바로 들어가기 전에 짧게 디자인을 탐색하면 결과가 나아집니다. 일상 언어로 원하는 느낌을 설명하면 여러 시안이 나오고, 댓글로 고칩니다.

따라 하기

  1. Claude Code를 열고 작업할 저장소(repo)를 연결합니다.
  2. Artifacts 탭으로 이동해 새 디자인을 만듭니다.
  3. 스펙을 바탕으로 주요 화면 시안을 여러 개 만들어 달라고 요청합니다.
  4. 결과가 나오면 잘 된 점과 아쉬운 점을 댓글로 남깁니다.
  5. 마음에 들지 않는 세부 사항은 에디터에서 직접 고치고, 필요하면 새 시안을 더 요청합니다.
예시 프롬프트
스펙 파일을 읽고 이 가계부 앱의 첫 화면과 지출 입력 화면 시안을 서로 다른 느낌으로 세 가지씩 만들어 줘.
  • 디자인 용어를 몰라도 원하는 느낌을 그대로 적으면 됩니다.
  • Claude가 작업하는 동안 다른 일을 하다 돌아와 결과를 확인해도 됩니다.

따라 하기

필요한 도구 MCP로 연결하기

Claude Code

MCP는 Claude Code를 외부 도구·데이터와 연결하는 표준입니다. 구현 중 쓸 라이브러리 문서나 브라우저 확인 도구처럼 꼭 필요한 서버만 연결해 둡니다.

따라 하기

  1. 연결할 서비스가 원격 서비스면 HTTP, 내 PC에서 도는 프로그램이면 STDIO 유형을 고릅니다.
  2. 터미널에서 claude mcp add 명령으로 서버를 추가합니다.
  3. Claude Code 세션에서 /mcp를 실행해 연결 상태를 확인합니다.
  4. 당장 쓰지 않는 서버는 /mcp에서 비활성화합니다.
  5. 팀과 공유하려면 프로젝트 범위로 추가해 .mcp.json을 버전 관리에 올립니다.
예시 프롬프트
/mcp
  • Context7 MCP 서버를 쓰면 사용 중인 라이브러리의 최신 문서를 받아 볼 수 있습니다.
  • 서버는 쓰지 않을 때도 도구 정의가 컨텍스트를 차지합니다.
  • GitHub의 gh처럼 CLI가 있으면 컨텍스트 효율이 더 좋습니다.

프로토타입대로 구현시키기

Claude Code

프로토타입에 만족하면 Claude에게 구현을 맡깁니다. 시작 전에 계획과 성공 기준을 받아 두면 이후 검증 단계의 기준이 됩니다.

따라 하기

  1. 프로토타입에 만족하면 Claude에게 구현(build)을 지시합니다.
  2. 구현 전에 만들 파일, 순서, 성공 기준이 담긴 계획을 먼저 보여 달라고 합니다.
  3. 계획을 검토해 고칠 점을 말하고 승인합니다.
  4. 여러 파일·프로젝트 전체를 바꾸는 큰 수정이면 /effort를 high로 올립니다.
  5. 진행 중에는 /context로 여유를 확인하고, 다른 기능으로 넘어갈 때는 /clear로 비웁니다.
예시 프롬프트
확정한 프로토타입대로 앱을 구현해 줘. 시작 전에 만들 파일, 작업 순서, 성공 기준을 계획으로 먼저 보여 줘.
  • Opus 5.5의 기본 effort는 medium이며 대부분 충분합니다.
  • 답만 필요한 조사는 서브에이전트에 맡기면 본 대화가 가벼워집니다.

브라우저로 검증 루프 돌리기

Claude Code

웹 앱은 테스트만으로 확인되지 않는 화면 동작이 많습니다. Claude가 브라우저를 직접 열어 클릭하고 확인하게 하고, 그 절차를 스킬로 저장해 매번 같은 기준으로 검증합니다.

따라 하기

  1. Claude Code에 포함된 verify 스킬로 프로젝트의 확인 절차 스킬을 만듭니다.
  2. 만들어진 스킬에 브라우저 클릭, 콘솔 확인, 성능 측정 같은 확인 항목을 더합니다.
  3. 스킬에 언제 실행할지, 실패하면 무엇을 할지, 항목별 통과 기준을 적습니다.
  4. 브라우저 확인 도구(예: Playwright MCP)를 쓰도록 지정하고 기능을 요청합니다.
  5. 파일 변경 권한 요청이 나오면 검토 후 허용합니다.
  6. Claude가 변경과 검증을 반복한 뒤 내놓는 요약으로 결과를 검토합니다.
예시 프롬프트
verify 스킬로 앱을 직접 실행해서 지출 입력부터 월별 합계 확인까지 브라우저에서 눌러 보고, 실패하면 고친 뒤 다시 확인해 줘. 이 확인 절차를 프로젝트 스킬로 저장해 줘.
  • 구현 전에 현재 화면을 먼저 확인시키면 기준이 정확해집니다.
  • 예전 방식: 매번 프롬프트에 Playwright MCP를 쓰라고 적었지만, 지금은 확인 절차를 스킬로 저장해 반복해서 씁니다.

Hook으로 안전장치 걸기

Claude Code

CLAUDE.md의 지시는 가끔 빠지지만 Hook은 정해 둔 시점마다 예외 없이 실행됩니다. 파일을 고칠 때마다 서식을 맞추고, 위험한 명령은 실행 전에 막아 둡니다.

따라 하기

  1. Claude Code에서 /hooks를 실행하거나 settings.json을 엽니다.
  2. PostToolUse 이벤트에 matcher를 Edit 또는 MultiEdit로 정해, 파일을 고칠 때마다 프로젝트의 포매터(예: Prettier)가 돌게 합니다.
  3. PreToolUse 이벤트로 rm -rf가 들어간 명령이나 main 브랜치 직접 커밋을 검사하는 Hook을 만듭니다.
  4. 막아야 하면 종료 코드 2로 끝내고 stderr에 이유를 적게, 허용하면 0으로 끝내게 합니다.
  5. 일부러 막아야 할 명령을 요청해 차단되는지 확인합니다.
  6. .claude/settings.json에 넣어 커밋하면 팀원에게도 같은 Hook이 적용됩니다.
예시 프롬프트
파일을 고칠 때마다 Prettier가 자동으로 돌고, rm -rf가 들어간 명령은 이유와 함께 막는 Hook을 .claude/settings.json에 만들어 줘. 만든 뒤 차단이 되는지 시험해 줘.
  • stderr에 적은 이유가 Claude에게 전달되어 다른 방법을 찾게 됩니다.
  • 자동 모드를 쓰더라도 꼭 막을 것은 deny 규칙과 Hook으로 분명히 정해 두세요.

클라우드 세션에 맡기기

Claude Code

기능 추가처럼 시간이 걸리는 작업은 클라우드 세션에 맡겨 퇴근 전에 걸어 둘 수 있습니다. GitHub 저장소를 복제해 별도 브랜치에서 일하므로, 휴대폰으로 질문에 답하고 PR로 받아 검토합니다.

따라 하기

  1. GitHub 계정을 연결하고 Claude GitHub App을 설치해 접근할 저장소를 고릅니다.
  2. 데스크톱 앱에서 Local 대신 Cloud를 선택합니다.
  3. 저장소, 환경, 시작할 브랜치를 고르고 작업을 맡깁니다.
  4. 노트북을 닫고, 휴대폰 Claude 앱의 Code 탭에서 질문에 답하거나 방향을 조정합니다.
  5. 변경 내용(diff)을 검토하고 필요하면 코멘트를 남깁니다.
  6. 문제가 없으면 Create PR을 눌러 GitHub에 풀 리퀘스트를 엽니다.
  • 세션은 저장소를 새로 복제해 시작하므로 커밋·푸시한 내용만 씁니다. 개인 설정·스킬·플러그인이 필요한 작업은 로컬에서 하세요.
  • 사용량은 로컬 세션과 함께 플랜 한도에 합산되며 가상 머신 비용은 따로 없습니다.
  • Remote Control은 내 컴퓨터가 켜져 있어야 하지만, 클라우드 세션은 꺼져 있어도 됩니다.
