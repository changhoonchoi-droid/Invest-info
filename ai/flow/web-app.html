질문받으며 화면 스펙 정하기

Claude Code

누가 쓰는지와 해결할 불편만 알려 주고 Claude의 질문에 답해 스펙을 만듭니다. 결과를 과하게 정하지 않을수록 최신 모델이 더 좋은 제안을 합니다.

따라 하기

  1. Claude Code에서 Shift + Tab으로 auto mode로 전환합니다.
  2. 대상 사용자와 해결할 불편만 적고, ask user question 도구로 나에게 질문하라고 명시합니다.
  3. 질문에 차례로 답합니다.
  4. 스펙을 HTML 파일로 받아 화면 목록과 기능을 검토합니다.
예시 프롬프트
우리 팀 행사 참석 신청을 받는 웹페이지를 만들고 싶어. 사용자는 휴대폰으로 접속하는 사내 직원들이야. 결과를 미리 정하지 않을 테니 ask user question 도구로 나에게 질문하면서 요구사항을 정리하고, 스펙을 한눈에 볼 수 있는 HTML 파일로 만들어 줘.
  • 스펙을 빠르게 여러 번 고칠 때는 /fast 모드가 유용합니다.

Claude 디자인으로 시안 고르기

Claude Design

코드를 짜기 전에 여러 화면 시안을 탐색하면 결과물 품질이 올라갑니다. 잘된 점과 아쉬운 점을 댓글로 남기며 마음에 드는 방향을 고릅니다.

따라 하기

  1. Claude Code를 열고 작업할 저장소(repo)를 연결합니다.
  2. Artifacts 탭으로 이동해 새 디자인을 만듭니다.
  3. 스펙을 바탕으로 여러 시안을 만들어 달라고 요청합니다.
  4. 시안마다 잘된 점과 아쉬운 점을 댓글로 남깁니다.
  5. 세부 사항은 에디터에서 직접 고치고, 필요하면 새 시안을 더 요청합니다.
예시 프롬프트
스펙의 행사 신청 화면으로 서로 다른 느낌의 시안 3개를 만들어 줘. 휴대폰 화면 기준이고, 신청 버튼은 첫 화면에서 바로 보여야 해.
  • Claude Design은 일상 언어 설명만으로 만들 수 있고, 문서보다 프로토타입을 먼저 보고 고치는 방식이 잘 맞습니다.
  • Claude가 작업하는 동안 다른 일을 하다 돌아와 확인해도 됩니다.

클릭형 프로토타입 써 보기

Claude Design

고른 시안을 클릭해 볼 수 있는 프로토타입으로 만들어 실제 사용 흐름을 확인합니다. 구현 전에 흐름을 고치는 편이 훨씬 빠르고 쌉니다.

따라 하기

  1. 고른 시안으로 클릭해 볼 수 있는 프로토타입(click-through prototype)을 만들어 달라고 요청합니다.
  2. 신청부터 완료까지 직접 눌러 보며 막히는 곳을 찾습니다.
  3. 고칠 점을 댓글로 남기고 다시 만들게 합니다.
  4. 동료 한두 명에게도 눌러 보게 하고 의견을 모읍니다.
예시 프롬프트
2번 시안으로 클릭해 볼 수 있는 프로토타입을 만들어 줘. 첫 화면 → 신청 양식 → 완료 화면까지 이어지게 해 줘.
  • 작은 사이드 프로젝트의 일부 화면에도 짧은 디자인 탐색을 거치면 결과가 나아집니다.

프로토타입대로 구현하기

Claude Code

프로토타입이 마음에 들면 Claude에게 구현(build)을 지시합니다. 여러 파일에 걸친 작업이므로 effort를 높여 한 번에 제대로 만들게 합니다.

따라 하기

  1. 프로토타입에 만족하면 Claude에게 구현을 지시합니다.
  2. 여러 파일을 만드는 작업이므로 /effort로 high를 설정합니다.
  3. CLAUDE.md에 스택과 실행 명령을 적어 두게 합니다.
  4. 구현이 끝나면 개발 서버를 띄워 직접 열어 봅니다.
예시 프롬프트
프로토타입대로 행사 신청 페이지를 구현해 줘. 끝나면 쓴 기술과 실행 명령을 CLAUDE.md에 적고, 내가 브라우저에서 확인하는 방법을 알려 줘.
  • Opus 5.5의 기본 effort는 medium이라 대부분 충분하지만, 프로젝트 전체를 바꾸는 수정에는 high를 씁니다.

Hook으로 서식 자동 맞추기

Claude Code

CLAUDE.md의 지시는 가끔 빠지지만 Hook은 매번 예외 없이 실행됩니다. 파일을 고칠 때마다 코드 서식을 자동으로 맞추게 해 두면 코드가 깔끔하게 유지됩니다.

따라 하기

  1. /hooks를 입력해 Hook 설정을 시작합니다.
  2. 이벤트로 PostToolUse를 고릅니다.
  3. matcher를 Edit 또는 MultiEdit로 지정합니다.
  4. 고친 파일 확장자에 맞는 포매터(예: TypeScript는 Prettier)를 실행하게 합니다.
  5. 파일 하나를 고쳐 달라고 요청해 서식이 맞춰지는지 확인합니다.
예시 프롬프트
/hooks
  • Hook 설정이 어렵다면 Claude에게 이 프로젝트에 맞는 서식 Hook을 만들어 달라고 요청해도 됩니다.

verify 스킬로 검증 루프 만들기

Claude Code

테스트·린터만으로는 화면이 의도대로 동작하는지 알 수 없습니다. 브라우저에서 눌러 보고 확인하는 절차를 스킬로 만들어 두면 Claude가 직접 확인하고, 실패하면 고쳐서 다시 확인합니다.

따라 하기

  1. Claude Code에 들어 있는 verify 스킬을 처음 사용합니다.
  2. Claude가 앱을 실행하고 변경 사항을 직접 확인하는 과정을 지켜봅니다.
  3. 성공한 확인 절차가 프로젝트에 스킬로 저장되는지 확인합니다.
  4. 스킬에 언제 실행할지, 실패하면 무엇을 할지, 항목별 통과 기준을 적습니다.
  5. 화면 변경을 요청하고 Claude가 서버 실행·클릭·스크린샷 후 실패 시 고쳐 다시 확인하는지 봅니다.
예시 프롬프트
화면을 바꾼 뒤에는 verify 스킬로 앱을 직접 실행해 확인하고, 휴대폰 화면 폭에서 신청 버튼이 첫 화면에 보이는지와 신청 완료 화면까지 이어지는지 통과 기준을 못 맞추면 고쳐서 다시 확인해 줘.
  • 예전 방식: 요청할 때마다 Playwright MCP를 쓰라고 지정했지만, 지금은 확인 절차를 스킬로 저장해 반복해서 씁니다.
  • 통과 기준이 측정 가능할수록 Claude가 혼자 더 멀리 갑니다.

리뷰 후 GitHub에 올리기

Claude Code

검증을 통과하면 서브에이전트 코드 리뷰어로 한 번 더 점검하고 GitHub 저장소에 올립니다. 저장소에 올려 두면 클라우드 세션으로 이어서 작업할 수 있습니다.

따라 하기

  1. 직접 화면을 열어 최종 확인합니다.
  2. 서브에이전트 코드 리뷰어로 변경 내용을 점검하게 합니다.

  4. GitHub 저장소에 푸시합니다.
예시 프롬프트
서브에이전트 코드 리뷰어로 변경 내용을 점검하고, 문제가 없으면 커밋 메시지를 만들어 커밋한 뒤 GitHub에 푸시해 줘.
  • 비밀번호·API 키가 코드에 들어가지 않았는지 푸시 전에 꼭 확인하세요.

웹에 공개하기

Claude Code

이 단계는 흐름을 잇기 위해 덧붙인 일반 안내입니다. 모니터링 영상에서 직접 다룬 내용은 아닙니다.

만든 페이지를 다른 사람이 볼 수 있게 인터넷에 올립니다. 영상은 Google Cloud 배포 사례를 보여 주지만 세부 절차는 자료에 없어, 여기서는 일반적인 순서만 적었습니다.

따라 하기

  1. Claude에게 이 프로젝트에 맞는 배포 방법과 비용을 비교해 달라고 합니다.
  2. 공개 범위(누구나 볼 수 있는지)와 비용을 확인하고 방법을 고릅니다.
  3. Claude가 안내하는 단계를 하나씩 따라 하고, 계정 생성·결제는 직접 합니다.
  4. 공개 주소를 휴대폰과 PC에서 열어 확인합니다.
예시 프롬프트
이 행사 신청 페이지를 사내 직원들이 볼 수 있게 인터넷에 올리고 싶어. 이 프로젝트에 맞는 배포 방법 2~3가지를 비용, 난이도, 공개 범위로 비교하고, 내가 고른 방법을 단계별로 안내해 줘.
  • 개인정보를 받는 페이지라면 회사 보안 정책을 먼저 확인하세요.

클라우드 세션으로 개선 맡기기

Claude Code

클라우드 세션은 GitHub 저장소를 복제해 별도 브랜치에서 작업하므로 노트북을 닫아도 계속됩니다. 퇴근 전에 개선 작업을 맡기고 휴대폰으로 확인한 뒤 PR로 받습니다.

따라 하기

  1. GitHub 계정을 연결하고 Claude GitHub App을 설치해 저장소 접근을 허용합니다.
  2. 데스크톱 앱에서 Local 대신 Cloud를 선택합니다.
  3. 저장소, 환경, 시작할 브랜치를 고르고 작업을 맡깁니다.
  4. 휴대폰 Claude 앱의 Code 탭에서 질문에 답하거나 방향을 조정합니다.
  5. 변경 내용(diff)을 검토하고 문제가 없으면 Create PR을 누릅니다.
예시 프롬프트
행사 신청 페이지에 '신청 마감' 안내 배너를 추가해 줘. 마감일은 설정 파일에서 바꿀 수 있게 하고, 휴대폰 화면에서 신청 버튼을 가리지 않게 해 줘.
  • 세션은 저장소를 새로 복제해 시작하므로 커밋·푸시한 내용만 씁니다. 개인 스킬이 필요한 작업은 로컬에서 돌리세요.
  • 가상 머신 비용은 따로 없고 플랜 한도에 합산됩니다.
