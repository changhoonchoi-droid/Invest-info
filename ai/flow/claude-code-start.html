Claude Code 설치하기

Claude Code

새 기능이 가장 먼저 나오는 곳은 터미널이지만, 터미널이 낯설면 Claude Desktop이나 VS Code에서도 쓸 수 있습니다. 설치 후 업무용 프로젝트 폴더에서 실행하고 로그인합니다.

따라 하기

  1. Windows PowerShell에서는 공식 안내의 Invoke-RestMethod 설치 명령을, macOS에서는 공식 안내의 curl 명령을 실행합니다.
  2. 터미널이 낯설면 Claude Desktop 상단의 Code 토글로 전환하거나, VS Code 확장 패널에서 Claude Code를 검색해 설치합니다.
  3. VS Code 확장은 Anthropic이 만든 파란 체크 표시 확장인지 확인합니다.
  4. 첫 프로젝트용 폴더를 만들고 그 폴더에서 Claude Code를 실행합니다.
  5. 색상 테마를 고르고 Claude 계정(Pro, Max, Enterprise) 또는 API 키로 로그인합니다.
  • 실행한 폴더와 하위 폴더 전체에 접근 권한이 생기므로 업무와 상관없는 상위 폴더에서 실행하지 않습니다.
  • Homebrew나 winget으로 설치하면 자동 업데이트가 되지 않습니다.

권한 모드 익히기

Claude Code

권한 모드는 Claude가 파일을 고치거나 명령을 실행하기 전에 얼마나 허락을 받을지 정합니다. 처음에는 매번 묻는 기본 모드로 무엇을 하는지 지켜보고, 익숙해지면 auto mode로 맡깁니다.

따라 하기

  1. 기본 상태에서는 파일 수정·명령 실행 전마다 허락을 묻는다는 점을 확인합니다.
  2. Shift+Tab을 눌러 모드를 차례로 바꾸고 입력창 아래 표시로 지금 모드를 확인합니다.
  3. Auto accept edits는 파일 수정만 자동 승인하고 명령 실행은 여전히 묻습니다.
  4. 익숙해지면 Shift+Tab으로 auto mode로 전환합니다.
  5. 허락을 묻는 명령이 나오면 내용을 읽고 승인합니다.
  • auto mode는 다른 모델이 요청의 안전성을 확인해 위험한 명령만 거부합니다.
  • 작업 도중에도 정보를 더하거나 중단하고 방향을 바꿀 수 있습니다.

인터뷰로 스펙 정하기

Claude Code

만들 것이 막연할 때는 요구사항을 다 적으려 하지 말고 Claude가 질문하게 합니다. 관심 영역만 주고 답하다 보면 스펙이 완성되고, 코드가 만들어지기 전에 방향을 바로잡을 수 있습니다.

따라 하기

  1. /effort로 노력 수준을 정합니다(처음에는 medium).
  2. 관심 영역(무엇을, 누가 쓸지)만 적고 결과를 과하게 지정하지 않습니다.
  3. 프롬프트에 ask user question 도구로 질문하라고 명시합니다.
  4. Claude가 띄우는 질문에 차례로 답합니다.
  5. 완성된 스펙을 읽고 빠진 부분을 고쳐 달라고 합니다.
예시 프롬프트
매주 팀 회의록 텍스트 파일을 넣으면 할 일·담당자·마감일을 표로 뽑아 주는 간단한 웹페이지를 만들고 싶어. 쓰는 사람은 우리 팀 8명이야. 바로 만들지 말고 ask user question 도구로 필요한 질문을 하나씩 해서 스펙을 정리해 줘.
  • '더 좋게 만들어', '실수 없이 만들어' 같은 막연한 프롬프트는 피합니다.
  • 예전 방식: 계획 모드로 계획부터 세웠지만, 최신 모델에서는 계획 단계 대신 auto mode에 맡기고 검증에 집중하는 쪽을 권합니다.

첫 버전 구현 맡기기

Claude Code

스펙이 정해지면 완성 기준을 분명히 적어 구현을 맡깁니다. 무엇이 올바른 결과인지 알려 줘야 Claude가 스스로 확인하며 끝까지 갑니다.

따라 하기

  1. auto mode인지 확인합니다.
  2. 방금 정리한 스펙대로 만들어 달라고 요청하고 완성 기준을 적습니다.
  3. 진행 중 방향이 틀리면 중단하고 정보를 더합니다.
  4. 여러 파일을 크게 바꾸는 작업에서만 /effort를 high로 올립니다.
예시 프롬프트
방금 정리한 스펙대로 첫 버전을 만들어 줘. 완성 기준은 예시 회의록 파일을 넣었을 때 할 일·담당자·마감일 표가 화면에 나오는 거야.
  • Opus 5.5의 기본 effort는 medium입니다. 강력한 모델일수록 낮게 시작해 필요할 때 올립니다.

verify로 직접 확인시키기

Claude Code

테스트 통과만으로는 의도대로 동작하는지 알 수 없습니다. 기본으로 들어 있는 verify 스킬로 Claude가 앱을 직접 실행해 확인하게 하고, 성공한 절차는 프로젝트 스킬로 남깁니다.

따라 하기

  1. 구현이 끝나면 verify 스킬로 앱을 실행해 확인해 달라고 요청합니다.
  2. Claude가 서버 실행·페이지 열기·클릭·스크린샷으로 확인하는 과정을 지켜봅니다.
  3. 성공한 절차가 프로젝트에 스킬로 저장됐는지 확인합니다.
  4. 스킬에 항목별 통과 기준과 실패하면 할 일을 적습니다.
  5. 결과를 직접 눌러 보고 만족하는지 확인합니다.
예시 프롬프트
이 변경을 마친 뒤 verify 스킬로 앱을 직접 실행해서, 예시 회의록을 넣었을 때 표가 제대로 나오는지 확인해 줘. 안 되면 고치고 다시 확인해 줘.
  • 통과 기준을 측정 가능하게 적을수록 Claude가 혼자 더 멀리 갑니다.
  • 웹 화면이면 Claude in Chrome 확장으로 브라우저에서 직접 테스트하게 할 수도 있습니다.

CLAUDE.md로 규칙 남기기

Claude Code

CLAUDE.md는 Claude Code가 세션을 시작할 때마다 읽는 프로젝트 규칙 파일입니다. 같은 실수를 다시 시키는 대신 규칙으로 적어 두면 다음 세션부터 첫 응답이 좋아집니다.

따라 하기

  1. 프로젝트 폴더에서 /init을 입력해 CLAUDE.md를 만듭니다.
  2. 사용 기술, 실행·테스트 명령, 코드 스타일이 맞는지 확인하고 고칩니다.
  3. 작업 중 여러 번 바로잡은 내용은 기억해 두라고 분명히 요청합니다.
  4. Claude가 실수하면 다시 시키기 전에 원인을 규칙으로 적습니다.
  5. 새 모델로 바꿨다면 /claude-api prompt-audit로 지침을 점검합니다.
예시 프롬프트
/init
  • 처음부터 많이 적지 말고 계속 바로잡아야 하는 것만 더하면 파일이 간결하게 유지됩니다.
  • 규칙끼리 부딪히지 않는지 함께 점검합니다.

컨텍스트 정리하기

Claude Code

컨텍스트는 Claude의 작업 기억으로, 읽은 파일과 대화가 모두 공간을 차지합니다. 한도에 가까워지면 자동 압축되며 세부 내용이 사라질 수 있으니 직접 정리합니다.

따라 하기

  1. /context로 컨텍스트 크기와 많이 차지하는 항목을 확인합니다.
  2. 같은 기능을 이어 갈 때는 /compact로 대화를 요약합니다.
  3. 새 기능을 시작할 때는 /clear로 비웁니다.
  4. 지금 작업과 관계없는 MCP 서버는 끕니다.
  5. 다음 세션에도 기억할 내용은 CLAUDE.md에 적습니다.
예시 프롬프트
/context
  • 답만 필요한 조사는 서브에이전트에 맡기면 본 대화가 가벼워집니다.

검토하고 커밋하기

Claude Code

결과에 만족하면 서브에이전트 코드 리뷰어로 한 번 더 점검하고 커밋으로 남깁니다. 탐색 → 계획 → 코딩 → 커밋 흐름의 마지막 단계입니다.

따라 하기

  1. 결과를 직접 확인하고 만족하는지 판단합니다.
  2. 서브에이전트 코드 리뷰어로 변경 내용을 점검하게 합니다.
  3. 내 스타일에 맞는 커밋 메시지를 만들게 합니다.
  4. GitHub에 올릴 프로젝트라면 푸시합니다.
예시 프롬프트
서브에이전트 코드 리뷰어로 이번 변경 내용을 점검해 줘. 문제가 없으면 내 스타일에 맞는 커밋 메시지를 만들어 줘.
  • 같은 문제가 반복되면 해결책을 CLAUDE.md에 저장해 달라고 요청합니다.
  • 읽기만 하는 서브에이전트는 Sonnet 같은 작은 모델로 돌려 비용을 아낄 수 있습니다.
