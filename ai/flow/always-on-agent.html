스킬과 하네스 세팅하기

Claude Code

하네스는 지도(CLAUDE.md), 전문 절차(스킬), 강제 규칙(Hooks)을 갖춘 환경입니다. 새 프로젝트에서 먼저 세팅하면 결과 품질이 안정됩니다.

따라 하기

  1. 연습용 폴더로 새 세션을 엽니다.
  2. 프로젝트 정보와 하네스 원칙을 담은 프롬프트를 입력합니다.
  3. 생성된 CLAUDE.md·스킬·훅 구조를 파일 탭에서 확인합니다.
  4. 세션을 재시작합니다.
  5. /를 입력해 스킬이 보이는지 확인합니다.
  • 권한 건너뛰기는 위험하니 연습용 폴더에서 먼저 씁니다.
  • 스킬은 재시작해야 같은 세션에서 인식됩니다.

Hooks로 필수 규칙 강제하기

Claude Code

CLAUDE.md는 권고지만 Hook은 예외 없이 실행됩니다. 위험 명령 차단이나 자동 서식 정리에 씁니다.

따라 하기

  1. .claude/settings.json 또는 /hooks에서 Hook을 설정합니다.
  2. 이벤트(PreToolUse, PostToolUse, Stop 등)를 고릅니다.
  3. 위험 작업 차단은 PreToolUse에서 도구 입력을 검사합니다.
  4. 막을 때는 종료 코드 2, 허용은 0으로 끝냅니다.
  5. 팀과 공유하려면 settings 파일을 저장소에 커밋합니다.
  • rm -rf 포함 명령이나 main 브랜치 커밋 차단 같은 규칙에 알맞습니다.

루틴 만들어 알아서 일하게

Claude Code 루틴

프롬프트·저장소·커넥터·트리거만 정하면 관리형 인프라에서 세션이 자동 실행됩니다. 먼저 트리거, 컨텍스트, 조종 방식 세 가지를 정합니다.

따라 하기

  1. 루틴이 할 일을 프롬프트로 정합니다.
  2. 연결할 저장소와 커넥터를 정합니다.
  3. 터미널에서 /schedule로 실행 시각·알림 방식을 답합니다.
  4. 웹의 Claude Code에서 루틴과 실행 결과 세션을 확인합니다.
  5. 종료 조건(최대 반복 횟수·비용 한도)을 겹쳐 정합니다.
예시 프롬프트
매일 아침 사용자 피드백을 모아 중요도별로 분류하고, 확신이 높은 항목만 수정안을 만들어 PR로 올려 줘.
  • 처음에는 결과를 직접 확인하고 신뢰가 쌓이면 권한을 넓힙니다.
  • Codex를 쓴다면 플러그인 연결을 먼저 해야 자동화가 동작합니다.

여러 작업 병렬로 돌리기

Claude Code Projects

Project는 작업마다 클라우드 별도 브랜치에서 도는 스레드를 만들어 병렬로 처리합니다. 현재 베타이며 Pro와 Max에 순차 제공됩니다.

따라 하기

  1. Claude 탭에서 새 프로젝트를 만들고 목표와 저장소를 입력합니다.
  2. 코드베이스 탐색과 개선안 제안을 요청합니다.
  3. 진행할 작업에 합의합니다.
  4. 스레드 카드로 진행을 보고 방향을 바꾸거나 중단합니다.
  5. 끝난 스레드가 풀 리퀘스트를 열게 합니다.
예시 프롬프트
이 저장소를 탐색해서 개선할 만한 점을 제안해 줘. 내가 동의한 항목은 각각 별도 스레드로 나눠서 진행해 줘.
  • 코디네이터는 낮은 노력 수준, 스레드는 작은 모델이 권장됩니다.

원격·클라우드로 어디서나

Claude Code

원격 제어는 내 컴퓨터 세션에 접속하는 것이고, 클라우드 세션은 내 PC가 꺼져도 가상 머신에서 계속됩니다. 둘은 다른 방식입니다.

따라 하기

  1. 원격 제어는 터미널에서 claude remote-control을 실행합니다.
  2. 표시된 URL이나 QR 코드로 휴대폰에서 접속합니다.
  3. 클라우드는 GitHub를 연결하고 Local 대신 Cloud를 선택합니다.
  4. 저장소·환경·브랜치를 고르고 작업을 맡깁니다.
  5. 변경 내용을 검토하고 Create PR로 마무리합니다.
  • 클라우드 세션은 커밋·푸시한 내용만 쓸 수 있고 내 PC 파일에는 접근하지 못합니다.
  • 원격 제어는 플랜 조건을 확인하세요.

모델 나눠 쓰고 비용 지키기

Claude Code

모든 일에 가장 큰 모델이 필요하지 않습니다. 탐색·정형 작업은 작은 모델 서브에이전트에 맡기고 결과가 부족하면 먼저 effort를 올립니다.

따라 하기

  1. 큰 작업은 큰 모델로 이끌게 합니다.
  2. 범위가 분명한 부분은 Sonnet 서브에이전트에 넘기게 합니다.
  3. 읽기만 하는 서브에이전트는 모델을 Sonnet으로 지정합니다.
  4. 결과가 부족하면 effort를 먼저 올립니다.
예시 프롬프트
이 마이그레이션은 네가 이끌어 줘. 패키지 업그레이드와 테스트 수정처럼 범위가 분명한 부분은 Sonnet 서브에이전트에게 맡기고 결과만 보고받아 줘.
  • 토큰 단가가 아니라 작업당 비용으로 비교합니다.
  • 가용성과 한도는 요금제마다 다릅니다.
