자동화할 업무 고르기

Claude 앱

이 단계는 흐름을 잇기 위해 덧붙인 일반 안내입니다. 모니터링 영상에서 직접 다룬 내용은 아닙니다.

처음에는 범위가 분명하고 결과를 사람이 확인할 수 있는 업무가 안전합니다. 완료 기준을 적어 두면 자동화 설계가 쉬워집니다.

따라 하기

  1. 매일·매주 반복하는 업무를 적어 봅니다.
  2. 그중 결과가 분명한 일 하나를 고릅니다.
  3. 무엇이 완료인지 참/거짓으로 판정할 수 있게 적습니다.
  4. 필요한 서비스(메일, 캘린더, 시트)를 정리합니다.
예시 프롬프트
내가 매주 반복하는 업무 목록이야. 이 중 자동화하기 좋은 것과 사람이 확인해야 하는 것을 나눠 줘.
  • 처음에는 PR 초안·이메일 초안처럼 사람이 검토하는 일부터 맡기세요.

커넥터 연결하기

Claude 앱

자동화가 외부 서비스를 읽고 쓰려면 먼저 커넥터가 연결돼 있어야 합니다. 예약 작업은 설정해 둔 커넥터를 그대로 씁니다.

따라 하기

  1. 플러스 → 커넥터 → 커넥터 추가 → 커넥터 둘러보기로 들어갑니다.
  2. Gmail, 구글 캘린더, 노션 등을 검색합니다.
  3. 플러스 버튼을 누르고 계정으로 인증합니다.
  4. 이메일 작업에는 이메일 커넥터가 켜져 있는지 확인합니다.
  • 웹 버전은 로컬 파일에 접근하지 못합니다.

스킬로 업무 방식 저장하기

코워크

스킬은 우리 팀의 업무 방식을 적어 둔 지시서입니다. 한 번 만들어 두면 같은 지시로 같은 품질의 결과가 나옵니다.

따라 하기

  1. 먼저 업무를 한 번 직접 시켜 결과를 다듬습니다.
  2. /를 입력해 플러그인·스킬 목록을 확인합니다.
  3. 우리 팀 업무라면 스킬 파일 초안을 만들게 합니다.
  4. 필요한 커넥터를 연결하고 테스트 자료로 실행합니다.
  5. 실행 후 배운 점을 스킬에 반영해 달라고 요청합니다.
예시 프롬프트
이번 주 실행하면서 배운 점을 정리해서 이 스킬에 반영해 줘.
  • 스킬은 일반 텍스트 파일이라 언제든 열어 확인할 수 있습니다.
  • 처음에는 샘플 자료로 돌려 보세요.

예약 작업 걸기

코워크

예약 작업은 정해진 주기에 Claude가 같은 일을 실행합니다. 실행마다 새 세션으로 최신 파일 기준으로 돕니다.

따라 하기

  1. 반복할 일을 자연어로 설명합니다.
  2. Claude가 만든 프롬프트 초안을 검토합니다.
  3. 주기를 매시간·매일·평일·수동 중에서 고칩니다.
  4. 제안을 수락합니다.
  5. 예약 페이지에서 작업이 추가됐는지 확인합니다.
  6. 첫 실행 결과를 확인하고 지시문을 고칩니다.
예시 프롬프트
매시간 공유 드라이브 폴더에 추가되거나 수정된 문서를 확인해서 변경한 사람을 기록하고, 내용을 요약해 클라이언트별로 묶어 문서로 저장해 줘.
  • 2026년 7월 업데이트 이후 기기가 꺼져 있어도 클라우드에서 실행됩니다.
  • 믿을 만해지면 더 많은 일을 맡기세요.

다른 도구로 자동화 넓히기

Gemini 스파크

쓰는 서비스에 따라 도구를 고릅니다. 구글 업무는 스파크, 캘린더 브리핑은 Codex 자동화, 서비스 간 연동은 n8n이 맞습니다.

따라 하기

  1. 구글 업무라면 제미나이 스파크 베타 탭을 열고 워크스페이스 연결을 확인합니다.
  2. 실행 시점을 프롬프트에 적습니다(예: 매주 월요일 오전 8시).
  3. 메일은 발송하지 말고 초안으로만 남기게 합니다.
  4. Codex를 쓴다면 플러그인을 먼저 연결하고 자동화 탭에서 채팅으로 만들기를 누릅니다.
  5. n8n은 빌드 위드 AI에 자동화할 내용을 구체적으로 적어 만듭니다.
  6. API 키·인증 정보는 직접 연결하고 테스트 데이터로 확인합니다.
예시 프롬프트
슬랙 채널에 긴급이 들어간 메시지가 오면 노션에 저장하고 담당자에게 이메일을 보내 줘.
  • 스파크는 구글 AI 프로 이상 구독이 필요합니다.
  • n8n AI 빌더는 프롬프트 한 번에 1크레딧을 씁니다.
  • Codex는 플러그인 연결을 먼저 하지 않으면 동작하지 않습니다.

결과 점검하고 안전장치 두기

Claude 앱

자동화가 폭주하거나 틀린 결과를 내보내지 않도록 한도와 확인 지점을 미리 정합니다. 외부에 나가는 결과물은 공개 전에 사람이 검수합니다.

따라 하기

  1. 최대 반복 횟수와 시간·비용 한도를 정합니다.
  2. 되돌리기 어려운 지점은 실행 전에 내 확인을 받도록 합니다.
  3. 만드는 AI와 검사하는 AI를 분리합니다.
  4. 피드백을 줄 때마다 스킬이나 규칙으로 남깁니다.
  5. 결과를 원문과 대조해 검수합니다.
  • 단순 작업에 고성능 모델은 필요하지 않습니다.
  • 비용·횟수 한도는 폭주를 막는 서킷 브레이커 역할을 합니다.
