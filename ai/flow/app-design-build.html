인터뷰로 화면 스펙 정하기

Claude Code

무엇을 만들지 막연하면 Claude가 질문하고 내가 답하는 방식으로 스펙을 만듭니다. 시안을 만들기 전에 누가 무엇을 하려고 쓰는지 분명해야 시안도 좋아집니다.

따라 하기

  1. 작업할 저장소 폴더에서 Claude Code를 열고 Shift+Tab으로 auto mode로 전환합니다.
  2. /effort로 노력 수준을 정합니다.
  3. 관심 영역(대상 사용자, 해결할 문제)만 주고 ask user question 도구로 질문하라고 합니다.
  4. 질문에 차례로 답한 뒤 스펙을 검토합니다.
  5. 스펙을 정보 밀도가 높은 HTML 파일로 받아 먼저 읽어 봅니다.
예시 프롬프트
사내 회의실 예약 웹앱의 첫 화면을 새로 만들고 싶어. 대상은 회의실을 자주 잡는 팀장과 총무 담당자야. 바로 만들지 말고 ask user question 도구로 필요한 질문을 하나씩 해서 스펙을 HTML 파일로 정리해 줘.
  • 빠르게 스펙을 반복할 때는 /fast 모드가 유용합니다.

디자인 시안 여러 개 받기

Claude Design

코드로 바로 만들기 전에 Claude 디자인으로 여러 시안을 탐색합니다. 말로 설명하기보다 시안을 보고 고르는 편이 빠릅니다.

따라 하기

  1. Claude Code에서 작업할 저장소(repo)를 연결합니다.
  2. Artifacts 탭으로 이동해 새 디자인을 만듭니다.
  3. 현재 앱과 스펙을 살펴보고 여러 시안을 만들어 달라고 요청합니다.
  4. Claude가 작업하는 동안 다른 일을 하다 돌아와 결과를 봅니다.
예시 프롬프트
현재 앱과 방금 정리한 스펙을 살펴보고, 회의실 예약 첫 화면 시안을 서로 다른 방향으로 3개 만들어 줘. 하나는 달력 중심, 하나는 빈 회의실 목록 중심으로 해 줘.
  • 원하는 느낌을 구체적으로 말할수록 결과가 좋아집니다.

클릭형 프로토타입 눌러 보기

Claude Design

정적인 시안만으로는 화면 사이 흐름의 문제를 놓치기 쉽습니다. 클릭해 볼 수 있는 프로토타입으로 실제 사용 순서를 확인한 뒤 구현으로 넘어갑니다.

따라 하기

  1. 선택한 시안으로 클릭형 프로토타입(click-through prototype)을 만들어 달라고 요청합니다.
  2. 대상 사용자가 되어 처음부터 끝까지 눌러 봅니다.
  3. 막히는 곳은 댓글로 남겨 고칩니다.
  4. 만족하면 구현으로 넘어갑니다.
예시 프롬프트
이 시안으로 클릭해 볼 수 있는 프로토타입을 만들어 줘. 회의실 선택 → 시간 선택 → 예약 완료까지 세 화면이 이어지게 해 줘.

프로토타입대로 구현하기

Claude Code

프로토타입이 확정되면 Claude에게 구현을 지시합니다. 여러 파일에 걸친 수정이면 effort를 high로 올리고, 읽기만 하는 탐색은 작은 모델에 맡겨 비용을 아낍니다.

따라 하기

  1. 프로토타입에 만족하면 Claude에게 구현(build)을 지시합니다.
  2. 여러 파일·프로젝트 전체를 바꾸는 수정이면 /effort를 high로 올립니다.
  3. 읽기만 하는 탐색은 Sonnet 같은 작은 모델의 서브에이전트에 맡깁니다.
  4. 진행 상황을 보다가 방향이 틀리면 중단하고 정보를 더합니다.
예시 프롬프트
확정한 프로토타입대로 구현해 줘. 완성 기준은 세 화면이 프로토타입과 같은 순서로 이어지고, 예약 완료 화면에 선택한 회의실과 시간이 표시되는 거야.
  • 서브에이전트를 너무 많이 만들면 메인 에이전트와 소통이 어긋날 수 있으니 단순한 구성에서 시작합니다.

브라우저 검증 스킬 만들기

Claude Code

테스트와 타입 검사만으로는 화면이 의도대로 동작하는지 증명되지 않습니다. 브라우저에서 클릭하고 측정하는 확인 절차를 스킬로 만들어 두면 Claude가 확인 → 수정 → 재확인을 반복합니다.

따라 하기

  1. verify 스킬로 앱을 실행해 변경 사항을 확인하게 합니다.
  2. 성공한 절차가 프로젝트 스킬로 저장됐는지 확인합니다.
  3. claude mcp add로 Chrome DevTools MCP를 연결하고, 레이아웃 시프트 같은 성능 측정 항목을 스킬에 더합니다.
  4. 항목마다 숫자로 된 통과 기준과 실패 시 할 일을 적습니다.
  5. UI 변경을 요청하고 Claude가 스스로 고치고 다시 확인하는지 지켜봅니다.
예시 프롬프트
회의실 예약 화면 변경을 마친 뒤 verify 스킬로 서버를 띄우고 세 화면을 직접 클릭해 확인해 줘. 레이아웃 시프트도 측정하고, 기준을 넘으면 고친 뒤 다시 확인해 줘.
  • 성능 예산, 접근성 체크리스트, 디자인 시스템 규칙을 통과 기준으로 삼아 보세요.
  • 쓰지 않는 MCP 서버는 /mcp에서 꺼 컨텍스트를 아낍니다.

클라우드 세션에 수정 맡기기

클라우드 세션

남은 수정이 크거나 퇴근 전에 맡기고 싶으면 클라우드 세션을 씁니다. 저장소를 복제해 별도 브랜치에서 작업하므로 노트북을 닫아도 일이 계속됩니다.

따라 하기

  1. 지금까지의 작업을 GitHub 저장소에 커밋·푸시해 둡니다.
  2. Claude GitHub App을 설치하고 접근할 저장소를 고릅니다.
  3. 데스크톱 앱에서 Local 대신 Cloud를 선택하고 저장소·환경·브랜치를 고릅니다.
  4. 작업을 맡기고 노트북을 닫습니다.
  5. 휴대폰 Claude 앱의 Code 탭에서 질문에 답하거나 방향을 바꿉니다.
  • 세션은 저장소를 새로 복제해 시작하므로 커밋·푸시한 내용만 쓸 수 있습니다. 개인 설정·스킬이 필요한 작업은 로컬에서 돌립니다.
  • Pro·Max·Team 플랜에서 쓸 수 있고 로컬 세션과 같은 한도를 씁니다.

검토하고 PR 올리기

Claude Code

작업이 끝나면 변경 내용을 직접 검토하고 풀 리퀘스트로 올립니다. CI 실패와 리뷰 코멘트 반영까지 Claude가 챙기게 할 수 있습니다.

따라 하기

  1. 변경 내용(diff)을 검토하고 필요한 곳에 코멘트를 남깁니다.
  2. 서브에이전트 코드 리뷰어로 한 번 더 점검하게 합니다.
  3. 문제가 없으면 Create PR을 눌러 풀 리퀘스트를 엽니다.
  4. CI가 실패하거나 리뷰 코멘트가 달리면 Claude가 수정을 푸시하는지 확인합니다.
  5. 병합할 준비가 되면 Claude에게 병합을 요청합니다.
  • diff에 남긴 코멘트는 다음 메시지와 함께 Claude에게 전달됩니다.
