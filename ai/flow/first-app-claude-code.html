작업 폴더 열고 도구 익히기

Claude Code

Claude Code에는 기본 대화 말고도 규칙, 도구, 작업 방법을 건네는 확장 수단이 있습니다. 무엇을 언제 쓰는지 알아 두면 뒤 단계에서 헤매지 않습니다.

따라 하기

  1. Claude Code 데스크톱 앱의 좌측 상단 코드 탭으로 들어갑니다.
  2. 로컬 옆 버튼에서 폴더 열기를 눌러 새 프로젝트 폴더를 만들어 엽니다.
  3. 프로젝트에서 늘 지킬 규칙과 맥락은 CLAUDE.md에 적는다고 기억합니다.
  4. 바깥 도구나 서비스를 써야 하면 MCP로, 반복하는 작업 방법은 스킬로 묶는다고 정리합니다.
  5. 대화가 길어지면 Claude가 한 번에 기억하는 분량(컨텍스트 윈도우)을 관리해야 한다는 점도 기억합니다.
  • Claude Code 화면이나 동작 자체를 바꾸고 싶으면 모드(Mods)를 씁니다. 10월에 발표된 기능이라 바뀔 수 있습니다.

권한 규칙으로 안전장치 걸기

Claude Code

Claude Code는 파일 수정이나 명령 실행 전에 권한을 묻습니다. 규칙을 미리 정해 두면 위험한 작업은 막고 안전한 작업은 묻지 않고 진행하게 할 수 있습니다.

따라 하기

  1. 권한 요청이 오면 무엇을 하려는지 읽고 승인하거나 거절하는 데 익숙해집니다.
  2. 어떤 경우에도 하면 안 되는 동작은 deny 규칙으로 막습니다.
  3. 실행 전에 꼭 확인받을 동작은 ask 규칙에 적습니다.
  4. 매번 묻지 않아도 되는 동작은 allow 규칙에 적습니다.
  5. 혼자 쓰면 사용자 설정(user settings)에 규칙을 넣습니다.
  • 연구에서 권한 요청의 97%가 승인되었습니다. 습관처럼 승인만 누르고 있다면 규칙이나 자동 모드를 써 볼 때입니다.
  • 자동 모드를 켜도 deny·ask·allow 규칙이 먼저 적용됩니다.

인터뷰로 요구사항 정하기

Claude Code

원하는 결과를 일일이 적는 대신 Claude가 나에게 질문하게 해서 요구사항을 끌어냅니다. 모델이 강해질수록 지시를 줄이고 질문에 답하는 편이 결과가 좋습니다.

따라 하기

  1. /effort로 노력 수준을 medium으로 정합니다.
  2. 프롬프트에는 만들 것과 대상 사용자 정도만 적고 결과를 지나치게 지정하지 않습니다.
  3. 바로 만들지 말고 ask user question 도구로 나에게 질문하라고 적습니다.
  4. Claude가 띄우는 질문에 차례로 답합니다.
  5. 답변이 끝나면 Claude가 쓴 스펙을 먼저 검토합니다.
예시 프롬프트
회사 동료들끼리 회식비를 나눠 내는 앱을 만들고 싶습니다. 대상 사용자는 스마트폰에 익숙한 20~40대 직장인입니다. 바로 만들지 말고, ask user question 도구로 저에게 질문해서 요구사항을 정리한 뒤 스펙을 작성해 주세요.
  • 스펙을 빠르게 여러 번 고칠 때는 /fast 모드가 쓸모 있습니다.
  • 계획은 긴 마크다운 대신 정보가 촘촘한 HTML 파일로 받아 검토할 수도 있습니다.
  • 예전 방식: 5월 영상은 effort를 X high로 권했습니다. 지금은 Opus 5.5 기본값 medium에서 시작합니다.

디자인 시안 먼저 보기

Claude Design

바로 코드로 가지 말고 화면 시안을 짧게 탐색하면 결과물이 나아집니다. 클릭해 볼 수 있는 프로토타입으로 흐름을 확인한 뒤 구현으로 넘어갑니다.

따라 하기

  1. Claude Code를 열고 작업할 저장소(repo)를 연결합니다.
  2. Artifacts 탭으로 이동해 새 디자인을 만듭니다.
  3. 원하는 화면의 시안을 서로 다른 방향으로 여러 개 요청합니다.
  4. 잘 된 점과 아쉬운 점을 댓글로 남기고, 세부 사항은 에디터에서 직접 고칩니다.
  5. 클릭해 볼 수 있는 프로토타입(click-through prototype)을 만들어 달라고 요청해 써 봅니다.
예시 프롬프트
회식비 나눠 내기 앱의 첫 화면 시안을 서로 다른 방향으로 세 가지 보여 줘. 참석자 추가, 금액 입력, 1인당 금액 확인이 한 화면에서 보이게 해 줘.
  • Claude가 작업하는 동안 기다리지 말고 다른 일을 하다가 돌아와도 됩니다.

자동 모드로 구현 맡기기

Claude Code

자동 모드에서는 별도 분류기가 내 지시와 맞는 작업인지 판단해 위험한 명령만 막습니다. 승인 버튼 때문에 작업이 자주 멈추지 않습니다.

따라 하기

  1. 앞에서 정한 deny·ask·allow 규칙이 들어가 있는지 확인합니다.
  2. Shift+Tab을 눌러 auto mode로 바꿉니다.
  3. 스펙과 시안을 기준으로 구현을 지시합니다.
  4. 읽기 전용이거나 되돌릴 수 있는 작업은 바로 진행되고, 나머지는 분류기가 판단하는지 지켜봅니다.
  5. 여러 파일이나 프로젝트 전체를 바꾸는 큰 수정일 때만 effort를 high로 올립니다.
예시 프롬프트
앞에서 정리한 스펙과 마지막 시안대로 회식비 나눠 내기 앱을 만들어 줘. 다 만들면 실행 방법과 바꾼 파일 목록을 알려 줘.
  • 기본값은 작업 폴더와 git 리모트만 '우리 것'으로 봅니다. 회사 인프라를 써야 하면 환경(environment) 설정이 필요합니다.
  • 예전 방식: 플랜 모드로 계획부터 세웠지만, 최신 모델에서는 자동 모드로 바로 맡기는 경우가 많아졌습니다.

verify 스킬로 직접 확인시키기

Claude Code

테스트를 통과해도 의도대로 동작한다는 증명은 되지 않습니다. verify 스킬을 쓰면 Claude가 앱을 실행해 직접 확인하고, 실패하면 고친 뒤 다시 확인합니다.

따라 하기

  1. Claude Code에 들어 있는 verify 스킬로 이번 변경을 확인해 달라고 요청합니다.
  2. Claude가 앱을 실행하고 화면에서 직접 확인하는 과정을 지켜봅니다.
  3. 성공한 절차가 프로젝트 스킬로 저장되었는지 확인합니다.
  4. 스킬에 언제 실행할지, 실패하면 무엇을 할지, 확인마다 통과 기준이 무엇인지 적습니다.
  5. 다음 화면 변경부터는 Claude가 실행·클릭·스크린샷까지 하고 실패 시 고쳐 다시 확인하는지 봅니다.
예시 프롬프트
이번 화면 변경을 verify 스킬로 확인해 줘. 참석자를 3명 추가하고 금액 90,000원을 넣었을 때 1인당 30,000원이 표시되는지 확인하는 단계를 스킬에 추가해 줘.
  • 확인 기준이 측정 가능할수록 Claude가 통과 여부를 판단하기 쉽고, 혼자 더 멀리 갑니다.
  • Chrome DevTools MCP로 레이아웃 시프트 같은 성능 지표를 측정하는 단계도 넣을 수 있습니다.

같은 실수는 CLAUDE.md에 적기

Claude Code

Claude가 실수했을 때 매번 다시 시키는 대신 그 내용을 규칙으로 적어 두면 다음부터 같은 실수가 나오지 않습니다.

따라 하기

  1. Claude가 실수하면 같은 요청을 다시 시키지 말고 무엇이 잘못됐는지 정리합니다.
  2. 지켜야 할 방법을 CLAUDE.md나 해당 스킬에 한 줄 규칙으로 적게 합니다.
  3. 새 규칙이 기존 규칙과 부딪치지 않는지 확인합니다.
  4. 모델을 새 버전으로 바꾼 뒤에는 /claude-api prompt-audit로 지침을 점검합니다.
예시 프롬프트
방금 금액을 소수점까지 표시한 실수를 다시 하지 않도록, '금액은 항상 원 단위 정수로 쉼표를 넣어 표시한다'는 규칙을 CLAUDE.md에 한 줄로 추가해 줘.
  • /claude-api prompt-audit는 API를 쓰지 않고 Claude Code만 써도 쓸 수 있습니다.

클라우드 세션에 맡기고 PR 열기

Claude Code 클라우드 세션

클라우드 세션은 클라우드 가상 머신에서 GitHub 저장소를 복제해 별도 브랜치에서 작업합니다. 노트북을 닫아도 계속되므로 큰 수정이나 퇴근 전 작업에 알맞습니다.

따라 하기

  1. 작업할 코드를 GitHub 저장소에 올립니다.
  2. GitHub 계정을 연결하고 Claude GitHub App을 설치해 접근할 저장소를 고릅니다.
  3. 데스크톱 앱에서 Local 대신 Cloud를 선택하고 저장소, 환경, 시작할 브랜치를 고릅니다.
  4. 작업을 맡기고 노트북을 닫습니다. 이동 중에는 휴대폰 Claude 앱의 Code 탭에서 질문에 답합니다.
  5. 변경 내용(diff)을 검토하고 문제가 없으면 Create PR을 눌러 풀 리퀘스트를 엽니다.
예시 프롬프트
정산 결과를 카카오톡으로 공유하기 좋은 텍스트로 복사하는 버튼을 추가해 줘. 끝나면 바꾼 내용을 요약해 줘.
  • 세션은 저장소를 새로 복제해 시작하므로 커밋·푸시한 내용만 씁니다. 개인 설정·스킬·플러그인이 필요한 작업은 로컬에서 실행하세요.
  • 가상 머신 비용은 따로 없지만 사용량은 로컬 세션과 함께 플랜 한도에 셉니다.

루틴으로 정기 점검 맡기기

Claude Code 루틴

루틴은 정한 일정이나 이벤트에 맞춰 Anthropic 서버에서 Claude Code 세션을 자동으로 돌립니다. 노트북이 꺼져 있어도 앱을 정기적으로 점검하게 할 수 있습니다.

따라 하기

  1. 터미널에서 Claude Code를 실행합니다.
  2. /schedule을 입력하고 원하는 작업을 적습니다.
  3. 몇 시에 실행할지, 끝나면 Slack 등으로 알릴지 같은 질문에 답합니다.
  4. 필요한 저장소를 컨텍스트로 연결합니다.
  5. 웹의 Claude Code에서 만들어진 루틴과 실행 결과 세션을 확인합니다.
  6. 처음 며칠은 결과를 매일 확인하며 지시를 다듬습니다.
예시 프롬프트
