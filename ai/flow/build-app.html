권한 규칙 먼저 정하기

Claude Code

Claude Code는 파일 수정이나 명령 실행 전에 권한을 요청합니다. deny·ask·allow 규칙을 먼저 정해 두면 위험한 동작은 막고 승인 횟수는 줄일 수 있습니다.

따라 하기

  1. 어떤 상황에서도 실행되면 안 되는 동작을 먼저 적어 봅니다.
  2. 그 동작을 deny 규칙에 넣어 막습니다.
  3. 실행 전에 항상 확인받고 싶은 동작은 ask 규칙에 넣습니다.
  4. 매번 확인할 필요가 없는 동작은 allow 규칙에 넣습니다.
  5. 처음에는 좁게 허용하고, 자주 막히는 항목을 보며 조금씩 넓힙니다.
  • deny·ask·allow 규칙은 자동 모드의 판단보다 먼저 적용됩니다.
  • 프로덕션 인프라 변경 같은 고위험 작업은 자동 모드에 맡기지 말고 직접 검토하세요.

디자인 시안 여러 개 받기

Claude Design

바로 코드로 들어가기보다 짧게라도 디자인을 탐색하면 결과가 좋아집니다. 시안을 여러 개 받아 댓글로 피드백하고 세부 사항은 직접 고칩니다.

따라 하기

  1. Claude Code를 열고 작업할 저장소를 연결합니다.
  2. Artifacts 탭으로 이동해 새 디자인을 만듭니다.
  3. 만들 화면을 설명하고 여러 디자인 시안을 요청합니다.
  4. 잘된 점과 아쉬운 점을 시안에 댓글로 남깁니다.
  5. 세부 사항은 에디터에서 직접 고치고, 필요하면 새 시안을 더 요청합니다.
예시 프롬프트
이 앱의 온보딩 화면 시안을 몇 가지 다른 방향으로 보여 줘. 브랜드 색은 남색과 흰색, 톤은 차분하고 신뢰감 있게 해 줘.
  • Claude가 작업하는 동안 다른 일을 하다가 돌아와 결과를 봐도 됩니다.
  • 말로 설명하기보다 시안을 보며 고치는 편이 빠릅니다.

프로토타입으로 흐름 확인하기

Claude Design

정지된 시안만으로는 화면 사이 흐름을 알기 어렵습니다. 직접 클릭해 볼 수 있는 프로토타입으로 확인하고 확정한 뒤에 구현으로 넘어갑니다.

따라 하기

  1. 마음에 드는 시안으로 클릭형 프로토타입(click-through prototype)을 요청합니다.
  2. 화면 흐름을 직접 눌러 보며 어색한 곳을 찾습니다.
  3. 고칠 점을 댓글로 남기고 다시 확인합니다.
  4. 만족하면 이 디자인으로 확정합니다.

확정한 디자인 구현하기

Claude Code

프로토타입이 만족스러우면 Claude에게 구현을 지시합니다. Opus 5.5의 기본 effort는 medium으로 대부분 충분하고, 여러 파일이나 프로젝트 전체를 바꾸는 작업이면 high로 올립니다.

따라 하기

  1. 모델을 Opus 5.5로 두고 effort는 medium으로 시작합니다.
  2. 확정한 프로토타입을 바탕으로 구현(build)을 지시합니다.
  3. 여러 파일에 걸친 큰 작업이면 effort를 high로 올립니다.
  4. 만들어진 화면을 직접 실행해 확인합니다.
예시 프롬프트
확정한 온보딩 프로토타입대로 실제 화면을 구현해 줘. 기존 코드 스타일을 따르고, 끝나면 바뀐 파일 목록을 알려 줘.
  • 코드를 읽기만 하는 탐색용 서브에이전트는 Sonnet이나 Haiku로 돌려 비용을 아낄 수 있습니다.

verify로 검증 루프 만들기

Claude Code

테스트·린터 통과만으로는 변경이 의도대로 동작하는지 알 수 없습니다. 내장 verify 스킬로 확인 절차를 프로젝트 스킬로 만들면 Claude가 고치고 다시 확인하기를 혼자 반복합니다.

따라 하기

  1. Claude Code에 포함된 verify 스킬을 처음으로 실행합니다.
  2. Claude가 앱을 실행하고 변경을 직접 확인하는 과정을 지켜봅니다.
  3. 성공한 확인 절차가 프로젝트 스킬로 저장됐는지 확인합니다.
  4. 평소 손으로 하던 확인(클릭, 콘솔 보기)과 성능 측정 항목을 스킬에 더합니다.
  5. 언제 실행할지, 실패하면 무엇을 할지, 통과 기준을 스킬에 적습니다.
  6. UI 변경을 요청하고 Claude가 확인·수정·재확인하는지 봅니다.
예시 프롬프트
이 프로젝트의 검증 스킬에 페이지를 불러올 때 레이아웃 시프트를 측정하는 확인 항목을 추가해 줘.
  • 통과 기준이 측정 가능할수록 Claude가 혼자 더 멀리 갑니다.
  • 웹은 브라우저, 백엔드는 엔드포인트 호출, 모바일은 iOS 시뮬레이터로 확인 절차를 만들 수 있습니다.

클라우드 세션에 작업 맡기기

Claude Code

큰 리팩터링이나 퇴근 전에 맡길 작업은 클라우드 세션으로 돌립니다. 저장소를 복제해 별도 브랜치에서 작업하므로 노트북을 닫아도 계속 진행됩니다.

따라 하기

  1. 작업에 필요한 내용을 커밋·푸시해 둡니다.
  2. 데스크톱 앱에서 Local 대신 Cloud를 선택합니다.
  3. 저장소, 환경, 시작할 브랜치를 고릅니다.
  4. 맡길 일을 설명하고 노트북을 닫습니다.
  5. 휴대폰 Claude 앱의 Code 탭에서 질문에 답하거나 방향을 조정합니다.
  • 클라우드 세션은 커밋·푸시한 내용만 씁니다. 개인 설정, 스킬, 플러그인이 필요한 작업은 로컬에서 실행하세요.
  • 가상 머신 비용은 따로 없지만 사용량은 로컬 세션과 함께 플랜 한도에 합산됩니다.
  • Remote Control은 내 컴퓨터의 세션에 연결하는 방식이라 컴퓨터가 켜져 있어야 합니다.

변경 검토하고 PR 만들기

Claude Code

작업이 끝나면 변경 내용을 직접 검토합니다. 문제가 없으면 GitHub에 풀 리퀘스트를 열어 팀 리뷰나 병합으로 넘깁니다.

따라 하기

  1. 변경 내용(diff)을 검토합니다.
  2. 고칠 점은 코멘트로 남기면 다음 메시지와 함께 Claude에게 전달됩니다.
  3. 문제가 없으면 Create PR을 눌러 GitHub에 풀 리퀘스트를 엽니다.
  4. 이어서 로컬에서 작업하려면 터미널에서 teleport 플래그를 붙여 claude를 실행해 세션을 가져옵니다.
  • 여러 클라우드 세션을 동시에 돌려 서로 관계없는 작업을 나눠 맡길 수 있습니다.
