Claude Code 설치·로그인하기

Claude Code

새 기능이 가장 먼저 나오는 터미널 버전을 기본으로 설치합니다. Claude Code는 실행한 폴더 전체에 접근하므로 연습용 폴더를 따로 만들어 그 안에서 시작합니다.

따라 하기

  1. macOS·Linux·WSL에서는 공식 안내에 나온 curl 설치 명령을 실행합니다.
  2. Windows PowerShell에서는 공식 안내의 Invoke-RestMethod 명령을, CMD에서는 공식 안내의 curl 명령을 실행합니다.
  3. 연습용 프로젝트 폴더로 이동한 뒤 Claude Code를 실행합니다.
  4. 처음 실행하면 색상 테마를 고릅니다.
  5. Claude 계정(Pro, Max, Enterprise) 또는 API 키로 로그인합니다.
  6. 편집기 안에서 쓰고 싶다면 VS Code 확장 패널에서 Anthropic이 만든 Claude Code 확장을 설치합니다.
  • 회사 문서가 많은 상위 폴더보다 작업할 폴더에서 실행하세요.
  • Homebrew나 winget으로 설치하면 자동 업데이트가 되지 않습니다.
  • Claude Desktop 앱에서는 상단의 Code 토글로 Claude Code 화면으로 바꿀 수 있습니다.

권한 모드 익히기

Claude Code

권한 모드는 Claude가 파일을 고치거나 명령을 실행하기 전에 얼마나 자주 허락을 받을지 정합니다. 처음에는 매번 확인하며 Claude가 무엇을 하는지 익힙니다.

따라 하기

  1. Claude Code 실행 중에 Shift + Tab을 누릅니다.
  2. 기본 모드에서는 파일 수정·명령 실행 전에 매번 허락을 묻습니다. 처음에는 이 모드로 하나씩 확인합니다.
  3. 한 번 더 누르면 Auto accept edits 모드가 됩니다. 파일 수정은 자동 승인하고 명령 실행은 계속 묻습니다.
  4. 한 번 더 누르면 Plan mode가 됩니다. 파일을 고치지 않고 읽기만 하며 계획을 세웁니다.
  5. 입력창 아래에 표시된 모드 이름을 보고 지금 어떤 모드인지 확인합니다.
  • Claude가 일하는 중간에도 정보를 더 주거나, 멈추게 하거나, 방향을 바꿀 수 있습니다.
  • 최신 영상에서는 별도 분류기가 판단해 자동 승인하는 auto mode도 소개됩니다. 익숙해진 뒤에 써 보세요.

CLAUDE.md로 규칙 적기

Claude Code

CLAUDE.md는 Claude Code가 세션을 시작할 때마다 자동으로 읽는 메모 파일입니다. 사용 기술과 규칙을 적어 두면 매번 설명하지 않아도 첫 응답부터 결과가 좋아집니다.

따라 하기

  1. 프로젝트 루트 폴더에서 Claude Code를 실행합니다.
  2. /init을 실행해 지금 프로젝트 내용을 바탕으로 CLAUDE.md를 만듭니다.
  3. 만들어진 파일에서 사용 기술, 실행·테스트 명령어, 작성 규칙을 확인하고 고칩니다.
  4. 참고할 문서가 있으면 @ 기호와 파일 경로로 연결합니다.
  5. 처음에는 최소한으로 쓰고, 계속 바로잡아야 하는 부분만 더해 갑니다.
예시 프롬프트
/init
  • 주석 쓰는 방식 같은 개인 취향은 사용자용 CLAUDE.md에 적으면 모든 프로젝트에 적용됩니다.
  • 사용 기술 → 개인 선호 → 명령어 순으로 적기 시작해 조금씩 늘려 가세요.

질문받아 기획서 만들기

Claude Code

만들 것을 자세히 지정하기 어렵다면 Claude가 질문을 던지게 합니다. 모델이 강해질수록 제약을 줄이고 질문에 답하는 쪽이 더 좋은 기획서(스펙)를 얻습니다.

따라 하기

  1. /effort로 노력 수준을 정합니다. Opus 5.5는 기본 medium으로 대부분 충분합니다.
  2. 프롬프트에는 만들 것과 관심 영역(예: 대상 사용자)만 적고 결과를 과하게 지정하지 않습니다.
  3. ask user question 도구로 질문해 달라고 명시합니다.
  4. Claude가 띄우는 질문에 차례로 답합니다.
  5. 완성된 스펙을 읽고 빠졌거나 틀린 부분을 고쳐 달라고 합니다.
예시 프롬프트
우리 팀 회의실 예약 현황을 한눈에 보는 간단한 웹 페이지를 만들고 싶어. ask user question 도구로 나에게 질문해 가며 요구사항을 정리하고, 다 끝나면 스펙을 작성해 줘. 아직 코드는 쓰지 마.
  • '더 좋게 만들어', '실수 없이 만들어' 같은 막연한 프롬프트는 피합니다.
  • 최신 영상에서는 이 과정을 계획 모드 대신 auto mode로 진행한다고 합니다. 처음이라면 기본 모드에서 해도 됩니다.

계획 확인하고 만들게 하기

Claude Code

계획 단계가 방향을 고치기 가장 좋은 때입니다. 스펙을 바탕으로 Claude가 파일을 읽고 세운 계획을 검토하고, 맞는 결과의 기준까지 확인한 뒤 실행을 맡깁니다.

따라 하기

  1. 스펙을 바탕으로 코드베이스를 먼저 살펴보고 구현 계획을 보여 달라고 요청합니다. 계획 모드(입력창 아래 plan mode 표시)를 써도 됩니다.
  2. 계획에 어떤 결과가 맞는 결과인지 성공 기준이 적혔는지 확인합니다.
  3. 빠졌거나 틀린 부분이 있으면 추가나 수정을 요청합니다.
  4. 계획이 마음에 들면 승인하고, 파일 수정을 자동으로 받아들일지 매번 물을지 고릅니다.
  5. 작업 중에도 정보를 더 주거나, 멈추게 하거나, 방향을 바꿉니다.
예시 프롬프트
방금 정리한 스펙대로 만들 계획을 먼저 보여 줘. 만들 파일 목록, 작업 순서, 다 됐는지 확인할 성공 기준을 적어 주고, 내가 승인하기 전에는 파일을 고치지 마.
  • 프롬프트는 최대한 구체적으로 씁니다.
  • 계획 모드에서는 Claude가 파일을 고칠 수 없고 읽기만 합니다.

컨텍스트 정리하며 이어가기

Claude Code

컨텍스트는 Claude의 작업 기억이라 읽은 파일과 메시지가 모두 공간을 차지합니다. 꽉 차면 자동 압축되며 세부 내용이 사라질 수 있으니 직접 확인하고 정리합니다.

따라 하기

  1. /context를 실행해 컨텍스트가 얼마나 찼는지, 무엇이 많이 차지하는지 확인합니다.
  2. 같은 기능을 계속 작업해야 하면 /compact로 지금까지의 내용을 요약합니다.
  3. 새 기능을 시작할 때는 /clear로 대화를 비웁니다.
  4. 지금 작업과 관계없는 MCP 서버는 끕니다.
  5. 다음 세션에도 기억해야 할 내용은 CLAUDE.md에 적습니다.
예시 프롬프트
/context
  • 압축하면 이전 대화의 세부 내용이 사라질 수 있습니다.
  • 프롬프트를 너무 짧게 쓰면 Claude가 파일을 더 많이 뒤지게 되어 오히려 컨텍스트를 더 씁니다.

verify로 직접 확인시키기

Claude Code

테스트만으로는 변경이 실제로 의도대로 동작하는지 알 수 없습니다. Claude Code에 들어 있는 verify 스킬로 Claude가 앱을 직접 실행해 확인하게 하면, 그 절차가 스킬로 남아 다음에도 씁니다.

따라 하기

  1. Claude Code에 포함된 verify 스킬을 처음 사용해 봅니다.
  2. Claude가 앱을 실행하고 변경 사항을 직접 확인하는 과정을 지켜봅니다.
  3. 성공한 확인 절차가 프로젝트에 스킬로 저장되었는지 확인합니다.
  4. 스킬에 항목별 통과 기준과 실패하면 무엇을 할지를 적어 둡니다.
  5. 다음 변경부터는 Claude가 실패하면 고쳐 다시 확인하는지 봅니다.
예시 프롬프트
방금 바꾼 화면이 실제로 잘 동작하는지 verify 스킬로 앱을 직접 실행해서 확인해 줘.
  • 통과 기준이 측정 가능할수록 Claude가 혼자 더 멀리 갑니다.
  • 같은 실수가 나오면 다시 시키지 말고 CLAUDE.md나 스킬에 적어 재발을 막습니다.

리뷰 받고 커밋하기

Claude Code

결과를 직접 확인해 만족하면, 저장(커밋)하기 전에 서브에이전트 코드 리뷰어로 한 번 더 점검합니다. 탐색 → 계획 → 코딩 → 커밋 흐름의 마지막 단계입니다.

따라 하기

  1. 결과를 직접 확인해 만족하는지 봅니다.
  2. 서브에이전트 코드 리뷰어로 이번 변경 내용을 점검하게 합니다.
  3. 리뷰에서 나온 문제를 고치게 하고 다시 확인합니다.
  4. 내 스타일에 맞는 커밋 메시지를 만들게 한 뒤 커밋합니다.
예시 프롬프트
서브에이전트 코드 리뷰어로 이번 변경 내용을 점검해 줘. 문제가 없으면 기존 커밋 스타일에 맞춰 커밋 메시지를 만들어 줘.
  • 커밋하려면 프로젝트가 Git으로 관리되고 있어야 합니다.
  • 탐색·리뷰만 하는 서브에이전트는 Sonnet 같은 작은 모델로도 충분합니다.

실수를 CLAUDE.md 규칙으로

Claude Code

Claude가 실수했을 때 매번 다시 시키는 대신 규칙으로 남기면 같은 실수가 줄어듭니다. 첫 작업에서 바로잡은 점을 정리해 두면 다음 작업이 훨씬 수월해집니다.

따라 하기

  1. Claude가 실수하면 같은 요청을 다시 하기 전에 무엇이 틀렸는지 정리합니다.
  2. 그 내용을 앞으로 지킬 규칙으로 CLAUDE.md나 스킬에 적어 달라고 요청합니다.
  3. 규칙끼리 서로 부딪히지 않는지 확인합니다.
  4. 다음 작업에서 같은 실수가 사라졌는지 확인합니다.
  5. 새 모델로 바꿨다면 /claude-api prompt-audit로 지침이 새 모델에 맞는지 점검합니다.
예시 프롬프트
