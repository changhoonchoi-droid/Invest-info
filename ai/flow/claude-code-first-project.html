Claude Code 설치·로그인하기

Claude Code

Claude Code를 내 컴퓨터에 설치하고 작업 폴더에서 처음 실행합니다. 실행한 폴더와 하위 폴더 전체에 접근 권한이 생기므로, 프로젝트용 폴더를 따로 만들어 그 안에서 실행합니다.

따라 하기

  1. Windows PowerShell에서는 공식 안내의 Invoke-RestMethod 설치 명령을, macOS에서는 공식 안내의 curl 설치 명령을 그대로 복사해 실행합니다.
  2. 터미널이 낯설면 VS Code 확장 패널에서 Claude Code를 검색해 Anthropic이 만든 확장을 설치합니다.
  3. 프로젝트용 새 폴더를 만들고 그 폴더로 이동합니다.
  4. claude를 입력해 실행하고 색상 테마를 고릅니다.
  5. Claude 계정(Pro, Max, Enterprise) 또는 API 키로 로그인합니다.
예시 프롬프트
claude
  • Homebrew나 winget으로 설치하면 자동 업데이트가 되지 않습니다.
  • 회사에 Enterprise 계정이 있으면 로그인할 때 그 옵션을 고릅니다.

권한 모드 익히기

Claude Code

Claude가 파일을 고치거나 명령을 실행하기 전에 얼마나 자주 허락을 받을지 정하는 기능입니다. 처음에는 매번 묻는 기본 모드로 Claude가 무엇을 하는지 지켜보는 것이 좋습니다.

따라 하기

  1. Claude Code를 실행한 상태에서 Shift + Tab을 눌러 모드를 바꿉니다.
  2. 기본 모드는 파일 수정과 명령 실행 전에 매번 허락을 묻습니다.
  3. Auto accept edits 모드는 파일 수정은 자동 승인하고 명령 실행은 계속 묻습니다.
  4. 입력창 아래 표시로 지금 모드를 확인한 뒤 요청합니다.
  • 권한 확인을 건너뛰면 실수를 미리 잡기 어려우니 익숙해질 때까지 기본 모드를 씁니다.
  • Claude가 작업하는 도중에도 내용을 더하거나 멈추거나 방향을 바꿀 수 있습니다.

CLAUDE.md로 규칙 정하기

Claude Code

CLAUDE.md는 Claude Code가 세션을 시작할 때마다 자동으로 읽는 메모 파일입니다. 쓰는 기술, 자주 쓰는 명령, 지켜야 할 규칙을 적어 두면 매번 설명하지 않아도 됩니다.

따라 하기

  1. 코드가 이미 있는 폴더라면 /init을 입력해 CLAUDE.md를 만듭니다.
  2. 빈 폴더라면 쓸 언어와 규칙을 말로 알려 주고 CLAUDE.md에 적어 달라고 요청합니다.
  3. 만들어진 파일에서 스택, 실행·테스트 명령, 코드 스타일 규칙을 확인하고 고칩니다.
  4. 처음부터 길게 쓰지 말고 같은 점을 여러 번 바로잡게 되면 그때 규칙을 더합니다.
예시 프롬프트
/init
  • 개인 취향은 사용자 수준 CLAUDE.md에 적으면 모든 프로젝트에 적용됩니다.
  • 같은 문제가 반복되면 해결 방법을 CLAUDE.md에 저장해 달라고 요청합니다.

질문받으며 요구사항 정하기

Claude Code

원하는 결과를 처음부터 자세히 적기 어렵다면 관심 영역만 알려 주고 Claude가 질문을 던져 요구사항을 끌어내게 합니다. 최신 모델에서는 계획 모드 대신 오토 모드와 질문 도구로 스펙을 만드는 방식이 권장됩니다.

따라 하기

  1. Shift + Tab을 눌러 auto mode로 전환합니다.
  2. /effort로 노력 수준을 정합니다.
  3. 만들 것의 관심 영역(대상 사용자, 해결할 불편)만 적고 결과는 과하게 정하지 않습니다.
  4. 같은 프롬프트에서 ask user question 도구로 나에게 질문하라고 명시합니다.
  5. Claude가 띄우는 질문에 차례로 답합니다.
  6. 작성된 스펙을 읽고 빠진 점이나 과한 점을 고칩니다.
예시 프롬프트
매주 팀 회의록(.md 파일)을 모아 결정 사항과 할 일만 뽑아 하나의 표로 만들어 주는 작은 프로그램을 만들고 싶어. 사용자는 코딩을 모르는 우리 팀원들이야. 결과를 내가 미리 정하지 않을 테니, ask user question 도구로 나에게 질문하면서 요구사항을 정리하고 스펙을 작성해 줘.
  • 예전 방식: 계획 모드로 읽기 전용 계획을 먼저 받았지만, 최신 모델에서는 오토 모드로 질문을 받으며 스펙을 정하는 쪽으로 바뀌었습니다.
  • 긴 마크다운 대신 정보 밀도가 높은 HTML 파일로 스펙을 받아 검토하는 방법도 있습니다.

스펙대로 만들게 하기

Claude Code

합의한 스펙을 기준으로 Claude가 코드를 쓰게 합니다. 성공 기준을 분명히 적어 두면 Claude가 스스로 확인하며 진행하고, 나는 중간 결과를 보고 방향만 바로잡으면 됩니다.

따라 하기

  1. 스펙에 '무엇이 올바른 결과인지' 성공 기준을 적어 달라고 합니다.
  2. 스펙대로 구현을 시작하라고 지시합니다.
  3. 파일 수정을 자동 승인할지 매번 물을지 정합니다.
  4. 진행 중 방향이 틀어지면 바로 멈추고 고칠 점을 말합니다.
  5. 완성되면 실행 방법을 물어 직접 실행해 봅니다.
예시 프롬프트
스펙대로 구현해 줘. 성공 기준은 '회의록 폴더를 지정하면 결정 사항·할 일·담당자 표가 엑셀 파일로 저장된다'야. 다 만들면 내가 실행하는 방법을 한 줄로 알려 줘.
  • 프롬프트는 구체적으로 씁니다. 짧게 쓰면 Claude가 코드베이스를 더 뒤지느라 컨텍스트를 더 씁니다.

컨텍스트 정리하며 이어 가기

Claude Code

컨텍스트는 Claude의 작업 기억으로, 읽은 파일과 대화가 모두 공간을 차지합니다. 한도에 가까워지면 자동 압축으로 세부 내용이 사라질 수 있으니 스스로 확인하고 정리합니다.

따라 하기

  1. /context로 컨텍스트가 얼마나 찼는지 확인합니다.
  2. 같은 기능을 이어 가면 /compact로 지금까지의 대화를 압축합니다.
  3. 새 기능을 시작할 때는 /clear로 대화를 비웁니다.
  4. 다음 세션에도 기억해야 할 내용은 CLAUDE.md에 적어 둡니다.
  5. 답만 필요한 조사는 서브에이전트에게 맡겨 요약만 받습니다.
예시 프롬프트
/context
  • 기능이 바뀌면 대화를 비웁니다. 이전 대화가 새 작업에 편향을 주지 않게 하기 위해서입니다.
  • 정답이 든 짧은 프롬프트가 긴 전체 기록보다 더 정확했다는 실험이 있습니다.

결과 검증하고 커밋하기

Claude Code

만든 결과가 성공 기준을 지키는지 직접 확인하고, 서브에이전트 코드 리뷰어로 한 번 더 점검한 뒤 변경 내용을 저장(커밋)합니다. 커밋해 두면 나중에 잘못돼도 되돌릴 수 있습니다.

따라 하기

  1. 성공 기준대로 동작하는지 직접 실행해 확인합니다.
  2. Claude에게 테스트를 만들어 프로젝트에 두게 합니다.
  3. 서브에이전트 코드 리뷰어로 변경 내용을 점검하게 합니다.
  4. 내 스타일에 맞는 커밋 메시지를 만들게 한 뒤 커밋합니다.
예시 프롬프트
커밋하기 전에 서브에이전트 코드 리뷰어로 변경 내용을 점검하고, 문제가 없으면 커밋 메시지를 만들어 줘.
  • 읽기 전용 리뷰 서브에이전트는 Sonnet이나 Haiku로도 충분해 사용량을 아낄 수 있습니다.
  • git이 설치되어 있지 않다면 Claude에게 내 운영체제에 맞는 설치 방법을 물어보세요.

휴대폰에서 이어 확인하기

Claude Code

내 컴퓨터에서 돌고 있는 세션에 휴대폰으로 접속해 진행 상황을 보고 이어서 지시할 수 있습니다. 도구와 파일은 내 컴퓨터에서 그대로 실행되므로 컴퓨터는 켜 두어야 합니다.

따라 하기

  1. 터미널에서 프로젝트 폴더로 이동합니다.
  2. claude remote-control을 실행합니다.
  3. 스페이스바를 눌러 QR 코드를 띄우고 휴대폰으로 스캔합니다.
  4. Claude 모바일 앱이나 모바일 브라우저에서 세션을 확인하고 이어서 지시합니다.
  5. 이미 실행 중인 세션이라면 그 세션에서 /remote-control을 입력합니다.
예시 프롬프트
claude remote-control
  • 컴퓨터를 꺼도 계속 돌아가야 하면 GitHub 저장소와 연결된 클라우드 세션을 씁니다.
  • 같은 계정으로 로그인되어 있으면 링크 없이 앱에서 세션을 찾을 수 있습니다.
