Claude Code 설치하고 로그인

Claude Code

터미널, VS Code·JetBrains, 데스크톱 앱 중 편한 방식을 고릅니다. 터미널이 낯설면 편집기나 데스크톱 앱이 더 쉽습니다. 구독 계정으로 로그인하는 것을 권합니다.

따라 하기

  1. macOS·Linux·WSL에서는 공식 안내에 나온 curl 설치 명령을 실행합니다.
  2. Windows PowerShell에서는 안내된 Invoke-RestMethod 명령을 사용합니다.
  3. VS Code는 확장 패널에서 Claude Code를 검색해 Anthropic이 만든 확장을 설치합니다.
  4. 작업할 프로젝트 폴더로 이동한 뒤 claude를 실행합니다.
  5. 색상 테마를 고르고 Claude 계정으로 로그인합니다.
  • 실행한 폴더와 그 하위 폴더 전체에 접근 권한이 생기니 폴더를 신중히 고르세요.
  • API 키 방식은 과금이 클 수 있어 구독 계정 로그인을 권합니다.
  • 터미널이 부담되면 데스크톱 앱의 Claude Code 모드를 쓰세요.

권한 모드와 계획 모드 익히기

Claude Code

파일을 고치기 전에 얼마나 허락을 구할지 정합니다. 처음에는 기본 모드로 시작하고 큰 작업은 계획 모드로 방향부터 잡습니다.

따라 하기

  1. 프로젝트 루트 폴더에서 Claude Code를 실행합니다.
  2. Shift + Tab을 눌러 모드를 바꿉니다. 기본 모드는 파일 수정·셸 명령 전에 매번 허락을 묻습니다.
  3. Plan mode로 전환하면 파일을 고치지 않고 읽기만 합니다.
  4. 구현하려는 내용과 알고 싶은 점을 구체적으로 요청합니다.
  5. 계획을 검토하고 좋으면 승인합니다.
예시 프롬프트
앱 전체에 다크 모드를 추가하고 싶어. 헤더에 토글 스위치를 만들고, 기존 라이트 테마와 어울리는 대비 색을 쓰도록 계획을 먼저 세워 줘.
  • 권한 무시는 작업 폴더 범위를 확인한 뒤에만 켭니다.

CLAUDE.md로 규칙 정하기

Claude Code

CLAUDE.md는 세션을 시작할 때마다 먼저 읽는 규칙 파일입니다. 스택, 명령어, 작업 규칙을 적어 두면 같은 설명을 반복하지 않아도 됩니다. 200줄 이내로 지도처럼 씁니다.

따라 하기

  1. 프로젝트 루트 폴더에서 Claude Code를 실행합니다.
  2. /init 명령을 실행해 코드베이스를 바탕으로 CLAUDE.md를 생성합니다.
  3. 스택, 명령어, 코드 스타일 규칙을 확인하고 필요한 내용을 고칩니다.
  4. 작업 중 반복해서 바로잡은 규칙은 메모리에 저장하라고 명시적으로 요청합니다.
예시 프롬프트
방금 바로잡은 규칙, 즉 보고서 숫자는 항상 천 단위 쉼표를 쓴다는 내용을 CLAUDE.md에 저장해 줘.
  • AI가 자동 생성한 설정 파일은 사람이 검수해야 합니다.
  • 처음에는 없이 시작해 계속 바로잡아야 하는 부분만 추가하면 간결해집니다.

탐색→계획→코딩→커밋 진행

Claude Code

먼저 읽고 계획한 뒤 구현하고, 검증과 리뷰를 거쳐 커밋하면 품질이 안정됩니다. 성공 기준을 분명히 적는 것이 중요합니다.

따라 하기

  1. 계획 모드에서 코드베이스를 탐색해 달라고 요청합니다.
  2. 계획에 무엇이 올바른 결과인지 성공 기준을 분명히 적습니다.
  3. 계획을 승인하고 구현을 진행합니다.
  4. 테스트 스위트를 프로젝트에 두어 Claude가 계속 검증하게 합니다.
  5. 직접 확인해 만족하면 서브에이전트 코드 리뷰어로 점검합니다.
  6. 내 스타일에 맞는 커밋 메시지를 만들게 한 뒤 푸시합니다.
예시 프롬프트
이 변경의 성공 기준은 기존 테스트가 모두 통과하고 로그인 화면에 오류가 없는 거야. 먼저 계획을 세우고, 구현 후 테스트까지 돌려서 결과를 알려 줘.
  • 같은 문제가 반복되면 해결책을 CLAUDE.md에 저장하도록 요청하세요.

컨텍스트 확인하고 정리하기

Claude Code

컨텍스트는 Claude의 작업 기억으로 읽은 파일·명령·대화가 모두 공간을 차지합니다. 슬래시 명령으로 상태를 보고 정리하면 긴 작업에서도 품질이 유지됩니다.

따라 하기

  1. /context를 실행해 컨텍스트 크기와 가장 많이 차지하는 항목을 확인합니다.
  2. 같은 기능 작업을 계속해야 하면 /compact로 지금까지 내용을 요약합니다.
  3. 새 기능을 시작할 때는 /clear로 대화를 완전히 비웁니다.
  4. 다음 세션에도 기억시킬 내용은 CLAUDE.md에 적습니다.
  • 압축하면 이전 대화의 세부 내용이 사라질 수 있습니다.
  • 안 쓰는 MCP 서버는 끄세요.
  • 궁금한 곁가지 질문은 데스크톱 앱에서 /btw로 물으면 본 대화에 쌓이지 않습니다.

스킬로 반복 작업 저장하기

스킬

스킬은 작업 방법을 한 번 가르쳐 두면 관련 상황에서 자동으로 적용되는 파일(SKILL.md)입니다. 항상 불러오는 CLAUDE.md와 달리 요청이 맞을 때만 로드되어 컨텍스트를 아낍니다.

따라 하기

  1. 잘 쓴 결과물 하나를 준비해 Claude에 업로드합니다.
  2. 이 양식으로 주간 보고서 스킬을 만들어 줘라고 요청합니다.
  3. 만들어진 스킬을 저장하고 세션을 재시작합니다.
  4. /를 입력해 스킬이 목록에 보이는지 확인합니다.
  5. 스킬 이름을 불러 호출하고 이번 주 자료만 넣습니다.
예시 프롬프트
이 보고서 양식으로 '주간 보고서' 스킬을 만들어 줘. 앞으로 이번 주 자료만 주면 같은 구성과 말투로 초안을 써 주게 해 줘.
  • 배포처럼 위험한 작업은 슬래시로 직접 호출하는 방식이 안전합니다.
  • 프로젝트 스킬은 저장소를 받은 팀원 모두가 자동으로 받습니다.

MCP로 외부 도구 연결하기

MCP

MCP는 Claude Code를 Linear, GitHub, 문서 서버 같은 외부 도구에 연결하는 표준입니다. 쓰지 않을 때도 도구 정의가 컨텍스트를 차지하니 안 쓰는 서버는 꺼 둡니다.

따라 하기

  1. 원격 서비스면 HTTP, 내 PC에서 도는 프로세스면 STDIO 유형을 고릅니다.
  2. 터미널에서 claude mcp add 명령으로 서버를 추가합니다.
  3. 세션 안에서 /mcp를 실행해 연결 상태를 확인합니다.
  4. 쓰지 않을 서버는 /mcp에서 비활성화합니다.
  • 범위는 local, user, project(.mcp.json, 팀 공유) 세 가지입니다.
  • gh 같은 CLI가 있으면 컨텍스트 효율이 더 좋습니다.
  • 커넥터 목록은 claude.com/connectors에서 볼 수 있습니다.

Hooks와 하네스로 규칙 강제하기

Hooks

CLAUDE.md의 지시는 가끔 지켜지지 않지만 Hook은 예외 없이 매번 실행됩니다. 자동 서식 정리, 위험 명령 차단 등에 씁니다. 지도(CLAUDE.md), 절차(스킬), 강제 규칙(Hooks)을 갖춘 환경을 하네스라고 합니다.

따라 하기

  1. .claude/settings.json 또는 /hooks에서 Hook을 설정합니다.
  2. 이벤트를 고릅니다. UserPromptSubmit, PreToolUse, PostToolUse, Notification, Stop을 쓸 수 있습니다.
  3. 편집 후 서식 정리라면 PostToolUse에 matcher를 Edit로 지정합니다.
  4. 위험 작업 차단은 PreToolUse Hook으로 만들고 막아야 하면 종료 코드 2로 끝냅니다.
  5. 팀과 공유하려면 .claude/settings.json을 저장소에 커밋합니다.
  • CLAUDE.md는 권고, Hooks는 강제입니다.
  • 권한 건너뛰기는 위험할 수 있으니 연습용 폴더에서 먼저 쓰세요.
