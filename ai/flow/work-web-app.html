코드 탭에서 작업 폴더 열기

Claude Code

개발이 처음이라면 데스크톱 앱의 코드 탭에서 시작하는 것이 가장 쉽습니다. Claude Code는 연 폴더와 그 아래 모든 폴더에 접근하므로 새 프로젝트 전용 폴더를 만들어 엽니다.

따라 하기

  1. 새 프로젝트용 빈 폴더를 만듭니다.
  2. Claude 데스크톱 앱에서 코드 탭으로 들어갑니다.
  3. 로컬 옆 버튼에서 폴더 열기를 선택해 그 폴더를 지정합니다.
  4. 워크스페이스 신뢰를 진행합니다.
  5. 필요한 자료 파일(예: 예시 데이터)을 폴더에 넣어 둡니다.
  • 코드 탭은 Pro(월 20달러) 이상에서 쓸 수 있습니다.
  • 익숙해지면 터미널(CLI)로 넘어가길 권합니다. 새 기능이 가장 먼저 나오는 곳이 터미널입니다.

인터뷰로 스펙 정하기

Claude Code

무엇을 원하는지 아직 흐릿할 때는 자세히 지시하기보다 Claude가 나를 인터뷰하게 합니다. 답을 모아 만든 스펙을 먼저 검토하면 엉뚱한 앱이 나오는 일을 막을 수 있습니다.

따라 하기

  1. 만들 앱의 관심 영역(대상 사용자, 해결할 불편)만 적고 결과는 지나치게 정하지 않습니다.
  2. 바로 만들지 말고 ask user question 도구로 질문하라고 명시합니다.
  3. Claude가 띄우는 질문에 하나씩 답합니다.
  4. 답이 끝나면 Claude가 정리한 스펙을 읽고 빠진 점을 고칩니다.
  5. 스펙에 '완성의 기준'을 확인 가능한 문장으로 넣습니다.
예시 프롬프트
회식비를 팀원끼리 나누는 간단한 앱을 만들고 싶어. 대상 사용자는 20~30명 규모 팀의 총무야. 바로 만들지 말고 ask user question 도구를 써서 나에게 필요한 것을 질문한 다음, 내 답을 바탕으로 스펙을 정리해 줘.
  • 스펙은 긴 마크다운 대신 정보 밀도가 높은 HTML 파일로 받으면 검토하기 쉽습니다.
  • '더 좋게 만들어' 같은 막연한 지시는 피합니다.
  • 예전 방식: 계획 모드로 먼저 계획을 받았지만, 최신 모델에서는 인터뷰로 스펙을 만들고 auto mode로 맡기는 방식이 소개됩니다.

화면 시안 먼저 받아 보기

Claude Code

코드를 짜기 전에 화면 시안을 여러 개 받아 보면 결과물이 훨씬 나아집니다. 클릭해 볼 수 있는 프로토타입으로 써 본 뒤 고른 시안을 구현합니다.

따라 하기

  1. Claude Code에서 Artifacts 탭으로 이동해 새 디자인을 만듭니다.
  2. 정한 스펙으로 화면 시안을 여러 개 만들어 달라고 요청합니다.
  3. 잘 된 점과 아쉬운 점을 댓글로 남깁니다.
  4. 세부 사항은 에디터에서 직접 고치고, 필요하면 새 시안을 더 요청합니다.
  5. 고른 시안으로 클릭해 볼 수 있는 프로토타입을 만들어 달라고 합니다.
  6. 써 보고 만족하면 구현을 지시합니다.
예시 프롬프트
지금 정한 스펙으로 회식비 정산 앱의 첫 화면 시안을 세 가지 만들어 줘. 휴대폰에서 쓰기 편해야 하고, 고른 시안은 클릭해 볼 수 있는 프로토타입으로 만들어 줘.
  • 회사 색·글꼴이 있다면 디자인 시스템을 먼저 만들어 두면 'AI 티'가 줄어듭니다.
  • 예전 방식: claude.ai/design에서 Prototype 프로젝트를 만들고 Handoff to Claude Code로 넘겼습니다.

Claude Code

스펙과 시안이 정해졌으면 구현을 맡기고, 권한 모드로 얼마나 자유롭게 맡길지 정합니다. 결과는 오른쪽 내장 브라우저에서 바로 써 보고 고칠 점을 다시 말합니다.

따라 하기

  1. 확정한 스펙·시안과 완성의 기준을 함께 적어 구현을 요청합니다.
  2. 파일 수정마다 확인하고 싶으면 기본 모드, 수정은 자동 승인하려면 Auto accept edits를 고릅니다 (터미널에서는 Shift+Tab).
  3. 작업 중에도 내용을 더하거나 방향을 바꿀 수 있습니다.
  4. 오른쪽 내장 브라우저에서 앱을 직접 써 봅니다.
  5. 필요하면 기본 브라우저에서 열기로 크롬에서 엽니다.
  6. 고칠 점은 하나씩 구체적으로 다시 요청합니다.
예시 프롬프트
확정한 스펙과 시안대로 회식비 정산 앱을 만들어 줘. 완성의 기준은 참석자를 추가하고 금액을 입력하면 1인당 금액이 바로 보이는 것이야. 다 만들면 직접 실행해서 확인해 줘.
  • 어떻게 만들지는 AI에게 맡기고 무엇을 만들지에 집중합니다.
  • 권한 확인을 건너뛰면 실수를 미리 잡기 어려우니 처음에는 승인 모드로 지켜보세요.

브라우저로 스스로 검증시키기

Claude Code

Claude Code는 테스트는 스스로 돌리지만 화면이 의도대로 동작하는지는 따로 확인해야 합니다. verify 스킬로 확인 절차를 만들어 두면 Claude가 앱을 열어 클릭해 보고, 틀리면 고친 뒤 다시 확인합니다.

따라 하기

  1. Claude Code에 포함된 verify 스킬을 사용해 변경 사항을 확인하게 합니다.
  2. Claude가 앱을 실행하고 클릭·스크린샷으로 확인하는지 지켜봅니다.
  3. 성공한 확인 절차가 프로젝트 스킬로 저장되었는지 확인합니다.
  4. 스킬에 확인 항목과 항목별 통과 기준을 숫자처럼 적어 넣습니다.
  5. Claude in Chrome 확장을 설치하면 Claude가 브라우저 탭에서 직접 테스트할 수 있습니다.
예시 프롬프트
verify 스킬로 방금 만든 정산 화면을 확인해 줘. 참석자 5명에 총액 25만 원을 넣었을 때 1인당 5만 원이 나오는지 직접 클릭해서 확인하고, 틀리면 고친 뒤 다시 확인해 줘.
  • 통과 기준을 측정할 수 있게 적을수록 Claude가 혼자 더 멀리 갑니다.
  • Claude가 만든 테스트가 맞는지 먼저 확인해 잘못된 통과를 막습니다.

CLAUDE.md에 규칙 남기기

Claude Code

CLAUDE.md는 Claude Code가 세션마다 자동으로 읽는 프로젝트 메모입니다. 기술 스택·실행 방법·금지 규칙과 작업 중 반복해서 바로잡은 내용을 적어 두면 다음 세션부터 같은 실수가 줄어듭니다.

따라 하기

  1. /init을 실행해 코드베이스를 바탕으로 CLAUDE.md 초안을 만듭니다.
  2. 프로젝트 개요(서비스, 기능, 기술 스택)를 읽고 고칩니다.
  3. 실행·테스트 명령과 건드리면 안 되는 폴더 같은 금지 규칙을 적습니다.
  4. 작업 중 반복해서 바로잡은 규칙은 CLAUDE.md에 저장하라고 요청합니다.
  5. 200줄 이내의 '지도'처럼 짧게 유지하고 자세한 절차는 스킬로 뺍니다.
예시 프롬프트
/init
  • AI가 자동으로 만든 내용은 사람이 꼭 검수합니다.
  • CLAUDE.md는 권고일 뿐입니다. 반드시 지켜야 하는 규칙은 훅(Hooks)으로 강제합니다.

따라 하기

  3. 새 기능을 시작할 때는 /clear로 대화를 비웁니다.
  4. 다음 세션에도 기억시킬 내용은 CLAUDE.md에 적습니다.

결과에 만족하면 코드 리뷰어 서브에이전트로 점검한 뒤 커밋해 저장합니다. GitHub에 올려 두면 클라우드 세션으로 노트북을 닫고도 이어서 작업을 맡길 수 있습니다.

따라 하기

  1. 결과를 직접 써 보고 만족하는지 확인합니다.
  2. 서브에이전트 코드 리뷰어로 변경 내용을 점검하게 합니다.
  3. 내 스타일에 맞는 커밋 메시지를 만들게 한 뒤 커밋합니다.
  4. GitHub 저장소에 푸시합니다.
  5. 큰 수정은 데스크톱 앱에서 Cloud를 골라 클라우드 세션에 맡기고, 끝나면 diff를 검토해 Create PR을 누릅니다.
예시 프롬프트
서브에이전트 코드 리뷰어로 이번 변경을 점검해 줘. 문제가 없으면 변경 내용을 요약한 커밋 메시지를 만들어 커밋해 줘.
