1. 환각 줄여서 AI 답변 믿고 쓰기

환각은 AI가 없는 내용을 사실처럼 말하는 현상입니다. 구체적인 통계, 인용, 날짜처럼 정확성이 중요한 업무에서 특히 조심해야 합니다. 몇 가지 요령으로 위험을 크게 줄일 수 있습니다.

  1. 숫자·통계·인용·정확한 날짜와 이름이 들어간 답변을 따로 표시해 둡니다.
  2. Claude에게 출처를 함께 달라고 요청합니다.
  3. 답변에 대해 확신도를 물어 불확실한 부분을 구분합니다.
  4. 중요한 내용은 새 대화를 열어 같은 질문으로 다시 검증합니다.
  5. 최신 내용이나 무명 주제는 직접 원문을 찾아 확인한 뒤 업무에 씁니다.
예시
방금 답변에서 숫자, 날짜, 인용이 들어간 부분을 모두 뽑아 주고, 각각 얼마나 확신하는지와 확인할 수 있는 출처를 알려 줘.
  • 환각은 1년 전보다 크게 줄었지만 해결된 문제는 아닙니다.
  • 횟수가 줄수록 확인을 건너뛰기 쉬우니 중요한 업무는 늘 검증하세요.
  • 구체적 사실, 통계, 인용, 무명 주제, 최신 내용에서 환각 가능성이 높습니다.

2. AI 편향 이해하고 대처하기

AI 편향은 고정관념, 정치적 편향, 특정 언어에서의 품질 차이 등으로 나타납니다. 보고서나 의견이 들어가는 글을 AI와 쓸 때 한쪽으로 기울지 않았는지 점검하는 방법을 익힙니다.

  1. 같은 주제를 서로 반대되는 두 관점으로 각각 질문합니다.
  2. 두 답변의 깊이와 노력, 어조가 비슷한지 비교합니다.
  3. 차이가 크면 어느 쪽이 더 약하게 쓰였는지 Claude에게 지적하고 다시 쓰게 합니다.
  4. 공개된 평가 데이터셋이 있다는 점을 알아 두고, 필요하면 같은 방식으로 직접 테스트합니다.
예시
이 주제에 찬성하는 입장과 반대하는 입장을 각각 같은 분량과 같은 수준의 근거로 설명해 줘.
  • Anthropic은 같은 주제를 두 관점으로 묻는 짝지은 프롬프트로 수천 개 프롬프트, 수백 개 주제를 평가합니다.
  • 평가 데이터셋은 공개되어 누구나 같은 테스트를 할 수 있습니다.

3. AI 조언에 휘둘리지 않고 결정하기

Anthropic 연구에 따르면 사람은 AI 에이전트의 기울기를 무의식적으로 따르면서 스스로 결정했다고 착각하기 쉽습니다. 계획 단계에서 AI에게 휘둘리지 않고 판단하는 세 가지 방법을 익힙니다.

  1. AI에게 추천을 받기 전에 내 우선순위를 먼저 정리해 적습니다.
  2. AI가 어떤 기준으로 우선순위를 물어보게 해서 내 기준을 먼저 드러냅니다.
  3. 고민되는 선택지는 말로 따지지 말고 작은 프로토타입을 만들어 비교한 뒤 결정합니다.
  4. AI에게 어떤 조건이면 조언을 바꾸겠느냐고 물어 의견이 얼마나 단단한지 확인합니다.
  5. 최종 결정 후 어느 부분이 AI의 논거였는지 출처를 따로 적어 둡니다.
예시
추천을 하기 전에 먼저 내 우선순위를 묻는 질문을 해 줘. 그리고 네 추천이 어떤 조건이면 바뀌는지도 알려 줘.
  • 연구에서 분석가는 에이전트가 기운 쪽을 86% 따랐고, 설명 시 77%가 에이전트 논거를 쓰면서도 출처로 밝힌 사람은 15%였습니다.
  • 한계: 에이전트의 기울기를 일부러 강화했고 한 분야·한 과제·한 모델만 연구했습니다.

4. Claude 모델 고르고 바꿔 쓰기

Claude에는 여러 모델이 있고 작업 성격에 따라 고르면 효율이 좋아집니다. 새 모델이 나왔을 때 내 업무에 맞는지 확인하는 방법까지 익힙니다.

  1. 유료 플랜 Claude에서 모델 전환 메뉴를 엽니다.
  2. 새로 출시된 Fable 5.2를 선택해 복잡한 작업을 맡겨 봅니다.
  3. 방향을 찾는 단계에는 Opus 5.5, 빠른 수정 단계에는 Sonnet 5.5를 고릅니다.
  4. 내가 자주 하는 업무 하나를 정해 두고 모델별로 같은 프롬프트를 돌려 비교합니다.
  5. 결과가 더 좋은 모델을 그 업무의 기본 모델로 정합니다.
예시
아래 보고서 초안을 임원 보고용으로 다듬어 줘. 핵심 결론을 맨 앞에 두고 숫자마다 해석을 한 줄씩 붙여 줘.
  • Fable 5.2는 벤치마크(Remote Labor Index)에서 지식 노동 과제 완료율이 Opus 5.5의 21%에서 41%로 올랐습니다.
  • 큰 작업은 사용량을 많이 씁니다. 슬라이드 덱 한 개를 약 30분 작업하는 데 ultra 플랜 사용량의 약 1.5%가 들었습니다.
  • 벤치마크와 실전은 다르니 직접 써 보고 고르세요. 예전 방식: 2월 영상에서는 Sonnet 4.6이 Free·Pro의 기본 모델이었습니다.

5. 채팅 하나로 문서·슬라이드·디자인 만들기

채팅과 Cowork가 하나의 Claude로 합쳐져, 어떤 대화에서든 문서, 슬라이드, 디자인을 기존 대화 내용을 바탕으로 만들 수 있습니다. 작업이 클라우드에서 돌아가 노트북을 닫아도 계속됩니다.

  1. Claude에서 평소처럼 대화를 시작해 만들고 싶은 내용의 배경을 설명합니다.
  2. 같은 대화에서 슬라이드, 문서, 디자인 중 필요한 결과물을 요청합니다.
  3. 하나의 브리프로 슬라이드, 소셜 이미지, 한 장짜리 요약 문서를 함께 요청해 봅니다.
  4. 결과물에서 고치고 싶은 부분에 코멘트를 달아 Claude에게 보냅니다.
  5. 작업 진행 상황은 휴대폰에서도 확인합니다.
예시
아래 신제품 출시 브리프를 바탕으로 10장짜리 발표 슬라이드와 소셜 이미지 세트, 현장 배포용 한 장 요약 문서를 만들어 줘.
  • Claude Slides, Claude Design, Claude Docs는 베타로 제공됩니다.
  • 기존 Cowork 작업도 그대로 유지됩니다.
  • Claude Docs에서는 팀원과 Claude가 같은 문서를 동시에 편집합니다.

6. Claude Design으로 앱·PPT 시안 만들기

Claude Design은 원하는 것을 일상 언어로 설명하면 제작 수준의 결과물을 만들어 주는 도구입니다. 먼저 회사 디자인 시스템을 만들어 두면 앱 프로토타입과 피치덱 모두에 색상·폰트·컴포넌트가 자동 적용됩니다.

  1. 웹에서 Claude Design에 접속합니다. 유료 구독(Pro·Max·Team·Enterprise)이 필요합니다.
  2. 회사의 디자인 시스템을 먼저 생성해 둡니다.
  3. 만들고 싶은 앱 프로토타입이나 피치덱을 일상 언어로 설명합니다.
  4. 결과를 보고 부분별로 수정을 요청합니다.
  5. 실제 서비스로 만들 때는 Claude Code로 넘겨 웹 서비스로 구현합니다.
예시
우리 회사 디자인 시스템을 적용해서 투자자용 12장짜리 피치덱을 만들어 줘. 문제, 해결책, 시장 규모, 팀 순서로 구성해 줘.
  • 디자인 시스템 없이 쓰면 결과물이 'AI스럽게' 나오기 쉽습니다.
  • 사용량 한도가 채팅·Claude Code와 별도이며, 영상 제작자는 Max 플랜에서 앱·PPT·디자인 시스템을 만들고 62%를 소진했습니다.
  • 웹에서만 쓸 수 있고 리서치 프리뷰로 공개된 기능입니다.

7. 화이트보드로 아이디어·계획 펼치기

Claude Artifacts에 새로 추가된 화이트보드는 아이디어 구상, 워크플로, 행사 계획을 시각적으로 펼쳐 보는 데 유용합니다. 시트와 데이터 기능도 함께 알아 두면 어떤 작업에 맞는지 가릴 수 있습니다.

  1. 유료 플랜 Claude에서 새 대화를 엽니다.
  2. 아이디어 구상, 업무 흐름, 행사 계획 중 펼쳐 보고 싶은 주제를 설명하며 화이트보드로 만들어 달라고 요청합니다.
  3. 만들어진 화이트보드를 보며 빠진 단계나 순서를 대화로 고칩니다.
  4. 표 계산이 필요하면 시트(Sheets), 대시보드는 이름이 바뀐 데이터(Data)를 선택합니다.
예시
다음 달 사내 워크숍 준비 계획을 화이트보드로 펼쳐 줘. 준비 단계, 담당, 일정이 한눈에 보이게 해 줘.
  • 시트·화이트보드·데이터는 모든 유료 플랜에서 쓸 수 있습니다.
  • 시트에는 피벗 테이블과 매크로가 없어 구글 시트를 대체하기는 어렵습니다.
  • 예전 방식: 지금의 데이터(Data)는 이전에 대시보드라고 불렀습니다.

8. Claude 모바일 앱 새 기능 설정하기

Claude 모바일 앱이 업데이트되어 계정 전환, 태블릿 화면 활용, 음성 모드, 언어 지원이 좋아졌습니다. 업무용과 개인용을 오가는 직장인이 알아 두면 편한 변경 사항입니다.

  1. iOS 또는 Android에서 Claude 앱을 최신 버전으로 업데이트합니다.
  2. 업무용과 개인 계정을 로그아웃 없이 함께 로그인해 필요할 때 전환합니다.
  3. iPad나 iPhone Duo에서는 아티팩트를 대화 옆 열에 열어 두 창을 나란히 씁니다.
  4. 음성 모드를 켜고, iPhone에서는 Apple CarPlay로도 사용합니다.
  5. 앱 언어를 원하는 언어로 바꿉니다.
  • 앱 인터페이스는 24개 언어가 추가되어 총 33개 언어를 지원합니다.
  • iPhone에서 사진을 고르면 업로드 중에도 바로 채팅에 표시됩니다.
  • iPhone·iPad의 당겨서 검색은 곧 제공될 예정입니다.

9. Slack에서 Claude Tag로 팀 업무 맡기기

Claude Tag는 Slack에서 팀과 함께 일하는 Claude입니다. 스레드에서 태그하면 채널 맥락을 파악해 작업하고, 끝나거나 입력이 필요할 때 알려 줍니다. 데이터 질문 답변이나 사내 문의 응대처럼 반복 업무에 맞습니다.

  1. Team 또는 Enterprise 요금제인지 확인합니다(베타).
  2. Slack 채널 스레드에서 Claude를 태그하고 맡길 일을 적습니다.
  3. 여러 사람이 같은 스레드에서 함께 추가 지시를 합니다.
  4. Claude가 작업을 끝내거나 입력이 필요하다고 알리면 확인하고 답합니다.

@Claude 이번 주 고객 문의 스레드를 훑어서 자주 나온 질문 3가지를 정리하고, 답변 초안도 만들어 줘.

10. Claude 데이터 보관 방식 이해하기

Claude Fable 5부터는 안전 모니터링을 위해 최근 30일의 프롬프트와 출력이 저장됩니다. 회사에서 민감한 자료를 다루는 직장인이 어떤 정보가 어떻게 보관되는지 알고 판단하도록 돕습니다.

  1. Fable 5 이후 모델을 쓰면 최근 30일 프롬프트·출력이 안전 모니터링용으로 저장된다는 점을 확인합니다.
  2. 자동 시스템이 이 데이터를 분석하며 기본적으로 Anthropic 직원은 읽을 수 없다는 점을 이해합니다.
  3. 회사 정책상 민감한 자료를 넣어도 되는지 보안 담당자와 확인합니다.
  4. 엔터프라이즈 조직이라면 Enterprise Frontier Safeguards(EFS)로 모니터링 데이터를 자체 클라우드에 보관할 수 있는지 문의합니다.
  • 엔터프라이즈 데이터는 명시적 허가 없이 학습에 쓰지 않습니다.
  • 사람의 검토는 자동 시스템이 유해 가능성을 표시한 드문 경우에만, 승인된 소수 검토자가 하며 접근 기록은 변조 불가 로그에 남습니다.
  • EFS는 올가을 이후 단계적으로 제공되며, 그 전까지 대상 조직은 Fable 5와 5.1에서 데이터 보관 없음(ZDR)을 받습니다.

11. AI 도입 때 일하는 규칙 다시 점검하기

AI로 만드는 속도가 빨라지면 병목이 검증·리뷰·유지보수로 옮겨 갑니다. 팀 업무 절차 중 지금도 필요한지 점검하는 방법을 정리합니다. 개발 직군이 아니어도 적용할 수 있습니다.

  1. 팀에서 가장 시간이 많이 드는 업무 절차 하나를 고릅니다.
  2. 그 절차가 지금도 필요한지, Claude로 줄일 수 있는지 따져 봅니다.
  3. 새 일이 들어오면 '이걸 안 하면 어떤 문제가 생길까?'를 먼저 묻습니다.
  4. 검증·리뷰 단계가 새 병목이 되지 않도록 담당과 기준을 정합니다.
  5. 모델이 좋아질 때마다 신뢰와 검증의 균형을 다시 평가합니다.
예시
우리 팀의 주간 보고 절차를 아래에 적을게. 지금도 필요한 단계와 Claude로 줄일 수 있는 단계를 나눠서 정리해 줘.
  • Claude Code 팀에서는 코딩이 더 이상 느린 단계가 아니며 새 병목은 검증·리뷰·유지보수입니다.
  • 프로세스는 스스로 사라지지 않고 쌓이므로 의식적으로 정리해야 합니다.
  • 일이 줄 것 같아도 새 일이 그 자리를 채워 더 바빠질 수 있습니다.
