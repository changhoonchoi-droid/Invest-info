1. Claude 모바일 앱 새 기능 쓰기

Claude 모바일 앱에 계정 전환, 분할 화면, 음성 모드 개선 등이 추가되었습니다. 출퇴근길이나 외근 중에 Claude를 업무에 쓰고 싶을 때 알아 두면 좋습니다.

  1. iOS 또는 Android 앱을 최신 버전으로 업데이트합니다.
  2. 업무용 계정과 개인 계정을 로그아웃 없이 모두 로그인해 둡니다.
  3. 필요할 때 계정을 바꿔 가며 업무와 개인 대화를 나눠 씁니다.
  4. iPad나 iPhone Duo에서는 Claude가 만든 아티팩트를 대화 옆 열에 열어 두 창을 나란히 봅니다.
  5. iPhone에서는 음성 모드를 Apple CarPlay에서 사용해 봅니다.
  6. iPhone에서 사진을 고르면 업로드 중에도 채팅에 바로 표시되는지 확인합니다.
  • 앱 인터페이스가 24개 언어가 추가되어 총 33개 언어를 지원합니다.
  • iPhone·iPad의 당겨서 검색은 곧 제공될 예정입니다. 웹과 데스크톱에는 이미 있고 Mac에서는 Command K를 씁니다.
  • Chromebook·폴더블의 Android 앱은 크기 조절 사이드바, 마우스 우클릭, Claude Desktop과 같은 단축키를 지원합니다.

2. AI 환각 줄이며 답 검증하기

환각은 AI가 없는 내용을 사실처럼 말하는 현상입니다. 보고서나 자료 조사에 AI를 쓸 때 틀린 정보를 걸러내는 습관을 만듭니다.

  1. 구체적인 사실·통계·인용, 무명 주제, 최신 내용, 정확한 날짜·이름·숫자는 환각 가능성이 높다고 먼저 인식합니다.
  2. AI에게 답의 출처를 함께 달라고 요청합니다.
  3. AI에게 방금 한 답에 얼마나 확신하는지 물어봅니다.
  4. 중요한 내용은 새 대화를 열어 같은 질문을 다시 하고 답이 일치하는지 비교합니다.
  5. 없는 논문 인용이나 가짜 통계가 있는지 출처를 직접 열어 확인합니다.
예시
방금 답에 쓴 수치와 인용마다 출처를 알려 줘. 확신이 낮은 부분은 따로 표시하고, 모르는 것은 모른다고 말해 줘.
  • Claude의 환각은 1년 전보다 크게 줄었지만 해결된 문제는 아닙니다.
  • 환각 횟수가 줄수록 확인을 건너뛰기 쉬우니 중요한 문서는 계속 점검합니다.

3. 화제가 된 AI 글 사실 확인하기

SNS에서 크게 퍼진 AI 관련 글도 작성자와 원문을 확인하면 달리 보일 수 있습니다. 회사 보고나 공유 전에 쓰는 간단한 점검법입니다.

  1. 글을 올린 작성자가 누구인지 프로필을 확인합니다.
  2. 글에 걸린 링크가 공식 자료나 공식 저장소인지 확인합니다.
  3. '96%' 같은 큰 숫자가 나오면 원 논문을 찾아 어떤 조건에서 나온 숫자인지 읽습니다.
  4. 표본 크기와 숫자의 정의를 확인합니다. 예를 들어 챗GPT 메모리 글의 96%는 사용자 80명의 메모리 2,050개 중 GPT가 사용자 요청 없이 스스로 만든 비율이었습니다.
  5. 확인한 내용을 한두 문장으로 정리한 뒤 공유합니다.
  • 조회수 200만 글이라도 작성자가 해당 회사 CEO이고 링크가 공식 저장소라면 신뢰할 근거가 되지만, 반대로 출처가 불분명하면 보류합니다.
  • 광고 점검이나 보안 점검 같은 공개 스킬도 이번 주에 직접 해 볼 거리로 제안되었습니다.

4. 베타 기능 제공 대상 먼저 확인하기

Claude 개인 금융과 Claude Duet처럼 새 기능은 베타나 연구 프리뷰로 일부 요금제·지역에만 열립니다. 써 보기 전에 대상과 안전 조건을 확인하는 방법입니다.

  1. 내 요금제가 대상에 있는지 확인합니다. 개인 금융은 미국의 Pro·Max·Ultra에 순차 제공되고, Duet은 미국의 Pro·Max 구독자 대상입니다.
  2. Duet처럼 대기자 명단 방식이면 명단에 등록해 열릴 때까지 기다립니다.
  3. 개인 금융을 쓸 수 있다면 연결할 계좌를 직접 골라 연결합니다.
  4. Claude의 계좌 접근이 읽기 전용인지 확인하고, 지출·청구서·잔액을 이해하기 쉽게 설명해 달라고 요청합니다.
  5. 더 이상 필요 없으면 언제든 계좌 연결을 해제합니다.
  6. Duet은 Claude가 대신 행동하기 전에 확인을 받는지 살펴보고, 중요한 일은 승인 전에 내용을 읽습니다.
  • 두 기능 모두 현재 한국 사용자에게 제공된다는 내용은 자료에 없으니 공식 안내를 확인하세요.
  • 개인 금융 영상은 자막이 거의 없어 제목과 설명을 바탕으로 정리한 것이라, 세부 화면은 다를 수 있습니다.

5. 하나의 Claude로 문서·슬라이드 만들기

채팅과 Cowork가 하나의 Claude로 합쳐져 모드를 고르지 않아도 됩니다. 대화 중에 문서, 슬라이드, 디자인을 만들고 코멘트로 수정하는 흐름을 익힙니다.

  1. Claude에게 만들고 싶은 결과를 말로 설명합니다. 방법은 Claude가 찾습니다.
  2. 문서, 슬라이드, 디자인이 필요한 대화에서 그대로 만들어 달라고 요청합니다.
  3. 하나의 출시 브리프만 주고 발표 자료, 소셜 이미지 세트, 한 장짜리 요약 문서를 함께 요청합니다.
  4. 결과물의 고칠 부분에 코멘트를 달아 Claude에게 보냅니다.
  5. Claude Docs에서는 팀원과 Claude가 같은 문서를 동시에 편집합니다.
  6. 긴 작업은 클라우드에서 돌아가므로 노트북을 닫고 휴대폰으로 진행 상황을 확인합니다.
예시
아래 출시 브리프를 바탕으로 발표용 슬라이드, 소셜 이미지 세트, 현장용 한 장 요약 문서를 만들어 줘.

6. Claude Design으로 앱·PPT 만들기

Claude Design은 일상 언어 설명만으로 제작 수준의 결과물을 만드는 도구입니다. 회사 디자인 시스템을 먼저 만들어 두면 앱 프로토타입과 PPT에 일관된 스타일이 적용됩니다.

  1. Pro·Max·Team·Enterprise 구독 중인지 확인합니다. 무료 플랜은 쓸 수 없습니다.
  2. 웹에서 Claude Design에 접속합니다. 웹에서만 사용할 수 있습니다.
  3. 먼저 회사의 디자인 시스템을 생성합니다.
  4. 만들어 둔 디자인 시스템이 색상·폰트·컴포넌트로 적용된 상태에서 앱 프로토타입을 요청합니다.
  5. 같은 디자인 시스템으로 12장짜리 피치덱 같은 PPT를 요청합니다.
  6. 실제 서비스가 필요하면 결과물을 클로드 코드로 넘겨 웹 서비스로 구현합니다.
  • 디자인 시스템 없이 쓰면 결과물이 'AI스럽다'는 평가가 있어 디자인 시스템 생성을 먼저 권합니다.
  • 사용량 한도가 채팅·클로드 코드와 별도로 관리됩니다. 영상 제작자는 Max 플랜에서 앱·PPT·디자인 시스템을 만들고 한도의 62%를 썼습니다.
  • 개발 철학은 문서보다 프로토타입을 우선하는 것입니다.
  • 2026년 4월 17일 리서치 프리뷰로 공개되었습니다.

7. AI 조언에 휘둘리지 않고 결정하기

Anthropic 연구에서 분석가들은 에이전트가 기운 쪽을 86% 따랐고, 자신이 직접 결정했다고 착각하기 쉬웠습니다. AI에게 계획이나 판단을 맡길 때 내 기준을 지키는 세 가지 방법입니다.

  1. AI가 추천하기 전에 내 우선순위를 먼저 묻게 합니다.
  2. 내 우선순위를 비용·속도·품질처럼 구체적으로 답합니다.
  3. 선택지가 갈리면 말로만 비교하지 말고 작은 프로토타입을 만들어 결과를 보고 정합니다.
  4. AI의 추천에 대해 어떤 조건이면 조언이 바뀔지 물어봅니다.
  5. 최종 결정을 설명할 때 AI의 논거를 가져왔다면 출처로 밝혀 둡니다.
예시
추천을 하기 전에 내 우선순위부터 질문해 줘. 추천한 뒤에는 어떤 조건이 바뀌면 다른 안을 추천할지도 알려 줘.
  • 연구에서 사전에 선호가 있던 분석가도 에이전트가 반대하면 60%가 선호를 바꿨습니다.
  • 설명할 때 77%가 에이전트의 논거를 썼지만 출처로 밝힌 사람은 15%였습니다.
  • 이 연구는 에이전트의 기울기를 일부러 강화했고 한 분야·한 과제·한 모델만 다뤘으니 한계를 감안해 읽습니다.

8. Slack에서 Claude Tag로 일 맡기기

Claude Tag는 Slack 채널에서 팀과 함께 일하는 Claude입니다. 스레드에서 태그하면 채널 맥락을 파악해 작업하고, 끝나거나 입력이 필요할 때 알려 줍니다.

  1. Team 또는 Enterprise 요금제에서 베타로 제공되는지 확인합니다.
  2. Slack 스레드에서 Claude를 태그하고 맡길 일을 적습니다.
  3. 여러 팀원이 같은 스레드에서 함께 지시를 보태게 합니다.
  4. Claude가 끝났거나 입력이 필요하다고 알려 주면 확인하고 답합니다.
  5. 채널별로 메모리가 쌓이니 반복되는 규칙은 해당 채널에서 알려 둡니다.
  6. 채널별 접근 범위와 자격 증명 사용 기록을 점검합니다.
  • 예전 방식: 사용자가 Claude를 열고 직접 요청해야 했습니다. Tag는 채널에서 필요한 때에 스스로 개입하고 며칠~몇 주 걸리는 일도 후속 확인까지 이어서 합니다.
  • Claude는 자기 계정과 권한을 가지며 모든 자격 증명 사용이 기록됩니다.
  • 비공개 채널이나 DM에서 배운 내용은 그 안에만 남습니다.
  • Anthropic은 제품 조직 PR의 약 65%를 Tag로 작성하며, 다른 사람의 사용법을 보며 모범 사례가 퍼집니다.

9. Claude 데이터 보관 방식 이해하기

Claude Fable 5부터 안전 모니터링을 위해 최근 30일의 프롬프트와 출력이 저장됩니다. 회사에서 도입할 때 보안 담당자와 함께 확인할 내용입니다.

  1. Claude Fable 5부터 최근 30일의 프롬프트와 출력이 안전 모니터링용으로 저장된다는 점을 확인합니다.
  2. 엔터프라이즈 데이터는 명시적 허가 없이 학습에 쓰지 않는다는 점을 확인합니다.
  3. 저장된 데이터는 자동 시스템이 분석하고, 사람의 검토는 유해 가능성이 표시된 드문 경우에만 승인된 소수 검토자가 한다는 점을 확인합니다.
  4. 조직 보안 요건이 엄격하면 Enterprise Frontier Safeguards(EFS)로 모니터링 데이터를 자체 클라우드에 보관하는 방안을 검토합니다.
  5. EFS가 제공되기 전까지 대상 조직은 Fable 5와 5.1에서 데이터 보관 없음(ZDR)을 받는다는 점을 확인합니다.
  • EFS는 올가을 이후 단계적으로 제공됩니다.
  • EFS는 로그를 고객이 통제하고, 검토는 기계로만 이뤄지며, 결과는 정해진 탐지 항목으로 제한됩니다.
  • 접근 기록은 변조 불가 로그에 남습니다.

10. 새 모델 나오면 내 업무로 평가하기

새 모델이 나올 때마다 내 업무에 맞는지 먼저 시험해 보는 방법입니다. 고객 팀들이 쓰는 평가(evals) 방식과 개발·운영에 모델을 나눠 쓰는 배벨 전략을 참고합니다.

  1. 새 모델을 받으면 자동화 평가(evals)를 백그라운드로 먼저 실행합니다.
  2. 법률 문서 초안 작성 같은 복잡한 실제 업무를 하나 맡겨 봅니다.
  3. 지금 안 되는 작업을 기록해 둡니다. 다음 모델이 나아질 영역의 단서가 됩니다.
  4. 모델 교체만으로 성공률이 얼마나 달라졌는지 숫자로 비교합니다.
  5. 개발·테스트처럼 판단이 중요한 곳에는 가장 큰 모델을, 운영과 파인튜닝에는 저렴한 모델을 나눠 씁니다.
  6. 폭주하는 프로세스에 대비해 서킷 브레이커를 둡니다.
  • 사례에서 모델 교체만으로 테스트 에이전트 성공률이 약 20% 올랐습니다.
  • Shopify는 모든 엔지니어에게 토큰을 제한 없이 주고 개발에는 가장 큰 모델을 씁니다.
  • LLM은 질문에 맞춰 답하려는 경향이 있으니 실제로 필요한 것을 정확히 요청하는 판단력이 더 중요합니다.

11. 루틴으로 반복 업무 맡기기

Claude Code 팀은 작업이 아니라 목표를 맡기고, 세션 밖에서 돌아가는 루틴으로 반복 일을 처리합니다. 개발 지식이 있는 분이 업무 자동화를 설계할 때 참고하세요.

  1. 매일 반복되는 일 중 하나를 고릅니다. 예를 들어 피드백 수집·분류입니다.
  2. 루틴을 일정, 웹훅, API 호출 중 하나로 시작하도록 정합니다.
  3. 루틴을 로컬 또는 원격 클라우드에서 실행할지 정합니다.
  4. 피드백을 중요도별로 분류하고 확신이 높은 것만 고치도록 지시합니다.
  5. 결과를 정기적으로 확인하고, 모델이 좋아져 필요 없어진 보조 기능은 과감히 지웁니다.
  • 모델 기반이 약 두 달마다 바뀌므로 모델의 약점을 메우려고 만든 기능은 주기적으로 점검합니다.
  • 질문이 필요하면 질문을 담은 HTML 아티팩트(다이어그램·목업 포함)를 쓰는 경우가 늘었습니다.
  • 에이전트 뷰와 루틴은 Claude Code 런던 기조연설에서 시연되었고, 루틴이 CI 자동 수정까지 맡는 흐름이 소개되었습니다.
  • 세부 설정 절차는 영상에서 다루지 않았으니 공식 문서를 함께 확인하세요.
