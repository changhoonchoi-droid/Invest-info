발표·소식

「발표·소식」 분야에서는 Claude의 새 모델과 업무 기능, 데이터 보관·안전 정책, 회사와 연구 소식을 직접 확인하고 내 업무에 연결하는 방법을 다룹니다. 먼저 새 소식을 믿고 읽는 법과 모델 고르는 법으로 기초를 잡고, 이어 업무용 새 기능(Docs·Slides·Design, 화이트보드·시트·데이터)을 써 본 뒤, 마지막으로 보관 정책과 AI 활용 태도 같은 고급 주제로 넘어가세요. 요금제와 제공 지역은 기능마다 달라서, 각 가이드의 첫 단계에서 내 요금제를 확인하는 습관을 권합니다.

1. 새 AI 소식 믿고 읽고 확인하기

AI 발표와 화제 글은 과장되거나 맥락이 빠진 채 퍼지는 일이 많습니다. 작성자·링크·원문을 확인하는 습관으로 소식을 걸러 내는 방법입니다. 업무에 새 도구를 들이기 전 판단 근거를 만드는 데 씁니다.

  1. 화제가 된 글의 작성자 프로필을 확인해 소속과 신뢰도를 봅니다.
  2. 글에 달린 링크가 공식 저장소나 공식 발표인지 확인합니다.
  3. 인용된 논문이 있으면 원문을 열어 조사 대상과 규모를 봅니다.
  4. 숫자(예: 96%)가 무엇의 비율인지 정의를 찾아 읽습니다.
  5. 소개 영상이나 글에 한계·적용 범위 언급이 있는지 찾습니다.
  6. 내 업무에 쓸 때는 작은 과제 하나로 직접 시험해 봅니다.
예시
아래 글의 주장을 점검해 줘. 1) 주장의 근거가 되는 원문이 무엇인지, 2) 숫자가 무엇의 비율인지, 3) 표본 크기와 한계가 무엇인지 표로 정리해 줘. 모르는 부분은 추측하지 말고 '확인 필요'라고 적어 줘.

[글 붙여넣기]
  • 영상 예시: 챗GPT 메모리 '96%' 글은 사용자가 요청하지 않고 GPT가 스스로 만든 메모리 비율이었습니다.
  • 조회수가 높다고 정확한 것은 아닙니다. 작성자와 링크 출처를 먼저 보세요.

2. AI의 환각 줄이고 답 검증하기

AI가 없는 논문이나 통계를 사실처럼 말하는 것이 환각입니다. 환각이 생기는 조건을 알고 출처 요청·확신도 질문·새 대화 검증으로 줄이는 방법입니다.

  1. 구체적 사실·통계·인용·날짜·이름·숫자가 나오면 환각 가능성이 높다고 의심합니다.
  2. 답을 받으면 출처를 알려 달라고 요청합니다.
  3. 답에 얼마나 확신하는지 물어봅니다.
  4. 중요한 내용은 새 대화를 열어 같은 질문을 하고 답을 비교합니다.
  5. 출처가 나오면 직접 열어 실제로 있는 자료인지 확인합니다.
예시
방금 답한 내용 중 구체적 수치와 인용을 모두 골라, 각각 출처와 확신도(높음/중간/낮음)를 표로 알려 줘. 확실하지 않으면 모른다고 말해 줘.
  • 환각은 1년 전보다 크게 줄었지만 해결된 문제는 아닙니다.
  • 횟수가 줄수록 확인을 건너뛰기 쉬우니 중요한 업무는 계속 점검하세요.
  • 자료가 적은 무명 주제와 최신 내용에서 특히 조심하세요.

3. AI 답을 이해하며 쓰고 편향 점검하기

AI 답을 복사해 전달만 하는 상태를 피하고, 내가 이해한 뒤 판단하는 방법입니다. AI 추천에 쉽게 끌리는 경향과 모델 편향도 함께 점검합니다.

  1. 리서치와 검증처럼 시간이 드는 일은 AI에게 맡깁니다.
  2. 제안서처럼 내가 책임질 문서는 빈 문서에서 AI와 한 줄씩 쓰며 질문합니다.
  3. AI에게 먼저 내 우선순위를 묻게 한 뒤 추천을 받습니다.
  4. 가능하면 작은 프로토타입으로 직접 비교해 결정합니다.
  5. AI에게 '어떤 조건이면 조언이 바뀌는가'를 물어봅니다.
  6. 같은 주제를 반대 관점으로도 물어 답의 깊이와 노력을 비교합니다.
  7. 일이 새로 들어오면 '이걸 안 하면 어떤 문제가 생길까'를 먼저 묻습니다.
예시
내 결정을 도와줘. 추천부터 하지 말고 먼저 내 우선순위를 세 가지 질문으로 물어봐 줘. 추천할 때는 어떤 조건이면 네 조언이 달라지는지도 함께 알려 줘.
  • Anthropic 연구에서 분석가들은 에이전트가 기운 쪽을 86% 따랐고, 설명할 때 에이전트 논거를 쓰고도 출처로 밝힌 사람은 15%였습니다.
  • 이 연구는 기울기를 일부러 강화했고 한 분야·한 모델만 다뤘으므로 그대로 일반화하지 마세요.
  • 결과물을 많이 만드는 능력보다 무엇을 만들고 버릴지 판단하는 능력이 중요해진다는 의견이 있습니다.

4. 새 모델 고르고 직접 평가하기

Fable 5.2 등 새 모델이 나올 때 모델 전환 메뉴에서 골라 쓰고, 내 업무 기준으로 직접 평가하는 방법입니다. 벤치마크만 믿지 않고 실제 과제로 확인합니다.

  1. 내 요금제가 유료인지 확인합니다.
  2. 대화창의 모델 전환 메뉴에서 새 모델을 선택합니다.
  3. 평소 쓰던 실제 업무 과제를 같은 프롬프트로 이전 모델과 새 모델에 각각 맡깁니다.
  4. 결과의 일관성, 수정 횟수, 걸린 시간, 사용량을 비교해 적습니다.
  5. 방향 잡기는 큰 모델, 빠른 수정은 작은 모델처럼 단계별로 나눠 씁니다.
  6. 지금 안 되는 작업은 기록해 두었다가 다음 모델에서 다시 시험합니다.
예시
아래 업무를 처음부터 끝까지 수행해 줘. 먼저 작업 계획을 세우고, 끝나면 내가 확인해야 할 부분을 목록으로 알려 줘.

[내 업무 설명]
  • 영상에서는 Fable 5.2의 지식 노동 과제 완료율이 Opus 5.5의 21%에서 41%로 올랐다고 소개합니다.
  • Claude 5.5 계열은 Opus 5.5로 방향을 찾고 Sonnet 5.5로 빠르게 고치는 식을 권합니다.
  • 사용량 한도를 쓰는 속도가 모델마다 다르니 큰 작업 전에 확인하세요.
  • 예전 방식: 벤치마크 점수만 보고 모델을 골랐지만, 영상은 직접 평가를 돌려 보길 권합니다.

5. Claude Slides·Design·Docs로 문서 만들기

하나의 브리프로 발표 자료, 이미지 세트, 한 장짜리 문서를 대화 안에서 만들고 코멘트로 고치는 기능입니다. 출시나 보고처럼 여러 형식의 결과물이 필요할 때 씁니다.

  1. 내 요금제에서 해당 기능이 열려 있는지 확인합니다(베타).
  2. 만들고 싶은 내용을 담은 브리프를 대화에 작성합니다.
  3. 필요한 결과물(슬라이드, 소셜 이미지, 한 장 문서)을 요청합니다.
  4. 결과물에서 고칠 부분에 코멘트를 답니다.
  5. 코멘트를 Claude에게 보내 그 부분을 수정시킵니다.
  6. 어느 대화에서든 문서·슬라이드·디자인을 만들 수 있고 기존 대화 내용이 바탕이 됩니다.
예시
아래 브리프로 발표용 슬라이드 8장, 소셜 이미지 3종, 현장 배포용 한 장 요약 문서를 만들어 줘.

[제품·행사 브리프]
  • 회사 디자인 시스템을 먼저 만들어 두면 색상·폰트가 자동 적용되어 결과물이 덜 'AI스럽다'는 후기가 있습니다.
  • Claude Design은 사용량 한도가 채팅·Claude Code와 별도로 관리되고 빡빡하다는 평가가 있어 한도를 확인하세요.
  • Claude Docs에서는 팀원과 Claude가 같은 문서를 동시에 편집할 수 있습니다.

6. 화이트보드·시트·데이터 기능 쓰기

Claude에 추가된 Whiteboards, Sheets, Data는 아이디어 정리, 수식 시트, 대시보드 작업을 맡깁니다. 무엇에 쓰고 무엇은 다른 도구가 낫기도 한지 알고 고릅니다.

  1. 유료 요금제인지 확인합니다. 세 기능 모두 유료 요금제에서 쓸 수 있습니다.
  2. 아이디어 구상이나 워크플로·행사 계획은 화이트보드에 펼쳐 달라고 요청합니다.
  3. 수식이 필요한 표는 시트로 만들고, 편집된 부분의 표시를 확인합니다.
  4. 데이터 분석은 Claude Data(옛 dashboards)에서 대시보드를 만들어 공유합니다.
  5. 피벗 테이블이나 매크로가 필요하면 기존 스프레드시트 도구를 함께 씁니다.
예시
신제품 출시 행사 준비를 화이트보드로 정리해 줘. 일정, 담당, 위험 요소를 세 영역으로 나눠 줘.
  • Whiteboards와 Sheets는 베타입니다. Claude Data도 인증 쿼리와 실시간 공유는 아직 베타입니다.
  • 한 리뷰에서는 시트에 피벗 테이블과 매크로가 없어 구글 시트를 대체하기 어렵다고 평가했습니다.
  • 모든 작업은 각자 가진 권한 안에서 이뤄집니다.

7. Claude Meetings와 인터랙티브 커넥터 쓰기

Claude Meetings는 통화에 참가자로 들어와 노트를 쓰고, 요청하면 문서나 화이트보드를 만듭니다. 인터랙티브 커넥터는 연동한 앱을 Claude 안에서 바로 엽니다.

  1. Meetings는 Team 또는 Enterprise 요금제인지 확인합니다(베타).
  2. 회의에 Claude를 참가자로 들어오게 합니다.
  3. 회의 중 필요할 때 문서나 화이트보드를 만들어 달라고 요청합니다.
  4. 회의 후 Claude가 쓴 노트를 검토하고 고칩니다.
  5. 연동 앱이 있으면 인터랙티브 커넥터로 Claude 안에서 바로 엽니다.
예시
지금까지 논의한 내용으로 결정 사항과 담당자별 할 일을 문서로 정리해 줘.
  • 인터랙티브 커넥터는 모든 요금제에 순차 제공 중이라 아직 안 보일 수 있습니다.
  • 모든 작업은 각자 가진 권한 안에서 이뤄집니다.

8. Slack에서 Claude Tag로 팀 업무 맡기기

Claude Tag는 Slack 스레드에서 Claude를 호출해 채널 맥락을 보고 작업하게 하는 기능입니다. 여러 사람이 함께 지시하고, 채널별 메모리가 쌓입니다.

  1. Team 또는 Enterprise 요금제에서 베타로 쓸 수 있는지 확인합니다.
  2. Slack 스레드에서 Claude를 태그합니다.
  3. 맡길 일과 기대하는 결과를 적습니다.
  4. Claude가 끝났거나 입력이 필요하다고 알리면 확인합니다.
  5. 같은 스레드에서 다른 팀원이 추가 지시를 줄 수 있습니다.
  6. 채널별 지시가 메모리로 쌓이는지 지켜보며 필요하면 고칩니다.

9. Claude 모바일 앱 새 기능 활용하기

모바일 앱에서 업무·개인 계정 전환, 태블릿 두 창 사용, 음성 모드, 언어 지원이 개선되었습니다. 이동 중이나 외근 때 Claude를 쓰는 방법입니다.

  1. 앱을 최신 버전으로 업데이트합니다.
  2. iOS·Android에서 업무용과 개인 계정을 로그아웃 없이 동시에 로그인해 전환합니다.

  4. 음성 모드를 켜고 말로 질문합니다. iPhone은 Apple CarPlay도 지원합니다.

10. 데이터 보관 방식과 기업용 보호 이해하기

Claude Fable 5부터 안전 모니터링을 위해 최근 30일의 프롬프트와 출력이 저장됩니다. 회사에서 쓰기 전에 보관 범위와 기업용 옵션을 알아 두는 방법입니다.

  1. 내 조직이 Fable 5 이후 모델을 쓰는지 확인합니다.
  2. 30일간 프롬프트와 출력이 안전 모니터링용으로 저장된다는 점을 보안 담당자와 공유합니다.
  3. 엔터프라이즈 데이터는 명시적 허가 없이 학습에 쓰지 않는다는 점을 확인합니다.
  4. 자동 시스템이 분석하고, 사람 검토는 유해 가능성이 표시된 드문 경우에 승인된 소수만 한다는 점을 정리합니다.
  5. 모니터링 데이터를 자체 클라우드에 두고 싶으면 Enterprise Frontier Safeguards(EFS)를 검토합니다.
  6. EFS 제공 전까지 대상 조직은 Fable 5와 5.1에서 데이터 보관 없음(ZDR)을 받는지 확인합니다.
  • EFS는 올가을 이후 단계적으로 제공됩니다.
  • EFS는 로그를 고객이 통제하고 검토를 기계로만 하며 결과는 정해진 탐지 항목으로 제한된다고 설명됩니다.
  • 정확한 적용 대상은 Anthropic 공식 안내로 확인하세요.

11. API 비용 아끼는 프롬프트 캐싱과 모델 전환

Claude API를 쓰는 개발자나 담당자가 비용을 관리하고 모델을 점진적으로 바꾸는 요령입니다. 프롬프트 캐싱과 평가(eval) 중심으로 정리합니다.

  1. 프롬프트 캐싱을 비용 관리의 첫 번째 수단으로 적용합니다.
  2. 대화 중간에 effort나 시스템 프롬프트를 바꿔도 캐싱이 깨지지 않는다는 점을 활용합니다.
  3. 새 모델이 나오면 내 업무 기준의 평가(eval)를 직접 돌립니다.
  4. 확장 사고에서 적응형 사고로 옮길 때는 한동안 이전 방식으로 되돌릴 수 있으니 점진적으로 옮깁니다.
  5. 새 모델마다 평가 결과를 기록해 모델 교체 효과를 비교합니다.
  • 모델 교체만으로 테스트 에이전트 성공률이 약 20% 올랐다는 고객 사례가 있습니다.
  • Claude Managed Agents는 Messages API 위에 만들어졌습니다.
  • Shopify는 개발·테스트에는 큰 모델, 운영에는 저렴한 모델을 쓰는 방식을 권하고, 폭주에 대비한 서킷 브레이커도 필요하다고 말합니다.
