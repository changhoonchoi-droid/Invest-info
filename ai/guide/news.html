1. Claude 모바일 앱 새 기능 쓰기

Claude 모바일 앱이 업데이트되어 계정 전환, 태블릿 화면 활용, 음성 모드가 좋아졌습니다. 업무와 개인 용도로 Claude를 나눠 쓰거나 이동 중에 음성으로 쓰고 싶을 때 유용합니다.

  1. iOS 또는 Android에서 Claude 앱을 최신 버전으로 업데이트합니다.
  2. 업무용 계정과 개인 계정을 로그아웃 없이 모두 로그인해 둡니다.
  3. 상황에 맞게 두 계정을 오가며 사용합니다.
  4. iPad나 iPhone Duo에서는 Claude가 만든 아티팩트를 대화 옆 열에 열고 두 창을 나란히 놓고 씁니다.
  5. 이동 중에는 더 빨라진 음성 모드를 쓰고, iPhone에서는 Apple CarPlay로도 이용합니다.
  6. 앱 인터페이스 언어가 총 33개로 늘었으니 필요하면 언어를 바꿔 봅니다.
  • iPhone·iPad의 당겨서 검색은 곧 제공될 예정이며, 웹·데스크톱에는 이미 있습니다(Mac은 Command K).
  • iPhone에서 사진을 고르면 업로드 중에도 바로 채팅에 표시됩니다.
  • Chromebook·폴더블의 Android 앱은 크기 조절 사이드바와 마우스 우클릭을 지원합니다.

2. 대화에서 문서·슬라이드·디자인 만들기

Claude 안에서 문서, 슬라이드, 디자인을 대화 흐름 그대로 만들 수 있습니다. 출시 브리프 하나로 발표 자료와 이미지, 한 장짜리 요약을 한 번에 만들고 싶을 때 씁니다.

  1. 만들 결과물의 배경(목적, 대상, 핵심 메시지)을 대화로 먼저 정리합니다.
  2. 같은 대화에서 문서, 슬라이드, 디자인 중 필요한 것을 요청합니다. 기존 대화 내용이 바탕이 됩니다.
  3. 결과물의 고치고 싶은 부분에 코멘트를 달아 Claude에게 보냅니다.
  4. Claude Docs에서는 팀원과 Claude가 같은 문서를 동시에 편집합니다.
  5. 회사 색상·폰트가 중요하면 Claude Design에서 디자인 시스템을 먼저 만들어 둡니다.
예시
위 대화에서 정리한 신제품 출시 브리프를 바탕으로 ① 발표용 슬라이드 ② SNS용 이미지 세트 ③ 현장 직원용 한 장 요약 문서를 만들어 줘.
  • 예전 방식: 채팅과 Cowork 중 모드를 골랐지만, 이제 하나의 Claude로 합쳐져 어느 대화에서든 만들 수 있습니다.
  • Claude Design은 디자인 시스템 없이 쓰면 결과물이 'AI스럽다'는 평가가 있어 먼저 만들어 두기를 권합니다.
  • Claude Slides·Design·Docs는 베타이고, Claude Design은 4월에 리서치 프리뷰로 공개되어 Pro 이상 구독과 별도 사용량 한도가 있었습니다. 현재 조건은 직접 확인하세요.

3. AI 답변의 환각 줄이고 검증하기

환각은 AI가 없는 내용을 사실처럼 말하는 현상입니다. 업무 문서에 숫자나 인용을 쓰기 전에 점검하는 습관이 필요합니다.

  1. 구체적 사실, 통계, 인용, 정확한 날짜·이름·숫자가 들어간 답변은 특히 의심하며 읽습니다.
  2. AI에게 답변의 근거가 되는 출처를 달라고 요청합니다.
  3. 답변의 각 부분에 대해 얼마나 확신하는지 물어봅니다.
  4. 중요한 내용은 새 대화를 열어 같은 사실을 다시 확인합니다.
  5. 출처가 있다면 직접 열어 실제로 그런 내용이 있는지 확인합니다.
예시
방금 답변에서 구체적인 사실, 숫자, 인용마다 출처를 달아 줘. 그리고 확신이 낮은 부분은 따로 표시해 줘.
  • 자료가 적은 무명 주제와 최신 내용에서 환각 가능성이 높습니다.
  • Claude의 환각은 1년 전보다 크게 줄었지만 해결된 문제는 아닙니다. 횟수가 줄수록 확인을 건너뛰기 쉬우니 주의하세요.
  • 정치적 편향 점검용 평가 데이터셋은 공개되어 있어 누구나 같은 테스트를 해 볼 수 있습니다.

4. Claude 개인 금융 기능 알아보기

개인 금융(Personal Finance)은 계좌를 연결해 지출, 청구서, 잔액을 쉬운 말로 설명받는 베타 기능입니다. 가계 흐름을 대화로 파악하고 싶을 때 씁니다.

  1. 내 요금제와 지역이 대상인지 확인합니다. 현재 미국의 Pro, Max, Ultra 요금제에 순차 제공됩니다.
  2. 기능이 열리면 연결할 계좌를 직접 고릅니다.
  3. Claude의 접근은 읽기 전용이라는 점을 확인하고 연결합니다.
  4. 지출, 청구서, 잔액에 대해 궁금한 점을 질문합니다.
  5. 더 이상 필요 없으면 언제든 연결을 해제합니다.
예시
연결한 계좌의 지난달 지출을 항목별로 정리하고, 이번 달 청구서 중 확인해야 할 것을 알려 줘.
  • 현재 베타이고 미국 요금제 대상이라 국내 사용자는 바로 쓰지 못할 수 있습니다.
  • 필요한 계좌만 골라 연결하고, 쓰지 않을 때는 해제하세요.

5. AI 조언에 휘둘리지 않고 결정하기

Anthropic 연구에서 분석가들은 에이전트가 기운 쪽을 86% 따랐고, 설명할 때 77%가 에이전트의 논거를 쓰면서도 출처로 밝힌 사람은 15%뿐이었습니다. AI와 함께 계획·분석할 때 스스로 결정했다고 착각하지 않게 돕는 방법입니다.

  1. AI에게 추천을 구하기 전에 내가 중요하게 보는 우선순위를 먼저 적습니다.
  2. AI가 우선순위를 먼저 묻도록 지시합니다.
  3. 의견이 갈리는 선택은 말로 따지기보다 프로토타입을 만들어 비교해 결정합니다.
  4. AI가 추천하면 어떤 조건이면 그 조언이 바뀌는지 묻습니다.
  5. 최종 결정에 AI 논거를 썼다면 보고서나 설명에 출처로 밝힙니다.
예시
추천을 하기 전에 먼저 내 우선순위를 질문해 줘. 추천 후에는 어떤 조건이 바뀌면 네 조언도 달라지는지 알려 줘.
  • 선호가 있던 사람도 에이전트가 반대하면 60%가 선호를 바꿨습니다.
  • 한계: 이 연구는 에이전트의 기울기를 일부러 강화했고, 한 분야·한 과제·한 모델만 다뤘습니다.

6. 새 모델을 내 업무로 시험하기

모델은 자주 바뀌므로, 벤치마크 대신 내 업무로 직접 시험해 보는 습관이 도움이 됩니다. 새 모델이 나왔을 때 바꿔 쓸지 판단하는 방법입니다.

  1. 평소 맡기는 대표 업무 3~5개를 질문 목록으로 정리해 둡니다.
  2. 새 모델이 나오면 같은 질문을 새 모델과 기존 모델에 똑같이 돌립니다.
  3. 결과를 같은 기준(정확도, 문체, 수정 횟수)으로 비교합니다.
  4. 법률 문서 초안처럼 복잡한 작업도 한두 개 맡겨 봅니다.
  5. 지금 잘 안 되는 작업은 기록해 두고 다음 모델이 나올 때 다시 시험합니다.
예시
아래 업무 질문 5개를 같은 조건으로 답해 줘. 각 답변 끝에 확신이 낮은 부분을 표시해 줘.
  • Anthropic 5.5 계열은 Opus 5.5로 방향을 찾고 Sonnet 5.5로 빠르게 고치는 식의 구분이 소개되었습니다.
  • 벤치마크와 실전 경험은 다르니 직접 써 보고 고르라는 조언이 있습니다.
  • 지금 안 되는 작업이 다음 모델이 나아질 영역의 단서라고 보는 팀들이 있습니다.

7. 클라우드에서 계속 도는 작업 맡기기

9월 업데이트로 Claude의 작업이 클라우드에서 돌아가 노트북을 닫아도 이어집니다. 오래 걸리는 일을 맡기고 휴대폰으로 진행 상황을 확인하고 싶을 때 씁니다.

  1. 원하는 결과를 목표 중심으로 말합니다. 방법은 Claude가 찾습니다.
  2. 작업을 시작한 뒤 노트북을 닫아도 됩니다.
  3. 휴대폰으로 진행 상황을 확인합니다.
  4. 큰 방향을 잡을 때는 Opus 5.5를, 빠른 수정 단계에서는 Sonnet 5.5를 씁니다.
  5. 결과를 확인하고 필요한 부분만 다시 요청합니다.
예시
이번 주 고객 피드백을 모아 주제별로 정리한 보고서를 만들어 줘. 끝나면 요약부터 보여 줘.
  • 예전 방식: 채팅과 Cowork를 나눠 골랐지만 지금은 하나로 통합되었고, 기존 Cowork 작업은 그대로 유지됩니다.
  • Claude Code 팀은 작업이 아니라 목표를 맡기는 방식으로 옮겨 갔다고 말합니다.

8. Slack에서 Claude Tag로 팀 일 맡기기

Claude Tag는 Slack 스레드에서 Claude를 태그해 팀과 함께 일하게 하는 기능입니다. 채널 맥락을 파악하고, 끝나거나 입력이 필요할 때 알려 줍니다.

  1. Team 또는 Enterprise 요금제에서 베타로 제공되는지 확인합니다.
  2. Slack 스레드에서 Claude를 태그해 할 일을 맡깁니다.
  3. 여러 사람이 같은 스레드에서 함께 지시할 수 있습니다.
  4. Claude가 끝났다고 알리거나 입력을 요청하면 답합니다.
  5. 채널별 지시가 메모리로 쌓이니 반복되는 규칙은 채널에 남겨 둡니다.
  6. 관리자는 채널별 접근 범위와 자격 증명 사용 기록을 확인합니다.
  • Claude는 자기 계정과 권한을 가지며, 비공개 채널이나 DM에서 배운 내용은 그 안에만 남습니다.
  • 데이터 질문 답변, PR 작성, 버그 수정, 사내 문의 응대에 쓰입니다.
  • Microsoft Teams 등으로 확대할 계획입니다.

9. Claude 데이터 보관 방식 확인하기

Claude Fable 5부터 안전 모니터링을 위해 최근 30일의 프롬프트와 출력이 저장됩니다. 회사에서 민감한 자료를 다루기 전에 어떤 보관 정책이 적용되는지 알아 두는 가이드입니다.

  1. Fable 5 이후 모델은 최근 30일의 프롬프트와 출력이 저장된다는 점을 확인합니다.

10. 루틴으로 반복 업무 자동화하기

Claude Code의 루틴은 사람이 지시하지 않아도 일정, 웹훅, API 호출로 시작되어 로컬이나 원격 클라우드에서 실행됩니다. 매일 반복되는 확인·정리 업무에 쓰는 고급 방법입니다.

  1. 자동으로 돌릴 반복 업무를 하나 고릅니다.
  2. 시작 조건을 일정, 웹훅, API 호출 중에서 정합니다.
  3. 실행 위치를 로컬 또는 원격 클라우드로 정합니다.
  4. 루틴이 할 일을 목표 중심으로 적습니다.
  5. 처음에는 결과를 사람이 확인하고, 안정되면 확신이 높은 것만 자동 처리하게 합니다.
예시
매일 들어온 고객 피드백을 모아 중요도별로 분류하고, 확신이 높은 것만 수정해 줘.
  • Claude Code 팀은 로컬 실행에서 클라우드 실행으로 넘어가며 세션 밖에서 도는 루틴이 가능해졌다고 설명합니다.
  • 에이전트 뷰로 여러 작업을 관리할 수 있습니다.
  • 세부 메뉴 사용법은 영상에서 다루지 않으니 공식 문서를 확인하세요.

11. AI 시대 업무 절차 점검하기

AI로 만드는 속도가 빨라지면 병목이 검증·리뷰·유지보수로 옮겨 갑니다. 팀의 업무 절차를 한 번 다시 보고 줄일 것을 찾는 방법입니다.

  1. 팀에서 가장 소모적인 업무 절차 하나를 고릅니다.
  2. 그 절차가 지금도 필요한지 묻습니다. 일이 들어오면 '이걸 안 하면 어떤 문제가 생길까?'를 먼저 묻습니다.
  3. 필요하다면 Claude로 줄일 수 있는지 확인합니다.
  4. 새 병목이 된 검증·리뷰 단계의 규칙을 다시 씁니다.
  5. 모델이 빠르게 바뀌므로 몇 달마다 기존 방식을 다시 의심해 봅니다.
예시
우리 팀의 [업무 절차] 단계를 설명할게. 이 절차가 지금도 필요한지, 안 하면 어떤 문제가 생기는지, Claude로 줄일 수 있는 부분이 어디인지 알려 줘.
  • Anthropic은 계획을 6개월 로드맵 대신 필요한 때 하는 방식으로 바꿨습니다.
  • Shopify는 개발에는 가장 큰 모델을, 운영에는 저렴한 모델을 쓰는 방식을 권하고, 폭주에 대비한 서킷 브레이커를 강조합니다.
  • 효율이 높아져도 새 일이 채워질 수 있으니 '할 수 있다'가 아니라 '해야 하는가'를 기준으로 삼으세요.
