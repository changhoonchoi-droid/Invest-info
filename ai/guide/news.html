발표·소식

「발표·소식」에서는 Claude의 새 기능과 모델 출시, 데이터 보관 같은 회사 정책, 편향·환각 같은 연구·안전 이야기를 업무에 바로 쓸 수 있게 정리합니다. 먼저 하나로 합쳐진 Claude와 문서·슬라이드 만들기, 모바일 앱 같은 기본 기능을 익히세요. 다음으로 환각·편향·데이터 보관처럼 안심하고 쓰기 위한 내용을 확인하고, 마지막에 모델 고르기, Slack 협업, 루틴 자동화, 검증 같은 응용으로 넘어가면 좋습니다.

1. 하나로 합쳐진 Claude에 일 맡기기

9월 업데이트로 채팅과 Cowork가 하나의 Claude로 합쳐졌습니다. 이제 모드를 고르지 않고 원하는 결과를 말하면 Claude가 방법을 찾고, 작업은 클라우드에서 돌아 노트북을 닫아도 계속됩니다. 오래 걸리는 업무를 맡겨 두고 다른 일을 할 때 씁니다.

  1. Claude를 열고 새 대화를 시작합니다. 채팅인지 Cowork인지 따로 고르지 않아도 됩니다.
  2. 어떻게 할지가 아니라 원하는 결과를 구체적으로 적어 요청합니다.
  3. 작업이 시작되면 노트북을 닫거나 다른 일을 해도 됩니다. 작업은 클라우드에서 계속 실행됩니다.
  4. 이동 중에는 휴대폰의 Claude 앱으로 진행 상황을 확인합니다.
  5. 예전에 Cowork에서 하던 작업은 그대로 남아 있으니 이어서 확인합니다.
  • 예전 방식: 채팅과 Cowork를 따로 골라 썼지만 지금은 하나로 합쳐졌습니다.
  • 작업 방법을 하나하나 지시하기보다 목표와 원하는 결과물을 분명히 적는 편이 낫습니다.
  • 예전 방식: 2026년 2월에는 Free·Pro 플랜의 claude.ai와 Cowork 기본 모델이 Sonnet 4.6이었고, 지금은 Claude 5.5 계열이 기능을 뒷받침합니다.

2. 대화에서 문서·슬라이드·디자인 만들기

Claude Slides, Claude Design, Claude Docs로 대화를 벗어나지 않고 발표 자료, 소셜 이미지, 한 장짜리 문서를 만듭니다. 결과물은 지금까지 나눈 대화 내용을 바탕으로 만들어집니다. 보고서·기획안·홍보물을 빠르게 초안으로 뽑을 때 씁니다.

  1. 대화에 출시 브리프나 기획 메모처럼 바탕이 될 자료를 붙여 넣거나 그 내용을 먼저 이야기합니다.
  2. 같은 대화에서 슬라이드, 이미지, 문서 중 필요한 결과물을 요청합니다.
  3. 만들어진 결과물에서 고치고 싶은 부분에 코멘트를 답니다.
  4. 코멘트를 Claude에게 보내면 그 부분만 고쳐 줍니다.
  5. 팀원과 함께 다듬을 문서는 Claude Docs에서 팀원·Claude와 동시에 편집합니다.
예시
이 출시 브리프로 발표 슬라이드, 소셜 이미지 세트, 현장에서 나눠 줄 한 장짜리 요약 문서를 만들어 줘.
  • Claude Slides·Design·Docs는 9월 중순에 베타로 공개되었습니다.
  • 대화에서 이미 정리한 내용이 결과물에 반영되므로, 핵심 메시지와 대상 독자를 먼저 대화에 적어 두면 결과가 좋아집니다.
  • Claude Design은 일상 언어로 설명해도 되며, 문서보다 프로토타입을 먼저 보고 고치는 방식이 잘 맞습니다.

3. Claude 모바일 앱 새 기능 쓰기

Claude 모바일 앱 업데이트로 업무용과 개인 계정을 로그아웃 없이 오갈 수 있고, iPad에서는 아티팩트를 대화 옆에 나란히 띄울 수 있습니다. 음성 모드가 빨라지고 CarPlay를 지원해 이동 중에도 쓰기 좋습니다.

  1. iOS나 Android의 Claude 앱을 최신 버전으로 업데이트합니다.
  2. 업무용과 개인 계정에 함께 로그인해 두고, 필요할 때 로그아웃 없이 전환합니다.
  3. iPad에서는 Claude가 만든 아티팩트를 대화 옆 열에 열어 두 창을 나란히 봅니다.
  4. 운전 중에는 iPhone을 Apple CarPlay에 연결해 음성 모드로 대화합니다.
  5. 사진을 고르면 업로드가 끝나기 전에도 채팅에 바로 표시되니 이어서 질문을 적습니다.
  • 앱 화면 언어가 24개 추가되어 총 33개 언어를 지원합니다.
  • Chromebook·폴더블의 Android 앱은 크기 조절 사이드바, 마우스 우클릭, Claude Desktop과 같은 단축키를 지원합니다.
  • 당겨서 검색은 iPhone·iPad에 곧 나올 예정이고, 웹과 데스크톱에는 이미 있습니다(Mac은 Command K).

4. AI 환각 줄이며 답변 확인하기

환각은 AI가 없는 논문, 가짜 통계, 틀린 인물·날짜를 사실처럼 말하는 현상입니다. 1년 전보다 크게 줄었지만 해결되지 않았으므로, 보고서·기사·수치를 업무에 쓰기 전에 확인하는 습관이 필요합니다.

  1. 답변에서 구체적 수치·인용·날짜·이름, 잘 알려지지 않은 주제, 최신 소식이 들어간 부분을 먼저 표시합니다.
  2. 그 부분의 출처를 Claude에게 요청합니다.
  3. 각 내용을 얼마나 확신하는지 물어봅니다.
  4. 중요한 내용은 새 대화를 열어 다시 물어보고 답이 같은지 비교합니다.
  5. 출처 링크를 직접 열어 실제로 그 내용이 있는지 확인한 뒤 씁니다.
예시
방금 답변에 나온 수치와 인용마다 출처를 알려 주고, 각 내용을 얼마나 확신하는지 높음·중간·낮음으로 표시해 줘. 모르는 부분은 모른다고 말해 줘.
  • 환각이 줄어들수록 확인을 건너뛰기 쉬우니 중요한 수치는 꼭 확인합니다.
  • AI는 자료가 적은 주제에서 추측하기 쉬우므로, 사내 자료나 원문을 대화에 함께 넣어 주면 정확도가 올라갑니다.

5. 짝지은 질문으로 답변 편향 점검하기

AI 편향은 고정관념, 정치적 쏠림, 언어에 따른 품질 차이로 나타납니다. Anthropic은 같은 주제를 두 관점으로 묻는 '짝지은 프롬프트'로 응답의 깊이와 노력을 비교해 검증합니다. 민감한 주제의 자료를 만들 때 같은 방법으로 직접 점검할 수 있습니다.

  1. 점검할 주제를 하나 정합니다.
  2. 같은 주제를 서로 반대 관점에서 묻는 질문 두 개를 만듭니다.
  3. 두 질문을 각각 새 대화에서 Claude에게 묻습니다.
  4. 두 답변의 길이, 근거의 깊이, 성의를 나란히 비교합니다.
  5. 한쪽이 눈에 띄게 얕다면 질문을 고치거나 결과물에서 균형을 맞춥니다.
예시
주제: 주 4일 근무제. 질문 1: 주 4일 근무제를 찬성하는 가장 강력한 근거를 정리해 줘. 질문 2: 주 4일 근무제를 반대하는 가장 강력한 근거를 정리해 줘.
  • Anthropic은 수천 개 프롬프트, 수백 개 주제로 이 방식을 테스트했고 평가 데이터셋을 공개해 누구나 같은 테스트를 할 수 있습니다.
  • 한국어처럼 특정 언어에서 품질 차이가 날 수 있으니, 중요한 내용은 영어 답변과도 비교해 볼 만합니다.

6. Claude 데이터 보관 방식 알아 두기

Claude Fable 5부터 안전 모니터링을 위해 최근 30일간의 프롬프트와 출력이 저장됩니다. 회사 자료를 Claude에 넣기 전에 어떤 데이터가 어떻게 보관·검토되는지 알아 두면 보안 담당자와 이야기하기 쉬워집니다.

  1. Fable 5 이후 모델을 쓰면 최근 30일의 프롬프트와 출력이 안전 모니터링용으로 저장된다는 점을 확인합니다.
  2. 저장된 데이터는 자동 시스템이 분석하고, 기본적으로 Anthropic 직원은 읽을 수 없다는 점을 사내 보안 담당자와 공유합니다.
  3. 사람 검토는 자동 시스템이 유해 가능성을 표시한 드문 경우에만 승인된 소수가 하고, 접근 기록이 변조 불가 로그에 남는다는 점을 확인합니다.
  4. 회사가 Enterprise 요금제라면 엔터프라이즈 데이터는 명시적 허가 없이 학습에 쓰이지 않는다는 점을 확인합니다.
  5. 모니터링 데이터를 자체 클라우드에 두어야 하는 조직이면 Enterprise Frontier Safeguards(EFS) 도입을 검토합니다.
  • EFS는 제로 데이터 보존(ZDR)과 오남용 탐지 세이프가드를 결합한 것으로, 로그는 고객이 통제하고 검토는 기계로만 이뤄집니다.
  • EFS는 올가을 이후 단계적으로 제공되며, 그 전까지 대상 조직은 Fable 5와 5.1에서 데이터 보관 없음(ZDR)을 받습니다.
  • 여러 세션·계정에 걸친 정교한 오남용은 한 번의 대화로는 찾기 어려워 30일 보관이 도입되었습니다.

7. 작업 단계별로 모델 골라 쓰기

Claude 5.5 계열은 방향을 찾는 단계에 Opus 5.5, 빠른 수정 단계에 Sonnet 5.5를 쓰도록 권합니다. 기업들도 어렵고 중요한 일에는 가장 큰 모델을, 반복 운영에는 저렴한 모델을 쓰는 '배벨 전략'을 씁니다. 비용과 품질을 함께 챙길 때 씁니다.

  1. 맡길 업무를 '방향 찾기·계획·복잡한 판단'과 '빠른 수정·반복 처리'로 나눕니다.
  2. 방향 찾기, 복잡한 계획과 조율은 Opus 5.5에 맡깁니다.
  3. 방향이 정해진 뒤의 빠른 수정은 Sonnet 5.5로 바꿔 진행합니다.
  4. 여러 자료를 오래 붙들고 근본 원인을 찾아야 하는 긴 작업은 Fable 5.1을 고려합니다.
  5. 자동으로 계속 돌아가는 작업에는 폭주를 막는 중단 장치(서킷 브레이커)를 함께 둡니다.
  • Shopify는 개발·테스트·자동 연구에는 가장 큰 모델을, 운영과 파인튜닝에는 저렴한 모델을 씁니다.
  • LLM은 질문에 맞춰 답하려는 경향이 있으니, 실제로 필요한 것을 정확히 요청하는 판단력이 모델 선택만큼 중요합니다.
  • 예전 방식: 6월 출시된 Fable 5는 일반 공개 모델 중 가장 뛰어난 모델로 소개되었고, 9월에 Fable 5.1, 10월에 5.5 계열 구분 사용법이 나왔습니다.

8. Slack에서 Claude Tag와 협업하기

Claude Tag는 Slack에서 팀과 함께 일하는 Claude입니다. 스레드에서 Claude를 태그하면 채널의 맥락을 파악해 작업하고, 끝나거나 입력이 필요할 때 알려 줍니다. 데이터 질문 답변, 사내 문의 응대, 며칠씩 걸리는 후속 확인 업무에 씁니다.

  1. 회사가 Slack을 쓰고 Claude Team 또는 Enterprise 요금제인지 확인합니다.
  2. 작업할 채널의 스레드에서 Claude를 태그하고 맡길 일을 적습니다.
  3. Claude가 채널 맥락을 파악해 일하는 동안 다른 일을 하고, 완료나 입력 요청 알림을 기다립니다.
  4. 같은 스레드에서 다른 팀원도 함께 지시를 덧붙입니다.
  5. 채널에서 자주 쓰는 규칙이나 지시는 반복해 알려 주어 채널별 메모리로 쌓이게 합니다.
  • Team과 Enterprise 요금제에서 베타로 제공되며, Microsoft Teams 등으로 확대할 계획입니다.
  • Claude는 자기 계정과 권한을 가지며 채널별로 접근 범위가 나뉘고, 비공개 채널이나 DM에서 배운 내용은 그 안에만 남습니다.
  • 작업이 아니라 목표를 맡기는 방식이 잘 맞습니다. Claude Code 팀원 한 명은 업무의 70~80%를 Claude Tag에서 처리합니다.
  • 다른 팀원이 Tag를 쓰는 방식을 보며 좋은 사용법을 따라 배울 수 있습니다.

9. 소모적인 업무 절차 하나 점검하기

AI로 작업 속도가 빨라지면 병목이 검증·리뷰·부서 간 협업으로 옮겨 가고, 예전에 도움이 되던 절차가 조용히 쓸모를 잃습니다. Anthropic Claude Code 팀은 가장 소모적인 절차 하나를 골라 지금도 필요한지 점검해 보라고 제안합니다.

  1. 우리 팀에서 시간이 가장 많이 드는 업무 절차 하나를 고릅니다.
  2. 그 절차가 처음 생긴 이유를 적습니다.
  3. 그 이유가 지금도 유효한지 팀과 함께 확인합니다.
  4. Claude로 줄이거나 대신할 수 있는 부분을 찾습니다.
  5. 긴 문서로 논쟁하기보다 Claude로 작은 시제품을 먼저 만들어 보여 주며 바꿀지 정합니다.
예시
우리 팀의 주간 보고 절차를 설명할게. 이 절차가 지금도 필요한지, Claude로 줄이거나 대신할 수 있는 단계가 어디인지 점검해 줘.
  • 절차는 스스로 사라지지 않고 계속 쌓이므로 의식적으로 정리해야 합니다.
  • Claude Code 팀은 6개월 로드맵 대신 필요한 때 계획하는 JIT 방식으로 바꿨습니다.
  • 모델이 계속 좋아지므로 AI 결과를 얼마나 믿고 얼마나 검증할지도 주기적으로 다시 정합니다.

10. 새 모델이 나오면 내 업무로 시험하기

모델은 몇 달마다 바뀌고, 모델 교체만으로 에이전트 성공률이 약 20% 오른 사례도 있습니다. 출시 전 모델을 먼저 받아 보는 기업들은 자동 평가(evals)를 먼저 돌리고 어려운 실제 업무를 맡겨 봅니다. 회사에서 어떤 모델로 바꿀지 판단할 때 씁니다.

  1. 평소 자주 하는 업무 중 대표적인 작업 몇 개를 골라 평가용 모음으로 만듭니다.
  2. 각 작업에 '잘했다'고 볼 기준을 적어 둡니다.
  3. 새 모델이 나오면 이 평가 모음을 먼저 돌려 기존 모델 결과와 비교합니다.
  4. 법률 문서 초안처럼 복잡하고 어려운 실제 업무를 맡겨 봅니다.
  5. 아직 잘 안 되는 작업은 따로 기록해 두고 다음 모델이 나올 때 다시 시험합니다.
  • 지금 안 되는 작업이 다음 모델이 나아질 분야의 신호라고 봅니다.
  • Lovable은 모든 모델 출시를 평가 루프에 통과시킨 뒤 적용합니다.
  • 모델이 좋아질수록 예전에 약점을 메우려고 만든 우회 방법이 필요 없어질 수 있으니, 기존 방식도 함께 다시 점검합니다.

11. Claude Code 루틴으로 반복 작업 돌리기

루틴은 사람이 매번 지시하지 않아도 정해진 계기에 Claude Code가 일을 시작하게 하는 기능입니다. 일정, 웹훅, API 호출로 시작할 수 있고 로컬이나 원격 클라우드에서 실행됩니다. 매일 들어오는 피드백 정리나 CI 오류 자동 수정 같은 반복 작업에 씁니다.

  1. 매일 또는 특정 사건마다 반복되는 작업 하나를 고릅니다.
  2. 루틴을 시작할 계기를 일정, 웹훅, API 호출 중에서 정합니다.
  3. 실행 위치를 로컬과 원격 클라우드 중에서 정합니다. 노트북을 꺼도 돌아가야 하면 원격 클라우드를 고릅니다.
  4. 루틴이 할 일을 목표 중심으로 적고, 확신이 높은 것만 처리하도록 범위를 정합니다.
  5. 처음 몇 번은 결과를 직접 확인하고 지시를 다듬습니다.
예시
매일 들어온 사용자 피드백을 모아 중요도별로 분류하고, 확신이 높은 문제만 고쳐 줘.
  • 런던 기조연설에서는 루틴이 사람 대신 Claude Code에 지시하고 CI 자동 수정까지 맡는 흐름을 시연했습니다.
  • 여러 작업이 동시에 돌 때는 에이전트 뷰로 한눈에 관리합니다.
  • 자동 실행이 길어질 때를 대비해 범위를 좁게 시작하고 결과 확인 단계를 남겨 두세요.

12. AI가 만든 결과물 검증 장치 두기

AI가 만든 코드나 결과물이 테스트를 모두 통과해도 실제로는 느리거나 틀릴 수 있습니다. 정확성은 테스트로, 속도는 측정으로, 품질은 AI의 판단이 아니라 권한·점진적 배포 같은 장치로 지켜야 합니다. AI 결과물을 실제 업무에 반영하기 전에 씁니다.

  1. AI에게 일을 맡기기 전에 결과가 맞는지 확인할 테스트를 먼저 준비합니다.
  2. AI 결과물이 테스트를 모두 통과하는지 확인합니다.
  3. 속도나 처리량이 중요하면 실제 사용 조건에서 직접 측정해 기존 방식과 비교합니다.
  4. AI가 접근할 수 있는 데이터와 권한을 필요한 범위로 제한합니다.
  5. 적용은 일부에 먼저 하고 문제가 없으면 넓히는 점진적 배포로 진행합니다.
  6. 최종 원인 확인과 적용 범위 결정, 승인은 사람이 맡습니다.
  • 실험에서 테스트 33개를 모두 통과한 Rust 토크나이저가 12스레드에서는 초당 10.7MB로 Python(20.2MB)보다 느렸습니다.
  • Stripe는 모든 개발자에게 Claude Code가 설치된 격리 개발 환경을 주고, 데이터 분리·권한·점진적 배포 같은 하드 가드레일로 품질을 지킵니다.
  • AI 작업이 빨라질수록 병목은 검증·리뷰로 옮겨 가므로, 검증 단계를 줄이지 말고 자동화하세요.
