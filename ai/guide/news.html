1. 상황에 맞는 Claude 모델 고르기

Claude에는 Opus·Fable·Sonnet·Haiku처럼 성격이 다른 모델이 있습니다. 작업 난이도에 맞춰 고르면 속도와 사용량을 아낄 수 있습니다.

  1. Claude 대화 화면에서 모델 전환 메뉴를 엽니다.
  2. 일상적인 코딩·지식 작업이라면 Opus 5.5를 선택해 시작합니다.
  3. 가장 어려운 문제나 오래 걸리는 기술 작업은 Fable 5.2로 바꿉니다.
  4. 작고 빠른 작업은 Sonnet 5.5나 Haiku를 선택합니다.
  5. 결과가 아쉬우면 같은 요청을 다른 모델로 다시 돌려 비교합니다.
  • Fable 5.2는 모든 유료 플랜에서 쓸 수 있고 Fable 5.1보다 빠르다고 소개됩니다.
  • 9월 업데이트에서는 방향을 찾을 때 Opus 5.5, 빠른 수정에는 Sonnet 5.5를 쓰라고 안내했습니다.
  • Fable 5.2는 대형 작업에서 사용량을 많이 쓸 수 있습니다. 슬라이드 한 개에 30분, ultra 플랜 사용량 약 1.5%를 썼다는 사례가 있습니다.
  • 벤치마크보다 직접 써 보고 고르라는 의견이 많습니다.

2. Claude 하나로 문서·슬라이드·디자인 만들기

하나의 Claude에서 대화를 벗어나지 않고 문서, 슬라이드, 디자인 결과물을 만들 수 있습니다. 출시 브리프 하나로 여러 산출물을 한꺼번에 뽑을 때 유용합니다.

  1. Claude에서 만들 결과물의 목적과 대상, 핵심 내용을 담은 브리프를 입력합니다.
  2. 슬라이드, 소셜 이미지, 한 장짜리 문서 중 필요한 것을 요청합니다.
  3. 결과물이 나오면 고칠 부분에 코멘트를 남겨 Claude에게 보냅니다.
  4. 수정본을 확인하고 필요하면 코멘트와 수정을 반복합니다.
예시
신제품 출시 브리프야. 대상은 영업팀이고 핵심 메시지는 '설치 10분'이야. 발표용 슬라이드 10장과 현장에서 나눠 줄 한 장짜리 요약 문서를 만들어 줘.
  • Claude Slides·Design·Docs는 9월에 베타로 공개되었고, 이후 채팅과 Cowork가 하나의 Claude로 합쳐졌습니다.
  • Claude Design은 회사 디자인 시스템(색상·폰트·컴포넌트)을 먼저 만들어 두면 이후 결과물에 자동 적용되고, 없으면 결과가 'AI스럽다'는 평가가 있습니다.
  • Claude Design은 리서치 프리뷰로 웹에서만 쓸 수 있고 Pro 이상 구독이 필요하며 사용량 한도가 빡빡합니다. 5월 영상 기준 정보라 지금 상태는 확인이 필요합니다.

3. Claude Sheets·Whiteboards·Data 써 보기

Claude에 시트, 화이트보드, 데이터(옛 대시보드) 기능이 추가되었습니다. 표 정리, 아이디어 구상, 데이터 공유를 Claude 안에서 할 때 씁니다.

  1. 유료 플랜 계정으로 Claude에 로그인합니다.
  2. 숫자 정리가 필요하면 Claude에게 수식이 담긴 시트를 만들어 달라고 요청합니다.
  3. 아이디어 구상이나 워크플로·행사 계획은 화이트보드로 펼쳐 달라고 요청합니다.
  4. 데이터를 보여 줄 때는 Data로 대시보드를 만들고 팀원과 공유합니다.
  5. 시트에서 Claude가 편집한 부분이 표시되는지 확인하고 결과를 검토합니다.
예시
월별 매출 숫자를 정리하는 시트를 수식 포함해서 만들어 줘. 합계와 전월 대비 증감률 열도 넣어 줘.
  • 시트·화이트보드·데이터는 모든 유료 플랜에서 쓸 수 있고, 화이트보드와 시트는 베타입니다.
  • 시트에는 피벗 테이블과 매크로가 없어 구글 시트를 대체하기는 어렵다는 평가가 있습니다. 화이트보드는 아이디어 구상에 더 유용하다고 합니다.
  • Data는 베타를 벗어났지만 인증 쿼리와 실시간 공유는 아직 베타입니다.
  • 모든 작업은 각자 가진 권한 안에서 이뤄집니다.

4. Claude Meetings로 회의 노트 맡기기

Claude Meetings는 통화에 참가자로 들어와 노트를 쓰고, 요청하면 문서나 화이트보드까지 만들어 줍니다. 회의록 정리 시간을 줄이고 싶을 때 씁니다.

  1. Team 또는 Enterprise 요금제인지 확인합니다.
  2. 회의에 Claude Meetings를 참가자로 들입니다.
  3. 회의 중 필요한 순간에 정리나 문서 작성을 요청합니다.
  4. 끝난 뒤 저장된 전사본과 요약을 확인합니다.
  5. 필요하면 요약을 바탕으로 문서나 화이트보드를 만들어 달라고 요청합니다.
예시
방금 회의에서 나온 결정 사항과 담당자별 할 일을 표로 정리해 줘.
  • Team·Enterprise 플랜 베타로 제공됩니다.
  • 전사본·요약·화면 설명은 저장되지만 음성은 저장하지 않는다고 합니다.
  • 참가자에게 기록 사실을 알리는 등 회사 규정을 먼저 확인하세요.

5. Slack에서 Claude Tag로 팀 일 맡기기

Claude Tag는 Slack 채널에서 팀과 함께 일하는 Claude입니다. 스레드에서 태그하면 채널 맥락을 보고 작업하고, 끝나거나 입력이 필요할 때 알려 줍니다.

  1. Team 또는 Enterprise 요금제에서 Claude Tag를 Slack에 연결합니다.
  2. 작업이 필요한 스레드에서 Claude를 태그하고 목표를 적습니다.
  3. 여러 팀원이 같은 스레드에서 추가 지시를 줍니다.
  4. 작업이 끝났다는 알림이나 입력 요청이 오면 확인하고 답합니다.
  5. 채널별로 알려 줄 규칙을 지시해 메모리가 쌓이게 합니다.
예시
@Claude 이 스레드의 고객 문의를 읽고 자주 나오는 질문 5가지를 정리해서 공유해 줘.
  • Team과 Enterprise 요금제에서 베타로 제공됩니다.
  • Claude는 자기 계정과 권한을 갖고, 채널별로 접근 범위가 나뉘며 모든 자격 증명 사용이 기록됩니다.
  • 비공개 채널이나 DM에서 배운 내용은 그 안에만 남습니다.
  • Anthropic 제품 조직 PR의 약 65%를 Tag가 작성한다고 합니다.
  • Microsoft Teams 등으로 확대할 계획입니다.

6. 모바일 앱에서 계정 전환·음성 쓰기

Claude 모바일 앱이 업데이트되어 업무용·개인 계정을 오가고, 음성 모드와 다국어 지원이 개선되었습니다. 이동 중에도 Claude를 쓰는 사람에게 유용합니다.

  1. iOS 또는 Android의 Claude 앱을 최신 버전으로 업데이트합니다.
  2. 업무용과 개인 계정을 로그아웃 없이 추가해 로그인합니다.
  3. 계정을 바꿔야 할 때 앱 안에서 전환합니다.
  4. 음성 모드를 켜서 말로 질문합니다.
  5. iPad에서는 아티팩트를 대화 옆 열에 열어 두 창을 나란히 씁니다.
  • 음성 모드는 더 빨라졌고 iPhone에서 Apple CarPlay를 지원합니다.
  • 앱 인터페이스는 24개 언어가 추가되어 총 33개 언어를 지원합니다.
  • iPhone·iPad의 당겨서 검색은 곧 제공될 예정입니다.
  • 개인 금융 기능은 읽기 전용이고 미국 Pro·Max·Ultra 베타라 한국에서는 아직 쓸 수 없을 수 있습니다.

7. Claude Duet으로 선제 알림 받기

Claude Duet은 주의가 필요한 일을 먼저 알려 주고, 사용자가 폰을 내려놓은 뒤에도 일하는 에이전트 앱입니다. 매일 아침 브리핑과 백그라운드 작업이 필요한 사람을 위한 기능입니다.

  1. 미국 Pro·Max·Ultra 구독자인지 확인합니다.
  2. Duet 대기 명단에 등록합니다.
  3. 초대를 받으면 앱에서 연결할 서비스를 정합니다.
  4. 아침 브리핑과 알림을 확인하고 확인이 필요한 일에 답합니다.
  5. Claude가 대신 행동하기 전에 보내는 승인 요청을 검토합니다.
  • 연구 프리뷰이며 대기 명단으로 열려 있습니다.
  • 민감한 행동은 사용자의 승인을 받습니다.
  • 현재 미국 구독자 대상이라 한국 계정은 대상이 아닐 수 있습니다.

8. Claude 데이터 보관 방식 이해하기

Claude Fable 5부터 안전 모니터링을 위한 데이터 보관 방식이 달라졌습니다. 회사에서 쓰기 전에 내용과 선택지를 알아 두면 보안 검토에 도움이 됩니다.

  1. Fable 5 이상을 쓰면 최근 30일의 프롬프트와 출력이 안전 모니터링용으로 저장된다는 점을 확인합니다.
  2. 자동 시스템이 분석하며 기본적으로 Anthropic 직원은 읽을 수 없다는 점을 파악합니다.
  3. 엔터프라이즈 데이터는 명시적 허가 없이 학습에 쓰지 않는다는 점을 확인합니다.
  4. 민감한 업무라면 Enterprise Frontier Safeguards(EFS)로 모니터링 데이터를 자체 클라우드에 보관하는 방법을 검토합니다.
  5. EFS가 제공되기 전에는 대상 조직이 Fable 5와 5.1에서 데이터 보관 없음(ZDR)을 받을 수 있는지 담당자에게 문의합니다.
  • 사람의 검토는 자동 시스템이 유해 가능성을 표시한 드문 경우에만 승인된 소수 검토자가 합니다.
  • EFS는 올가을 이후 단계적으로 제공됩니다.
  • EFS는 ZDR의 프라이버시와 오남용 탐지 세이프가드를 결합한 것이고, 로그는 고객이 통제합니다.
  • 내용은 영상 시점 기준이므로 실제 적용은 공식 안내로 다시 확인하세요.

9. AI의 환각을 줄이는 질문법

AI는 없는 내용을 사실처럼 말하는 환각을 일으킬 수 있습니다. 보고서나 자료 조사에 쓰기 전에 확인하는 습관을 익힙니다.

  1. 구체적인 사실, 통계, 인용, 날짜·이름·숫자는 환각 가능성이 높다는 점을 기억합니다.
  2. 답변에 출처를 요청합니다.
  3. 답변에 얼마나 확신하는지 되묻습니다.
  4. 중요한 내용은 새 대화에서 같은 질문을 다시 해 검증합니다.
  5. 출처 링크가 실제로 열리고 내용이 맞는지 직접 확인합니다.
예시
방금 답변의 근거가 된 출처를 알려 주고, 확실한 부분과 추측인 부분을 구분해 줘.

10. AI 조언에 휘둘리지 않고 결정하기

Anthropic 연구에 따르면 사람들은 AI 에이전트가 기운 쪽을 크게 따르고, 스스로 결정했다고 착각하기 쉽습니다. 계획 단계에서 AI의 영향을 점검하는 방법입니다.

  1. AI에게 추천을 받기 전에 내 우선순위를 먼저 정리해 알려 줍니다.
  2. 결정이 갈리는 지점은 말로만 비교하지 말고 프로토타입으로 직접 확인합니다.
  3. AI에게 '어떤 조건이면 조언이 바뀌는지' 묻습니다.
  4. 최종 결정 전에 내 논거와 AI의 논거를 구분해 적어 봅니다.
예시
이 두 방안 중 하나를 추천하기 전에 내 우선순위부터 질문해 줘. 그리고 어떤 조건이면 추천이 바뀌는지도 알려 줘.
  • 연구에서 분석가는 에이전트가 기운 쪽을 86% 따랐고, 선호가 있던 사람도 에이전트가 반대하면 60%가 바꿨습니다.
  • 설명할 때 77%가 에이전트의 논거를 썼지만 출처로 밝힌 사람은 15%였습니다.
  • 한계: 에이전트의 기울기를 일부러 강화했고 한 분야·한 과제·한 모델만 연구했습니다.

11. 새 모델이 나오면 내 업무로 평가하기

새 모델이 나올 때마다 내 업무에서 실제로 나아졌는지 직접 확인하는 방법입니다. 고객사들이 출시 전에 모델을 시험하는 방식을 참고합니다.

  1. 내 업무에서 자주 하는 대표 작업 몇 개를 골라 평가 세트로 정해 둡니다.
  2. 새 모델이 나오면 같은 작업을 먼저 돌려 결과를 이전 모델과 비교합니다.
  3. 법률 초안 같은 복잡한 작업도 맡겨 보고 지금 안 되는 일을 기록합니다.
  4. API를 쓴다면 모델 교체 전후 성공률을 측정합니다.
  5. 모델 전환 때는 기존 방식을 한동안 유지하며 점진적으로 옮깁니다.
  • 모델 교체만으로 테스트 에이전트 성공률이 약 20% 올랐다는 사례가 있습니다.
  • 지금 안 되는 작업은 다음 모델이 나아질 영역의 단서로 봅니다.
  • 프롬프트 캐싱은 비용 관리의 첫 번째 권장 사항으로 언급됐습니다.
  • 모델은 몇 달마다 바뀌므로 모델의 약점을 메우려고 만든 기능은 주기적으로 다시 점검하세요.
