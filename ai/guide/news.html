1. 하나로 합쳐진 Claude에 일 맡기기

9월 업데이트로 채팅과 Cowork가 하나의 Claude로 합쳐졌습니다. 이제 모드를 고르지 않고 원하는 결과만 말하면 Claude가 방법을 찾고, 작업은 클라우드에서 계속 돌아갑니다. 시간이 걸리는 일을 맡겨 두고 다른 일을 하고 싶을 때 씁니다.

  1. Claude를 열고 채팅이나 Cowork 중 하나를 고르지 말고 새 대화를 시작합니다.
  2. 어떻게 할지 말고 무엇을 얻고 싶은지, 곧 목표를 한두 문장으로 적습니다.
  3. 참고할 자료나 조건(마감, 분량, 독자)을 같은 대화에 덧붙입니다.
  4. 요청을 보내고 작업이 클라우드에서 도는 동안 노트북을 닫아도 됩니다.
  5. 이동 중에는 휴대폰으로 진행 상황을 확인합니다.
  6. 결과를 받으면 바꿀 부분을 같은 대화에서 이어서 요청합니다.
예시
다음 주 팀 회의에서 공유할 3분기 고객 문의 동향 보고서가 필요합니다. 첨부한 문의 목록에서 많이 나온 유형 5개와 대응 제안을 정리해 주세요.
  • 예전 방식: 채팅과 Cowork를 따로 골라 썼지만, 지금은 하나의 Claude로 합쳐졌고 기존 Cowork 작업도 그대로 남아 있습니다.
  • Claude Code 팀도 할 일을 하나하나 지시하기보다 목표를 맡기는 방식으로 바꿨다고 말합니다.
  • 중요한 결과물은 받은 뒤 꼭 직접 검토하세요.

2. Opus 5.5와 Sonnet 5.5 골라 쓰기

Claude 5.5 계열은 단계에 따라 모델을 나눠 쓰라고 권합니다. 방향을 잡는 어려운 단계에는 Opus 5.5, 이미 정한 방향에서 빠르게 고치는 단계에는 Sonnet 5.5가 맞습니다.

  1. 지금 하는 일이 방향을 정하는 단계인지, 정한 방향대로 다듬는 단계인지 먼저 판단합니다.
  2. 기획·구조 잡기·어려운 분석처럼 방향을 찾는 단계라면 Opus 5.5를 고릅니다.
  3. 문장 다듬기·수치 수정·형식 맞추기처럼 빠른 수정 단계라면 Sonnet 5.5로 바꿉니다.
  4. 두 모델 결과를 비교해 보고, 자주 하는 업무마다 어느 모델을 쓸지 메모해 둡니다.
  • Shopify CTO도 개발·연구처럼 어려운 일에는 가장 큰 모델을, 반복 운영에는 저렴한 모델을 쓰는 '배벨 전략'을 권합니다.
  • 예전 방식: 2026년 2월에는 Free·Pro 플랜 기본 모델이 Sonnet 4.6이었습니다. 지금은 5.5 계열을 기준으로 고르세요.
  • 모델은 몇 달마다 바뀌므로 새 모델이 나오면 자주 하는 업무로 다시 시험해 보세요.

3. 대화에서 문서·슬라이드·디자인 만들기

Claude Slides, Claude Design, Claude Docs를 쓰면 대화를 벗어나지 않고 발표 자료, 소셜 이미지, 한 장짜리 문서를 만들 수 있습니다. 결과물의 특정 부분에 코멘트를 달면 Claude가 그 부분만 고쳐 주고, Claude Docs에서는 팀원과 Claude가 같은 문서를 동시에 편집합니다.

  1. 만들 결과물의 바탕이 될 브리프(출시 소식, 자주 묻는 질문, 회의 내용 등)를 대화에 붙여 넣습니다.
  2. 필요한 결과물 종류(슬라이드, 소셜 이미지, 한 장 요약 문서)를 구체적으로 요청합니다.
  3. 결과물에서 마음에 들지 않는 부분에 코멘트를 달아 Claude에게 보냅니다.
  4. Claude가 코멘트를 단 부분을 고치면 다시 확인합니다.
  5. 팀과 함께 다듬을 문서는 Claude Docs에서 팀원과 함께 편집합니다.
예시
아래 출시 브리프를 바탕으로 ① 발표용 슬라이드 ② 소셜 이미지 세트 ③ 현장에서 나눠 줄 한 장짜리 요약 문서를 만들어 주세요.
  • 예전 방식: 9월 중순에는 Slides·Design·Docs가 별도 베타 도구로 소개됐지만, 지금은 어떤 대화에서든 만들 수 있고 앞선 대화 내용이 바탕이 됩니다.
  • 한 양봉가는 그동안 모은 고객 질문을 Claude로 정리해 한 장짜리 안내문을 만들었습니다. 쌓아 둔 FAQ가 있다면 좋은 출발점입니다.

4. Claude 데이터 보관 방식 확인하기

Claude Fable 5부터는 안전 모니터링을 위해 최근 30일간의 프롬프트와 출력이 저장됩니다. 회사 업무에 Claude를 쓰기 전에 무엇이 저장되고 누가 볼 수 있는지 확인하고, 필요하면 Enterprise Frontier Safeguards(EFS)를 검토합니다.

  1. Fable 5 이후 모델에서는 최근 30일 치 프롬프트와 출력이 안전 모니터링용으로 저장된다는 점을 확인합니다.
  2. 저장된 데이터는 자동 시스템이 분석하고 기본적으로 Anthropic 직원은 읽을 수 없다는 점을 보안 담당자와 공유합니다.
  3. 사람의 검토는 자동 시스템이 유해 가능성을 표시한 드문 경우에만 승인된 소수 검토자가 하며, 접근 기록이 변조할 수 없는 로그에 남는다는 점을 확인합니다.
  4. 엔터프라이즈 데이터는 명시적 허가 없이 학습에 쓰이지 않는다는 점을 사내 가이드에 적습니다.
  5. 모니터링 데이터를 자체 클라우드에 두어야 하는 조직이라면 EFS 도입을 검토합니다.
  • EFS는 올가을부터 단계적으로 제공되며, 그 전까지 대상 조직은 Fable 5와 5.1에서 데이터 보관 없음(ZDR)을 받습니다.
  • EFS에서는 로그를 고객이 통제하고, 검토는 기계로만 하며, 결과는 고객 콘텐츠가 아닌 정해진 탐지 항목으로 제한됩니다.
  • Visa와 Uber는 정책 수준이 아니라 아키텍처 수준의 보호가 핵심이라고 말합니다. 보안 검토 때 이 관점으로 질문해 보세요.

5. Claude Duet 대기자 명단 신청하기

Claude Duet은 Claude가 주의가 필요한 일을 먼저 알려 주고, 폰을 내려놓은 뒤에도 계속 일하는 새 앱입니다. 무엇을 지금 확인해야 하고 무엇을 미뤄도 되는지 판단해 주고, 사용자를 대신해 행동하기 전에는 먼저 확인을 받습니다.

  1. 내가 미국의 Pro 또는 Max 구독자인지 확인합니다. 지금은 이 사용자만 대상입니다.
  2. 대상이라면 연구 프리뷰 대기자 명단에 신청합니다.
  3. 사용할 수 있게 되면 Claude가 먼저 알려 주는 일 가운데 무엇을 맡길지 정합니다.
  4. Claude가 대신 행동하기 전에 확인을 요청하면 내용을 읽고 승인할지 정합니다.
  • 연구 프리뷰라 기능과 대상이 바뀔 수 있습니다. 한국 사용자는 대상이 넓어지는지 지켜보세요.
  • 영상 속 사용자들은 맥락 이해, 먼저 판단해 주는 점, Slack에서 필요한 내용을 먼저 가져다주는 점을 장점으로 꼽았습니다.

6. Slack에서 Claude Tag 호출하기

Claude Tag는 Slack 팀 채널에서 함께 일하는 Claude입니다. 스레드에서 태그하면 채널 맥락을 파악해 작업하고, 일이 끝나거나 입력이 필요할 때 알려 줍니다. 데이터 질문 답변, 사내 문의 응대, 버그 수정, PR 작성 등에 쓰입니다.

  1. 회사가 Team 또는 Enterprise 요금제인지 확인합니다. Claude Tag는 이 요금제에서 베타로 제공됩니다.
  2. 작업을 맡길 Slack 채널의 스레드에서 Claude를 태그하고 할 일을 적습니다.
  3. 같은 스레드에서 다른 팀원도 지시를 덧붙이게 해 여러 사람이 함께 일을 맡깁니다.
  4. Claude가 입력을 요청하면 스레드에서 답하고, 완료 알림이 오면 결과를 검토합니다.
  5. 채널별로 자주 쓰는 지시를 알려 두면 메모리에 쌓여 다음 작업에 반영됩니다.
  • Claude는 자기 계정과 권한을 따로 갖고, 채널마다 접근 범위가 나뉘며, 모든 자격 증명 사용이 기록됩니다.
  • 비공개 채널이나 DM에서 배운 내용은 그 안에만 남습니다. 민감한 업무는 채널을 나눠 쓰세요.
  • 며칠~몇 주 걸리는 일도 후속 확인까지 이어서 하므로, 긴 일은 목표 단위로 맡기는 편이 좋습니다.
  • Microsoft Teams 등으로 넓힐 계획이 발표됐습니다.

7. AI로 만든 콘텐츠 공개 원칙 정하기

편집부터 영상 제작까지 AI로 자동화할 수 있게 되면서, AI 콘텐츠를 어떻게 공개할지 정할 필요가 생겼습니다. 사내 뉴스레터, 교육 영상, 홍보물처럼 사람에게 보여 줄 콘텐츠를 만들기 전에 원칙을 세울 때 씁니다.

  1. AI로 만들 콘텐츠의 종류와 보는 사람을 적습니다.
  2. 네 가지 선택지 가운데 하나를 고릅니다: ① AI로 모두 만들기 ② AI 콘텐츠는 별도 채널·짧은 영상으로 나누기 ③ AI를 쓰되 사람의 몫 넣기 ④ AI 쓰지 않기.
  3. ③을 고르면 사람이 맡을 부분(경험담, 판단, 최종 검수)을 정합니다.
  4. 공개 전 사실 확인과 검수를 누가 할지 정합니다.
  5. 독자 반응을 모아 원칙을 다시 조정합니다.
  • 품질이 높아도 독자가 받아들이는 방식은 다를 수 있습니다. 영상에서는 사람의 가치가 완벽함보다 진실성에 있다고 봅니다.
  • AI가 만든 콘텐츠일수록 검수·검증과 신뢰가 더 중요해집니다.
  • AI 음성 품질은 ElevenLabs V4 API 이후 크게 좋아졌다고 합니다.

8. Fable 5.1로 문제의 근본 원인 찾기

Claude Fable 5.1은 오래 이어지는 엔지니어링 작업에 강하고, 증상이 아니라 근본 원인을 찾아 고치는 데 강점이 있다고 소개됩니다. 여러 자료를 한꺼번에 봐야 하고 내부에서 재현하기 어려운 문제를 추적할 때 씁니다.

  1. 문제와 관련된 자료(몇 달 치 데이터, 고객 지원 티켓, 관련 코드베이스)를 모읍니다.
  2. Fable 5.1에 자료를 주고, 증상이 아니라 근본 원인을 찾아 달라고 요청합니다.
  3. Fable 5.1이 원인을 제안하면 담당자가 직접 맞는지 확인합니다.
  4. 안전하게 배포할 범위를 사람이 정합니다.
  5. 수정 내용을 검토하고 승인합니다.

첨부한 3개월 치 운영 데이터, 고객 지원 티켓, 관련 코드를 함께 살펴보고, 우리 팀이 재현하지 못한 이 오류의 증상이 아니라 근본 원인을 찾아 근거와 함께 설명해 주세요.
  • 원인 확인, 배포 범위 결정, 수정 승인은 반드시 사람이 맡습니다.
  • Cursor는 Fable 5 계열이 계속 재촉하지 않아도 깊은 문제 해결을 이어 간다고 평가했습니다.
  • Fable 5는 모든 Claude Code 사용자에게 제공됩니다.

9. Claude Code 루틴으로 반복 업무 맡기기

Claude Code가 로컬 실행에서 클라우드 실행으로 넘어가면서, 세션 밖에서 정해진 대로 도는 루틴을 만들 수 있게 됐습니다. 매일 들어오는 피드백 정리처럼 반복되는 일을 자동으로 맡길 때 씁니다.

  1. 매일 또는 매주 반복하는 일 가운데 맡길 일 하나를 고릅니다(예: 사용자 피드백 모으기).
  2. 루틴이 할 일을 순서대로 적습니다: 자료 모으기 → 중요도별 분류 → 처리.
  3. 자동으로 처리할 기준을 정합니다. 예를 들어 확신이 높은 것만 고치고 나머지는 보고만 하게 합니다.
  4. Claude Code의 루틴 기능에 이 내용을 등록합니다.
  5. 처음 며칠은 결과를 매일 확인해 기준을 조정합니다.
  • Claude Code 팀은 매일 피드백을 모아 중요도별로 분류하고 확신이 높은 것만 고치는 방식으로 루틴을 씁니다.
  • 원격 제어, 자동 모드, 자동 메모리, 에이전트 뷰 같은 관련 기능도 함께 출시됐습니다.
  • 모델이 좋아지면 예전에 필요했던 보조 장치가 필요 없어질 수 있으니 주기적으로 정리하세요.

10. 팀 AI 도입 원칙과 안전장치 세우기

Shopify, Stripe, Lovable 같은 회사는 AI를 대규모로 쓰면서 모델 선택, 품질 관리, 평가에 대한 원칙을 세웠습니다. 팀이나 회사에서 AI 활용을 넓히기 전에 기준을 정할 때 참고합니다.

  1. AI로 기존 일을 덜 것인지(바닥 올리기), 예전에 못 하던 일을 할 것인지(천장 올리기) 목표를 정합니다.
  2. 개발·테스트·연구에는 가장 큰 모델을, 반복 운영에는 저렴한 모델을 쓰는 배벨 전략으로 모델 배분을 정합니다.
  3. 품질을 AI 판단에만 맡기지 말고 데이터 분리, 권한 제한, 점진적 배포 같은 하드 가드레일을 둡니다.
  4. 멈추지 않고 돌아가는 프로세스를 끊을 서킷 브레이커를 마련합니다.
  5. 새 모델이 나올 때마다 우리 업무 기준의 평가를 돌려 통과한 모델만 씁니다.
  • LLM은 질문에 맞춰 답하려는 경향이 있으므로, 실제로 필요한 것을 정확히 요청하는 판단력이 더 중요합니다.
  • Stripe는 모든 개발자에게 Claude Code가 미리 설치된 격리 개발 환경을 주고, 엔지니어 2~3명이 약 2개월 만에 새 제품을 출시했습니다.
  • Lovable은 모든 모델 출시를 평가 루프에 통과시킨 뒤에야 씁니다.
