1. Fable 5.2로 모델 바꿔 쓰기

Claude Fable 5.2는 유료 플랜에서 고를 수 있는 새 모델입니다. 영상 소개에 따르면 지식 노동 과제 완료율이 Opus 5.5의 21%에서 41%로 올랐습니다. 문서·슬라이드·간단한 게임처럼 결과물이 큰 작업을 한 번에 맡길 때 써 볼 만합니다.

  1. 유료 플랜으로 로그인했는지 확인합니다.
  2. 대화창의 모델 전환 메뉴를 엽니다.
  3. 목록에서 Fable 5.2를 선택합니다.
  4. 만들 결과물(슬라이드, 발표용 인터랙티브 자료 등)과 대상 청중을 한 번에 적어 요청합니다.
  5. 결과가 Artifact로 나오면 그 안에서 바로 실행해 확인합니다.
  6. 고칠 곳은 한 번에 하나씩 말해 수정시킵니다.
  7. 사용량이 얼마나 줄었는지 확인하고, 큰 작업은 나눠서 맡깁니다.
예시
우리 팀 신입 교육용으로 '보고서 잘 쓰는 법' 슬라이드를 만들어 줘. 10장 이내, 각 장에 퀴즈나 클릭해 볼 수 있는 요소를 하나씩 넣어 줘.
  • 영상에서 슬라이드 한 개에 약 30분이 걸렸고 ultra 플랜 사용량의 약 1.5%를 썼다고 합니다. 큰 작업은 사용량을 고려하세요.
  • 9월 업데이트 영상은 Opus 5.5로 방향을 찾고 Sonnet 5.5로 빠르게 고치는 구분을 권했습니다.

2. 시트·화이트보드·데이터 아티팩트 쓰기

Claude Artifacts에 시트(Sheets)와 화이트보드(Whiteboard)가 추가됐고, 대시보드는 데이터(Data)로 이름이 바뀌었습니다. 모든 유료 플랜에서 쓸 수 있습니다. 표 정리와 아이디어·워크플로·행사 계획을 눈으로 펼쳐 볼 때 유용합니다.

  1. 유료 플랜 계정으로 Claude에 접속합니다.
  2. 아이디어 구상이나 행사 계획이 필요하면 Claude에게 화이트보드로 정리해 달라고 요청합니다.
  3. 간단한 표가 필요하면 시트로 만들어 달라고 요청합니다.
  4. 숫자 데이터를 보여 줄 때는 예전 '대시보드' 자리인 데이터 기능을 씁니다.
  5. 결과를 보고 항목 추가·삭제를 대화로 요청해 고칩니다.
예시
다음 달 팀 워크숍 준비 흐름을 화이트보드로 펼쳐 줘. 사전 준비, 당일 진행, 사후 정리로 나눠 줘.
  • 시트에는 피벗 테이블과 매크로가 없어 구글 시트를 대체하기는 어렵다는 평가입니다. 간단한 표용으로 쓰세요.
  • 예전 방식: 지금의 데이터 기능은 이전에 '대시보드'라고 불렸습니다.

3. 슬라이드·디자인·문서 한 번에 만들기

Claude Slides, Claude Design, Claude Docs는 출시 브리프 하나로 발표 자료, 이미지 세트, 한 장짜리 문서를 대화 안에서 만들어 줍니다. 회사 디자인 시스템을 먼저 만들어 두면 결과물이 덜 'AI스럽게' 나옵니다.

  1. Pro·Max·Team·Enterprise 같은 유료 구독인지 확인합니다. Claude Design은 무료 플랜에서 쓸 수 없습니다.
  2. Claude Design에서 먼저 회사의 디자인 시스템(색상·폰트·컴포넌트)을 생성합니다.
  3. 만들 것의 목적, 대상, 핵심 메시지를 브리프 하나로 적습니다.
  4. 그 브리프로 슬라이드, 소셜 이미지, 한 장짜리 문서를 요청합니다.
  5. 고칠 부분에 코멘트를 달아 Claude에게 보내면 그 부분을 고쳐 줍니다.
  6. 대화 내용을 바탕으로 문서·슬라이드를 만들 수도 있으니 정리된 대화가 있으면 그 자리에서 요청합니다.
  • Claude Design은 웹에서만 쓸 수 있고 사용량 한도가 채팅·Claude Code와 별도입니다. 영상 제작자는 Max 플랜에서 앱·PPT·디자인 시스템을 만들며 62%를 썼습니다.
  • Claude Slides·Design·Docs는 베타입니다.
  • 디자인 시스템 없이 쓰면 결과물이 'AI스럽다'는 한계가 지적됩니다.

4. Claude 모바일 앱 새 기능 쓰기

Claude 모바일 앱에서 업무용·개인 계정을 오가고, 태블릿에서는 대화와 아티팩트를 나란히 볼 수 있습니다. 출퇴근길이나 외근 중 Claude를 쓰는 분께 맞습니다.

  1. iOS 또는 Android 앱을 최신 버전으로 업데이트합니다.
  2. 업무용과 개인 계정을 모두 로그인해 로그아웃 없이 전환합니다.
  3. iPad나 iPhone Duo에서는 Claude가 만든 아티팩트를 대화 옆 열에 열어 두 창을 나란히 씁니다.
  4. 음성 모드를 켜 보세요. 더 빨라졌고 iPhone에서는 Apple CarPlay를 지원합니다.
  5. iPhone에서 사진을 고르면 업로드 중에도 채팅에 바로 표시되는지 확인합니다.

5. AI 환각 줄이며 답 확인하기

환각은 AI가 없는 내용을 사실처럼 말하는 현상입니다. 줄었지만 해결된 문제는 아니므로, 숫자·날짜·인용이 들어간 답은 사용자가 확인하는 습관이 필요합니다.

  1. 답에 구체적 사실, 통계, 인용, 날짜·이름·숫자가 있으면 위험 신호로 표시합니다.
  2. Claude에게 출처를 달라고 요청합니다.
  3. 확신도를 물어 어디가 불확실한지 말하게 합니다.
  4. 새 대화를 열어 같은 질문을 다시 해 답이 같은지 비교합니다.
  5. 중요한 내용은 출처를 직접 열어 확인한 뒤 씁니다.
예시
방금 답에서 구체적인 숫자와 인용마다 출처를 붙여 줘. 확신이 낮은 부분은 따로 표시해 줘.
  • 무명 주제와 최신 내용은 환각 가능성이 높습니다.
  • 횟수가 줄수록 확인을 건너뛰기 쉬우니 더 주의하세요.

6. 화제의 AI 소식, 출처 확인하기

SNS에서 크게 화제가 된 AI 글도 작성자, 링크, 원 논문을 보면 달리 읽힐 수 있습니다. 소식을 업무 판단에 쓰기 전에 확인하는 순서입니다.

  1. 화제 글의 작성자 프로필을 확인합니다.
  2. 글에 걸린 링크가 공식 저장소나 원 자료인지 확인합니다.
  3. 인용한 논문이 있으면 원문을 열어 표본 수와 조건을 봅니다.
  4. 수치가 무엇을 센 것인지(예: 전체인지 일부인지) 정의를 확인합니다.
  5. 확인한 내용만 팀에 공유합니다.
  • 영상 사례: 챗GPT 메모리 '96%' 글의 논문은 사용자 80명의 메모리 2,050개를 분석한 것이었고, 96%는 사용자가 요청하지 않고 GPT가 스스로 만든 메모리 비율이었습니다.
  • 조회수 200만 글의 작성자는 프로필상 해당 회사 CEO였고 링크도 공식 저장소였습니다.

7. AI 조언에 휘둘리지 않고 결정하기

Anthropic 연구에서 분석가들은 에이전트가 기운 쪽을 86% 따랐고, 설명할 때 77%가 에이전트 논거를 썼지만 출처로 밝힌 사람은 15%뿐이었습니다. AI와 계획을 세울 때 스스로 결정했다고 착각하지 않도록 하는 방법입니다.

  1. AI에게 추천을 받기 전에 내 우선순위를 먼저 묻고 정리하게 합니다.
  2. 두 안이 갈리면 말로만 고르지 말고 간단한 프로토타입으로 비교합니다.
  3. AI에게 그 조언을 바꿀 조건이 무엇인지 묻습니다.
  4. 최종 결정 후 어떤 논거가 AI에서 왔는지 따로 적어 둡니다.
예시
추천하기 전에 내 우선순위부터 질문해 줘. 그리고 네 추천이 바뀌려면 어떤 조건이 필요한지도 알려 줘.
  • 자기 선호가 있던 사람도 에이전트가 반대하면 60%가 선호를 바꿨습니다.
  • 한계: 에이전트의 기울기를 일부러 강화했고 한 분야·한 과제·한 모델만 연구했습니다.

8. AI 답을 이해하며 쓰기

AI 답을 복사해 전달만 하는 '미트 프록시'는 누구나 할 수 있어 가치가 없다는 이야기입니다. 이해를 확보하는 작업 방식을 소개합니다.

  1. 자료 조사와 검증은 AI에게 많이 돌리게 합니다.
  2. 제안서처럼 책임이 따르는 문서는 빈 문서에서 AI와 한 줄씩 씁니다.
  3. 한 줄을 쓸 때마다 이유를 AI에게 묻고 이해되면 넘어갑니다.
  4. 내 전문 분야에서는 AI가 모르는 맥락을 보태고 AI로 스스로 검증합니다.
  5. 일이 새로 들어오면 '이걸 안 하면 어떤 문제가 생길까?'를 먼저 묻습니다.
  • 일이 줄 것 같지만 새 일이 채워 더 바빠질 수 있습니다. 무엇을 만들고 버릴지 판단하는 힘이 중요해진다는 의견입니다.
  • 가장 소모적인 업무 절차 하나를 골라 지금도 필요한지, Claude로 줄일 수 있는지 점검해 보라는 제안도 있습니다.

9. Slack에서 Claude Tag로 일 맡기기

Claude Tag는 Slack 스레드에서 Claude를 태그해 팀과 함께 일하는 기능입니다. 채널 맥락을 파악해 작업하고 끝나거나 입력이 필요할 때 알려 줍니다. 여러 사람이 한 스레드에서 같이 지시할 수 있습니다.

  1. Team 또는 Enterprise 요금제인지 확인합니다. 현재 Slack에서 베타입니다.
  2. 관리자에게 Claude Tag 사용 가능 여부와 채널별 접근 범위를 확인합니다.
  3. 스레드에서 Claude를 태그해 작업을 요청합니다.
  4. 작업이 끝나거나 입력이 필요하다는 알림이 오면 답합니다.
  5. 여러 팀원이 같은 스레드에서 추가 지시를 합니다.
  6. 반복되는 채널 규칙은 지시로 남겨 메모리에 쌓이게 합니다.
  • Claude는 자기 계정과 권한을 가지며 채널별로 접근 범위가 나뉘고, 모든 자격 증명 사용이 기록됩니다.
  • 비공개 채널이나 DM에서 배운 내용은 그 안에만 남습니다.
  • Microsoft Teams 등으로 확대할 계획이 언급됐습니다.

10. Claude 데이터 보관 방식 이해하기

Claude Fable 5부터 안전 모니터링을 위해 최근 30일의 프롬프트와 출력이 저장됩니다. 회사 자료를 넣기 전에 알아 둘 보관·열람 규칙을 정리합니다.

  1. Fable 5 이상 모델을 쓰면 최근 30일의 프롬프트와 출력이 안전 모니터링용으로 저장된다는 점을 확인합니다.
  2. 엔터프라이즈 데이터는 명시적 허가 없이 학습에 쓰지 않는다는 점을 확인합니다.
  3. 사람의 검토는 자동 시스템이 유해 가능성을 표시한 드문 경우에만 승인된 소수 검토자가 한다는 점을 사내 보안 담당자와 공유합니다.
  4. 모니터링 데이터를 자체 클라우드에 두려면 Enterprise Frontier Safeguards(EFS) 제공 여부를 문의합니다.
  • EFS는 올가을 이후 단계적으로 제공되며, 그 전까지 대상 조직은 Fable 5와 5.1에서 데이터 보관 없음(ZDR)을 받습니다.
  • EFS의 로그는 고객이 통제하며 검토는 기계로만 이뤄집니다.

11. 새 모델 나오면 내 업무로 직접 평가하기

새 모델이 나올 때마다 앞선 고객 팀들은 자동화 평가(evals)를 먼저 돌려 봅니다. 벤치마크 점수보다 내 업무에서 되는지가 중요하기 때문입니다.

  1. 평소 쓰는 대표 업무 3~5개를 정해 같은 프롬프트로 기록해 둡니다.
  2. 새 모델이 나오면 그 프롬프트를 이전 모델과 새 모델에 똑같이 넣어 결과를 비교합니다.
  3. 법률 문서 초안처럼 복잡한 작업도 하나 맡겨 봅니다.
  4. 지금 안 되는 작업을 목록으로 남겨 다음 모델에서 다시 시도합니다.
  5. 결과가 좋아졌을 때만 기본 모델을 바꿉니다.
  • 모델 교체만으로 테스트 에이전트 성공률이 약 20% 올랐다는 사례가 있습니다.
  • API 쪽은 확장 사고에서 적응형 사고로 바꿀 때 한동안 이전 방식으로 되돌릴 수 있게 했고, 고객이 직접 평가를 돌려 보길 권합니다.
  • 예전 방식: 모델 성능을 벤치마크 수치로만 판단했다면 이제는 직접 평가를 돌려 보라는 흐름입니다.
