발표·소식

「발표·소식」은 Claude의 새 기능과 모델, 회사 소식, 연구·안전 이야기를 업무에 옮겨 쓰는 방법을 모은 분야입니다. 먼저 AI 답변을 믿기 전에 확인하는 법과 모바일 앱·문서 만들기 같은 기초부터 보세요. 그다음 모델 고르기, 데이터 보관 확인, Slack 협업을 거쳐 마지막의 에이전트 운영 가이드로 넘어가면 좋습니다. 일부 기능은 미국 요금제 대상이거나 베타입니다.

신기능 발표, 모델 출시, 회사 소식, 연구·안전 이야기 · 영상 56개 기반 · 2026-11-07 갱신

최근 바뀐 점

  • Claude 개인 금융 기능이 베타로 추가되어 계좌를 읽기 전용으로 연결해 지출·청구서·잔액을 설명받을 수 있습니다(미국 Pro·Max·Ultra 순차 제공).
  • Claude 모바일 앱에서 업무용·개인 계정을 로그아웃 없이 전환할 수 있고, 음성 모드가 빨라졌으며 iPhone은 Apple CarPlay를 지원합니다.
  • Claude Duet이 연구 프리뷰로 공개되어, 주의가 필요한 일을 먼저 알려 주고 폰을 내려놓은 뒤에도 일하는 앱의 대기자 명단을 받고 있습니다(미국 Pro·Max 대상).
  • Anthropic 연구에서 분석가가 에이전트가 기운 쪽을 86% 따랐다는 결과가 나와, AI 조언을 받아들이는 방식을 점검하라는 제안이 나왔습니다.

1. AI 답변 믿기 전에 확인하기

AI는 없는 내용을 사실처럼 말하는 환각을 일으킬 수 있습니다. 보고서나 회의 자료에 숫자·인용을 넣기 전에 쓰는 확인 습관입니다.

  1. 답변에 구체적 사실, 통계, 인용, 날짜, 이름, 숫자가 있는지 먼저 표시합니다.
  2. Claude에게 해당 내용의 출처를 알려 달라고 요청합니다.
  3. 각 주장에 대해 얼마나 확신하는지 물어봅니다.
  4. 새 대화를 열어 같은 내용을 다시 물어 답이 일치하는지 비교합니다.
  5. 중요한 수치와 인용은 원문 자료에서 직접 확인한 뒤 씁니다.
예시
방금 답변에 들어 있는 통계와 인용마다 출처를 알려 주고, 각각 얼마나 확신하는지 말해 줘. 확실하지 않은 것은 모른다고 말해 줘.
  • 환각은 1년 전보다 크게 줄었지만 해결된 문제는 아니며, 줄수록 확인을 건너뛰기 쉬우니 주의하세요.
  • 자료가 적은 무명 주제와 최신 내용에서 특히 틀리기 쉽습니다.
  • SNS에서 화제가 된 글도 작성자, 링크, 원 논문을 확인하면 달리 보일 수 있습니다.

2. Claude 모바일 앱 새 기능 쓰기

Claude 모바일 앱이 계정 전환, 음성 모드, 언어 지원 등을 업데이트했습니다. 출퇴근길이나 이동 중에 Claude를 쓰는 분께 맞습니다.

  1. iOS 또는 Android에서 Claude 앱을 최신 버전으로 업데이트합니다.
  2. 업무용 계정과 개인 계정에 모두 로그인합니다.
  3. 로그아웃하지 않고 두 계정을 오가며 전환해 봅니다.
  4. 음성 모드를 켜 보고 이전보다 빨라진 응답을 확인합니다.
  5. iPhone이라면 사진을 골라 채팅에 올려, 업로드 중에도 바로 표시되는지 확인합니다.
  • iPad와 iPhone Duo에서는 Claude가 만든 아티팩트가 대화 옆 열에 열려 두 창을 나란히 쓸 수 있습니다.
  • 앱이 총 33개 언어를 지원하고, iPhone의 음성 모드는 Apple CarPlay를 지원합니다.
  • iPhone·iPad의 당겨서 검색은 곧 제공 예정입니다. 웹과 데스크톱에는 이미 있고 Mac은 Command K입니다.

3. Claude 개인 금융 기능 살펴보기

Claude에 계좌를 연결해 지출, 청구서, 잔액을 쉬운 말로 설명받는 베타 기능입니다. 현재는 미국 사용자 대상이니 한국에서는 소식으로 알아 두세요.

  1. 내 요금제가 미국의 Pro, Max, Ultra 중 하나인지, 순차 제공 대상에 포함됐는지 확인합니다.
  2. Claude에 연결할 계좌를 직접 고릅니다.
  3. 연결 후 지출, 청구서, 잔액에 대해 궁금한 점을 질문합니다.
  4. 더 쓰지 않으려면 언제든 연결을 해제합니다.
  • Claude의 계좌 접근은 읽기 전용입니다.
  • 현재 베타이며 단계적으로 제공됩니다.

4. 문서·슬라이드·디자인 한 번에 만들기

Claude Slides, Design, Docs는 한 번의 브리프로 발표 자료, 이미지, 요약 문서를 대화 안에서 만드는 베타 기능입니다. 채팅과 Cowork가 하나의 Claude로 합쳐져 모드를 고를 필요도 없습니다.

  1. Claude 대화에서 만들고 싶은 결과를 일상 언어로 말합니다.
  2. 출시 계획 같은 브리프 하나를 붙여 넣고 슬라이드, 소셜 이미지 세트, 한 장짜리 문서를 요청합니다.
  3. 결과물에서 고치고 싶은 부분에 코멘트를 남깁니다.
  4. 코멘트를 Claude에게 보내 그 부분만 수정하게 합니다.
  5. Claude Docs에서는 팀원과 Claude가 같은 문서를 동시에 편집합니다.
예시
아래 출시 브리프로 발표 자료, 소셜 이미지 세트, 현장용 한 장 요약 문서를 만들어 줘.
[브리프 내용 붙여넣기]
  • 어떤 대화에서든 만들 수 있고, 기존 대화 내용을 바탕으로 결과물이 만들어집니다.
  • 작업이 클라우드에서 돌아 노트북을 닫아도 계속되고 휴대폰으로 진행 상황을 볼 수 있습니다.
  • 기존 Cowork 작업은 그대로 유지됩니다.

5. Claude Design으로 앱·PPT 만들기

Claude Design은 원하는 것을 일상 언어로 설명하면 제작 수준의 결과물을 만드는 도구입니다. 회사 디자인 시스템을 먼저 만들어 두면 이후 작업에 색상·폰트·컴포넌트가 자동 적용됩니다.

  1. 웹에서 Claude Design에 접속합니다(웹에서만 사용 가능).
  2. Pro, Max, Team, Enterprise 중 하나의 구독 상태인지 확인합니다.
  3. 먼저 회사의 디자인 시스템을 생성합니다.
  4. 그 시스템을 바탕으로 앱 프로토타입이나 12장짜리 피치덱을 요청합니다.
  5. 프로토타입을 클로드 코드로 넘겨 실제 웹 서비스로 구현합니다.
예시
우리 회사 디자인 시스템을 적용해서 투자자용 12장짜리 피치덱을 만들어 줘.
  • 디자인 시스템 없이 쓰면 결과물이 'AI스럽게' 나옵니다.
  • 사용량 한도가 채팅·클로드 코드와 별도로 관리되며 빡빡한 편입니다.
  • 4월 공개 때는 연구 프리뷰였고 9월 영상에서는 베타로 소개됩니다.
  • 무료 플랜은 쓸 수 없습니다.

6. 작업 단계별로 모델 나눠 쓰기

Claude 5.5 계열은 Opus 5.5와 Sonnet 5.5를 단계에 맞게 나눠 쓰기를 권합니다. 비용과 속도를 함께 챙기려는 팀을 위한 기본 전략입니다.

  1. 방향을 찾는 초기 단계에는 Opus 5.5를 씁니다.
  2. 방향이 정해지면 빠르게 고치는 단계에서 Sonnet 5.5로 바꿉니다.
  3. 개발·테스트처럼 품질이 중요한 곳에는 가장 큰 모델을 씁니다.
  4. 반복되는 운영 업무에는 저렴한 모델을 씁니다.
  5. 새 모델이 나오면 자동화 평가(evals)를 먼저 돌려 결과를 비교합니다.
  • Shopify는 이 방식을 배벨 전략이라 부르며, 폭주하는 프로세스에 대비한 서킷 브레이커도 필요하다고 합니다.
  • 지금 안 되는 작업을 적어 두면 다음 모델에서 나아질 영역의 단서가 됩니다.
  • 모델 교체만으로 테스트 에이전트 성공률이 약 20% 오른 사례도 있습니다.

7. AI 조언에 휘둘리지 않고 결정하기

Anthropic 연구에서 분석가들은 에이전트가 기운 쪽을 86% 따랐고, 설명할 때 출처로 에이전트를 밝힌 사람은 15%뿐이었습니다. 계획 단계에서 스스로 결정했다는 착각을 줄이는 세 가지 방법입니다.

  1. AI에게 추천을 요청하기 전에 나의 우선순위를 먼저 묻게 합니다.
  2. 추천이 나오면 바로 따르지 말고 프로토타입으로 직접 비교해 결정합니다.
  3. AI에게 이 조언이 바뀌려면 어떤 조건이어야 하는지 묻습니다.
  4. 최종 결정과 그 이유를 내 말로 적어 둡니다.
예시
추천하기 전에 내 우선순위가 무엇인지 먼저 질문해 줘. 그리고 네 조언이 달라지려면 어떤 조건이어야 하는지도 알려 줘.
  • 선호가 있던 사람도 에이전트가 반대하면 60%가 입장을 바꿨습니다.
  • 연구는 에이전트의 기울기를 일부러 강화했고, 한 분야·한 과제·한 모델만 다뤘다는 한계가 있습니다.

8. 데이터 보관 방식 확인하기

Claude Fable 5부터 안전 모니터링을 위해 최근 30일의 프롬프트와 출력이 저장됩니다. 회사 자료를 Claude에 넣는 직장인과 담당자가 알아 둘 내용입니다.

  1. 사용하는 모델이 Fable 5 이후인지 확인합니다.
  2. 저장 대상이 최근 30일의 프롬프트와 출력임을 팀에 공유합니다.
  3. 엔터프라이즈 데이터는 명시적 허가 없이 학습에 쓰이지 않는다는 점을 확인합니다.
  4. 데이터를 자체 클라우드에 두고 싶다면 Enterprise Frontier Safeguards(EFS) 제공 여부를 문의합니다.
  5. EFS 제공 전까지 대상 조직은 Fable 5와 5.1에서 데이터 보관 없음(ZDR)을 받는지 확인합니다.
  • 사람의 검토는 자동 시스템이 유해 가능성을 표시한 드문 경우에만, 승인된 소수 검토자가 하며 접근 기록은 변조 불가 로그에 남습니다.
  • EFS는 올가을 이후 단계적으로 제공됩니다.
  • EFS에서는 로그를 고객이 통제하고 검토는 기계로만 이뤄집니다.

9. Slack에서 Claude Tag로 팀 일 맡기기

Claude Tag는 Slack 채널에서 팀과 함께 일하는 Claude입니다. 스레드에서 태그하면 채널 맥락을 파악해 작업하고, 끝나거나 입력이 필요할 때 알려 줍니다.

  1. Team 또는 Enterprise 요금제에서 Claude Tag 베타를 쓸 수 있는지 확인합니다.
  2. Slack 스레드에서 Claude를 태그해 할 일을 적습니다.
  3. Claude가 채널 맥락을 파악해 작업하도록 기다립니다.
  4. 다른 팀원도 같은 스레드에서 함께 지시를 보탭니다.
  5. 작업 완료나 입력 요청 알림이 오면 확인하고 답합니다.
  6. Claude 계정의 채널별 접근 범위와 자격 증명 사용 기록을 점검합니다.
  • 메모리가 쌓여 채널별 지시를 기억하고, 비공개 채널이나 DM에서 배운 내용은 그 안에만 남습니다.
  • 데이터 질문 답변, PR 작성, 버그 수정, 사내 문의 응대에 쓰입니다.
  • Anthropic 제품 PR의 약 65%를 Tag가 작성합니다.
  • Microsoft Teams 등으로 확대할 계획입니다.

10. Claude Code 루틴으로 반복 일 맡기기

루틴은 사람이 지시하지 않아도 Claude Code가 정해진 조건에서 알아서 일하게 하는 기능입니다. 매일 반복되는 피드백 정리나 CI 수정 같은 일에 쓸 수 있습니다.

  1. 자동으로 맡길 반복 작업을 하나 정합니다.
  2. 루틴의 시작 조건을 일정, 웹훅, API 호출 중에서 고릅니다.
  3. 실행 위치를 로컬 또는 원격 클라우드로 정합니다.
  4. 작업 내용을 '피드백을 모아 중요도별로 분류하고 확신이 높은 것만 고친다'처럼 구체적으로 적습니다.
  5. 에이전트 뷰에서 실행 결과를 확인합니다.
예시
매일 들어온 피드백을 모아 중요도별로 분류하고, 확신이 높은 것만 수정해 줘.
  • 영상은 세부 사용 절차보다 기능 소개 중심이니 실제 설정 화면은 직접 확인하세요.
  • 모델 기술 기반이 약 두 달마다 바뀌어 하네스 기능은 필요 없어지면 지웁니다.

11. AI 에이전트에 목표 맡기고 안전장치 두기

Stripe와 Factory 같은 회사는 에이전트에게 작업이 아닌 목표를 맡기고, 품질은 AI의 판단이 아니라 구조적 보호 장치로 지킵니다. 에이전트를 팀에 도입하려는 리더를 위한 가이드입니다.

  1. 지시를 작업 단위가 아니라 달성할 목표로 바꿉니다.
  2. 개발자마다 격리된 개발 환경을 줍니다.
  3. 데이터 분리와 권한 같은 인프라 차원의 보호 장치를 둡니다.
  4. 점진적 배포 같은 하드 가드레일로 품질을 지킵니다.
  5. 검증·리뷰·유지보수를 새 병목으로 보고 팀 규칙을 다시 씁니다.
  6. 가장 소모적인 업무 절차 하나를 골라 지금도 필요한지 점검합니다.
  • Stripe의 한 엔지니어는 상반기에 AI 작성 PR 600개 이상을 병합했고 되돌린 것은 1건뿐이었습니다.
  • Factory는 COBOL 현대화에서 두 번째 작업부터 사람 개입이 90% 줄었다고 합니다.
  • 프로세스는 스스로 사라지지 않으니 의식적으로 정리해야 합니다.
  • 모델이 하니스를 흡수하므로 매달 기존 해법을 다시 의심해 보세요.
