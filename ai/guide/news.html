1. 작업에 맞는 Claude 모델 고르기

Claude에는 Fable 5.2, Opus 5.5, Sonnet 5.5, Haiku처럼 용도가 다른 모델이 있습니다. 작업 난이도에 맞춰 고르면 사용량과 시간을 아낄 수 있습니다.

  1. 일상적인 코딩이나 지식 작업은 Opus 5.5로 시작합니다.
  2. 작은 작업이나 빠른 수정은 Sonnet 5.5 또는 Haiku로 처리합니다.
  3. 가장 어려운 문제나 오래 걸리는 기술 작업에는 Fable 5.2를 씁니다.
  4. 모델을 바꾸고 싶으면 Claude의 모델 전환 메뉴에서 원하는 모델을 선택합니다.
  5. 결과가 아쉬우면 같은 요청을 다른 모델로 다시 돌려 비교합니다.
  • Fable 5.2는 유료 플랜에서 쓸 수 있습니다.
  • Fable 5.2는 사용량을 더 많이 쓰는 편입니다. 영상에서는 슬라이드 덱 하나를 약 30분 작업하는 데 ultra 플랜 사용량의 약 1.5%가 들었습니다.
  • 9월 업데이트 영상에서는 Opus 5.5로 방향을 찾고 Sonnet 5.5로 빠르게 고치는 순서를 권했습니다.

2. 모바일 앱에서 업무·개인 계정 전환하기

Claude 모바일 앱에서 업무용과 개인 계정에 동시에 로그인해 두고 전환할 수 있습니다. 계정마다 로그아웃과 로그인을 반복하지 않아도 됩니다.

  1. iOS 또는 Android의 Claude 앱을 최신 버전으로 업데이트합니다.
  2. 업무용 계정과 개인 계정에 모두 로그인합니다.
  3. 작업하려는 목적에 맞는 계정으로 전환해서 대화를 시작합니다.
  • 영상은 계정 전환 메뉴의 정확한 위치를 보여 주지 않으므로 앱 안에서 확인해야 합니다.
  • iPad와 iPhone Duo에서는 아티팩트가 대화 옆 열에 열려 두 창을 나란히 쓸 수 있습니다.
  • 음성 모드가 빨라졌고 iPhone에서는 Apple CarPlay를 지원합니다. 앱 인터페이스는 총 33개 언어를 지원합니다.

3. AI 답을 이해하고 검증해서 쓰기

AI 답을 복사해 전달만 하는 상태에서는 가치를 만들기 어렵습니다. AI는 없는 내용을 사실처럼 말하는 환각을 일으킬 수 있으므로, 이해하고 검증하며 쓰는 습관이 필요합니다.

  1. 자료 조사와 검증처럼 시간이 많이 드는 일은 AI에게 맡깁니다.
  2. 제안서처럼 내가 책임져야 하는 문서는 빈 문서에서 AI와 한 줄씩 쓰며 모르는 부분을 질문합니다.
  3. AI에게 답의 출처를 요청합니다.
  4. AI에게 이 답을 얼마나 확신하는지 물어봅니다.
  5. 중요한 내용은 새 대화를 열어 같은 사실을 다시 확인합니다.
예시
방금 답변에서 구체적인 수치와 인용을 모두 뽑아 줘. 각각의 출처와 네 확신 정도를 알려 주고, 확인하기 어려운 것은 따로 표시해 줘.
  • 구체적 사실·통계·인용, 무명 주제, 최신 내용, 정확한 날짜·이름·숫자에서 환각 가능성이 높습니다.
  • 환각이 줄수록 확인을 건너뛰기 쉬우니 주의해야 합니다.
  • Claude의 환각은 1년 전보다 크게 줄었지만 해결된 문제는 아닙니다.

4. AI 조언에 휘둘리지 않고 결정하기

Anthropic 연구에서 분석가들은 에이전트가 기운 쪽을 86% 따랐고, 스스로 결정했다고 착각하기 쉬웠습니다. 코딩 에이전트의 계획 단계에서 이를 줄이는 세 방법이 제안되었습니다.

  1. AI에게 추천을 구하기 전에, 내 우선순위를 먼저 AI가 묻도록 요청합니다.
  2. 고민되는 선택지는 말로만 정하지 말고 프로토타입을 만들어 비교해 결정합니다.
  3. AI에게 이 조언을 바꿀 조건이 무엇인지 물어봅니다.
  4. 최종 결정이 AI의 논거와 내 판단 중 어디에서 왔는지 따로 적어 둡니다.
예시
추천을 하기 전에 내 우선순위부터 질문해 줘. 그다음 각 선택지를 추천하는 이유와, 네 조언이 바뀌는 조건을 알려 줘.
  • 연구는 에이전트의 기울기를 일부러 강화했고, 한 분야·한 과제·한 모델만 다뤘다는 한계가 있습니다.
  • 사전에 선호가 있던 사람도 에이전트가 반대하면 60%가 선호를 바꿨습니다.

5. 시트·화이트보드·데이터 기능으로 일하기

Claude에 시트(Sheets), 화이트보드(Whiteboards), 데이터(Data, 옛 대시보드)가 추가되었습니다. 표 작업, 아이디어 구상, 데이터 공유를 Claude 안에서 처리할 때 씁니다.

  1. 유료 플랜 계정으로 Claude에 접속합니다. 세 기능 모두 유료 플랜에서 쓸 수 있습니다.
  2. 수식이 담긴 표가 필요하면 Claude Sheets에 요청합니다. 편집된 부분이 표시됩니다.
  3. 아이디어 구상, 워크플로, 행사 계획은 Claude Whiteboards로 시각적으로 펼칩니다.
  4. 데이터를 공유하거나 대시보드를 만들 때는 Claude Data를 씁니다.
  5. 작업은 각자 가진 권한 안에서만 이뤄지므로 필요한 권한이 있는지 확인합니다.
  • Whiteboards와 Sheets는 베타이고, Claude Data의 인증 쿼리와 실시간 공유도 아직 베타입니다.
  • 한 영상은 Sheets에 피벗 테이블과 매크로가 없어 구글 시트를 대체하기는 어렵다고 평가했습니다.
  • 같은 영상은 화이트보드가 아이디어 구상과 워크플로·행사 계획에 유용하다고 봤습니다.

6. Slides·Design·Docs로 발표 자료 만들기

Claude Slides, Design, Docs로 발표 자료, 소셜 이미지, 한 장짜리 문서를 대화 안에서 만들 수 있습니다. 새로 만들어야 하는 자료가 여러 종류일 때 유용합니다.

  1. 만들 자료의 내용을 담은 브리프(출시 안내 같은 기본 설명) 하나를 정리합니다.
  2. 그 브리프로 슬라이드, 소셜 이미지, 한 장짜리 문서를 Claude에게 요청합니다.
  3. 결과물에서 고치고 싶은 부분에 코멘트를 달아 Claude에게 보냅니다.
  4. Claude Design을 쓴다면 먼저 회사 디자인 시스템을 만들어 둡니다. 이후 프로젝트에 색상·폰트·컴포넌트가 자동 적용됩니다.
  • Slides, Design, Docs는 베타로 제공됩니다.
  • 디자인 시스템 없이 Claude Design을 쓰면 결과물이 AI스럽다는 평가가 있었습니다.
  • Claude Design은 리서치 프리뷰로 웹에서만 쓰며 Pro·Max·Team·Enterprise 구독이 필요하고, 사용량 한도가 별도로 관리됩니다.

7. Slack에서 Claude Tag 호출하기

Claude Tag는 Slack 스레드에서 Claude를 태그해 팀과 함께 일하게 하는 기능입니다. 채널의 맥락을 읽고 작업하며 끝나거나 입력이 필요할 때 알려 줍니다.

  1. Team 또는 Enterprise 요금제인지 확인합니다. 베타로 제공됩니다.
  2. Slack 스레드에서 Claude를 태그하고 작업을 요청합니다.
  3. 같은 스레드에서 여러 사람이 함께 추가 지시를 줄 수 있습니다.
  4. Claude가 완료나 입력 필요를 알리면 결과를 확인하고 다음 지시를 줍니다.
  5. 채널마다 반복되는 지시를 알려 주면 메모리로 쌓입니다.
  • Claude는 자기 계정과 권한을 가지며 채널별로 접근 범위가 나뉘고 모든 자격 증명 사용이 기록됩니다.
  • 비공개 채널이나 DM에서 배운 내용은 그 안에만 남습니다.
  • Anthropic은 제품 조직 PR의 약 65%를 Tag로 작성한다고 밝혔습니다.
  • Microsoft Teams 등으로 확대할 계획입니다.

8. Claude 개인 금융 기능 쓰기

개인 금융(Personal Finance)은 계좌를 연결해 지출, 청구서, 잔액을 쉽게 설명해 주는 베타 기능입니다. 가계 흐름을 정리할 때 씁니다.

  1. 미국의 Pro, Max, Ultra 플랜인지 확인합니다. 순차 제공 중입니다.
  2. Claude에 연결할 계좌를 직접 선택합니다.

  4. 더 이상 필요 없으면 언제든 연결을 해제합니다.
  • Claude의 접근은 읽기 전용입니다.
  • 영상에 자막이 거의 없어 세부 메뉴 이름은 확인되지 않았습니다. 한국 제공 여부도 밝혀지지 않았습니다.

9. 조직 도입 전 데이터 보관 방식 확인하기

Claude Fable 5부터 안전 모니터링을 위해 최근 30일의 프롬프트와 출력이 저장됩니다. 회사에서 쓰기 전에 이 방식과 기업용 옵션을 알아 두어야 합니다.

  1. Claude Fable 5 이후 모델은 최근 30일의 프롬프트와 출력이 안전 모니터링용으로 저장된다는 점을 확인합니다.
  2. 엔터프라이즈 데이터는 명시적 허가 없이 학습에 쓰지 않는다는 점을 확인합니다.
  3. 저장 데이터는 자동 시스템이 분석하며, 사람의 검토는 유해 가능성이 표시된 드문 경우에만 승인된 소수가 합니다.
  4. 모니터링 데이터를 자체 클라우드에 보관해야 하면 Enterprise Frontier Safeguards(EFS)를 검토합니다.
  5. EFS가 제공되기 전에는 대상 조직이 Fable 5와 5.1에서 데이터 보관 없음(ZDR)을 받는지 확인합니다.
  • EFS는 올가을 이후 단계적으로 제공됩니다.
  • EFS의 검토는 기계로만 이뤄지고 결과는 정해진 탐지 항목으로 제한됩니다.
  • 접근 기록은 변조 불가 로그에 남습니다.

10. API 비용을 줄이는 캐싱과 평가 습관

Claude API를 쓰는 팀이 비용과 모델 교체 위험을 관리하는 방법입니다. 프롬프트 캐싱과 직접 돌리는 평가(eval)가 핵심입니다.

  1. 비용 관리의 첫 번째로 프롬프트 캐싱을 적용합니다.
  2. 대화 중간에 effort나 시스템 프롬프트를 바꿔도 캐싱이 깨지지 않는 점을 활용합니다.
  3. 새 모델을 받으면 자동화 평가를 먼저 백그라운드로 돌려 봅니다.
  4. 확장 사고에서 적응형 사고로 바꿀 때는 한동안 이전 방식으로 되돌릴 수 있으므로 점진적으로 옮깁니다.
  5. 지금 안 되는 작업은 기록해 두고 다음 모델에서 다시 시험합니다.
  • 모델 교체만으로 테스트 에이전트 성공률이 약 20% 올랐다는 사례가 있습니다.
