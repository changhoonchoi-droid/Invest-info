Claude Code 고급

Claude Code 고급 단계에서는 스킬로 작업 방식을 저장하고, Hooks로 규칙을 강제하며, 서브에이전트로 일을 나누고, 루틴·클라우드 세션으로 내가 자리를 비운 사이에도 작업이 돌아가게 만들 수 있습니다. 스킬 → Hooks → 서브에이전트와 모델 선택 → 검증 루프 → 클라우드·루틴·프로젝트 → 플러그인과 모드 순서로 보면 기초에서 응용으로 자연스럽게 넘어갑니다.

서브에이전트, 스킬, Hooks, 플러그인, 병렬·백그라운드 작업, 워크트리, 대규모 작업 요령 · 영상 52개 기반 · 2026-11-20 갱신

1. 스킬로 반복 작업 방법 저장하기

스킬은 Claude에게 작업 방법을 한 번 가르쳐 두면 관련 상황에서 자동으로 적용되게 하는 마크다운 파일(SKILL.md)입니다. 매번 같은 지시를 반복해야 하는 보고서·양식 작업에 쓰면 좋습니다. 이름과 설명만 먼저 불러오므로 컨텍스트도 아낍니다.

  1. 잘 쓴 보고서나 결과물 하나를 준비해 Claude에 업로드합니다.
  2. 이 양식으로 주간 보고서 스킬을 만들어 줘라고 요청합니다.
  3. 만들어진 스킬을 저장합니다. 직접 만들 때는 개인용은 홈 디렉터리의 .claude/skills, 프로젝트용은 저장소 루트의 .claude/skills에 SKILL.md로 둡니다.
  4. 새로 만든 스킬이 인식되도록 세션을 재시작합니다.
  5. /를 입력해 스킬이 목록에 보이는지 확인합니다.
  6. 스킬 이름을 불러 호출하고 이번 주 자료만 넣습니다. 요청이 스킬 설명과 맞으면 자동으로도 적용됩니다.
예시
이 보고서 양식으로 '주간 보고서' 스킬을 만들어 줘. 앞으로 이번 주 자료만 주면 같은 구성과 말투로 초안을 써 주게 해 줘.
  • 스킬 이름은 달라도 되고, 안의 내용과 설명(description)이 맞는지만 확인하면 됩니다.
  • 항상 불러오는 CLAUDE.md와 달리 스킬은 요청이 맞을 때만 로드됩니다.
  • 프로젝트 스킬은 저장소를 받은 팀원 모두가 자동으로 받습니다.
  • 배포처럼 위험한 작업은 슬래시로 직접 호출하는 방식이 안전합니다.

2. 디자인 규칙을 스킬로 묶어 PPT 만들기

회사 디자인 규칙을 마크다운 문서로 만들고 PPT 제작 절차를 스킬로 저장하면, 대본만 넣어도 같은 디자인의 슬라이드가 나옵니다. AI 티 나는 PPT와 들쭉날쭉한 레이아웃을 줄이고 싶을 때 씁니다.

  1. 디자인 시스템 기반 샘플 PPT를 요청해 PPTX와 키노트 결과를 확인합니다.
  2. 만족스러울 때까지 샘플을 수정합니다.
  3. 대본과 디자인 시스템을 넣으면 PPT를 만들어 주는 스킬을 만들어 달라고 요청합니다.
  4. 요청에 새 작업 폴더 생성, HTML·PPTX·키노트 생성, HTML 기준 검증을 포함합니다.
  5. Claude Code를 껐다가 다시 실행해 스킬을 적용합니다.
  6. 스킬을 호출해 주제(예: 최신 AI 트렌드 정리)로 PPT를 만들어 달라고 요청합니다.
  7. 다른 디자인을 쓰려면 새 회사의 디자인 MD를 붙여 넣고 대본과 함께 요청합니다.
예시
방금 만든 샘플 PPT 방식을 스킬로 만들어 줘. 새 작업 폴더를 만들고 HTML, PPTX, 키노트를 생성한 뒤 HTML 기준으로 결과를 검증하는 단계까지 넣어 줘.
  • 스킬은 자동 호출되기도 하고 이름을 직접 불러 호출할 수도 있습니다.
  • 추가하고 싶은 레이아웃이 있으면 스킬에 계속 더해 가세요.

3. MCP를 스킬로 바꿔 토큰 아끼기

MCP는 연결하는 순간 도구 정의가 컨텍스트에 계속 남아 토큰을 차지합니다. 스킬은 시작 시 메타데이터만 읽고 필요할 때만 내용을 불러오므로, 자주 쓰는 MCP 작업은 스킬로 바꾸면 효율적입니다.

  1. /skill-creator를 실행합니다.
  2. 기존 MCP가 하던 일(예: n8n)을 스킬로 만들어 달라고 프롬프트를 입력합니다.
  3. 생성된 스킬들을 확인합니다.
  4. /mcp에서 해당 MCP를 선택해 Disable로 연결을 끊습니다.
  5. 스킬에 필요한 API 키를 새로 발급해 입력합니다.
  6. 같은 작업(예: n8n에 간단한 AI 챗봇 만들어 줘)을 요청해 동일하게 동작하는지 확인합니다.
예시
n8n에 간단한 AI 챗봇 만들어 줘
  • MCP는 세션 내내 토큰을 차지하지만 스킬은 사용할 때만 내용을 불러옵니다.
  • 스킬은 프롬프트에 따라 자동 실행되거나 슬래시 명령으로 직접 호출할 수 있습니다.

4. Hooks로 서식·차단 규칙 강제하기

Hooks는 Claude Code 작업의 특정 시점에 명령을 실행하는 기능입니다. CLAUDE.md의 지시는 가끔 지켜지지 않지만 Hook은 예외 없이 매번 실행됩니다. 자동 서식 정리, 위험 명령 차단, 완료 알림 등에 씁니다.

  1. .claude/settings.json 또는 /hooks에서 Hook을 설정합니다.
  2. 이벤트를 고릅니다. 사용할 수 있는 이벤트는 UserPromptSubmit, PreToolUse, PostToolUse, Notification, Stop입니다.
  3. 편집 후 서식 정리라면 PostToolUse에 matcher를 Edit 또는 MultiEdit로 지정합니다.
  4. 실행 명령에서 파일 확장자를 확인해 프로젝트에서 쓰는 포매터(Prettier, Go format, Ruff 등)를 실행하게 합니다.
  5. 위험 작업 차단은 PreToolUse Hook으로 만들고, stdin으로 받는 JSON의 도구 이름과 입력을 검사합니다.
  6. 막아야 하면 종료 코드 2로, 허용하면 0으로 끝냅니다. stderr 메시지는 Claude에게 차단 이유로 전달됩니다.
  7. 팀과 공유하려면 .claude/settings.json을 저장소에 커밋합니다.
  • CLAUDE.md는 권고, Hooks는 강제입니다.
  • rm -rf 포함 명령이나 main 브랜치 커밋 차단 같은 규칙에 알맞습니다.
  • 프로젝트 스크립트는 CLAUDE_PROJECT_DIR 환경 변수로 참조하면 작업 위치와 무관하게 동작합니다.

5. 서브에이전트와 모델 나눠 쓰기

서브에이전트는 자체 컨텍스트를 가진 별도의 Claude로, 메인 세션이 일부 작업을 맡기면 처리하고 결과만 보고합니다. 모든 부분에 가장 비싼 모델이 필요하지 않으므로 작업 성격에 따라 모델을 나누면 비용과 시간을 아낄 수 있습니다.

  1. 큰 작업(예: 모든 패키지의 프레임워크 버전 마이그레이션)은 Fable로 메인 세션을 시작합니다.
  2. 패키지 업그레이드나 테스트 수정처럼 범위가 분명한 부분을 가려 냅니다.
  3. Fable에게 마이그레이션을 이끌면서 그 부분은 Sonnet에게 넘기라고 요청합니다.
  4. 코드를 읽기만 하는 서브에이전트는 커스텀 서브에이전트의 frontmatter에서 모델을 Sonnet으로 지정합니다.
  5. 모든 서브에이전트의 기본 모델을 한 곳에서 바꾸려면 settings.json에 CLAUDE_CODE_SUBAGENT_MODEL 환경 변수를 설정합니다.
예시
이 마이그레이션은 네가 이끌어 줘. 패키지 업그레이드와 테스트 수정처럼 범위가 분명한 부분은 Sonnet 서브에이전트에게 맡기고 결과만 보고받아 줘.
  • 시작점은 중간 노력 수준의 Opus 5.5이고, 결과가 부족하면 먼저 노력 수준을 올립니다.
  • Sonnet은 범위가 분명한 작업에, Haiku는 요약·분류 같은 대량 작업에 맞습니다. 가용성과 한도는 요금제마다 다릅니다.
  • 탐색만 하는 서브에이전트에는 Opus급 추론이 필요 없습니다.
  • 예전 방식: 한 모델로 전 과정을 처리했지만, 지금은 부분별로 모델을 나누는 방식이 권장됩니다.

6. verify 스킬로 검증 루프 만들기

테스트나 린터만으로는 변경이 의도대로 동작하는지 증명되지 않습니다. 브라우저에서 클릭하고 확인하던 수동 절차를 스킬로 저장해 두면 Claude가 직접 실행하고, 실패하면 고쳐서 다시 확인합니다.

  1. Claude Code에 포함된 verify 스킬을 처음 사용합니다.
  2. Claude가 앱을 실행하고 변경 사항을 직접 확인하는 것을 지켜봅니다.
  3. 성공한 절차가 프로젝트에 스킬로 저장되는지 확인합니다.
  4. 생성된 스킬에 확인 항목을 추가합니다. 예: Chrome DevTools MCP로 레이아웃 시프트를 측정하는 성능 트레이스.
  5. 스킬에 언제 실행할지, 실패하면 무엇을 할지, 각 확인의 통과 기준을 적습니다.
  6. UI 변경을 요청하고 서버 실행, 페이지 열기, 클릭, 스크린샷, 성능 트레이스, 실패 시 재수정이 이뤄지는지 봅니다.
  • 확인 기준이 측정 가능할수록 Claude가 더 멀리 혼자 갑니다.
  • 성능 예산, 접근성 체크리스트, 디자인 시스템 규칙을 기준으로 삼을 수 있습니다.
  • 실수가 나오면 다시 시키지 말고 CLAUDE.md나 스킬에 적어 같은 실수를 막으세요.

7. 클라우드 세션으로 외출 중 작업 맡기기

클라우드 세션은 내 컴퓨터가 아닌 클라우드 가상 머신에서 도는 Claude Code 작업입니다. 노트북을 닫아도 계속되고 휴대폰으로 질문에 답할 수 있어, 큰 리팩터링이나 퇴근 전 맡겨 두는 작업에 알맞습니다.

  1. GitHub 계정을 연결하고 GitHub에서 접근을 승인합니다.
  2. Claude GitHub App을 설치하고 접근을 허용할 저장소를 고릅니다.
  3. 데스크톱 앱에서 Local 대신 Cloud를 선택합니다.
  4. 저장소, 환경, 시작할 브랜치를 고릅니다.
  5. Claude에게 작업을 맡기고 노트북을 닫습니다.
  6. 휴대폰 Claude 앱의 Code 탭에서 질문에 답하거나 방향을 조정합니다.
  7. 변경 내용(diff)을 검토합니다. 남긴 코멘트는 다음 메시지와 함께 Claude에게 전달됩니다.
  8. 문제가 없으면 Create PR을 눌러 풀 리퀘스트를 엽니다.
  • Pro, Max, Team 플랜과 일부 Enterprise 좌석에서 쓸 수 있고, 한도는 로컬 세션과 합산됩니다.
  • 세션은 저장소를 새로 복제해 시작하므로 커밋·푸시한 내용만 쓸 수 있습니다. 개인 설정, 스킬, 플러그인이 필요한 작업은 로컬에서 실행하세요.
  • 비공개 저장소는 Claude GitHub App이 접근할 수 있어야 목록에 나타납니다.
  • 기본 환경에 없는 것이 필요하면 사용자 지정 환경에서 네트워크 범위, 환경 변수, 설정 스크립트를 지정합니다.

8. Projects로 여러 작업을 병렬로 돌리기

Project는 Claude가 작업을 조율하는 하나의 지속적인 대화입니다. 작업마다 클라우드의 별도 브랜치에서 도는 스레드를 만들어 병렬로 처리하므로, 여러 세션이나 저장소에 걸친 큰 목표에 알맞습니다. 현재 베타이며 Pro와 Max에 순차 제공됩니다.

  1. 데스크톱 앱 또는 웹 앱에서 Claude 탭을 엽니다.
  2. 새 프로젝트를 만들고 이름, 달성할 목표, 관련 저장소나 폴더를 입력합니다.
  3. 메인 대화에서 코드베이스 탐색과 개선안 제안을 요청합니다.
  4. Claude가 찾은 내용을 보고 진행할 작업에 합의합니다.
  5. 작업마다 만들어진 스레드 카드를 눌러 진행 상황을 확인하고, 필요하면 방향을 바꾸거나 중단합니다.
  6. threads 탭에서 사용자를 기다리는 스레드를 확인합니다.
  7. 수정이 끝난 스레드가 풀 리퀘스트를 열게 하고, overview의 pull requests 탭에서 상태를 봅니다.
예시
이 저장소를 탐색해서 개선할 만한 점을 제안해 줘. 내가 동의한 항목은 각각 별도 스레드로 나눠서 진행해 줘.
  • 로컬 파일이나 도구가 필요한 작업은 해당 스레드를 내 컴퓨터에서 실행하도록 요청하세요.
  • 코디네이터는 낮은 노력 수준으로 두고, 스레드는 작은 모델을 기본으로 쓰다 복잡한 작업에서만 바꾸는 것이 권장됩니다.
  • library 탭은 모든 스레드가 공유하는 파일 폴더입니다.

9. 루틴으로 알아서 일하는 에이전트 만들기

루틴은 프롬프트, 저장소, 커넥터, 트리거만 정하면 Anthropic 관리형 인프라에서 Claude Code 세션을 자동 실행하는 기능입니다. 노트북이 꺼져 있어도 돌아가며, 매일 점검이나 매주 문서 갱신 같은 반복 업무에 알맞습니다.

  1. 루틴이 할 일을 프롬프트로 정합니다(예: 매주 병합된 변경을 문서 저장소와 비교해 문서 수정 PR 만들기).
  2. 연결할 저장소와 커넥터를 정합니다.
  3. 트리거를 고릅니다. 일정 기반 또는 GitHub 이벤트, 웹훅·API 호출 같은 이벤트 기반이 있습니다.
  4. 루틴을 만들 때 트리거, 컨텍스트, 조종 방식 세 가지를 정했는지 확인합니다.
  5. 실행된 루틴은 웹·CLI·데스크톱에서 열어 지시하고 이어서 쓸 수 있는 세션으로 남습니다.
예시
매일 아침 사용자 피드백을 모아 중요도별로 분류하고, 확신이 높은 항목만 수정안을 만들어 PR로 올려 줘.
  • Projects 안에서도 매일 성능 저하를 점검하는 루틴을 만들 수 있고, 문제가 발견되면 조사 스레드가 열립니다.
  • 스킬과 결합하면 매주 초안을 자동으로 받을 수 있습니다.
  • 종료 조건(검증 통과·최대 반복 횟수·비용 한도)을 겹쳐 정해 두면 안전합니다.

10. 모드로 Claude Code 화면·동작 바꾸기

모드(Mods)는 Claude Code의 모습과 행동 방식을 바꾸는 작은 프로그램입니다. 스킬·MCP가 밖에서 지식과 도구를 건네는 방식이라면, 모드는 작업 환경 자체를 바꿉니다. 코드를 몰라도 말로 설명하면 만들 수 있습니다.

  1. Claude Code 데스크톱 앱의 좌측 상단 코드 탭으로 들어갑니다.
  2. 로컬 옆 버튼에서 폴더 열기로 프로젝트 폴더를 만들어 엽니다.
  3. 만들고 싶은 모드를 말로 설명해 요청합니다(예: 토큰 사용량을 아이콘과 함께 보여 주는 모드).
  4. 핫 리로딩 안내가 나오면 Enable for this session을 누릅니다.
  5. 잘 보이는지 확인해 달라고 요청해 결과를 확인합니다.
  6. 모든 세션에서 쓰려면 방금 만든 모드를 플러그인으로 설치해 달라고 요청합니다.
  7. 다른 세션이나 프로젝트에서도 모드가 적용되는지 확인합니다.
예시
토큰 사용량을 아이콘과 함께 화면에 보여 주는 모드를 만들어 줘.
  • 모드를 만드는 전용 스킬이 이미 들어 있습니다.
  • 플러그인으로 설치하지 않으면 모드는 만든 대화 안에서만 작동합니다.
  • 직접 개발한다면 모드는 플러그인의 hook.json에 modules 키를 추가해 TypeScript 파일을 가리키게 하며, 파일을 저장하면 현재 세션에 바로 반영됩니다.
  • 모드는 마켓플레이스 저장소에 올려 공유할 수 있습니다.

11. CLI를 연결해 외부 서비스를 말로 조작하기

외부 서비스의 CLI를 Claude Code에 설치하면 자연어 요청만으로 그 서비스의 작업을 맡길 수 있습니다. 광고 소재 제작처럼 반복 작업이 많은 업무에 쓰는 사례입니다.

  1. 서비스 화면의 왼쪽 상단 프로필을 누릅니다.
  2. 세팅에서 디벨로퍼스 메뉴를 엽니다.
  3. CLI 설치 명령을 복사합니다(영상의 예: 어사이드 CLI).
  4. Claude Code 화면에 붙여 넣고 설치해 달라고 요청합니다.
  5. 만들 영상이나 이미지를 자연어로 요청합니다.
  • 작업이 길어지면 토큰을 꽤 소모합니다.
  • 기획·이미지·스토리라인을 미리 정하면 품질이 올라갑니다.
  • 템플릿과 제품의 감도가 맞아야 결과가 좋습니다.

12. 하네스로 Claude Code 환경 세팅하기

하네스는 AI가 잘 일하도록 지도(CLAUDE.md), 전문 절차(스킬), 강제 규칙(Hooks)을 갖춰 주는 환경 설계입니다. 새 프로젝트를 시작할 때 이 세 가지를 먼저 세팅하면 결과 품질이 안정됩니다.

  1. Claude 데스크톱의 Claude Code 탭에서 설정의 권한을 모두 허용 상태로 바꿉니다.
  2. 뉴세션을 누르고 작업 폴더를 만들어 엽니다.
  3. 프로젝트 정보(앱 목적, 기술 스택, 디자인 시스템)와 하네스 원칙을 담은 프롬프트를 입력합니다.
  4. 편집 모드를 권한 건너뛰기로 바꾸고 요청을 실행합니다.
  5. 생성된 CLAUDE.md, 스킬, 훅 구조를 파일 탭에서 확인합니다.
  6. 세션을 재시작합니다.
  7. /를 입력해 만들어진 스킬(예: 클린업)이 프로젝트 범위로 보이는지 확인합니다.
  • CLAUDE.md는 200줄 이내의 목차처럼 쓰고, 어길 수 없는 규칙은 Hooks에 맡깁니다.
  • 스킬은 재시작해야 같은 세션에서 인식됩니다.
  • /init으로 만든 CLAUDE.md는 직접 규칙을 추가해 다듬어야 효과가 있습니다.
  • 권한 건너뛰기는 위험할 수 있으니 연습용 폴더에서 먼저 쓰세요.
