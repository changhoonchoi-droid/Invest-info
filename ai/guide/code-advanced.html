Claude Code 고급

Claude Code 고급 기능을 쓰면 반복해서 설명하던 일을 스킬로 굳히고, Hooks로 규칙을 빠짐없이 지키게 하고, 클라우드 세션·Projects·루틴으로 내가 자리를 비운 사이에도 여러 작업을 동시에 맡길 수 있습니다. 먼저 스킬과 모드로 Claude의 일하는 방식을 바꾸는 법을 익히고, 서브에이전트·Hooks·검증 루프로 품질을 잡은 뒤, 클라우드 세션과 Projects·루틴으로 병렬·백그라운드 작업을 넓혀 가는 순서를 권합니다. 마지막 두 가이드는 기억 서버 연결과 큰 코드 이식처럼 시간이 드는 고급 실습입니다.

서브에이전트, 스킬, Hooks, 플러그인, 병렬·백그라운드 작업, 워크트리, 대규모 작업 요령 · 영상 36개 기반 · 2026-10-31 갱신

최근 바뀐 점

  • 10월 1일 Anthropic이 Claude Code의 화면과 행동 방식을 바꾸는 '모드(Mods)'를 공식 발표했고, 데스크톱 앱에서는 말로 설명만 해도 모드를 만들 수 있습니다.
  • Claude Code Projects(베타)가 Pro·Max 요금제에 차례로 제공됩니다. 하나의 대화가 작업마다 클라우드 스레드를 만들어 여러 일을 동시에 처리합니다.
  • 데스크톱 앱에서 Local 대신 Cloud를 고르면 클라우드 세션으로 작업이 돌아가 노트북을 닫아도 이어지고, 휴대폰 Claude 앱의 Code 탭에서 답하거나 방향을 바꿀 수 있습니다.
  • Shorts를 시리즈로 묶고 시리즈마다 스킬을 두어 같은 지시로 같은 품질을 내는 방식으로, 일주일에 롱폼 약 8편과 Shorts 약 60개를 만든 사례가 소개됐습니다.
스킬로 작업 방법 가르쳐 두기모드 만들어 모든 세션에 쓰기서브에이전트를 싼 모델로 돌리기Hook으로 편집 후 자동 서식 맞추기verify 스킬로 검증 루프 만들기클라우드 세션에 작업 맡기기Hook으로 위험한 작업 막기hook.json으로 모드 직접 만들기Projects로 여러 작업 병렬 처리하기루틴으로 반복 점검 자동화하기기억 서버로 세션 간 기억 잇기큰 코드 이식을 테스트로 맡기기
입문

1. 스킬로 작업 방법 가르쳐 두기

스킬은 Claude에게 작업 방법을 한 번 적어 두면 관련 요청이 올 때 자동으로 꺼내 쓰게 하는 마크다운 파일(SKILL.md)입니다. 같은 설명을 매번 반복하거나 같은 실수가 되풀이될 때, 또는 같은 품질의 결과를 계속 내야 할 때 씁니다.

  1. 매번 반복해서 설명하는 작업이나 Claude가 자꾸 틀리는 작업 하나를 고릅니다.
  2. 모든 프로젝트에서 쓸 스킬이면 홈 디렉터리의 .claude/skills, 팀과 함께 쓸 스킬이면 저장소 루트의 .claude/skills에 두기로 정합니다.
  3. 그 폴더에 SKILL.md 파일을 만들고 작업 방법을 적습니다.
  4. 파일 안의 설명(description)에 어떤 요청일 때 쓰는 스킬인지 분명하게 적습니다. Claude는 이 설명을 보고 스킬을 고릅니다.
  5. 관련된 요청을 해서 스킬이 자동으로 적용되는지 확인합니다.
  6. 결과가 마음에 들지 않으면 Claude에게 다시 시키지 말고 스킬 파일을 고칩니다.
예시
방금 고친 실수가 다시 나오지 않도록, 이 작업 절차를 프로젝트 스킬로 만들어 줘.
  • CLAUDE.md는 모든 대화에 항상 불러오고, 스킬은 요청이 맞을 때만 불러옵니다. 슬래시 명령은 직접 입력해야 하지만 스킬은 자동으로 적용됩니다.
  • 스킬에는 해야 할 일의 목록보다 '어떻게 생각할지'를 담은 원칙을 적는 편이 좋습니다.
  • 회사에서 여럿이 쓸 스킬은 첫 스킬을 내놓기 전에 소유자·검토자·폐기 기준·테스트 방식을 먼저 정하세요. 파워 유저가 자기에게만 맞춘 스킬이 문제를 일으킨 사례가 있습니다.
  • 콘텐츠처럼 같은 형식을 반복하는 일은 시리즈마다 스킬을 하나씩 두면 같은 지시로 같은 결과가 나옵니다.

2. 모드 만들어 모든 세션에 쓰기

모드는 Claude Code의 모습과 행동 방식을 바꾸는 작은 프로그램으로, Claude가 작업할 때 나오는 신호를 듣고 지켜보거나 고치거나 대신 처리합니다. 스킬·MCP가 지식과 도구를 건네는 방식이라면 모드는 작업 환경 자체를 바꾸며, 데스크톱 앱에서는 말로 설명만 해도 만들 수 있습니다.

  1. Claude Code 데스크톱 앱의 좌측 상단 코드 탭으로 들어갑니다.
  2. 로컬 옆 버튼에서 폴더 열기로 프로젝트 폴더를 만들어 엽니다.
  3. 만들고 싶은 모드를 말로 설명해 요청합니다.
  4. 핫 리로딩 안내가 나오면 Enable for this session을 누릅니다.
  5. 모드가 잘 보이는지 확인해 달라고 요청해 결과를 봅니다.
  6. 같은 대화에서 방금 만든 모드를 내 모든 세션에서 쓸 수 있도록 플러그인으로 설치해 달라고 요청합니다.
  7. 다른 세션이나 프로젝트를 열어 모드가 적용되는지 확인합니다.
예시
토큰 사용량을 아이콘과 함께 보여 주는 모드를 만들어 줘.
  • 모드를 만드는 전용 스킬이 이미 들어 있어 코드를 몰라도 말로 설명하면 됩니다.
  • 플러그인으로 설치하지 않으면 모드는 만든 대화 안에서만 작동합니다.
  • 창·버튼 같은 화면 요소는 모드로만 만들 수 있습니다.
  • 응용 예: 턴이 끝날 때마다 다음 할 일 세 가지를 카드로 띄우고 클릭하면 바로 실행되는 '다음 작업 추천' 모드.

3. 서브에이전트를 싼 모델로 돌리기

서브에이전트는 메인 Claude가 일부 일을 떼어 맡기는 보조 에이전트입니다. 코드를 읽기만 하는 탐색이나 커밋 전 리뷰처럼 깊은 추론이 필요 없는 일은 작은 모델로 돌려 비용과 사용 한도를 아낄 수 있습니다.

  1. 코드베이스를 읽기만 하는 탐색 작업처럼 서브에이전트에게 맡길 일을 정합니다.
  2. 커스텀 서브에이전트의 frontmatter에서 모델을 Sonnet으로 지정합니다.
  3. 모든 서브에이전트의 기본 모델을 한 번에 바꾸려면 settings.json에 CLAUDE_CODE_SUBAGENT_MODEL 환경 변수를 설정합니다.
  4. 커밋하기 전에는 서브에이전트 코드 리뷰어로 변경 내용을 점검하고 커밋 메시지를 만들게 합니다.
예시
커밋하기 전에 서브에이전트 코드 리뷰어로 변경 내용을 점검하고, 문제가 없으면 커밋 메시지를 만들어 줘.
  • 읽기 전용 서브에이전트는 Sonnet, 경우에 따라 Haiku로도 충분합니다.
  • 메인 모델 Opus 5.5의 기본 effort는 medium이라 대부분의 작업에 충분하지만, 여러 파일이나 프로젝트 전체를 바꾸는 수정에는 high를 씁니다.
  • Opus 5.5는 Opus 5보다 토큰당 20% 저렴하고 Pro·Max·Team 한도도 25% 더 갑니다.

4. Hook으로 편집 후 자동 서식 맞추기

Hooks는 Claude Code가 일하는 특정 시점에 정해 둔 명령을 실행하는 기능입니다. CLAUDE.md의 지시는 가끔 빠지지만 Hook은 예외 없이 매번 실행되므로, 파일을 고칠 때마다 코드 서식을 맞추는 일처럼 꼭 지켜야 하는 규칙에 씁니다.

  1. /hooks를 입력하거나 settings.json을 열어 Hook 설정을 시작합니다.
  2. 이벤트로 PostToolUse를 고릅니다.
  3. matcher를 Edit 또는 MultiEdit로 지정합니다.
  4. 실행 명령에서 고친 파일의 확장자를 확인해 맞는 포매터를 실행하게 합니다.
  5. TypeScript는 Prettier, Go는 Go format, Python은 Ruff처럼 프로젝트에서 쓰는 도구를 연결합니다.
  6. 파일을 하나 고쳐 달라고 요청해 서식이 자동으로 맞춰지는지 확인합니다.
예시
/hooks
  • 쓸 수 있는 이벤트는 UserPromptSubmit, PreToolUse, PostToolUse, Notification, Stop입니다. 작업 완료 알림이나 실행 명령 기록에도 쓸 수 있습니다.
  • CLAUDE.md에 '서식을 맞춰 줘'라고 적는 것보다 Hook이 훨씬 확실합니다.
  • /context를 실행하면 컨텍스트를 얼마나 쓰고 있는지 색 격자로 볼 수 있습니다.

5. verify 스킬로 검증 루프 만들기

Claude Code는 테스트·타입 검사·린터는 스스로 돌리지만, 그것만으로는 변경이 실제로 의도대로 동작하는지 알 수 없습니다. 브라우저에서 눌러 보고 화면을 확인하는 수동 점검 절차를 스킬로 만들어 두면 Claude가 직접 확인하고, 실패하면 고쳐서 다시 확인합니다.

  1. Claude Code에 들어 있는 verify 스킬을 처음 사용합니다.
  2. Claude가 앱을 실행하고 변경 사항을 앱에서 직접 확인하는 과정을 지켜봅니다.
  3. 성공한 확인 절차가 프로젝트에 스킬로 저장되는지 확인합니다.
  4. 저장된 스킬에 확인 항목을 더합니다. 예: Chrome DevTools MCP로 레이아웃 시프트를 재는 성능 트레이스.
  5. 스킬에 언제 실행할지, 확인에 실패하면 무엇을 할지, 항목별 통과 기준을 적습니다.
  6. 화면 변경을 요청하고 Claude가 서버 실행·페이지 열기·클릭·스크린샷·성능 측정을 한 뒤 실패 시 고쳐 다시 확인하는지 봅니다.
예시
화면을 바꾼 뒤에는 verify 스킬로 앱을 직접 실행해 확인하고, 통과 기준을 못 맞추면 고쳐서 다시 확인해 줘.
  • 통과 기준이 측정 가능할수록 Claude가 혼자 더 멀리 갑니다.
  • 내가 손으로 확인하고 고칠 점을 알려 주고 있다면 그걸 기준으로 바꿔 보세요. 예: 성능 예산, 접근성 체크리스트, 디자인 시스템 규칙.
  • 웹은 브라우저(예: Playwright MCP), 백엔드는 엔드포인트 호출, 모바일은 iOS 시뮬레이터로 확인 절차를 만들 수 있습니다.
  • 검증을 사람과 에이전트가 같은 명령으로 돌릴 수 있게 만들어 두면 CI에서도 그대로 씁니다(예: bun verify).

6. 클라우드 세션에 작업 맡기기

클라우드 세션은 내 컴퓨터가 아닌 클라우드 가상 머신에서 돌아가는 Claude Code 작업입니다. GitHub 저장소를 복제해 별도 브랜치에서 일하므로 노트북을 닫아도 계속되고, 퇴근 전에 큰 수정을 맡겨 두거나 여러 작업을 동시에 돌릴 때 좋습니다.

  1. GitHub 계정을 연결하고 GitHub에서 접근을 승인합니다.
  2. Claude GitHub App을 설치하고 접근을 허용할 저장소를 고릅니다.
  3. 데스크톱 앱에서 Local 대신 Cloud를 선택합니다.
  4. 저장소, 환경, 시작할 브랜치를 고릅니다.
  5. Claude에게 작업을 맡기고 노트북을 닫습니다.
  6. 휴대폰 Claude 앱의 Code 탭에서 질문에 답하거나 방향을 조정합니다.
  7. 변경 내용(diff)을 검토합니다. 남긴 코멘트는 다음 메시지와 함께 Claude에게 전달됩니다.
  8. 문제가 없으면 Create PR을 눌러 GitHub에 풀 리퀘스트를 엽니다.
  • 세션은 저장소를 새로 복제해 시작하므로 커밋·푸시한 내용만 씁니다. 개인 설정·스킬·플러그인이 필요한 작업은 로컬에서 돌리세요.
  • 기본 환경에 없는 도구가 필요하면 사용자 지정 환경을 만들어 네트워크 범위, 환경 변수, 설치용 설정 스크립트를 정합니다.
  • 터미널에서 teleport 플래그를 붙여 claude를 실행하면 클라우드 세션을 내 컴퓨터로 가져와 이어갈 수 있습니다.
  • Remote Control은 내 컴퓨터에서 도는 세션에 연결하는 방식이라 컴퓨터가 켜져 있어야 합니다. 클라우드 세션 비용은 플랜 한도에 합산되며 가상 머신 비용은 따로 없습니다.

7. Hook으로 위험한 작업 막기

PreToolUse Hook은 Claude가 도구를 쓰기 직전에 실행되어 그 작업을 허용할지 막을지 정합니다. rm -rf 같은 삭제 명령, 운영 설정 폴더 쓰기, main 브랜치 커밋처럼 절대 일어나면 안 되는 일을 확실하게 차단할 때 씁니다.

  1. 이벤트를 PreToolUse로 하는 Hook을 만듭니다.
  2. Hook 스크립트가 stdin으로 받는 JSON에서 도구 이름과 입력 내용을 검사하게 합니다.
  3. 막아야 할 작업이면 종료 코드 2로 끝내게 합니다.
  4. 차단할 때 stderr에 이유를 남겨 Claude가 그 이유를 보고 방법을 바꾸게 합니다.
  5. 허용할 작업이면 종료 코드 0으로 끝내게 합니다.
  6. 팀 전체에 적용하려면 Hook을 .claude/settings.json에 넣고 저장소에 커밋합니다.
  • 프로젝트 안 스크립트는 CLAUDE_PROJECT_DIR 환경 변수로 경로를 적으면 작업 폴더가 달라도 동작합니다.
  • .claude/settings.json은 프로젝트 수준 설정이라 저장소를 받은 팀원에게 같은 Hook이 자동 적용됩니다.
  • 자동 모드에서도 deny·ask·allow 규칙이 먼저 실행됩니다. 꼭 막아야 할 일은 분류기에 맡기지 말고 규칙과 Hook으로 정해 두세요.

8. hook.json으로 모드 직접 만들기

모드는 플러그인의 한 형태로, Claude Code 내부 이벤트에 TypeScript 함수를 붙여 화면에 그릴 내용이나 프롬프트, 호출할 도구를 바꿉니다. 데스크톱 앱의 말로 만들기로 부족할 때 코드를 직접 짜서 세밀하게 조정합니다.

  1. 플러그인의 hook.json에 modules 키를 추가하고 TypeScript 파일을 가리키게 합니다.
  2. 그 파일에서 렌더 이벤트(render)에 함수를 등록합니다.
  3. 이벤트 데이터로 들어오는 답변 텍스트에서 바꿀 부분(예: 이메일 주소)을 찾습니다.
  4. $send 객체로 바꾼 화면 블록을 만듭니다(예: 마우스를 올릴 때만 보이는 텍스트).
  5. next를 호출하지 않고 결과를 직접 반환해 Claude Code가 내 버전을 그리게 합니다.
  6. plugin dir 플래그로 그 폴더를 지정해 Claude Code를 시작하거나, 데스크톱 앱은 글로벌 설정 파일에 폴더를 추가합니다.
  • 함수는 $send 객체, 이벤트, next 세 값을 받습니다. next에 넘긴 값이 Claude Code가 실제로 수행하는 내용입니다.
  • 폴더를 감시하므로 파일을 저장하면 현재 세션에 바로 반영됩니다.
  • 렌더 변경은 화면만 바꿉니다. 모델은 원래 내용(실제 이메일 주소)을 그대로 씁니다.
  • 모드는 자체 샌드박스에서 Claude Code가 노출한 이벤트만 볼 수 있고, 플러그인이라 마켓플레이스 저장소에 올려 공유할 수 있습니다.

9. Projects로 여러 작업 병렬 처리하기

Project는 Claude가 큰 목표를 맡아 작업을 조율하는 하나의 지속적인 대화입니다. 작업마다 클라우드의 별도 브랜치에서 도는 스레드를 만들어 동시에 처리하므로, 여러 세션이나 저장소에 걸친 큰 일에 알맞습니다(현재 베타, Pro·Max에 순차 제공).

  1. 데스크톱 앱 또는 웹 앱에서 Claude 탭을 엽니다.
  2. 새 프로젝트를 만들고 이름, Claude가 달성할 목표, 관련 저장소나 폴더를 입력합니다.
  3. 열린 메인 대화에서 코드베이스 탐색과 개선안 제안을 요청합니다.
  4. Claude가 찾은 내용을 보고 진행할 작업에 합의합니다.
  5. 작업마다 생긴 스레드 카드를 눌러 진행 상황을 보고, 필요하면 스레드에 말을 걸어 방향을 바꾸거나 중단합니다.
  6. threads 탭에서 내 답을 기다리는 스레드를 확인합니다.
예시
이 저장소를 살펴보고 개선할 점을 제안해 줘. 합의한 작업은 각각 스레드로 나눠서 진행해 줘.
  • 메인(코디네이터) 대화는 낮은 노력 수준으로, 스레드는 작은 모델을 기본으로 두고 복잡한 작업에서만 바꾸는 것을 권합니다.
  • library 탭은 아티팩트와 직접 넣은 파일(목업, 디자인 명세)을 모든 스레드가 함께 쓰는 폴더입니다. 스레드 공유 메모리는 프로젝트 설정에서 고칩니다.
  • 로컬 파일이나 도구가 필요한 작업은 그 스레드를 내 컴퓨터에서 돌리도록 요청합니다.
  • 내 컴퓨터에서 같은 저장소로 여러 세션을 동시에 돌릴 때는 세션마다 worktree를 나눠 쓰면 서로 부딪히지 않습니다(DoorDash·Spotify 사례).

10. 루틴으로 반복 점검 자동화하기

루틴은 프롬프트·저장소·커넥터·트리거만 정하면 Anthropic 관리형 인프라에서 Claude Code 세션을 자동으로 실행하는 기능입니다. PR 관리, 피드백 분류, 문서 갱신, 성능 저하 점검처럼 매일·매주 반복되는 일을 내가 시키기 전에 먼저 처리하게 합니다.

  1. 매일·매주 반복되는 점검 업무 하나를 고릅니다.
  2. 루틴이 쓸 프롬프트, 연결할 저장소, 필요한 커넥터를 정합니다.
  3. 트리거를 정합니다: 시간 기반 일정, 또는 GitHub 이벤트·웹훅·API 호출 같은 이벤트.
  4. 지표를 봐야 하면 모니터링 서비스를 Claude에 연결합니다.
  5. Claude에게 루틴을 만들어 달라고 요청합니다.
  6. 루틴이 실행된 세션을 웹·CLI·데스크톱에서 열어 결과를 보고 이어서 지시합니다.
  7. 루틴이 연 PR은 overview의 pull requests 탭에서 상태를 보고, 준비되면 Claude에게 병합을 요청합니다.
예시
매주 병합된 변경을 문서 저장소와 비교해서, 고칠 곳이 있으면 문서 수정 PR을 만드는 루틴을 만들어 줘.
  • 관리형 인프라에서 돌아가므로 노트북이 꺼져 있어도 실행됩니다.
  • 루틴이 문제를 찾으면 조사 스레드를 열어 프로젝트에서 기다리게 할 수 있습니다.
  • 피드백을 중요도별로 분류하고 확신이 높은 것만 고치게 하면 안전합니다.
  • 정해진 반복 업무는 루틴·루프로, 단계를 미리 알 수 없는 작업(시스템 최적화 등)은 동적 워크플로로 맡기는 구분이 권장됩니다.

11. 기억 서버로 세션 간 기억 잇기

Claude는 세션이 끝나면 내용을 기억하지 못하므로, 이어서 일하는 에이전트에는 별도의 기억 저장소가 필요합니다. 내 PC에 Hindsight 기억 서버를 띄우고 MCP로 연결하면 세션 A에서 저장한 사실을 새 세션 B가 꺼내 쓸 수 있습니다.

  1. make env로 준비물 표가 모두 통과하는지 확인합니다.
  2. make models로 모델을 미리 받아 둡니다.
  3. Claude Code를 열고 폴더 신뢰 대화 상자에서 신뢰를 누릅니다.
  4. labs/01 폴더의 PROMPT.md 내용을 그대로 붙여 넣어 서버를 띄웁니다.
  5. MCP 연결 목록에서 Hindsight 서버가 connected로 뜨는지 확인합니다.
  6. 세션 A에서 가상 인물의 정보를 저장해 달라고 요청합니다.
  7. 세션을 닫고 새 세션 B에서 같은 정보를 물어 기억에서 꺼내 답하는지 봅니다.
예시
make env
  • 저장 직후 바로 물으면 빈 결과가 나올 수 있으니 저장이 끝날 때까지 기다리는 동기 방식으로 저장하게 합니다.
  • 처음부터 다시 하려면 make reset을 실행합니다.
  • API 키는 .env 파일에만 둡니다.
  • 로컬 Ollama(Gemma 3 12B) 기준 15~25분 걸리며 메모리 16GB 이상을 권장합니다.
