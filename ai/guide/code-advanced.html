Claude Code 고급

Claude Code를 한 단계 더 쓰고 싶은 분을 위한 가이드입니다. 같은 작업을 반복 저장하는 스킬, 어길 수 없는 규칙을 거는 Hooks, 일을 나눠 맡기는 서브에이전트와 모델 선택, 플러그인(모드), 클라우드·루틴·프로젝트를 이용한 병렬·백그라운드 작업 순으로 구성했습니다. 위에서부터 차례로 따라 하면 쉬운 것부터 큰 작업 요령까지 이어집니다.

서브에이전트, 스킬, Hooks, 플러그인, 병렬·백그라운드 작업, 워크트리, 대규모 작업 요령 · 영상 51개 기반 · 2026-11-16 갱신

최근 바뀐 점

  • Fable 5.2 출시와 함께, 큰 작업은 Fable 메인 세션이 이끌고 범위가 분명한 부분은 Sonnet 서브에이전트에게 넘기는 방식이 소개됐습니다(11/11).
  • 주간 보고서 같은 반복 업무를 스킬로 만들고 예약 작업과 결합해 매주 초안을 자동으로 받는 방법이 나왔습니다(11/15).
  • 영상 편집 매뉴얼을 스킬로 저장하고 루틴으로 1~2시간마다 드라이브 폴더를 확인하게 하면 업로드만으로 편집이 돌아가는 사례가 공개됐습니다(11/13).
  • 모드(Mods)는 만든 뒤 플러그인으로 설치하면 모든 세션에서 쓸 수 있다는 점이 정리됐습니다(10/21).

1. 반복 업무를 스킬로 저장하기

스킬은 작업 방법을 한 번 가르쳐 두면 관련 상황에서 Claude가 꺼내 쓰는 마크다운 파일(SKILL.md)입니다. 매주 같은 양식의 보고서나 PPT처럼 반복되는 업무에 쓰면 매번 설명하지 않아도 같은 품질로 결과가 나옵니다.

  1. 평소 잘 썼다고 생각하는 결과물(예: 보고서) 하나를 준비해 Claude에 업로드합니다.
  2. "이 양식으로 주간 보고서 스킬을 만들어 줘"라고 요청합니다.
  3. 만들어진 스킬을 저장합니다.
  4. 스킬을 바로 인식하지 못하면 Claude Code를 껐다가 다시 실행합니다.
  5. 다음부터는 슬래시(/)로 스킬 이름을 부르고 이번 주 자료만 넣습니다.
  6. 빠진 항목이나 레이아웃이 있으면 스킬에 계속 더해 가며 다듬습니다.
예시
첨부한 보고서를 양식 기준으로 삼아 '주간 보고서 스킬'을 만들어 줘. 앞으로 이번 주 자료만 주면 같은 구성으로 초안을 써 주게 해 줘.
  • 스킬 이름은 달라도 되고, 안에 든 내용만 확인하면 됩니다.
  • 개인 스킬은 홈 디렉터리의 .claude/skills에, 프로젝트 스킬은 저장소 루트의 .claude/skills에 두면 팀이 함께 씁니다.
  • 스킬은 자동으로 적용되기도 하고 이름을 직접 불러 호출할 수도 있습니다. 매번 읽는 CLAUDE.md와 달리 요청이 맞을 때만 불러와 컨텍스트를 아낍니다.
  • 예약 작업이나 루틴과 결합하면 매주 초안을 자동으로 받을 수 있습니다.

2. MCP를 스킬로 바꿔 토큰 아끼기

MCP는 연결하는 순간 도구 정의가 컨텍스트에 상주해 세션 내내 토큰을 차지합니다. 스킬은 시작할 때 이름과 설명만 불러오고 쓸 때만 내용을 읽으므로, 자주 쓰는 MCP 작업을 스킬로 바꾸면 효율적입니다.

  1. /skill-creator를 실행합니다.
  2. 기존 MCP가 하던 일을 스킬로 만들어 달라고 프롬프트를 입력합니다(영상에서는 n8n MCP 작업).
  3. 생성된 스킬 목록을 확인합니다(영상에서는 5개).
  4. /mcp에서 해당 MCP를 선택해 Disable로 연결을 끊습니다.
  5. 스킬이 쓸 API 키를 새로 발급해 입력합니다.
  6. MCP 없이 같은 요청을 해서 똑같이 동작하는지 확인합니다.
예시
n8n에 간단한 AI 챗봇 만들어 줘
  • 스킬은 프롬프트에 따라 자동 실행되거나 슬래시 명령으로 직접 호출할 수 있습니다.
  • n8n은 Docker Desktop 위에서 실행했고 기본 포트는 5678입니다.

3. 어사이드 CLI를 Claude Code에 연결하기

외부 서비스의 CLI를 Claude Code에 설치하면 자연어 요청만으로 그 서비스 작업을 조종할 수 있습니다. 영상에서는 어사이드 CLI로 드리미나의 광고 이미지·영상 제작을 맡기는 예를 보여 줍니다.

  1. 어사이드에서 왼쪽 상단 프로필을 누릅니다.
  2. 세팅에서 디벨로퍼스 메뉴를 엽니다.
  3. 어사이드 CLI 설치 명령을 복사합니다.
  4. Claude Code 화면에 붙여 넣고 설치해 달라고 요청합니다.
  5. 드리미나로 만들 영상이나 이미지를 자연어로 요청합니다.
  • 작업이 길어지면 토큰을 꽤 소모합니다.
  • 기획, 이미지, 스토리라인을 미리 정해 주면 품질이 올라갑니다.
  • 템플릿과 제품의 감도가 맞아야 결과가 좋습니다.

4. Hooks로 자동 서식·위험 작업 막기

Hooks는 Claude Code가 일하는 특정 시점에 지정한 명령을 실행하는 기능입니다. CLAUDE.md의 지시는 가끔 지켜지지 않지만 Hook은 예외 없이 실행되므로, 꼭 지켜야 할 규칙에 씁니다.

  1. .claude/settings.json 또는 /hooks에서 Hook을 설정합니다.
  2. 편집 뒤 서식을 맞추려면 이벤트로 PostToolUse를 고르고 matcher를 Edit 또는 MultiEdit로 지정합니다.
  3. 실행 명령에서 파일 확장자를 확인해 맞는 포매터(Prettier, Go format, Ruff 등)를 실행하게 합니다.
  4. 위험한 작업을 막으려면 PreToolUse Hook을 만들고 stdin으로 받는 JSON의 도구 이름과 입력을 검사합니다.
  5. 막아야 하면 종료 코드 2로, 허용하면 0으로 끝냅니다.
  6. 막을 때 stderr에 이유를 남기면 Claude가 그 이유를 받아 방식을 조정합니다.
  7. .claude/settings.json을 저장소에 커밋하면 팀원도 같은 Hook을 씁니다.
  • Hook 이벤트에는 UserPromptSubmit, PreToolUse, PostToolUse, Notification, Stop이 있습니다.
  • rm -rf 포함 명령이나 main 브랜치 커밋 차단 같은 규칙에 알맞습니다.
  • 프로젝트 스크립트는 CLAUDE_PROJECT_DIR 환경 변수로 참조하면 작업 디렉터리와 무관하게 동작합니다.
  • CLAUDE.md는 권고, Hooks는 강제라고 기억하세요.

5. 서브에이전트에 모델 나눠 맡기기

서브에이전트는 자체 컨텍스트를 가진 별도의 Claude로, 메인 세션이 맡긴 일을 처리하고 결과만 보고합니다. 어려운 판단은 큰 모델이, 범위가 분명한 일이나 탐색은 작은 모델이 맡게 하면 속도와 비용을 아낄 수 있습니다.

  1. 큰 작업(예: 모든 패키지의 프레임워크 메이저 버전 마이그레이션)은 Fable로 메인 세션을 시작합니다.
  2. 패키지 업그레이드나 테스트 수정처럼 범위가 분명한 부분을 가려 냅니다.
  3. Fable에게 마이그레이션을 이끌면서 그 부분을 Sonnet에게 넘기라고 요청합니다.
  4. 코드를 읽기만 하는 서브에이전트는 커스텀 서브에이전트의 frontmatter에서 모델을 Sonnet으로 지정합니다.
  5. 모든 서브에이전트의 기본 모델을 한 곳에서 바꾸려면 settings.json에 CLAUDE_CODE_SUBAGENT_MODEL 환경 변수를 설정합니다.
예시
모든 패키지의 프레임워크 메이저 버전 마이그레이션을 네가 이끌어 줘. 패키지 업그레이드와 테스트 수정처럼 범위가 분명한 부분은 Sonnet 서브에이전트에게 넘겨 줘.
  • 시작점은 중간 노력 수준의 Opus 5.5가 좋고, 결과가 부족하면 모델을 바꾸기 전에 노력 수준을 먼저 올리세요.
  • Fable은 토큰당 가격이 Opus의 두 배, Sonnet은 절반입니다. 모든 부분에 Fable의 성능이 필요하지는 않습니다.
  • 읽기 전용 탐색 서브에이전트는 Sonnet, 경우에 따라 Haiku까지 써도 됩니다.
  • 모델은 작업의 길이와 복잡도 기준으로 고르세요. 단순한 파일 생성에 고성능 모델은 필요 없습니다.

6. verify 스킬로 검증 루프 만들기

테스트나 린터만으로는 변경이 의도대로 동작하는지 증명되지 않습니다. 브라우저에서 클릭하고 확인하는 수동 절차를 스킬로 만들어 두면 Claude가 직접 실행하고, 실패하면 고친 뒤 다시 확인합니다.

  1. Claude Code에 포함된 verify 스킬을 처음 사용합니다.
  2. Claude가 앱을 실행하고 변경 사항을 직접 확인하는 것을 지켜봅니다.
  3. 성공한 절차가 프로젝트에 스킬로 저장되는지 확인합니다.
  4. 생성된 스킬에 확인 항목을 추가합니다(예: Chrome DevTools MCP로 레이아웃 시프트를 재는 성능 트레이스).
  5. 스킬에 언제 실행할지, 실패하면 무엇을 할지, 각 확인의 통과 기준을 적습니다.
  6. UI 변경을 요청해 서버 실행, 페이지 열기, 클릭, 스크린샷, 성능 트레이스를 하고 실패 시 고쳐 다시 확인하는지 봅니다.
  • 통과 기준이 측정 가능할수록 Claude가 더 멀리 혼자 갑니다.
  • 수동으로 확인하고 있다면 성능 예산, 접근성 체크리스트, 디자인 시스템 규칙처럼 기준이 될 만한 것을 적어 두세요.
  • 실수가 나오면 다시 시키지 말고 CLAUDE.md나 스킬에 적어 같은 실수를 막으세요.

7. 모드를 만들어 모든 세션에서 쓰기

모드(Mods)는 Claude Code의 모습과 행동을 바꾸는 작은 프로그램으로, 플러그인 형태입니다. 토큰 사용량 표시나 다음 작업 추천처럼 화면 요소를 바꾸고 싶을 때 쓰며, 코드를 몰라도 말로 설명하면 만들어 줍니다.

  1. Claude Code 데스크톱 앱의 좌측 상단 코드 탭으로 들어갑니다.
  2. 로컬 옆 버튼에서 폴더 열기로 프로젝트 폴더를 만들어 엽니다.
  3. 만들고 싶은 모드를 말로 설명해 요청합니다.
  4. 핫 리로딩 안내가 나오면 Enable for this session을 누릅니다.
  5. 잘 보이는지 확인해 달라고 요청해 결과를 확인합니다.
  6. 모든 세션에서 쓰려면 방금 만든 모드를 플러그인으로 설치해 달라고 요청합니다.
  7. 다른 세션이나 프로젝트에서도 모드가 적용되는지 확인합니다.
예시
토큰 사용량을 아이콘과 함께 보여 주는 모드를 만들어 줘.
  • 모드를 만드는 전용 스킬이 이미 들어 있습니다.
  • 플러그인으로 설치하지 않으면 모드는 만든 대화 안에서만 작동합니다.
  • 직접 만들 때는 플러그인의 hook.json에 modules 키를 추가해 TypeScript 파일을 가리키게 하고, 마켓플레이스 저장소에 올려 공유할 수도 있습니다.
  • 화면 요소(창·버튼)는 모드로만 만들 수 있습니다.

8. 클라우드 세션으로 맡겨 두고 PR 만들기

클라우드 세션은 내 컴퓨터가 아니라 클라우드 가상 머신에서 도는 Claude Code 작업입니다. GitHub 저장소를 복제해 별도 브랜치에서 일하므로 노트북을 닫아도 계속되고, 퇴근 전 큰 작업을 맡겨 두기에 좋습니다.

  1. GitHub 계정을 연결하고 GitHub에서 접근을 승인합니다.
  2. Claude GitHub App을 설치하고 접근을 허용할 저장소를 고릅니다.
  3. 데스크톱 앱에서 Local 대신 Cloud를 선택합니다.
  4. 저장소, 환경, 시작할 브랜치를 고릅니다.
  5. Claude에게 작업을 맡기고 노트북을 닫습니다.
  6. 휴대폰 Claude 앱의 Code 탭에서 질문에 답하거나 방향을 조정합니다.
  7. 변경 내용(diff)을 검토합니다. 남긴 코멘트는 다음 메시지와 함께 Claude에게 전달됩니다.
  8. 문제가 없으면 Create PR을 눌러 풀 리퀘스트를 엽니다.
  • 세션은 저장소를 새로 복제해 시작하므로 커밋·푸시한 내용만 쓸 수 있습니다. 개인 설정, 스킬, 플러그인이 필요한 작업은 로컬에서 실행하세요.
  • 비공개 저장소는 Claude GitHub App이 접근할 수 있어야 목록에 나타납니다.
  • 더 필요한 도구가 있으면 사용자 지정 환경을 만들어 네트워크 범위, 환경 변수, 설치용 설정 스크립트를 정합니다.
  • 플랜 한도는 로컬 세션과 합산되며 가상 머신 비용은 따로 없습니다. Remote Control은 내 컴퓨터가 켜져 있어야 합니다.

9. 루틴으로 알아서 일하는 에이전트 만들기

루틴은 프롬프트, 저장소, 커넥터, 트리거만 정해 두면 Anthropic 관리형 인프라에서 원격 Claude Code 세션을 자동 실행하는 기능입니다. 노트북이 꺼져 있어도 돌아가며, 매주 문서 점검이나 매일 피드백 분류 같은 반복 업무에 알맞습니다.

  1. 루틴이 할 일을 하나로 정합니다(예: 매주 병합된 변경을 문서 저장소와 비교해 문서 수정 PR 만들기).
  2. 트리거를 고릅니다. 일정(시간 기반) 또는 GitHub 이벤트, 웹훅·API 호출(이벤트 기반)이 있습니다.
  3. 루틴이 볼 저장소와 커넥터 같은 컨텍스트를 정합니다.
  4. 프롬프트에 해야 할 일과 결과물의 형태를 적습니다.
  5. 루틴을 만들어 실행시킨 뒤, 웹·CLI·데스크톱에서 해당 세션을 열어 결과를 확인합니다.
  6. 필요하면 그 세션에서 추가로 지시해 이어서 씁니다.
  • 루틴을 만들 때는 트리거, 컨텍스트, 조종 방식 세 가지를 정하세요.
  • 영상 편집 사례에서는 루틴으로 1~2시간마다 구글 드라이브 폴더를 확인하게 해, 영상만 올리면 편집이 시작되도록 했습니다.
  • 매일 피드백을 모아 중요도별로 분류하고 확신이 높은 것만 고치게 하는 식으로도 씁니다.

10. 프로젝트로 여러 작업 병렬 처리하기

Claude Code의 Project는 Claude가 작업을 조율하는 하나의 지속적인 대화입니다. 작업마다 클라우드의 별도 브랜치에서 도는 스레드를 만들어 병렬로 처리하며, 여러 세션이나 저장소에 걸친 큰 목표에 알맞습니다. 현재 베타이며 Pro와 Max 요금제에 순차 제공됩니다.

  1. 데스크톱 앱 또는 웹 앱에서 Claude 탭을 엽니다.
  2. 새 프로젝트를 만들고 이름, 달성할 목표, 관련 저장소나 폴더를 입력합니다.
  3. 열리는 메인 대화에서 코드베이스 탐색과 개선안 제안을 요청합니다.
  4. Claude가 찾은 내용을 보고 진행할 작업에 합의합니다.
  5. 작업마다 생긴 스레드 카드를 눌러 진행 상황을 확인하고, 필요하면 말을 걸어 방향을 바꾸거나 중단합니다.
  6. threads 탭에서 사용자를 기다리는 스레드를 확인합니다.
  7. 수정이 끝난 스레드가 풀 리퀘스트를 열면 overview의 pull requests 탭에서 상태를 보고, 준비되면 Claude에게 병합을 요청합니다.
  8. 모니터링 서비스를 연결한 뒤 매일 성능 저하를 점검하는 루틴을 만들어 달라고 요청합니다.
예시
이 저장소 코드베이스를 탐색해서 개선할 만한 작업을 제안해 줘. 내가 동의한 작업마다 스레드를 만들어 진행해 줘.
  • 코디네이터는 낮은 노력 수준으로 두고, 스레드는 작은 모델을 기본으로 쓰다 복잡한 작업에서만 바꾸세요.
  • 로컬 파일이나 도구가 필요한 스레드는 내 컴퓨터에서 실행하도록 요청하세요.
  • library 탭은 아티팩트와 직접 추가한 파일(목업, 디자인 명세)을 모든 스레드가 공유하는 폴더입니다.
  • 같은 저장소에서 세션을 여러 개 병렬로 돌릴 때는 worktree를 쓴다는 사례가 있습니다(DoorDash, Spotify).

11. 대규모 작업을 안전하게 쪼개 돌리기

마이그레이션이나 대량 수정처럼 큰 작업은 한 번에 시키지 않고, 끝났는지 판정하는 기준과 검사 수단을 먼저 만든 뒤 나눠 맡기는 것이 핵심입니다. 이렇게 하면 에이전트가 사람 손을 덜 타고 멀리 갑니다.

  1. 작업의 완료 조건을 누가 봐도 참·거짓으로 판정할 수 있게 적습니다.
  2. 종료 조건을 겹쳐 겁니다. 검증 통과, 최대 반복 횟수, 시간·비용 한도, 진전 없음 중단이 있습니다.
  3. 결과를 코드로 검사하는 검사기(테스트, 스킬)를 구조를 늘리기 전에 먼저 만듭니다.
  4. 진행 상황을 적는 상태 파일을 두어 세션이 바뀌어도 이어 가게 합니다.
  5. 범위가 분명한 부분만 서브에이전트나 병렬 세션으로 나눠 맡깁니다.
  6. 만드는 AI와 검사하는 AI를 분리해 자기 결과에 관대해지는 문제를 줄입니다.
  7. 병합 전에 사람이 핵심 부분의 검증 결과를 직접 확인합니다.
  • 기본은 루프 하나로 하고, 병렬 후 취합, 독립 검증, 단계별 다른 권한, 사람 승인, 장시간 저장·재개 같은 이유가 있을 때만 그래프(여러 단계) 구조를 쓰세요. 작은 실험에서 그래프는 코드 검사 루프보다 토큰이 4배 넘게 들었습니다.
  • 멀티에이전트는 성과가 높을 수 있지만 토큰도 채팅의 약 15배를 씁니다.
  • 핵심 소프트웨어일수록 검증을 가장 중요하게 보세요.
  • 코드가 늘면 CI/CD, 코드 리뷰, 보안이 새 병목이 되므로 AI 리뷰 에이전트를 함께 두는 사례가 있습니다.
