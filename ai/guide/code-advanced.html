Claude Code 고급

「Claude Code 고급」에서는 Claude Code의 화면과 동작을 바꾸는 모드, 플러그인, 서브에이전트, 스킬을 다룹니다. 노트북을 닫아도 계속 도는 클라우드 세션·Projects·루틴으로 여러 작업을 한꺼번에 맡기는 방법도 함께 봅니다. 처음이라면 말로 모드를 만들어 플러그인으로 설치하는 데서 시작하세요. 그다음 서브에이전트와 검증 스킬, 자동 모드를 익힌 뒤 클라우드 세션과 Projects, 루틴, 팀 스킬 관리 순서로 넘어가면 됩니다.

서브에이전트, 스킬, Hooks, 플러그인, 병렬·백그라운드 작업, 워크트리, 대규모 작업 요령 · 영상 26개 기반 · 2026-10-25 갱신

최근 바뀐 점

  • Claude Code 모드는 2026년 9월 일부 개발자에게 먼저 공개되었고, 10월 1일 Anthropic이 공식 발표했습니다. 모드는 Claude Code의 화면, 프롬프트, 도구 호출을 바꾸는 플러그인입니다.
  • 클라우드 세션은 클라우드의 가상 머신에서 GitHub 저장소를 복제해 작업합니다. 노트북을 닫아도 계속 진행되고, 휴대폰 앱에서 방향을 바꾸거나 Create PR로 풀 리퀘스트를 열 수 있습니다.
  • Claude Code Projects가 베타로 나와 Pro·Max 요금제에 순차적으로 제공됩니다. 대화 하나에서 클라우드 스레드 여러 개를 병렬로 조율합니다.
  • Claude Code에 verify 스킬이 들어 있습니다. Claude가 앱을 직접 실행해 확인하는 절차를 프로젝트 스킬로 저장해 줍니다.

1. 말로 설명해 모드 만들기

모드는 Claude Code의 모습과 행동 방식을 바꾸는 작은 프로그램입니다. Claude가 작업할 때마다 나가는 신호를 듣고, 지켜보거나 살짝 고치거나 대신 처리합니다. 모드를 만드는 전용 스킬이 이미 들어 있어서 코드를 몰라도 원하는 기능을 말로 설명하면 됩니다.

  1. Claude Code 데스크톱 앱의 좌측 상단 코드 탭으로 들어갑니다.
  2. 로컬 옆 버튼에서 폴더 열기를 눌러 모드용 프로젝트 폴더를 만들어 엽니다.
  3. 만들고 싶은 모드를 말로 설명해 요청합니다.
  4. 핫 리로딩 안내가 나오면 Enable for this session을 누릅니다.
  5. 모드가 잘 보이는지 확인해 달라고 요청해 결과를 봅니다.
예시
토큰 사용량을 아이콘과 함께 화면에 보여 주는 모드를 만들어 줘.
  • 다음 작업 추천 모드처럼 턴이 끝날 때마다 할 일 세 가지를 카드로 띄우고, 클릭하면 바로 실행되게 요청할 수도 있습니다.
  • 창이나 버튼 같은 화면 요소는 모드로만 만들 수 있습니다.
  • 스킬과 MCP는 밖에서 지식과 도구를 건네고, 모드는 작업 환경 자체를 바꿉니다.

2. 모드를 플러그인으로 설치하기

방금 만든 모드는 그 모드를 만든 대화 안에서만 작동합니다. 플러그인으로 설치하면 다른 세션과 프로젝트에서도 쓸 수 있습니다. 모드는 플러그인이라 마켓플레이스 저장소에 올려 다른 사람과 공유할 수도 있습니다.

  1. 모드를 만든 대화로 돌아갑니다.
  2. 방금 만든 모드를 내 모든 세션에서 쓸 수 있도록 플러그인으로 설치해 달라고 요청합니다.
  3. 새 세션이나 다른 프로젝트를 열어 모드가 적용되는지 확인합니다.
예시
방금 만든 모드를 내 모든 세션에서 쓸 수 있도록 플러그인으로 설치해 줘.
  • 이 단계를 건너뛰면 모드는 만든 대화 안에서만 작동합니다.
  • 팀과 나누려면 플러그인을 마켓플레이스 저장소에 올립니다.

3. 서브에이전트를 작은 모델로 돌리기

코드베이스를 읽기만 하는 탐색용 서브에이전트에는 Opus급 추론이 필요 없습니다. 이런 서브에이전트를 Sonnet이나 Haiku 같은 작은 모델로 돌리면 비용과 사용 한도를 아낄 수 있습니다.

  1. 코드베이스를 읽기만 하는 서브에이전트가 어느 것인지 정합니다.
  2. 그 커스텀 서브에이전트의 frontmatter에서 모델을 Sonnet으로 지정합니다.
  3. 모든 서브에이전트의 기본 모델을 한 번에 바꾸려면 settings.json에 CLAUDE_CODE_SUBAGENT_MODEL 환경 변수를 설정합니다.
예시
코드베이스를 읽기만 하는 탐색용 서브에이전트를 만들고, frontmatter에서 모델을 Sonnet으로 지정해 줘.
  • 읽기 전용 서브에이전트는 Sonnet, 경우에 따라 Haiku까지 써도 됩니다.
  • 메인 작업의 기본 effort는 medium이면 대부분 충분하고, 여러 파일이나 프로젝트 전체를 바꾸는 수정에만 high를 씁니다.
  • Opus 5.5는 Opus 5보다 토큰당 20% 저렴하고, 작업 하나당 비용은 약 40% 낮습니다.

4. verify 스킬로 검증 루프 만들기

테스트와 린터를 통과해도 변경이 의도대로 동작한다는 증명은 되지 않습니다. 브라우저에서 클릭하고 콘솔을 보는 식의 확인 절차를 스킬로 만들어 두면, Claude가 직접 확인하고 실패하면 고친 뒤 다시 확인합니다. 내가 매번 손으로 확인하고 고칠 점을 알려 주고 있다면 이 방법을 쓸 때입니다.

  1. Claude Code에 들어 있는 verify 스킬을 처음 사용합니다.
  2. Claude가 앱을 실행하고 변경 사항을 앱에서 직접 확인하는 과정을 지켜봅니다.
  3. 성공한 절차가 프로젝트에 스킬로 저장되었는지 확인합니다.
  4. 생성된 스킬에 확인 항목을 더합니다. 예를 들어 Chrome DevTools MCP로 레이아웃 시프트를 측정하는 성능 트레이스를 넣을 수 있습니다.
  5. 스킬에 언제 실행할지, 확인에 실패하면 무엇을 할지, 확인마다 통과 기준이 무엇인지 적습니다.
  6. UI 변경을 요청한 뒤 Claude가 서버 실행부터 클릭, 스크린샷, 성능 측정까지 하고 실패 시 고쳐 다시 확인하는지 봅니다.
예시
이번 화면 변경을 verify 스킬로 확인해 줘. 그리고 만들어진 스킬에 Chrome DevTools MCP로 레이아웃 시프트를 측정하는 단계를 추가해 줘.
  • 확인 기준이 측정 가능할수록 Claude가 통과 여부를 판단하기 쉽고, 혼자 더 멀리 갑니다.
  • 성능 예산, 접근성 체크리스트, 디자인 시스템 규칙처럼 이미 있는 기준을 스킬에 넣어 보세요.
  • Claude가 같은 실수를 하면 다시 시키지 말고 CLAUDE.md나 스킬에 적어 두면 반복되지 않습니다.
  • 웹은 브라우저, 백엔드는 엔드포인트 호출, 모바일은 iOS 시뮬레이터로 확인 절차를 만들 수 있습니다.

5. 자동 모드로 승인 피로 줄이기

Claude Code 권한 요청의 97%가 그냥 승인된다는 점에서 자동 모드가 나왔습니다. Claude가 스스로 승인하지 않고, 별도 분류기가 사용자의 메시지와 도구 호출을 보고 의도에 맞는지 판단해 위험한 명령만 막습니다. 승인 버튼을 누르느라 작업이 자주 멈출 때 씁니다.

  1. 꼭 막아야 하거나 꼭 물어봐야 하는 작업을 deny·ask·allow 규칙으로 먼저 정합니다.
  2. 자동 모드 설정의 환경 필드에 우리 조직 인프라를 설명해, 어디까지가 내부인지 알려 줍니다.
  3. 자동 모드를 켜고 작업을 맡깁니다.
  4. 읽기 전용이거나 되돌릴 수 있는 작업은 바로 진행되고, 나머지는 분류기가 판단하는지 지켜봅니다.
  • 기본값은 작업 디렉터리와 git 리모트만 내부로 보므로 환경 필드 설정이 필요합니다.
  • deny·ask·allow 규칙이 분류기보다 먼저 적용됩니다.
  • 도구 결과는 서버 측 프로브가 숨은 악성 지시를 먼저 검사해 프롬프트 인젝션을 막습니다.
  • 예전 방식: 최신 모델에서는 플랜 모드로 계획부터 세우는 대신 자동 모드로 바로 맡기는 경우가 많아졌습니다.

6. 클라우드 세션으로 맡기고 PR 만들기

클라우드 세션은 내 컴퓨터가 아니라 클라우드의 가상 머신에서 도는 Claude Code 작업입니다. GitHub 저장소를 복제해 별도 브랜치에서 작업하므로 노트북을 닫아도 계속 진행됩니다. 큰 리팩터링이나 퇴근 전에 맡겨 두는 작업에 알맞습니다.

  1. GitHub 계정을 연결하고 GitHub에서 접근을 승인합니다.
  2. Claude GitHub App을 설치하고 접근을 허용할 저장소를 고릅니다.
  3. 데스크톱 앱에서 Local 대신 Cloud를 선택합니다.
  4. 저장소, 환경, 시작할 브랜치를 고릅니다.
  5. Claude에게 작업을 맡기고 노트북을 닫습니다.
  6. 휴대폰 Claude 앱의 Code 탭에서 질문에 답하거나 방향을 조정합니다.
  7. 변경 내용(diff)을 검토합니다. 남긴 코멘트는 다음 메시지와 함께 Claude에게 전달됩니다.
  8. 문제가 없으면 Create PR을 눌러 GitHub에 풀 리퀘스트를 엽니다.
  • 세션은 저장소를 새로 복제해 시작하므로 커밋·푸시한 내용만 쓸 수 있습니다. 개인 설정, 스킬, 플러그인이 필요한 작업은 로컬에서 실행하세요.
  • 비공개 저장소는 Claude GitHub App에 접근을 허용해야 목록에 나타납니다.
  • 터미널에서 teleport 플래그를 붙여 claude를 실행하면 클라우드 세션을 내 컴퓨터로 가져와 이어갈 수 있습니다.
  • Remote Control은 내 컴퓨터에서 도는 세션에 연결하는 방식이라 컴퓨터가 켜져 있어야 합니다. 사용량은 로컬 세션과 함께 플랜 한도에 합산되고, 가상 머신 비용은 따로 없습니다.

7. 클라우드 세션 환경 맞춤 설정하기

클라우드 세션의 기본 환경에는 주요 언어 런타임, 빌드 도구, 데이터베이스가 미리 설치되어 있습니다. 저장소에 더 필요한 것이 있으면 사용자 지정 환경을 만들어 네트워크, 환경 변수, 설치 스크립트를 정합니다.

  1. 기본 환경에 이미 설치된 런타임, 빌드 도구, 데이터베이스를 확인합니다.
  2. 더 필요한 것이 있으면 사용자 지정 환경을 만듭니다.
  3. 네트워크 접근 범위를 설정합니다.
  4. 필요한 환경 변수를 추가합니다.
  5. 저장소에 필요한 것을 설치하는 설정 스크립트를 작성합니다.
  • Team·Enterprise 플랜은 조직의 자체 인프라에서 클라우드 세션을 실행할 수 있습니다.

8. Projects로 여러 작업 병렬로 맡기기

Project는 Claude가 여러 작업을 조율하는 하나의 지속적인 대화입니다. 작업마다 클라우드의 별도 브랜치에서 도는 스레드를 만들어 병렬로 처리하므로, 여러 세션이나 저장소에 걸친 큰 목표에 알맞습니다. 현재 베타이며 Pro·Max 요금제에 순차적으로 제공됩니다.

  1. 데스크톱 앱 또는 웹 앱에서 Claude 탭을 엽니다.
  2. 새 프로젝트를 만들고 이름, Claude가 달성할 목표, 관련 저장소나 폴더를 입력합니다.
  3. 프로젝트가 만들어지면 열리는 메인 대화에서 코드베이스 탐색과 개선안 제안을 요청합니다.
  4. Claude가 찾은 내용을 보고 진행할 작업에 합의합니다.
  5. 작업마다 만들어진 스레드 카드를 눌러 진행 상황을 보고, 필요하면 스레드에서 방향을 바꾸거나 중단합니다.
  6. threads 탭에서 내 답을 기다리는 스레드를 확인합니다.
예시

  • 코디네이터는 낮은 노력 수준으로 두고, 스레드는 작은 모델을 기본으로 쓰다가 복잡한 작업에서만 바꾸는 것이 권장됩니다.
  • library 탭은 모든 스레드가 함께 쓰는 폴더라 목업이나 디자인 명세를 넣어 두면 좋습니다.

9. PR 관리와 매일 점검 루틴 만들기

루틴은 정한 일정이나 이벤트에 맞춰 원격 Claude Code 세션을 자동으로 실행하는 기능입니다. 노트북이 꺼져 있어도 PR을 돌보고, CI 실패를 고치고, 매일 성능 저하를 점검하게 할 수 있습니다. 반복 업무를 사람이 매번 지시하지 않아도 되게 만들 때 씁니다.

  1. 수정 사항이 준비된 스레드가 스스로, 또는 요청을 받아 풀 리퀘스트를 열게 합니다.
  2. 스레드가 PR을 지켜보며 CI가 실패하면 수정을 푸시하고 리뷰 코멘트를 반영하는지 확인합니다.
  3. overview의 pull requests 탭에서 모든 PR과 상태를 봅니다.
  4. 병합할 준비가 되면 Claude에게 병합을 요청합니다.
  5. 모니터링 서비스를 Claude에 연결해 실제 사용자 지표를 직접 보게 합니다.
  6. 매일 성능 저하를 점검하는 루틴을 만들어 달라고 요청합니다.
예시
매일 성능 저하를 점검하는 루틴을 만들어 줘.
  • 루틴을 만들 때는 트리거, 컨텍스트, 조종 방식 세 가지를 정합니다.
  • 트리거는 일정 같은 시간 기반과 GitHub 이벤트·웹훅·API 호출 같은 이벤트 기반이 있습니다.
  • 루틴이 성능 저하를 발견하면 조사 스레드를 열어 두고 프로젝트에서 기다립니다.
  • 루틴도 Claude Code 세션이라 웹·CLI·데스크톱에서 열어 보고 지시하며 이어 쓸 수 있습니다.

10. 코드로 모드 직접 만들기

모드는 플러그인의 hook.json이 가리키는 TypeScript 함수입니다. 이 함수를 Claude Code 내부 이벤트에 등록하면 이벤트가 생길 때마다 실행되어 화면, 프롬프트, 도구 호출을 바꿉니다. 말로 만든 모드보다 세밀하게 고치고 싶을 때 씁니다. 아래 단계는 마우스를 올릴 때만 이메일 주소를 보여 주는 모드를 예로 듭니다.

  1. 플러그인의 hook.json에 modules 키를 추가하고 TypeScript 파일을 가리키게 합니다.
  2. 그 파일에서 렌더 이벤트(render)에 함수를 등록합니다.
  3. 이벤트 데이터로 들어오는 답변 텍스트에서 이메일 주소를 찾습니다.
  4. 주소마다 $send 객체로 마우스를 올릴 때만 텍스트가 보이는 블록을 만듭니다.
  5. next를 호출하지 않고 결과를 직접 반환해 Claude Code가 내 버전을 그리게 합니다.
  6. plugin dir 플래그로 폴더를 지정해 Claude Code를 시작합니다. 데스크톱 앱이라면 글로벌 설정 파일에 폴더를 추가합니다.
  • 함수는 $send 객체, 이벤트, next 세 값을 받습니다. next에 넘긴 값이 실제로 수행되고, next를 호출하지 않고 반환하면 내가 이벤트를 처리합니다.
  • 폴더를 감시하므로 파일을 저장하면 현재 세션에 바로 반영됩니다.
  • 렌더를 바꾸면 화면만 달라지므로 모델은 실제 이메일 주소를 그대로 씁니다.
  • 모드는 자체 샌드박스에서 실행되어 Claude Code가 노출한 이벤트만 볼 수 있습니다.

11. 팀 스킬을 규칙 있게 관리하기

회사의 업무 방식을 스킬로 만들어 여러 사람이 쓰기 시작하면, 담당자가 아닌 사람이 만든 개인용 스킬이 문제를 일으킬 수 있습니다. 소유자·검토·폐기 규칙과 마켓플레이스를 갖춰 두면 수백 명 규모로 안전하게 늘릴 수 있습니다.

  1. 첫 스킬을 내놓기 전에 소유자, 검토자, 폐기 방식, 테스트 방식을 정합니다.
  2. 스킬은 파워 유저가 아니라 그 업무를 실제로 맡은 사람이 만들거나 검토하게 합니다.
  3. 모든 스킬이 보이도록 마켓플레이스에 모으고 태그와 평가를 붙입니다.
  4. 스킬 지침을 코드처럼 PR로 수정하고, 검토를 거쳐 병합합니다.
  5. 팀의 판단이 피드백으로 매일 스킬에 반영되는 흐름을 만듭니다.
  • 비용센터 코드가 고정된 경비 스킬처럼, 개인 환경에 맞춘 스킬은 다른 사람에게 오류를 낼 수 있습니다.
  • 스킬에는 해야 할 일 목록보다 어떻게 생각할지에 대한 원칙을 적는 것이 좋습니다.
  • 검증된 스킬과 커뮤니티 스킬을 구분해 표시하면 고르기 쉽습니다.
