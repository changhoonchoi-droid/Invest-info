Claude Code 고급

Claude Code 고급 기능을 쓰면 확인 작업을 스킬로 맡기고, 서브에이전트 비용을 줄이고, 노트북을 닫은 뒤에도 클라우드에서 여러 작업을 동시에 진행할 수 있습니다. 먼저 verify 스킬과 서브에이전트 설정으로 로컬 작업을 다듬으세요. 그다음 클라우드 세션과 Projects로 작업을 병렬로 맡기고, 마지막에 루틴과 모드 플러그인으로 자동화와 맞춤 설정을 넓혀 가면 됩니다.

서브에이전트, 스킬, Hooks, 플러그인, 병렬·백그라운드 작업, 워크트리, 대규모 작업 요령 · 영상 17개 기반 · 2026-10-20 갱신

최근 바뀐 점

  • 클라우드 세션이 나왔습니다. 클라우드의 가상 머신에서 GitHub 저장소를 별도 브랜치로 작업하므로 노트북을 닫아도 일이 계속되고, 휴대폰에서 답하거나 방향을 바꿀 수 있습니다.
  • Claude Code Projects가 베타로 나와 Pro·Max 요금제에 순차 제공됩니다. 대화 하나가 작업마다 클라우드 스레드를 만들어 병렬로 처리합니다.
  • 모드라는 플러그인이 생겼습니다. hook.json의 modules 키로 TypeScript 함수를 등록하면 Claude Code의 화면 표시, 프롬프트, 도구 호출을 바꿀 수 있습니다.
  • Claude Code에 verify 스킬이 들어 있습니다. Claude가 앱을 실행해 변경 내용을 직접 확인하고, 성공한 절차를 프로젝트 스킬로 저장합니다.

1. verify 스킬로 검증 루프 만들기

테스트나 린터만으로는 변경이 의도대로 동작하는지 알 수 없습니다. 브라우저에서 클릭해 보고 콘솔을 보는 확인 절차를 스킬로 만들어 두면, Claude가 직접 확인하고 고친 뒤 다시 확인합니다. UI를 바꾼 뒤 사람이 일일이 확인하고 있다면 이 기능을 쓰세요.

  1. Claude Code에 포함된 verify 스킬을 처음으로 실행합니다.
  2. Claude가 앱을 실행하고 변경 사항을 앱에서 직접 확인하는 과정을 지켜봅니다.
  3. 성공한 확인 절차가 프로젝트에 스킬로 저장되었는지 확인합니다.
  4. 저장된 스킬에 확인 항목을 더합니다. 예: Chrome DevTools MCP로 레이아웃 시프트를 재는 성능 트레이스
  5. 스킬에 언제 실행할지, 확인에 실패하면 무엇을 할지, 항목마다 통과 기준을 적습니다.
  6. UI 변경을 요청한 뒤 Claude가 서버 실행, 페이지 열기, 클릭, 스크린샷, 성능 트레이스를 하는지 봅니다. 실패하면 고쳐서 다시 확인하는지도 봅니다.
예시
verify 스킬로 방금 바꾼 화면을 앱에서 직접 확인하고, 문제가 있으면 고친 뒤 다시 확인해 줘.
  • 확인 기준이 측정 가능할수록 Claude가 통과 여부를 스스로 판단하고 더 오래 혼자 작업합니다.
  • 웹은 브라우저, 백엔드는 엔드포인트 호출, 모바일은 iOS 시뮬레이터로 확인 절차를 만들 수 있습니다.
  • Claude에게 고칠 점을 직접 알려 주고 있다면 그 내용을 기준으로 바꿔 보세요. 성능 예산, 접근성 체크리스트, 디자인 시스템 규칙 같은 것들입니다.

2. 서브에이전트를 작은 모델로 돌리기

서브에이전트는 메인 작업을 돕도록 따로 실행되는 보조 에이전트입니다. 코드베이스를 읽기만 하는 탐색용 서브에이전트에는 Opus급 추론이 필요 없으므로 Sonnet이나 Haiku로 돌리면 비용과 사용 한도를 아낄 수 있습니다.

  1. 코드베이스를 읽기만 하는(탐색용) 서브에이전트를 고릅니다.
  2. 그 커스텀 서브에이전트 파일의 frontmatter에서 모델을 Sonnet으로 지정합니다.
  3. 모든 서브에이전트의 기본 모델을 한 번에 바꾸려면 settings.json에 CLAUDE_CODE_SUBAGENT_MODEL 환경 변수를 설정합니다.
예시
model: sonnet
  • 읽기 전용 서브에이전트에는 Sonnet을, 경우에 따라 Haiku까지 써도 됩니다.
  • 메인 모델 Opus 5.5의 기본 effort는 medium이며 대부분의 작업에 충분합니다. 여러 파일이나 프로젝트 전체를 바꾸는 수정에는 high를 쓰세요.

3. 클라우드 세션으로 작업 맡기기

클라우드 세션은 내 컴퓨터가 아니라 클라우드 가상 머신에서 도는 Claude Code 작업입니다. 노트북을 닫아도 계속 진행되고 휴대폰으로 확인할 수 있습니다. 큰 리팩터링이나 마이그레이션, 퇴근 전에 맡겨 둘 일에 알맞습니다.

  1. GitHub 계정을 연결하고 GitHub에서 접근을 승인합니다.
  2. Claude GitHub App을 설치하고 접근을 허용할 저장소를 고릅니다.
  3. 데스크톱 앱에서 Local 대신 Cloud를 선택합니다.
  4. 작업할 저장소, 환경, 시작 브랜치를 고릅니다.
  5. Claude에게 작업을 맡기고 노트북을 닫습니다.
  6. 휴대폰 Claude 앱의 Code 탭에서 질문에 답하거나 방향을 조정합니다.
  7. 변경 내용(diff)을 검토합니다. 남긴 코멘트는 다음 메시지와 함께 Claude에게 전달됩니다.
  8. 문제가 없으면 Create PR을 눌러 GitHub에 풀 리퀘스트를 엽니다.
  • Pro, Max, Team 플랜과 Enterprise(프리미엄 좌석 또는 Chat + Claude Code 좌석)에서 쓸 수 있습니다. 사용량은 로컬 세션과 같은 플랜 한도에서 빠지고 가상 머신 비용은 따로 들지 않습니다.
  • 세션은 저장소를 새로 복제해 시작하므로 커밋·푸시한 내용만 쓸 수 있습니다. 개인 설정, 스킬, 플러그인이 필요한 작업은 로컬에서 하세요.
  • 비공개 저장소는 Claude GitHub App에 접근 권한을 줘야 목록에 나타납니다.
  • Remote Control은 내 컴퓨터에서 도는 세션에 연결하는 방식이라 컴퓨터가 켜져 있어야 합니다. 클라우드 세션과 헷갈리지 마세요.

4. 클라우드 세션 환경 맞춤 설정하기

클라우드 세션의 기본 환경에는 주요 언어 런타임, 빌드 도구, 데이터베이스가 미리 설치되어 있습니다. 저장소에 다른 도구, 네트워크 접근, 환경 변수가 필요하면 사용자 지정 환경을 만들어 씁니다.

  1. 기본 환경에 필요한 런타임, 빌드 도구, 데이터베이스가 있는지 확인합니다.
  2. 부족한 것이 있으면 사용자 지정 환경을 새로 만듭니다.
  3. 환경이 접근할 수 있는 네트워크 범위를 정합니다.
  4. 필요한 환경 변수를 추가합니다.
  5. 저장소에 필요한 것을 설치하는 설정 스크립트를 작성합니다.
  6. 클라우드 세션을 시작할 때 만든 환경을 선택합니다.
  • Team·Enterprise 플랜은 조직의 자체 인프라에서 클라우드 세션을 실행할 수 있습니다.

5. Projects로 큰 작업 나눠 맡기기

Project는 Claude가 여러 작업을 조율하는, 계속 이어지는 대화 하나입니다. 작업마다 클라우드의 별도 브랜치에서 도는 스레드가 생겨 병렬로 처리됩니다. 여러 세션이나 저장소에 걸친 큰 목표에 알맞습니다.

  1. 데스크톱 앱이나 웹 앱에서 Claude 탭을 엽니다.
  2. 새 프로젝트를 만들고 프로젝트 이름, Claude가 달성할 목표, 관련 저장소나 폴더를 입력합니다.
  3. 열린 메인 대화에서 코드베이스를 살펴보고 개선안을 제안해 달라고 요청합니다.
  4. Claude가 찾은 내용을 보고 진행할 작업을 정합니다.
  5. Claude가 작업마다 만든 스레드 카드를 눌러 진행 상황을 봅니다. 필요하면 스레드에서 말을 걸어 방향을 바꾸거나 중단합니다.
  6. threads 탭에서 내 답을 기다리는 스레드를 확인합니다.
예시
이 저장소의 코드베이스를 살펴보고 개선할 점을 제안해 줘.
  • 코디네이터(메인 대화)는 낮은 노력 수준으로 두세요. 스레드는 작은 모델을 기본으로 쓰고 복잡한 작업에서만 바꾸는 것이 좋습니다.
  • library 탭은 아티팩트와 직접 넣은 파일(목업, 디자인 명세)을 모든 스레드가 함께 쓰는 폴더입니다.
  • 로컬 파일이나 도구가 필요한 작업은 그 스레드를 내 컴퓨터에서 실행해 달라고 요청하세요.
  • 같은 저장소에서 로컬 세션 여러 개를 동시에 돌릴 때는 worktree를 쓰는 사례도 있습니다.

6. PR 관리와 매일 점검 루틴 만들기

Projects의 스레드는 풀 리퀘스트를 연 뒤에도 CI 결과와 리뷰 코멘트를 지켜보며 대응합니다. 모니터링 서비스를 연결하고 루틴을 만들어 두면 매일 성능 저하를 점검하고, 문제가 보이면 조사까지 시작합니다.

  1. 수정이 준비된 스레드가 스스로, 또는 요청하면 풀 리퀘스트를 열게 합니다.
  2. 스레드가 PR을 지켜보며 CI가 실패하면 수정을 푸시하고 리뷰 코멘트를 반영하는지 확인합니다.
  3. overview의 pull requests 탭에서 모든 PR과 상태를 봅니다.
  4. 병합할 준비가 되면 Claude에게 병합을 요청합니다.
  5. 모니터링 서비스를 Claude에 연결해 실제 사용자 지표를 직접 보게 합니다.
  6. 매일 성능 저하를 점검하는 루틴을 만들어 달라고 요청합니다.
예시
매일 성능 저하를 점검하는 루틴을 만들어 줘.
  • 루틴이 성능 저하를 찾으면 조사 스레드를 열어 프로젝트에 두고 내 확인을 기다립니다.
  • 루틴과 루프는 PR 관리나 코드 리뷰처럼 반복되는 업무에 알맞습니다. 단계를 미리 알 수 없는 최적화 같은 작업은 동적 워크플로에 맡기는 식으로 나눠 쓰기도 합니다.
  • 루틴은 매일 피드백을 모아 중요도별로 나누고, 확신이 높은 것만 고치는 식으로도 쓸 수 있습니다.

7. 모드 플러그인으로 화면 바꾸기

모드는 Claude Code가 무엇을 화면에 그리고, 프롬프트에 무엇을 넣고, 어떤 도구를 부르는지 바꾸는 플러그인 함수입니다. 예를 들어 답변 속 이메일 주소를 마우스를 올릴 때만 보이게 할 수 있습니다.

  1. 플러그인의 hook.json에 modules 키를 추가하고 TypeScript 파일을 가리키게 합니다.
  2. 그 TypeScript 파일에서 렌더 이벤트(render)에 함수를 등록합니다.
  3. 이벤트 데이터로 들어오는 답변 텍스트에서 이메일 주소를 찾습니다.
  4. 찾은 주소마다 $send 객체로 마우스를 올릴 때만 보이는 블록을 만듭니다.
  5. next를 호출하지 않고 결과를 직접 반환해 Claude Code가 내 버전을 그리게 합니다.
  6. plugin dir 플래그로 이 폴더를 지정해 Claude Code를 시작합니다. 데스크톱 앱에서는 글로벌 설정 파일에 폴더를 추가합니다.
  • 함수는 $send(Claude Code와의 연결), 이벤트, next 세 값을 받습니다. next에 넘긴 값이 Claude Code가 실제로 수행하는 내용입니다.
  • Claude Code가 폴더를 감시하므로 파일을 저장하면 지금 세션에 바로 반영됩니다.
  • 렌더 변경은 화면 표시만 바꿉니다. 모델은 실제 이메일 주소를 그대로 씁니다.
  • 모드는 자체 샌드박스에서 돌고 Claude Code가 노출한 이벤트만 볼 수 있습니다. 플러그인이므로 마켓플레이스 저장소에 올려 공유할 수 있습니다.
