Claude Code 고급

Claude Code 고급 기능을 쓰면 반복 확인 작업을 스킬로 맡기고, 서브에이전트 비용을 줄이고, 모드로 작업 화면을 바꾸고, 노트북을 닫은 뒤에도 클라우드에서 여러 작업을 동시에 돌릴 수 있습니다. 먼저 스킬과 서브에이전트로 내 컴퓨터에서 Claude가 혼자 일하는 범위를 넓히세요. 그다음 모드로 작업 환경을 내게 맞게 바꾸고, 마지막으로 클라우드 세션과 Projects로 큰 작업을 병렬·백그라운드로 맡기는 순서를 권합니다.

서브에이전트, 스킬, Hooks, 플러그인, 병렬·백그라운드 작업, 워크트리, 대규모 작업 요령 · 영상 23개 기반 · 2026-10-23 갱신

최근 바뀐 점

  • Anthropic이 2026년 10월 1일 Claude Code 모드(Mods)를 공식 발표했습니다. 모드는 Claude Code의 화면과 행동 방식을 바꾸는 플러그인이며, 코드를 몰라도 말로 설명하면 만들 수 있습니다.
  • 클라우드 세션은 클라우드의 가상 머신에서 GitHub 저장소를 복제해 따로 작업합니다. 그래서 노트북을 닫아도 작업이 계속되고, 휴대폰에서 답하거나 방향을 바꿀 수 있습니다.
  • Claude Code Projects가 베타로 나와 Pro·Max 요금제에 차례로 제공되고 있습니다. 프로젝트의 메인 대화에서 Claude가 작업을 나눠 스레드로 병렬 처리하고 PR까지 챙깁니다.
  • Claude Code에 들어 있는 verify 스킬로 시작하면 Claude가 앱을 직접 실행해 변경 사항을 확인합니다. 이 확인 절차는 프로젝트 스킬로 저장됩니다.

1. verify 스킬로 검증 루프 만들기

테스트·타입 검사·린터를 통과해도 변경이 의도대로 동작하는지는 알 수 없습니다. 브라우저를 클릭하고 콘솔을 보는 식의 수동 확인 절차를 스킬로 만들어 두면 Claude가 직접 확인합니다. 문제가 있으면 고친 뒤 다시 확인합니다. 사람이 일일이 결과를 확인해 주지 않아도 되게 하고 싶을 때 씁니다.

  1. Claude Code에 포함된 verify 스킬을 처음 사용합니다.
  2. Claude가 앱을 실행하고 변경 사항을 앱에서 직접 확인하는 것을 지켜봅니다.
  3. 성공한 확인 절차가 프로젝트에 스킬로 저장되었는지 확인합니다.
  4. 생성된 스킬에 확인 항목을 더합니다. 예: Chrome DevTools MCP로 레이아웃 시프트를 측정하는 성능 트레이스.
  5. 스킬에 언제 실행할지, 확인에 실패하면 무엇을 할지, 확인마다 무엇이 통과 기준인지 적습니다.
  6. UI 변경을 요청합니다. Claude가 서버 실행, 페이지 열기, 클릭, 스크린샷, 성능 트레이스를 하고, 실패하면 고쳐서 다시 확인하는지 봅니다.
예시
verify 스킬로 방금 바꾼 화면을 앱에서 직접 실행해 확인하고, 문제가 있으면 고친 뒤 다시 확인해 줘
  • 확인 기준이 측정 가능할수록 Claude가 통과 여부를 판단하기 쉽고, 더 멀리 혼자 진행합니다.
  • 직접 확인하고 고칠 점을 알려 주는 일이 반복된다면, 그 판단을 기준으로 바꿀 수 있는지 생각해 보세요. 예: 성능 예산, 접근성 체크리스트, 디자인 시스템 규칙.
  • Claude가 같은 실수를 하면 다시 시키기보다 CLAUDE.md나 스킬에 적어 두면 같은 실수를 막을 수 있습니다.
  • 웹은 브라우저, 백엔드는 엔드포인트 호출, 모바일은 iOS 시뮬레이터로 확인 절차를 만들 수 있습니다.

2. 서브에이전트를 작은 모델로 돌리기

코드베이스를 읽고 탐색만 하는 서브에이전트에는 Opus급 추론이 필요 없습니다. 이런 서브에이전트를 Sonnet이나 Haiku 같은 작은 모델로 돌리면 사용 한도와 비용을 아낄 수 있습니다.

  1. 코드베이스를 읽기만 하는 서브에이전트가 무엇인지 정합니다.
  2. 그 커스텀 서브에이전트의 frontmatter에서 모델을 Sonnet으로 지정합니다.
  3. 모든 서브에이전트의 기본 모델을 한 번에 바꾸려면 settings.json에 CLAUDE_CODE_SUBAGENT_MODEL 환경 변수를 설정합니다.
  • 읽기 전용 서브에이전트는 Sonnet으로 충분하고, 경우에 따라 Haiku까지 내려도 됩니다.
  • Opus 5.5의 기본 effort는 medium이며 대부분의 작업에 충분합니다. 여러 파일이나 프로젝트 전체를 바꾸는 수정에는 high를 씁니다.

3. 말로 설명해 모드 만들기

모드는 Claude Code의 화면과 행동 방식을 바꾸는 작은 프로그램입니다. Claude가 작업할 때마다 보내는 신호를 듣고 지켜보거나, 살짝 고치거나, 대신 처리합니다. 데스크톱 앱에는 모드를 만드는 스킬이 이미 들어 있어서 코드를 몰라도 원하는 모드를 말로 설명하면 만들 수 있습니다.

  1. Claude Code 데스크톱 앱에서 좌측 상단 코드 탭으로 들어갑니다.
  2. 로컬 옆 버튼에서 폴더 열기를 눌러 프로젝트 폴더를 만들고 엽니다.
  3. 만들고 싶은 모드를 말로 설명해 요청합니다.
  4. 핫 리로딩 안내가 나오면 Enable for this session을 누릅니다.
  5. 모드가 잘 보이는지 확인해 달라고 요청해 결과를 봅니다.
예시
토큰 사용량을 아이콘과 함께 화면에 보여 주는 모드를 만들어 줘
  • 스킬·MCP는 밖에서 지식과 도구를 건네고, 모드는 작업 환경 자체를 바꿉니다. 창이나 버튼 같은 화면 요소는 모드로만 만들 수 있습니다.
  • 응용 예: 턴이 끝날 때마다 다음 할 일 세 가지를 카드로 띄우고, 카드를 클릭하면 바로 실행되는 모드를 요청할 수 있습니다.
  • 이렇게 만든 모드는 만든 대화 안에서만 작동합니다. 다른 세션에서도 쓰려면 다음 가이드처럼 플러그인으로 설치하세요.

4. 만든 모드를 모든 세션에서 쓰기

모드는 플러그인이어서 설치해 두면 다른 세션과 프로젝트에서도 쓸 수 있습니다. 마음에 드는 모드를 계속 쓰고 싶을 때 씁니다.

  1. 모드를 만든 대화로 돌아갑니다.
  2. 방금 만든 모드를 모든 세션에서 쓸 수 있도록 플러그인으로 설치해 달라고 요청합니다.
  3. 새 세션이나 다른 프로젝트를 열어 모드가 적용되는지 확인합니다.
예시
방금 만든 모드를 내 모든 세션에서 쓸 수 있도록 플러그인으로 설치해 줘
  • 이 단계를 건너뛰면 모드는 만든 대화 안에서만 작동합니다.
  • 모드는 플러그인이라 마켓플레이스 저장소에 올려 팀과 공유할 수 있습니다.

5. 클라우드 세션으로 작업 맡기기

클라우드 세션은 내 컴퓨터가 아니라 클라우드의 가상 머신에서 돌아가는 Claude Code 작업입니다. GitHub 저장소를 복제해 별도 브랜치에서 일하므로 노트북을 닫아도 작업이 계속되고, 휴대폰으로 확인할 수 있습니다. 큰 리팩터링이나 마이그레이션, 퇴근 전에 맡겨 두는 작업에 알맞습니다.

  1. GitHub 계정을 연결하고 GitHub에서 접근을 승인합니다.
  2. Claude GitHub App을 설치하고 접근을 허용할 저장소를 고릅니다.
  3. 데스크톱 앱에서 Local 대신 Cloud를 선택합니다.
  4. 저장소, 환경, 시작할 브랜치를 고릅니다.
  5. Claude에게 작업을 맡기고 노트북을 닫습니다.
  6. 휴대폰 Claude 앱의 Code 탭에서 Claude의 질문에 답하거나 방향을 조정합니다.
  7. 변경 내용(diff)을 검토합니다. 남긴 코멘트는 다음 메시지와 함께 Claude에게 전달됩니다.
  8. 문제가 없으면 Create PR을 눌러 GitHub에 풀 리퀘스트를 엽니다.
  • 세션은 저장소를 새로 복제해 시작하므로 커밋하고 푸시한 내용만 쓸 수 있습니다. 개인 설정, 스킬, 플러그인이 필요한 작업은 로컬에서 실행하세요.
  • 비공개 저장소는 Claude GitHub App에 접근 권한이 있어야 목록에 나타납니다.
  • 터미널에서 teleport 플래그를 붙여 claude를 실행하면 클라우드 세션을 내 컴퓨터로 가져와 이어 갈 수 있습니다.
  • Remote Control은 내 컴퓨터에서 실행 중인 세션에 연결하는 방식이라 컴퓨터가 켜져 있어야 합니다. 클라우드 세션은 Pro·Max·Team, 그리고 프리미엄 좌석 또는 Chat + Claude Code 좌석이 있는 Enterprise 사용자가 쓸 수 있으며, 사용량은 플랜 한도에 함께 합산됩니다.

6. 클라우드 세션 환경 맞춤 설정하기

클라우드 세션의 기본 환경에는 주요 언어 런타임, 빌드 도구, 데이터베이스가 미리 설치되어 있습니다. 저장소에 다른 도구나 설정이 필요하면 사용자 지정 환경을 만들어 맞춥니다.

  1. 먼저 기본 환경에 필요한 런타임, 빌드 도구, 데이터베이스가 있는지 확인합니다.
  2. 부족한 것이 있으면 사용자 지정 환경을 만듭니다.
  3. 네트워크 접근 범위를 설정합니다.
  4. 필요한 환경 변수를 추가합니다.
  5. 저장소에 필요한 것을 설치하는 설정 스크립트를 작성합니다.
  • Team·Enterprise 플랜은 클라우드 세션을 조직의 자체 인프라에서 실행할 수 있습니다.
  • API 키 같은 비밀 값은 코드에 적지 말고 환경 변수로 넣으세요.

7. Projects로 큰 작업 병렬로 맡기기

Project는 Claude가 여러 작업을 조율하는 하나의 대화이며, 대화가 끝나도 계속 이어집니다. Claude가 작업마다 클라우드의 별도 브랜치에서 도는 스레드를 만들어 동시에 처리합니다. 여러 세션이나 저장소에 걸친 큰 목표에 알맞습니다. 현재 베타이며 Pro·Max 요금제에 차례로 제공됩니다.

  1. 데스크톱 앱이나 웹 앱에서 Claude 탭을 엽니다.
  2. 새 프로젝트를 만들고 프로젝트 이름, Claude가 달성할 목표, 관련 저장소나 폴더를 입력합니다.
  3. 프로젝트를 만들면 열리는 메인 대화에서 코드베이스 탐색과 개선안 제안을 요청합니다.
  4. Claude가 찾은 내용을 보고 진행할 작업에 합의합니다.
  5. Claude가 작업마다 만든 스레드 카드를 눌러 진행 상황을 확인합니다. 필요하면 스레드에서 말을 걸어 방향을 바꾸거나 중단합니다.
  6. threads 탭에서 내 답을 기다리는 스레드를 확인합니다.
예시
이 저장소의 코드베이스를 탐색하고 개선할 점을 제안해 줘
  • 로컬 파일이나 도구가 필요한 작업은 해당 스레드를 내 컴퓨터에서 실행해 달라고 요청합니다.
  • 코디네이터(메인 대화)는 노력 수준을 낮게 둡니다. 스레드는 작은 모델로 돌리다가 복잡한 작업에서만 모델을 바꾸는 것이 좋습니다.
  • library 탭은 모든 스레드가 함께 쓰는 폴더입니다. 목업이나 디자인 명세를 넣어 두면 모든 스레드가 볼 수 있습니다.
  • 예전 방식: 터미널 탭 5~10개에 세션을 하나씩 띄우고, 같은 저장소에서 동시에 작업할 때는 세션마다 worktree를 따로 썼습니다(Spotify·DoorDash 사례).

8. PR 관리와 매일 점검 루틴 돌리기

프로젝트의 스레드는 풀 리퀘스트를 열고 CI 실패와 리뷰 코멘트까지 챙깁니다. 루틴을 설정하면 매일 정해진 점검이 세션 밖에서 자동으로 돌아갑니다. PR 관리나 성능 점검처럼 반복되는 일을 맡기고 싶을 때 씁니다.

  1. 수정이 준비된 스레드가 스스로, 또는 요청을 받아 풀 리퀘스트를 열게 합니다.
  2. 스레드가 PR을 지켜보다가 CI가 실패하면 수정을 푸시하고 리뷰 코멘트를 반영하는지 확인합니다.
  3. overview의 pull requests 탭에서 모든 PR과 상태를 봅니다.
  4. 병합할 준비가 되면 Claude에게 병합을 요청합니다.
  5. 모니터링 서비스를 Claude에 연결해 실제 사용자 지표를 직접 확인하게 합니다.
  6. 매일 성능 저하를 점검하는 루틴을 만들어 달라고 요청합니다.

매일 성능 저하를 점검하는 루틴을 만들어 줘
  • 루틴이 성능 저하를 발견하면 조사 스레드를 열어 둡니다. 이 스레드는 프로젝트에서 내 확인을 기다립니다.
  • 반복 업무(PR 관리, 코드 리뷰 등)는 루틴·루프에 맡기고, 단계를 미리 알 수 없는 작업은 동적 워크플로에 맡기는 식으로 나눠 쓰면 좋습니다.
  • 루틴은 매일 피드백을 모아 중요도별로 분류하고, 확신이 높은 것만 고치게 하는 용도로도 쓸 수 있습니다.

9. 코드로 모드 직접 만들기

모드는 Claude Code가 화면에 그리는 내용, 프롬프트에 넣는 내용, 호출하는 도구를 바꾸는 함수입니다. 플러그인의 hook.json에서 TypeScript 파일을 연결하고, 그 파일의 함수를 Claude Code 내부 이벤트에 등록하면 이벤트가 생길 때마다 함수가 실행됩니다. 아래 단계는 마우스를 올릴 때만 이메일 주소가 보이게 하는 모드를 예로 듭니다.

  1. 플러그인의 hook.json에 modules 키를 추가해 TypeScript 파일을 가리키게 합니다.
  2. 그 파일에서 렌더 이벤트(render)에 함수를 등록합니다.
  3. 이벤트 데이터로 들어오는 답변 텍스트에서 이메일 주소를 찾습니다.
  4. 찾은 주소마다 $send 객체로 마우스를 올릴 때만 텍스트가 보이는 블록을 만듭니다.
  5. next를 호출하지 말고 결과를 직접 반환해 Claude Code가 내 버전을 그리게 합니다.
  6. plugin dir 플래그로 해당 폴더를 지정해 Claude Code를 시작합니다. 데스크톱 앱이라면 글로벌 설정 파일에 그 폴더를 추가합니다.
  • 함수는 $send 객체(Claude Code와의 연결), 이벤트, next를 받습니다. next에 넘긴 값대로 Claude Code가 실행하고, next를 호출하지 않고 반환하면 내가 그 이벤트를 직접 처리합니다.
  • Claude Code가 폴더를 감시하므로 파일을 저장하면 현재 세션에 바로 반영됩니다.
  • 렌더 변경은 화면만 바꿉니다. 모델은 실제 이메일 주소를 그대로 씁니다.
  • 모드는 자체 샌드박스에서 실행되며 Claude Code가 노출한 이벤트만 볼 수 있습니다.
