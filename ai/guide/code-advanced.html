Claude Code 고급

Claude Code 고급 기능은 같은 일을 반복해서 맡기고, 여러 일을 동시에 돌리고, 실수를 자동으로 막는 데 쓰입니다. 먼저 스킬과 검증 루프로 일하는 방식을 저장하고, 서브에이전트와 Hooks로 비용과 안전을 챙기세요. 그다음 클라우드 세션, 루틴, Projects로 내 컴퓨터 밖에서 병렬로 돌리고, 모드와 루프 설계로 마무리하는 순서를 권합니다.

1. 스킬 만들어 반복 작업 맡기기

스킬은 작업 방법을 한 번 가르쳐 두면 관련 요청에서 자동으로 적용되는 마크다운 파일(SKILL.md)입니다. 보고서, PPT처럼 매번 같은 품질이 필요한 반복 업무에 쓰면 좋습니다.

  1. 먼저 원하는 결과물을 Claude에게 한 번 만들게 하고, 마음에 들 때까지 수정합니다.
  2. 만족스러운 방식을 스킬로 만들어 달라고 요청합니다.
  3. 요청에 작업 순서와 검증 기준(무엇을 확인하면 끝인지)을 함께 적습니다.
  4. 모든 프로젝트에서 쓸 스킬은 홈 디렉터리의 .claude/skills에, 팀과 공유할 스킬은 저장소 루트의 .claude/skills에 두도록 합니다.
  5. Claude Code를 껐다가 다시 실행해 스킬을 적용합니다.
  6. 작업을 요청해 스킬이 자동으로 쓰이는지 확인하고, 필요하면 스킬 이름을 직접 불러 호출합니다.
  7. 추가하고 싶은 내용이 생기면 스킬에 계속 더해 갑니다.
예시
방금 만든 결과물의 작업 순서와 검증 기준을 정리해서, 다음에도 같은 방식으로 만들 수 있는 스킬로 만들어 줘. 프로젝트 스킬 폴더에 저장해 줘.
  • 스킬은 재시작해야 같은 세션에서 인식됩니다.
  • 스킬은 요청이 맞을 때만 불러오고, CLAUDE.md는 모든 대화에 항상 불러옵니다. 항상 지킬 규칙은 CLAUDE.md에 적으세요.
  • 스킬 설명(description)이 요청과 맞아야 자동으로 선택되니 언제 쓰는지 분명히 적으세요.

2. MCP를 스킬로 바꿔 토큰 아끼기

MCP는 연결하는 순간 도구 정의가 컨텍스트에 계속 남아 토큰을 차지합니다. 스킬은 시작할 때 이름과 설명만 불러오고 필요할 때만 내용을 읽어서 더 가볍습니다.

  1. /skill-creator를 실행합니다.
  2. 지금 연결된 MCP가 하던 일을 스킬로 만들어 달라고 프롬프트를 입력합니다.
  3. 생성된 스킬 목록을 확인합니다.
  4. /mcp에서 해당 MCP를 선택해 Disable로 연결을 끊습니다.
  5. 스킬이 쓸 API 키를 새로 발급해 입력합니다.
  6. MCP 없이도 같은 요청이 똑같이 동작하는지 확인합니다.
예시
/skill-creator 연결된 n8n MCP가 하던 일을 스킬로 만들어 줘.
  • 스킬은 프롬프트에 따라 자동 실행되기도 하고 슬래시 명령으로 직접 호출할 수도 있습니다.
  • API 키는 문서에 적지 말고 설정 파일 등 안전한 곳에만 두세요.

3. verify 스킬로 검증 루프 만들기

테스트만으로는 변경이 의도대로 동작하는지 증명되지 않습니다. 앱을 직접 실행해 확인하는 절차를 스킬로 만들어 두면 Claude가 확인하고 고치고 다시 확인합니다.

  1. Claude Code에 포함된 verify 스킬을 처음 사용합니다.
  2. Claude가 앱을 실행하고 변경 사항을 직접 확인하는 것을 지켜봅니다.
  3. 성공한 절차가 프로젝트에 스킬로 저장되는지 확인합니다.
  4. 생성된 스킬에 확인 항목을 추가합니다(예: Chrome DevTools MCP로 레이아웃 시프트를 재는 성능 트레이스).
  5. 스킬에 언제 실행할지, 실패하면 무엇을 할지, 각 확인의 통과 기준을 적습니다.
  6. 화면 변경을 요청해 서버 실행, 페이지 열기, 클릭, 스크린샷, 성능 트레이스를 하고 실패 시 고쳐 다시 확인하는지 봅니다.
  • 확인 기준이 측정 가능할수록 Claude가 더 멀리 혼자 갑니다.
  • 수동으로 확인하고 고칠 점을 알려 주고 있다면 성능 예산, 접근성 체크리스트, 디자인 시스템 규칙처럼 기준이 될 만한 것을 스킬에 넣어 보세요.
  • 실수가 나오면 다시 시키지 말고 CLAUDE.md나 스킬에 적어 같은 실수를 막으세요.

4. 서브에이전트를 작은 모델로 돌리기

서브에이전트는 코드 탐색이나 리뷰처럼 일부 작업을 따로 맡는 도우미입니다. 읽기만 하는 도우미는 작은 모델로 돌리면 한도와 비용을 아낄 수 있습니다.

  1. 코드베이스를 읽기만 하는 서브에이전트를 정합니다.
  2. 커스텀 서브에이전트의 frontmatter에서 모델을 Sonnet으로 지정합니다.
  3. 모든 서브에이전트의 기본값을 한 곳에서 바꾸려면 settings.json에 CLAUDE_CODE_SUBAGENT_MODEL 환경 변수를 설정합니다.
  4. 커밋 전에는 서브에이전트 코드 리뷰어로 점검하고 커밋 메시지를 생성하게 합니다.
예시
커밋하기 전에 서브에이전트 코드 리뷰어로 변경 사항을 점검해 주고, 문제가 없으면 커밋 메시지를 만들어 줘.
  • 탐색만 하는 서브에이전트에는 Opus급 추론이 필요 없습니다. 읽기 전용은 Sonnet, 경우에 따라 Haiku까지 씁니다.
  • 모델은 작업의 길이와 복잡도를 기준으로 고르세요. 단순 파일 생성에 고성능 모델은 필요하지 않습니다.
  • 기본 effort는 medium이며 대부분 충분하지만, 여러 파일에 걸친 수정에는 high가 필요합니다.

5. Hooks로 편집 후 자동 서식 적용하기

Hooks는 Claude Code가 일하는 특정 시점에 내 명령을 실행하는 기능입니다. CLAUDE.md 지시는 가끔 지켜지지 않지만 Hook은 예외 없이 항상 실행됩니다.

  1. settings.json 또는 /hooks에서 Hook을 설정합니다.
  2. 이벤트로 PostToolUse를 고릅니다.
  3. matcher를 Edit 또는 MultiEdit로 지정합니다.
  4. 실행 명령에서 파일 확장자를 확인해 맞는 포매터를 실행하게 합니다.
  5. TypeScript는 Prettier, Go는 Go format, Python은 Ruff 등 프로젝트에서 쓰는 도구를 연결합니다.
  • Hook 이벤트는 UserPromptSubmit, PreToolUse, PostToolUse, Notification, Stop이 있습니다.
  • 작업 완료 알림, 실행 명령 기록 같은 용도로도 쓸 수 있습니다.

6. Hooks로 위험 작업 막고 팀과 공유하기

PreToolUse Hook은 Claude가 도구를 쓰기 직전에 검사해서 위험한 작업을 차단합니다. 프로젝트 설정에 넣어 저장소에 올리면 팀 전체가 같은 안전장치를 씁니다.

  1. 이벤트로 PreToolUse Hook을 만듭니다.
  2. Hook이 stdin으로 받는 JSON의 도구 이름과 입력을 검사합니다.
  3. 막아야 할 경우 종료 코드 2로 끝내고 stderr에 이유를 남깁니다.
  4. 허용할 경우 종료 코드 0으로 끝냅니다.
  5. .claude/settings.json에 Hook을 설정하고 이 파일을 저장소에 커밋합니다.
  6. 팀원이 저장소를 받으면 같은 Hook이 자동 적용되는지 확인합니다.
  • stderr 메시지를 남기면 Claude가 차단 이유를 전달받아 방식을 조정합니다.
  • 운영 설정 폴더 쓰기, rm -rf 포함 명령, main 브랜치 커밋 차단 같은 규칙에 씁니다.
  • 프로젝트 스크립트는 CLAUDE_PROJECT_DIR 환경 변수로 참조하면 작업 디렉터리와 무관하게 동작합니다.
  • 비밀 파일 보호, 종료 시 요약 같은 강제 규칙도 훅으로 맡기고, 권고 수준의 규칙은 CLAUDE.md에 두세요.

7. 클라우드 세션으로 외출 중 작업 맡기기

클라우드 세션은 내 컴퓨터가 아닌 클라우드 가상 머신에서 도는 Claude Code 작업입니다. 노트북을 닫아도 계속되고 휴대폰으로 확인할 수 있어, 큰 리팩터링이나 퇴근 전 맡겨 두는 작업에 알맞습니다.

  1. GitHub 계정을 연결하고 GitHub에서 접근을 승인합니다.
  2. Claude GitHub App을 설치하고 접근을 허용할 저장소를 고릅니다.
  3. 데스크톱 앱에서 Local 대신 Cloud를 선택합니다.
  4. 저장소, 환경, 시작할 브랜치를 고릅니다.
  5. Claude에게 작업을 맡기고 노트북을 닫습니다.
  6. 휴대폰 Claude 앱의 Code 탭에서 질문에 답하거나 방향을 조정합니다.
  7. 변경 내용(diff)을 검토합니다. 남긴 코멘트는 다음 메시지와 함께 Claude에게 전달됩니다.
  8. 문제가 없으면 Create PR을 눌러 GitHub에서 풀 리퀘스트를 엽니다.
  • Pro, Max, Team 플랜 등에서 쓸 수 있고, 한도는 로컬 세션과 합산됩니다. 가상 머신 비용은 따로 없습니다.
  • 세션은 저장소를 새로 복제해 시작하므로 커밋·푸시한 내용만 쓸 수 있습니다. 개인 설정, 스킬, 플러그인이 필요한 작업은 로컬에서 실행하세요.
  • 비공개 저장소는 Claude GitHub App이 접근할 수 있어야 목록에 나타납니다.
  • Remote Control은 내 컴퓨터에서 도는 세션에 연결하는 방식이라 컴퓨터가 켜져 있어야 합니다.

8. 루틴으로 알아서 일하는 에이전트 만들기

루틴은 프롬프트, 저장소, 커넥터, 트리거만 정하면 Anthropic 관리형 인프라에서 원격 Claude Code 세션을 자동 실행하는 기능입니다. 노트북이 꺼져 있어도 돌아가며, 매주 문서 수정 PR을 만드는 식의 반복 업무에 맞습니다.

  1. 루틴이 할 일을 프롬프트로 정합니다(예: 매주 병합된 변경을 문서 저장소와 비교해 문서 수정 PR 만들기).
  2. 작업할 저장소와 필요한 커넥터를 연결합니다.
  3. 트리거를 고릅니다. 일정 기반 또는 GitHub 이벤트·웹훅·API 호출 같은 이벤트 기반이 있습니다.
  4. 트리거, 컨텍스트, 조종 방식 세 가지를 정했는지 확인합니다.
  5. 루틴을 실행한 뒤 결과 세션을 웹·CLI·데스크톱에서 열어 확인하고 이어서 지시합니다.
  • 모든 루틴은 열어 보고 지시하고 이어서 쓸 수 있는 Claude Code 세션입니다.
  • 매일 피드백을 모아 중요도별로 분류하고 확신이 높은 것만 고치는 식으로 쓸 수 있습니다.
  • 처음에는 PR 초안 만들기처럼 결과를 사람이 검토하는 일부터 맡기세요.

9. Projects로 여러 스레드 병렬 조율하기

Project는 Claude가 작업을 조율하는 하나의 지속적인 대화입니다. 작업마다 클라우드의 별도 브랜치에서 도는 스레드를 만들어 병렬로 처리하며, 여러 세션이나 저장소에 걸친 큰 목표에 적합합니다. 현재 베타이며 Pro와 Max에 순차 제공됩니다.

  1. 데스크톱 앱 또는 웹 앱에서 Claude 탭을 엽니다.
  2. 새 프로젝트를 만들고 이름, 달성할 목표, 관련 저장소나 폴더를 입력합니다.
  3. 열리는 메인 대화에서 코드베이스 탐색과 개선안 제안을 요청합니다.
  4. Claude가 찾은 내용을 보고 진행할 작업에 합의합니다.
  5. 작업마다 만들어진 스레드 카드를 눌러 진행 상황을 확인하고, 필요하면 말을 걸어 방향을 바꾸거나 중단합니다.
  6. threads 탭에서 사용자를 기다리는 스레드를 확인합니다.
  7. overview의 pull requests 탭에서 PR과 상태를 보고, 준비되면 병합을 요청합니다.
예시
이 저장소를 살펴보고 개선할 수 있는 점을 제안해 줘. 내가 동의한 작업마다 스레드를 따로 만들어서 진행해 줘.
  • 코디네이터는 낮은 노력 수준으로 두고, 스레드는 작은 모델을 기본으로 쓰다 복잡한 작업에서만 바꾸는 것을 권장합니다.
  • 로컬 파일이나 도구가 필요한 스레드는 내 컴퓨터에서 실행하도록 요청하세요.
  • library 탭은 모든 스레드가 공유하는 폴더이고, 매일 성능 저하를 점검하는 루틴도 같은 프로젝트 안에서 만들 수 있습니다.
  • 같은 저장소에서 로컬 세션을 병렬로 돌릴 때는 worktree를 쓴다는 사례가 있습니다.

10. 모드로 Claude Code 화면·동작 바꾸기

모드는 Claude Code의 모습과 행동을 바꾸는 작은 프로그램으로, 플러그인 형태입니다. 토큰 사용량 표시나 다음 작업 추천 카드처럼 창·버튼 같은 화면 요소는 모드로만 만들 수 있다고 합니다.

  1. Claude Code 데스크톱 앱의 좌측 상단 코드 탭으로 들어갑니다.
  2. 로컬 옆 버튼에서 폴더 열기로 프로젝트 폴더를 만들어 엽니다.
  3. 만들고 싶은 모드를 말로 설명해 요청합니다.
  4. 핫 리로딩 안내가 나오면 Enable for this session을 누릅니다.
  5. 잘 보이는지 확인해 달라고 요청해 결과를 확인합니다.
  6. 모든 세션에서 쓰려면, 방금 만든 모드를 플러그인으로 설치해 달라고 요청합니다.
예시
토큰 사용량을 아이콘과 함께 보여 주는 모드를 만들어 줘.
  • 모드를 만드는 전용 스킬이 들어 있어 코드를 몰라도 말로 설명하면 됩니다.
  • 플러그인으로 설치하지 않으면 모드는 만든 대화 안에서만 작동합니다.
  • 직접 코딩하려면 플러그인의 hook.json에 modules 키를 추가해 TypeScript 파일을 가리키게 합니다. 렌더 변경은 화면만 바꾸므로 모델은 원래 내용을 그대로 씁니다.
  • 모드는 플러그인이라 마켓플레이스 저장소에 올려 공유할 수 있습니다.

11. 루프로 대규모 작업 설계하기

루프 엔지니어링은 내가 시키지 않아도 AI가 계속 돌아가게 만드는 바깥 순환을 설계하는 일입니다. 반복 업무나 큰 작업을 맡길 때 무엇이 끝인지 판정하는 종료 조건이 가장 중요합니다.

  1. 반복해서 맡길 작업을 하나 정합니다(예: PR 관리, 코드 리뷰).
  2. 진행 상황을 적는 상태 파일을 만들어 AI의 기억 장치로 씁니다.
  3. 누가 봐도 참/거짓을 판정할 수 있는 종료 조건을 적습니다.
  4. 검증 통과, 최대 반복 횟수, 시간·비용 한도, 진전 없음 중단을 겹쳐서 걸어 둡니다.
  5. 만드는 AI와 검사하는 AI를 분리합니다.
  6. 스킬, 서브에이전트, MCP, 작업 공간 분리를 필요한 만큼만 붙입니다.
  7. 처음에는 결과를 코드로 검사하는 단순한 루프 하나로 시작해 돌려 봅니다.
  • 루프는 반복 업무에, 단계를 미리 알 수 없는 작업에는 동적 워크플로가 적합하다고 설명됩니다.
  • 한 실험에서 코드 검사 루프가 가장 빠르고 쌌고 그래프 방식은 토큰이 4배 넘게 들었습니다. 병렬 후 취합, 사람 승인 같은 이유가 있을 때만 구조를 늘리세요.
  • 만드는 AI가 자기 결과에 관대해지는 문제를 검사 AI 분리로 줄일 수 있습니다.
