Claude Code 고급

「Claude Code 고급」에서는 스킬로 일하는 방법을 저장해 두고, Hooks로 꼭 지킬 규칙을 강제하고, 서브에이전트·클라우드 세션·루틴·Projects로 여러 작업을 동시에 또는 내가 없을 때도 돌리는 방법을 다룹니다. 먼저 스킬과 Hooks로 기본 환경을 갖추세요. 그다음 검증 루프로 Claude가 결과를 스스로 확인하게 하고, 마지막에 백그라운드·병렬 작업과 큰 작업 설계로 넘어가면 됩니다.

서브에이전트, 스킬, Hooks, 플러그인, 병렬·백그라운드 작업, 워크트리, 대규모 작업 요령 · 영상 45개 기반 · 2026-11-03 갱신

최근 바뀐 점

  • 10월 1일 공식 발표된 '모드'로 Claude Code의 화면과 동작 방식을 바꿀 수 있으며, 데스크톱 앱에서는 코드를 몰라도 말로 설명해 만들 수 있습니다.
  • 클라우드 세션은 GitHub 저장소를 클라우드 가상 머신에 복제해 작업하므로, 노트북을 닫아도 일이 계속되고 휴대폰 Claude 앱의 Code 탭에서 질문에 답할 수 있습니다.
  • Claude Code Projects(베타, Pro·Max에 순차 제공)는 하나의 대화가 작업마다 클라우드 브랜치에서 도는 스레드를 만들어 병렬로 조율합니다.
  • 같은 과제를 비교한 실험에서 코드로 결과를 검사하는 루프 하나가 그래프(여러 단계 에이전트) 방식보다 빠르고, 토큰도 4배 넘게 덜 썼습니다.

1. 스킬로 반복 작업 맡기기

스킬은 Claude에게 작업 방법을 한 번 가르쳐 두면 관련 요청이 올 때 자동으로 적용되는 마크다운 파일(SKILL.md)입니다. 보고서·PPT처럼 같은 형식으로 반복해서 만드는 일을 매번 같은 품질로 맡기고 싶을 때 씁니다.

  1. 반복해서 시키는 작업 하나를 골라 Claude와 함께 샘플을 만들고, 만족스러울 때까지 다듬습니다.
  2. /skill-creator를 실행하거나, 방금 한 작업을 스킬로 만들어 달라고 요청합니다.
  3. 나만 쓸 스킬이면 홈 디렉터리의 .claude/skills, 팀과 함께 쓸 스킬이면 저장소 루트의 .claude/skills에 두라고 말합니다.
  4. 생성된 SKILL.md의 설명(description)에 언제 쓰는 스킬인지 분명히 적혀 있는지 확인합니다.
  5. Claude Code를 껐다가 다시 실행합니다.
  6. /를 입력해 새 스킬이 목록에 보이는지 확인합니다.
  7. 스킬 이름을 불러 작업을 요청하거나, 관련 요청을 해서 스킬이 자동으로 쓰이는지 확인합니다.
예시
대본과 디자인 시스템을 넣으면 PPT를 만들어 주는 스킬을 만들어 줘. 새 작업 폴더 생성, HTML·PPTX 생성, HTML 기준 검증까지 포함해 줘.
  • CLAUDE.md는 모든 대화에 불러오지만 스킬은 이름과 설명만 먼저 읽고 요청이 맞을 때만 내용을 불러오므로 컨텍스트를 아낍니다.
  • Claude가 같은 실수를 반복하면 다시 시키기보다 그 내용을 CLAUDE.md나 스킬에 적어 두세요.
  • 비슷한 결과물을 시리즈로 묶고 시리즈마다 스킬을 하나씩 두면 같은 지시로 같은 품질이 나옵니다.
  • 팀에서 스킬을 늘릴 때는 첫 스킬을 내기 전에 소유자·검토자·폐기·테스트 방식을 정해 두세요.

2. MCP를 스킬로 바꿔 토큰 아끼기

MCP는 연결하는 순간 도구 정의가 컨텍스트에 계속 머물러 세션 내내 토큰을 차지합니다. 자주 쓰는 MCP 작업을 스킬로 바꾸면 필요할 때만 내용을 불러와 더 가볍게 쓸 수 있습니다.

  1. /skill-creator를 실행합니다.
  2. 기존 MCP(예: n8n MCP)가 하던 일을 스킬로 만들어 달라고 요청합니다.
  3. 생성된 스킬 목록과 내용을 확인합니다.
  4. /mcp에서 해당 MCP를 선택해 Disable로 연결을 끊습니다.
  5. 스킬에 필요한 API 키를 새로 발급해 입력합니다.
  6. MCP로 하던 요청을 똑같이 해서 스킬로도 동일하게 동작하는지 확인합니다.
예시
n8n에 간단한 AI 챗봇 만들어 줘
  • 스킬은 프롬프트에 따라 자동 실행되거나 슬래시 명령으로 직접 호출할 수 있습니다.
  • API 키는 .env 파일에만 두고 문서나 대화에 그대로 적지 마세요.

3. 서브에이전트를 작은 모델로 돌리기

서브에이전트는 메인 Claude가 일부 일을 따로 맡기는 보조 에이전트입니다. 코드를 읽기만 하는 탐색용 서브에이전트는 작은 모델로 돌리면 결과는 비슷하고 비용과 사용 한도는 아낄 수 있습니다.

  1. 코드베이스를 읽기만 하는 서브에이전트(탐색·조사용)를 정합니다.
  2. 커스텀 서브에이전트의 frontmatter에서 모델을 Sonnet으로 지정합니다.
  3. 모든 서브에이전트의 기본 모델을 한 번에 바꾸려면 settings.json에 CLAUDE_CODE_SUBAGENT_MODEL 환경 변수를 설정합니다.
  4. 커밋하기 전에 코드 리뷰어 서브에이전트로 변경 내용을 점검하게 합니다.
예시
코드베이스를 읽기만 하는 탐색용 서브에이전트를 만들고, frontmatter에서 모델을 Sonnet으로 지정해 줘.
  • 탐색만 하는 서브에이전트에는 Opus급 추론이 필요 없습니다. 읽기 전용이면 Sonnet, 경우에 따라 Haiku까지 씁니다.
  • 메인 작업은 Opus 5.5의 기본 effort medium이면 대부분 충분하고, 여러 파일에 걸친 수정에만 high를 씁니다.
  • 여러 에이전트로 나누면 토큰이 크게 늘 수 있으니, 나눌 이유가 있을 때만 쓰세요.

4. Hooks로 편집 후 자동 서식 적용하기

Hooks는 Claude Code가 일하는 특정 시점에 정해 둔 명령을 실행하는 기능입니다. CLAUDE.md 지시는 가끔 지켜지지 않지만 Hook은 예외 없이 항상 실행되므로, 파일을 고칠 때마다 서식을 맞추는 일처럼 '반드시' 해야 하는 일에 씁니다.

  1. settings.json을 열거나 /hooks를 실행합니다.
  2. 이벤트로 PostToolUse를 고릅니다.
  3. matcher를 Edit 또는 MultiEdit로 지정합니다.
  4. 실행 명령에서 파일 확장자를 확인해 맞는 포매터를 실행하게 합니다.
  5. TypeScript는 Prettier, Python은 Ruff처럼 프로젝트에서 쓰는 도구를 연결합니다.
  6. 팀 전체가 쓰게 하려면 .claude/settings.json에 Hook을 넣고 저장소에 커밋합니다.
  • Hook 이벤트에는 UserPromptSubmit, PreToolUse, PostToolUse, Notification, Stop이 있습니다.
  • CLAUDE.md는 권고, Hooks는 강제라고 기억하세요.
  • .claude/settings.json을 커밋하면 팀원이 저장소를 받는 순간 같은 Hook이 자동 적용됩니다.

5. Hooks로 위험한 작업 차단하기

PreToolUse Hook은 Claude가 도구를 쓰기 직전에 실행되어, 위험한 명령이면 실행 전에 막을 수 있습니다. 운영 설정 폴더 쓰기, rm -rf 같은 삭제 명령, 비밀 파일 수정처럼 절대 일어나면 안 되는 일을 막을 때 씁니다.

  1. 이벤트로 PreToolUse Hook을 만듭니다.
  2. Hook 스크립트가 stdin으로 받는 JSON에서 도구 이름과 입력을 검사하게 합니다.
  3. 막아야 하는 경우 종료 코드 2로 끝내게 합니다.
  4. 차단 이유를 stderr에 남기게 해 Claude가 이유를 전달받고 방식을 바꾸게 합니다.
  5. 허용하는 경우 종료 코드 0으로 끝내게 합니다.
  6. 일부러 막힐 만한 요청을 해서 차단되는지 확인합니다.
  • 운영 설정 폴더 쓰기, rm -rf가 들어간 명령, main 브랜치 커밋 차단 같은 규칙에 알맞습니다.
  • 프로젝트 스크립트는 CLAUDE_PROJECT_DIR 환경 변수로 가리키면 작업 폴더가 바뀌어도 동작합니다.
  • 비밀 파일 보호, 세션 종료 시 요약 같은 Hook도 함께 두면 좋습니다.

6. CLAUDE.md·스킬·훅으로 하네스 세팅하기

하네스는 AI가 일을 잘하도록 감싸는 규칙·도구·검사 환경 전체를 말합니다. 새 프로젝트를 시작할 때 CLAUDE.md(목차), 스킬(필요할 때 부르는 절차), Hooks(어길 수 없는 규칙)를 한 번에 만들어 두면 이후 작업이 안정됩니다.

  1. Claude 데스크톱 앱의 Claude Code 탭에서 뉴세션을 누르고 작업 폴더를 만들어 엽니다.
  2. 앱 목적, 기술 스택, 디자인 시스템 같은 프로젝트 정보를 정리합니다.
  3. 프로젝트 정보와 함께 CLAUDE.md·스킬·훅을 만들어 달라는 프롬프트를 입력합니다.
  4. 생성된 CLAUDE.md, 스킬, 훅 구조를 파일 탭에서 확인합니다.
  5. 세션을 재시작합니다.
  6. /를 입력해 만든 스킬(예: 클린업)이 프로젝트 범위 스킬로 보이는지 확인합니다.
  • CLAUDE.md는 200줄 이내의 목차처럼 짧게 두고, 자세한 절차는 스킬로 뺍니다.
  • /init으로 만든 CLAUDE.md는 직접 규칙을 더해 다듬어야 효과가 있습니다.
  • 배포처럼 위험한 작업은 자동 호출에 맡기지 말고 슬래시로 직접 호출하세요.
  • 영상은 권한을 모두 허용하고 권한 건너뛰기로 진행하지만, 분류기가 위험한 요청만 막아 주는 자동 모드를 쓰는 편이 더 안전합니다.

7. verify 스킬로 검증 루프 만들기

Claude Code는 테스트·타입 검사는 스스로 돌리지만, 화면에서 실제로 의도대로 동작하는지는 따로 확인해야 합니다. 브라우저 클릭·스크린샷 같은 확인 절차를 스킬로 만들어 두면 Claude가 직접 확인하고, 틀리면 고친 뒤 다시 확인합니다.

  1. Claude Code에 포함된 verify 스킬을 처음 사용합니다.
  2. Claude가 앱을 실행하고 변경 사항을 앱에서 직접 확인하는지 지켜봅니다.
  3. 성공한 확인 절차가 프로젝트에 스킬로 저장되었는지 확인합니다.
  4. 생성된 스킬에 확인 항목을 추가합니다. 예: Chrome DevTools MCP로 레이아웃 시프트를 재는 성능 트레이스.
  5. 스킬에 언제 실행할지, 실패하면 무엇을 할지, 항목별 통과 기준을 적습니다.
  6. UI 변경을 요청하고 Claude가 서버 실행·페이지 열기·클릭·스크린샷을 한 뒤 실패하면 고쳐 다시 확인하는지 봅니다.
  • 통과 기준을 숫자처럼 측정할 수 있게 적을수록 Claude가 혼자 더 멀리 갑니다.
  • 지금 사람이 직접 확인하며 고칠 점을 알려 주고 있다면 성능 예산, 접근성 체크리스트, 디자인 시스템 규칙처럼 기준으로 바꿀 수 있는지 생각해 보세요.
  • Playwright MCP를 연결해 Claude가 앱을 직접 실행하고 결과를 보게 하는 방법도 있습니다.
  • 웹은 브라우저, 백엔드는 엔드포인트 호출, 모바일은 iOS 시뮬레이터로 확인 절차를 만들 수 있습니다.

8. 모드로 Claude Code 화면 바꾸기

모드는 Claude Code가 화면에 무엇을 그리고 어떻게 행동할지 바꾸는 작은 프로그램(플러그인)입니다. 토큰 사용량 표시, 다음 할 일 추천 카드처럼 작업 환경 자체를 내 입맛에 맞게 바꾸고 싶을 때 씁니다.

  1. Claude Code 데스크톱 앱 좌측 상단의 코드 탭으로 들어갑니다.
  2. 로컬 옆 버튼에서 폴더 열기로 프로젝트 폴더를 만들어 엽니다.
  3. 만들고 싶은 모드를 말로 설명해 요청합니다.
  4. 핫 리로딩 안내가 나오면 Enable for this session을 누릅니다.
  5. 잘 보이는지 확인해 달라고 요청해 결과를 확인합니다.
  6. 같은 대화에서 방금 만든 모드를 모든 세션에서 쓸 수 있도록 플러그인으로 설치해 달라고 요청합니다.
  7. 다른 세션이나 프로젝트를 열어 모드가 적용되는지 확인합니다.
예시
토큰 사용량을 아이콘과 함께 보여 주는 모드를 만들어 줘.
  • 모드를 만드는 전용 스킬이 이미 들어 있어 코드를 몰라도 말로 설명하면 됩니다.
  • 플러그인으로 설치하지 않으면 모드는 만든 대화 안에서만 작동합니다.
  • 직접 코드로 만들려면 플러그인의 hook.json에 modules 키를 추가해 TypeScript 파일을 가리키게 하고, render 같은 이벤트에 함수를 등록합니다.
  • 화면을 바꾸는 모드는 보이는 것만 바꿉니다. 예를 들어 이메일을 화면에서 가려도 모델은 실제 주소를 그대로 씁니다.

9. 클라우드 세션으로 백그라운드 작업하기

클라우드 세션은 내 컴퓨터가 아닌 클라우드 가상 머신에서 도는 Claude Code 작업입니다. 노트북을 닫아도 계속 진행되므로 큰 수정이나 퇴근 전에 맡겨 두는 작업에 알맞고, 여러 세션을 동시에 돌릴 수 있습니다.

  1. GitHub 계정을 연결하고 GitHub에서 접근을 승인합니다.
  2. Claude GitHub App을 설치하고 접근을 허용할 저장소를 고릅니다.
  3. 데스크톱 앱에서 Local 대신 Cloud를 선택합니다.
  4. 저장소, 환경, 시작할 브랜치를 고릅니다.
  5. Claude에게 작업을 맡기고 노트북을 닫습니다.
  6. 휴대폰 Claude 앱의 Code 탭에서 질문에 답하거나 방향을 바꿉니다.
  7. 변경 내용(diff)을 검토하고 필요하면 코멘트를 남깁니다.
  8. 문제가 없으면 Create PR을 눌러 풀 리퀘스트를 엽니다.
  • 세션은 저장소를 새로 복제해 시작하므로 커밋·푸시한 내용만 쓸 수 있습니다. 개인 설정·스킬·플러그인이 필요한 작업은 로컬에서 실행하세요.
  • 기본 환경에 없는 도구가 필요하면 사용자 지정 환경을 만들어 네트워크 범위, 환경 변수, 설치 스크립트를 정합니다.
  • 터미널에서 teleport 플래그를 붙여 claude를 실행하면 클라우드 세션을 내 컴퓨터로 가져와 이어 갈 수 있습니다.
  • Remote Control은 내 컴퓨터에서 도는 세션에 연결하는 방식이라 컴퓨터가 켜져 있어야 합니다.

10. 루틴으로 정기 작업 자동 실행하기

루틴은 프롬프트, 연결할 저장소, 커넥터, 시작 조건(트리거)만 정하면 Anthropic 인프라에서 Claude Code 세션을 자동으로 실행하는 기능입니다. 매일 피드백 정리, 매주 문서 갱신처럼 정해진 때 반복되는 일을 내가 시키지 않아도 먼저 하게 할 때 씁니다.

  1. 매일·매주 반복되는 일 하나를 고릅니다. 예: 그 주에 병합된 변경을 문서와 비교해 문서 수정 PR 만들기.
  2. 트리거를 정합니다. 시간 기반(일정)이나 이벤트 기반(GitHub 이벤트, 웹훅·API 호출) 중에서 고릅니다.
  3. 루틴이 참고할 컨텍스트로 저장소와 커넥터를 정합니다.
  4. 루틴이 실행할 프롬프트를 씁니다.
  5. 결과를 어떻게 확인하고 조종할지 정합니다. 루틴은 웹·CLI·데스크톱에서 열어 이어서 지시할 수 있는 세션입니다.
  6. 첫 실행 결과 세션을 열어 확인하고 필요하면 지시를 덧붙입니다.
예시
매일 성능 저하를 점검하는 루틴을 만들어 줘.
  • 루틴은 관리형 인프라에서 돌아 노트북이 꺼져 있어도 동작합니다.
  • 매일 피드백을 모아 중요도별로 나누고 확신이 높은 것만 고치게 하는 식으로 범위를 좁히면 안전합니다.
  • 루틴이 문제를 발견하면 조사 스레드를 열어 두고 기다리게 할 수 있습니다.
  • 반복 업무는 루틴·루프로, 단계를 미리 알 수 없는 작업은 동적 워크플로로 맡기는 것이 좋습니다.

11. Projects로 여러 작업 병렬 처리하기

Project는 Claude가 여러 작업을 조율하는 하나의 지속적인 대화입니다. 작업마다 클라우드의 별도 브랜치에서 도는 스레드를 만들어 동시에 처리하므로, 여러 세션이나 저장소에 걸친 큰 목표에 알맞습니다(현재 베타).

  1. 데스크톱 앱 또는 웹 앱에서 Claude 탭을 엽니다.
  2. 새 프로젝트를 만들고 이름, 달성할 목표, 관련 저장소나 폴더를 입력합니다.
  3. 열린 메인 대화에서 코드베이스 탐색과 개선안 제안을 요청합니다.
  4. Claude가 찾은 내용을 보고 진행할 작업에 합의합니다.
  5. 작업마다 생긴 스레드 카드를 눌러 진행 상황을 보고, 필요하면 말을 걸어 방향을 바꾸거나 중단합니다.
  6. threads 탭에서 내 답을 기다리는 스레드를 확인합니다.
  7. overview의 pull requests 탭에서 PR 상태를 보고, 준비되면 Claude에게 병합을 요청합니다.
  • 조율하는 메인 대화는 낮은 노력 수준으로, 스레드는 작은 모델을 기본으로 두고 복잡한 작업에서만 바꾸는 것이 권장됩니다.
  • library 탭에 목업·디자인 명세를 넣으면 모든 스레드가 함께 씁니다.
  • 로컬 파일이나 도구가 필요한 작업은 해당 스레드를 내 컴퓨터에서 실행하도록 요청합니다.
  • 스레드는 PR을 계속 지켜보며 CI 실패 시 수정을 푸시하고 리뷰 코멘트를 반영합니다.

12. 큰 작업을 루프와 종료 조건으로 맡기기

큰 작업은 AI가 만들고, 검사하고, 다시 고치는 순환(루프)으로 맡겨야 끝까지 갑니다. 핵심은 무엇이 '완료'인지 누구나 판정할 수 있는 기준과 멈출 조건을 먼저 정하는 것으로, 코드 이전·대규모 수정·앱 분석처럼 오래 걸리는 일에 씁니다.

  1. 맡길 일 하나와 '완료' 기준을 정합니다. 누가 봐도 참·거짓으로 판정할 수 있어야 합니다.
  2. 구조를 늘리기 전에 결과를 코드로 검사하는 검사기(테스트)부터 만들게 합니다.
  3. 원본으로 검사기를 먼저 통과시켜 검사기 자체가 맞는지 확인합니다.
  4. 고치면 안 되는 것과 하면 안 되는 일(원본·테스트 수정, 푸시·배포·삭제)을 명시합니다.
  5. 종료 조건을 겹쳐 겁니다: 검증 통과, 최대 반복 횟수, 시간·비용 한도, 진전 없음 시 중단.
  6. 진행 상황을 적는 상태 파일을 두게 해 세션이 바뀌어도 이어서 하게 합니다.
  7. 결과가 기준에 못 미치면 측정한 숫자를 그대로 Claude에게 돌려줍니다.
  8. 병렬 후 취합, 독립 검증, 사람 승인처럼 이유가 있을 때만 여러 에이전트로 나눕니다.
예시
원본 코드와 테스트는 고치지 말고, 푸시·배포·삭제는 하지 마. 먼저 원본과 새 함수의 출력을 비교하는 테스트를 만들어 원본으로 통과시킨 다음 작업을 시작해.
  • 실험에서 코드 검사 루프는 8.3초·약 1만7천 토큰, 그래프 방식은 53.3초·약 7만4천 토큰이 들었습니다. 기본은 루프 하나로 하세요.
  • 만드는 AI와 검사하는 AI를 나누면 자기 결과에 관대해지는 문제를 줄일 수 있습니다.
  • 같은 저장소에서 세션 여러 개를 동시에 돌릴 때는 세션마다 worktree로 작업 공간을 나눕니다.
  • 테스트를 모두 통과해도 속도는 따로 재야 합니다. 통과한 Rust 버전이 여러 스레드에서 Python보다 느렸던 사례가 있습니다.
