Claude Code 고급

Claude Code 고급 단계에서는 스킬로 일하는 방법을 가르치고, Hooks로 규칙을 강제하며, 서브에이전트와 여러 모델로 일을 나누고, 클라우드·프로젝트·루틴으로 내 컴퓨터를 벗어나 일을 맡기는 법을 익힙니다. 스킬 → Hooks → 서브에이전트와 모델 선택 → 검증 루프 → 클라우드 세션·프로젝트·루틴 → 모드 순으로 보면 부담 없이 따라갈 수 있습니다. 모델 이름과 요금제별 제공 범위는 자주 바뀌니 영상에 나온 기준일을 함께 확인하세요.

최근 바뀐 점

  • Claude Fable 5.2가 출시되어, 크고 모호한 장기 작업은 Fable, 범위가 분명한 작업은 Sonnet, 대량 작업은 Haiku로 나누어 쓰는 기준이 나왔습니다.
  • 메인 세션은 Fable이 맡고 세부 작업은 Sonnet 서브에이전트에 넘기는 방식이 소개되었습니다.
  • 모드(Mods)를 플러그인으로 설치하면 모든 세션에서 쓸 수 있고, 데스크톱 앱에서 말로 설명해 만들 수 있습니다.
  • Claude Code 클라우드 세션은 노트북을 닫아도 계속 진행되며, 휴대폰에서 방향을 바꾸고 Create PR로 마무리할 수 있습니다.

1. 스킬로 반복 작업 가르치기

스킬은 Claude에게 작업 방법을 한 번 가르쳐 두면 관련 요청이 올 때 자동으로 적용되는 SKILL.md 마크다운 파일입니다. 보고서 양식이나 PPT 제작처럼 매번 같은 방식으로 해야 하는 일에 씁니다.

  1. 스킬이 필요한 반복 작업을 하나 정하고, 만족스러운 결과가 나올 때까지 평소처럼 Claude와 작업해 봅니다.
  2. 만족스러운 결과가 나오면 이 작업 방식을 스킬로 만들어 달라고 요청합니다.
  3. 모든 프로젝트에서 쓸 스킬은 홈 디렉터리의 .claude/skills에, 팀과 공유할 스킬은 저장소 루트의 .claude/skills에 두도록 안내받아 확인합니다.
  4. 스킬 안의 설명(description)이 언제 쓰는 스킬인지 분명히 적혀 있는지 확인합니다.
  5. Claude Code를 껐다가 다시 실행해 스킬을 적용합니다.
  6. 스킬이 자동으로 실행되는지, 또는 /를 입력해 이름을 직접 불러서 실행되는지 확인합니다.
  7. 추가하고 싶은 항목이 생기면 스킬에 계속 더해 갑니다.
예시
방금 만든 PPT 작업 방식을 스킬로 만들어 줘. 대본과 디자인 시스템을 넣으면 같은 디자인의 PPT가 나오게 하고, 새 작업 폴더 생성과 결과 검증도 포함해 줘.
  • CLAUDE.md는 모든 대화에 로드되고, 스킬은 요청이 맞을 때만 이름과 설명이 먼저 로드되어 컨텍스트를 아낍니다.
  • 스킬은 재시작해야 같은 세션에서 인식됩니다.
  • 스킬은 '무엇을 할지'보다 '어떻게 생각할지'를 가르치도록 쓰면 좋다고 합니다.
  • 예전 방식: 외부 도구를 MCP로 연결했지만 도구 정의가 세션 내내 토큰을 차지하므로, 반복 작업은 /skill-creator로 스킬로 바꾸는 방법이 소개되었습니다.

2. MCP를 스킬로 바꿔 토큰 아끼기

MCP는 연결하는 순간 도구 정의가 컨텍스트에 계속 남아 토큰을 차지합니다. 스킬은 시작할 때 이름과 설명만 불러오므로, 자주 쓰는 외부 도구 작업을 스킬로 바꾸면 효율적입니다.

  1. MCP로 하던 작업이 이미 잘 동작하는지 확인합니다.
  2. /skill-creator를 실행합니다.
  3. 기존 MCP가 하던 일을 스킬로 만들어 달라고 프롬프트를 입력합니다.
  4. 생성된 스킬 목록을 확인합니다.
  5. /mcp에서 해당 MCP를 선택해 Disable로 연결을 끊습니다.
  6. 스킬이 필요로 하는 API 키를 새로 발급해 입력합니다.
  7. 같은 작업을 요청해 MCP 없이 똑같이 동작하는지 확인합니다.
예시
/skill-creator 기존 n8n MCP가 하던 일을 스킬로 만들어 줘.
  • API 키는 파일이나 대화에 그대로 남기지 말고 안전한 곳에 보관하세요.
  • 스킬은 프롬프트에 따라 자동 실행되거나 슬래시 명령으로 직접 호출할 수 있습니다.

3. Hooks로 규칙을 반드시 지키게 하기

Hooks는 Claude Code의 특정 시점에 명령을 실행하는 기능입니다. CLAUDE.md의 지시는 가끔 지켜지지 않지만 Hook은 예외 없이 실행되므로, 자동 서식 적용이나 위험 작업 차단에 씁니다.

  1. settings.json 또는 /hooks에서 Hook을 설정합니다.
  2. 편집 뒤 서식을 맞추려면 이벤트로 PostToolUse를 고르고 matcher를 Edit 또는 MultiEdit로 지정합니다.
  3. 실행 명령에서 파일 확장자를 확인해 프로젝트에서 쓰는 포매터(Prettier, Ruff 등)를 실행하게 합니다.
  4. 위험 작업을 막으려면 PreToolUse Hook을 만들고, stdin으로 받는 JSON의 도구 이름과 입력을 검사합니다.
  5. 막아야 하면 종료 코드 2로 끝내고 stderr에 이유를 남깁니다. 허용하면 0으로 끝냅니다.
  6. 팀과 공유하려면 .claude/settings.json에 설정하고 저장소에 커밋합니다.
  • Hook 이벤트에는 UserPromptSubmit, PreToolUse, PostToolUse, Notification, Stop이 있습니다.
  • CLAUDE.md는 권고, Hooks는 강제라고 이해하면 됩니다.
  • 프로젝트 스크립트는 CLAUDE_PROJECT_DIR 환경 변수로 참조하면 작업 디렉터리와 무관하게 동작합니다.
  • rm -rf 포함 명령이나 main 커밋 차단 같은 규칙에 쓰기 좋습니다.

4. 검증 루프로 Claude가 직접 확인하게 하기

테스트나 린터만으로는 변경이 의도대로 동작하는지 증명되지 않습니다. 실제 앱을 실행해 확인하는 절차를 스킬로 만들어 두면 Claude가 스스로 확인하고 고친 뒤 다시 확인합니다.

  1. Claude Code에 포함된 verify 스킬을 처음 사용합니다.
  2. Claude가 앱을 실행하고 변경 사항을 직접 확인하는 것을 지켜봅니다.
  3. 성공한 절차가 프로젝트에 스킬로 저장되는지 확인합니다.
  4. 생성된 스킬에 확인 항목을 추가합니다. 예: Chrome DevTools MCP로 레이아웃 시프트를 측정하는 성능 트레이스.
  5. 스킬에 언제 실행할지, 확인에 실패하면 무엇을 할지, 각 확인의 통과 기준을 적습니다.
  6. UI 변경을 요청하고 서버 실행, 페이지 열기, 클릭, 스크린샷, 성능 트레이스, 실패 시 재확인이 이어지는지 봅니다.
  • 확인 기준이 측정 가능할수록 Claude가 더 멀리 혼자 갑니다.
  • 수동으로 확인하고 고칠 점을 알려 주고 있다면 성능 예산, 접근성 체크리스트, 디자인 시스템 규칙 같은 기준으로 만들 수 있는지 생각해 보세요.
  • 실수가 나오면 다시 시키지 말고 CLAUDE.md나 스킬에 적어 같은 실수를 막으세요.

5. 서브에이전트에 작은 모델 배정하기

서브에이전트는 자체 컨텍스트를 가진 별도의 Claude로, 메인 세션 대신 세부 작업을 처리하고 결과를 보고합니다. 코드를 읽기만 하는 서브에이전트에는 작은 모델을 지정해 비용과 한도를 아낄 수 있습니다.

  1. 코드베이스를 읽기만 하는 서브에이전트로 쓸 작업을 정합니다.
  2. 커스텀 서브에이전트의 frontmatter에서 모델을 Sonnet으로 지정합니다.
  3. 모든 서브에이전트의 기본값을 한 곳에서 바꾸려면 settings.json에 CLAUDE_CODE_SUBAGENT_MODEL 환경 변수를 설정합니다.
  4. 서브에이전트를 쓰는 작업을 실행해 결과가 충분한지 확인합니다.
  • 탐색만 하는 서브에이전트에는 Opus급 추론이 필요 없습니다.
  • 읽기 전용 서브에이전트는 Sonnet, 경우에 따라 Haiku까지 씁니다.
  • 커밋 전에 서브에이전트 코드 리뷰어로 점검하게 하는 방법도 있습니다.

6. 한 작업을 여러 모델로 나누어 맡기기

큰 작업 전체에 가장 비싼 모델이 필요한 것은 아닙니다. 방향을 잡는 메인 세션은 Fable이 맡고, 범위가 분명한 세부 작업은 Sonnet 서브에이전트에 넘기면 성능과 비용을 함께 챙길 수 있습니다.

  1. 큰 작업(예: 모든 패키지의 프레임워크 메이저 버전 마이그레이션)에는 Fable로 메인 세션을 시작합니다.
  2. 패키지 업그레이드와 테스트 수정처럼 범위가 분명한 부분을 가려 냅니다.
  3. Fable에게 마이그레이션을 이끌면서 그 부분을 Sonnet에게 넘기라고 요청합니다.
  4. 메인 세션이 서브에이전트에 작업을 맡기면, 서브에이전트가 자체 컨텍스트로 처리하고 결과를 보고하는 것을 확인합니다.
예시
모든 패키지의 프레임워크 메이저 버전 마이그레이션을 이끌어 줘. 패키지 업그레이드와 테스트 수정처럼 범위가 분명한 부분은 Sonnet 서브에이전트에게 넘겨.
  • 추천 시작점은 중간 노력 수준의 Opus 5.5이고, 결과가 부족하면 먼저 노력 수준을 올립니다.
  • Fable은 토큰당 가격이 Opus의 두 배, Sonnet은 Opus의 절반이며, 요약·분류 같은 대량 작업은 Haiku가 맞습니다. Haiku의 가용성과 한도는 요금제마다 다릅니다.
  • 모델은 작업의 길이와 복잡도로 고릅니다. 단순 파일 생성에 고성능 모델은 필요하지 않습니다.

7. 클라우드 세션으로 맡겨 두고 PR 만들기

클라우드 세션은 내 컴퓨터가 아닌 클라우드 가상 머신에서 도는 Claude Code 작업입니다. 노트북을 닫아도 계속 진행되어, 큰 리팩터링이나 퇴근 전 맡겨 두는 작업에 알맞습니다.

  1. GitHub 계정을 연결하고 GitHub에서 접근을 승인합니다.
  2. Claude GitHub App을 설치하고 접근을 허용할 저장소를 고릅니다.
  3. 데스크톱 앱에서 Local 대신 Cloud를 선택합니다.
  4. 저장소, 환경, 시작할 브랜치를 고릅니다.
  5. Claude에게 작업을 맡기고 노트북을 닫습니다.
  6. 휴대폰 Claude 앱의 Code 탭에서 질문에 답하거나 방향을 조정합니다.
  7. 변경 내용(diff)을 검토합니다. 남긴 코멘트는 다음 메시지와 함께 Claude에게 전달됩니다.
  8. 문제가 없으면 Create PR을 눌러 풀 리퀘스트를 엽니다.
  • 세션은 저장소를 새로 복제해 시작하므로 커밋·푸시한 내용만 쓸 수 있습니다. 개인 설정, 스킬, 플러그인이 필요한 작업은 로컬에서 실행하세요.
  • 비공개 저장소는 Claude GitHub App이 접근할 수 있어야 목록에 나타납니다.
  • Remote Control은 내 컴퓨터에서 실행 중인 세션에 연결하는 방식이라 컴퓨터가 켜져 있어야 합니다.
  • 기본 환경에 없는 것이 필요하면 사용자 지정 환경에서 네트워크 범위, 환경 변수, 설정 스크립트를 추가합니다.

8. Projects로 여러 작업을 병렬 조율하기

Project는 Claude가 작업을 조율하는 하나의 지속적인 대화로, 작업마다 클라우드의 별도 브랜치에서 도는 스레드를 만들어 병렬로 처리합니다. 여러 세션이나 저장소에 걸친 큰 목표에 적합하며 현재 베타입니다.

  1. 데스크톱 앱 또는 웹 앱에서 Claude 탭을 엽니다.
  2. 새 프로젝트를 만들고 이름, 달성할 목표, 관련 저장소나 폴더를 입력합니다.
  3. 열리는 메인 대화에서 코드베이스 탐색과 개선안 제안을 요청합니다.
  4. Claude가 찾은 내용을 보고 진행할 작업에 합의합니다.
  5. 작업마다 만들어진 스레드 카드를 눌러 진행 상황을 확인하고, 필요하면 방향을 바꾸거나 중단합니다.
  6. threads 탭에서 사용자를 기다리는 스레드를 확인합니다.
  7. overview의 pull requests 탭에서 모든 PR과 상태를 보고, 준비되면 Claude에게 병합을 요청합니다.
  • Projects는 베타이며 Pro와 Max 요금제에 점진적으로 제공됩니다.
  • 코디네이터는 낮은 노력 수준으로 두고, 스레드는 작은 모델을 기본으로 쓰다 복잡한 작업에서만 바꾸는 것을 권장합니다.
  • 로컬 파일이나 도구가 필요한 스레드는 내 컴퓨터에서 실행하도록 요청하세요.
  • library 탭은 모든 스레드가 공유하는 파일 폴더입니다.

9. 루틴으로 매일 점검 맡기기

루틴은 프롬프트, 저장소, 커넥터, 트리거를 정해 두면 Anthropic 관리형 인프라에서 원격 Claude Code 세션을 자동 실행하는 기능입니다. 노트북이 꺼져 있어도 돌아가며 일정이나 이벤트로 시작할 수 있습니다.

  1. 루틴으로 맡길 반복 업무(예: 매일 성능 점검, 매주 문서 갱신)를 정합니다.
  2. 트리거를 고릅니다. 일정 기반 또는 GitHub 이벤트·웹훅·API 호출 같은 이벤트 기반이 있습니다.
  3. 루틴이 읽을 컨텍스트(저장소, 커넥터)를 연결합니다.
  4. 결과를 어떻게 조종할지, 즉 PR을 열지 알림만 줄지를 정합니다.
  5. 루틴을 실행한 뒤 웹·CLI·데스크톱에서 해당 세션을 열어 결과를 확인하고 이어서 지시합니다.
예시
매일 성능 저하를 점검하는 루틴을 만들어 줘. 저하를 발견하면 조사 스레드를 열어 프로젝트에서 기다리게 해.
  • 모든 루틴은 열어 보고 지시하고 이어서 쓸 수 있는 Claude Code 세션입니다.
  • 수정 PR을 계속 지켜보며 CI 실패 시 고치게 하는 용도로도 씁니다.

10. 병렬 세션에 워크트리 쓰기

같은 저장소에서 여러 Claude 세션을 동시에 돌리면 파일이 서로 겹칠 수 있습니다. 워크트리를 쓰면 세션마다 작업 공간을 나눌 수 있어, 대규모 작업을 병렬로 처리하는 데 도움이 됩니다.

  1. 동시에 진행할 작업을 서로 겹치지 않게 나눕니다.
  2. 작업마다 터미널 탭을 하나씩 열고 Claude 세션을 시작합니다.
  3. 같은 저장소에서 병렬로 도는 세션에는 각각 worktree를 씁니다.
  4. 세션마다 결과를 확인하고 변경 내용을 검토합니다.
  • 영상에서는 Spotify 엔지니어가 터미널 탭 5~10개에 Claude 세션과 worktree를 매트릭스로 운영하고, DoorDash 공동창업자도 병렬 세션에 worktree를 쓴다고 합니다.
  • 영상에 worktree 명령어 자체는 나오지 않았으니 세부 방법은 Claude에게 물어 확인하세요.
  • 병렬화는 토큰을 많이 쓰므로, 기본은 루프 하나로 하고 병렬 후 취합, 독립 검증 같은 이유가 있을 때만 구조를 늘리세요.

11. 모드(Mods)로 Claude Code 화면 바꾸기

모드는 Claude Code가 무엇을 그리고 어떤 도구를 호출하는지 바꾸는 작은 플러그인입니다. 토큰 사용량 표시나 다음 작업 추천 카드처럼 작업 환경 자체를 말로 설명해 만들 수 있습니다.

  1. Claude Code 데스크톱 앱의 좌측 상단 코드 탭으로 들어갑니다.
  2. 로컬 옆 버튼에서 폴더 열기로 프로젝트 폴더를 만들어 엽니다.
  3. 만들고 싶은 모드를 말로 설명해 요청합니다.
  4. 핫 리로딩 안내가 나오면 Enable for this session을 누릅니다.
  5. 잘 보이는지 확인해 달라고 요청해 결과를 확인합니다.
  6. 모든 세션에서 쓰려면 방금 만든 모드를 플러그인으로 설치해 달라고 요청하고, 다른 세션에서 적용되는지 확인합니다.
예시
토큰 사용량을 아이콘과 함께 보여 주는 모드를 만들어 줘.
  • 모드를 만드는 전용 스킬이 이미 들어 있어 코드를 몰라도 말로 설명하면 됩니다.
  • 플러그인으로 설치하지 않으면 모드는 만든 대화 안에서만 작동합니다.
  • 직접 만들 때는 플러그인의 hook.json에 modules 키를 추가해 TypeScript 파일을 가리키게 하며, 폴더를 감시하므로 저장하면 현재 세션에 바로 반영됩니다.
  • 렌더 변경은 화면만 바꾸므로 모델은 실제 내용을 그대로 씁니다.
