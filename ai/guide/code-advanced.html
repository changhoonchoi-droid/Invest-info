Claude Code 고급

Claude Code 고급 기능을 쓰면 반복 규칙을 Hooks로 자동화하고, 검증 절차를 스킬로 남기고, 서브에이전트·클라우드 세션·Projects로 여러 일을 동시에 맡길 수 있습니다. 먼저 Hooks와 verify 스킬로 내 컴퓨터의 작업을 안정시키고, 이어서 서브에이전트와 모드로 작업 환경을 다듬은 뒤, 마지막으로 클라우드 세션·Projects·루틴으로 노트북을 닫아도 돌아가는 병렬 작업으로 넓혀 가는 순서를 권합니다.

  • 모드는 플러그인으로 동작하며, 플러그인의 hook.json에 modules 키를 넣어 TypeScript 파일을 연결하는 방식으로 직접 만들 수도 있습니다.

1. Hook으로 편집 후 자동 서식 적용하기

Hooks는 Claude Code가 일하는 특정 시점마다 정해 둔 명령을 실행하는 기능입니다. CLAUDE.md에 적은 지시는 가끔 빠지지만 Hook은 예외 없이 매번 실행되므로, 파일을 고칠 때마다 서식을 맞추는 것처럼 반드시 지켜야 하는 규칙에 씁니다.

  1. settings.json을 열거나 Claude Code에서 /hooks를 실행해 Hook 설정을 시작합니다.
  2. 이벤트로 PostToolUse(도구 사용 직후)를 고릅니다.
  3. matcher를 Edit 또는 MultiEdit로 지정해 파일을 고칠 때만 실행되게 합니다.
  4. 실행할 명령에서 파일 확장자를 확인해 맞는 포매터를 부르게 합니다.
  5. TypeScript는 Prettier, Go는 Go format, Python은 Ruff처럼 프로젝트에서 쓰는 도구를 연결합니다.
  6. Claude에게 파일 하나를 고치게 한 뒤 서식이 자동으로 맞춰졌는지 확인합니다.
  • Hook 이벤트에는 UserPromptSubmit, PreToolUse, PostToolUse, Notification, Stop이 있어 작업 완료 알림이나 실행 명령 기록에도 쓸 수 있습니다.
  • 프로젝트의 .claude/settings.json에 Hook을 넣고 저장소에 커밋하면 팀원 모두에게 같은 Hook이 자동 적용됩니다.
  • 프로젝트 안의 스크립트는 CLAUDE_PROJECT_DIR 환경 변수로 가리키면 작업 폴더가 달라도 동작합니다.

2. Hook으로 위험한 작업 막기

도구가 실행되기 직전에 도는 PreToolUse Hook으로 위험한 명령을 미리 검사해 막을 수 있습니다. 운영 설정 폴더에 쓰기, rm -rf가 들어간 명령, main 브랜치 직접 커밋처럼 절대 일어나면 안 되는 일을 차단할 때 씁니다.

  1. 이벤트를 PreToolUse로 정해 새 Hook을 만듭니다.
  2. Hook 스크립트가 stdin으로 받는 JSON에서 도구 이름과 입력 내용을 읽어 검사합니다.
  3. 막아야 하는 경우 종료 코드 2로 끝내게 합니다.
  4. 막을 때 stderr에 이유를 적어, Claude가 차단 이유를 전달받고 다른 방법을 찾게 합니다.
  5. 허용하는 경우 종료 코드 0으로 끝내게 합니다.
  6. 일부러 막아야 할 명령을 요청해 차단되는지 확인합니다.
  • 종료 코드 0은 진행, 2는 차단입니다.
  • 자동 모드를 함께 쓰는 경우에도 deny·ask·allow 규칙이 먼저 적용되므로, 꼭 막을 것은 규칙과 Hook으로 분명히 정해 두세요.
  • 이 Hook도 .claude/settings.json에 넣어 커밋하면 팀 전체에 같은 안전장치가 걸립니다.

3. verify 스킬로 검증 루프 만들기

테스트·린터만으로는 변경이 실제로 의도대로 동작하는지 알 수 없습니다. Claude Code에 들어 있는 verify 스킬로 Claude가 앱을 직접 실행해 확인하게 하고, 그 절차를 프로젝트 스킬로 남겨 두면 이후에는 Claude가 스스로 고치고 다시 확인합니다.

  1. Claude Code에 포함된 verify 스킬을 처음 사용해 봅니다.
  2. Claude가 앱을 실행하고 변경 사항을 앱에서 직접 확인하는 과정을 지켜봅니다.
  3. 성공한 확인 절차가 프로젝트에 스킬로 저장되었는지 확인합니다.
  4. 생성된 스킬에 확인 항목을 더합니다(예: Chrome DevTools MCP로 레이아웃 시프트를 재는 성능 트레이스).
  5. 스킬에 언제 실행할지, 실패하면 무엇을 할지, 항목별 통과 기준을 적습니다.
  6. UI 변경을 요청하고 Claude가 서버 실행·페이지 열기·클릭·스크린샷·성능 측정을 한 뒤 실패하면 고쳐 다시 확인하는지 봅니다.
예시
방금 바꾼 화면이 실제로 잘 동작하는지 verify 스킬로 앱을 직접 실행해서 확인해 줘.
  • 통과 기준이 측정 가능할수록 Claude가 혼자 더 멀리 갑니다. 성능 예산, 접근성 체크리스트, 디자인 시스템 규칙 같은 것을 기준으로 삼아 보세요.
  • 웹은 브라우저, 백엔드는 엔드포인트 호출, 모바일은 iOS 시뮬레이터로 확인 절차를 만들 수 있습니다.
  • 같은 실수가 나오면 다시 시키지 말고 CLAUDE.md나 스킬에 적어 재발을 막습니다.
  • 검증 명령은 사람과 에이전트가 똑같이 돌릴 수 있게 만들어 CI에서도 실행합니다.

4. 서브에이전트에 탐색·리뷰 맡기기

서브에이전트는 메인 Claude 대신 일부 작업을 따로 맡아 처리하는 보조 에이전트입니다. 코드베이스를 읽기만 하는 탐색이나 커밋 전 코드 리뷰를 맡기면 메인 대화가 깔끔해지고, 작은 모델로 돌리면 비용과 한도도 아낄 수 있습니다.

  1. 코드베이스를 읽기만 하는 서브에이전트(예: 탐색용)를 정합니다.
  2. 커스텀 서브에이전트의 frontmatter에서 모델을 Sonnet으로 지정합니다.
  3. 모든 서브에이전트의 기본 모델을 한 번에 바꾸려면 settings.json에 CLAUDE_CODE_SUBAGENT_MODEL 환경 변수를 설정합니다.
  4. 커밋하기 전에 서브에이전트 코드 리뷰어로 변경 내용을 점검하게 합니다.
  5. 리뷰가 끝나면 커밋 메시지를 만들게 합니다.
예시
코드베이스를 읽기만 하는 탐색용 서브에이전트를 만들고, frontmatter에서 모델을 Sonnet으로 지정해 줘.
  • 탐색만 하는 서브에이전트에는 Opus급 추론이 필요 없어 Sonnet, 경우에 따라 Haiku로도 충분합니다.
  • Opus 5.5의 기본 effort는 medium이며 대부분 충분하지만, 여러 파일·프로젝트 전체를 바꾸는 수정에는 high를 씁니다.
  • 큰 작업 중에는 /context로 컨텍스트 사용 현황을 확인해 여유를 살핍니다.

5. 말로 설명해 모드 만들기

모드(Mods)는 Claude Code의 화면과 행동 방식을 바꾸는 작은 프로그램으로, 2026년 10월 1일 공식 발표되었습니다. Claude가 작업할 때 나오는 신호를 듣고 지켜보거나, 살짝 고치거나, 대신 처리합니다. 데스크톱 앱에는 모드 제작용 스킬이 들어 있어 코드를 몰라도 말로 만들 수 있습니다.

  1. Claude Code 데스크톱 앱 좌측 상단의 코드 탭으로 들어갑니다.
  2. 로컬 옆 버튼에서 폴더 열기로 모드용 프로젝트 폴더를 만들어 엽니다.
  3. 만들고 싶은 모드를 말로 설명해 요청합니다.
  4. 핫 리로딩 안내가 나오면 Enable for this session을 누릅니다.
  5. 모드가 잘 보이는지 확인해 달라고 요청해 결과를 봅니다.
예시
토큰 사용량을 아이콘과 함께 화면에 보여 주는 모드를 만들어 줘.
  • 창·버튼 같은 화면 요소는 모드로만 만들 수 있다고 설명합니다. 스킬·MCP는 지식과 도구를 건네고, 모드는 작업 환경 자체를 바꿉니다.
  • 다음 작업 추천 모드처럼 턴이 끝날 때마다 할 일 세 가지를 카드로 띄우고 클릭하면 바로 실행되게 만들 수도 있습니다.
  • 만든 대화 밖에서도 쓰려면 다음 가이드처럼 플러그인으로 설치해야 합니다.

6. 모드를 플러그인으로 모든 세션에 쓰기

말로 만든 모드는 처음에는 만든 대화 안에서만 작동합니다. 플러그인으로 설치하면 다른 세션과 프로젝트에서도 같은 모드를 쓸 수 있고, 마켓플레이스 저장소에 올려 남과 공유할 수도 있습니다.

  1. 모드를 만든 대화로 돌아갑니다.
  2. 방금 만든 모드를 모든 세션에서 쓸 수 있도록 플러그인으로 설치해 달라고 요청합니다.
  3. 다른 세션이나 다른 프로젝트를 열어 모드가 적용되는지 확인합니다.
예시
방금 만든 모드를 내 모든 세션에서 쓸 수 있도록 플러그인으로 설치해 줘.
  • 이 단계를 건너뛰면 모드는 만든 대화 안에서만 작동합니다.
  • 모드는 플러그인이라 마켓플레이스 저장소에 올려 팀과 공유할 수 있습니다.
  • 클라우드 세션은 저장소를 새로 복제해 시작하므로 개인 플러그인이 필요한 작업은 로컬에서 실행합니다.

7. 코드로 모드 직접 만들기

모드는 Claude Code가 무엇을 그리고, 프롬프트에 무엇을 넣고, 어떤 도구를 부를지 바꾸는 함수입니다. 내부 이벤트에 함수를 등록하면 이벤트마다 실행되므로, 화면에서 이메일 주소를 가리는 것처럼 정교한 동작을 직접 만들 수 있습니다. 개발 지식이 조금 필요한 고급 방법입니다.

  1. 플러그인의 hook.json에 modules 키를 추가하고 TypeScript 파일을 가리키게 합니다.
  2. 그 파일에서 렌더 이벤트(render)에 함수를 등록합니다.
  3. 이벤트 데이터로 들어오는 답변 텍스트에서 이메일 주소를 찾습니다.
  4. 주소마다 $send 객체로 마우스를 올릴 때만 보이는 블록을 만듭니다.
  5. next를 호출하지 않고 결과를 직접 반환해 Claude Code가 내 버전을 그리게 합니다.
  6. plugin dir 플래그로 폴더를 지정해 Claude Code를 시작하거나, 데스크톱 앱은 글로벌 설정 파일에 폴더를 추가합니다.
  • 함수는 $send 객체, 이벤트, next 세 값을 받습니다. next에 넘긴 값이 실제로 수행되고, 호출하지 않고 반환하면 내가 이벤트를 처리합니다.
  • 폴더를 감시하므로 파일을 저장하면 현재 세션에 바로 반영됩니다.
  • 렌더 변경은 화면만 바꾸므로 모델은 실제 이메일 주소를 그대로 씁니다.
  • 모드는 자체 샌드박스에서 실행되며 Claude Code가 노출한 이벤트만 볼 수 있습니다.

8. 클라우드 세션으로 외출 중 작업하기

클라우드 세션은 내 컴퓨터가 아닌 클라우드 가상 머신에서 도는 Claude Code 작업입니다. GitHub 저장소를 복제해 별도 브랜치에서 일하므로 노트북을 닫아도 계속 진행되고, 휴대폰으로 답하거나 방향을 바꿀 수 있어 퇴근 전 맡겨 두는 큰 작업에 알맞습니다.

  1. GitHub 계정을 연결하고 GitHub에서 접근을 승인합니다.
  2. Claude GitHub App을 설치하고 접근을 허용할 저장소를 고릅니다.
  3. 데스크톱 앱에서 Local 대신 Cloud를 선택합니다.
  4. 저장소, 환경, 시작할 브랜치를 고릅니다.
  5. Claude에게 작업을 맡기고 노트북을 닫습니다.
  6. 휴대폰 Claude 앱의 Code 탭에서 질문에 답하거나 방향을 조정합니다.
  7. 변경 내용(diff)을 검토하고 필요하면 코멘트를 남깁니다.
  8. 문제가 없으면 Create PR을 눌러 GitHub에 풀 리퀘스트를 엽니다.
  • 세션은 저장소를 새로 복제해 시작하므로 커밋·푸시한 내용만 씁니다. 개인 설정·스킬·플러그인이 필요한 작업은 로컬에서 하세요.
  • 비공개 저장소는 Claude GitHub App이 접근할 수 있어야 목록에 나타납니다.
  • Remote Control은 내 컴퓨터에서 도는 세션에 붙는 방식이라 컴퓨터가 켜져 있어야 합니다. 클라우드 세션은 꺼져 있어도 됩니다.
  • 내 컴퓨터에서 같은 저장소로 여러 세션을 동시에 돌릴 때는 worktree로 작업 폴더를 나눠 씁니다(DoorDash·Spotify 사례).

9. 클라우드 세션 환경 맞춤 설정하기

클라우드 세션의 기본 환경에는 주요 언어 런타임, 빌드 도구, 데이터베이스가 미리 설치되어 있습니다. 프로젝트에 더 필요한 도구나 설정이 있으면 사용자 지정 환경을 만들어 매번 같은 조건에서 작업하게 합니다.

  1. 기본 환경에 필요한 런타임·빌드 도구·데이터베이스가 있는지 확인합니다.
  2. 부족하면 사용자 지정 환경을 만듭니다.
  3. 네트워크 접근 범위를 설정합니다.
  4. 필요한 환경 변수를 추가합니다.
  5. 저장소에 필요한 것을 설치하는 설정 스크립트를 작성합니다.
  • Team·Enterprise 플랜은 조직의 자체 인프라에서 클라우드 세션을 실행할 수 있습니다.
  • 에이전트는 실행 때마다 환경을 처음부터 시작하므로 시작·대기·상태 확인용 도구를 갖춰 두면 좋습니다.
  • 비용은 플랜 한도에 로컬 세션과 합산되며 가상 머신 비용은 따로 없습니다.

10. Projects로 큰 작업 병렬 처리하기

Claude Code Projects는 Claude가 작업을 조율하는 하나의 지속적인 대화입니다. 작업마다 클라우드의 별도 브랜치에서 도는 스레드를 만들어 병렬로 처리하므로, 여러 세션이나 저장소에 걸친 큰 목표에 알맞습니다. 현재 베타로 Pro·Max에 순차 제공됩니다.

  1. 데스크톱 앱 또는 웹 앱에서 Claude 탭을 엽니다.
  2. 새 프로젝트를 만들고 이름, 달성할 목표, 관련 저장소나 폴더를 입력합니다.
  3. 열린 메인 대화에서 코드베이스 탐색과 개선안 제안을 요청합니다.
  4. Claude가 찾은 내용을 보고 진행할 작업에 합의합니다.
  5. 작업마다 생긴 스레드 카드를 눌러 진행 상황을 보고, 필요하면 스레드에서 방향을 바꾸거나 중단합니다.
  6. threads 탭에서 내 답을 기다리는 스레드를 확인합니다.
예시
이 코드베이스를 탐색해서 개선할 점을 제안해 줘.
  • 코디네이터는 낮은 노력 수준으로 두고, 스레드는 작은 모델을 기본으로 쓰다 복잡한 작업에서만 바꾸는 것을 권합니다.
  • library 탭에 목업·디자인 명세를 넣어 두면 모든 스레드가 함께 씁니다.
  • 로컬 파일이나 도구가 필요한 작업은 그 스레드를 내 컴퓨터에서 실행해 달라고 요청합니다.
  • 스레드는 메모리를 공유하며 프로젝트 설정에서 편집할 수 있습니다.

11. PR 검토와 매일 도는 루틴 만들기

루틴은 프롬프트·저장소·커넥터·트리거만 정하면 Anthropic 관리형 인프라에서 Claude Code 세션을 자동으로 실행하는 기능입니다. Projects 안에서 스레드가 PR을 돌보게 하고 매일 점검 루틴을 걸어 두면, 사람이 지시하지 않아도 Claude가 먼저 일을 찾아 처리합니다.

  1. 수정이 준비된 스레드가 스스로, 또는 요청 시 풀 리퀘스트를 열게 합니다.
  2. 스레드가 PR을 지켜보며 CI 실패 시 수정을 푸시하고 리뷰 코멘트를 반영하는지 확인합니다.
  3. overview의 pull requests 탭에서 모든 PR과 상태를 봅니다.
  4. 병합할 준비가 되면 Claude에게 병합을 요청합니다.
  5. 모니터링 서비스를 Claude에 연결해 실제 사용자 지표를 보게 합니다.
  6. 매일 성능 저하를 점검하는 루틴을 만들어 달라고 요청합니다.
예시
매일 성능 저하를 점검하는 루틴을 만들어 줘.
  • 루틴을 만들 때는 트리거, 컨텍스트, 조종 방식 세 가지를 정합니다. 트리거는 일정 기반과 GitHub 이벤트·웹훅·API 호출 같은 이벤트 기반이 있습니다.
  • 루틴이 저하를 발견하면 조사 스레드를 열어 프로젝트에서 기다립니다.
  • 매일 피드백을 모아 중요도별로 분류하고 확신이 높은 것만 고치게 하는 식으로도 씁니다.
  • 반복 업무는 루프·루틴에, 단계를 미리 알 수 없는 작업은 동적 워크플로에 맡기는 것이 좋다는 사례가 있습니다.
