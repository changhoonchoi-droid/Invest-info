Claude Code 고급

Claude Code 고급 기능은 한 번 가르쳐 두면 반복해서 쓰는 것(스킬, Hooks), 일을 나누고 모델을 고르는 것(서브에이전트), 내 컴퓨터 밖에서 맡겨 두는 것(클라우드 세션, 루틴, Projects)으로 나뉩니다. 먼저 스킬과 서브에이전트로 기본 틀을 익히고, Hooks와 검증 루프로 품질을 지킨 뒤, 클라우드·루틴·Projects로 병렬·백그라운드 작업을 넓혀 가는 순서를 권합니다.

서브에이전트, 스킬, Hooks, 플러그인, 병렬·백그라운드 작업, 워크트리, 대규모 작업 요령 · 영상 49개 기반 · 2026-11-14 갱신

최근 바뀐 점

  • Claude Fable 5.2 출시와 함께 작업별 모델 선택 기준이 정리됐습니다. 기본은 중간 노력 수준의 Opus 5.5이고, 크고 모호한 장기 작업은 Fable, 범위가 분명한 작업은 Sonnet, 대량 작업은 Haiku입니다.
  • 메인 세션은 Fable이 맡고 세부 작업은 서브에이전트에 Sonnet으로 넘기는 식으로 한 작업을 여러 모델로 나눌 수 있습니다.
  • Claude Code의 모습과 동작을 바꾸는 모드(Mods)가 10월 1일 공식 발표됐고, 데스크톱 앱에서 말로 설명해 만들 수 있습니다.
  • 구조를 늘리기 전에 기본은 루프 하나로 시작하고, 병렬·독립 검증·사람 승인 같은 이유가 있을 때만 그래프로 가라는 비교 실험이 나왔습니다.

1. 스킬 만들어 반복 작업 맡기기

스킬은 작업 방법을 한 번 가르쳐 두면 관련 요청이 올 때 Claude가 자동으로 적용하는 마크다운 파일입니다. 항상 불러오는 CLAUDE.md와 달리 요청이 맞을 때만 내용을 불러와 컨텍스트를 아낍니다. 보고서, PPT, 영상 편집처럼 기준이 정해진 반복 업무에 알맞습니다.

  1. 스킬은 SKILL.md 파일이며, 그 안의 설명(description)을 보고 Claude가 요청과 맞는 스킬을 고른다는 점을 먼저 이해합니다.
  2. 모든 프로젝트에서 쓸 스킬은 홈 디렉터리의 .claude/skills에, 팀과 나눌 스킬은 저장소 루트의 .claude/skills에 둡니다.
  3. 먼저 평소처럼 결과물(예: 샘플 PPT)을 요청해 만족스러울 때까지 고칩니다.
  4. 만족스러우면 같은 일을 대본이나 자료만 넣으면 해 주는 스킬로 만들어 달라고 요청합니다.
  5. 요청에 작업 폴더 생성, 결과물 생성, 기준에 따른 검증 단계를 함께 적습니다.
  6. Claude Code를 껐다가 다시 실행해 스킬을 적용합니다.
  7. 스킬 이름을 직접 불러 호출하거나, 관련 요청을 해서 자동으로 쓰이는지 확인합니다.
  8. 결과가 아쉬우면 추가하고 싶은 규칙이나 레이아웃을 스킬에 계속 더해 갑니다.
예시
지금 만든 샘플 PPT 방식을 스킬로 만들어 줘. 대본과 디자인 시스템 문서를 넣으면 새 작업 폴더를 만들고 PPTX를 생성한 뒤 기준대로 맞는지 검증하는 순서로 해 줘.
  • 스킬은 재시작해야 같은 세션에서 인식됩니다.
  • 실수가 나오면 다시 시키지 말고 CLAUDE.md나 스킬에 적어 같은 실수를 막으세요.
  • 영상 편집처럼 포맷별 템플릿과 업무 매뉴얼(SOP)을 스킬로 저장하면 기준대로 작업이 이뤄집니다. 34초 영상 편집에 약 40분이 걸렸다는 사례가 있습니다.
  • 회사에서 여럿이 쓰는 스킬은 소유자·검토자·폐기·테스트 방식을 먼저 정해 두세요.

2. 서브에이전트로 일 나누고 모델 고르기

서브에이전트는 자체 컨텍스트를 가진 별도의 Claude로, 메인 세션이 맡긴 부분을 처리하고 결과만 보고합니다. 일을 나누면서 부분마다 알맞은 모델을 지정해 속도와 비용을 아낄 수 있습니다. 큰 마이그레이션이나 코드베이스 탐색 같은 작업에 씁니다.

  1. 기본 시작점은 중간 노력 수준의 Opus 5.5입니다. 결과가 부족하면 모델을 바꾸기 전에 노력 수준부터 올립니다.
  2. 크고 모호한 장기 작업이면 메인 세션을 Fable로 시작합니다.
  3. 패키지 업그레이드나 테스트 수정처럼 범위가 분명한 부분을 가려 냅니다.
  4. 메인 세션에 마이그레이션을 이끌면서 그 부분은 Sonnet에게 넘기라고 요청합니다.
  5. 코드베이스를 읽기만 하는 서브에이전트는 커스텀 서브에이전트의 frontmatter에서 모델을 Sonnet으로 지정합니다.
  6. 모든 서브에이전트의 기본 모델을 한 번에 바꾸려면 settings.json에 CLAUDE_CODE_SUBAGENT_MODEL 환경 변수를 설정합니다.
  7. 서브에이전트가 보고한 결과를 메인 세션에서 확인하고 이어서 진행합니다.
예시
Fable로 이 프레임워크 메이저 버전 마이그레이션을 이끌어 줘. 패키지 업그레이드와 테스트 수정처럼 범위가 분명한 부분은 서브에이전트에 Sonnet으로 넘겨서 처리하고 결과만 보고해 줘.
  • 모든 부분에 Fable의 성능이 필요한 것은 아닙니다. Fable은 토큰당 가격이 Opus의 두 배이고, Sonnet은 Opus보다 빠르며 가격이 절반입니다.
  • 탐색만 하는 서브에이전트에는 Opus급 추론이 필요 없고, 읽기 전용이면 Sonnet이나 경우에 따라 Haiku까지 씁니다.
  • Haiku는 요약·분류·라우팅 같은 대량 작업에 맞고, 가용성과 사용 한도는 요금제마다 다릅니다.
  • 모델은 작업의 길이와 복잡도로 고르세요. 단순한 파일 생성에 고성능 모델은 필요하지 않습니다.

3. Hooks로 자동 서식·위험 작업 차단하기

Hooks는 Claude Code가 일하는 특정 시점에 정해 둔 명령을 실행하는 기능입니다. CLAUDE.md의 지시는 가끔 지켜지지 않지만 Hook은 예외 없이 항상 실행됩니다. 편집 후 서식 정리, 위험한 명령 차단, 작업 완료 알림에 씁니다.

  1. .claude/settings.json 또는 /hooks에서 Hook을 설정합니다.
  2. 언제 실행할지 이벤트를 고릅니다. UserPromptSubmit, PreToolUse, PostToolUse, Notification, Stop이 있습니다.
  3. 자동 서식은 이벤트로 PostToolUse를, matcher로 Edit 또는 MultiEdit를 지정합니다.
  4. 실행 명령에서 파일 확장자를 확인해 맞는 포매터를 돌립니다(예: Python은 Ruff, TypeScript는 Prettier).
  5. 위험 작업 차단은 PreToolUse Hook을 만들어 stdin으로 받은 JSON의 도구 이름과 입력을 검사합니다.
  6. 막아야 하면 stderr에 이유를 남기고 종료 코드 2로 끝내고, 허용하면 0으로 끝냅니다.
  7. .claude/settings.json을 저장소에 커밋하면 팀원이 받는 즉시 같은 Hook이 적용됩니다.
예시
`.claude/settings.json`에 PostToolUse Hook을 추가해 줘. matcher는 Edit과 MultiEdit로 하고, 수정한 파일의 확장자를 확인해서 이 프로젝트에서 쓰는 포매터를 자동으로 실행하게 해 줘.
  • 종료 코드 0은 진행, 2는 차단입니다. stderr 메시지는 Claude에게 전달돼 방식을 조정하게 합니다.
  • rm -rf 포함 명령, 운영 설정 폴더 쓰기, main 커밋 차단 같은 규칙에 알맞습니다.
  • 프로젝트 스크립트는 CLAUDE_PROJECT_DIR 환경 변수로 참조하면 작업 디렉터리와 상관없이 동작합니다.
  • CLAUDE.md는 권고, Hooks는 강제입니다. 어길 수 없는 규칙만 Hook으로 만드세요.

4. 검증 루프로 스스로 확인하게 만들기

테스트나 린터만으로는 변경이 의도대로 동작하는지 증명되지 않습니다. 브라우저에서 클릭하고 화면을 보는 수동 확인 절차를 스킬로 만들어 두면 Claude가 직접 실행하고, 실패하면 고쳐서 다시 확인합니다. 확인 기준이 측정 가능할수록 Claude가 혼자 더 멀리 갑니다.

  1. Claude Code에 포함된 verify 스킬을 처음 사용합니다.
  2. Claude가 앱을 실행하고 변경 사항을 앱에서 직접 확인하는 모습을 지켜봅니다.
  3. 성공한 절차가 프로젝트에 스킬로 저장됐는지 확인합니다.
  4. 생성된 스킬에 확인 항목을 더합니다. 예: Chrome DevTools MCP로 레이아웃 시프트를 재는 성능 트레이스.
  5. 스킬에 언제 실행할지, 확인에 실패하면 무엇을 할지, 각 확인의 통과 기준을 적습니다.
  6. UI 변경을 요청해 서버 실행, 페이지 열기, 클릭, 스크린샷, 성능 트레이스를 하고 실패 시 고쳐 다시 확인하는지 봅니다.
예시
방금 성공한 확인 절차를 이 프로젝트의 스킬로 저장해 줘. UI를 바꿀 때마다 서버를 실행하고 페이지를 열어 클릭과 스크린샷으로 확인하고, 실패하면 고친 뒤 다시 확인하게 해 줘.
  • 내가 수동으로 확인하고 고칠 점을 알려 주고 있다면, 기준이 될 만한 것(성능 예산, 접근성 체크리스트, 디자인 시스템 규칙)이 있는지 생각해 보세요.
  • 계획 모드는 파일을 수정하지 않고 읽기만 하므로, 코드가 쓰이기 전에 방향을 고치기 좋습니다.
  • 커밋 전에는 서브에이전트 코드 리뷰어로 점검하고 커밋 메시지를 생성하게 하세요.
  • 예전 방식: 최신 모델 이전에는 계획 모드가 중요했지만, 최근에는 오토 모드를 쓴다는 설명도 있습니다.

5. MCP를 스킬로 바꿔 토큰 아끼기

MCP는 연결하는 순간 도구 정의가 컨텍스트에 상주해 세션 내내 토큰을 차지합니다. 스킬은 시작할 때 메타데이터만 읽고 쓸 때만 내용을 불러와 효율적입니다. 자주 쓰는 MCP 작업은 스킬로 옮길 수 있습니다.

  1. /skill-creator를 실행합니다.
  2. 기존 MCP가 하던 일을 스킬로 만들어 달라고 프롬프트를 입력합니다.
  3. 생성된 스킬들(영상의 n8n 예시는 5개)을 확인합니다.
  4. /mcp에서 해당 MCP를 선택해 Disable로 연결을 끊습니다.
  5. 스킬에서 쓸 API 키를 새로 발급해 입력합니다.
  6. MCP 없이 같은 요청(예: n8n에 간단한 AI 챗봇 만들어 줘)을 해서 동일하게 동작하는지 확인합니다.
예시
n8n MCP가 하던 일을 스킬로 만들어 줘.
  • 스킬은 프롬프트에 따라 자동 실행되거나 슬래시 명령으로 직접 호출할 수 있습니다.
  • n8n의 기본 포트는 5678입니다.
  • MCP를 끊은 뒤 API 키는 .env 같은 별도 파일에 두고 문서에 적지 마세요.

6. 모드로 Claude Code 모습·동작 바꾸기

모드(Mods)는 Claude Code가 무엇을 화면에 그리고 어떤 신호를 어떻게 처리할지 바꾸는 작은 프로그램입니다. 스킬·MCP가 밖에서 지식과 도구를 건네는 방식이라면 모드는 작업 환경 자체를 바꿉니다. 코드를 몰라도 데스크톱 앱에서 말로 설명해 만들 수 있습니다.

  1. Claude Code 데스크톱 앱의 좌측 상단 코드 탭으로 들어갑니다.
  2. 로컬 옆 버튼에서 폴더 열기로 프로젝트 폴더를 만들어 엽니다.
  3. 만들고 싶은 모드를 말로 설명해 요청합니다.
  4. 핫 리로딩 안내가 나오면 Enable for this session을 누릅니다.
  5. 잘 보이는지 확인해 달라고 요청해 결과를 확인합니다.
  6. 모든 세션에서 쓰려면 방금 만든 모드를 플러그인으로 설치해 달라고 요청합니다.
  7. 다른 세션이나 프로젝트를 열어 모드가 적용되는지 확인합니다.
예시
토큰 사용량을 아이콘과 함께 보여 주는 모드를 만들어 줘.
  • 모드를 만드는 전용 스킬이 이미 들어 있어 코드를 몰라도 말로 설명하면 됩니다.
  • 6번 단계를 하지 않으면 모드는 만든 대화 안에서만 작동합니다.
  • 다음 작업 추천 모드는 턴이 끝날 때마다 카드로 할 일 세 가지를 띄우고, 클릭하면 바로 실행되게 요청한 예시가 있습니다.

7. 클라우드 세션으로 외출 중에도 작업하기

클라우드 세션은 내 컴퓨터가 아니라 클라우드의 가상 머신에서 도는 Claude Code 작업입니다. GitHub 저장소를 복제해 별도 브랜치에서 일하므로 노트북을 닫아도 계속되고, 휴대폰으로 질문에 답할 수 있습니다. 큰 리팩터링이나 퇴근 전에 맡겨 두는 작업에 알맞습니다.

  1. GitHub 계정을 연결하고 GitHub에서 접근을 승인합니다.
  2. Claude GitHub App을 설치하고 접근을 허용할 저장소를 고릅니다.
  3. 데스크톱 앱에서 Local 대신 Cloud를 선택합니다.
  4. 저장소, 환경, 시작할 브랜치를 고릅니다.
  5. Claude에게 작업을 맡기고 노트북을 닫습니다.
  6. 휴대폰 Claude 앱의 Code 탭에서 질문에 답하거나 방향을 조정합니다.
  7. 변경 내용(diff)을 검토합니다. 남긴 코멘트는 다음 메시지와 함께 Claude에게 전달됩니다.
  8. 문제가 없으면 Create PR을 눌러 GitHub에서 풀 리퀘스트를 엽니다.
  • Pro, Max, Team 플랜과 일부 Enterprise 좌석에서 쓸 수 있고, 사용 한도는 로컬 세션과 합산됩니다.
  • 세션은 저장소를 새로 복제해 시작하므로 커밋·푸시한 내용만 쓸 수 있습니다. 개인 설정, 스킬, 플러그인이 필요한 작업은 로컬에서 실행하세요.
  • Remote Control은 내 컴퓨터에서 도는 세션에 연결하는 방식이라 컴퓨터가 켜져 있어야 합니다.
  • 필요한 런타임이 더 있으면 사용자 지정 환경을 만들고 네트워크 범위, 환경 변수, 설정 스크립트를 추가합니다.

8. 루틴으로 정기 작업 자동화하기

루틴은 프롬프트, 저장소, 커넥터, 트리거만 정하면 Anthropic 관리형 인프라에서 원격 Claude Code 세션을 자동 실행하는 기능입니다. 노트북이 꺼져 있어도 돌아가고, 모든 루틴은 웹·CLI·데스크톱에서 열어 이어서 쓸 수 있는 세션입니다. 문서 갱신, 피드백 분류, PR 돌보기 같은 반복 업무에 씁니다.

  1. 트리거를 정합니다. 일정 기반이나, GitHub 이벤트·웹훅·API 호출 같은 이벤트 기반 중에서 고릅니다.
  2. 루틴이 알아야 할 컨텍스트로 연결할 저장소와 커넥터를 정합니다.
  3. 무엇을 어떻게 할지 프롬프트에 적습니다.
  4. 루틴이 어떻게 조종될지(결과를 PR로 올릴지, 사람이 확인할지)를 정합니다.
  5. 루틴을 만들고 첫 실행 결과를 세션으로 열어 확인합니다.
  6. 결과가 어긋나면 그 세션에서 지시를 보태고 프롬프트를 고칩니다.
예시
매주 병합된 변경을 문서 저장소와 비교해서, 바뀐 내용에 맞게 문서를 고치는 PR을 만들어 줘.
  • 루틴을 만들 때는 트리거, 컨텍스트, 조종 방식 세 가지를 정하세요.
  • 매일 피드백을 모아 중요도별로 분류하고 확신이 높은 것만 고치게 하는 식으로도 쓸 수 있습니다.
  • 루틴은 버그 리포트에 자동으로 수정안을 올리는 용도로도 쓰입니다.

9. Projects로 여러 작업 병렬로 맡기기

Project는 Claude가 작업을 조율하는 하나의 지속적인 대화입니다. 작업마다 클라우드의 별도 브랜치에서 도는 스레드를 만들어 병렬로 처리하고, 노트북을 닫아도 휴대폰으로 확인할 수 있습니다. 여러 세션이나 저장소에 걸친 큰 목표에 알맞으며, 현재 베타로 Pro와 Max 요금제에 순차 제공됩니다.

  1. 데스크톱 앱 또는 웹 앱에서 Claude 탭을 엽니다.
  2. 새 프로젝트를 만들고 이름, 달성할 목표, 관련 저장소나 폴더를 입력합니다.
  3. 열리는 메인 대화에서 코드베이스 탐색과 개선안 제안을 요청합니다.
  4. Claude가 찾은 내용을 보고 진행할 작업에 합의합니다.
  5. Claude가 작업마다 만든 스레드 카드를 눌러 진행 상황을 확인하고, 필요하면 말을 걸어 방향을 바꾸거나 중단합니다.
  6. threads 탭에서 사용자를 기다리는 스레드를 확인합니다.
  7. overview의 pull requests 탭에서 PR과 상태를 보고, 병합할 준비가 되면 Claude에게 병합을 요청합니다.
  8. 모니터링 서비스를 연결하고 매일 성능 저하를 점검하는 루틴을 만들어 달라고 요청합니다.
  • 로컬 파일이나 도구가 필요한 작업은 해당 스레드를 내 컴퓨터에서 실행하도록 요청하세요.
  • 코디네이터는 낮은 노력 수준으로 두고, 스레드는 작은 모델을 기본으로 쓰다가 복잡한 작업에서만 바꾸기를 권장합니다.
  • PR을 연 스레드는 CI 실패 시 수정을 푸시하고 리뷰 코멘트를 반영합니다.
  • 같은 저장소에서 로컬 병렬 세션을 돌릴 때는 worktree를 쓴다는 사례가 있습니다.

10. 루프 설계로 AI가 알아서 돌게 하기

루프 엔지니어링은 내가 계속 시키지 않아도 AI가 반복해서 일하도록 바깥 순환(아우터 루프)을 설계하는 방법입니다. AI는 대화가 끝나면 잊어버리므로 진행 상황을 적는 상태 파일과, 언제 끝났는지 판정하는 종료 조건이 핵심입니다. 구조를 늘리기 전에 기본은 루프 하나로 시작하세요.

  1. 반복할 일을 정하고, 무엇이 완료인지 누가 봐도 참/거짓으로 판정할 수 있게 적습니다.
  2. 결과를 코드로 검사하는 검사기(테스트 등)부터 만듭니다.
  3. 진행 상황을 기록할 상태 파일을 두어 다음 회차가 이어받게 합니다.
  4. 종료 조건을 겹쳐 겁니다. 검증 통과, 최대 반복 횟수, 시간·비용 한도, 진전 없음 중단입니다.
  5. 만드는 AI와 검사하는 AI를 분리해 자기 결과에 관대해지는 문제를 줄입니다.
  6. 먼저 루프 하나로 돌려 보고, 병렬 후 취합, 독립 검증, 단계별 다른 권한, 사람 승인, 장시간 작업의 저장·재개가 필요할 때만 그래프로 넓힙니다.
예시
이 작업을 루프로 돌려 줘. 테스트가 모두 통과하면 끝, 최대 5회 반복, 진전이 없으면 중단하고, 매 회차마다 진행 상황을 상태 파일에 적어 줘.
  • 작은 실험에서 코드 검사 루프는 8.3초·16,688토큰이었고 그래프는 53.3초·73,692토큰이 들었습니다. 한 사례일 뿐이라 일반화는 조심하세요.
  • 멀티에이전트 리서치는 단일 에이전트보다 90.2% 높았지만 토큰은 채팅의 약 15배를 썼습니다.
  • 반복 업무(PR 관리, 코드 리뷰)는 루프·루틴으로, 단계를 미리 알 수 없는 작업은 동적 워크플로로 맡긴다는 구분도 있습니다.
