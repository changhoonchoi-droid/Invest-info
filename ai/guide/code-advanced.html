Claude Code 고급

Claude Code 고급 기능을 쓰면 일을 하나씩 시키던 방식에서 벗어날 수 있습니다. 검증 절차를 스킬로 남기고, 서브에이전트와 클라우드 세션으로 여러 작업을 동시에 맡기고, 모드로 작업 화면까지 바꿀 수 있습니다. 서브에이전트 모델 설정과 verify 스킬로 기초를 다지고, 클라우드 세션·Projects·루틴으로 병렬·백그라운드 작업을 익힌 뒤, 마지막에 모드와 플러그인을 다루는 순서를 권합니다.

서브에이전트, 스킬, Hooks, 플러그인, 병렬·백그라운드 작업, 워크트리, 대규모 작업 요령 · 영상 28개 기반 · 2026-10-27 갱신

최근 바뀐 점

  • 모드(Mods)가 10월 1일 공식 발표되었습니다. Claude Code의 화면, 프롬프트, 도구 호출을 바꾸는 플러그인 형태의 작은 프로그램입니다.
  • 데스크톱 앱에 모드를 만드는 전용 스킬이 들어 있어, 코드를 몰라도 원하는 모드를 말로 설명하면 만들 수 있습니다.
  • 클라우드 세션이 공개되었습니다. 노트북을 닫아도 클라우드 가상 머신에서 작업이 계속되며, 휴대폰이나 Slack에서도 시작하고 지시할 수 있습니다.
  • Claude Code Projects가 베타로 나왔습니다. 하나의 대화가 여러 스레드를 클라우드에서 병렬로 조율하며, Pro·Max 요금제에 순차적으로 제공됩니다.

1. 서브에이전트를 작은 모델로 돌리기

서브에이전트는 메인 Claude가 일부 작업을 맡기는 보조 에이전트입니다. 코드베이스를 읽기만 하는 탐색용 서브에이전트에는 Opus급 추론이 필요 없으므로, 작은 모델로 돌리면 비용과 사용 한도를 아낄 수 있습니다.

  1. 코드베이스를 읽기만 하는 서브에이전트가 무엇인지 정합니다.
  2. 커스텀 서브에이전트 파일의 frontmatter에서 모델을 Sonnet으로 지정합니다.
  3. 모든 서브에이전트의 기본 모델을 한 번에 바꾸려면 settings.json에 CLAUDE_CODE_SUBAGENT_MODEL 환경 변수를 설정합니다.
  4. 커밋 전에는 코드 리뷰어 역할의 서브에이전트에게 변경 내용을 점검하게 합니다.
  • 읽기 전용 서브에이전트는 Sonnet으로 충분하고, 경우에 따라 Haiku까지 쓸 수 있습니다.
  • 메인 모델 Opus 5.5의 기본 effort는 medium입니다. 여러 파일에 걸친 수정에는 high로 올립니다.
  • 서브에이전트를 너무 많이 만들면 메인 에이전트와 소통이 어긋날 수 있습니다. 단순한 구성에서 시작하고, 필요한 정보는 스킬로 단계적으로 불러오게 합니다.

2. verify 스킬로 검증 루프 만들기

Claude가 테스트만 통과시키는 데서 그치지 않고, 앱을 실제로 실행해 클릭하고 화면을 보며 변경이 의도대로 동작하는지 확인하게 만드는 방법입니다. 한 번 성공한 확인 절차를 프로젝트 스킬로 저장해 두면, Claude가 고치고 다시 확인하는 일을 스스로 반복합니다.

  1. Claude Code에 기본으로 들어 있는 verify 스킬을 처음 사용합니다.
  2. Claude가 앱을 실행하고 변경 사항을 앱에서 직접 확인하는 과정을 지켜봅니다.
  3. 성공한 절차가 프로젝트에 스킬로 저장되었는지 확인합니다.
  4. 저장된 스킬에 확인 항목을 더합니다. 예: Chrome DevTools MCP로 레이아웃 시프트를 재는 성능 트레이스.
  5. 스킬에 언제 실행할지, 확인에 실패하면 무엇을 할지, 항목마다 통과 기준을 적습니다.
  6. UI 변경을 요청한 뒤, Claude가 서버 실행·페이지 열기·클릭·스크린샷·성능 측정을 하고 실패하면 고쳐서 다시 확인하는지 봅니다.
예시
이 UI 변경을 마친 뒤 verify 스킬로 앱을 직접 실행해서 의도대로 동작하는지 확인해 줘.
  • 통과 기준을 측정 가능하게 적을수록 Claude가 혼자 더 멀리 갑니다. 성능 예산, 접근성 체크리스트, 디자인 시스템 규칙을 기준으로 삼아 보세요.
  • Claude가 같은 실수를 하면 다시 시키기보다 CLAUDE.md나 스킬에 적어 두어 재발을 막습니다.
  • 웹은 브라우저, 백엔드는 엔드포인트 호출, 모바일은 iOS 시뮬레이터로 확인 절차를 만들 수 있습니다.
  • 예전 방식: 코딩 전에 계획 모드로 계획부터 세웠습니다. 최신 모델에서는 계획 모드 대신 오토 모드에 맡기고, 검증에 집중하는 쪽을 권합니다.

3. 클라우드 세션으로 작업 맡기기

클라우드 세션은 내 컴퓨터가 아니라 클라우드의 가상 머신에서 Claude Code를 돌리는 방식입니다. GitHub 저장소를 복제해 별도 브랜치에서 작업하므로 노트북을 닫아도 일이 계속됩니다. 큰 수정 작업이나 퇴근 전에 맡겨 두는 일에 알맞습니다.

  1. GitHub 계정을 연결하고 GitHub에서 접근을 승인합니다.
  2. Claude GitHub App을 설치하고 접근을 허용할 저장소를 고릅니다.
  3. 데스크톱 앱에서 Local 대신 Cloud를 선택합니다.
  4. 저장소, 환경, 시작할 브랜치를 고릅니다.
  5. Claude에게 작업을 맡기고 노트북을 닫습니다.
  6. 휴대폰 Claude 앱의 Code 탭에서 Claude의 질문에 답하거나 방향을 바꿉니다.
  7. 변경 내용(diff)을 검토합니다. 남긴 코멘트는 다음 메시지와 함께 Claude에게 전달됩니다.
  8. 문제가 없으면 Create PR을 눌러 GitHub에 풀 리퀘스트를 엽니다.
  • 세션은 저장소를 새로 복제해 시작하므로 커밋·푸시한 내용만 쓸 수 있습니다. 개인 설정, 스킬, 플러그인이 필요한 작업은 로컬에서 돌립니다.
  • 비공개 저장소는 Claude GitHub App에 접근 권한을 줘야 목록에 나타납니다.
  • Pro·Max·Team 플랜에서 쓸 수 있고, 로컬 세션과 같은 한도를 씁니다. 가상 머신 비용은 따로 없습니다.
  • Remote Control은 내 컴퓨터에서 돌고 있는 세션에 연결하는 방식이라 컴퓨터가 켜져 있어야 합니다. 터미널에서 teleport 플래그를 붙여 claude를 실행하면 클라우드 세션을 내 컴퓨터로 가져와 이어 갈 수 있습니다.

4. 클라우드 세션 환경 맞춤 설정하기

클라우드 세션의 가상 머신에 필요한 도구, 네트워크 권한, 환경 변수를 미리 준비해 두는 방법입니다. 기본 환경으로 부족한 저장소에서 쓰면 됩니다.

  1. 기본 환경에 주요 언어 런타임, 빌드 도구, 데이터베이스가 이미 설치되어 있는지 확인합니다.
  2. 더 필요한 것이 있으면 사용자 지정 환경을 만듭니다.
  3. 네트워크 접근 범위를 설정합니다.
  4. 필요한 환경 변수를 추가합니다.
  5. 저장소에 필요한 것을 설치하는 설정 스크립트를 작성합니다.
  • Team·Enterprise 플랜은 조직의 자체 인프라에서 클라우드 세션을 실행할 수 있습니다.

5. Projects로 여러 작업 병렬 처리하기

Project는 Claude가 여러 작업을 조율하는 하나의 지속적인 대화입니다. 작업마다 클라우드의 별도 브랜치에서 도는 스레드를 만들어 병렬로 처리하므로, 여러 세션이나 저장소에 걸친 큰 목표에 알맞습니다.

  1. 데스크톱 앱이나 웹 앱에서 Claude 탭을 엽니다.
  2. 새 프로젝트를 만들고 이름, Claude가 달성할 목표, 관련 저장소나 폴더를 입력합니다.
  3. 메인 대화가 열리면 코드베이스를 살펴보고 개선안을 제안해 달라고 요청합니다.
  4. Claude가 찾은 내용을 보고 진행할 작업을 합의합니다.
  5. Claude가 작업마다 만든 스레드 카드를 눌러 진행 상황을 보고, 필요하면 그 스레드에서 방향을 바꾸거나 중단합니다.
  6. threads 탭에서 내 답을 기다리는 스레드를 확인합니다.
예시
이 코드베이스를 살펴보고 개선할 점을 제안해 줘.
  • 코디네이터(메인 대화)는 낮은 노력 수준으로 두고, 스레드는 작은 모델로 돌리다가 복잡한 작업에서만 바꾸기를 권합니다.
  • library 탭은 모든 스레드가 함께 쓰는 폴더입니다. 목업이나 디자인 명세를 여기에 넣어 둡니다.
  • 로컬 파일이나 도구가 필요한 작업은 해당 스레드를 내 컴퓨터에서 실행하도록 요청합니다.
  • 한 저장소에서 로컬 세션을 여러 개 동시에 돌릴 때는 세션마다 worktree를 따로 쓰는 방식이 쓰입니다.

6. PR 관리와 매일 점검 루틴 만들기

Claude가 만든 수정 사항을 풀 리퀘스트로 올리고 CI 실패와 리뷰 코멘트까지 챙기게 하는 방법입니다. 매일 자동으로 도는 루틴을 만들면, 사람이 지시하지 않아도 Claude가 먼저 문제를 찾아 조사를 시작합니다.

  1. 수정이 준비된 스레드가 스스로, 또는 요청을 받아 풀 리퀘스트를 열게 합니다.
  2. 스레드가 PR을 지켜보며 CI가 실패하면 수정을 푸시하고 리뷰 코멘트를 반영하는지 확인합니다.
  3. overview의 pull requests 탭에서 모든 PR과 상태를 봅니다.
  4. 병합할 준비가 되면 Claude에게 병합을 요청합니다.
  5. 모니터링 서비스를 Claude에 연결해 실제 사용자 지표를 직접 보게 합니다.
  6. 매일 성능 저하를 점검하는 루틴을 만들어 달라고 요청합니다.
예시
매일 성능 저하를 점검하는 루틴을 만들어 줘.
  • 루틴이 성능 저하를 발견하면 조사 스레드를 열어 두고 프로젝트에서 기다립니다.
  • 루틴은 일정(시간)이나 GitHub 이벤트·웹훅·API 호출로 시작할 수 있고, Anthropic 관리형 인프라에서 돌아 노트북이 꺼져 있어도 동작합니다.
  • 루틴을 만들 때는 트리거(언제 시작할지), 컨텍스트(무엇을 볼지), 조종 방식(어떻게 지시할지) 세 가지를 정합니다.
  • 반복 업무(PR 관리, 코드 리뷰)는 루틴·루프에 맡기고, 단계를 미리 알 수 없는 작업은 동적 워크플로에 맡기는 식으로 나눕니다.

7. 말로 설명해 모드 만들고 설치하기

모드는 Claude Code의 화면과 행동 방식을 바꾸는 작은 프로그램입니다. Claude가 작업할 때마다 나오는 신호를 듣고, 지켜보거나 살짝 고치거나 대신 처리합니다. 데스크톱 앱에 모드를 만드는 전용 스킬이 들어 있어서, 원하는 모드를 말로 설명하기만 하면 됩니다.

  1. Claude Code 데스크톱 앱의 왼쪽 위 코드 탭으로 들어갑니다.
  2. 로컬 옆 버튼에서 폴더 열기를 눌러 프로젝트 폴더를 만들어 엽니다.
  3. 만들고 싶은 모드를 말로 설명해 요청합니다.
  4. 핫 리로딩 안내가 나오면 Enable for this session을 누릅니다.
  5. 잘 보이는지 확인해 달라고 요청해 결과를 봅니다.
  6. 같은 대화에서 방금 만든 모드를 모든 세션에서 쓸 수 있도록 플러그인으로 설치해 달라고 요청합니다.
  7. 다른 세션이나 프로젝트를 열어 모드가 적용되는지 확인합니다.
예시
토큰 사용량을 아이콘과 함께 보여 주는 모드를 만들어 줘.
  • 플러그인으로 설치하지 않으면 모드는 만든 대화 안에서만 작동합니다.
  • 턴이 끝날 때마다 다음 할 일 세 가지를 카드로 띄우고, 누르면 바로 실행되는 모드도 만들 수 있습니다.
  • 스킬·MCP가 밖에서 지식과 도구를 건네준다면, 모드는 작업 환경 자체를 바꿉니다. 창·버튼 같은 화면 요소는 모드로만 만들 수 있습니다.

8. 코드로 모드 직접 만들기

모드는 플러그인이며, Claude Code 내부 이벤트에 TypeScript 함수를 등록해 이벤트가 생길 때마다 실행되게 만듭니다. 화면에 그리는 내용, 프롬프트, 도구 호출을 세밀하게 바꾸고 싶을 때 씁니다. 예로, 답변 속 이메일 주소를 마우스를 올릴 때만 보이게 하는 모드를 만듭니다.

  1. 플러그인의 hook.json에 modules 키를 추가하고 TypeScript 파일을 가리키게 합니다.
  2. 그 파일에서 렌더 이벤트(render)에 함수를 등록합니다.
  3. 이벤트 데이터로 들어오는 답변 텍스트에서 이메일 주소를 찾습니다.
  4. 주소마다 $send 객체로 마우스를 올릴 때만 텍스트가 보이는 블록을 만듭니다.
  5. next를 호출하지 않고 그 결과를 직접 반환해, Claude Code가 내 버전을 그리게 합니다.
  6. plugin dir 플래그로 이 폴더를 지정해 Claude Code를 시작합니다. 데스크톱 앱은 글로벌 설정 파일에 폴더를 추가합니다.
  • 함수는 $send 객체, 이벤트, next 세 값을 받습니다. next에 넘긴 값이 Claude Code가 실제로 하는 일이 되고, 호출하지 않고 반환하면 내가 이벤트를 직접 처리합니다.
  • 폴더를 감시하므로 파일을 저장하면 현재 세션에 바로 반영됩니다.
  • 렌더 변경은 화면만 바꿉니다. 모델은 실제 이메일 주소를 그대로 씁니다.
  • 모드는 자체 샌드박스에서 돌고 Claude Code가 노출한 이벤트만 볼 수 있습니다. 플러그인이므로 마켓플레이스 저장소에 올려 공유할 수 있습니다.
