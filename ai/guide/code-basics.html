Claude Code 기본

Claude Code는 내 컴퓨터의 파일을 직접 읽고 고치고 명령을 실행해 일을 대신 처리하는 AI 도구입니다. 터미널, VS Code·JetBrains, 데스크톱 앱, 웹, 휴대폰에서 쓸 수 있습니다. 처음이라면 '설치 → 권한 모드 → 계획 모드 → CLAUDE.md → 컨텍스트 관리' 순서로 익히세요. 그다음 원격 제어, 클라우드 세션, MCP, 자동 모드로 넓혀 가면 됩니다.

설치, 첫 실행, CLAUDE.md, 권한, 슬래시 명령, IDE·데스크톱·웹·모바일에서 쓰기 · 영상 17개 기반 · 2026-10-31 갱신

최근 바뀐 점

  • 10월 1일 Anthropic이 '모드(Mods)'를 공식 발표했습니다. 모드는 Claude Code의 모습과 행동 방식을 바꾸는 작은 프로그램이며, 9월에 일부 개발자에게 먼저 공개되었습니다.
  • 모드는 Claude가 작업할 때 보내는 신호를 듣고 지켜보거나, 살짝 고치거나, 대신 처리합니다. 창·버튼 같은 화면 요소는 모드로만 만들 수 있다고 소개되었습니다.
  • 클라우드 세션은 GitHub 저장소를 클라우드 가상 머신에서 작업합니다. 노트북을 닫아도 작업이 계속되고, 휴대폰이나 Slack에서도 시작할 수 있습니다.
  • Claude 디자인을 쓰면 코드를 짜기 전에 화면 시안부터 만들어 볼 수 있습니다. 댓글 피드백, 클릭형 프로토타입을 거쳐 구현까지 이어집니다.

1. 터미널에 Claude Code 설치하기

Claude Code를 내 컴퓨터의 터미널에 설치하고 처음 실행해 로그인하는 과정입니다. 새 기능이 터미널에 가장 먼저 나오므로, 기본 설치 방법으로 먼저 익혀 두면 좋습니다.

  1. macOS·Linux·WSL에서는 공식 안내에 있는 curl 설치 명령을 그대로 복사해 한 번에 실행합니다.
  2. Homebrew를 쓰는 맥이라면 brew install로 설치해도 됩니다.
  3. Windows PowerShell에서는 공식 안내의 Invoke-RestMethod 설치 명령을 실행합니다.
  4. Windows CMD에서는 공식 안내의 curl 설치 명령을 실행합니다.
  5. 작업할 프로젝트 폴더로 이동한 뒤 Claude Code를 실행합니다.
  6. 처음 실행하면 색상 테마를 고릅니다.
  7. Claude 계정(Pro, Max, Enterprise) 또는 API 키로 로그인합니다.
예시
claude
  • Homebrew나 winget으로 설치하면 자동 업데이트가 되지 않습니다.
  • 회사에 Enterprise 계정이 있으면 로그인할 때 그 옵션을 고릅니다.
  • Claude Code를 실행한 폴더와 그 하위 폴더 전체에 접근 권한이 생기므로, 꼭 작업할 폴더에서 실행합니다.

2. VS Code·JetBrains에서 쓰기

평소 쓰는 코드 편집기(IDE) 안에서 Claude Code를 여는 방법입니다. 터미널이 낯설다면 익숙한 편집기 화면에서 바로 시작할 수 있습니다.

  1. VS Code의 확장 패널을 열고 Claude Code를 검색합니다.
  2. Anthropic이 만든, 파란 체크 표시가 있는 확장인지 확인하고 설치합니다.
  3. 필요하면 VS Code를 다시 시작합니다.
  4. Ctrl/Cmd + Shift + P로 명령 팔레트를 열고 Claude Code를 검색해 새 탭을 엽니다.
  5. JetBrains를 쓴다면 JetBrains Marketplace에서 Claude Code 플러그인을 설치합니다.
  6. JetBrains IDE를 다시 시작한 뒤, 화면에 보이는 Claude 로고를 눌러 창을 엽니다.
  • VS Code에서는 파일을 열었을 때 보이는 Claude 로고를 눌러도 열 수 있습니다.
  • VS Code 설정 파일에서 화면(UI) 방식 대신 터미널 방식으로 쓰도록 바꿀 수 있습니다.

3. 권한 모드 전환하기

Claude가 파일을 고치거나 명령을 실행하기 전에 얼마나 자주 허락을 받을지 정하는 기능입니다. 기본 모드는 매번 묻습니다. 작업에 따라 자동 수락 모드나 계획 모드로 바꿔 쓸 수 있습니다.

  1. Claude Code를 실행한 상태에서 Shift + Tab을 누릅니다.
  2. 기본 모드: 파일 수정과 셸 명령 전에 매번 허락을 묻습니다. 모든 단계를 직접 확인하고 싶을 때 씁니다.
  3. 한 번 더 누르면 Auto accept edits 모드가 됩니다. 파일 수정·생성은 자동으로 승인하고, 명령 실행은 계속 허락을 묻습니다.
  4. 한 번 더 누르면 Plan mode가 됩니다. 파일을 고치지 않고 읽기만 하며 작업 계획을 먼저 세웁니다.
  5. 입력창 아래 표시를 보고 지금 어떤 모드인지 확인한 뒤 요청을 입력합니다.
  • 권한 확인을 건너뛰면 실수를 미리 잡기 어려우니 신중하게 씁니다.
  • Claude가 작업하는 도중에도 내용을 더하거나, 멈추거나, 방향을 바꿀 수 있습니다.

4. 계획 모드로 첫 요청하기

Claude가 코드를 쓰기 전에 먼저 파일을 읽고 조사해 계획을 세우게 하는 방법입니다. 코드가 만들어지기 전인 계획 단계가 방향을 바로잡기 가장 좋은 때라서, 큰 작업은 이렇게 시작하는 것이 좋습니다.

  1. 프로젝트 루트 폴더에서 Claude Code를 엽니다.
  2. Shift + Tab을 여러 번 눌러 입력창 아래에 plan mode가 표시되게 합니다.
  3. 만들고 싶은 것과 알고 싶은 점을 범위·위치·디자인 조건까지 구체적으로 적어 요청합니다.
  4. Claude가 파일을 읽고 웹 검색을 거쳐 내놓은 계획을 검토합니다.
  5. 부족한 부분이 있으면 추가하거나 고쳐 달라고 요청합니다.
  6. 계획이 마음에 들면 승인하고, 파일 수정을 자동으로 받아들일지 매번 물을지 고릅니다.
예시
앱 전체에 다크 모드를 넣어 줘. 헤더에 다크 모드를 켜고 끄는 토글 스위치를 만들고, 다크 테마 색은 기존 라이트 테마와 어울리는 대비 색으로 정해 줘.
  • 프롬프트는 가능한 한 구체적으로 씁니다. 짧게 쓰면 Claude가 코드베이스를 더 많이 뒤지느라 오히려 컨텍스트를 더 씁니다.
  • 계획 모드를 켜지 않고 '코드베이스를 먼저 살펴봐 줘'라고 요청해도 됩니다.

5. CLAUDE.md로 프로젝트 규칙 정하기

CLAUDE.md는 프로젝트 루트에 두는 메모 파일로, Claude Code가 세션을 시작할 때마다 자동으로 읽습니다. 쓰는 기술(스택), 자주 쓰는 명령어, 작성 규칙을 적어 두면 매번 설명하지 않아도 첫 응답부터 결과가 좋아집니다.

  1. 프로젝트 루트 폴더에서 Claude Code를 실행합니다.
  2. /init을 입력해 지금 코드베이스를 바탕으로 CLAUDE.md를 만듭니다.
  3. 만들어진 파일에서 스택, 개발 서버·테스트·린트 명령어, 코드 스타일 규칙을 확인하고 필요한 부분을 고칩니다.
  4. 참고할 문서가 있으면 @ 기호와 파일 경로로 연결합니다.
  5. 작업하다 같은 점을 여러 번 바로잡았다면, 그 규칙을 메모리에 저장하라고 Claude에게 분명히 요청합니다.
  6. 프로젝트용 CLAUDE.md는 버전 관리(git)에 올려 팀과 함께 씁니다.
예시
/init
  • 개인 취향(예: 코드 주석 작성 방식)은 설정 폴더의 사용자 수준 CLAUDE.md에 적습니다. 그러면 모든 프로젝트에 적용됩니다.
  • 처음부터 길게 쓰지 말고 스택 → 개인 선호 → 명령어 순으로 시작해, 계속 바로잡게 되는 내용만 더하면 파일이 간결하게 유지됩니다.
  • 같은 문제가 반복되면 해결 방법을 CLAUDE.md에 저장해 달라고 요청합니다.

6. 컨텍스트 확인하고 정리하기

컨텍스트는 Claude의 작업 기억입니다. 읽은 파일, 실행한 명령, 주고받은 메시지가 모두 이 공간을 차지합니다. 한도에 가까워지면 자동으로 압축되면서 세부 내용이 사라질 수 있으니, 스스로 확인하고 정리하는 습관이 필요합니다.

  1. /context를 입력해 컨텍스트가 얼마나 찼는지, 무엇이 가장 많이 차지하는지 확인합니다.
  2. 같은 기능 작업을 이어 가야 하면 /compact로 지금까지의 대화를 요약해 공간을 줄입니다.
  3. 새 기능을 시작할 때는 /clear로 대화를 완전히 비웁니다.
  4. 다음 세션에도 기억해야 할 내용은 CLAUDE.md에 적어 둡니다.
  5. 지금 작업과 관계없는 MCP 서버는 꺼 둡니다.
  6. 답만 필요한 조사는 서브에이전트에게 맡겨 별도 컨텍스트에서 처리하고 요약만 받습니다.
예시
/context
  • 압축하면 이전 대화의 세부 내용이 사라질 수 있습니다.
  • 기능이 바뀌면 대화를 비웁니다. 이전 대화가 새 작업에 편향을 주지 않게 하기 위해서입니다.
  • MCP 서버는 기본적으로 모든 도구 정의를 컨텍스트에 올리지만, 스킬은 전체를 올리지 않아 공간을 덜 씁니다.

7. 결과 검증하고 커밋하기

Claude가 만든 결과가 맞는지 스스로 확인하게 하고, 점검을 거쳐 변경 내용을 저장(커밋)하는 흐름입니다. '탐색 → 계획 → 코딩 → 커밋' 가운데 마지막 단계입니다.

  1. 계획에 '무엇이 올바른 결과인지' 성공 기준을 분명히 적습니다.
  2. 웹 화면을 만든다면 Claude in Chrome 확장을 설치해, Claude가 브라우저 탭에서 직접 테스트하게 합니다.
  3. Claude가 계속 검증할 수 있도록 프로젝트에 테스트 스위트를 둡니다. 테스트 작성도 Claude에게 맡길 수 있습니다.
  4. 결과를 직접 확인해 만족하면, 서브에이전트 코드 리뷰어로 코드를 한 번 더 점검합니다.
  5. 내 스타일에 맞는 커밋 메시지를 Claude에게 만들게 한 뒤 푸시합니다.
  • 테스트가 팀의 기준이 되므로, 오탐이 없도록 테스트 내용을 먼저 직접 확인합니다.
  • 같은 문제가 반복되면 해결책을 CLAUDE.md에 저장하도록 요청합니다.

8. 원격 제어로 휴대폰에서 이어가기

내 컴퓨터에서 돌고 있는 Claude Code 세션에 웹이나 휴대폰 앱으로 접속해 이어서 작업하는 기능입니다. 도구, MCP 서버, 파일은 모두 내 컴퓨터에서 그대로 실행되고, 대화는 기기끼리 실시간으로 맞춰집니다.

  1. 터미널에서 프로젝트 폴더로 이동합니다.
  2. claude remote-control을 실행합니다.
  3. 화면에 표시된 URL을 Claude Code 웹에서 엽니다.
  4. 휴대폰으로 접속하려면 스페이스바를 눌러 QR 코드를 띄우고 휴대폰으로 스캔합니다.
  5. 모바일 브라우저나 Claude 모바일 앱에서 진행 중인 세션을 확인하고 이어서 지시합니다.
  6. 이미 실행 중인 세션을 넘기려면 그 세션에서 /remote-control을 입력하고, 표시된 URL로 접속합니다.
  7. 원격에서 새 세션을 만들려면 웹·모바일에서 환경(environment) 버튼을 눌러 내 기기를 고른 뒤 원격 세션을 만듭니다.
예시
claude remote-control
  • 원격 제어는 내 컴퓨터에서 돌아가는 방식이라 컴퓨터가 켜져 있어야 합니다. 컴퓨터를 꺼도 계속 돌아가게 하려면 클라우드 세션을 씁니다.
  • 같은 Claude 계정으로 로그인되어 있으면 링크를 누르지 않아도 앱에서 바로 세션을 찾을 수 있습니다.
  • 모든 세션에 원격 제어를 기본으로 켜려면 /config에서 설정합니다. 기본값은 세션마다 직접 켜는 방식입니다.
  • 2026년 3월 영상 기준으로는 Max, Team, Enterprise 플랜에 먼저 제공되었고 Pro·Max로 순차 확대 중이었습니다.

9. 클라우드 세션으로 작업 맡겨 두기

클라우드 세션은 내 컴퓨터가 아니라 클라우드의 가상 머신에서 GitHub 저장소를 복제해 작업합니다. 노트북을 닫아도 계속 진행되므로 큰 정리 작업이나 퇴근 전에 맡겨 둘 일에 알맞습니다.

  1. Claude 데스크톱 앱이라면 상단의 Code 토글로 전환하고, 브라우저라면 claude.ai/code에 접속합니다.
  2. 작업할 GitHub 저장소를 고릅니다.
  3. 할 일을 구체적으로 요청합니다. Claude는 별도 브랜치에서 작업합니다.
  4. 노트북을 닫고 외출해도 됩니다. Claude가 질문하면 휴대폰에서 답하거나 방향을 바꿔 줍니다.
  5. 필요하면 여러 세션을 동시에 돌려 일을 나눠 맡깁니다.
  6. 작업이 끝나면 변경 내용을 검토하고 PR을 만듭니다.
  • 웹(claude.ai/code)은 GitHub 저장소만 지원합니다.
  • Pro, Max, Team 플랜과 Enterprise(프리미엄 좌석 또는 Chat + Claude Code 좌석)에서 쓸 수 있습니다. 가상 머신 비용은 따로 없고 플랜 한도에 로컬 세션과 함께 합산됩니다.
  • 데스크톱 앱, 브라우저, 터미널, 휴대폰, Slack 어디서든 시작할 수 있습니다.

10. MCP 서버로 외부 도구 연결하기

MCP는 Claude Code를 GitHub, Linear, 문서 서버 같은 외부 도구와 데이터에 연결하는 표준 방식입니다. 연결해 두면 Claude가 그 도구의 정보를 직접 찾아보고 작업에 씁니다.

  1. claude.com/connectors에서 연결할 수 있는 커넥터 목록을 살펴봅니다.
  2. 터미널에서 claude mcp add 명령으로 서버를 추가합니다.
  3. 원격 서버는 HTTP 방식, 내 컴퓨터에서 돌리는 서버는 STDIO 방식으로 추가합니다.
  4. 설정 범위를 로컬·사용자·프로젝트 가운데에서 고릅니다.
  5. 팀과 함께 쓰려면 프로젝트 범위로 설정해 .mcp.json 파일로 공유합니다.
  6. 지금 쓰지 않는 서버는 꺼서 컨텍스트를 아낍니다.
  • MCP 서버는 쓰지 않을 때도 도구 정의가 컨텍스트를 차지합니다.
  • MCP 도구 정의가 컨텍스트 창의 10%를 넘으면 Claude Code가 자동으로 도구 검색 모드로 바뀝니다.
  • Context7 MCP 서버를 연결하면 쓰고 있는 라이브러리의 최신 문서를 받아 볼 수 있습니다.

11. 자동 모드를 우리 환경에 맞추기

자동 모드는 권한 요청마다 일일이 승인하는 피로를 줄이는 기능입니다. 별도의 분류기가 '사용자의 의도에 맞는 행동인지' 판단해 대신 승인합니다. 기본값은 작업 폴더와 git 리모트만 내부로 보므로, 우리 조직의 인프라를 설명해 주는 설정이 필요합니다.

  1. 회사 관리자는 관리형 설정(managed settings)에 환경을 정의합니다. 그러면 모든 개발자가 이 설정을 이어받습니다.
  2. 개발자는 사용자 설정(user settings)에 자기 항목을 더합니다.
  3. environment 필드에 회사 GitHub 조직, 클라우드 버킷, 내부 서비스 등을 평이한 영어로 설명합니다.
  4. environment를 설정하면 기본 항목이 대체되므로, 기본 문자열도 함께 넣어 유지합니다.
  5. 예외로 허용할 동작은 allow에, 명시적으로 요청하지 않으면 막을 동작은 soft deny에, 무조건 막을 동작은 hard deny에 적습니다.
  6. 확실히 막아야 하는 것은 deny 규칙으로, 자동 모드에서도 확인을 받아야 하는 것은 ask 규칙으로 정합니다.
  • 처음에는 좁게 시작하고, 거부되는 항목을 보면서 점차 넓힙니다.
  • 개발자는 관리자가 설정한 항목을 지울 수 없습니다.
  • deny·ask·allow 규칙이 먼저 적용되고, 읽기 전용이거나 되돌릴 수 있는 작업은 분류기를 거치지 않습니다.
  • 운영(프로덕션) 인프라 변경 같은 위험한 작업은 직접 검토합니다.
