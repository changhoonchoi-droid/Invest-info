Claude Code 기본

Claude Code는 터미널, VS Code, JetBrains, 데스크톱 앱, 웹, 휴대폰에서 쓸 수 있는 에이전트형 코딩 도구입니다. 코드를 모르는 직장인도 폴더 하나를 열고 말로 시키면 파일 정리, 문서·대시보드 제작, 반복 업무 자동화까지 맡길 수 있습니다. 설치 → 첫 요청과 권한 모드 → CLAUDE.md → 컨텍스트 관리 → 슬래시 명령 → 원격·클라우드 사용 순으로 따라 하면 자연스럽게 익힐 수 있습니다.

1. Claude Code 설치하고 로그인하기

Claude Code를 내 컴퓨터의 터미널에 설치하고 Claude 계정으로 로그인하는 첫 단계입니다. 새 기능은 터미널에 가장 먼저 나오므로 기능을 빨리 써 보고 싶을 때 알맞습니다.

  1. macOS·Linux·WSL에서는 공식 안내에 나온 curl 설치 명령을 한 번에 실행합니다.
  2. Homebrew를 쓴다면 brew install로 설치해도 됩니다.
  3. Windows PowerShell에서는 안내된 Invoke-RestMethod 명령을, CMD에서는 안내된 curl 명령을 사용합니다.
  4. 작업할 프로젝트 폴더로 이동한 뒤 claude를 실행합니다.
  5. 처음 실행하면 색상 테마를 고릅니다.
  6. Claude 계정(Pro, Max, Enterprise) 또는 API 키 중 하나로 로그인합니다.
  • Homebrew와 winget으로 설치하면 자동 업데이트가 되지 않습니다.
  • 조직에 Enterprise 계정이 있으면 해당 로그인 옵션을 고릅니다.
  • 실행한 폴더와 그 하위 폴더 전체에 접근 권한이 생기니 폴더를 신중히 고르세요.
  • API 키 방식은 과금이 클 수 있어 구독 계정 로그인을 권합니다.

2. VS Code·JetBrains에서 Claude Code 쓰기

평소 쓰는 편집기 안에서 Claude Code를 바로 여는 방법입니다. 파일을 보면서 대화할 수 있어 터미널이 낯선 분께 편합니다.

  1. VS Code에서는 확장 패널을 열고 Claude Code를 검색합니다.
  2. Anthropic이 만든 파란 체크 표시 확장인지 확인하고 설치합니다.
  3. 필요하면 VS Code를 다시 시작합니다.
  4. Ctrl/Cmd + Shift + P로 명령 팔레트를 열고 Claude Code를 검색해 새 탭을 엽니다.
  5. JetBrains에서는 JetBrains Marketplace에서 Claude Code 플러그인을 설치하고 IDE를 다시 시작합니다.
  6. 다시 열면 보이는 Claude 로고를 눌러 터미널 화면 창을 엽니다.
  • VS Code에서 파일을 열었을 때 보이는 Claude 로고를 눌러도 열 수 있습니다.
  • VS Code 설정 파일에서 UI 대신 터미널 방식을 쓰도록 바꿀 수 있습니다.

3. 데스크톱 앱에서 Claude Code 세팅하기

터미널 없이 Claude 데스크톱 앱의 Claude Code 모드로 폴더를 열고 작업을 시키는 방법입니다. 개발 지식이 없는 직장인이 문서·영상·대시보드 작업을 맡길 때 가장 쉽습니다.

  1. Claude 데스크톱 앱에서 Claude Code 모드(상단의 Code 토글, 괄호 모양 탭)를 선택합니다.
  2. 메뉴에서 아래로 내려 나오는 세 가지 설정을 모두 켭니다(리모트 컨트롤 포함).
  3. 로컬 옆 버튼에서 폴더 열기를 눌러 작업할 폴더를 선택합니다.
  4. 폴더(워크스페이스) 신뢰를 허용합니다.
  5. 필요한 파일(예: CSV)을 첨부하고 만들 결과물을 풀어서 요청합니다.
  6. 우측 내장 브라우저에서 결과를 확인하고, 필요하면 기본 브라우저에서 열기로 크롬에서 엽니다.
  7. 고칠 점은 프롬프트로 이어서 요청합니다.
예시
첨부한 설문 결과 CSV로, 팀원 누구나 브라우저로 볼 수 있는 대시보드 웹사이트를 만들어 줘. 응답자 연령대별 만족도 막대그래프와 주요 의견 요약을 넣어 줘.
  • 어떻게 만들지는 AI에게 맡기고 무엇을 만들지에 집중하세요.
  • 사용량이 빨리 닳으면 모델을 한 단계 가벼운 것으로 바꿉니다.
  • 웹(claude.ai/code)은 GitHub 저장소만 지원하므로 내 PC 폴더를 다루려면 데스크톱 앱이나 터미널을 씁니다.

4. 권한 모드와 계획 모드로 안전하게 시키기

Claude Code가 파일을 고치거나 명령을 실행하기 전에 얼마나 허락을 구할지 정하는 기능입니다. 처음에는 기본 모드로 시작하고, 큰 작업은 계획 모드로 먼저 방향을 잡으면 실수를 줄일 수 있습니다.

  1. 프로젝트 루트 폴더에서 Claude Code를 실행합니다.
  2. Shift + Tab을 눌러 모드를 바꿉니다. 기본 모드는 파일 수정·셸 명령 전에 매번 허락을 묻습니다.
  3. Auto accept edits 모드는 파일 수정은 묻지 않고 명령 실행은 계속 묻습니다.
  4. Plan mode로 전환하면 입력창 아래에 plan mode가 표시되고, 파일을 고치지 않고 읽기만 합니다.
  5. 구현하려는 내용과 알고 싶은 점을 구체적으로 요청합니다.
  6. Claude가 내놓은 계획을 검토하고, 부족하면 추가·수정을 요청합니다.
  7. 계획이 좋으면 승인한 뒤 파일 수정을 자동 수락할지 매번 물을지 고릅니다.
예시
앱 전체에 다크 모드를 추가하고 싶어. 헤더에 토글 스위치를 만들고, 기존 라이트 테마와 어울리는 대비 색을 쓰도록 계획을 먼저 세워 줘.
  • 코드가 쓰이기 전인 계획 단계가 방향을 고치기 가장 좋은 시점입니다.
  • 프롬프트는 가능한 한 구체적으로 씁니다.
  • 모든 단계를 직접 확인하고 싶으면 기본 승인 모드를 유지하세요.
  • 권한 무시는 물어보지 않고 전부 실행하므로 작업 폴더 범위를 확인한 뒤에만 켭니다.

5. CLAUDE.md로 프로젝트 규칙 정하기

CLAUDE.md는 프로젝트 폴더에 두는 규칙 파일로, Claude Code가 세션을 시작할 때마다 먼저 읽습니다. 스택, 명령어, 작업 규칙을 적어 두면 매번 같은 설명을 반복하지 않아도 됩니다.

  1. 프로젝트 루트 폴더에서 Claude Code를 실행합니다.
  2. /init 명령을 실행해 코드베이스를 바탕으로 CLAUDE.md를 생성합니다.
  3. 스택, 개발 서버·테스트·린트 명령어, 코드 스타일 규칙을 확인하고 필요한 내용을 고칩니다.
  4. 참고할 문서가 있으면 @ 기호와 파일 경로로 연결합니다.
  5. 작업 중 반복해서 바로잡은 규칙은 Claude에게 메모리에 저장하라고 명시적으로 요청합니다.
  6. 프로젝트용 파일은 버전 관리에 올려 팀과 공유합니다.
예시
방금 바로잡은 규칙, 즉 보고서 숫자는 항상 천 단위 쉼표를 쓴다는 내용을 CLAUDE.md에 저장해 줘.
  • 200줄 이내로 매뉴얼이 아니라 지도처럼 씁니다. 상세 내용은 문서나 스킬로 넘기세요.
  • 개인 취향은 설정 폴더의 사용자 수준 CLAUDE.md에 적으면 모든 프로젝트에 적용됩니다.
  • 처음에는 없이 시작해 계속 바로잡아야 하는 부분만 추가하면 간결하게 유지됩니다.
  • AI가 자동 생성한 설정 파일은 성능을 떨어뜨릴 수 있어 사람이 검수해야 합니다.

6. 컨텍스트 확인하고 정리하기

컨텍스트는 Claude의 작업 기억으로, 읽은 파일·명령·대화가 모두 공간을 차지합니다. 슬래시 명령으로 상태를 보고 정리하면 긴 작업에서도 답변 품질을 지킬 수 있습니다.

  1. /context를 실행해 컨텍스트 크기와 가장 많이 차지하는 항목을 확인합니다.
  2. 같은 기능 작업을 계속해야 하면 /compact로 지금까지 내용을 요약합니다.
  3. 새 기능을 시작할 때는 /clear로 대화를 완전히 비웁니다.
  4. 다음 세션에도 기억시킬 내용은 CLAUDE.md에 적습니다.
  • 압축하면 이전 대화의 세부 내용이 사라질 수 있습니다.
  • 프롬프트를 너무 짧게 쓰면 Claude가 코드베이스를 더 뒤져 오히려 컨텍스트를 더 씁니다.
  • 안 쓰는 MCP 서버는 끄고, 답만 필요한 조사는 서브에이전트에 맡기면 아낄 수 있습니다.

7. 탐색→계획→코딩→커밋 흐름 익히기

Claude Code를 잘 쓰는 기본 작업 순서입니다. 먼저 읽고 계획한 뒤 구현하고, 검증과 리뷰를 거쳐 커밋하면 결과물의 품질이 안정됩니다.

  1. 계획 모드에서 코드베이스를 탐색해 달라고 요청합니다(계획 모드 없이도 가능합니다).
  2. 계획에 무엇이 올바른 결과인지 성공 기준을 분명히 적습니다.
  3. 계획을 승인하고 구현을 진행합니다.
  4. 웹 UI라면 Claude in Chrome 확장을 설치해 Claude가 탭에서 직접 테스트하게 합니다.
  5. 테스트 스위트를 프로젝트에 두어 Claude가 계속 검증하게 합니다.
  6. 직접 확인해 만족하면 서브에이전트 코드 리뷰어로 코드를 점검합니다.
  7. 내 스타일에 맞는 커밋 메시지를 만들게 한 뒤 푸시합니다.
예시
이 변경의 성공 기준은 기존 테스트가 모두 통과하고 로그인 화면에 오류가 없는 거야. 먼저 계획을 세우고, 구현 후 테스트까지 돌려서 결과를 알려 줘.
  • 같은 문제가 반복되면 해결책을 CLAUDE.md에 저장하도록 요청하세요.
  • 테스트가 팀의 기준이 되도록 먼저 확인해 오탐을 막습니다.

8. 곁가지 질문은 /btw로 물어보기

/btw는 데스크톱 앱에서 진행 중인 작업을 방해하지 않고 잠깐 궁금한 것을 묻는 사이드 채팅 기능입니다. 본 대화를 길게 만들지 않고 질문하고 싶을 때 씁니다.

  1. Claude Code 데스크톱 앱에서 대화를 진행합니다.
  2. 입력창에 /btw를 입력해 사이드 채팅을 엽니다.
  3. 지금까지의 대화를 바탕으로 궁금한 것을 묻습니다.
예시
/btw 방금 말한 '컨텍스트'가 정확히 무슨 뜻이야?
  • 사이드 채팅에서 한 질문은 원래 대화에 추가되지 않습니다.

9. 원격 제어로 휴대폰에서 세션 이어가기

내 컴퓨터에서 실행 중인 Claude Code 세션에 웹이나 모바일 앱으로 접속해 이어서 작업하는 기능입니다. 파일과 도구는 모두 내 컴퓨터에서 실행되고 대화만 기기 간에 동기화됩니다.

  1. 프로젝트 디렉터리로 이동합니다.
  2. 터미널에서 claude remote-control을 실행합니다.
  3. 화면에 표시된 URL을 Claude Code 웹에서 엽니다.
  4. 스페이스바를 누르면 나오는 QR 코드를 휴대폰으로 스캔합니다.
  5. 모바일 브라우저 또는 Claude 모바일 앱에서 진행 중인 세션을 확인합니다.
  6. 이미 실행 중인 세션을 넘기려면 그 세션에서 /remote-control을 입력하고 표시된 URL로 접속합니다.
  7. 모든 세션에 기본 적용하려면 /config에서 원격 제어를 켭니다.
  • 같은 Claude 계정으로 로그인되어 있으면 링크 없이 앱에서 바로 세션을 찾을 수 있습니다.
  • 내 컴퓨터가 켜져 있어야 합니다.
  • 데스크톱 앱에서는 Claude Code 모드의 리모트 컨트롤 설정을 켭니다.
  • 영상 기준 Max, Team, Enterprise에 제공되며 Pro와 Max에 순차 확대 중이었으니 내 플랜에서 되는지 확인하세요.

10. 클라우드 세션으로 외출 중에도 작업 맡기기

클라우드 세션은 내 컴퓨터가 아니라 클라우드 가상 머신에서 도는 Claude Code 작업입니다. GitHub 저장소를 복제해 별도 브랜치에서 작업하므로 노트북을 닫아도 계속되고, 퇴근 전에 큰 작업을 맡겨 두기에 알맞습니다.

  1. Pro, Max, Team 플랜 등 사용 가능한 플랜인지 확인합니다.
  2. 데스크톱 앱, 브라우저, 터미널, 휴대폰, Slack 중 편한 곳에서 클라우드 세션을 시작합니다.
  3. 작업할 GitHub 저장소를 연결하고 할 일을 요청합니다.
  4. 세션이 도는 동안 휴대폰에서 Claude의 질문에 답하거나 방향을 바꿉니다.
  5. 작업이 끝나면 변경 내용을 검토하고 PR을 만듭니다.
  • 여러 세션을 동시에 돌릴 수 있어 큰 리팩터링이나 마이그레이션에 알맞습니다.
  • 플랜 한도에 로컬 세션과 함께 합산되며 가상 머신 비용은 따로 없습니다.
  • Remote Control은 내 컴퓨터의 세션에 연결하는 방식이라 컴퓨터가 켜져 있어야 하는 점이 다릅니다.

11. 자동 모드를 우리 환경에 맞게 설정하기

자동 모드는 별도 분류기가 사용자의 메시지와 도구 호출만 보고 의도에 맞는지 판단해 승인 피로를 줄이는 기능입니다. 기본값은 작업 디렉터리와 git 리모트만 내부로 보므로, 조직 환경을 설명해 주는 설정이 필요합니다.

  1. 관리자는 관리형 설정(managed settings)에서 환경을 정의해 모든 개발자가 상속하게 합니다.
  2. 개발자는 사용자 설정(user settings)에 자기 항목을 추가합니다.
  3. environment 필드에 GitHub 조직, 클라우드 버킷, 내부 서비스 등을 평이한 영어로 설명합니다.
  4. environment를 설정하면 기본 항목이 대체되므로 기본 문자열을 함께 넣어 유지합니다.
  5. 예외는 allow, 명시 요청 없이는 막을 동작은 soft deny, 무조건 막을 동작은 hard deny에 씁니다.
  6. 확실한 제한은 deny 규칙으로 막고, 자동 모드에서도 확인을 받으려면 ask 규칙을 씁니다.
  • 처음에는 좁게 시작해 거부되는 항목을 보고 점차 넓힙니다.
  • 개발자는 관리자가 설정한 항목을 제거할 수 없습니다.
  • 프로덕션 인프라 변경 같은 고위험 작업은 직접 검토하세요.
