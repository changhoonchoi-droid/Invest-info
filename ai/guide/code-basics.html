Claude Code 기본

Claude Code는 내 컴퓨터의 파일을 직접 읽고 고치고 명령까지 실행하는 AI 작업 도구입니다. 터미널, VS Code, JetBrains, 데스크톱 앱, 웹, 휴대폰에서 쓸 수 있습니다. 처음이라면 설치 → 권한 모드 → 계획 모드로 첫 요청 → CLAUDE.md 순서로 기본기를 익히세요. 그다음 컨텍스트 관리, 검증·커밋, MCP 연결, 클라우드 세션, 자동 모드 설정으로 넘어가면 됩니다.

최근 바뀐 점

  • Anthropic이 10월 1일 '모드(Mods)'를 공식 발표했습니다. Claude Code의 화면과 행동 방식을 바꾸는 작은 프로그램으로, 작업 신호를 듣고 지켜보거나 고치거나 대신 처리하며, 창·버튼 같은 화면 요소도 모드로 만들 수 있다고 소개되었습니다.
  • 클라우드 세션은 클라우드 가상 머신에서 GitHub 저장소를 복제해 별도 브랜치에서 일합니다. 노트북을 닫아도 작업이 계속되고 휴대폰에서 답하거나 방향을 바꿀 수 있으며, 가상 머신 비용은 따로 없습니다.
  • Claude 디자인을 쓰면 코드를 짜기 전에 화면 디자인부터 만들 수 있습니다. 공식 영상은 저장소 연결 → 시안 → 댓글 피드백 → 직접 수정 → 클릭형 프로토타입 → 구현 순서로 진행했습니다.

1. 터미널에 Claude Code 설치하기

Claude Code를 내 컴퓨터 터미널에 설치하고 처음 로그인하는 과정입니다. 새 기능은 터미널 버전에 가장 먼저 나오므로 기본 설치 방법으로 권장됩니다.

  1. macOS·Linux·WSL에서는 공식 안내에 나온 curl 설치 명령을 한 번에 실행합니다.
  2. Homebrew를 쓰는 사람은 brew install로 설치해도 됩니다.
  3. Windows PowerShell에서는 공식 안내의 Invoke-RestMethod 명령을 실행합니다.
  4. Windows CMD에서는 공식 안내의 curl 명령을 실행합니다.
  5. 작업할 프로젝트 폴더로 이동한 뒤 Claude Code를 실행합니다.
  6. 처음 실행하면 색상 테마를 고릅니다.
  7. Claude 계정(Pro, Max, Enterprise) 또는 API 키로 로그인합니다.
  • Homebrew나 winget으로 설치하면 자동 업데이트가 되지 않습니다.
  • Claude Code는 실행한 폴더와 그 하위 폴더 전체에 접근할 수 있습니다. 회사 문서가 많은 상위 폴더보다 작업할 폴더에서 실행하세요.
  • 조직에 Enterprise 계정이 있으면 로그인할 때 그 옵션을 고릅니다.

2. VS Code·JetBrains에서 쓰기

평소 쓰는 코드 편집기 안에서 Claude Code를 여는 방법입니다. 터미널 창을 따로 띄우지 않고 편집기 화면 옆에서 바로 요청할 수 있습니다.

  1. VS Code에서 확장 패널을 열고 Claude Code를 검색합니다.
  2. Anthropic이 만든 파란 체크 표시 확장인지 확인하고 설치합니다.
  3. 필요하면 VS Code를 다시 시작합니다.
  4. Ctrl/Cmd + Shift + P로 명령 팔레트를 열고 Claude Code를 검색해 새 탭으로 엽니다.
  5. JetBrains IDE를 쓴다면 JetBrains Marketplace에서 Claude Code 플러그인을 설치합니다.
  6. IDE를 다시 시작한 뒤 Claude 로고를 눌러 창을 엽니다.
  • VS Code에서는 파일을 열었을 때 보이는 Claude 로고를 눌러도 열립니다.
  • VS Code 설정 파일에서 확장 화면 대신 터미널 방식으로 쓰도록 바꿀 수 있습니다.
  • Claude Desktop 앱에서는 상단의 Code 토글로 Claude Code 화면으로 바꿉니다.

3. 권한 모드 바꿔 가며 쓰기

Claude가 파일을 고치거나 명령을 실행하기 전에 얼마나 자주 허락을 받을지 정하는 기능입니다. 처음에는 매번 확인하고, 익숙해지면 파일 수정만 자동으로 맡기는 식으로 조절합니다.

  1. Claude Code 실행 중에 Shift + Tab을 누릅니다.
  2. 기본 모드에서는 파일 수정·명령 실행 전에 매번 허락을 묻습니다. 처음에는 이 모드로 하나씩 확인합니다.
  3. 한 번 더 누르면 Auto accept edits 모드가 됩니다. 파일 수정·생성은 자동으로 승인하고 명령 실행은 계속 묻습니다.
  4. 한 번 더 누르면 Plan mode가 됩니다. 파일을 고치지 않고 읽기만 하면서 작업 계획을 먼저 세웁니다.
  5. 입력창 아래에 표시된 모드 이름을 보고 지금 어떤 모드인지 확인합니다.
  • 권한 확인을 건너뛰면 실수를 미리 잡기 어렵습니다. 신중하게 쓰세요.
  • Claude가 일하는 중간에도 정보를 더 주거나, 멈추게 하거나, 방향을 바꿀 수 있습니다.
  • 모든 단계를 직접 보고 싶으면 기본(승인) 모드를 유지합니다.

4. 계획 모드로 첫 요청하기

코드를 고치기 전에 Claude가 먼저 파일을 읽고 계획을 세우게 하는 방법입니다. 계획 단계가 방향을 고치기 가장 좋은 때라서, 큰 작업은 이 모드로 시작하면 좋습니다.

  1. 프로젝트 최상위(루트) 폴더에서 Claude Code를 엽니다.
  2. Shift+Tab을 여러 번 눌러 입력창 아래에 plan mode가 표시되게 합니다.
  3. 만들려는 기능의 범위와 원하는 모습을 구체적으로 적어 요청합니다.
  4. Claude가 파일을 읽고 웹 검색까지 해서 내놓은 계획을 검토합니다.
  5. 빠졌거나 틀린 부분이 있으면 추가나 수정을 요청합니다.
  6. 계획이 마음에 들면 승인하고, 파일 수정을 자동으로 받아들일지 매번 물을지 고릅니다.
예시
앱 전체에 다크 모드를 추가해 줘. 헤더에 다크 모드 토글 스위치를 넣고, 다크 모드 색은 지금 라이트 테마와 어울리는 대비 색으로 맞춰 줘. 먼저 계획을 보여 줘.
  • 프롬프트는 최대한 구체적으로 씁니다.
  • 계획 모드에서는 Claude가 파일을 고칠 수 없고 읽기만 합니다.
  • 계획 모드를 켜지 않고 '코드베이스를 먼저 살펴봐 줘'라고 요청해도 비슷하게 쓸 수 있습니다.

5. CLAUDE.md로 프로젝트 규칙 정하기

CLAUDE.md는 Claude Code가 세션을 시작할 때마다 자동으로 읽는 메모 파일입니다. 사용하는 기술, 자주 쓰는 명령어, 작성 규칙을 적어 두면 매번 설명하지 않아도 첫 응답부터 결과가 좋아집니다.

  1. 프로젝트 루트 폴더에서 Claude Code를 실행합니다.
  2. /init을 실행해 지금 프로젝트 내용을 바탕으로 CLAUDE.md를 만듭니다.
  3. 만들어진 파일에서 사용 기술, 개발 서버·테스트·린트 명령어, 코드 스타일 규칙을 확인하고 고칩니다.
  4. 참고할 문서가 있으면 @ 기호와 파일 경로로 연결합니다.
  5. 작업 중 같은 내용을 여러 번 바로잡았다면 그 규칙을 메모리에 저장하라고 Claude에게 직접 요청합니다.
  6. 프로젝트용 CLAUDE.md는 버전 관리에 올려 팀과 함께 씁니다.
예시
/init
  • 주석 쓰는 방식 같은 개인 취향은 설정 폴더의 사용자용 CLAUDE.md에 적습니다. 그러면 모든 프로젝트에 적용됩니다.
  • 사용 기술 → 개인 선호 → 명령어 순으로 적기 시작해 조금씩 늘려 가세요.
  • 처음에는 최소한으로 쓰고, 계속 바로잡아야 하는 부분만 더하면 파일이 간결하게 유지됩니다.

6. 컨텍스트 확인하고 정리하기

컨텍스트는 Claude의 작업 기억입니다. 읽은 파일, 실행한 명령, 주고받은 메시지가 모두 공간을 차지합니다. 기억이 꽉 차면 자동으로 압축되며 세부 내용이 사라질 수 있으니, 슬래시 명령으로 직접 확인하고 정리합니다.

  1. /context를 실행해 컨텍스트가 얼마나 찼는지, 무엇이 가장 많이 차지하는지 확인합니다.
  2. 같은 기능을 계속 작업해야 하면 /compact로 지금까지의 내용을 요약합니다.
  3. 새 기능을 시작할 때는 /clear로 대화를 완전히 비웁니다.
  4. 지금 작업과 관계없는 MCP 서버는 끕니다.
  5. 답만 필요한 조사는 서브에이전트에게 맡깁니다. 서브에이전트는 별도 컨텍스트에서 일하고 요약만 돌려줍니다.
  6. 다음 세션에도 기억해야 할 내용은 CLAUDE.md에 적습니다.
예시
/context
  • 압축하면 이전 대화의 세부 내용이 사라질 수 있습니다.
  • 작업할 기능이 바뀌면 이전 대화가 새 작업에 영향을 주지 않도록 비웁니다.
  • 프롬프트를 너무 짧게 쓰면 Claude가 파일을 더 많이 뒤지게 되어 오히려 컨텍스트를 더 씁니다.
  • 스킬은 MCP와 비슷하지만 전체 내용을 한 번에 컨텍스트에 올리지 않아 공간을 덜 씁니다.

7. 결과 검증하고 커밋하기

Claude가 만든 결과가 맞는지 스스로 확인하게 하고, 점검한 뒤 커밋(변경 저장)까지 마무리하는 흐름입니다. 탐색 → 계획 → 코딩 → 커밋 순서의 마지막 단계입니다.

  1. 계획을 세울 때 어떤 결과가 맞는 결과인지 성공 기준을 분명히 적습니다.
  2. 웹 화면을 만드는 작업이라면 Claude in Chrome 확장을 설치해 Claude가 브라우저 탭에서 직접 테스트하게 합니다.
  3. Claude가 반복해서 확인할 수 있도록 프로젝트에 테스트 스위트를 둡니다. 테스트는 Claude에게 만들게 해도 됩니다.
  4. 결과를 직접 확인해 만족하면 서브에이전트 코드 리뷰어로 코드를 점검합니다.
  5. Claude에게 내 스타일에 맞는 커밋 메시지를 만들게 한 뒤 푸시합니다.
예시
서브에이전트 코드 리뷰어로 이번 변경 내용을 점검해 줘. 문제가 없으면 기존 커밋 스타일에 맞춰 커밋 메시지를 만들어 줘.
  • 테스트가 팀의 기준이 되므로, Claude가 만든 테스트는 먼저 직접 확인해 잘못된 경고를 막습니다.
  • 같은 문제가 반복되면 해결 방법을 CLAUDE.md에 저장해 달라고 요청합니다.

8. MCP 서버로 외부 도구 연결하기

MCP는 Claude Code를 Linear, GitHub, 문서 서버 같은 외부 도구·데이터와 연결하는 개방형 표준입니다. 다른 서비스의 정보를 Claude가 직접 가져와 써야 할 때 연결합니다.

  1. claude.com/connectors에서 연결할 수 있는 커넥터 목록을 살펴봅니다.
  2. claude mcp add로 서버를 추가합니다.
  3. 인터넷에 있는 원격 서버는 HTTP 방식, 내 컴퓨터에서 돌리는 서버는 STDIO 방식으로 등록합니다.
  4. 적용 범위를 로컬·사용자·프로젝트 가운데 하나로 정합니다.
  5. 팀과 함께 쓸 서버는 프로젝트 범위로 등록해 .mcp.json 파일로 공유합니다.
  6. 지금 쓰지 않는 서버는 꺼서 컨텍스트를 아낍니다.
  • MCP 서버는 쓰지 않을 때도 도구 설명이 컨텍스트를 차지합니다.
  • MCP 도구 설명이 컨텍스트의 10%를 넘으면 Claude Code가 자동으로 도구 검색 모드로 바뀝니다.
  • Context7 MCP 서버를 쓰면 사용 중인 라이브러리의 최신 문서를 받아 볼 수 있습니다.

9. 웹·휴대폰에서 클라우드 세션 쓰기

클라우드 세션은 내 컴퓨터가 아니라 클라우드의 가상 머신에서 돌아가는 Claude Code 작업입니다. 노트북을 닫아도 계속 진행되므로 큰 작업, 여러 작업을 동시에 돌릴 때, 퇴근 전 맡겨 둘 때 알맞습니다.

  1. Pro, Max, Team 플랜인지 확인합니다. Enterprise는 프리미엄 좌석 또는 Chat + Claude Code 좌석이어야 합니다.
  2. 작업할 프로젝트를 GitHub 저장소에 올려 둡니다. 웹(claude.ai/code)은 GitHub 저장소만 지원합니다.
  3. 데스크톱 앱, 브라우저, 터미널, 휴대폰, Slack 가운데 편한 곳에서 클라우드 세션을 시작합니다.
  4. Claude는 저장소를 복제해 별도 브랜치에서 작업합니다. 이동 중에는 휴대폰으로 질문에 답하거나 방향을 바꿉니다.
  5. 필요하면 세션을 여러 개 동시에 돌립니다.
  6. 작업이 끝나면 변경 내용을 검토하고 PR을 만듭니다.
  • 클라우드 세션 사용량은 로컬 세션과 함께 플랜 한도에 합산되며, 가상 머신 비용은 따로 없습니다.
  • Remote Control은 내 컴퓨터에서 실행 중인 세션에 연결하는 방식이라 컴퓨터가 켜져 있어야 합니다. 컴퓨터를 끌 예정이면 클라우드 세션을 쓰세요.
  • 데스크톱 앱은 백그라운드 작업에 알맞다고 소개됩니다.

10. 자동 모드를 우리 환경에 맞추기

자동 모드는 매번 허락 버튼을 누르는 피로를 줄이기 위한 기능입니다. 별도의 분류기가 사용자 메시지와 Claude의 행동이 의도에 맞는지 판단해 자동으로 승인합니다. 회사 인프라를 설명해 두어야 안전하고 매끄럽게 동작하므로 주로 관리자나 숙련 사용자가 설정합니다.

  1. 관리자는 관리형 설정(managed settings)에 환경을 정의합니다. 그러면 모든 개발자가 이 설정을 이어받습니다.
  2. 개발자는 사용자 설정(user settings)에 자기 항목을 더합니다.
  3. environment 필드에 회사의 GitHub 조직, 클라우드 버킷, 내부 서비스 등을 평이한 영어로 설명합니다.
  4. environment를 설정하면 기본 항목이 대체되므로, 기본 문자열도 함께 넣어 유지합니다.
  5. 예외로 허용할 동작은 allow에 씁니다. 명시적으로 요청하지 않으면 막을 동작은 soft deny, 무조건 막을 동작은 hard deny에 씁니다.
  6. 반드시 막아야 할 것은 deny 규칙으로, 자동 모드에서도 확인을 받을 것은 ask 규칙으로 정합니다.
  • 처음에는 좁게 시작합니다. 거부되는 항목을 보면서 조금씩 넓히세요.
  • 기본값은 작업 폴더와 git 리모트만 내부로 봅니다. 회사 인프라를 따로 설명하지 않으면 정상 작업도 막힐 수 있습니다.
  • deny·ask·allow 규칙이 분류기보다 먼저 적용됩니다. 읽기 전용이거나 되돌릴 수 있는 작업은 분류기를 거치지 않습니다.
  • 개발자는 관리자가 정한 항목을 지울 수 없습니다. 운영 서버 변경 같은 위험한 작업은 직접 검토하세요.
