Claude Code 기본

Claude Code는 내 컴퓨터의 파일을 직접 읽고 고치며 명령까지 실행하는 AI 작업 도구입니다. 터미널·VS Code·JetBrains·데스크톱 앱·웹·휴대폰에서 쓸 수 있습니다. 먼저 설치와 데스크톱 앱으로 첫 결과물을 만들어 보세요. 그다음 권한 모드·계획 모드·CLAUDE.md로 기본기를 익히고, 컨텍스트 관리·MCP·원격 작업·자동 모드 순서로 넓혀 가면 됩니다.

최근 바뀐 점

  • 클라우드 세션은 내 컴퓨터가 아닌 클라우드 가상 머신에서 작업하므로, 노트북을 닫아도 작업이 이어지고 휴대폰에서 질문에 답하거나 방향을 바꿀 수 있습니다.
  • 클라우드 세션은 데스크톱 앱·브라우저·터미널·휴대폰·Slack에서 시작할 수 있습니다. Pro·Max·Team 플랜 등에서 쓸 수 있고, 플랜 한도에 함께 합산되며 가상 머신 비용은 따로 없습니다.
  • Claude Code의 화면과 행동 방식을 바꾸는 작은 프로그램인 '모드(Mods)'가 10월 1일 공식 발표되었습니다. 창·버튼 같은 화면 요소는 모드로 만들 수 있다고 소개되었습니다.

1. 터미널에 Claude Code 설치하기

가장 기본이 되는 설치 방법으로, 새 기능이 가장 먼저 나오는 곳이 터미널입니다. 운영체제에 맞는 설치 명령을 실행한 뒤 Claude 계정으로 로그인하면 바로 쓸 수 있습니다.

  1. macOS·Linux·WSL에서는 공식 안내에 나온 curl 설치 명령을 한 번에 실행합니다.
  2. Homebrew를 쓰고 있다면 brew install로 설치해도 됩니다.
  3. Windows PowerShell에서는 안내된 Invoke-RestMethod 명령을 실행합니다.
  4. Windows CMD에서는 안내된 curl 명령을 실행합니다.
  5. 작업할 프로젝트 폴더로 이동해 Claude Code를 실행합니다.
  6. 처음 실행하면 색상 테마를 고릅니다.
  7. Claude 계정(Pro, Max, Enterprise) 또는 API 키로 로그인합니다.
  • Homebrew나 winget으로 설치하면 자동 업데이트가 되지 않습니다.
  • 회사에 Enterprise 계정이 있으면 로그인할 때 해당 옵션을 고릅니다.
  • 실행한 폴더와 그 아래 모든 폴더에 접근 권한이 생기므로, 작업할 폴더에서 실행합니다.

2. 데스크톱 앱 코드 탭으로 시작하기

Claude 데스크톱 앱의 코드 탭을 쓰면 터미널 없이 화면에서 폴더를 고르고 결과를 바로 볼 수 있습니다. 개발이 처음이라면 데스크톱 앱으로 시작하고, 익숙해지면 터미널(CLI)로 넘어가길 권합니다.

  1. Claude 데스크톱 앱에서 코드 탭으로 들어갑니다.
  2. 로컬 옆 버튼을 눌러 폴더 열기를 선택하고 작업할 폴더(예: 대시보드)를 지정합니다.
  3. 폴더를 고른 뒤 워크스페이스 신뢰를 진행합니다.
  4. 작업에 쓸 자료 파일(예: 설문 결과 CSV)을 첨부합니다.
  5. 무엇을 만들지, 필요한 기능을 풀어 써서 요청합니다.
  6. 오른쪽 내장 브라우저에서 결과를 확인하고, 필요하면 기본 브라우저에서 열기로 크롬에서 엽니다.
  7. 고칠 점은 다시 프롬프트로 요청합니다.
예시
첨부한 설문 결과 CSV로 팀원 누구나 브라우저에서 볼 수 있는 대시보드 웹사이트를 만들어 줘. 문항별 응답 비율을 그래프로 보여 주고, 연령대별로 걸러 볼 수 있게 해 줘.
  • 어떻게 만들지는 AI에게 맡기고, 무엇을 만들지에 집중합니다.
  • 코워크·코드·디자인은 프로 플랜(월 20달러) 이상에서 쓸 수 있습니다.
  • 용도 구분: 생각 정리는 채팅, 문서·파일 정리는 코워크, 웹사이트·앱 제작은 코드, 발표 자료는 디자인이 알맞습니다.
  • 예전 방식: Claude Desktop 상단의 Code 토글로 코드 화면으로 전환했습니다.

3. VS Code·JetBrains에서 쓰기

평소 쓰는 코드 편집기 안에서 Claude Code를 열어 파일을 보면서 함께 작업하는 방법입니다. VS Code는 확장 프로그램, JetBrains는 플러그인으로 설치합니다.

  1. VS Code의 확장 패널을 열고 Claude Code를 검색합니다.
  2. Anthropic이 만든 파란 체크 표시 확장인지 확인하고 설치합니다.
  3. 필요하면 VS Code를 다시 시작합니다.
  4. Ctrl/Cmd + Shift + P로 명령 팔레트를 열고 Claude Code를 검색해 새 탭을 엽니다.
  5. JetBrains에서는 JetBrains Marketplace에서 Claude Code 플러그인을 설치하고 IDE를 다시 시작합니다.
  6. JetBrains를 다시 열면 보이는 Claude 로고를 눌러 Claude Code 창을 엽니다.
  • VS Code에서는 파일을 열었을 때 보이는 Claude 로고를 눌러도 열 수 있습니다.
  • VS Code 설정 파일에서 화면(UI) 대신 터미널 방식으로 쓰도록 바꿀 수 있습니다.

4. 권한 모드 전환하기

Claude Code는 기본적으로 파일을 고치거나 명령을 실행하기 전에 허락을 묻습니다. 권한 모드를 바꾸면 얼마나 자유롭게 맡길지 조절할 수 있습니다.

  1. Claude Code 실행 중 Shift+Tab을 누릅니다.
  2. 기본 모드에서는 파일 수정과 명령 실행 전에 매번 허락을 묻습니다.
  3. 한 번 더 눌러 Auto accept edits 모드로 바꾸면 파일 수정·생성은 자동으로 승인하고, 명령 실행은 계속 묻습니다.
  4. 다시 눌러 Plan mode로 바꾸면 파일을 고치지 않고 읽기만 하며 계획을 세웁니다.
  5. 입력창 아래 표시를 보고 지금 어떤 모드인지 확인합니다.
  • 모든 단계를 직접 확인하고 싶으면 기본(승인) 모드를 유지합니다.
  • 권한 확인을 건너뛰면 실수를 미리 잡기 어려우니 신중하게 씁니다.
  • 작업 도중에도 내용을 더하거나, 중단하거나, 방향을 바꿀 수 있습니다.

5. 계획 모드로 첫 요청하기

계획 모드에서 Claude는 파일을 고치지 않고 코드를 읽고 조사만 한 뒤 상세한 계획을 내놓습니다. 코드가 쓰이기 전에 방향을 고칠 수 있어 첫 요청이나 큰 작업에 알맞습니다.

  1. 프로젝트 루트 폴더에서 Claude Code를 엽니다.
  2. Shift+Tab을 여러 번 눌러 입력창 아래에 plan mode가 표시되게 합니다.
  3. 만들려는 내용과 범위, 지켜야 할 조건을 구체적으로 적어 요청합니다.
  4. Claude가 파일을 읽고 웹 검색을 거쳐 내놓은 계획을 검토합니다.
  5. 부족한 부분은 추가나 수정을 요청합니다.
  6. 계획이 마음에 들면 승인하고, 파일 수정을 자동 수락할지 매번 물을지 고릅니다.
  7. 실행 결과와 Claude가 그 결론에 이른 과정을 확인합니다.
예시
앱 전체에 다크 모드를 추가해 줘. 헤더에 다크 모드를 켜고 끄는 토글 스위치를 넣고, 다크 모드 색은 기존 라이트 테마와 어울리면서 글자가 잘 보이도록 대비를 맞춰 줘.
  • 코드가 쓰이기 전인 계획 단계가 방향을 고치기 가장 좋은 시점입니다.
  • 프롬프트는 가능한 한 구체적으로 씁니다.
  • 계획 모드 없이 코드베이스를 살펴봐 달라고 요청해도 됩니다.
  • 탐색 → 계획 → 코딩 → 커밋 순서로 일하는 것이 기본 흐름입니다.

6. CLAUDE.md로 프로젝트 규칙 정하기

CLAUDE.md는 프로젝트 루트에 두는 메모 파일입니다. Claude Code가 세션을 시작할 때마다 자동으로 읽습니다. 기술 스택·명령어·규칙을 적어 두면 매번 설명하지 않아도 첫 응답부터 품질이 좋아집니다.

  1. 프로젝트 루트 폴더에서 Claude Code를 실행합니다.
  2. /init을 실행해 코드베이스를 바탕으로 CLAUDE.md 초안을 만듭니다.
  3. 프로젝트 개요(만들 서비스, 기능, 기술 스택, 디자인 시스템)를 확인하고 고칩니다.
  4. 빌드·테스트·실행 명령어와 코딩 규칙을 적습니다.
  5. 건드리면 안 되는 폴더 같은 금지 규칙을 적습니다.
  6. 주요 폴더 위치를 안내하고, 자세한 내용은 별도 문서로 넘겨 @와 파일 경로로 연결합니다.
  7. 작업 중 반복해서 바로잡은 규칙은 Claude에게 CLAUDE.md에 저장하라고 요청합니다.
  8. 프로젝트용 파일은 버전 관리에 올려 팀과 공유합니다.
예시
/init
  • 200줄 이내로, 매뉴얼이 아니라 '지도'처럼 짧게 씁니다.
  • AI가 자동으로 만든 내용은 성능을 떨어뜨릴 수 있으니 사람이 꼭 검수합니다.
  • 개인 취향(주석 쓰는 방식 등)은 설정 폴더의 사용자용 CLAUDE.md에 적으면 모든 프로젝트에 적용됩니다.
  • CLAUDE.md는 권고일 뿐입니다. 반드시 지켜야 하는 규칙은 훅(Hooks)으로 강제합니다.

7. 컨텍스트 확인하고 정리하기

컨텍스트는 Claude의 작업 기억으로, 읽은 파일·실행한 명령·주고받은 대화가 모두 공간을 차지합니다. 한도에 가까워지면 자동으로 압축되면서 세부 내용이 사라질 수 있으므로, 직접 확인하고 정리하는 습관이 필요합니다.

  1. /context를 실행해 컨텍스트 크기와 가장 많이 차지하는 항목을 확인합니다.
  2. 같은 기능 작업을 이어가야 하면 /compact로 지금까지 내용을 요약합니다.
  3. 새 기능을 시작할 때는 /clear로 대화를 완전히 비웁니다.
  4. 다음 세션에도 기억시킬 내용은 CLAUDE.md에 적습니다.
  5. 지금 작업과 관련 없는 MCP 서버는 끕니다.
  6. 답만 필요한 조사는 서브에이전트에게 맡겨 요약만 받습니다.
예시
/context
  • 압축하면 이전 대화의 세부 내용이 사라질 수 있습니다.
  • 이전 대화가 새 작업에 영향을 주지 않도록, 기능이 바뀌면 비우고 시작합니다.
  • 프롬프트를 너무 짧게 쓰면 Claude가 코드를 더 많이 뒤져서 오히려 컨텍스트를 더 씁니다.
  • 스킬은 MCP와 달리 전체 내용을 컨텍스트에 올리지 않아 공간을 아낄 수 있습니다.

8. 결과 검증하고 커밋하기

Claude가 만든 결과를 스스로 확인하게 하고, 점검한 뒤 저장(커밋)하는 흐름입니다. 테스트나 브라우저 확장 같은 검증 수단을 주면 Claude가 직접 고쳐 가며 결과를 맞춥니다.

  1. 계획에 무엇이 올바른 결과인지 성공 기준을 분명히 적습니다.
  2. 웹 화면이라면 Claude in Chrome 확장을 설치해 Claude가 브라우저 탭에서 직접 테스트하게 합니다.
  3. Claude가 계속 검증할 수 있도록 프로젝트에 테스트 스위트를 둡니다(Claude에게 작성을 맡겨도 됩니다).
  4. 결과를 직접 확인해 만족하면 서브에이전트 코드 리뷰어로 코드를 점검하게 합니다.
  5. Claude에게 내 스타일에 맞는 커밋 메시지를 만들게 한 뒤 푸시합니다.
  • 테스트가 팀의 기준이 되므로, Claude가 만든 테스트가 맞는지 먼저 확인해 잘못된 통과를 막습니다.
  • 같은 문제가 반복되면 해결책을 CLAUDE.md에 저장하라고 요청합니다.
  • 성공 기준은 확인 가능한 형태로 둡니다(카파시 가이드라인).

9. MCP 서버 연결하기

MCP는 Claude Code를 Linear, GitHub, 문서 서버 같은 외부 도구와 데이터에 연결하는 표준입니다. 필요한 서버만 골라 연결하고, 쓰지 않을 때는 꺼서 컨텍스트를 아낍니다.

  1. claude.com/connectors에서 쓸 수 있는 커넥터를 찾아봅니다.
  2. claude mcp add 명령으로 서버를 추가합니다.
  3. 원격 서버는 HTTP 방식, 내 컴퓨터에서 돌리는 서버는 STDIO 방식으로 연결합니다.
  4. 적용 범위를 로컬·사용자·프로젝트 중에서 고릅니다.
  5. 팀과 함께 쓸 서버는 프로젝트 범위로 설정해 .mcp.json으로 공유합니다.
  6. 지금 작업에 쓰지 않는 서버는 끕니다.
  • MCP 서버는 쓰지 않을 때도 모든 도구 정의가 컨텍스트를 차지합니다.
  • 도구 정의가 컨텍스트의 10%를 넘으면 Claude Code가 자동으로 도구 검색 모드로 바뀝니다.
  • Context7 MCP 서버를 연결하면 사용하는 라이브러리의 최신 문서를 참고하게 할 수 있습니다.

10. 원격 제어로 휴대폰에서 이어가기

원격 제어(Remote Control)는 내 컴퓨터에서 돌고 있는 Claude Code 세션에 웹이나 휴대폰 앱으로 접속해 이어서 작업하는 기능입니다. 파일과 도구는 모두 내 컴퓨터에서 그대로 실행되고, 대화는 기기 사이에 실시간으로 동기화됩니다.

  1. 컴퓨터에서 프로젝트 폴더로 이동합니다.
  2. 터미널에서 claude remote-control을 실행합니다.
  3. 화면에 나온 URL을 Claude Code 웹에서 엽니다.
  4. 휴대폰으로 이어가려면 스페이스바를 눌러 나온 QR 코드를 스캔합니다.
  5. 모바일 브라우저나 Claude 모바일 앱에서 진행 중인 세션을 확인하고 이어서 지시합니다.
  6. 이미 작업 중인 세션을 넘기려면 그 세션에서 /remote-control을 입력하고 표시된 URL로 접속합니다.
예시
claude remote-control
  • 같은 Claude 계정으로 로그인되어 있으면 링크 없이 앱에서 바로 세션을 찾을 수 있습니다.
  • 모든 세션에 기본으로 켜려면 /config에서 원격 제어를 켭니다.
  • 원격에서 새 세션을 여러 개 만들려면 웹·모바일에서 환경(environment) 버튼으로 내 기기를 고른 뒤 원격 세션을 만듭니다.
  • 작업이 내 컴퓨터에서 돌아가므로 컴퓨터가 켜져 있어야 합니다. 컴퓨터를 끄고 맡기려면 클라우드 세션을 씁니다.

11. 클라우드 세션으로 맡겨 두기

클라우드 세션은 내 컴퓨터가 아닌 클라우드 가상 머신에서 Claude Code가 작업하는 방식입니다. 노트북을 닫아도 작업이 계속됩니다. 퇴근 전에 맡겨 두는 일이나 큰 수정 작업, 여러 작업을 동시에 돌릴 때 알맞습니다.

  1. 작업할 프로젝트를 GitHub 저장소에 올려 둡니다.
  2. 데스크톱 앱·브라우저(claude.ai/code)·터미널·휴대폰·Slack 중 편한 곳에서 클라우드 세션을 시작합니다.
  3. 저장소를 고르고 할 일을 요청합니다. Claude가 저장소를 복제해 별도 브랜치에서 작업합니다.
  4. 외출 중에는 휴대폰에서 Claude의 질문에 답하거나 방향을 바꿉니다.
  5. 필요하면 다른 작업도 세션을 더 열어 동시에 맡깁니다.
  6. 작업이 끝나면 변경 내용을 검토하고 PR을 만듭니다.
  • 웹(claude.ai/code)은 GitHub 저장소만 지원합니다.
  • Pro·Max·Team 플랜, Enterprise는 프리미엄 좌석 또는 Chat + Claude Code 좌석에서 쓸 수 있습니다.
  • 사용량은 로컬 세션과 함께 플랜 한도에 합산되며, 가상 머신 비용은 따로 없습니다.

12. 자동 모드를 안전하게 설정하기

자동 모드는 매번 승인하는 피로를 줄이기 위해 별도 분류기가 내 요청과 맞는 행동인지 판단해 대신 승인하는 기능입니다. 기본값은 작업 폴더와 git 리모트만 내부로 보므로, 회사 환경에 맞게 설명을 넣어 줘야 제대로 작동합니다.

  1. 관리자는 관리형 설정(managed settings)에 환경을 정의해 모든 개발자가 물려받게 합니다.
  2. 개발자는 사용자 설정(user settings)에 자기 항목을 더합니다.
  3. environment 필드에 GitHub 조직, 클라우드 버킷, 내부 서비스 등을 평이한 영어로 설명합니다.
  4. environment를 설정하면 기본 항목이 대체되므로 기본 문자열을 함께 넣어 유지합니다.
  5. 예외로 허용할 동작은 allow에 적고, 막을 동작은 soft deny(명시 요청 없으면 막기)와 hard deny(무조건 막기)로 나눠 적습니다.
  6. 확실히 막을 것은 deny 규칙으로, 자동 모드에서도 확인받을 것은 ask 규칙으로 정합니다.
  • 처음에는 좁게 시작하고, 거부되는 항목을 보며 점차 넓힙니다.
  • 개발자는 관리자가 설정한 항목을 지울 수 없습니다.
  • deny·ask·allow 규칙이 먼저 적용되고, 읽기 전용이거나 되돌릴 수 있는 작업은 분류기를 거치지 않습니다.
  • 운영 서버 변경 같은 위험한 작업은 사람이 직접 검토합니다.
