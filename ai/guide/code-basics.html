Claude Code 기본

Claude Code는 터미널, VS Code·JetBrains, 데스크톱 앱, 웹, 휴대폰에서 쓸 수 있는 AI 작업 도우미입니다. 파일을 읽고 고치고 명령을 실행해 일을 끝까지 처리합니다. 설치와 권한 모드부터 익히고, 계획 모드로 첫 요청을 해 본 뒤 CLAUDE.md·컨텍스트 관리·MCP 연결 순서로 넓혀 가면 좋습니다. 익숙해지면 클라우드 세션과 자동 모드로 더 많은 일을 맡길 수 있습니다.

1. 터미널에 Claude Code 설치하기

내 컴퓨터의 터미널에 Claude Code를 설치하고 로그인하는 첫 단계입니다. 새 기능이 가장 먼저 나오는 곳이 터미널이라, 처음 시작할 때 권장되는 방식입니다.

  1. macOS·Linux·WSL에서는 공식 안내에 있는 curl 설치 명령을 한 번에 실행합니다.
  2. Homebrew를 쓰고 있다면 brew install로 설치해도 됩니다.
  3. Windows PowerShell에서는 공식 안내의 Invoke-RestMethod 명령을 실행합니다.
  4. Windows CMD에서는 공식 안내의 curl 명령을 실행합니다.
  5. 작업할 프로젝트 폴더로 이동해 Claude Code를 실행합니다.
  6. 처음 실행할 때 색상 테마를 고릅니다.
  7. Claude 계정(Pro, Max, Enterprise) 또는 API 키로 로그인합니다.
  • Homebrew나 winget으로 설치하면 자동 업데이트가 되지 않습니다.
  • 회사에 Enterprise 계정이 있으면 로그인할 때 그 옵션을 고릅니다.
  • 실행한 폴더와 그 아래 모든 하위 폴더에 접근 권한이 생기므로, 업무와 상관없는 상위 폴더에서 실행하지 않습니다.

2. IDE·데스크톱·웹에서 쓰기

터미널이 낯설다면 VS Code, JetBrains, Claude Desktop, 웹에서도 Claude Code를 쓸 수 있습니다. 데스크톱은 백그라운드 작업에, 웹은 GitHub 저장소 기반의 원격·병렬 작업에 알맞습니다.

  1. VS Code에서는 확장 패널을 열고 Claude Code를 검색합니다.
  2. Anthropic이 만든 파란 체크 표시 확장인지 확인하고 설치한 뒤, 필요하면 VS Code를 다시 시작합니다.
  3. Ctrl/Cmd + Shift + P로 명령 팔레트를 열고 Claude Code를 검색해 새 탭을 엽니다.
  4. JetBrains에서는 JetBrains Marketplace에서 Claude Code 플러그인을 설치하고 IDE를 다시 시작합니다.
  5. JetBrains를 다시 열면 보이는 Claude 로고를 눌러 창을 엽니다.
  6. Claude Desktop에서는 상단의 Code 토글을 눌러 Claude Code로 전환합니다.
  7. 브라우저에서는 claude.ai/code에 접속해 GitHub 저장소를 골라 작업합니다.
  • VS Code에서는 파일을 열었을 때 보이는 Claude 로고를 눌러도 열 수 있습니다.
  • VS Code 설정 파일에서 화면(UI) 대신 터미널 방식을 쓰도록 바꿀 수 있습니다.
  • 웹(claude.ai/code)은 GitHub 저장소만 지원합니다.

3. 권한 모드 바꾸기

Claude Code가 파일을 고치거나 명령을 실행하기 전에 얼마나 허락을 받을지 정하는 기능입니다. 처음에는 매번 묻는 기본 모드로 시작하고, 익숙해지면 상황에 맞게 바꿔 씁니다.

  1. Claude Code 실행 중 Shift+Tab을 누릅니다.
  2. 기본 모드에서는 파일 수정과 명령 실행 전에 매번 허락을 묻습니다.
  3. 한 번 더 눌러 Auto accept edits 모드로 바꾸면 파일 수정·생성은 자동으로 승인하고 명령 실행만 묻습니다.
  4. 한 번 더 눌러 Plan mode로 바꾸면 파일을 고치지 않고 읽기만 하며 계획을 먼저 세웁니다.
  5. 입력창 아래 표시를 보고 지금 어떤 모드인지 확인합니다.
  • 모든 단계를 직접 확인하고 싶으면 기본(승인) 모드를 유지합니다.
  • 권한 확인을 건너뛰면 실수를 미리 잡기 어려우니 신중하게 씁니다.
  • 작업 도중에도 정보를 더하거나 중단하고 방향을 바꿀 수 있습니다.

4. 계획 모드로 첫 요청하기

계획 모드에서는 Claude가 파일을 고치지 않고 읽기만 하면서 조사한 뒤 상세한 계획을 내놓습니다. 코드가 만들어지기 전에 방향을 바로잡을 수 있어 첫 요청이나 큰 작업에 알맞습니다.

  1. 프로젝트 루트 폴더에서 Claude Code를 엽니다.
  2. Shift+Tab을 여러 번 눌러 입력창 아래에 plan mode가 표시되게 합니다.
  3. 만들고 싶은 내용과 범위, 지켜야 할 조건을 구체적으로 적어 요청합니다.
  4. Claude가 파일을 읽고 웹 검색을 거쳐 내놓은 계획을 검토합니다.
  5. 부족한 부분이 있으면 추가나 수정을 요청합니다.
  6. 계획이 마음에 들면 승인하고, 파일 수정을 자동으로 받을지 매번 물을지 고릅니다.
  7. 실행 결과와 Claude가 그 결론에 이른 과정을 확인합니다.
예시
앱 전체에 다크 모드를 넣어 줘. 헤더에 다크 모드를 켜고 끄는 토글 스위치를 만들고, 기존 라이트 테마와 어울리는 대비 색을 써 줘.
  • 프롬프트는 가능한 한 구체적으로 씁니다. 짧게 쓰면 Claude가 코드베이스를 더 뒤지느라 오히려 컨텍스트를 더 씁니다.
  • 코드가 쓰이기 전인 계획 단계가 방향을 고치기 가장 좋은 때입니다.
  • 계획 모드를 켜지 않고 '코드베이스를 먼저 살펴봐 줘'라고 요청해도 됩니다.

5. CLAUDE.md로 프로젝트 규칙 정하기

CLAUDE.md는 프로젝트 루트에 두는 마크다운 파일로, Claude Code가 세션을 시작할 때마다 자동으로 읽습니다. 사용하는 기술, 자주 쓰는 명령, 지켜야 할 규칙을 적어 두면 매번 설명하지 않아도 첫 응답부터 품질이 좋아집니다.

  1. 프로젝트 루트 폴더에서 Claude Code를 실행합니다.
  2. /init을 입력해 코드베이스를 바탕으로 CLAUDE.md를 만듭니다.
  3. 만들어진 파일에서 사용하는 기술(스택), 개발 서버·테스트·린트 명령, 코드 스타일 규칙을 확인하고 고칩니다.
  4. 참고할 문서가 있으면 @ 기호와 파일 경로로 연결합니다.
  5. 작업 중 여러 번 바로잡은 규칙은 Claude에게 기억해 두라고 분명히 요청합니다.
  6. 프로젝트용 CLAUDE.md는 버전 관리에 올려 팀과 공유합니다.
예시
/init
  • 개인 취향(주석 쓰는 방식 등)은 설정 폴더에 있는 사용자 수준 CLAUDE.md에 적으면 모든 프로젝트에 적용됩니다.
  • 처음부터 많이 적지 말고 스택 → 개인 선호 → 명령어 순으로, 계속 바로잡아야 하는 것만 더하면 파일이 간결하게 유지됩니다.
  • 같은 문제가 반복되면 그 해결책을 CLAUDE.md에 저장해 달라고 요청합니다.

6. 컨텍스트 확인하고 정리하기

컨텍스트는 Claude의 작업 기억으로, 읽은 파일·실행한 명령·주고받은 메시지가 모두 공간을 차지합니다. 한도에 가까워지면 자동으로 압축되며 세부 내용이 사라질 수 있으니, 직접 확인하고 정리하면 결과가 더 좋아집니다.

  1. /context를 실행해 컨텍스트 크기와 가장 많이 차지하는 항목을 확인합니다.
  2. 같은 기능 작업을 계속해야 하면 /compact로 지금까지의 내용을 요약합니다.
  3. 새 기능을 시작할 때는 /clear로 대화를 완전히 비웁니다.
  4. 지금 작업과 관계없는 MCP 서버는 끕니다.
  5. 답만 필요한 조사는 서브에이전트에게 맡깁니다.
  6. 다음 세션에도 기억해야 할 내용은 CLAUDE.md에 적습니다.
예시
/context
  • 압축하면 이전 대화의 세부 내용이 사라질 수 있습니다.
  • 이전 대화가 새 작업에 영향을 주지 않도록 기능이 바뀌면 비웁니다.
  • 서브에이전트는 별도 컨텍스트 창을 쓰고 요약만 돌려주어 메인 대화 공간을 아낍니다.
  • 스킬은 MCP와 비슷하지만 전체 내용을 컨텍스트에 올리지 않습니다.

7. 결과 검증하고 커밋하기

Claude가 만든 결과를 스스로 확인하게 하고, 점검을 거쳐 커밋까지 마무리하는 흐름입니다. 탐색 → 계획 → 코딩 → 커밋 중 마지막 단계에 해당합니다.

  1. 계획에 '무엇이 올바른 결과인지' 성공 기준을 분명히 적습니다.
  2. 웹 화면 작업이라면 Claude in Chrome 확장을 설치해 Claude가 브라우저 탭에서 직접 테스트하게 합니다.
  3. Claude가 계속 검증할 수 있도록 프로젝트에 테스트 스위트를 둡니다(Claude에게 작성을 맡겨도 됩니다).
  4. 결과를 직접 확인하고 만족하면 서브에이전트 코드 리뷰어로 코드를 점검하게 합니다.
  5. Claude에게 내 스타일에 맞는 커밋 메시지를 만들게 한 뒤 푸시합니다.
예시
서브에이전트 코드 리뷰어로 이번 변경 내용을 점검해 줘. 문제가 없으면 내 스타일에 맞는 커밋 메시지를 만들어 줘.
  • 테스트가 팀의 기준이 되므로 먼저 직접 확인해 잘못된 테스트를 막습니다.
  • 같은 문제가 반복되면 해결책을 CLAUDE.md에 저장해 달라고 요청합니다.

8. MCP 서버 연결하기

MCP는 Claude Code를 Linear, GitHub, 문서 서버 같은 외부 도구와 데이터에 연결하는 개방형 표준입니다. 업무에서 쓰는 서비스를 Claude가 직접 조회하고 다루게 하고 싶을 때 씁니다.

  1. claude.com/connectors에서 연결할 수 있는 커넥터 목록을 확인합니다.
  2. 터미널에서 claude mcp add 명령으로 서버를 추가합니다.
  3. 원격 서비스라면 HTTP 방식, 내 컴퓨터에서 돌리는 서버라면 STDIO 방식을 고릅니다.
  4. 적용 범위를 로컬·사용자·프로젝트 중에서 정합니다.
  5. 팀과 함께 쓸 서버는 프로젝트 범위로 설정해 .mcp.json 파일로 공유합니다.
  6. 쓰지 않는 서버는 꺼 둡니다.
  • MCP 서버는 쓰지 않을 때도 도구 정의가 컨텍스트를 차지합니다.
  • MCP 도구 정의가 컨텍스트 창의 10%를 넘으면 Claude Code가 자동으로 도구 검색 모드로 바뀝니다.
  • Context7 MCP 서버를 연결하면 프로젝트에서 쓰는 라이브러리의 최신 문서를 받아 볼 수 있습니다.

9. 클라우드 세션으로 작업 맡기기

클라우드 세션은 내 컴퓨터가 아닌 클라우드 가상 머신에서 Claude Code를 돌리는 방식입니다. 노트북을 닫아도 작업이 계속되므로 퇴근 전에 맡겨 두는 일이나 큰 정리 작업에 알맞고, 휴대폰으로 진행 상황을 챙길 수 있습니다.

  1. Pro, Max, Team 플랜(또는 해당 좌석이 있는 Enterprise)인지 확인합니다.
  2. 작업할 프로젝트를 GitHub 저장소에 올려 둡니다.
  3. 데스크톱 앱, 브라우저, 터미널, 휴대폰, Slack 중 편한 곳에서 클라우드 세션을 시작합니다.

10. 자동 모드를 우리 환경에 맞추기

자동 모드는 매번 허락을 누르는 피로를 줄이기 위해, 별도 분류기가 요청 의도와 맞는 작업인지 판단해 대신 승인하는 기능입니다. 기본값은 작업 폴더와 git 리모트만 '내부'로 보므로, 회사 인프라를 알려 주는 설정을 해야 제대로 쓸 수 있습니다.

  1. 관리자는 관리형 설정(managed settings)에 환경을 정의해 모든 개발자가 물려받게 합니다.
  2. 개발자는 자기 사용자 설정(user settings)에 필요한 항목을 더합니다.
  3. environment 필드에 GitHub 조직, 클라우드 버킷, 내부 서비스 등을 평이한 영어로 설명합니다.
  4. environment를 설정하면 기본 항목이 대체되므로 기본 문자열도 함께 넣어 둡니다.
  5. 예외로 허용할 동작은 allow, 명시적 요청 없이는 막을 동작은 soft deny, 무조건 막을 동작은 hard deny에 적습니다.
  6. 확실히 막을 것은 deny 규칙으로, 자동 모드에서도 확인받고 싶은 것은 ask 규칙으로 정합니다.
  • 처음에는 좁게 시작하고, 거부되는 항목을 보면서 점차 넓힙니다.
  • 개발자는 관리자가 정한 항목을 지울 수 없습니다.
  • deny·ask·allow 규칙이 분류기보다 먼저 적용되고, 읽기 전용이거나 되돌릴 수 있는 작업은 분류기를 거치지 않습니다.
  • 운영(프로덕션) 인프라 변경 같은 위험한 작업은 직접 검토합니다.
