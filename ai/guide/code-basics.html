Claude Code 기본

Claude Code는 내 컴퓨터, 데스크톱 앱, 브라우저, 휴대폰에서 코딩 작업을 맡길 수 있는 AI 도구입니다. 이 페이지는 먼저 클라우드 세션으로 작업을 맡기는 방법을 보고, 이어서 권한 규칙과 자동 모드로 안전하게 승인을 줄이는 방법을 다룹니다. 마지막으로 디자인 시안 만들기와 모드로 작업 환경을 바꾸는 응용으로 넘어가면 됩니다.

입문

1. 클라우드 세션으로 외출 중에도 작업 맡기기

클라우드 세션은 내 컴퓨터가 아니라 클라우드 가상 머신에서 돌아가는 Claude Code 작업입니다. GitHub 저장소를 복제해 별도 브랜치에서 작업하므로 노트북을 닫아도 계속 진행됩니다. 큰 리팩터링, 마이그레이션, 퇴근 전에 맡겨 두는 작업에 알맞습니다.

  1. 내 플랜이 Pro, Max, Team이거나, Enterprise에서 프리미엄 좌석 또는 Chat + Claude Code 좌석을 쓰고 있는지 확인합니다.
  2. 작업할 코드를 GitHub 저장소에 올려 둡니다.
  3. 데스크톱 앱, 브라우저, 터미널, 휴대폰, Slack 중 편한 곳에서 클라우드 세션을 시작합니다.
  4. 작업할 저장소를 고르고 맡길 일을 설명합니다. Claude가 저장소를 복제해 별도 브랜치에서 작업합니다.
  5. 노트북을 닫고 자리를 떠도 됩니다. Claude가 질문하면 휴대폰에서 답하거나 작업 방향을 바꿉니다.
  6. 작업이 끝나면 변경 내용을 검토하고 PR을 만듭니다.
  • 여러 클라우드 세션을 동시에 돌릴 수 있어 서로 관계없는 작업을 나눠 맡기기 좋습니다.
  • 가상 머신 비용은 따로 없지만, 사용량은 로컬 세션과 함께 플랜 한도에 합산됩니다.
  • Remote Control은 클라우드 세션과 다릅니다. 내 컴퓨터에서 실행 중인 세션에 연결하는 방식이라 컴퓨터가 켜져 있어야 합니다.

2. 권한 규칙으로 위험한 작업 막기

Claude Code는 파일 수정이나 명령 실행 전에 권한을 요청합니다. deny·ask·allow 규칙을 정해 두면 꼭 막아야 할 동작은 막고, 확인이 필요한 동작만 묻게 할 수 있습니다. 승인 버튼을 누르는 횟수를 줄이면서 안전도 지키고 싶을 때 씁니다.

  1. 어떤 상황에서도 실행되면 안 되는 동작을 먼저 적어 봅니다.
  2. 그 동작을 deny 규칙에 넣어 확실히 막습니다.
  3. 실행 전에 항상 확인받고 싶은 동작은 ask 규칙에 넣습니다.
  4. 매번 확인할 필요가 없는 예외 동작은 allow 규칙에 넣습니다.
  5. 처음에는 좁게 허용하고, 사용하면서 자주 막히는 항목을 보고 조금씩 넓힙니다.
  • deny·ask·allow 규칙은 자동 모드의 판단보다 먼저 적용됩니다.
  • ask 규칙에 넣은 동작은 자동 모드에서도 확인을 받습니다.
  • 관리자가 관리형 설정(managed settings)에 넣은 항목은 개발자가 지울 수 없습니다.

3. Claude 디자인으로 화면 시안부터 만들기

코드를 짜기 전에 Claude 디자인으로 화면 시안을 여러 개 보고 고르는 방법입니다. 시안에 댓글로 피드백하고 직접 고친 다음, 클릭해 볼 수 있는 프로토타입을 거쳐 구현까지 이어 갑니다. 앱 온보딩처럼 화면 완성도가 중요한 작업에서 결과물을 더 좋게 만들 때 씁니다.

  1. Claude 디자인에 작업할 저장소를 연결합니다.
  2. 만들 화면을 설명하고 시안을 요청합니다.
  3. 마음에 드는 시안에 댓글로 고칠 점을 남깁니다.
  4. 세부적인 부분은 시안에서 직접 수정합니다.
  5. 클릭형 프로토타입으로 화면 흐름을 직접 눌러 보며 확인합니다.
  6. 확정한 디자인을 바탕으로 구현을 진행합니다.
예시
이 앱의 온보딩 화면 시안을 몇 가지 다른 방향으로 보여 줘.
  • 바로 코드로 들어가기보다 디자인 탐색에 짧게라도 시간을 쓰면 결과가 더 좋아진다는 것이 영상의 핵심입니다.

4. 자동 모드를 우리 회사 환경에 맞추기

자동 모드는 매번 권한을 승인하는 수고를 줄여 줍니다. 별도 분류기가 사용자 메시지와 도구 호출만 보고 Claude의 행동이 사용자의 의도와 맞는지 판단합니다. 기본값은 작업 디렉터리와 git 리모트만 내부로 보므로, 회사 인프라를 environment 필드에 알려 줘야 제대로 동작합니다.

  1. 팀 전체에 적용하려면 관리자가 관리형 설정(managed settings)에서 환경을 정의합니다. 모든 개발자가 이 설정을 이어받습니다.
  2. 개인 항목은 각 개발자가 사용자 설정(user settings)에 추가합니다.
  3. environment 필드에 회사 GitHub 조직, 클라우드 버킷, 내부 서비스 등을 쉬운 영어로 설명합니다.
  4. environment를 설정하면 기본 항목이 대체되므로 기본 문자열도 함께 넣어 둡니다.
  5. 더 세밀하게 조정하려면 예외는 allow에, 명시적으로 요청하지 않으면 막을 동작은 soft deny에, 무조건 막을 동작은 hard deny에 적습니다.
  6. 처음에는 좁게 설정하고, 거부되는 항목을 확인하며 범위를 넓힙니다.
예시
Our GitHub organization is example-corp. Our cloud storage bucket is example-corp-data. Our internal services run under internal.example-corp.com.
  • 읽기 전용이거나 되돌릴 수 있는 작업은 분류기 검사를 건너뜁니다.
  • 도구 결과에 숨은 악성 지시는 서버 측 프로브가 먼저 검사합니다. 프로브와 자동 모드를 함께 켠 평가에서 프롬프트 인젝션 공격 성공률이 0이었습니다.
  • 프로덕션 인프라 변경 같은 고위험 작업은 자동 모드에 맡기지 말고 직접 검토합니다.
  • 연구에 따르면 권한 요청의 97%가 승인되었습니다. 그만큼 반복 승인에서 오는 피로를 줄이려고 만든 기능입니다.

5. 모드로 Claude Code 작업 환경 바꾸기

모드(Mods)는 Claude Code의 모습과 행동 방식을 바꾸는 작은 프로그램입니다. Claude가 작업할 때마다 보내는 신호를 받아서 지켜보거나, 살짝 고치거나, 대신 처리합니다. 스킬과 MCP가 밖에서 지식과 도구를 건넨다면, 모드는 작업 환경 자체를 바꿉니다.

  1. 만들고 싶은 기능이 지켜보기, 살짝 고치기, 대신 처리하기 중 어디에 해당하는지 정합니다.
  2. 창이나 버튼처럼 화면 요소가 필요한 기능이라면 스킬이나 MCP 대신 모드를 선택합니다.
  3. 데스크톱 앱에서 토큰 사용량을 보여 주는 모드처럼 간단한 것부터 만들어 봅니다.
  4. 익숙해지면 다음 작업 추천, 사용 패턴 기반 추천처럼 Claude의 행동에 관여하는 모드로 넓혀 갑니다.
  • 영상에서는 토큰 표시, 다음 작업 추천, 픽셀 병아리, 사용 패턴 기반 추천 네 가지 모드를 실습합니다.
  • 모드는 2026년 10월 1일 공식 발표된 새 기능이라 앞으로 사용 방법이 바뀔 수 있습니다.
