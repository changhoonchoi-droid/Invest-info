1. Claude Code 설치하고 첫 로그인하기

Claude Code는 코드베이스를 이해하고 파일을 고치며 명령을 실행하는 에이전트형 도구입니다. 터미널, VS Code, JetBrains, 데스크톱 앱, 웹에서 쓸 수 있으며, 가장 먼저 설치와 로그인을 마쳐야 합니다.

  1. macOS·Linux·WSL에서는 안내된 curl 설치 명령을 한 번에 실행합니다.
  2. Homebrew를 선호하면 brew install로 설치합니다.
  3. Windows PowerShell에서는 Invoke-RestMethod 명령을 사용합니다.
  4. Windows CMD에서는 안내된 curl 명령을 사용합니다.
  5. 작업할 프로젝트 폴더로 이동해 Claude Code를 실행합니다.
  6. 처음 실행 시 색상 테마를 고르고 Claude 계정(Pro, Max, Enterprise) 또는 API 키로 로그인합니다.
  • Homebrew와 winget으로 설치하면 자동 업데이트가 되지 않습니다.
  • 조직에 Enterprise 계정이 있으면 해당 옵션을 선택합니다.
  • 실행한 폴더와 그 하위 폴더 전체에 접근 권한이 생기므로 폴더 위치를 확인하고 실행합니다.
  • 새 기능은 터미널에 가장 먼저 출시됩니다.

2. VS Code·JetBrains·데스크톱에서 쓰기

터미널이 낯설다면 평소 쓰는 편집기나 데스크톱 앱에서 Claude Code를 쓸 수 있습니다. 환경마다 맞는 용도가 다르니 골라 쓰세요.

  1. VS Code는 확장 패널에서 Claude Code를 검색하고, Anthropic이 만든 파란 체크 표시 확장을 설치합니다.
  2. 필요하면 VS Code를 다시 시작합니다.
  3. Ctrl/Cmd + Shift + P로 명령 팔레트를 열고 Claude Code를 검색해 새 탭을 엽니다.
  4. JetBrains는 Marketplace에서 Claude Code 플러그인을 설치하고 IDE를 다시 시작합니다.
  5. 다시 열면 보이는 Claude 로고를 눌러 터미널 화면 창을 엽니다.
  6. 데스크톱 앱은 Claude Desktop 상단의 Code 토글(또는 코드 탭)로 전환합니다.
  • VS Code에서 파일을 열었을 때 보이는 Claude 로고를 눌러도 열 수 있습니다.
  • 웹(claude.ai/code)은 GitHub 저장소만 지원합니다.
  • 처음에는 데스크톱 앱으로 시작하고 익숙해지면 CLI로 넘어가는 것을 추천합니다(영상 추천).

3. 데스크톱 앱으로 첫 결과물 만들기

폴더를 지정하고 파일을 첨부해 요청하면, 개발 지식 없이도 대시보드 같은 웹사이트를 만들 수 있습니다. 어떻게 만들지는 AI에게 맡기고 무엇을 만들지에 집중하세요.

  1. 클로드 데스크톱 앱에서 코드 탭으로 들어갑니다.
  2. 로컬 옆 버튼으로 폴더 열기를 눌러 작업 폴더를 지정합니다.
  3. 폴더 선택 후 워크스페이스 신뢰를 진행합니다.
  4. 설문 결과 CSV 같은 자료 파일을 첨부합니다.
  5. 만들고 싶은 결과물과 필요한 기능을 풀어 써서 요청합니다.
  6. 우측 내장 브라우저에서 결과를 확인하고, 필요하면 기본 브라우저에서 열기로 크롬에서 엽니다.
  7. 수정할 점은 프롬프트로 요청합니다.
예시
첨부한 설문 결과 CSV로 팀원 누구나 브라우저에서 볼 수 있는 대시보드 웹사이트를 만들어 줘. 응답자 분포와 항목별 평균을 차트로 보여 줘.
  • 코워크·코드·디자인은 프로 플랜(월 20달러) 이상에서 사용할 수 있습니다.
  • 생각 정리는 채팅, 파일 정리는 코워크, 웹사이트·앱 제작은 코드, 발표 자료는 디자인으로 고릅니다.

4. 권한 모드 전환해 안전하게 쓰기

Claude Code는 기본적으로 파일 수정이나 명령 실행 전에 허락을 묻습니다. Shift + Tab으로 모드를 바꿔 어디까지 맡길지 조절합니다.

  1. Claude Code 실행 중 Shift + Tab을 누릅니다.
  2. 기본(승인) 모드에서는 파일 수정·셸 명령 전에 매번 허락을 묻습니다.
  3. Auto accept edits 모드는 파일 수정은 묻지 않고 명령 실행은 계속 묻습니다.
  4. Plan mode는 읽기 전용 도구로 작업 계획을 먼저 세웁니다.
  5. 상황에 맞는 모드가 입력창 아래에 표시되는지 확인하고 작업합니다.
  • 모든 단계를 직접 확인하고 싶으면 승인 모드를 유지합니다.
  • 권한을 건너뛰면 실수를 미리 잡기 어려우니 신중히 사용합니다.
  • 루프 중간에 컨텍스트를 더하거나 중단·방향 수정이 가능합니다.

5. 계획 모드로 작업 시작하기

계획 모드에서는 Claude가 파일을 수정하지 않고 읽기만 하며 조사해 계획을 세웁니다. 코드가 쓰이기 전에 방향을 고칠 수 있어 큰 작업에 알맞습니다.

  1. 프로젝트 루트 디렉터리에서 Claude Code를 엽니다.
  2. Shift+Tab을 눌러 입력창 아래에 plan mode가 표시될 때까지 전환합니다.
  3. 구현하려는 내용과 알고 싶은 점을 구체적으로 요청합니다.
  4. Claude가 파일을 읽고 웹 검색을 거쳐 내놓은 계획을 검토합니다.
  5. 부족하면 추가나 수정을 요청합니다.
  6. 계획이 좋으면 승인하고, 파일 수정을 자동 수락할지 매번 물을지 고릅니다.
예시
앱 전체에 다크 모드를 넣고 싶어. 헤더에 토글 스위치를 만들고, 기존 라이트 테마에 어울리는 대비 색을 쓰는 계획을 먼저 세워 줘.
  • 코드가 쓰이기 전인 계획 단계가 방향을 고치기 가장 좋은 시점입니다.
  • 계획 모드 없이 코드베이스를 탐색해 달라고 요청해도 됩니다.
  • 프롬프트는 가능한 한 구체적으로 씁니다.

6. CLAUDE.md로 프로젝트 규칙 정하기

CLAUDE.md는 프로젝트 루트에 두는 마크다운 파일로, Claude Code가 세션을 시작할 때마다 자동으로 읽습니다. 스택, 명령어, 코드 스타일을 적어 두면 첫 응답부터 품질이 좋아집니다.

  1. 프로젝트 루트 폴더에서 Claude Code를 실행합니다.
  2. /init 명령을 실행해 코드베이스를 바탕으로 CLAUDE.md를 생성합니다.
  3. 스택, 개발 서버·테스트·린트 명령어, 코드 스타일 규칙을 확인하고 필요한 내용을 고칩니다.
  4. 금지 규칙(예: 건드리면 안 되는 폴더)과 주요 폴더 안내를 추가합니다.
  5. 참고할 문서가 있으면 @ 기호와 파일 경로로 연결합니다.
  6. 작업 중 반복해서 바로잡은 규칙은 Claude에게 메모리에 저장하라고 명시적으로 요청합니다.
  7. 프로젝트용 파일은 버전 관리에 올려 팀과 공유합니다.
예시
방금 알려 준 규칙(커밋 메시지는 한국어로 쓴다)을 CLAUDE.md에 저장해 줘.
  • 200줄 이내로 매뉴얼이 아니라 지도처럼 씁니다.
  • AI가 자동 생성한 설정 파일은 성능을 떨어뜨릴 수 있어 사람이 검수합니다.
  • 개인 취향은 설정 폴더의 사용자 수준 CLAUDE.md에 적으면 모든 프로젝트에 적용됩니다.
  • CLAUDE.md는 권고이고, 어길 수 없는 규칙은 Hooks로 강제합니다.

7. 컨텍스트 확인하고 정리하기

컨텍스트는 Claude의 작업 기억으로, 읽은 파일과 명령, 대화가 모두 공간을 차지합니다. 한도에 가까워지면 자동 압축되어 세부 내용이 사라질 수 있으니 직접 관리하는 편이 좋습니다.

  1. /context를 실행해 컨텍스트 크기와 가장 많이 차지하는 항목을 확인합니다.
  2. 같은 기능 작업을 계속해야 하면 /compact로 지금까지 내용을 요약합니다.
  3. 새 기능을 시작할 때는 /clear로 대화를 완전히 비웁니다.
  4. 다음 세션에도 기억시킬 내용은 CLAUDE.md에 적습니다.
  5. 쓰지 않는 MCP 서버는 끕니다.
  • 압축하면 이전 대화의 세부 내용이 사라질 수 있습니다.
  • 프롬프트를 너무 짧게 쓰면 Claude가 코드베이스를 더 뒤져 오히려 컨텍스트를 더 씁니다.
  • 답만 필요한 조사는 별도 컨텍스트 창을 쓰는 서브에이전트에 맡길 수 있습니다.
  • MCP 서버는 쓰지 않을 때도 도구 정의가 컨텍스트를 차지합니다.

8. 검증하고 커밋까지 마무리하기

성공 기준과 검증 수단을 주면 Claude가 스스로 결과를 확인합니다. 마지막에 리뷰와 커밋 메시지까지 맡겨 한 작업을 매듭짓습니다.

  1. 계획에 무엇이 올바른 결과인지 성공 기준을 분명히 적습니다.
  2. 웹 UI라면 Claude in Chrome 확장을 설치해 Claude가 탭에서 직접 테스트하게 합니다.
  3. Claude가 계속 검증할 수 있는 테스트 스위트를 프로젝트에 둡니다.
  4. 직접 확인해 만족하면 서브에이전트 코드 리뷰어로 코드를 점검합니다.
  5. Claude에게 내 스타일에 맞는 커밋 메시지를 만들게 한 뒤 푸시합니다.
  • 테스트가 팀의 기준이 되도록 먼저 확인해 오탐을 막습니다.
  • 같은 문제가 반복되면 해결책을 CLAUDE.md에 저장하도록 요청합니다.

9. 원격 제어로 어디서나 세션 이어가기

원격 제어(Remote Control)는 내 컴퓨터에서 실행 중인 세션에 웹이나 모바일 앱으로 접속해 이어 작업하는 기능입니다. 도구와 파일은 모두 내 컴퓨터에서 실행되므로 컴퓨터가 켜져 있어야 합니다.

  1. 프로젝트 디렉터리로 이동합니다.
  2. 터미널에서 claude remote-control을 실행합니다.
  3. 화면에 표시된 URL을 Claude Code 웹에서 엽니다.
  4. 스페이스바를 누르면 나오는 QR 코드를 휴대폰으로 스캔합니다.
  5. 모바일 브라우저 또는 Claude 모바일 앱에서 진행 중인 세션을 확인합니다.
  6. 이미 실행 중인 세션은 /remote-control을 입력해 표시된 URL로 접속합니다.
  • 같은 Claude 계정으로 로그인되어 있으면 앱에서 바로 세션을 찾을 수 있습니다.
  • 모든 세션에 기본 적용하려면 /config에서 원격 제어를 켭니다.
  • 영상 기준 Max, Team, Enterprise에 제공되고 Pro와 Max에 순차 확대 중이었으니 내 플랜에서 되는지 확인하세요.

10. 클라우드 세션으로 외출 중에도 맡기기

클라우드 세션은 내 컴퓨터가 아닌 클라우드 가상 머신에서 GitHub 저장소를 복제해 별도 브랜치에서 작업합니다. 노트북을 닫아도 계속 진행되어 큰 리팩터링이나 퇴근 전 맡길 작업에 알맞습니다.

  1. Pro, Max, Team 플랜 등 사용 가능한 계정인지 확인합니다.
  2. 데스크톱 앱, 브라우저, 터미널, 휴대폰, Slack 중 편한 곳에서 클라우드 세션을 시작합니다.
  3. 작업할 GitHub 저장소를 지정하고 할 일을 요청합니다.
  4. 여러 세션을 동시에 돌리고, 휴대폰에서 질문에 답하거나 방향을 바꿉니다.
  5. 작업이 끝나면 변경 내용을 검토하고 PR을 만듭니다.
  • 플랜 한도에 로컬 세션과 함께 합산되며 가상 머신 비용은 따로 없습니다.
  • 내 PC 파일에는 접근하지 못하고, 내 컴퓨터에서 도는 세션에 연결하는 Remote Control과는 다릅니다.

11. 자동 모드 이해하고 환경 설정하기

권한 요청의 97%가 승인되어 생기는 승인 피로를 줄이려고 나온 자동 모드는, 별도 분류기가 내 의도와 맞는 작업인지 판단합니다. 기본값은 작업 디렉터리와 git 리모트만 내부로 보므로 우리 조직 환경을 설명해 줘야 합니다.

  1. 관리자는 관리형 설정(managed settings)에서 환경을 정의해 모든 개발자가 상속하게 합니다.
  2. 개발자는 사용자 설정(user settings)에 자기 항목을 추가합니다.
  3. environment 필드에 GitHub 조직, 클라우드 버킷, 내부 서비스 등을 평이한 영어로 설명합니다.
  4. environment를 설정하면 기본 항목이 대체되므로 기본 문자열을 함께 넣어 유지합니다.
  5. 예외는 allow, 명시 요청 없이는 막을 동작은 soft deny, 무조건 막을 동작은 hard deny에 씁니다.
  6. 확실한 제한은 deny 규칙으로, 자동 모드에서도 확인받을 동작은 ask 규칙으로 막습니다.
  • 처음에는 좁게 시작해 거부되는 항목을 보고 점차 넓힙니다.
  • 개발자는 관리자가 설정한 항목을 제거할 수 없습니다.
  • 프로덕션 인프라 변경 같은 고위험 작업은 직접 검토합니다.
  • deny·ask·allow 규칙이 먼저 실행되고, 읽기 전용 작업은 분류기를 건너뜁니다.

12. 24시간 도는 Claude Code 서버 만들기

노트북은 꺼지면 멈추고 클라우드 세션은 내 PC 파일에 접근하지 못합니다. VPS에 전용 서버를 두면 둘의 장점을 합쳐, 데스크톱 앱을 꺼도 모바일 앱에서 세션을 쓸 수 있습니다. 영상에는 Hostinger 제휴 홍보가 포함되어 있습니다.

  1. Hostinger에서 VPS 호스팅의 KVM 요금제를 고릅니다(일반 업무는 KVM2).
  2. 서버 위치는 가까운 곳으로, 운영체제 템플릿은 Claude Code를 선택합니다.
  3. 결제 후 VPS 설정에서 root 비밀번호를 만들어 안전한 곳에 저장합니다.
  4. VPS 관리에서 웹 콘솔을 엽니다.
  5. claude를 입력하고 테마를 고른 뒤 구독 계정 로그인을 선택합니다.
  6. 표시된 링크에서 인증 후 받은 코드를 붙여 넣고 Yes, I trust this folder를 선택합니다.
  7. 서버에서 adduser로 별도 claude 사용자를 만들고, PC의 공개 키를 서버에 등록해 SSH 접속을 확인합니다.
  8. Claude Code 데스크톱 앱에서 SSH 연결 정보를 입력하고 연결 테스트 후 SSH 연결 추가로 세션을 시작합니다.
  • API 키 방식은 과금이 클 수 있어 구독 계정 로그인을 권합니다.
  • 권한 무시 모드는 승인 질문 없이 작업하므로 서버처럼 격리된 환경에서만 씁니다.
  • 개인 키는 내 PC에만 두고 절대 공유하지 않습니다.
  • 영상 속 일부 명령어는 자막이 불분명해 정확한 입력은 영상 화면을 확인해야 합니다.
