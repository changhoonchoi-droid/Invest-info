Claude Code 기본

Claude Code는 파일을 읽고 고치고 명령까지 실행하는 AI 도구로, 터미널·VS Code·JetBrains·데스크톱 앱·웹·휴대폰에서 쓸 수 있습니다. 먼저 설치와 첫 프롬프트로 감을 잡고, 권한 모드와 CLAUDE.md로 일하는 규칙을 정한 뒤, 컨텍스트 관리와 계획 모드로 품질을 높이세요. 그다음 원격 제어·클라우드 세션·서버 연결로 어디서든 이어서 쓰는 방법으로 넓혀 가면 됩니다.

1. Claude Code 터미널에 설치하고 시작하기

Claude Code를 내 컴퓨터 터미널에 설치하고 처음 로그인하는 과정입니다. 새 기능이 가장 먼저 나오는 환경이라 익숙해지면 터미널 방식을 쓰게 됩니다.

  1. 운영체제에 맞는 설치 명령을 고릅니다. macOS·Linux·WSL은 안내된 curl 명령, Windows PowerShell은 Invoke-RestMethod 명령, Windows CMD는 안내된 curl 명령입니다.
  2. Homebrew를 쓴다면 brew install로 설치해도 됩니다.
  3. 작업할 프로젝트 폴더로 이동합니다.
  4. 터미널에서 claude를 실행합니다.
  5. 처음 실행 시 색상 테마를 고릅니다.
  6. Claude 계정(Pro, Max, Enterprise) 또는 API 키로 로그인합니다.
  • Homebrew와 winget으로 설치하면 자동 업데이트가 되지 않습니다.
  • 조직에 Enterprise 계정이 있으면 해당 옵션을 선택합니다.
  • 실행한 폴더와 그 하위 폴더 전체에 접근 권한이 생기므로 어느 폴더에서 실행하는지 확인하세요.

2. VS Code·JetBrains·데스크톱 앱에서 쓰기

터미널이 낯설다면 평소 쓰는 편집기나 데스크톱 앱에서 Claude Code를 쓸 수 있습니다. 환경마다 장점이 달라 용도에 맞게 고르면 됩니다.

  1. VS Code는 확장 패널에서 Claude Code를 검색합니다.
  2. Anthropic이 만든 파란 체크 표시 확장인지 확인하고 설치합니다.
  3. 필요하면 VS Code를 다시 시작한 뒤 Ctrl/Cmd + Shift + P로 명령 팔레트를 열고 Claude Code를 검색해 새 탭을 엽니다.
  4. JetBrains는 Marketplace에서 Claude Code 플러그인을 설치하고 IDE를 다시 시작합니다.
  5. 다시 열면 보이는 Claude 로고를 눌러 터미널 화면 창을 엽니다.
  6. 데스크톱 앱은 Claude Desktop 상단의 Code 토글로 전환하고 작업할 폴더를 선택합니다.
  • VS Code에서 파일을 열었을 때 보이는 Claude 로고를 눌러도 열 수 있습니다.
  • 처음에는 데스크톱 앱, 익숙해지면 터미널(CLI)로 넘어가는 순서를 추천하는 영상도 있습니다.
  • 웹(claude.ai/code)은 GitHub 저장소만 지원합니다.

3. 권한 모드 바꿔 가며 안전하게 쓰기

Claude Code는 파일 수정이나 명령 실행 전에 허락을 구합니다. Shift + Tab으로 권한 모드를 바꿔 얼마나 맡길지 조절하는 방법입니다.

  1. Claude Code 실행 중 Shift + Tab을 누릅니다.
  2. 기본 모드에서는 파일 수정·셸 명령 전에 매번 허락을 묻습니다. 모든 단계를 확인하고 싶으면 이 모드를 유지합니다.
  3. Auto accept edits 모드로 바꾸면 파일 수정·생성은 묻지 않고 명령 실행만 계속 묻습니다.
  4. Plan mode로 바꾸면 읽기 전용 도구로 작업 계획을 먼저 세웁니다.
  5. 데스크톱 앱에서는 오른쪽 아래 권한 설정에서 권한 무시를 켜면 매번 허용을 묻지 않습니다.
  • 권한 무시는 물어보지 않고 전부 실행하므로 작업 폴더 범위를 확인한 뒤 켜세요.
  • 권한을 건너뛰면 실수를 미리 잡기 어렵습니다. 서버처럼 격리된 환경에서 쓰는 것이 안전합니다.
  • 작업 중간에 컨텍스트를 더하거나 중단·방향 수정을 할 수 있습니다.

4. 계획 모드로 첫 프롬프트 요청하기

계획 모드는 파일을 수정하지 않고 읽기만 하며 계획을 세워 주는 모드입니다. 코드가 쓰이기 전에 방향을 고칠 수 있어 처음 쓰는 사람에게 특히 유용합니다.

  1. 프로젝트 루트 폴더에서 Claude Code를 엽니다.
  2. Shift+Tab을 여러 번 눌러 입력창 아래에 plan mode가 표시되게 합니다.
  3. 만들려는 내용과 알고 싶은 점을 구체적으로 적어 요청합니다.
  4. Claude가 파일을 읽고 내놓은 계획을 검토합니다.
  5. 부족한 부분은 추가·수정을 요청합니다.
  6. 계획이 좋으면 승인하고, 파일 수정을 자동 수락할지 매번 물을지 고릅니다.
예시
앱 전체에 다크 모드를 추가해 줘. 헤더에 토글 스위치를 만들고, 기존 라이트 테마와 어울리는 대비 색을 사용해 줘. 먼저 계획부터 세워 줘.
  • 프롬프트는 가능한 한 구체적으로 씁니다.
  • 계획 단계가 방향을 고치기 가장 좋은 시점입니다.
  • 계획 모드 없이 코드베이스를 탐색해 달라고 요청해도 됩니다.

5. CLAUDE.md로 프로젝트 규칙 정하기

CLAUDE.md는 프로젝트 루트에 두는 마크다운 파일로, Claude Code가 세션을 시작할 때마다 가장 먼저 읽는 규칙서입니다. 스택·명령어·금지 규칙을 적어 두면 매번 같은 설명을 반복하지 않아도 됩니다.

  1. 프로젝트 루트 폴더에서 Claude Code를 실행합니다.
  2. /init 명령으로 코드베이스를 바탕으로 CLAUDE.md를 생성합니다.
  3. 스택, 개발 서버·테스트·린트 명령어, 코드 스타일 규칙을 확인하고 필요한 내용을 고칩니다.
  4. 건드리면 안 되는 폴더 같은 금지 규칙을 적습니다.
  5. 참고할 문서가 있으면 @ 기호와 파일 경로로 연결합니다.
  6. 작업 중 반복해서 바로잡은 규칙은 Claude에게 메모리에 저장하라고 명시적으로 요청합니다.
  7. 프로젝트용 파일은 버전 관리에 올려 팀과 공유합니다.
예시
반복해서 알려 준 규칙이니까 앞으로도 지키도록 CLAUDE.md에 저장해 줘.
  • 200줄 이내로 쓰고 매뉴얼이 아니라 지도(목차)처럼 씁니다.
  • 개인 취향은 설정 폴더의 사용자 수준 CLAUDE.md에 적으면 모든 프로젝트에 적용됩니다.
  • 처음에는 없이 시작해 계속 바로잡는 부분만 추가하면 간결하게 유지됩니다.
  • AI가 자동 생성한 설정 파일은 성능을 떨어뜨릴 수 있으니 사람이 검수하세요. CLAUDE.md는 권고이고, 어길 수 없는 강제 규칙은 Hooks가 맡습니다.

6. 컨텍스트 확인하고 정리하기

컨텍스트는 Claude의 작업 기억으로, 읽은 파일·명령·대화가 모두 공간을 차지합니다. 한도에 가까워지면 자동 압축되며 세부 내용이 사라질 수 있어 직접 관리하면 결과가 좋아집니다.

  1. /context를 실행해 컨텍스트 크기와 가장 많이 차지하는 항목을 확인합니다.
  2. 같은 기능 작업을 이어갈 때는 /compact로 지금까지 내용을 요약합니다.
  3. 새 기능을 시작할 때는 /clear로 대화를 완전히 비웁니다.
  4. 다음 세션에도 기억시킬 내용은 CLAUDE.md에 적습니다.
  5. 쓰지 않는 MCP 서버는 꺼서 도구 정의가 컨텍스트를 차지하지 않게 합니다.
  • 이전 대화가 새 작업에 편향을 주지 않도록 기능이 바뀌면 비웁니다.
  • 프롬프트를 너무 짧게 쓰면 Claude가 코드베이스를 더 뒤져 오히려 컨텍스트를 더 씁니다.
  • 답만 필요한 조사는 서브에이전트에 맡기면 별도 컨텍스트 창에서 처리하고 요약만 돌려줍니다.

7. 탐색→계획→코딩→커밋 흐름으로 일하기

Claude Code를 잘 쓰는 기본 흐름입니다. 먼저 조사와 계획을 거치고, 검증 수단을 주어 스스로 결과를 확인하게 한 뒤 커밋까지 마무리합니다.

  1. 계획 모드에서 구현할 내용을 구체적으로 요청해 탐색과 계획을 받습니다.
  2. 계획에 무엇이 올바른 결과인지 성공 기준을 분명히 적습니다.
  3. 계획을 승인해 코딩을 진행합니다.
  4. 웹 UI라면 Claude in Chrome 확장을 설치해 Claude가 탭에서 직접 테스트하게 합니다.
  5. Claude가 계속 검증할 수 있도록 테스트 스위트를 프로젝트에 둡니다.
  6. 직접 확인해 만족하면 서브에이전트 코드 리뷰어로 코드를 점검합니다.
  7. 내 스타일에 맞는 커밋 메시지를 만들게 한 뒤 푸시합니다.
예시
이 기능이 올바르게 동작한다는 기준은 다음과 같아: (1) … (2) …. 이 기준을 통과하는 테스트를 작성하고, 통과할 때까지 구현해 줘.
  • 테스트가 팀의 기준이 되도록 먼저 확인해 오탐을 막습니다.
  • 같은 문제가 반복되면 해결책을 CLAUDE.md에 저장하도록 요청합니다.

8. 데스크톱 앱에서 폴더 연결해 작업 시키기

클로드 데스크톱 앱의 코드 모드에서 폴더를 지정하고 파일을 넣어 결과물을 만드는 방법입니다. 대시보드 웹사이트나 영상 편집처럼 개발자가 아니어도 업무에 바로 쓸 수 있습니다.

  1. 클로드 데스크톱 앱에서 코드 탭(Claude Code 모드)을 선택합니다.
  2. 로컬 옆 버튼으로 폴더 열기를 눌러 작업할 폴더를 지정합니다.
  3. 폴더 신뢰(워크스페이스 신뢰)를 허용합니다.
  4. 작업에 쓸 자료(예: 설문 결과 CSV, 레퍼런스 영상)를 폴더에 넣거나 첨부합니다.
  5. 무엇을 만들지와 필요한 기능을 풀어 써서 요청합니다.
  6. 우측 내장 브라우저에서 결과를 확인하고, 필요하면 기본 브라우저에서 열기로 크롬에서 엽니다.
  7. 수정할 점은 프롬프트로 이어서 요청합니다.
예시
첨부한 설문 결과 CSV로 팀원 누구나 브라우저에서 볼 수 있는 대시보드 웹사이트를 만들어 줘. 응답 항목별 비율 차트와 주요 인사이트 요약을 넣어 줘.
  • 어떻게 만들지는 AI에게 맡기고 무엇을 만들지에 집중하세요.
  • 사용량이 빨리 닳으면 모델을 한 단계 가벼운 것으로 바꿉니다.
  • 코워크·코드·디자인은 프로 플랜(월 20달러) 이상에서 쓸 수 있습니다.

9. 원격 제어로 휴대폰에서 세션 이어가기

내 컴퓨터에서 실행 중인 Claude Code 세션에 웹이나 모바일 앱으로 접속해 이어서 작업하는 기능입니다. 모든 작업은 내 컴퓨터에서 실행되고 대화는 기기 간에 실시간 동기화됩니다.

  1. 프로젝트 디렉터리로 이동합니다.
  2. 터미널에서 claude remote-control을 실행합니다.
  3. 화면에 표시된 URL을 Claude Code 웹에서 엽니다.
  4. 스페이스바를 누르면 나오는 QR 코드를 휴대폰으로 스캔합니다.
  5. 모바일 브라우저 또는 Claude 모바일 앱에서 진행 중인 세션을 확인합니다.
  6. 이미 실행 중인 세션을 넘기려면 그 세션에서 /remote-control을 입력하고 표시된 URL로 접속합니다.
예시
claude remote-control
  • 같은 Claude 계정으로 로그인되어 있으면 링크 없이 앱에서 바로 세션을 찾을 수 있습니다.
  • 모든 세션에 기본 적용하려면 /config에서 원격 제어를 켭니다.
  • 컴퓨터가 켜져 있어야 합니다. 영상 기준 Max, Team, Enterprise 사용자에게 제공되며 Pro와 Max로 순차 확대 중이었으니 내 플랜에서 되는지 확인하세요.

10. 클라우드 세션으로 외출 중에도 맡기기

클라우드 세션은 내 컴퓨터가 아닌 클라우드 가상 머신에서 도는 Claude Code 작업입니다. GitHub 저장소를 복제해 별도 브랜치에서 일하므로 노트북을 닫아도 계속 진행되고, 퇴근 전에 큰 작업을 맡기기에 알맞습니다.

  1. GitHub 저장소를 준비합니다.
  2. 데스크톱 앱, 브라우저, 터미널, 휴대폰, Slack 중 편한 곳에서 클라우드 세션을 시작합니다.
  3. 맡길 작업을 구체적으로 요청합니다.
  4. 진행 중 Claude가 묻는 질문에는 휴대폰에서 답하거나 방향을 바꿉니다.
  5. 여러 작업은 세션을 동시에 여러 개 돌립니다.
  6. 작업이 끝나면 변경 내용을 검토하고 PR을 만듭니다.
  • Pro, Max, Team 플랜과 일부 Enterprise 좌석에서 쓸 수 있고, 플랜 한도에 로컬 세션과 합산됩니다(가상 머신 비용은 따로 없음).
  • 원격 제어는 내 컴퓨터가 켜져 있어야 하지만 클라우드 세션은 그렇지 않습니다.

11. 자동 모드를 우리 환경에 맞게 설정하기

권한 요청의 97%가 승인될 만큼 매번 허락하는 일이 피곤해서 나온 자동 모드입니다. 별도 분류기가 사용자의 메시지와 도구 호출만 보고 의도에 맞는지 판단하며, 우리 조직 환경을 설명해 주어야 정확히 동작합니다.

  1. 관리자는 관리형 설정(managed settings)에서 환경을 정의해 모든 개발자가 상속하게 합니다.
  2. 개발자는 사용자 설정(user settings)에 자기 항목을 추가합니다.
  3. environment 필드에 GitHub 조직, 클라우드 버킷, 내부 서비스 등을 평이한 영어로 설명합니다.
  4. environment를 설정하면 기본 항목이 대체되므로 기본 문자열도 함께 넣어 유지합니다.
  5. 예외는 allow, 명시 요청 없이는 막을 동작은 soft deny, 무조건 막을 동작은 hard deny에 씁니다.
  6. 확실한 제한은 deny 규칙으로, 자동 모드에서도 확인을 받으려면 ask 규칙을 씁니다.
  • 처음에는 좁게 시작해 거부되는 항목을 보고 점차 넓힙니다.
  • 개발자는 관리자가 설정한 항목을 제거할 수 없습니다.
  • 프로덕션 인프라 변경 같은 고위험 작업은 직접 검토하세요.

12. VPS에 24시간 도는 Claude Code 서버 만들기

노트북은 꺼지면 멈추고 클라우드 세션은 내 PC 파일에 접근하지 못합니다. 전용 서버를 두면 두 장점을 합쳐, 데스크톱 앱을 꺼도 모바일 앱 코드 메뉴에서 서버 세션을 쓸 수 있습니다. (영상에 Hostinger 제휴 홍보가 포함되어 있습니다.)

  1. Hostinger에서 VPS 호스팅의 KVM 요금제를 고릅니다(일반 업무는 KVM2).
  2. 서버 위치는 가까운 곳으로, 운영체제 템플릿은 Claude Code를 선택합니다.
  3. 결제 후 VPS 설정에서 root 비밀번호를 만들어 안전한 곳에 저장합니다.
  4. VPS 관리에서 웹 콘솔을 엽니다.
  5. claude를 입력하고 테마를 고른 뒤 구독 계정 로그인을 선택합니다.
  6. 표시된 링크에서 인증 후 받은 코드를 붙여 넣고 폴더 신뢰(Yes, I trust this folder)를 선택합니다.
  7. 서버에서 adduser로 별도 claude 사용자를 만들고, 내 PC의 공개 키를 서버에 등록해 SSH로 접속되는지 확인합니다.
  8. Claude Code 데스크톱 앱에서 SSH 연결 정보를 입력하고 연결 테스트 후 SSH 연결 추가로 세션을 시작합니다.
  • API 키 방식은 과금이 클 수 있어 구독 계정 로그인을 권합니다.
  • 개인 키는 내 PC에만 두고 절대 공유하지 않습니다.
  • 권한 무시 모드는 서버처럼 격리된 환경에서만 씁니다.
  • 영상 속 일부 명령어는 자막이 불분명하므로 정확한 입력은 영상 화면을 확인하세요.
