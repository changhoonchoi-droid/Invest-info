Claude Code 기본

Claude Code는 작업 전에 권한을 묻고, CLAUDE.md·MCP·스킬로 넓혀 쓰고, 클라우드나 휴대폰에서도 작업을 이어 갈 수 있는 AI 코딩 도구입니다. 처음이라면 확장 기능이 각각 무슨 일을 하는지 먼저 익히고, 권한 규칙과 자동 모드로 안전하게 맡기는 법을 배운 뒤, 클라우드 세션·Claude 디자인·모드로 넓혀 가세요. 이번 자료에는 설치 절차가 없으니 설치는 Anthropic 공식 안내를 함께 보세요.

1. CLAUDE.md·MCP·스킬 역할 구분하기

Claude Code는 기본 대화 말고도 여러 확장 수단이 있어서, 무엇을 언제 쓰는지 알면 효과가 크게 달라집니다. 이 가이드는 각 수단이 맡는 일을 정리해, 나중에 어느 기능부터 손볼지 정하도록 돕습니다.

  1. 프로젝트에서 늘 지켜야 할 규칙과 맥락은 CLAUDE.md에 적는다고 기억합니다.
  2. Claude가 바깥 도구나 서비스를 써야 하면 MCP로 연결한다고 정리합니다.
  3. 팀이 반복해서 쓰는 지식과 작업 방법은 스킬로 묶어 둔다고 정리합니다.
  4. 여러 확장을 한 묶음으로 나눠 주고 싶으면 플러그인을 씁니다.
  5. Claude Code 화면이나 행동 방식 자체를 바꾸고 싶으면 모드(Mods)를 씁니다. 스킬·MCP는 지식과 도구를 건네고, 모드는 작업 환경을 바꿉니다.
  6. 대화가 길어지면 컨텍스트 윈도우(Claude가 한 번에 기억하는 분량)를 관리해야 한다는 점도 함께 기억합니다.
  • 공식 영상은 CLAUDE.md·MCP·스킬·자동 모드를 실전 활용의 네 축으로 꼽습니다.
  • 새 기능(원격 제어, 워크트리, 자동 메모리, 자동 코드 리뷰, 루틴, 에이전트 뷰)이 계속 더해지고 있으니 공식 '새 기능 총정리' 영상도 함께 보세요.

2. 권한 규칙으로 위험한 작업 막기

Claude Code는 파일 수정이나 명령 실행 같은 작업 전에 사용자에게 권한을 묻습니다. allow·ask·deny 규칙을 정해 두면 늘 허용할 작업, 꼭 확인받을 작업, 절대 하면 안 되는 작업을 미리 나눌 수 있습니다.

  1. Claude Code가 작업 전에 권한을 묻는 방식에 익숙해집니다. 무엇을 하려는지 읽고 승인하거나 거절합니다.
  2. 어떤 경우에도 하면 안 되는 동작은 deny 규칙으로 막습니다.
  3. 실행 전에 꼭 확인을 받고 싶은 동작은 ask 규칙에 적습니다.
  4. 매번 묻지 않아도 되는 예외 동작은 allow 규칙에 적습니다.
  5. 혼자 쓰면 사용자 설정(user settings)에, 회사 전체에 적용하려면 관리자가 관리형 설정(managed settings)에 규칙을 넣습니다.
  • 연구에서 권한 요청의 97%가 승인되었습니다. 습관처럼 승인만 누르게 된다면 규칙이나 자동 모드를 써 볼 때입니다.
  • 자동 모드를 켜도 deny·ask·allow 규칙이 먼저 적용됩니다.
  • 관리자가 관리형 설정에 넣은 항목은 개발자가 지울 수 없습니다.

3. 자동 모드를 우리 환경에 맞추기

자동 모드는 권한 요청을 사람이 하나하나 승인하지 않고, 따로 둔 분류기가 사용자의 지시와 맞는 작업인지 판단해 진행하게 합니다. 기본값으로는 작업 폴더와 git 리모트만 '우리 것'으로 보기 때문에, 회사 인프라를 알려 주는 설정이 필요합니다.

  1. 자동 모드의 원리를 이해합니다. 분류기는 사용자 메시지와 도구 호출만 보고 판단하며, Claude의 추론이나 도구 결과는 보지 않습니다.
  2. 회사 전체에 적용하려면 관리자가 관리형 설정(managed settings)에 환경을 정의합니다. 그러면 모든 개발자에게 적용됩니다.
  3. 개인 항목은 사용자 설정(user settings)에 더합니다.
  4. environment 필드에 GitHub 조직, 클라우드 버킷, 내부 서비스 등을 쉬운 영어 문장으로 적습니다.
  5. environment를 넣으면 기본 항목이 대체되므로 기본 문자열도 함께 넣습니다.
  6. 예외로 허용할 동작은 allow에, 명시적 요청 없이는 막을 동작은 soft deny에, 무조건 막을 동작은 hard deny에 적습니다.
  7. 자동 모드에서도 확인을 받고 싶은 동작은 ask 규칙에 넣습니다.
예시
Our GitHub organization is example-corp. The storage bucket example-corp-data and the internal service api.example-corp.internal belong to us.
  • 처음에는 범위를 좁게 잡고, 거부되는 항목을 보면서 조금씩 넓힙니다.
  • 읽기만 하거나 되돌릴 수 있는 작업은 분류기를 거치지 않습니다.
  • 도구 결과에 숨은 악성 지시는 서버 쪽 프로브가 먼저 검사합니다. 평가에서 자동 모드와 함께 켰을 때 프롬프트 인젝션 성공률이 0이었습니다.
  • 운영 서버 변경 같은 위험한 작업은 직접 검토하거나 자체 평가를 따로 만드세요.

4. 클라우드 세션으로 외출 중 작업 맡기기

클라우드 세션은 내 컴퓨터가 아닌 클라우드 가상 머신에서 Claude Code를 돌리는 방식입니다. 노트북을 닫아도 작업이 계속되어, 큰 리팩터링이나 마이그레이션, 퇴근 전에 맡겨 둘 일에 알맞습니다.

  1. 내 플랜이 Pro·Max·Team이거나, Enterprise라면 프리미엄 좌석 또는 Chat + Claude Code 좌석인지 확인합니다.
  2. 작업할 코드를 GitHub 저장소에 올려 둡니다. 클라우드 세션은 이 저장소를 복제해 별도 브랜치에서 작업합니다.
  3. 데스크톱 앱, 브라우저, 터미널, 휴대폰, Slack 중 편한 곳에서 클라우드 세션을 시작하고 할 일을 맡깁니다.
  4. 필요하면 세션을 여러 개 동시에 돌려 작업을 나눕니다.
  5. 이동 중에는 휴대폰으로 Claude의 질문에 답하거나 방향을 바꿔 줍니다.
  6. 작업이 끝나면 변경 내용을 검토하고 PR(풀 리퀘스트)을 만듭니다.
예시
이 저장소의 코드를 새 라이브러리 버전에 맞게 마이그레이션해 줘. 끝나면 바꾼 내용을 요약해 줘.
  • 가상 머신 비용은 따로 없지만 사용량은 로컬 세션과 함께 플랜 한도에 셉니다.
  • Remote Control은 내 컴퓨터에서 돌고 있는 세션에 연결하는 방식이라 컴퓨터가 켜져 있어야 합니다. 컴퓨터를 끄고 나갈 거라면 클라우드 세션을 쓰세요.

5. Claude 디자인으로 시안 먼저 만들기

코드를 짜기 전에 Claude 디자인으로 화면 시안을 먼저 살펴보면 결과물이 더 좋아집니다. 앱 온보딩 화면처럼 모양을 먼저 정하고 싶은 작업에 씁니다.

  1. 작업할 앱의 저장소를 Claude 디자인에 연결합니다.
  2. 만들고 싶은 화면(예: 온보딩)의 시안을 요청합니다.
  3. 시안에 댓글을 달아 고칠 점을 알려 줍니다.
  4. 필요한 부분은 직접 수정합니다.
  5. 클릭해 볼 수 있는 프로토타입으로 만들어 흐름을 확인합니다.
  6. 마음에 들면 구현 단계로 넘어갑니다.
예시
앱을 처음 켠 사람이 보는 온보딩 화면 시안을 서로 다른 방향으로 몇 가지 보여 줘.
  • 디자인에 시간을 더 쓰고 싶을 때 바로 코드로 가지 말고 짧게 시안부터 탐색하라는 것이 영상의 핵심입니다.

6. 모드로 작업 환경 바꿔 보기

모드(Mods)는 Claude Code의 모습과 행동 방식을 바꾸는 작은 프로그램입니다. Claude가 작업할 때마다 나가는 신호를 듣고 반응하며, 창·버튼 같은 화면 요소는 모드로만 만들 수 있다고 소개됩니다.

  1. 모드가 하는 일 세 가지를 알아 둡니다. 신호를 듣고 지켜보기, 살짝 고치기, 대신 처리하기입니다.
  2. 만들 모드가 셋 중 어떤 일을 할지 정합니다.
  3. 영상처럼 데스크톱 앱에서 작은 모드부터 시작합니다. 예: 토큰 사용량 표시, 다음 작업 추천.
  4. 익숙해지면 픽셀 병아리 같은 장식형 모드나, 내 사용 패턴에 맞춰 추천해 주는 모드로 넓혀 봅니다.
  • 지식이나 도구를 건네고 싶으면 스킬·MCP를, 작업 환경 자체를 바꾸고 싶으면 모드를 쓰세요.
  • 10월 1일 공식 발표된 새 기능이라 바뀔 수 있습니다. 쓰기 전에 최신 안내를 확인하세요.
