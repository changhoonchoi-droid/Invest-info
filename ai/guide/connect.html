MCP·커넥터 연결

MCP와 커넥터를 쓰면 Claude가 Gmail·캘린더·노션·Slack 같은 업무 도구와 웹 브라우저를 직접 다루며 자료 수집, 문서 작성, 반복 업무 자동화를 대신 해 줍니다. 처음이라면 앱 화면에서 커넥터를 연결하고 예약 작업을 거는 것부터 시작하세요. 그다음 브라우저 자동화, 마지막으로 Claude Code·안티그래비티에 MCP 서버를 직접 붙이는 순서로 보면 좋습니다.

1. Claude에 커넥터 연결하기

커넥터는 Claude가 Gmail, 구글 캘린더, 노션 같은 업무 도구의 자료를 읽고 쓸 수 있게 이어 주는 기능입니다. 한 번 연결해 두면 대화, 코워크 작업, 예약 작업, PowerPoint 애드인에서 모두 같은 커넥터를 쓸 수 있습니다.

  1. Claude 입력창 옆의 플러스 버튼을 누릅니다.
  2. 커넥터 → 커넥터 추가 → 커넥터 둘러보기로 들어갑니다.
  3. Gmail, 구글 캘린더, 노션 등 연결할 서비스를 검색합니다.
  4. 서비스 옆 플러스 버튼을 누르고 해당 계정으로 로그인해 인증합니다.
  5. 대화나 코워크 작업에서 연결한 도구의 자료를 쓰는 일을 요청해 제대로 동작하는지 확인합니다.
예시
Gmail에서 지난 한 주 받은 이메일 중 답장이 필요한 것을 정리해 줘.
  • Claude에 설정해 둔 커넥터는 PowerPoint용 Claude 애드인에도 그대로 적용되어, Google Drive·Notion·Confluence 자료로 슬라이드를 만들 수 있습니다.
  • 연결할 수 있는 커넥터 목록은 claude.com/connectors에서 미리 볼 수 있습니다.
  • 웹 버전은 로컬 파일 접근과 컴퓨터 직접 조작이 안 되므로, 그런 작업은 데스크톱 앱에서 하세요.

2. 코워크 예약 작업으로 반복 업무 맡기기

매주 월요일 메일 정리, 매일 아침 할 일 브리핑처럼 정해진 시각에 반복되는 일을 Claude 코워크에 맡기는 기능입니다. 커넥터와 함께 쓰면 메일·캘린더·Slack을 확인해 문서와 답장 초안까지 자동으로 만들어 둡니다.

  1. 예약 작업에 쓸 Gmail·캘린더 등 커넥터를 먼저 연결해 둡니다.
  2. 새 작업에서 협업을 누르고 새 프로젝트를 만듭니다.
  3. 언제, 무엇을 확인해, 어떤 결과물을 남길지 한 문장으로 요청합니다.
  4. Claude가 만든 예약 작업 프롬프트 초안과 실행 주기를 확인하고 필요하면 고칩니다.
  5. 승인 버튼을 눌러 예약을 확정합니다.
  6. 실행 뒤 좌측 코워크 탭에서 작업 내역과 결과를 확인합니다.
예시
매주 월요일 아침 7시에 지난 한 주 받은 이메일 중 답장이 필요한 것을 정리하고, 고객 미팅 브리핑 문서를 만들고, 필요한 후속 이메일은 초안으로 남겨 줘.
  • 예전 방식: 예약 작업은 컴퓨터가 켜져 있고 데스크톱 앱이 열려 있을 때만 실행됐습니다. 2026년 7월 7일 업데이트 뒤로는 클라우드에서 돌아 기기가 꺼져 있어도 실행됩니다.
  • 예약 작업은 실행마다 새 세션으로 돌아 그때의 최신 파일과 도구 상태를 기준으로 합니다.
  • 마음에 든 업무 과정은 스킬로 저장해 두면 매주 같은 방식으로 실행되고 팀과도 공유할 수 있습니다.
  • 승인이 필요한 단계는 모바일로도 요청이 오며 데스크톱 앱과 똑같이 처리할 수 있습니다.

3. Claude in Chrome으로 웹 작업 맡기기

Claude in Chrome은 Claude가 웹페이지를 읽고 클릭·입력까지 하게 해 주는 크롬 확장입니다. 코워크에 커넥터로 연결하면 크롬은 웹 데이터를 모으고, 코워크는 그 자료로 엑셀·문서 보고서를 만들도록 역할을 나눌 수 있습니다.

  1. 크롬 웹스토어에서 클로드를 검색해 Claude in Chrome 베타를 찾습니다.
  2. Chrome에 추가를 누르고 승인한 뒤 로그인합니다.
  3. 크롬 오른쪽 위 퍼즐 버튼에서 클로드 확장을 핀으로 고정합니다.
  4. 클로드 데스크톱 앱의 설정 → 커넥터 탭에서 Claude in Chrome을 찾아 구성을 누릅니다.
  5. 커넥터를 활성화합니다.
  6. 코워크의 + 버튼 → 커넥터에서 Claude in Chrome을 켜고 웹 작업을 요청합니다.
  • Pro 플랜은 경량 모델만 쓸 수 있어, 복잡한 작업은 Sonnet 이상을 쓰는 Max·Team·Enterprise가 낫습니다.
  • 민감한 작업에서는 실행 전에 확인을 받는 Ask before acting 모드를 켜세요.
  • 악의적인 웹사이트에 숨은 지시(프롬프트 인젝션)에 조작될 수 있고, 사람이 직접 할 때보다 느리며 사용량도 많이 듭니다.
  • 캡차와 로그인은 직접 처리해야 하므로 80% 자동화, 20% 사람 확인을 기대하는 게 현실적입니다.

4. 어사이드 브라우저를 Codex에 연결하기

어사이드(Aside)는 AI가 클릭과 입력을 대신해 주는 크롬 같은 웹 브라우저입니다. GPT Codex 데스크톱 앱에 연결하면 메일 확인, 사내 사이트 조회처럼 로그인이 필요한 웹 업무도 말로 시킬 수 있습니다.

  1. PC에 Claude 데스크톱 앱과 GPT의 Codex 앱을 설치합니다.
  2. 어사이드를 설치하고 쓰고 있는 GPT·Claude 계정을 연결합니다.
  3. 어사이드 하단에서 모델을 고릅니다. 요금제가 낮으면 가성비 좋은 균형형 모델을 씁니다.
  4. 크롬의 비밀번호와 즐겨찾기를 어사이드로 가져옵니다.
  5. Codex를 열고 시작하기를 진행하면서 승인 요청에서 전체 액세스를 켭니다.
  6. 터미널을 열어 영상에서 안내한 어사이드 연결 문구를 복사해 붙여 넣습니다.
  7. Codex에 어사이드를 쓰라고 지정해 일을 시키고, 어사이드 창에서 실제로 작동하는지 확인합니다.
예시
어사이드를 활용해서 오늘 받은 메일을 확인해 줘.
  • 전체 액세스는 모든 권한을 여는 설정이라 보안 위험이 있으니 회사 PC라면 먼저 사내 규정을 확인하세요.
  • 요청할 때 어사이드를 활용하라고 분명히 지정할수록 정확해집니다.
  • 크롬 로그인 정보가 제대로 옮겨졌는지 확인하고, 안 됐다면 GPT에 시켜 연결합니다.
  • 이미 GPT·Claude를 유료로 쓰고 있으면 어사이드에는 따로 비용을 내지 않아도 됩니다.

5. Slack 채널에 Claude 들이기

Claude Tag는 Slack 같은 팀 워크스페이스의 채널에 Claude를 추가해, 팀 대화를 따라가며 정리·문서 초안·도구 내 수정까지 하게 하는 기능입니다. 채팅 창을 오가거나 맥락을 복사해 붙일 필요 없이 채널에서 바로 일을 맡길 수 있습니다.

  1. 회사 Claude 계정이 Team 또는 Enterprise 요금제인지 확인합니다.
  2. 관리자가 팀 워크스페이스의 채널에 Claude Tag를 추가합니다.
  3. 채널마다 Claude가 맡을 일, 개입 빈도, 자율 범위를 정합니다.
  4. 필요하면 다른 공개 채널의 정보에 접근할 수 있게 허용합니다.
  5. 채널에서 Claude에게 정리나 문서 초안 같은 작업을 요청합니다.
  6. Claude가 남긴 변경 내역과 요청자 기록을 확인합니다.
  • DM과 비공개 채널은 비공개로 유지되어 Claude가 보지 않습니다.
  • Claude는 별도의 자체 계정으로 작업하고 모든 변경과 요청자를 기록하므로, 누가 무엇을 시켰는지 나중에 추적할 수 있습니다.
  • 채널별 지침을 기억하므로 채널마다 역할을 나눠 두면 편합니다.

6. Claude Code에 MCP 서버 연결하기

MCP는 Claude Code를 GitHub, Linear, 문서 서버 같은 외부 도구와 데이터에 연결하는 개방형 표준입니다. 원격 서비스는 HTTP, 내 PC에서 도는 프로그램은 STDIO 방식으로 붙이고, 범위를 정해 나만 쓰거나 팀과 공유합니다.

  1. 연결할 서비스가 원격이면 HTTP, 내 PC에서 도는 프로세스면 STDIO 유형을 고릅니다.
  2. 터미널에서 claude mcp add 명령으로 서버를 추가합니다.
  3. Claude Code 세션 안에서 /mcp를 실행해 연결 상태를 확인합니다.
  4. 쓰지 않을 서버는 /mcp에서 비활성화합니다.
  5. 팀과 공유하려면 프로젝트 범위로 추가해 .mcp.json을 버전 관리에 올립니다.
예시
/mcp
  • 범위는 local(현재 프로젝트, 나만), user(모든 프로젝트), project(.mcp.json, 팀 공유) 세 가지입니다.
  • MCP 서버는 쓰지 않을 때도 도구 정의가 컨텍스트를 차지합니다. 도구 정의가 컨텍스트 창의 10%를 넘으면 Claude Code가 자동으로 도구 검색 모드로 바뀝니다.
  • GitHub의 gh, AWS의 aws처럼 CLI가 있는 서비스는 CLI를 쓰는 편이 컨텍스트 효율이 좋고, CLI 사용법은 스킬에 넣어 두면 필요할 때만 불러옵니다.
  • 라이브러리 최신 문서가 필요하면 Context7 MCP 서버를 쓸 수 있습니다.

7. 안티그래비티에 NotebookLM 연결하기

구글의 개발 환경 도구 안티그래비티의 AI 에이전트에 NotebookLM MCP를 연결하면, 노트북 생성·소스 추가·분석을 에이전트가 대신 해 줍니다. 손으로 소스를 넣고 결과를 복사하던 반복 작업을 줄이고, 분석 결과로 랜딩 페이지 같은 결과물까지 이어서 만들 수 있습니다.

  1. 구글에서 안티그래비티를 검색해 사이트의 다운로드로 내 운영체제에 맞게 설치합니다.
  2. 화면 오른쪽 위 토글 에이전트를 눌러 프롬프트 입력창을 엽니다.
  3. 노트북 LM MCP를 검색해 첫 번째 사이트를 열고, 다른 MCP 클라이언트용 설정 코드를 전부 복사합니다.
  4. 에이전트의 점 세 개 Additional Options에서 MCP 서버를 열고 Manage MCP Servers를 누릅니다.
  5. View raw config 파일에 복사한 코드를 붙여 넣고 Ctrl+S로 저장합니다.
  6. Refresh를 눌러 NotebookLM이 연결된 것을 확인합니다.
  7. 프롬프트에 연결 확인을 요청한 뒤 인증 진행해 줘로 구글 계정 로그인을 마칩니다.
예시
노트북 LM MCP 연결되었는지 확인해 줘
  • 어떤 MCP를 연결하든 먼저 연결 확인을 요청해 보는 것이 좋습니다.
  • 안티그래비티는 NotebookLM MCP 안내 페이지의 목록에 없어서 설정 코드를 직접 붙여 넣어야 합니다.
  • NotebookLM은 올린 자료(PDF·웹사이트·유튜브·구글 독스)에서만 답하고 출처를 표시하므로 근거가 필요한 조사에 알맞습니다.

8. BigQuery MCP로 데이터 분석하기

데이터 팀이 BigQuery MCP로 제품 데이터를 Claude Code에 연결해 두면, SQL을 몰라도 말로 지표를 조회하고 그래프를 만들 수 있습니다. 몇 시간 걸리던 분석이 몇 분으로 줄어 결과 해석에 집중할 수 있습니다.

  1. 데이터 팀에 BigQuery MCP로 제품 데이터 테이블을 Claude Code에 연결해 달라고 요청합니다.
  2. Claude Code에서 보고 싶은 지표와 기간을 말합니다.
  3. 조회할 데이터 테이블 이름을 알려 줍니다.
  4. 파일 수정 권한 요청이 나오면 내용을 보고 허용합니다.
  5. 만들어진 그래프를 확인합니다.
  6. '요금제별로 나눠 달라'처럼 후속 요청으로 분석을 다듬습니다.
예시
제품 데이터 테이블에서 다크 모드 사용 비율을 그래프로 그려 줘. 이어서 요금제별로 나눠서 다시 그려 줘.
  • 요청하지 않은 7일 이동평균 같은 요소가 추가될 수 있으니 그래프를 꼭 확인하세요.
  • SQL 작성보다 결과를 해석하는 역할이 중요해집니다.
  • Google Cloud 환경이라면 BigQuery와 Looker MCP 툴박스로 분석 대시보드까지 연결할 수 있습니다.

9. 브라우저로 결과를 검증하게 하기

Claude Code는 테스트·린터는 스스로 돌리지만, 화면이 실제로 의도대로 동작하는지는 브라우저에서 확인해야 압니다. Playwright MCP와 검증 스킬을 쓰면 Claude가 앱을 직접 실행해 확인하고, 고친 뒤 다시 확인하는 과정을 혼자 반복합니다.

  1. Claude Code에 Playwright MCP를 연결합니다.
  2. Claude Code에 포함된 verify 스킬로 프로젝트의 확인 절차를 스킬로 만듭니다.
  3. 생성된 스킬에 성능 측정처럼 꼭 확인할 항목을 추가합니다.
  4. 프롬프트에 설계 문서(spec)를 읽고 Playwright MCP를 쓰라고 명시한 뒤 구현할 기능을 구체적으로 요청합니다.
  5. Claude가 앱을 실행해 현재 화면을 확인하는 과정을 지켜보고, 파일 변경 권한 요청은 검토 후 허용합니다.
  6. Claude가 수정과 검증을 반복한 뒤 내놓는 변경 요약으로 결과를 리뷰합니다.
  • 검증 기준이 측정 가능할수록(예: 레이아웃 시프트 같은 Core Web Vitals 지표) Claude가 더 멀리 혼자 갑니다.
  • 구현 전에 현재 화면을 먼저 확인시키면 비교 기준이 정확해집니다.
  • 웹은 브라우저, 백엔드는 엔드포인트 호출, 모바일은 iOS 시뮬레이터로 확인 절차를 만들 수 있습니다.
  • 예전 방식: 프롬프트마다 Playwright MCP를 쓰라고 적었다면, 지금은 확인 절차를 스킬로 저장해 두고 매번 자동으로 쓰게 하는 것이 권장됩니다.

10. n8n MCP 연결하고 스킬로 바꾸기

Docker에서 돌리는 n8n을 MCP로 Claude Code에 연결하면 자동화 워크플로우를 말로 만들 수 있습니다. 다만 MCP는 도구 정의가 세션 내내 토큰을 차지하므로, 익숙해진 작업은 필요할 때만 불러오는 스킬로 바꾸면 더 효율적입니다.

  1. Docker Desktop에서 n8n 컨테이너를 실행하고 n8n API 키를 발급받습니다.
  2. n8n MCP를 검색해 GitHub 페이지에서 Claude Code 연결 방법을 엽니다.
  3. 전체 설정(full configuration)을 복사해 Claude Code 명령 입력 위치에 붙여 넣습니다.
  4. 설정 속 API URL을 localhost:5678 주소로, API 키를 발급받은 키로 바꿉니다.
  5. /mcp를 입력해 n8n MCP가 연결되었는지 확인합니다.
  6. 자연어로 워크플로우 생성을 요청합니다.
  7. 스킬 크리에이터로 이 n8n 작업을 스킬로 만든 뒤 MCP를 해제하고 같은 작업이 재현되는지 확인합니다.
예시
n8n MCP로 간단한 AI 챗봇 만들어 줘
  • 워크플로우의 OpenAI 모델 노드에는 OpenAI API 키를 따로 등록해야 합니다.
  • 스킬은 시작할 때 메타데이터만 읽고 쓸 때만 내용을 불러와 MCP보다 토큰 부담이 적습니다.
  • 토큰 최적화 규칙을 CLAUDE.md에 저장해 두고 시작하면 좋습니다.
