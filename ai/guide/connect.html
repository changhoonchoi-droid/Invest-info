MCP·커넥터 연결

MCP와 커넥터를 쓰면 Claude가 구글 드라이브·Slack·Gmail·Notion 같은 업무 도구에서 자료를 직접 읽고 쓰며, 브라우저를 열어 클릭과 입력까지 대신합니다. 처음이라면 Cowork와 PowerPoint에서 커넥터를 연결해 보고, 예약 작업과 팀 채널 활용으로 넓힌 다음, AI 브라우저와 Claude Code의 MCP 서버 연결로 넘어가면 좋습니다.

1. Cowork에 커넥터 연결해 업무 맡기기

Claude Cowork에 캘린더·Slack·이메일 같은 커넥터를 연결하면 여러 도구에 흩어진 정보를 Claude가 한꺼번에 모아 문서로 정리합니다. 회의 준비, 고객 미팅 브리핑, 밀린 메일과 대화 따라잡기처럼 자료를 찾아 모으는 일에 씁니다.

  1. Claude 데스크톱 앱에서 Cowork를 엽니다.
  2. 업무에 쓰는 캘린더·Slack·이메일 등을 커넥터로 연결합니다.
  3. 할 일을 한 문장으로 요청합니다. 예: 내일 회의 준비 문서 만들기
  4. 작업 중에 빠진 출처를 추가하거나 고칠 점을 말해 방향을 바꿉니다.
  5. 완성된 문서가 작업 폴더에 저장되면 내용을 직접 확인하고 다듬습니다.
  6. 메일 답장이나 Slack 메시지 초안은 하나씩 검토한 뒤 승인해 보냅니다.
예시
캘린더에서 내일 회의를 찾고, 관련 Slack 대화와 이메일을 읽어서 회의 준비 문서를 만들어 줘. 참석자, 지난 논의 내용, 확인할 질문을 정리해 줘.
  • 작업 도중 수정을 요청해도 처음부터 다시 하지 않고 이어서 진행합니다.
  • 결과물의 최종 소유와 수정은 사용자 몫이니, 브리핑의 근거는 원문에서 직접 확인합니다.
  • 자주 하는 과정은 스킬로 저장해 두면 매주 같은 방식으로 실행하고 팀과 공유할 수 있습니다.
  • 커넥터 목록은 claude.com/connectors 에서 볼 수 있습니다.

2. PowerPoint에서 커넥터 자료 쓰기

PowerPoint용 Claude 애드인에서 파일을 올리거나 Google Drive·Notion·Confluence 커넥터로 외부 자료를 불러와 슬라이드를 만듭니다. 보고서나 데이터를 발표 자료로 바꾸거나, 기존 덱의 논지와 출처를 확인할 때 씁니다.

  1. Claude AI에서 Google Drive·Notion·Confluence 등 커넥터를 먼저 설정합니다.
  2. PowerPoint에서 Claude 애드인을 엽니다.
  3. + 버튼으로 보고서·데이터·분석 파일을 올립니다.
  4. 커넥터의 자료를 읽어 슬라이드를 만들어 달라고 요청합니다.
  5. 기존 덱이면 슬라이드별 논지 요약이나 특정 슬라이드의 출처를 물어봅니다.
  6. 완성된 슬라이드가 회사 브랜드 지침에 맞는지 직접 확인합니다.
예시
올린 분석 파일을 바탕으로 핵심 결과 5장짜리 슬라이드를 만들어 줘. 그리고 지금 덱의 슬라이드별 논지를 한 줄씩 요약해 줘.
  • Claude AI에 설정해 둔 커넥터는 애드인에도 그대로 적용됩니다.
  • 작업 결과를 커넥터로 연결된 도구에 다시 쓸 수도 있습니다.
  • 슬라이드 마스터·레이아웃·글꼴·색상을 따르지만, 복잡한 템플릿은 꼭 직접 점검합니다.

3. 커넥터 업무를 예약 작업으로 돌리기

매일 아침 메일 정리, 매주 지표 리뷰처럼 반복되는 일을 정해진 시각에 Cowork가 알아서 실행하게 합니다. 연결해 둔 커넥터를 예약 작업에서도 그대로 쓸 수 있어, 출근 전에 자료가 준비되어 있게 할 수 있습니다.

  1. Cowork에서 반복할 업무를 한 번 직접 시켜 보고 결과가 마음에 드는지 확인합니다.
  2. 이 작업을 정기적으로 실행하고 싶다고 Claude에게 말합니다.
  3. Claude가 만든 예약 작업 프롬프트 초안을 읽고 필요한 부분을 고칩니다.
  4. 실행 주기를 확인하고 수정한 뒤 승인해 등록합니다.
  5. 실행 시각에 컴퓨터를 켜 두고 데스크톱 앱을 열어 둡니다.
예시
매일 아침 Gmail을 확인해서 오늘 처리할 일을 정리해 주는 작업을 평일마다 실행하도록 예약해 줘.
  • 예약 작업은 실행마다 새 세션으로 돌아가 그때의 최신 파일과 도구 상태를 기준으로 합니다.
  • 컴퓨터가 꺼져 있거나 데스크톱 앱이 닫혀 있으면 실행되지 않습니다.
  • 데이터가 맞지 않으면 Claude가 추측하지 않고 질문하므로, 결과의 숫자는 출처를 함께 확인합니다.
  • 실행 후 배운 점을 스킬에 저장해 두면 다음 회차에 반영됩니다.

4. Slack 채널에 Claude Tag 들이기

Claude Tag는 Slack 같은 팀 워크스페이스 채널에 Claude를 추가해 팀 대화를 따라가며 일하게 하는 기능입니다. 채팅 창을 오가거나 맥락을 복사할 필요 없이 채널에서 바로 정보 정리, 문서 초안, 도구 내 수정을 요청할 수 있습니다.

  1. 회사가 Claude Team 또는 Enterprise 계정을 쓰는지 확인합니다.
  2. 관리자가 Claude를 쓸 팀 채널에 추가합니다.
  3. 채널마다 Claude가 맡을 일, 개입 빈도, 자율 범위를 정합니다.
  4. 필요하면 다른 공개 채널의 정보에 접근할 수 있게 허용합니다.
  5. 채널에서 Claude에게 정리나 초안 작성 같은 일을 요청합니다.
  6. 기록된 변경 내역과 요청자를 확인해 결과를 점검합니다.
  • DM과 비공개 채널의 내용은 비공개로 유지됩니다.
  • Claude는 별도의 자체 계정으로 작업하며 모든 변경과 요청자를 기록합니다.
  • 채널별 지침을 기억하므로 처음에 채널의 역할을 분명히 알려 두면 좋습니다.

5. 어사이드 브라우저로 웹 일 시키기

어사이드(Aside)는 AI가 클릭하고 입력하는 일을 대신하는 크롬 같은 AI 웹 브라우저입니다. Codex에 연결하면 메일 확인, 사내 사이트 조회, SNS 계정 탐색처럼 로그인이 필요한 웹 업무를 말로 시킬 수 있습니다.

  1. PC에 Claude 데스크톱 앱과 GPT의 Codex 앱을 설치합니다.
  2. 어사이드를 설치하고 쓰고 있는 GPT·Claude 계정을 연결합니다.
  3. 어사이드 하단에서 모델을 고릅니다.
  4. 크롬의 비밀번호와 즐겨찾기를 어사이드로 가져옵니다.
  5. Codex를 열어 시작하기를 진행하고 승인 요청에서 전체 액세스를 켭니다.
  6. 터미널을 열어 영상에서 안내한 어사이드 연결 문구를 붙여 넣습니다.
  7. Codex에 어사이드를 쓰라고 지정해 일을 시키고, 어사이드 창에서 실제 작동을 지켜봅니다.
예시
어사이드를 활용해서 내 메일함을 열고 오늘 온 메일 중 답장이 필요한 것만 정리해 줘.
  • 이미 GPT나 Claude를 유료로 쓰고 있으면 어사이드에는 따로 비용이 들지 않는다고 합니다.
  • 전체 액세스는 모든 권한을 여는 설정이라 보안 위험이 있으니 회사 보안 규정을 먼저 확인합니다.
  • 요청할 때 '어사이드를 활용해'라고 지정할수록 정확해집니다.
  • 크롬 로그인 정보가 제대로 옮겨졌는지 확인하고, 안 됐다면 GPT에 연결을 시킵니다.

6. Claude Code에 MCP 서버 연결하기

MCP는 Claude Code를 GitHub, Linear, 문서 서버 같은 외부 도구와 데이터에 연결하는 개방형 표준입니다. 필요한 서버만 추가해 켜 두고, 팀과 같은 설정을 공유할 수 있습니다.

  1. 연결할 서비스가 원격 서비스면 HTTP, 내 PC에서 도는 프로그램이면 STDIO 유형을 고릅니다.
  2. 터미널에서 claude mcp add 명령으로 서버를 추가합니다.
  3. Claude Code 세션에서 /mcp를 실행해 연결 상태를 확인합니다.
  4. 당장 쓰지 않는 서버는 /mcp에서 비활성화합니다.
  5. 팀과 공유하려면 프로젝트 범위로 추가해 .mcp.json을 버전 관리에 올립니다.
예시
/mcp
  • 범위는 local(현재 프로젝트, 나만), user(모든 프로젝트), project(.mcp.json, 팀 공유) 세 가지입니다.
  • 서버는 쓰지 않을 때도 도구 정의가 컨텍스트를 차지하며, 10%를 넘으면 Claude Code가 도구 검색 모드로 자동 전환합니다.
  • GitHub의 gh, AWS의 aws처럼 CLI가 있으면 컨텍스트 효율이 더 좋고, 사용법은 스킬에 넣어 두면 됩니다.
  • Context7 MCP 서버를 쓰면 사용 중인 라이브러리의 최신 문서를 받아 볼 수 있습니다.

7. 브라우저로 결과 검증 루프 만들기

Claude가 브라우저를 직접 열어 클릭하고 화면을 확인하게 하면, 고친 기능이 실제로 의도대로 동작하는지 스스로 검증하고 다시 고칩니다. 테스트만으로는 확인되지 않는 화면 동작을 점검할 때 씁니다.

  1. Claude Code에 포함된 verify 스킬로 프로젝트의 확인 절차 스킬을 만듭니다.
  2. 만들어진 스킬에 브라우저 클릭, 콘솔 확인, 성능 측정 같은 확인 항목을 더합니다.
  3. 설계 문서(spec)가 있으면 읽도록 프롬프트에 지정합니다.
  4. 브라우저 확인 도구(예: Playwright MCP)를 쓰라고 프롬프트에 명시하고 구현할 기능을 구체적으로 요청합니다.
  5. 파일 변경 권한 요청이 나오면 검토 후 허용합니다.
  6. Claude가 변경과 검증을 반복한 뒤 내놓는 요약으로 결과를 검토합니다.
예시
설계 문서를 먼저 읽고, Playwright MCP를 사용해서 앱의 현재 화면을 확인한 뒤 CSV 파일 미리보기 기능을 구현하고 브라우저에서 동작을 검증해 줘.
  • 검증 기준을 측정 가능하게 적을수록 Claude가 더 멀리 혼자 갑니다.
  • 구현 전에 현재 화면을 먼저 확인시키면 기준이 정확해집니다.
  • 백엔드는 엔드포인트 호출, 모바일은 iOS 시뮬레이터로도 확인 절차를 만들 수 있습니다.
  • 예전 방식: 매번 프롬프트에 Playwright MCP를 쓰라고 적었지만, 지금은 확인 절차를 스킬로 저장해 두고 반복해서 씁니다.

8. 클라우드에서 MCP 도구 연결하기

Google Cloud나 Microsoft Foundry에서 Claude를 쓰면 회사 클라우드 안에서 MCP 서버와 커넥터를 붙여 에이전트를 만들 수 있습니다. 데이터를 회사 프로젝트 안에 두면서 BigQuery 같은 사내 데이터나 업무 도구를 연결해야 할 때 씁니다.

  1. 회사가 쓰는 클라우드(Google Cloud 또는 Microsoft Foundry)에서 Claude 모델을 사용할 수 있게 준비합니다.
  2. Google Cloud라면 인증을 애플리케이션 기본 자격 증명(ADC)으로 설정합니다.
  3. 데이터 분석이 필요하면 BigQuery와 Looker MCP 툴박스를 연결합니다.
  4. Microsoft Foundry라면 Claude 모델을 배포하고 에이전트에 연결한 뒤 커넥터·MCP 도구를 붙입니다.
  5. 보안·규정 준수 담당자와 함께 접근 범위를 검토하고 평가(evals)로 결과를 확인한 뒤 운영에 씁니다.
  • ADC를 쓰면 API 키 교체가 필요 없어 설정이 가장 간단합니다.
  • Google Cloud에서는 토큰 단위로 과금되어 메시지 한도가 없습니다.
