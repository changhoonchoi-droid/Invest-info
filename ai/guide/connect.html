MCP·커넥터 연결

MCP·커넥터를 연결하면 Claude가 캘린더, Slack, 이메일 같은 업무 도구와 브라우저를 직접 쓰면서 문서 작성, 반복 업무 자동화, 결과 확인까지 맡을 수 있습니다. 처음이라면 Cowork에 커넥터를 연결해 일을 한 번 맡겨 보세요. 그다음 예약 작업으로 반복 업무를 자동화하고, 팀 채널 연동, 브라우저 검증, 자체 MCP 설계 순서로 넓혀 가면 됩니다.

MCP 서버, 커넥터(구글·노션·슬랙 등), 브라우저·컴퓨터 사용, 외부 도구 연결 · 영상 6개 기반 · 2026-10-22 갱신

최근 바뀐 점

  • Claude Tag가 나왔습니다. Slack 같은 팀 워크스페이스 채널에 Claude를 추가하면 팀 대화를 실시간으로 따라가며 채널에서 바로 작업을 처리합니다(Team·Enterprise 계정).
  • Claude Code에 포함된 verify 스킬로 프로젝트 전용 검증 스킬을 만들 수 있습니다. 이 스킬이 있으면 Claude가 브라우저 확인까지 직접 하면서 고치고 다시 확인하는 검증 루프를 돌립니다.

1. Cowork에 커넥터 연결해 업무 맡기기

Claude Cowork에 캘린더·Slack·이메일 같은 커넥터를 연결하면 여러 도구에 흩어진 정보를 모아 문서로 만들어 줍니다. 회의 준비 문서처럼 자료를 여기저기서 모아야 하는 업무를 맡길 때 씁니다.

  1. Claude 데스크톱 앱에서 Cowork를 엽니다.
  2. 업무에 필요한 커넥터(캘린더, Slack, 이메일 등)를 연결합니다.
  3. 맡길 일과 원하는 결과물을 한 번에 요청합니다.
  4. 작업이 진행되는 동안 빠진 출처가 있으면 추가하고, 방향이 다르면 수정을 요청합니다. 처음부터 다시 하지 않고 이어서 고칩니다.
  5. 작업 폴더에 저장된 문서를 열어 직접 검토하고 마무리합니다.
예시
내일 회의 일정을 캘린더에서 확인하고, 관련 Slack 대화와 이메일을 참고해서 회의 준비 문서를 만들어 줘.
  • 완성된 문서의 최종 소유와 수정은 사용자 몫입니다. 보내기 전에 꼭 직접 확인하세요.
  • 중간에 수정을 요청해도 앞서 한 작업은 그대로 이어지므로 완벽하게 요청하려고 처음부터 길게 쓰지 않아도 됩니다.

2. Cowork 예약 작업으로 반복 업무 자동화하기

매일 또는 매주 반복하는 업무를 정한 시간에 Cowork가 자동으로 실행하게 하는 기능입니다. 한 번 해 보고 결과가 마음에 든 작업을 정기 업무로 돌릴 때 씁니다.

  1. 반복할 작업을 Cowork에서 먼저 한 번 실행해 결과가 원하는 대로 나오는지 확인합니다.
  2. Claude에게 이 작업을 예약 작업으로 만들어 달라고 요청합니다.
  3. Claude가 써 준 프롬프트 초안을 읽고 필요한 부분을 고칩니다.
  4. 실행 주기(예: 평일 오후 4시)를 확인하고 필요하면 바꿉니다.
  5. 내용을 승인해 예약 작업을 등록합니다.
  6. 예약 시간에 컴퓨터가 켜져 있고 데스크톱 앱이 열려 있는지 확인합니다.
예시
방금 만든 회의 준비 문서 작업을 평일 오후 4시마다 자동으로 실행하는 예약 작업으로 만들어 줘.
  • 예약 작업은 실행할 때마다 새 Cowork 세션으로 돌아가므로 늘 그 시점의 최신 파일과 도구 상태를 기준으로 합니다.
  • 미리 설정해 둔 커넥터는 예약 작업에서도 그대로 쓸 수 있습니다.
  • 컴퓨터가 꺼져 있거나 데스크톱 앱이 닫혀 있으면 예약 작업이 실행되지 않습니다.

3. Claude Tag로 팀 채널에 Claude 넣기

Claude Tag는 Slack 같은 팀 워크스페이스 채널에 Claude를 추가해 팀 대화를 실시간으로 따라가며 일하게 하는 기능입니다. 채팅 창을 오가거나 맥락을 복사해 붙이지 않고, 채널에서 바로 정보 정리, 문서 초안 작성, 도구 안 수정까지 맡길 때 씁니다.

  1. 사용하는 계정이 Team 또는 Enterprise인지 확인합니다.
  2. Slack 같은 팀 워크스페이스에서 Claude를 쓸 채널에 Claude를 추가합니다.
  3. 채널마다 Claude가 맡을 일, 대화에 끼어드는 빈도, 스스로 처리할 수 있는 범위를 정합니다.
  4. 다른 공개 채널의 정보가 필요하면 그 채널에 접근 권한을 줍니다.
  5. 채널에서 바로 Claude에게 정리, 초안 작성, 도구 수정 같은 작업을 요청합니다.
  6. 작업이 끝나면 기록된 변경 내역과 요청자를 확인합니다.
예시
이 채널에서 이번 주에 논의한 내용을 정리해서 공유 문서 초안으로 만들어 줘.
  • DM과 비공개 채널은 비공개로 유지되고, 다른 공개 채널은 접근 권한을 준 경우에만 참고합니다.
  • Claude는 별도 계정으로 작업하며 모든 변경과 요청자를 기록하므로 누가 무엇을 시켰는지 추적할 수 있습니다.
  • 채널별 지침을 기억하므로 채널 용도에 맞는 규칙을 처음에 알려 두면 좋습니다.
  • 관리자는 채널마다 접근 범위와 자율성을 조절할 수 있습니다.

4. 브라우저 확인까지 맡기는 검증 루프 만들기

Claude Code는 테스트, 타입 검사, 린터를 스스로 돌리지만, 그것만으로는 변경이 의도대로 동작하는지 증명되지 않습니다. 브라우저에서 클릭하고 콘솔을 확인하던 수동 절차를 프로젝트 스킬로 만들어 두면 Claude가 직접 확인하고, 고치고, 다시 확인합니다.

  1. Claude Code에 포함된 verify 스킬로 프로젝트 전용 검증 스킬을 만듭니다.
  2. 평소 손으로 하던 확인 절차(브라우저에서 클릭하고 콘솔 보기 등)를 스킬에 적습니다.
  3. 프로젝트 종류에 맞게 확인 방법을 정합니다. 웹은 브라우저, 백엔드는 엔드포인트 호출, 모바일은 iOS 시뮬레이터로 확인합니다.
  4. 만들어진 스킬에 성능 측정 같은 확인 항목을 더합니다.
  5. 수정을 요청하고, Claude가 검증 스킬을 실행해 문제를 고친 뒤 다시 확인하는지 지켜봅니다.
예시
이 프로젝트의 검증 스킬에 페이지를 불러올 때 레이아웃 시프트를 측정하는 확인 항목을 추가해 줘.
  • 검증 기준이 측정 가능할수록 Claude가 사람 개입 없이 더 멀리 진행합니다.
  • Claude Code의 한 사이클은 맥락 수집 → 실행 → 검증 → 응답입니다. 검증 단계를 탄탄하게 만드는 게 핵심입니다.
  • 레이아웃 시프트는 Core Web Vitals 지표 중 하나라 성능 확인 항목으로 넣기 좋습니다.

5. 자체 MCP로 사내 업무 흐름 설계하기

회사 내부 시스템을 자체 MCP 서버나 MCP 게이트웨이로 Claude에 연결해 팀 단위 업무 흐름을 만드는 방법입니다. 금융 범죄 대응처럼 위험도가 높은 업무나 기획부터 배포까지 이어지는 개발 업무를 실제로 운영할 때 참고합니다.

  1. Claude로 해결할 업무 문제와 목표를 정의합니다.
  2. 업무에 맞는 모델을 고르고 벤치마크로 비교합니다.
  3. 보안·규정 준수 요건을 확인하고 MCP 게이트웨이처럼 접근을 관리할 구조를 정합니다.
  4. 자체 MCP 서버, 스킬, 서브에이전트를 묶어 전체 시스템을 설계합니다.
  5. 실무자가 쓸 화면과 프롬프트·스킬 구조를 만듭니다.
  6. 평가(evals)로 결과를 검증해 신뢰를 쌓은 뒤 팀에 배포하고 범위를 넓힙니다.
  • 근거 영상 두 편 모두 자막이 없어 제목·설명·챕터만으로 정리했습니다. 세부 명령과 설정은 영상에서 직접 확인하세요.
  • Google Cloud와 함께 MCP 서버, 커스텀 스킬, 서브에이전트를 써서 약 30분 만에 앱을 배포까지 진행하는 사례도 있습니다.
