MCP·커넥터 연결

이 분야에서는 Gmail·구글 캘린더·노션 같은 업무 도구를 Claude에 연결하고, 연결한 도구로 정해진 시각에 업무를 자동으로 돌리고, AI가 브라우저를 대신 조작하게 할 수 있습니다. 처음이라면 커넥터 연결과 예약 작업부터 해 보세요. 그다음 AI 브라우저 연결, Claude Code의 MCP 서버 연결 순서로 넘어가면 됩니다.

MCP 서버, 커넥터(구글·노션·슬랙 등), 브라우저·컴퓨터 사용, 외부 도구 연결 · 영상 18개 기반 · 2026-11-02 갱신

1. Claude에 커넥터 연결하기

커넥터는 Gmail, 구글 캘린더, 노션, 구글 드라이브, 슬랙 같은 업무 도구를 Claude에 연결하는 기능입니다. 연결해 두면 자료를 복사해 붙이지 않아도 Claude가 해당 도구의 내용을 직접 읽고 정리합니다. 이메일 정리, 회의 준비, 보고서 작성처럼 여러 도구의 자료를 모아야 할 때 씁니다.

  1. Claude 입력창의 플러스 버튼을 누릅니다.
  2. 커넥터 → 커넥터 추가 → 커넥터 둘러보기로 들어갑니다.
  3. Gmail, 구글 캘린더, 노션 등 연결할 서비스를 검색합니다.
  4. 서비스 옆의 플러스 버튼을 누릅니다.
  5. 해당 서비스 계정으로 로그인해 인증을 마칩니다.
  6. 연결한 도구의 자료를 활용해 달라고 Claude에 요청해 봅니다.
  • Claude와 제휴한 커넥터는 200개가 넘습니다. 전체 목록은 claude.com/connectors에서 볼 수 있습니다.
  • Claude에 설정해 둔 커넥터는 PowerPoint용 Claude 애드인에서도 그대로 쓸 수 있습니다. 구글 드라이브·노션·컨플루언스 자료를 읽어 슬라이드로 만들 수 있습니다.
  • 웹 버전 Claude는 내 PC의 파일에 접근하거나 컴퓨터를 조작할 수 없습니다. 그런 작업은 데스크톱 앱에서 하세요.

2. 코워크로 예약 작업 걸기

Claude 코워크(Cowork)에 반복 업무를 맡기고 정해진 요일·시각마다 자동으로 실행하는 기능입니다. 연결해 둔 커넥터를 예약 작업에서도 쓸 수 있습니다. 매주 이메일 정리, 아침 할 일 브리핑, 주간 지표 리포트 같은 정기 업무에 알맞습니다.

  1. 먼저 작업에 필요한 커넥터(예: Gmail, 구글 캘린더)를 연결해 둡니다.
  2. 새 작업에서 협업을 누릅니다.
  3. 새 프로젝트를 만듭니다.
  4. 실행 주기와 할 일을 한 문장으로 요청합니다.
  5. Claude가 만들어 준 프롬프트 초안과 실행 주기를 확인하고, 필요하면 고칩니다.
  6. 승인 버튼을 눌러 예약을 확정합니다.
  7. 왼쪽 코워크 탭에서 작업 내역과 결과를 확인합니다.
예시
매주 월요일 아침 7시에 지난 한 주 동안 받은 이메일 중 답장이 필요한 것을 정리하고, 고객 미팅 브리핑 문서를 만들어 줘. 필요한 후속 이메일은 보내지 말고 초안으로 남겨 줘.
  • 예전 방식: 예약 작업은 컴퓨터가 켜져 있고 데스크톱 앱이 열려 있을 때만 실행됐습니다. 2026년 7월 7일 업데이트 이후에는 기기가 꺼져 있어도 클라우드에서 실행됩니다.
  • 예약 작업은 실행할 때마다 새 세션으로 시작합니다. 그래서 늘 그 시점의 최신 파일과 도구 상태를 기준으로 일합니다.
  • 승인이 필요한 단계는 모바일 앱으로도 요청이 옵니다. 데스크톱 앱과 똑같이 처리할 수 있습니다.
  • 마음에 드는 작업 방식은 스킬로 저장해 두세요. 매주 같은 방식으로 실행되고 팀과도 공유할 수 있습니다.

3. AI 브라우저 어사이드 연결하기

어사이드(Aside)는 크롬과 비슷한 웹 브라우저입니다. AI가 사이트에서 클릭하고 입력하는 일을 대신 합니다. GPT의 Codex 앱에 연결하면 말로 시키는 것만으로 메일 확인, 사내 시스템 조회, SNS 계정 탐색 같은 일을 맡길 수 있습니다.

  1. PC에 Claude 데스크톱 앱과 GPT의 Codex 앱을 설치합니다.
  2. 어사이드를 설치하고, 쓰고 있는 GPT·Claude 계정을 연결합니다.
  3. 어사이드 하단에서 사용할 모델을 고릅니다.
  4. 크롬의 비밀번호와 즐겨찾기를 어사이드로 가져옵니다.
  5. Codex를 열고 시작하기를 진행합니다. 승인 요청 단계에서 전체 액세스를 켭니다.
  6. 터미널을 열고, 영상에서 안내한 어사이드 연결 문구를 복사해 붙여 넣습니다.
  7. Codex에 어사이드를 쓰라고 지정해 일을 시킵니다.
  8. 어사이드 창에서 실제로 작동하는지 확인합니다.
예시
어사이드를 활용해서 내 메일함에 오늘 들어온 메일을 확인하고 중요한 것만 정리해 줘.
  • 전체 액세스는 모든 권한을 여는 설정이라 보안 위험이 있습니다. 회사 PC라면 보안 규정을 먼저 확인하세요.
  • 일을 시킬 때 '어사이드를 활용하라'고 분명히 적을수록 결과가 정확해집니다.
  • 낮은 요금제를 쓴다면 가성비 좋은 균형형 모델을 고르세요.
  • 크롬 로그인 정보가 제대로 옮겨졌는지 확인하세요. 안 됐다면 GPT에 연결을 시켜 해결합니다.

4. Claude Code에 MCP 서버 추가하기

MCP는 Claude Code를 GitHub, Linear, 문서 서버 같은 외부 도구와 데이터에 연결하는 개방형 표준입니다. 터미널 명령 하나로 서버를 추가하고 Claude Code 안에서 상태를 관리합니다. 팀원과 같은 연결 설정을 함께 쓰고 싶을 때도 이 방법을 씁니다.

  1. 연결 방식을 고릅니다. 원격 서비스면 HTTP, 내 PC에서 도는 프로그램이면 STDIO입니다.
  2. 터미널에서 claude mcp add 명령으로 서버를 추가합니다.
  3. Claude Code 세션 안에서 /mcp를 실행해 연결 상태를 확인합니다.
  4. 당분간 쓰지 않을 서버는 /mcp에서 비활성화합니다.
  5. 팀과 공유하려면 프로젝트 범위로 설정하고, .mcp.json 파일을 버전 관리에 올립니다.
예시
/mcp
  • 설정 범위는 세 가지입니다. local은 현재 프로젝트에서 나만, user는 모든 프로젝트에서, project는 .mcp.json으로 팀과 공유합니다.
  • MCP 서버는 쓰지 않을 때도 도구 정의가 컨텍스트를 차지합니다. 이 비중이 10%를 넘으면 Claude Code가 자동으로 도구 검색 모드로 바뀝니다.
  • GitHub의 gh, AWS의 aws처럼 명령줄 도구(CLI)가 있는 서비스는 CLI를 쓰는 편이 컨텍스트를 덜 씁니다. CLI 사용법은 스킬에 넣어 두면 필요할 때만 불러옵니다.
  • Context7 MCP 서버를 연결하면 사용하는 라이브러리의 최신 문서를 참고하게 할 수 있습니다.

5. BigQuery MCP로 데이터 분석하기

데이터 팀이 BigQuery MCP로 회사 데이터를 Claude Code에 연결해 두면, SQL을 몰라도 말로 데이터를 조회하고 그래프를 만들 수 있습니다. 기획자나 마케터가 직접 지표를 확인하고 싶을 때 유용합니다.

  1. 데이터 팀에 BigQuery MCP로 제품 데이터 테이블을 Claude Code에 연결해 달라고 요청합니다.
  2. Claude Code에서 보고 싶은 지표와 기간을 말합니다.
  3. 조회할 데이터 테이블 이름을 알려 줍니다.
  4. 파일 수정 권한 요청이 나오면 허용합니다.
  5. 만들어진 그래프를 확인합니다.
  6. '요금제별로 나눠 그려 줘'처럼 후속 요청을 이어 갑니다.
예시
지난 3개월 동안 다크 모드를 쓰는 사용자 비율을 주별 그래프로 그려 줘. 그다음 같은 그래프를 요금제별로 나눠서 다시 그려 줘.
  • SQL을 직접 쓰는 것보다 결과를 해석하는 일이 더 중요해집니다.
  • 7일 이동평균처럼 요청하지 않은 요소가 그래프에 더해질 수 있습니다. 결과를 꼭 확인하세요.
  • Google Cloud 환경에서는 Looker MCP 툴박스로도 데이터 분석 도구를 연결할 수 있습니다.

6. Playwright MCP로 화면 검증하기

Playwright MCP를 연결하면 Claude Code가 브라우저로 앱을 직접 실행해 화면을 확인합니다. 그 결과를 보며 수정과 확인을 스스로 반복합니다. 테스트 통과만으로는 알 수 없는 '실제로 의도대로 보이고 동작하는지'까지 Claude가 확인하게 할 때 씁니다.

  1. 설계 문서(spec)가 있으면 먼저 읽으라고 프롬프트에 지정합니다.
  2. Playwright MCP를 사용하라고 프롬프트에 분명히 적습니다.
  3. 구현할 기능을 구체적으로 적어 요청합니다.
  4. Claude가 코드를 읽고 앱을 실행해 현재 화면을 확인하는 과정을 지켜봅니다.
  5. 파일 변경 권한 요청이 나오면 내용을 검토한 뒤 허용합니다.
  6. Claude가 수정과 검증을 반복한 뒤 내놓는 변경 요약을 보고 코드를 검토합니다.
예시
설계 문서를 먼저 읽고, Playwright MCP를 사용해서 앱을 실행해 현재 화면을 확인해 줘. 그다음 Excel·CSV·TSV 파일 미리보기 기능을 구현하고, 화면에서 제대로 보이는지 직접 확인해 줘.
  • 구현 전에 현재 화면을 먼저 확인시키면 비교 기준이 정확해집니다.
  • 브라우저에서 클릭하고 콘솔을 보는 수동 확인 절차를 스킬로 만들어 두면, Claude가 직접 실행하고 고친 뒤 다시 확인합니다. Claude Code에 포함된 verify 스킬로 시작하면 됩니다.
  • 검증 기준이 측정 가능할수록(예: 레이아웃 시프트 같은 성능 지표) Claude가 혼자 더 멀리 진행합니다.
