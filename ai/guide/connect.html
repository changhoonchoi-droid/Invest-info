MCP·커넥터 연결

MCP·커넥터를 쓰면 Claude나 Codex가 메일, 캘린더, Slack, 웹 브라우저, 회사 시스템 같은 외부 도구에 직접 들어가서 일합니다. 처음에는 AI 브라우저를 연결해 클릭과 입력을 맡겨 보세요. 다음으로 커넥터를 연결해 업무를 위임하고 예약 작업을 만듭니다. 그 뒤 팀 채널에 Claude를 들이고, 마지막으로 개발·기업용 환경에서 검증 루프와 MCP 도구를 붙이는 순서로 보면 좋습니다.

MCP 서버, 커넥터(구글·노션·슬랙 등), 브라우저·컴퓨터 사용, 외부 도구 연결 · 영상 8개 기반 · 2026-10-25 갱신

최근 바뀐 점

  • AI 웹 브라우저 어사이드(Aside)를 Codex에 연결하면 메일 확인, 사내 사이트 조회 같은 브라우저 작업을 말로 시킬 수 있고, 이미 GPT나 Claude를 유료로 쓰고 있으면 어사이드 비용은 따로 들지 않는다고 소개되었습니다.
  • Claude Tag가 나왔습니다. Slack 같은 팀 워크스페이스 채널에 Claude를 추가하면 팀 대화를 따라가며 정리, 문서 초안 작성, 도구 안 수정까지 합니다. Team·Enterprise 계정에서 쓸 수 있습니다.
  • Claude Code에 포함된 verify 스킬로 시작하면, 브라우저 클릭이나 콘솔 확인 같은 수동 검증 절차를 프로젝트 스킬로 만들어 Claude가 스스로 확인하고 고치게 할 수 있습니다.

1. Codex에 어사이드 브라우저 연결하기

어사이드(Aside)는 크롬 같은 AI 웹 브라우저로, AI가 사이트에서 클릭하고 입력하는 일을 대신 합니다. Codex에 연결하면 메일 확인, 사내 물류 사이트 조회, 인스타그램 계정 탐색처럼 로그인이 필요한 브라우저 업무도 말로 시킬 수 있습니다.

  1. PC에 Claude 데스크톱 앱과 GPT의 Codex 앱을 설치합니다.
  2. 어사이드를 설치하고, 쓰고 있는 GPT와 Claude 계정을 연결합니다.
  3. 어사이드 하단에서 사용할 모델을 고릅니다. 낮은 요금제라면 가성비 좋은 균형형 모델을 고릅니다.
  4. 크롬에 저장된 비밀번호와 즐겨찾기를 어사이드로 가져옵니다.
  5. Codex를 열어 시작하기를 진행하고, 승인 요청 단계에서 전체 액세스를 켭니다.
  6. 터미널을 열고 영상에서 안내한 어사이드 연결 문구를 복사해 붙여 넣습니다.
  7. Codex에 어사이드를 쓰라고 지정해 일을 시킵니다.
  8. 어사이드 창에서 AI가 실제로 클릭하고 입력하는지 확인합니다.
예시
어사이드를 활용해서 내 메일함을 열고 오늘 받은 메일을 확인한 뒤 중요한 것만 요약해 줘.
  • 전체 액세스는 모든 권한을 여는 설정이라 보안 위험이 있습니다. 회사 PC라면 사내 보안 규정을 먼저 확인하세요.
  • 일을 시킬 때 '어사이드를 활용해서'라고 지정할수록 더 정확하게 움직입니다.
  • 크롬 로그인 정보가 제대로 옮겨졌는지 확인하고, 안 됐다면 GPT에 연결을 시켜 봅니다.
  • 컴퓨터가 켜져 있으면 휴대폰 앱으로도 Codex에 일을 시킬 수 있습니다.

2. 커넥터로 Cowork에 업무 맡기기

Claude Cowork에 캘린더, Slack, 이메일 같은 커넥터를 연결하면 여러 도구의 정보를 모아 회의 준비 문서 같은 결과물을 만들어 줍니다. 작업 중에 방향을 바꾸라고 해도 처음부터 다시 하지 않고 이어서 진행합니다.

  1. Claude 데스크톱 앱에서 Cowork를 엽니다.
  2. 업무에 필요한 캘린더, Slack, 이메일 커넥터를 연결합니다.
  3. 만들 결과물을 구체적으로 요청합니다. 예: 다음 회의의 준비 문서.
  4. 작업이 진행되는 동안 참고할 출처를 더하거나 고칠 점을 말해 방향을 바꿉니다.
  5. 작업 폴더에 저장된 완성 문서를 열어 직접 검토하고 마무리합니다.
예시
내 캘린더에서 내일 회의를 찾고, 관련 Slack 대화와 이메일을 참고해서 회의 준비 문서를 만들어 줘.
  • 완성된 문서의 최종 소유와 수정은 사용자 몫입니다. 사실관계는 꼭 직접 확인하세요.
  • 중간에 수정을 요청해도 처음부터 다시 하지 않으니 생각나는 대로 바로 말하면 됩니다.

3. 반복 업무를 예약 작업으로 자동화하기

한 번 해 보고 마음에 든 업무를 정해진 주기(예: 평일 오후 4시)마다 자동으로 돌게 하는 기능입니다. 매일 하는 보고, 회의 준비, 수업 피드백처럼 같은 일을 반복할 때 씁니다.

  1. 먼저 Cowork에서 자동화할 업무를 한 번 직접 시켜 결과가 마음에 드는지 확인합니다.
  2. 이 작업을 정기적으로 실행하는 예약 작업으로 만들어 달라고 Claude에 요청합니다.
  3. Claude가 만들어 준 예약 작업 프롬프트 초안을 읽고 필요한 부분을 고칩니다.
  4. 실행 주기를 확인하고 필요하면 수정합니다.
  5. 승인해서 예약 작업을 등록합니다.
  6. 정해진 시간에 컴퓨터를 켜 두고 데스크톱 앱을 열어 둡니다.
예시
방금 한 작업을 평일 오후 4시마다 자동으로 실행하는 예약 작업으로 만들어 줘.
  • 예약 작업은 컴퓨터가 켜져 있고 데스크톱 앱이 열려 있을 때만 실행됩니다.
  • 실행할 때마다 새 Cowork 세션으로 돌아가서 그 시점의 최신 파일과 도구 상태를 기준으로 합니다.
  • 미리 설정해 둔 커넥터는 예약 작업에서도 그대로 쓸 수 있습니다.

4. Claude Tag로 Slack 채널에 Claude 두기

Claude Tag는 Slack 같은 팀 워크스페이스 채널에 Claude를 추가해 팀 대화를 실시간으로 따라가며 일하게 하는 기능입니다. 채팅 창을 오가거나 맥락을 복사해 붙이지 않고, 채널 안에서 바로 정보 정리, 문서 초안, 도구 안 수정을 요청할 수 있습니다.

  1. 회사가 Claude Team 또는 Enterprise 계정을 쓰고 있는지 확인합니다.
  2. 관리자가 Claude를 쓸 팀 채널에 추가합니다.
  3. 채널마다 Claude가 맡을 일, 대화에 끼어드는 빈도, 스스로 처리해도 되는 범위를 정합니다.
  4. 필요하면 참고할 다른 공개 채널에 대한 접근 권한을 줍니다.
  5. 채널에서 Claude에게 정리, 문서 초안, 도구 수정 같은 일을 요청합니다.
  6. 기록된 변경 내역과 요청자를 확인해 결과를 검토합니다.
  • DM과 비공개 채널은 비공개로 유지되고, 공개 채널만 접근 권한을 줄 수 있습니다.
  • Claude는 자체 계정으로 작업하고 모든 변경과 요청자를 기록하므로 누가 무엇을 시켰는지 추적할 수 있습니다.
  • Claude는 채널별 지침을 기억하니 채널 성격에 맞게 처음에 역할을 분명히 정해 두세요.

5. verify 스킬로 브라우저 검증 맡기기

Claude Code는 테스트, 타입 검사, 린터를 스스로 돌리지만, 그것만으로는 변경이 의도대로 동작하는지 증명되지 않습니다. 브라우저에서 클릭하고 콘솔을 보는 수동 확인 절차를 스킬로 만들어 두면 Claude가 직접 확인하고, 고치고, 다시 확인합니다.

  1. Claude Code에 포함된 verify 스킬로 시작합니다.
  2. 평소 사람이 하던 확인 절차를 Claude에 설명합니다. 웹은 브라우저 클릭과 콘솔 확인, 백엔드는 엔드포인트 호출, 모바일은 iOS 시뮬레이터 확인입니다.
  3. 생성된 프로젝트 스킬을 열어 확인 항목이 맞는지 봅니다.
  4. 성능 측정처럼 숫자로 판단할 수 있는 확인 항목을 스킬에 추가합니다. 예: 레이아웃 시프트.
  5. Claude에 작업을 맡기고, 스킬로 검증한 뒤 문제가 있으면 고쳐 다시 확인하게 합니다.
  • Claude Code는 '맥락 수집 → 실행 → 검증 → 응답' 순서로 한 사이클을 돕니다. 검증 단계를 단단히 만들수록 결과가 좋아집니다.
  • 검증 기준이 측정 가능할수록 Claude가 사람 도움 없이 더 멀리 혼자 갑니다.
  • 레이아웃 시프트는 Core Web Vitals 지표 중 하나라 성능 기준으로 쓰기 좋습니다.

6. 기업용 플랫폼에서 MCP 도구 붙이기

회사 시스템에 Claude를 넣을 때는 Microsoft Foundry나 Google Cloud 같은 기업용 플랫폼에서 Claude 모델을 배포하고, 에이전트에 커넥터와 MCP 도구를 붙여 씁니다. 보안·거버넌스와 평가(evals)까지 함께 챙겨야 하는 실제 운영 배포에 해당합니다.

  1. aka.ms/cloudworkshop 실습 페이지를 열어 제공된 실습 환경에 들어갑니다.
  2. Microsoft Foundry에서 Claude 모델을 배포합니다.
  3. 배포한 모델을 에이전트에 연결합니다.
  4. Foundry가 제공하는 커넥터·MCP 도구 가운데 필요한 것을 에이전트에 붙입니다.
  5. 실습 시나리오(가상의 컵케이크 가게 에이전트)를 단계별 안내대로 따라 하며 동작을 확인합니다.
  6. 실제 업무에 쓰기 전에 보안·규정 준수와 평가(evals)로 결과를 믿을 수 있는지 점검합니다.
  • Foundry는 1,400개 이상의 내장 커넥터와 MCP 도구, 그리고 Defender·Purview·Entra ID와 연동되는 보안·거버넌스 기능을 제공한다고 합니다.
  • 금융처럼 위험도가 높은 업무에서는 자체 MCP와 MCP 게이트웨이를 두고 평가로 신뢰를 쌓는 방식이 소개되었습니다.
  • Google Cloud 사례는 서브에이전트, MCP 서버, 커스텀 스킬을 함께 써서 약 30분 만에 앱 하나를 배포까지 만들었습니다. 다만 자막이 없어 세부 명령어는 영상에서 직접 확인해야 합니다.
  • Foundry 실습 영상은 자막이 중간에 끊겨 있어 세부 절차는 실습 페이지 안내를 기준으로 하세요.
