MCP·커넥터 연결

이 분야에서는 Claude에 구글 캘린더·Gmail·슬랙 같은 업무 도구를 연결해 흩어진 정보를 한 번에 모으고, AI 브라우저로 클릭·입력을 맡기고, MCP 서버로 외부 도구를 붙이는 방법을 다룹니다. 처음이라면 Cowork에 커넥터를 연결해 업무 하나를 맡겨 보고, 예약 작업과 스킬로 반복 업무를 자동화한 뒤, 팀 채널과 Claude Code의 MCP 연결로 넓혀 가는 순서를 권합니다.

  • 신영선의 AI탐구(10/24)는 한국인이 만든 AI 웹 브라우저 '어사이드(Aside)'를 Codex에 연결해 메일 확인·사내 사이트 조회 같은 일을 말로 시키는 방법을 소개했고, 이미 GPT나 Claude를 유료로 쓰고 있으면 어사이드에는 따로 비용이 들지 않는다고 설명합니다.
  • 같은 영상에 따르면 PC가 켜져 있으면 휴대폰 앱으로도 Codex에 일을 시킬 수 있습니다.

1. Cowork에 커넥터 연결해 업무 맡기기

Claude Cowork에 캘린더·Slack·이메일 같은 업무 도구를 커넥터로 연결하면, 여러 곳에 흩어진 정보를 Claude가 한 번에 모아 문서로 정리합니다. 회의 준비, 고객 미팅 브리핑, 밀린 대화 따라잡기처럼 자료를 찾아 모으는 데 시간이 많이 드는 일에 씁니다.

  1. claude.com/connectors에서 연결할 수 있는 커넥터 목록을 확인합니다.
  2. Cowork에 자주 쓰는 캘린더·Slack·이메일을 커넥터로 연결합니다.
  3. 만들고 싶은 결과물을 말로 요청합니다 (예: 내일 회의 준비 문서).
  4. 작업 중간에 출처를 추가하거나 수정을 요청해 방향을 바꿉니다. 처음부터 다시 하지 않고 이어서 진행합니다.
  5. 완성된 문서를 작업 폴더에서 열어 내용을 확인하고 직접 고칩니다.
  6. 메일 답장이나 Slack 메시지 초안은 내용을 확인하고 승인한 뒤에 보냅니다.
예시
내일 오전 고객 미팅 준비 문서를 만들어 줘. 캘린더의 미팅 정보, 최근 Slack 대화, 이 고객과 주고받은 이메일을 모아서 지금 진행 상황과 확인할 점을 정리해 줘.
  • Claude가 정리한 브리핑은 근거가 된 원문 메일·대화를 직접 열어 확인한 뒤에 씁니다.
  • 최종 문서의 책임과 수정은 사용자 몫입니다. 보내기 전 승인 단계를 건너뛰지 않습니다.
  • 미팅이 끝난 뒤 같은 세션에서 녹취록을 넘기면 할 일 목록, 내부 공유 메시지, 고객 후속 메일까지 이어서 만들 수 있습니다.

2. AI 브라우저 어사이드를 Codex에 연결하기

어사이드(Aside)는 크롬과 비슷한 브라우저인데, 클릭과 입력을 AI가 대신 합니다. Codex에 연결해 두면 로그인이 필요한 메일, 사내 시스템, SNS에서 하는 일을 말로 시킬 수 있습니다.

  1. PC에 Claude 데스크톱 앱과 GPT의 Codex 앱을 설치합니다.
  2. 어사이드를 설치하고, 쓰고 있는 GPT·Claude 계정을 연결합니다.
  3. 어사이드 하단에서 모델을 고릅니다. 요금제가 낮으면 가성비 좋은 균형형 모델을 고릅니다.
  4. 크롬에 저장된 비밀번호와 즐겨찾기를 어사이드로 가져옵니다.
  5. Codex를 열어 시작하기를 진행하고, 승인 요청에서 전체 액세스를 켭니다.
  6. 터미널을 열고, 영상에서 안내한 어사이드 연결 문구를 복사해 붙여 넣습니다.
  7. Codex에 어사이드를 쓰라고 지정해 일을 시킨 뒤, 어사이드 창에서 실제로 작동하는지 확인합니다.
예시
어사이드를 활용해서 오늘 받은 메일을 확인하고 중요한 것만 정리해 줘.
  • 전체 액세스는 모든 권한을 여는 설정이라 보안 위험이 있습니다. 회사 PC라면 보안 규정을 먼저 확인합니다.
  • 요청할 때 '어사이드를 활용해서'라고 지정하면 결과가 더 정확합니다.
  • 크롬 로그인 정보가 제대로 옮겨졌는지 확인하고, 안 됐다면 GPT에 연결 작업을 맡깁니다.
  • PC가 켜져 있으면 휴대폰 앱으로도 Codex에 일을 시킬 수 있습니다.

3. 예약 작업으로 반복 업무 자동화하기

매일 아침 메일 정리나 매주 지표 리뷰처럼 정해진 때마다 하는 일을 Cowork 예약 작업으로 등록하면, Claude가 시간에 맞춰 알아서 실행합니다. 연결해 둔 커넥터도 예약 작업에서 그대로 쓸 수 있습니다.

  1. 먼저 Cowork에서 해당 업무를 한 번 직접 시켜 보고 결과가 마음에 드는지 확인합니다.
  2. 이 작업을 정기적으로 실행하고 싶다고 Claude에 요청합니다.
  3. Claude가 만든 프롬프트 초안을 읽고 필요한 부분을 고칩니다.
  4. 실행 주기(예: 평일 아침, 일요일 저녁)를 확인하고 수정합니다.
  5. 승인해 예약 작업을 등록합니다.
  6. 첫 실행 결과를 확인하고, 부족한 점이 있으면 프롬프트를 다듬습니다.
예시
매일 아침 Gmail을 확인해서 오늘 처리해야 할 일을 정리해 주는 예약 작업을 만들어 줘.
  • 예약 작업은 컴퓨터가 켜져 있고 데스크톱 앱이 열려 있을 때만 실행됩니다.
  • 실행할 때마다 새 Cowork 세션에서 돌아가므로, 항상 최신 파일과 도구 상태를 기준으로 작업합니다.
  • 데이터가 맞지 않으면 Claude가 추측하지 않고 질문하도록 프롬프트에 적어 둡니다.

4. 업무 절차를 스킬로 저장해 재사용하기

잘 된 업무 방식을 스킬로 저장하면 매번 길게 설명하지 않아도 같은 절차로 일을 시킬 수 있습니다. 여러 커넥터에서 자료를 동시에 모으는 조사, 숫자 검증, 변경 사항 브리핑처럼 순서가 정해진 일에 잘 맞습니다.

  1. Cowork에서 업무를 한 번 끝까지 진행하며 원하는 순서와 결과물 형태를 정합니다.
  2. 이 과정을 스킬로 저장해 달라고 Claude에 요청합니다.
  3. 다음부터는 스킬 이름을 불러 같은 방식으로 실행합니다 (예: /brief).
  4. 실행 후 새로 알게 된 점을 스킬에 추가해 다음 실행에 반영합니다.
  5. 팀원도 같은 방식으로 일하도록 스킬을 공유합니다.
  • 검증 단계를 스킬에 넣어 두면 좋습니다. 예를 들어 초안의 모든 숫자가 확인된 데이터 출처로 이어지는지 점검하게 합니다.
  • Anthropic 법무팀의 /brief는 지난 검토 문서와 새 Slack·Gmail 대화를 읽어 무엇이 바뀌었는지 짧게 알려 주는 스킬입니다.
  • 플러그인은 오픈 프로토콜이라 내 업무에 맞게 고쳐 쓸 수 있습니다.

5. Claude Tag로 슬랙 채널에서 일 시키기

Claude Tag는 Slack 같은 팀 채널에 Claude를 넣어, 팀 대화를 실시간으로 따라가며 일하게 하는 기능입니다. 채팅 창을 오가거나 맥락을 복사해 붙일 필요 없이 채널에서 바로 정리, 문서 초안, 도구 안의 수정까지 요청할 수 있습니다.

  1. Team 또는 Enterprise 계정인지 확인합니다.
  2. Claude가 일할 팀 채널에 Claude를 추가합니다.
  3. 채널마다 Claude가 맡을 일, 개입 빈도, 자율 범위를 정합니다.
  4. 관리자가 채널별 접근 범위와 다른 공개 채널의 정보를 볼 수 있는지 정합니다.
  5. 채널에서 Claude에 작업을 요청합니다.
  6. 기록된 변경 내역과 요청자를 확인합니다.
  • DM과 비공개 채널은 비공개로 유지되고, 다른 공개 채널은 접근 권한을 줄 때만 참고합니다.
  • Claude는 별도 계정으로 작업하며, 누가 무엇을 요청했는지 모두 기록합니다.
  • 채널별 지침을 기억하므로 채널 용도에 맞게 처음에 잘 정해 두면 이후에 편합니다.

6. Claude Code에 MCP 서버 연결하기

MCP는 Claude Code를 Linear, GitHub, 문서 서버 같은 외부 도구와 데이터에 연결하는 개방형 표준입니다. 서버를 추가하면 Claude Code가 그 도구를 직접 조회하고 다룰 수 있습니다.

  1. 연결할 서비스가 원격 서비스면 HTTP, 내 PC에서 도는 프로그램이면 STDIO 유형을 고릅니다.
  2. 범위를 정합니다. local은 현재 프로젝트에서 나만, user는 내 모든 프로젝트, project는 팀과 공유입니다.
  3. 터미널에서 claude mcp add 명령으로 서버를 추가합니다.
  4. Claude Code 세션 안에서 /mcp를 실행해 연결 상태를 확인합니다.
  5. 쓰지 않는 서버는 /mcp에서 비활성화합니다.
  6. 팀과 공유하려면 project 범위로 두고 .mcp.json 파일을 버전 관리에 올립니다.
예시
/mcp
  • MCP 서버는 쓰지 않을 때도 도구 정의가 컨텍스트를 차지하므로 안 쓰는 서버는 꺼 둡니다.
  • MCP 도구 정의가 컨텍스트 창의 10%를 넘으면 Claude Code가 자동으로 도구 검색 모드로 바뀝니다.
  • GitHub의 gh, AWS의 aws처럼 CLI가 있는 도구는 CLI를 쓰는 편이 컨텍스트를 덜 차지합니다. CLI 사용법은 스킬에 넣어 두면 필요할 때만 불러옵니다.
  • Context7 MCP 서버를 연결하면 사용하는 라이브러리의 최신 문서를 참고하게 할 수 있습니다.

7. 브라우저 확인 절차를 검증 스킬로 만들기

Claude Code는 테스트와 타입 검사는 스스로 실행하지만, 그것만으로는 변경이 의도대로 동작하는지 증명되지 않습니다. 브라우저에서 클릭하고 콘솔을 보는 식의 확인 절차를 스킬로 만들어 두면, Claude가 직접 확인하고 고친 뒤 다시 확인합니다.

  1. 사람이 손으로 하던 확인 절차를 적어 봅니다. 웹은 브라우저, 백엔드는 엔드포인트 호출, 모바일은 iOS 시뮬레이터로 확인합니다.
  2. Claude Code에 포함된 verify 스킬로 프로젝트용 검증 스킬을 만듭니다.
  3. 만들어진 스킬에 성능 측정 같은 확인 항목을 추가합니다 (예: 레이아웃 시프트).
  4. 확인 기준을 숫자처럼 측정할 수 있게 적습니다.
  5. 작업을 맡기고 Claude가 확인 → 수정 → 재확인을 반복하는지 지켜봅니다.
  • Claude Code는 맥락 수집 → 실행 → 검증 → 응답 순서로 일합니다. 검증 단계를 채워 주는 것이 핵심입니다.
  • 검증 기준이 측정 가능할수록 Claude가 사람 도움 없이 더 멀리 진행합니다.

8. 클라우드에서 MCP 붙인 에이전트 만들기

Microsoft Foundry나 Google Cloud 같은 클라우드에서 Claude 모델을 배포하고, 커넥터·MCP 도구를 붙여 회사용 AI 에이전트를 만드는 방법입니다. 보안·거버넌스가 중요한 조직에서 여러 시스템을 연결한 에이전트를 운영할 때 씁니다.

  1. 실습 페이지 aka.ms/cloudworkshop에 들어가 제공된 실습 환경을 엽니다.
  2. Microsoft Foundry에서 Claude 모델을 배포합니다.
  3. 배포한 모델을 에이전트에 연결합니다.
  4. 에이전트에 필요한 커넥터나 MCP 도구를 붙입니다.
  5. 실습 시나리오(가상의 컵케이크 가게 에이전트)를 단계별 안내에 따라 진행합니다.
  • Foundry는 1,400개 이상의 내장 커넥터와 MCP 도구, Defender·Purview·Entra ID와 연동되는 보안 기능을 제공한다고 합니다.
