업무 자동화·에이전트

업무 자동화·에이전트 분야에서는 Cowork에 문서 작업을 맡기고, 반복되는 일은 예약 작업으로 자동 실행하고, Slack 채널에서 팀과 함께 Claude에게 일을 시킬 수 있습니다. 처음이라면 Cowork 업무 위임과 예약 작업부터 해 보세요. 그다음 Word·Excel·PDF 같은 업무 도구 연동과 Slack의 Claude Tag로 넓히고, 마지막에 스킬, 모델 선택, Managed Agents 같은 에이전트 설계로 넘어가면 됩니다.

1. Cowork로 회의 준비 문서 만들기

Claude Cowork에 캘린더·Slack·이메일과 회의록 폴더를 연결해 두면 회의 준비 문서를 대신 만들어 줍니다. 참석자 조사, 지난 논의 확인, 안건 작성처럼 여러 곳을 뒤져야 하는 준비 작업을 한 번에 맡길 때 씁니다.

  1. 캘린더, Slack, 이메일을 Claude에 연결합니다.
  2. 회의록이 있는 폴더를 Claude가 볼 수 있게 지정합니다.
  3. 회의 상대와 시간을 알려 주며 준비를 요청합니다.
  4. 캘린더 검색, 참석자 조사, Slack 스레드 확인, 이전 회의록 검토, 안건 작성을 요청하고 기존 문서 형식을 템플릿으로 따르라고 지시합니다.
  5. Claude가 세운 계획을 확인한 뒤 작업이 진행되게 둡니다.
  6. 빠진 출처가 있으면 작업 중에 바로 추가로 요청합니다(예: 이메일도 확인해 줘).
  7. 작업 폴더에 저장된 안건 문서를 열어 검토하고, 빠진 내용은 Claude에게 추가를 요청하거나 직접 고칩니다.
예시
Prep me for today's call with Acme Corp at 1PM. 캘린더에서 회의를 찾고, 참석자를 조사하고, 관련 Slack 스레드와 이전 회의록을 검토해서 기존 안건 문서 형식대로 안건을 작성해 줘.
  • 작업 도중 지시를 더해도 처음부터 다시 만들지 않고 방향만 바꿔 이어 갑니다.
  • 완성된 문서의 최종 책임과 수정은 사용자에게 있으니 꼭 한 번 읽어 보고 쓰세요.

2. Cowork 예약 작업으로 반복 업무 자동화하기

매시간이나 매일 하는 반복 업무를 말로 설명하면 Claude가 예약 작업으로 만들어 정해진 시간에 자동 실행합니다. 폴더 변경 사항 요약이나 매일 쓰는 보고서처럼 주기적으로 같은 순서로 하는 일에 알맞습니다.

  1. 반복할 일을 자연어로 자세히 설명합니다(무엇을 확인하고, 어떻게 정리하고, 어디에 저장할지).
  2. Claude가 만들어 준 예약 작업 프롬프트 초안을 읽고 확인합니다.
  3. 필요하면 실행 주기를 매시간·매일·평일·수동 중에서 바꿉니다.
  4. 내용이 맞으면 제안을 수락해 등록합니다.
  5. 왼쪽 사이드바의 예약(scheduled) 페이지에 작업이 추가됐는지 확인합니다.
  6. 등록한 뒤 바로 한 번 실행해 결과가 제대로 나오는지 확인합니다.
예시
매시간 공유 드라이브 폴더에서 새로 추가되거나 수정된 문서를 확인해 줘. 누가 바꿨는지 기록하고, 변경 내용을 요약해서 클라이언트별로 묶은 다음 문서로 저장해 줘.
  • 예약 작업은 컴퓨터가 켜져 있고 Claude 데스크톱 앱이 열려 있어야 실행됩니다. 꺼져 있어서 놓친 작업은 다시 켰을 때 바로 실행되고, 지연됐다고 알려 줍니다.
  • 실행할 때마다 새 Cowork 세션으로 돌기 때문에 항상 최신 파일과 도구 상태를 기준으로 작업합니다. 미리 설정해 둔 커넥터도 그대로 쓸 수 있습니다.
  • 예약 페이지에서 지난 실행 기록을 보고, 지시문과 주기를 고치고, 즉시 실행할 수 있습니다.
  • 한 번 대화로 해 보고 결과가 마음에 들 때 '매주 평일 오후 4시마다 이 작업을 해 달라'처럼 요청하는 방법도 있습니다.

3. Acrobat AI로 자료 정리해 PPT 만들기

Adobe Acrobat의 PDF 스페이스에 보고서, 기사 링크, 메모를 모아 넣으면 AI가 핵심 내용을 정리하고 발표 자료 초안까지 만들어 줍니다. 요약에 붙은 출처 번호로 원문 근거를 바로 확인할 수 있어서 보고·발표 준비에 유용합니다.

  1. PDF 스페이스를 만들고 보고서 파일, 이미지, 웹 링크, 텍스트를 자료로 넣습니다.
  2. AI 어시스턴트에게 자료의 핵심 내용을 정리해 달라고 요청합니다.
  3. 요약 속 숫자를 눌러 원문의 해당 부분을 열고 근거를 확인합니다.
  4. 정리한 내용으로 프레젠테이션 초안을 만들게 합니다.
  5. Adobe Express 편집 화면에서 글자·배경·아이콘을 하나씩 고칩니다.
  6. 완성본을 PPTX, PDF, JPG, PNG 중 필요한 형식으로 내려받습니다.
  7. AI 어시스턴트에게 팀 회의에서 나올 만한 질문과 답변을 정리해 달라고 하고, 답변마다 붙은 출처를 눌러 확인합니다.
예시
이 자료를 바탕으로 팀 회의에서 나올 만한 질문 세 개와 답변을 정리해 줘. 근거가 없는 내용은 '확인 필요'라고 표시해 줘.
  • PDF 스페이스에는 확장자와 관계없이 최대 100개 파일까지 넣을 수 있습니다.
  • 근거가 없는 내용은 '확인 필요'라고 표시해 달라고 요청하면 잘못된 내용을 걸러 내기 쉽습니다.

4. Claude for Word로 초안 다듬기

Claude for Word는 Word 옆 패널에서 문서를 읽고 댓글 요약, 사실 확인, 서식 정리, 고쳐 쓰기까지 해 줍니다. 모든 수정은 추적 변경으로 남기 때문에, 여러 사람이 댓글을 단 초안을 완성본으로 다듬을 때 안심하고 쓸 수 있습니다.

  1. Microsoft AppSource에서 Claude for Microsoft 365를 설치합니다(Word 웹·Windows·Mac 지원).
  2. 다듬을 초안을 Word에서 열고 Claude 패널을 엽니다.
  3. 문서에 달린 댓글을 요약하고 그대로 반영해 달라고 요청합니다.
  4. Box 등에 있는 원본 문서와 대조해 사실 확인을 맡깁니다.
  5. 서식 정리, 고객용 문장으로 고쳐 쓰기, 분량 줄이기를 차례로 요청합니다.
  6. 패널에서 /brand-guidelines 같은 나만의 스킬을 불러 교정합니다.
  7. 검토 카드와 추적 변경을 하나씩 보며 수락하거나 거절합니다.
예시
/brand-guidelines
  • Pro, Max, Team, Enterprise 유료 플랜에 포함돼 있습니다.
  • 스킬은 Claude 계정에서 미리 만들어 두면 Word 패널에서 바로 불러 쓸 수 있습니다.
  • Claude가 고친 내용은 바로 반영되지 않고 추적 변경으로 남으니, 수락 전에 꼭 확인하세요.

5. Excel·PowerPoint를 한 대화로 잇기

Claude for Excel과 PowerPoint는 열려 있는 두 파일을 한 세션에서 함께 다룹니다. 엑셀로 분석하고 그 결과를 발표 자료에 넣는 일을 탭을 오가거나 데이터를 다시 설명하지 않고 한 번에 처리할 수 있습니다.

  1. 작업할 Excel 파일과 PowerPoint 파일을 둘 다 엽니다.
  2. Claude 패널에서 데이터 수집, 표 작성, 슬라이드 반영까지 한 번에 요청합니다.
  3. Claude가 실시간 셀 값을 읽어 만든 Excel 분석 표를 확인합니다.
  4. PowerPoint에 들어간 요약 슬라이드와 문장을 검토합니다.
  5. 자주 하는 흐름이면 Skills로 저장해 두고 다음에 한 번의 클릭으로 다시 실행합니다.
예시
비교 기업 재무 자료를 가져와 Excel에 트레이딩 컴프스 표를 만들고, 밸류에이션 요약을 피치덱에 넣은 다음 요약문까지 작성해 줘.
  • 유료 플랜 사용자라면 Mac·Windows에서 모두 쓸 수 있습니다.
  • 회사에서 Amazon Bedrock, Google Cloud Vertex AI, Microsoft Foundry를 쓴다면 그 경로로도 쓸 수 있습니다.

6. Slack에서 Claude Tag에게 일 맡기기

Claude Tag는 Slack 같은 팀 워크스페이스 채널에 들어와 팀 대화를 따라가며 일하는 Claude입니다. 채팅 창을 오가거나 맥락을 복사해 붙일 필요 없이, 채널에서 태그만 하면 대화 기록·공유 문서·연결된 도구를 참고해 복잡한 작업도 처리합니다.

  1. Claude Tag를 쓸 Slack 채널 하나에 Claude를 추가합니다.
  2. Google Drive, Asana처럼 작업에 필요한 도구를 Claude Tag에 연결합니다.
  3. 채널이나 스레드에서 Claude를 태그하고 할 일을 구체적으로 요청합니다.
  4. Claude가 단계별로 진행하는 상황을 채널에서 확인합니다.
  5. 기다리지 말고 다른 일을 하다가, 완료 알림이나 결정 요청 알림이 오면 확인하고 답합니다.
  6. 채널의 다른 사람도 같은 요청에 이어서 추가 요청을 할 수 있습니다.
예시
@Claude 최근 3일 동안의 스레드, Google Drive 회의록, Asana의 열린 작업을 확인해서 이번 주 미결 액션 아이템 목록을 만들어 줘.
  • Team과 Enterprise 계정에서 쓸 수 있으며, Slack에서 베타로 제공됩니다.
  • 처음에는 채널 하나에서만 시작해 보세요. 프로젝트 상태를 추적하려면 공개 채널이 좋습니다.
  • Claude는 별도의 자체 계정으로 일하고, 모든 변경과 요청자를 기록합니다. 사용자를 대신해 응답하거나 개별 도구에 접근할 때는 매번 권한을 묻습니다.
  • DM과 비공개 채널에서 배운 내용은 그 안에만 남고, 채널별로 접근 권한이 나뉘어 다른 채널의 시스템은 볼 수 없습니다.

7. Claude Tag에 채널 규칙 기억시키기

Claude Tag는 채널마다 지침을 기억해서 한 번 알려 준 규칙을 계속 따릅니다. 맡을 일, 개입 빈도, 자율 범위를 채널에 맞게 정해 두면 매번 같은 설명을 반복하지 않아도 됩니다.

  1. 반복할 지침은 Remember for this channel: ... 형태로 말해 저장시킵니다.
  2. 스타일 가이드나 체크리스트 문서를 알려 주고 작업할 때 참고하라고 합니다.
  3. 무엇을 지켜볼지, 어떻게 처리할지 같은 선호를 말로 알려 줍니다.
  4. 매번 태그하기 번거로우면 항상 응답하라고 지시합니다.
  5. 너무 자주 또는 너무 드물게 끼어들면 개입 빈도를 조정해 달라고 말합니다.
  6. 필요하면 Claude를 태그해 지금 기억하는 내용을 읽어 보고 고칩니다.
예시
Remember for this channel: 고객 문의 답변 초안은 항상 공유 드라이브의 스타일 가이드를 따르고, 보내기 전에 나에게 먼저 확인받아 줘.
  • 참고 문서가 바뀌면 기본적으로 최신 내용을 따릅니다.
  • 채널의 누구든 Claude를 태그해 기억 내용을 읽고 고칠 수 있으니 팀 규칙처럼 관리하세요.
  • Claude가 스스로 작업을 검증할 수 있게 해 두면 중간 확인 요청이 줄어듭니다.
  • 관리자는 채널마다 접근 범위와 자율성을 조절할 수 있습니다.

8. 스킬로 우리 팀 기준 가르치기

스킬은 우리 팀의 교정 기준, 브랜드 가이드, 업무 방식을 Claude에게 가르쳐 두는 문서입니다. 한 번 만들어 두면 Word, Excel 같은 도구에서 같은 기준으로 작업하게 할 수 있고, 사람이 고친 내용을 다시 반영해 점점 개선할 수 있습니다.

  1. 팀의 과거 수정 이력, 잘된 예시, 스타일 가이드 같은 판단 근거를 모읍니다.
  2. Claude 계정에서 스킬을 만들고, 지켜야 할 규칙 목록보다 어떻게 판단해야 하는지(원칙)를 중심으로 씁니다.
  3. 업무 도구 패널에서 /brand-guidelines처럼 스킬 이름으로 불러 실행합니다.
  4. 스킬 결과에 사람이 추가로 고친 내용을 모아 둡니다.
  5. 모은 수정 내용을 스킬에 다시 반영하고, 바꾸기 전에 팀원이 검토하게 합니다.
  • Every는 편집장이 과거에 고친 3만 건으로 교정 스킬을 만들어 Google Docs에 수정 제안을 달게 했고, 이후 사람이 고친 내용을 추적해 스킬에 다시 반영합니다.
  • 지침을 코드처럼 수정→검토→병합하는 방식으로 관리하면 팀의 판단이 매일 에이전트에 쌓입니다.
  • 마케터처럼 개발을 모르는 사람에게는 익숙한 문서 형태(예: AirOps의 Playbooks)로 스킬을 제공하면 쓰기 쉽습니다.
  • Slack 같은 공개된 곳에서 프롬프트를 쓰면 잘 쓰는 사람의 방식이 동료에게 자연스럽게 퍼집니다.

9. Claude Code Projects로 큰 일 나눠 맡기기

Claude Code의 Project는 여러 작업을 Claude가 조율하는 하나의 지속적인 대화입니다. 작업마다 클라우드에서 따로 도는 스레드를 만들어 병렬로 처리하므로, 여러 세션이나 저장소에 걸친 큰 목표를 노트북을 닫아 둔 채로도 진행할 수 있습니다.

  1. 여러 세션이나 저장소에 걸친 큰 목표로 Project를 만듭니다.
  2. 작업을 나눠 각각 스레드로 맡깁니다(스레드마다 클라우드의 자체 브랜치에서 실행됩니다).
  3. 모든 스레드가 함께 볼 목업이나 디자인 명세 같은 파일을 library 탭에 넣습니다.
  4. 프로젝트 설정에서 스레드들이 함께 쓰는 메모리를 확인하고 편집합니다.
  5. 필요하면 외부 서비스를 연결하고, 매일 도는 루틴을 설정합니다.
  6. 노트북을 닫은 뒤에도 휴대폰으로 진행 상황과 결과를 확인합니다.
  • 코디네이터는 낮은 노력 수준으로 두고, 스레드는 작은 모델을 기본으로 쓰다가 복잡한 작업에서만 바꾸는 것이 권장됩니다.
  • 현재 베타이며 Pro·Max 요금제에 순차적으로 제공됩니다.
  • 예전 방식: 터미널 탭 여러 개에서 세션을 직접 띄우고, 같은 저장소의 병렬 작업은 worktree로 나눠 돌렸습니다.

10. 자동화할 일과 모델 고르기

모든 일을 같은 방식, 같은 모델로 자동화하면 비용과 품질 모두 손해를 볼 수 있습니다. 반복 업무인지 단계를 미리 알 수 없는 일인지, 개발 단계인지 운영 단계인지에 따라 실행 방식과 모델을 나누면 효과가 커집니다.

  1. 맡길 업무를 순서가 정해진 반복 업무와 단계를 미리 알 수 없는 탐색형 업무로 나눕니다.
  2. 반복 업무(PR 관리, 코드 리뷰, 정기 보고 등)는 루프나 루틴, 예약 작업으로 맡깁니다.
  3. 탐색형 업무(시스템 최적화 등)는 동적 워크플로에 맡깁니다.
  4. 만들고 시험하는 단계에서는 가장 큰 모델을 쓰고, 안정적으로 운영하는 단계에서는 저렴한 모델로 바꿉니다(배벨 전략).
  5. 멈추지 않고 계속 도는 프로세스에 대비해 중단 장치(서킷 브레이커)를 둡니다.
  6. 토큰 비용이 투자 대비 수익을 내는지 보고 활용 범위를 정합니다.
  • Ramp는 동적 워크플로로 CI 시간을 P50 기준 약 18분에서 6분으로 줄였습니다.
  • LLM은 질문에 맞춰 답하려는 경향이 있으니, 실제로 필요한 것을 정확히 요청하는 판단력이 더 중요합니다.
  • 지금 모델이 아니라 3~6개월 뒤 모델에 맞춰 설계하면 모델이 바뀔수록 시스템이 좋아집니다.
  • Shopify와 Ramp는 엔지니어에게 토큰 예산 상한을 두지 않고 마음껏 실험하게 합니다.

11. Managed Agents로 에이전트 설계하기

Claude Managed Agents는 에이전트의 호스팅, 확장, 샌드박스, 관측을 Anthropic이 맡는 플랫폼입니다. 장애 대응, 영업 보고, 회의 브리프처럼 사내에 오래 두고 쓸 업무 에이전트를 빠르게 만들어 운영할 때 씁니다.

  1. 에이전트에게 맡길 업무 하나를 정합니다(예: 장애 대응, 회의 전 브리프 작성).
  2. 구조를 세 가지 자원으로 나눠 설계합니다: 에이전트(두뇌), 환경(손), 세션(둘을 연결).
  3. 에이전트가 쓸 자격 증명은 Vaults에 따로 저장해 사용자·세션별로 관리합니다.
  4. 세션이 끝나도 배운 내용이 남도록 메모리 스토어를 세션에 붙입니다.
  5. 쌓인 메모리는 드리밍(백그라운드 정리 작업)으로 사실 확인·정리·중복 제거를 합니다.
  6. Outcomes로 좋은 결과의 기준(루브릭)과 반복 횟수를 정해, 기준을 채울 때까지 다시 시도하게 합니다.
  7. 에이전트가 행동할 때 필요한 권한은 사람에게 요청해 승인받도록 합니다.
  • 모델이 좋아질수록 업무 절차 틀(하네스)은 얇게 만들 수 있으니, 새 모델이 나오면 하네스도 다시 살펴보세요.
  • 에이전트끼리 호출해야 하면 API나 얇은 MCP 서버로 노출할 수 있습니다. 한 에이전트가 아이디어를 내고 다른 에이전트가 반박하게 하거나, 막히면 더 똑똑한 모델에 묻는 advisor 방식도 있습니다.
  • 비용 조절 수단이 적고 처음 시작할 때 지연(콜드 스타트)이 있어, 어려운 작업이 아니면 직접 만드는 쪽이 나을 수 있습니다.
  • Actively는 2주, Wispr는 하루 만에 첫 버전을 만들었습니다.

12. 평가로 에이전트 결과 검증하기

평가(evals)는 내 업무에서 AI가 얼마나 잘하는지 체계적으로 재는 테스트입니다. '좀 이상한데' 같은 느낌을 숫자로 바꿔 주기 때문에, 수정이나 모델 교체가 다른 곳을 망가뜨리지 않았는지 확인할 수 있습니다.

  1. 좋은 결과가 무엇인지 성공 기준을 먼저 글로 정합니다.
  2. 공개 벤치마크 대신 내 업무에서 나온 실제 사례로 테스트 세트를 만듭니다.
  3. 형식·필수 문구처럼 정해진 기준은 코드 기반 채점기로 엄격하게 검사합니다.
  4. 문장 품질처럼 뉘앙스가 있는 기준은 모델 기반 채점기(LLM 판정)로 평가합니다.
  5. 판정 모델도 틀릴 수 있으니 여러 채점기를 함께 씁니다.
  6. 새 모델이 나오면 같은 평가를 돌려 옮길지 판단합니다.
  • 평가가 없으면 사용자 불만이 나올 때까지 문제를 모르고 지나치게 됩니다.
  • 결과가 같아도 어떤 과정을 거쳐 나왔는지 사람과 다른 에이전트가 확인할 수 있어야 신뢰할 수 있습니다.
  • Managed Agents의 Outcomes를 쓰면 루브릭을 만족할 때까지 에이전트가 스스로 반복합니다.
