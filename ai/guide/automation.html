업무 자동화·에이전트

이 분야에서는 Claude에게 회의 준비 같은 업무를 맡기고, 반복 작업을 정해진 시간에 자동으로 돌리고, Slack 채널에서 팀 동료처럼 일을 시킬 수 있습니다. 더 나아가 결과를 스스로 검증하고 피드백으로 나아지는 에이전트도 설계할 수 있습니다. 처음이라면 Cowork 업무 위임과 예약 작업부터 해 보세요. 그다음 문서·발표 도구와 팀 채널 활용을 익히고, 마지막으로 에이전트 설계 가이드를 보는 순서를 권합니다.

1. Cowork에 회의 준비 맡기기

Claude Cowork에 캘린더·Slack·이메일과 회의록 폴더를 연결해 두면, 회의 준비 문서를 알아서 조사하고 작성해 줍니다. 여러 곳에 흩어진 정보를 모아 문서 하나로 정리해야 할 때 씁니다.

  1. 캘린더, Slack, 이메일을 Claude에 연결합니다.
  2. 이전 회의록이 들어 있는 폴더를 Claude가 볼 수 있게 지정합니다.
  3. 어떤 회의인지와 시간을 알려 주며 준비를 요청합니다.
  4. 캘린더 검색, 참석자 조사, Slack 스레드 확인, 이전 회의록 검토, 안건 작성을 요청합니다. 이때 기존 문서 형식을 템플릿으로 따르라고 함께 지시합니다.
  5. Claude가 세운 계획을 확인한 뒤 작업이 진행되게 둡니다.
  6. 빠뜨린 출처가 있으면 작업 중에 바로 추가로 요청합니다(예: 이메일도 확인해 달라).
  7. 작업 폴더에 저장된 안건 문서를 열어 검토합니다. 빠진 내용은 Claude에 추가를 요청하거나 직접 고칩니다.
예시
Prep me for today's call with Acme Corp at 1PM.
  • 작업 도중에 지시를 더해도 처음부터 다시 만들지 않고, 방향만 바꿔 이어서 작업합니다.
  • 완성된 문서의 최종 책임과 수정은 사용자에게 있으니, 공유하기 전에 꼭 직접 검토하세요.

2. Cowork 예약 작업 만들기

매시간·매일처럼 반복되는 일을 자연어로 설명하면 Claude가 예약 작업으로 만들어 정해진 주기에 자동으로 실행합니다. 폴더 변경 사항 요약이나 정기 보고처럼 같은 일을 되풀이할 때 씁니다.

  1. 반복할 일을 자연어로 자세히 설명합니다(무엇을 확인하고, 어떻게 정리해, 어디에 저장할지).
  2. Claude가 만든 예약 작업 프롬프트 초안을 읽어 봅니다.
  3. 필요하면 실행 주기를 매시간·매일·평일·수동 중에서 바꿉니다.
  4. 내용이 맞으면 제안을 수락합니다.
  5. 왼쪽 사이드바의 예약(scheduled) 페이지에 작업이 추가됐는지 확인합니다.
  6. 예약 페이지에서 즉시 실행을 눌러 한 번 돌려 보고 결과가 제대로 나오는지 확인합니다.
예시
매시간 공유 드라이브 폴더에서 새로 추가되거나 수정된 문서를 확인하고, 누가 바꿨는지 기록해 줘. 변경 내용은 요약해서 클라이언트별로 묶은 뒤 문서로 저장해 줘.
  • 예약 작업은 컴퓨터가 켜져 있고 Claude 데스크톱 앱이 열려 있을 때만 실행됩니다. 꺼져 있어 놓친 작업은 다시 켰을 때 바로 실행되고, 늦어졌다는 사실도 알려 줍니다.
  • 예약 작업은 실행할 때마다 새 Cowork 세션에서 돌아가 그 시점의 최신 파일과 도구 상태를 기준으로 합니다. 설정해 둔 커넥터도 그대로 쓸 수 있습니다.
  • 대화로 한 번 끝까지 해 보고 결과가 마음에 들면 '매주 평일 오후 4시마다 이 작업을 해 달라'처럼 요청해 반복 작업으로 바꿀 수도 있습니다.
  • 예약 페이지에서 지난 실행 기록을 보고, 지시문과 주기를 수정할 수 있습니다.

3. PDF 자료로 발표 자료 만들기

Adobe Acrobat의 AI 기반 PDF 스페이스에 보고서와 기사 링크를 모아 넣으면 핵심 내용을 정리하고 발표 초안까지 만들어 줍니다. 요약마다 원문 근거가 붙어 있어, 자료 조사부터 발표 준비까지 한곳에서 끝낼 때 좋습니다.

  1. PDF 스페이스에 보고서 파일, 이미지, 웹 링크, 텍스트 같은 자료를 넣습니다.
  2. AI 어시스턴트에 자료의 핵심 내용을 정리해 달라고 요청합니다.
  3. 요약 속 숫자를 눌러 원문의 해당 부분을 열고 근거를 확인합니다.
  4. 정리한 내용으로 프레젠테이션 초안을 만들어 달라고 요청합니다.
  5. Adobe Express 편집 화면에서 글자·배경·아이콘을 하나씩 고칩니다.
  6. 완성한 슬라이드를 JPG, PNG, PPTX, PDF 중 필요한 형식으로 내려받습니다.
  7. AI 어시스턴트에 팀 회의에서 나올 만한 질문 세 개와 답변을 정리해 달라고 요청합니다.
  8. 답변마다 붙은 출처를 눌러 근거를 확인합니다.
예시
팀회의에서 나올 만한 질문 세 개와 답변을 정리해 줘. 자료에서 근거를 찾을 수 없는 내용은 '확인 필요'라고 표시해 줘.
  • PDF 스페이스에는 확장자와 상관없이 파일을 최대 100개까지 넣을 수 있습니다.
  • 근거가 없는 내용은 '확인 필요'라고 표시해 달라고 요청하면 잘못된 정보를 걸러 내기 쉽습니다.

4. Claude for Word로 초안 다듬기

Claude for Word는 Microsoft Word 옆 패널에서 문서를 읽고 실제로 편집까지 합니다. 댓글이 잔뜩 달린 초안을 정리하거나, 사실을 확인하거나, 독자에 맞게 고쳐 써야 할 때 씁니다.

  1. Microsoft AppSource에서 Claude for Microsoft 365를 설치합니다.
  2. Word(웹, Windows, Mac)에서 다듬을 초안을 열고 Claude 패널을 엽니다.
  3. 문서에 달린 댓글을 요약해 달라고 요청합니다.
  4. Box에 있는 문서와 대조해 사실을 확인해 달라고 요청합니다.
  5. 서식 정리, 고객용 문장으로 고쳐 쓰기, 분량 줄이기를 하나씩 요청합니다.
  6. /brand-guidelines처럼 내 Claude 계정에서 만든 스킬로 교정을 요청합니다.
  7. 검토 카드와 추적 변경으로 표시된 수정을 하나씩 수락하거나 거절합니다.
  • 모든 수정이 추적 변경으로 남으므로, 내가 수락하지 않으면 원문은 그대로 유지됩니다.
  • Pro, Max, Team, Enterprise 유료 플랜에 포함되어 있습니다.

5. Excel과 PPT를 한 대화로 잇기

Claude for Excel과 PowerPoint를 함께 쓰면, 열려 있는 두 파일을 하나의 대화로 이어서 다룹니다. Excel에서 분석한 숫자를 슬라이드에 반영해야 할 때, 탭을 오가거나 데이터를 다시 설명하지 않아도 됩니다.

  1. 작업할 Excel 파일과 PowerPoint 파일을 둘 다 엽니다.
  2. 한 번의 프롬프트로 Excel 분석과 슬라이드 갱신을 함께 요청합니다.
  3. Claude가 실시간 셀 값을 읽어 Excel에 표를 만들고 슬라이드를 고치는 과정을 지켜봅니다.
  4. Excel의 숫자가 슬라이드에 제대로 들어갔는지 확인합니다.
  5. 자주 하는 흐름이면 Skills로 저장해 다음부터 한 번에 다시 실행합니다.
예시
비교 기업들의 재무 자료를 가져와 Excel에 트레이딩 컴프스 표를 만들어 줘. 그다음 밸류에이션 요약을 피치덱에 넣고 요약문도 써 줘.
  • 유료 플랜 사용자라면 누구나 Mac·Windows에서 쓸 수 있습니다.
  • 두 앱 사이에서 맥락이 이어지므로 앞에서 한 분석을 다시 설명하지 않아도 됩니다.

6. Slack 채널에서 Claude Tag 쓰기

Claude Tag는 Slack 같은 팀 워크스페이스 채널에 들어온 Claude입니다. 채널 대화와 공유 문서, 연결된 도구를 참고해 일합니다. 채팅 창을 오가며 맥락을 복사해 붙이지 않고, 팀이 일하는 채널에서 바로 복합 작업을 맡길 때 씁니다.

  1. Claude를 쓸 채널 하나에 Claude를 추가합니다.
  2. 작업에 필요한 도구를 Claude Tag에 연결합니다.
  3. 채널이나 스레드에서 Claude를 태그하고 할 일을 요청합니다.
  4. Claude가 단계별로 진행하는 상황을 채널에서 확인합니다.
  5. 기다리지 말고 다른 일을 하다가, 완료나 결정 요청 알림이 오면 확인하고 답합니다.
  6. 필요하면 채널의 다른 사람도 기존 요청에 이어서 추가 요청을 합니다.
예시
@Claude 최근 3일 스레드, Google Drive 회의록, Asana의 열린 작업을 확인해서 이번 주 미결 액션 아이템 목록을 만들어 줘.
  • Team과 Enterprise 계정에서 쓸 수 있습니다. 처음에는 한 채널에서만 시작해 보세요.
  • Claude는 자기 계정으로 일하고, 모든 변경 내역과 요청자를 기록합니다.
  • Claude가 사용자 대신 응답하거나 개별 도구에 접근할 때는 매번 권한을 묻습니다.
  • 예전 방식: 6월 소개 당시에는 Team·Enterprise 베타로 제공되었습니다. 9월 영상부터는 관리자가 채널마다 접근 범위와 자율성을 조절하는 방식이 함께 소개됩니다.

7. Claude Tag에 채널 규칙 기억시키기

Claude Tag는 채널마다 지침을 기억하고, 개입 빈도와 자율 범위도 채널별로 맞출 수 있습니다. 같은 지시를 매번 반복하지 않고 채널의 역할에 맞게 Claude를 길들일 때 씁니다.

  1. 반복해서 지켜야 할 지침을 Remember for this channel: ... 형태로 말해 저장합니다.
  2. 스타일 가이드나 체크리스트 문서를 알려 주고 참고하라고 합니다.
  3. 감시할 범위나 처리 방식 같은 선호를 말로 알려 줍니다.
  4. 매번 태그하기 번거로우면 항상 응답하라고 지시합니다.
  5. 너무 자주 또는 너무 드물게 끼어들면 개입 빈도를 조정해 달라고 말합니다.
  6. 관리자는 채널마다 맡을 일, 접근 범위, 자율 범위를 정합니다.
예시
Remember for this channel: 주간 보고는 항상 체크리스트 문서 형식을 따르고, 결정이 필요한 항목은 맨 위에 적어 줘.
  • 알려 준 문서가 바뀌면 기본적으로 최신 내용을 따릅니다.
  • 채널의 누구든 Claude를 태그해 기억된 내용을 읽고 고칠 수 있습니다.
  • 다른 공개 채널의 정보는 접근 권한을 줄 수 있지만, DM과 비공개 채널에서 배운 내용은 그 안에만 남습니다.
  • 프로젝트 상태를 추적하려면 공개 채널을 쓰는 것이 좋습니다. Claude가 스스로 작업을 검증할 수 있게 해 두면 중간 확인도 줄어듭니다.

8. 업무에 맞는 자동화 방식 고르기

모든 일을 같은 방식으로 자동화하면 비용이 낭비되거나 결과가 불안정해집니다. 매번 단계가 같은 일인지, 단계를 미리 알 수 없는 일인지에 따라 자동화 방식과 모델을 나눠 고르면 효과가 좋아집니다.

  1. 맡길 업무를 적고, 매번 같은 단계를 거치는 일인지 판단합니다.
  2. 단계가 정해진 반복 업무(보고서 수집, PR 관리, 코드 리뷰 등)는 루프·루틴이나 예약 작업으로 맡깁니다.
  3. 단계를 미리 알 수 없는 일(시스템 최적화 등)은 동적 워크플로로 맡깁니다.
  4. 새로 만들고 시험하는 단계에는 가장 큰 모델을 쓰고, 안정된 반복 운영에는 저렴한 모델을 씁니다(배벨 전략).
  5. 폭주하는 작업에 대비해, 일정 조건이 되면 멈추는 서킷 브레이커를 정해 둡니다.
  6. 요청할 때는 실제로 필요한 결과를 정확히 적습니다.
  • LLM은 질문에 맞춰 답하려는 경향이 있습니다. 그래서 무엇을 요청할지 정하는 판단력이 더 중요해집니다.
  • 모델이 빠르게 좋아지므로 지금 모델이 아니라 3~6개월 뒤 모델을 기준으로 설계하라는 조언이 있습니다. 복잡한 업무 절차 틀(하네스)도 점점 얇게 만드는 추세입니다.
  • 토큰 비용이 투자 대비 수익을 내는 구간이라면, 비용을 아끼기보다 활용을 늘리는 쪽이 낫다는 사례가 많습니다.

9. Claude Code Projects로 병렬 작업하기

Claude Code의 Project는 Claude가 여러 작업을 조율하는 하나의 지속적인 대화입니다. 작업마다 클라우드에서 따로 도는 스레드를 만들어 병렬로 처리합니다. 여러 세션이나 저장소에 걸친 큰 목표를 노트북을 닫은 뒤에도 계속 진행시키고 싶을 때 씁니다.

  1. 여러 세션이 필요한 큰 목표를 하나 정해 Project 대화에 설명합니다.
  2. Claude가 작업마다 스레드를 만들어 병렬로 처리하게 둡니다.
  3. 목업이나 디자인 명세처럼 모든 스레드가 함께 볼 파일을 library 탭에 추가합니다.
  4. 코디네이터는 낮은 노력 수준으로 둡니다.
  5. 스레드는 작은 모델을 기본으로 쓰고, 복잡한 작업에서만 큰 모델로 바꿉니다.
  6. 프로젝트 설정에서 스레드들이 공유하는 메모리를 확인하고 고칩니다.
  7. 노트북을 닫은 뒤에는 휴대폰으로 진행 상황을 확인합니다.
  • 각 스레드는 클라우드의 자기 브랜치에서 독립 세션으로 돌아갑니다.
  • 한 프로젝트 안에서 풀 리퀘스트 검토, 아티팩트 생성, 외부 서비스 연결, 매일 도는 루틴 설정까지 할 수 있습니다.
  • 현재 베타이며 Pro·Max 요금제에 차례로 제공됩니다.
  • 예전 방식: 같은 저장소에서 여러 세션을 병렬로 돌릴 때는 터미널 탭마다 worktree를 따로 만들어 운영했습니다.

10. 루브릭으로 에이전트 결과 검증하기

에이전트에 '좋은 결과의 기준'(루브릭)을 주면, 기준을 만족할 때까지 스스로 다시 시도하게 할 수 있습니다. Claude Managed Agents의 Outcomes 기능이 바로 이런 방식이며, 결과 품질이 중요한 어려운 작업에 맞습니다.

  1. 맡길 작업의 좋은 결과가 무엇인지 평가 기준(루브릭)으로 적습니다.
  2. 기준을 만족하지 못할 때 몇 번까지 다시 시도할지 정합니다.
  3. Managed Agents의 Outcomes 기능에 루브릭과 반복 횟수를 넣어 에이전트를 실행합니다.
  4. 나온 결과가 루브릭을 실제로 만족하는지 직접 확인합니다.
  5. 품질이 더 중요하면 한 에이전트가 낸 아이디어를 다른 에이전트가 반박하게 하거나, 막혔을 때 더 똑똑한 모델에 묻게(advisor 전략) 구성합니다.
  • 대규모로 운영할수록 검증이 가장 중요합니다. Spotify는 LLM 판정자(judge)와 작업 분해로 자동화의 한계를 넘었습니다.
  • Managed Agents는 비용을 조절할 수단이 적고 처음 시작할 때 지연(콜드 스타트)이 있다는 의견이 있습니다. 어려운 작업이 아니면 직접 만드는 쪽도 검토하세요.
  • 에이전트끼리는 API나 얇은 MCP 서버로 서로 호출하게 연결할 수 있습니다.

11. 피드백으로 나아지는 에이전트 만들기

사람이 고친 내용을 모아 스킬에 다시 반영하면, 에이전트가 팀의 판단을 배우며 계속 나아집니다. 교정, 문서 검토, 지원서 평가처럼 기준이 사람의 판단에 달려 있고 시간이 지나며 바뀌는 업무에 맞습니다.

  1. 전문가가 과거에 고친 기록을 모읍니다(예: 편집장의 수정 내역).
  2. 그 기록으로 스킬을 만들되, 할 일을 나열하기보다 어떻게 생각할지를 원칙 중심으로 씁니다.
  3. 에이전트가 문서에 바로 고치지 말고 제안 수정을 달게 합니다.
  4. 에이전트의 제안 뒤에 사람이 추가로 고친 내용을 추적합니다.
  5. 추적한 수정을 스킬에 다시 반영하고, 지침 변경은 코드처럼 수정·검토·병합합니다.
  6. 이 피드백 과정이 매일 돌아가도록 반복 작업으로 만듭니다.
  • Every는 편집장의 과거 수정 3만 건으로 스킬을 만들어 Google Docs에 제안 수정을 달게 했습니다.
  • 공개된 Slack 채널에서 프롬프트를 쓰면 잘 쓰는 사람의 방식이 동료에게 자연스럽게 퍼집니다.
  • 기준을 미리 고정하지 않고 담당자의 결정에서 계속 배우게 하면, 선호가 바뀔 때마다 시스템을 다시 만들 필요가 없습니다.
  • 알게 된 것을 글로 남겨 공유하면 동료의 학습 자료가 되고, 에이전트가 읽을 자료도 됩니다.
