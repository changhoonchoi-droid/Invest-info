업무 자동화·에이전트

이 분야에서는 Claude Cowork에 파일 정리·회의 준비 같은 일을 통째로 맡기고, 예약 작업과 스킬로 매주 반복되는 보고·브리핑을 자동으로 돌리고, Slack 채널이나 클라우드 루틴으로 에이전트가 먼저 일하게 만드는 방법을 다룹니다. 처음이라면 'Cowork 시작하기 → 회의 준비 → 예약 작업 → 스킬' 순서로 익히세요. 그다음 팀 채널(Claude Tag), Claude Code 루틴, 콘텐츠 파이프라인과 사람의 확인 지점 설계로 넓혀 가면 됩니다.

  • Claude Code Projects가 베타로 나왔습니다. 작업마다 클라우드의 별도 브랜치에서 스레드가 병렬로 돌아 노트북을 닫아도 일이 계속되고, 매일 도는 루틴도 한 프로젝트 안에서 설정할 수 있습니다(Pro·Max 순차 제공).
  • Claude Tag는 Team·Enterprise 계정에서 채널마다 맡을 일·개입 빈도·자율 범위를 정할 수 있고, Remember for this channel: ...로 채널별 지침을 저장합니다.

1. Cowork로 폴더 정리 맡기기

Cowork는 대화를 한 단계씩 주고받는 대신 작업 전체를 맡기는 방식으로, 내 컴퓨터의 파일과 Google Drive·Notion·Slack 같은 서비스를 다룹니다. 다운로드 폴더 정리처럼 범위가 분명한 일로 처음 써 보기에 좋습니다.

  1. macOS 또는 Windows에서 Claude 데스크톱 앱을 열고 Cowork 탭을 누릅니다.
  2. Claude가 작업할 폴더를 선택해 접근을 허용합니다.
  3. 필요하면 커넥터를 연결해 Google Drive·Notion·Slack 등에서 맥락을 가져오게 합니다.
  4. 정리할 내용을 요청하면서 변경 전에 계획부터 보여 달라고 합니다.
  5. 제안된 계획을 확인하고, 삭제 후보 중 남길 파일은 검토 폴더로 옮기라고 수정을 지시합니다.
  6. 승인하면 Claude가 실제로 파일을 옮깁니다. 오른쪽 위에서 진행 상황을 확인합니다.
예시
Organize my downloads folder. Scan the contents and propose a plan.
  • Pro·Max·Team·Enterprise 요금제의 데스크톱 앱에서 쓸 수 있고, Claude는 파일을 바꾸기 전에 권한을 묻습니다.
  • 작업 중에는 데스크톱 앱을 열어 두어야 하며 세션은 내 기기에 로컬로 저장됩니다.
  • Settings의 Cowork 탭에서 내 역할 설명이나 기본 파일 형식(예: Word 문서) 같은 전역 지침을 정해 둘 수 있습니다.
  • 브라우저 작업까지 맡기려면 Claude in Chrome을 따로 설정해야 합니다.

2. Cowork로 회의 준비 문서 만들기

캘린더·Slack·이메일과 지난 회의록을 Claude가 직접 찾아 읽고 회의 안건 문서를 만들어 줍니다. 회의 전에 흩어진 맥락을 모으는 시간을 줄이고 싶을 때 씁니다.

  1. 캘린더, Slack, 이메일을 Claude에 연결합니다.
  2. 회의록이 있는 폴더를 Claude가 볼 수 있게 지정합니다.
  3. 회의 상대와 시간을 알려 주며 회의 준비를 요청합니다.
  4. 캘린더 검색, 참석자 조사, Slack 스레드 확인, 이전 회의록 검토, 안건 작성을 요청하고 기존 문서 형식을 템플릿으로 따르라고 지시합니다.
  5. Claude가 세운 계획을 확인하고 작업이 진행되게 둡니다.
  6. 빠뜨린 출처가 있으면 작업 도중에 추가로 요청합니다(예: 이메일도 확인).
  7. 완성된 안건 문서를 작업 폴더에서 열어 검토하고, 빠진 내용은 추가를 요청하거나 직접 고칩니다.
예시
Prep me for today's call with Acme Corp at 1PM.
  • 작업 도중 지시를 더해도 처음부터 다시 만들지 않고 방향만 바꿔 이어갑니다.
  • 최종 문서의 책임과 수정은 사용자에게 있으니 보내기 전에 꼭 읽어 봅니다.

3. Cowork 예약 작업 만들기

매시간·매일·평일처럼 정해진 주기에 Cowork가 같은 일을 자동으로 실행하게 하는 기능입니다. 아침마다 메일함 정리, 일요일 저녁 주간 지표 준비, 공유 드라이브 변경 요약 같은 반복 업무에 씁니다.

  1. 반복할 일을 자연어로 설명합니다(예: 매시간 공유 드라이브 폴더의 추가·수정 문서 확인, 변경자 기록, 요약, 클라이언트별 그룹화, 문서로 저장).
  2. Claude가 만든 예약 작업 프롬프트 초안을 검토합니다.
  3. 필요하면 주기를 매시간·매일·평일·수동 중에서 바꿉니다.
  4. 내용이 맞으면 제안을 수락합니다.
  5. 왼쪽 사이드바의 예약(scheduled) 페이지에 작업이 추가됐는지 확인합니다.
  6. 설정 후 한 번 실행해 결과가 제대로 나오는지 확인합니다.
예시
매시간 공유 드라이브 폴더에서 새로 추가되거나 수정된 문서를 확인해, 누가 바꿨는지 기록하고 내용을 요약한 뒤 클라이언트별로 묶어 문서로 저장해 줘.
  • 컴퓨터가 켜져 있고 Claude 데스크톱 앱이 열려 있어야 실행됩니다. 꺼져 있어 놓친 작업은 복귀 후 바로 실행되고 지연됐다고 알려 줍니다.
  • 실행마다 새 Cowork 세션으로 돌아 최신 파일·도구 상태를 기준으로 하며, 설정해 둔 커넥터도 그대로 씁니다.
  • 예약 페이지에서 지난 실행 기록 확인, 지시문·주기 수정, 즉시 실행을 할 수 있습니다.
  • 잘 된 대화 끝에 '매주 평일 오후 4시마다 이 작업을 해 달라'고 말해 바로 맡기는 방법도 있습니다.

4. 스킬로 미팅 브리핑·후속 처리하기

스킬은 반복하는 업무 방식을 일반 텍스트 파일로 저장해 두고 /로 불러 쓰는 기능입니다. 같은 지시로 매번 같은 품질의 결과를 얻을 수 있어, 미팅 전 계정 브리핑과 미팅 후 녹취록 정리처럼 자주 하는 일에 맞습니다.

  1. Cowork 세션을 열고 미팅 전에 알고 싶은 내용을 설명해 스킬 파일 초안을 만듭니다.
  2. 설정에서 데이터 웨어하우스, Salesforce, 웹, 이메일, Slack 등 필요한 곳을 연결합니다.
  3. Claude가 파일을 읽고 수정하고 저장할 폴더를 지정합니다.
  4. 테스트용 계정으로 스킬을 실행해 결과를 보고 다듬습니다.
  5. 미팅 전 Cowork에서 /를 입력하고 계정 전략 스킬을 고른 뒤 고객사 이름을 입력합니다.
  6. 미팅 후 같은 세션으로 돌아와 /로 통화 녹취록 처리 스킬을 고릅니다.
  7. Claude가 만든 개인 할 일, 내부 Slack 메시지, 고객 후속 메시지를 하나씩 확인하고 승인한 뒤 발송합니다.
  • 스킬은 일반 텍스트 파일이라 언제든 열어서 동작을 확인하고 회사 방식에 맞게 고칠 수 있습니다.
  • 피드백을 줄 때마다 그 내용을 스킬에 다시 반영하면 결과가 점점 좋아집니다.
  • 법무팀의 /brief처럼 과거 검토 문서와 새 Slack·Gmail 대화를 비교해 '무엇이 바뀌었는지'만 알려 주는 스킬도 만들 수 있습니다. 이름을 걸고 보내는 답장이라면 브리핑이 가리키는 원문을 직접 확인합니다.
  • Word 패널에서도 /brand-guidelines 같은 나만의 스킬을 불러 교정에 쓸 수 있습니다.

5. Cowork로 주간 지표 리뷰 자동화하기

예약 작업과 스킬을 묶어 매주 지표 리뷰 문서·Slack 메시지·리더십용 슬라이드까지 만드는 흐름입니다. 숫자 수집과 검증은 Claude가, 서사와 초점은 사람이 정합니다.

  1. 리뷰 준비, 교정(숫자 검증), 액션 아이템 관리용 스킬을 각각 만듭니다.
  2. 일요일 저녁에 실행되는 예약 작업을 설정합니다.
  3. 월요일 아침 Cowork를 열어 준비된 숫자와 제안된 집중 영역을 확인합니다.
  4. 분기 리뷰 문서를 넣고 이번 주 초점을 지시합니다.
  5. Claude가 데이터 불일치를 알리면 어떻게 처리할지 알려 줍니다.
  6. 지표 표와 헤드라인만 있는 초안을 먼저 확인합니다.
  7. ship it이라고 말해 최종 문서와 Slack 메시지를 만듭니다.
  8. 같은 데이터로 리더십용 슬라이드 한 장을 만들도록 요청합니다.
  9. 이번 주 배운 점을 스킬에 반영하도록 요청합니다.
예시
ship it
  • 데이터가 맞지 않으면 Claude가 추측하지 않고 질문하도록 되어 있으니 답을 주면 됩니다.
  • 교정 스킬은 초안의 모든 숫자가 검증된 데이터 출처로 추적되는지 확인합니다.
  • 후속 조치는 Asana 작업으로 남겨 누락을 막습니다.
  • 스킬을 팀과 공유하면 누구나 같은 결과를 낼 수 있습니다.

6. Slack에서 Claude Tag로 일 맡기기

Claude Tag는 Slack 채널에 Claude를 추가해 팀 대화를 따라가며 일하게 하는 기능입니다. 채팅 창을 오가며 맥락을 복사할 필요 없이, 채널에서 태그만 하면 대화 기록·공유 문서·연결된 도구를 참고해 정리·초안 작성·도구 내 수정까지 합니다.

  1. Claude를 쓸 Slack 채널 하나에 Claude를 추가합니다.
  2. 필요한 도구(Google Drive, Asana 등)를 Claude Tag에 연결합니다.
  3. 작업이 필요한 스레드에서 Claude를 태그해 일을 요청합니다.
  4. Claude가 단계별로 진행하는 상황을 채널에서 확인하고, 그동안 다른 일을 합니다.
  5. 완료 또는 결정 요청 알림이 오면 확인하고 답합니다.
  6. 반복할 지침은 Remember for this channel: ... 형태로 말해 저장시킵니다.
  7. 너무 자주 또는 드물게 끼어들면 개입 빈도를 조정해 달라고 말합니다.
예시
(채널에서 Claude를 태그한 뒤) 최근 3일 스레드, Google Drive 회의록, Asana의 열린 작업을 확인해서 이번 주 미결 액션 아이템 목록을 만들어 줘.
  • Team·Enterprise 계정에서 쓸 수 있으며, 처음에는 한 채널에서만 시작해 보세요.
  • Claude는 자체 계정으로 일하고 모든 변경과 요청자가 기록됩니다. 사용자를 대신해 응답하거나 개별 도구에 접근할 때는 매번 권한을 묻습니다.
  • DM과 비공개 채널 내용은 그 안에만 남고, 채널마다 접근 범위가 나뉩니다. 프로젝트 상태를 추적하려면 공개 채널이 좋습니다.
  • 스타일 가이드나 체크리스트 문서를 알려 주면 참고하고, 문서가 바뀌면 최신 내용을 따릅니다.

7. Claude Code 루틴 예약하기

루틴은 프롬프트·저장소·커넥터·트리거만 정하면 Anthropic 관리형 인프라에서 Claude Code 세션을 자동 실행하는 기능입니다. 내 노트북이 꺼져 있어도 돌아가며, 일정 또는 GitHub 이벤트·웹훅으로 시작할 수 있습니다.

  1. 터미널에서 Claude Code를 실행합니다.
  2. /schedule을 입력하고 원하는 작업을 적습니다.
  3. Claude가 묻는 질문에 답합니다(예: 매주 몇 시에 실행할지, 끝난 뒤 Slack 등으로 알릴지).
  4. 작업에 필요한 저장소(예: 소스 코드 저장소와 문서 저장소)를 컨텍스트로 연결합니다.
  5. 만들어진 루틴을 웹의 Claude Code에서 확인하고, 실행 결과 세션을 열어 봅니다.
예시
/schedule 매주 main에 병합된 변경을 문서 저장소와 비교해서, 바뀐 부분이 있으면 문서 수정 PR을 만들어 줘
  • 트리거(언제), 컨텍스트(무엇을 알아야 하나), 조종(어떻게 바로잡나) 세 가지를 먼저 정하세요.
  • 모든 루틴은 웹·CLI·데스크톱에서 열어 지시를 이어 갈 수 있는 일반 Claude Code 세션입니다.
  • 처음에는 결과를 직접 확인하고, 신뢰가 쌓이면 권한을 넓혀 가세요.
  • 베타인 Claude Code Projects 안에서도 매일 도는 루틴을 설정할 수 있습니다. 코디네이터는 낮은 노력 수준, 스레드는 작은 모델을 기본으로 두고 복잡한 작업에서만 바꾸는 것이 권장됩니다.

8. 업무 단계를 파이프라인으로 만들기

기획·리서치부터 대본·검수·패키징·업로드까지 반복되는 단계를 하나의 파이프라인으로 짜고, 각 단계 규칙을 스킬로 저장해 원본만 넘기면 돌아가게 하는 방법입니다. 영상 제작 사례지만 보고서·콘텐츠 등 여러 단계 업무에 그대로 응용할 수 있습니다.

  1. 기획·리서치 단계에서 사람들이 관심 갖는 주제와 형식을 조사시킵니다.
  2. 초안 단계에서 내 말투를 반영해 큰 틀과 스토리보드를 짜게 합니다.
  3. 남의 자료를 쓸 때는 Claude가 질문을 뽑아 나를 인터뷰하게 하고, 내 소감과 의견을 말로 답해 내 해석을 더합니다.
  4. 반복되는 규칙(컷 편집, 모션 그래픽 등)은 단계마다 스킬로 만들어 둡니다.
  5. 검수 단계에서 Claude가 쓴 것은 Codex가, Codex가 쓴 것은 Claude가 독립적으로 검증하게 합니다.
  6. 패키징 단계에서 썸네일과 제목을 만들고 업로드까지 맡깁니다.
  7. 공개 전에는 사람이 원문과 대조해 마지막으로 검수합니다.
  • 한 편씩 만들지 말고 시리즈로 묶어 시리즈마다 스킬을 두면 같은 지시로 같은 품질이 나옵니다.
  • 서너 번 손대지 않고도 잘 나오면 그때 매일 자동 실행으로 넘기세요.
  • 번역·자막만 단 결과물은 누구나 만들 수 있어 차별점이 없습니다. 현업 경험과 검수자로서의 판단이 사람의 몫입니다.
  • 남의 파이프라인 화면을 캡처해 Claude에 붙여 넣고 내 상황에 맞게 바꿔 달라고 하면 출발점을 빨리 만들 수 있습니다.

9. 사람이 확인할 지점 설계하기

여러 작업을 동시에 돌릴 때 내가 병목이 되지 않도록, 에이전트에 권한을 넉넉히 주되 비용이 크거나 되돌리기 어려운 지점에서만 내 확인을 받게 정하는 방법입니다(Human on the loop).

  1. 피드백을 줄 때마다 그 내용을 스킬이나 규칙으로 남깁니다.
  2. 에이전트에 가능한 한 많은 권한을 줍니다.
  3. 크레딧·비용처럼 한 번에 크게 나가는 것은 상한을 정합니다.
  4. 되돌리기 어려운 지점(예: 캐릭터 생성, 외부 발송)은 실행 전에 내 확인을 받도록 정합니다.
  5. Claude가 스스로 결과를 검증할 수 있게 기준을 알려 주어 중간 확인을 줄입니다.
  • 알렉스의 상한 예시는 쇼츠 500, 롱폼 1,500 크레딧이지만 내 요금제에 맞게 정해야 합니다.
  • 폭주하는 작업에 대비해 멈출 장치(서킷 브레이커)를 두라는 조언도 있습니다.
  • Cowork·Claude Tag·Duet 모두 사용자를 대신해 보내거나 바꾸기 전에 확인을 받는 구조이니, 승인 단계를 건너뛰지 마세요.

10. 발표 예상 질문·답변 준비하기

Adobe Acrobat의 PDF 스페이스에 보고서·기사 링크 등을 넣고 AI 어시스턴트로 핵심 정리, 발표 초안, 예상 질문과 답변까지 만드는 방법입니다. 답변마다 원문 출처가 붙어 근거를 바로 확인할 수 있습니다.

  1. Acrobat의 PDF 스페이스에 파일, 이미지, 웹 링크, 텍스트 등 자료를 넣습니다.
  2. AI 어시스턴트에 팀 회의에서 나올 만한 질문 세 개와 답변을 정리해 달라고 요청합니다.
  3. 각 답변에 붙은 출처를 눌러 원문의 근거를 확인합니다.
예시
팀 회의에서 나올 만한 질문 세 개와 답변을 정리해 줘. 근거가 없는 내용은 '확인 필요'라고 표시해 줘.

11. 소모적인 업무 절차 점검하기

자동화할 대상을 고르기 전에, 팀에서 가장 부담이 큰 회의나 절차가 아직도 필요한지부터 따져 보는 방법입니다. 없애도 되는 일은 없애고, 남길 일만 Claude로 줄여야 자동화 효과가 커집니다.

  1. 팀에서 가장 비용이 크거나 모두가 꺼리는 업무 절차·회의를 하나 고릅니다.
  2. 그 절차가 원래 어떤 목적을 위해 생겼는지 묻습니다.
  3. 지금도 그 목적에 도움이 되는지 확인합니다.
  4. 도움이 되지 않으면 없애고, 필요하면 Claude가 도울 수 있는 부분을 찾아 자동화합니다.
  5. 한 번에 한 단계씩 바꿔 나갑니다.
  • 영상 사례에서는 50명이 참석하지만 다들 노트북만 보던 주간 리뷰를 '왜 하는가'라는 질문 하나로 취소했습니다.
  • 절차는 스스로 사라지지 않고 쌓이기만 하므로 의식적으로 정리해야 합니다.
  • 모델이 좋아지면 검증 수준도 달라지니 주기적으로 다시 점검합니다.
