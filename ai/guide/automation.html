업무 자동화·에이전트

이 분야에서는 같은 일을 정해진 시간에 자동으로 돌리는 방법, Slack 같은 팀 채널이나 Word·Excel·PowerPoint 안에서 Claude에게 일을 맡기는 방법, 그리고 스스로 나아지는 에이전트를 설계하는 방법을 다룹니다. 처음이라면 '예약 작업'과 '팀 채널에서 일 시키기'로 시작하세요. 그다음 문서 도구 활용과 Projects를 익히고, 에이전트 설계와 비용 전략은 마지막에 보는 순서를 권합니다.

  • Claude Code에 Projects(베타)가 생겼습니다. 대화 하나에서 여러 스레드를 클라우드의 별도 브랜치로 동시에 돌리고, 결과는 휴대폰으로도 확인할 수 있습니다. Pro·Max 요금제에 차례로 열리고 있습니다.
  • Claude Tag가 나왔습니다. Team·Enterprise 계정에서 Slack 같은 팀 채널에 Claude를 추가하고, 채널 안에서 태그해 바로 일을 맡길 수 있습니다.

1. 반복 업무를 예약 작업으로 맡기기

한 번 해 보고 결과가 마음에 든 작업을 정해진 시간마다 Claude가 자동으로 하게 하는 기능입니다. 매일 쓰는 보고서나 다음 날 계획처럼 형식이 정해진 일에 잘 맞습니다.

  1. 자동으로 맡기고 싶은 작업을 먼저 대화로 한 번 요청합니다. 어떤 자료를 가져올지 함께 적습니다.
  2. 결과에서 잘된 점과 부족한 점을 짚고 고쳐 달라고 요청합니다.
  3. 대상, 기준, 형식 같은 조건을 구체적으로 덧붙여 결과를 다듬습니다.
  4. 완성된 결과를 직접 읽고, 원하는 내용이 다 들어 있는지 확인합니다.
  5. 마음에 들면 매주 평일 오후 4시마다 이 작업을 해 달라처럼 요일과 시간을 정해 반복 실행을 요청합니다.
  6. 설정한 뒤 한 번 실행해서 제대로 돌아가는지 확인합니다.
예시
매주 평일 오후 4시마다 이 작업을 해 줘
  • 타이핑이 길어지는 요청은 음성으로 한 번에 말하면 편합니다.
  • 대상(학년·팀), 주제, 적용할 기준을 요청에 구체적으로 적어야 매번 결과가 고르게 나옵니다.
  • Claude Code Projects 안에서도 매일 도는 루틴을 설정할 수 있습니다.

2. 팀 채널에서 Claude Tag로 일 시키기

Claude Tag는 Slack 같은 팀 채널에 Claude를 넣어 두고, 팀원 누구나 태그해서 일을 맡기는 기능입니다. 채널 대화, 공유 문서, 연결된 도구를 참고해 정리, 문서 초안 작성, 도구 안에서 수정까지 합니다. Team·Enterprise 계정에서 쓸 수 있습니다.

  1. Slack 같은 팀 워크스페이스의 채널에 Claude를 추가합니다.
  2. 채널에서 Claude를 태그하고, 참고할 자료와 원하는 결과물을 함께 적어 요청합니다.
  3. Claude가 단계별로 진행하는 상황을 채널에서 확인합니다.
  4. 기다리지 말고 다른 일을 하다가, 완료 알림이나 결정을 묻는 알림이 오면 확인합니다.
  5. 추가로 필요한 것이 있으면 다른 팀원도 같은 요청에 이어서 요청할 수 있습니다.
  6. 자주 쓰는 지침은 Remember for this channel: ... 형태로 말해 채널에 저장합니다.
예시
@Claude 최근 3일 스레드, Google Drive 회의록, Asana 열린 작업을 확인해서 이번 주 미결 액션 아이템 목록을 만들어 줘
  • 스타일 가이드나 체크리스트 문서를 알려 주면 그 문서를 참고합니다. 문서가 바뀌면 기본으로 최신 내용을 따릅니다.
  • 채널 기억은 누구나 Claude를 태그해 읽고 고칠 수 있으니, 팀에서 정한 규칙만 저장하세요.
  • DM과 비공개 채널은 공개되지 않습니다. 다른 공개 채널은 접근 권한을 줄 수 있습니다.
  • Claude는 별도 계정으로 일하며 모든 변경과 요청자를 기록합니다. 사용자를 대신해 응답하거나 도구에 접근할 때는 매번 권한을 묻습니다.

3. Word에서 초안을 완성 문서로 다듬기

Claude for Word는 Word 옆 패널에서 문서를 읽고 실제로 편집까지 합니다. 댓글이 많이 달린 초안을 정리하거나, 사실을 확인하고, 독자에 맞게 고쳐 쓸 때 유용합니다. 모든 수정은 변경 내용 추적으로 남아서 직접 수락하거나 거절할 수 있습니다.

  1. Microsoft AppSource에서 Claude for Microsoft 365를 설치합니다. Word 웹, Windows, Mac에서 쓸 수 있습니다.
  2. 다듬을 초안을 Word에서 열고 Claude 패널을 엽니다.
  3. 문서에 달린 댓글을 요약하고 반영해 달라고 요청합니다.
  4. Box 같은 연결된 자료와 대조해 사실관계를 확인해 달라고 요청합니다.
  5. 서식 정리, 고객용 문장으로 고쳐 쓰기, 분량 줄이기를 하나씩 요청합니다.
  6. /brand-guidelines처럼 내 Claude 계정에서 만든 스킬을 패널에서 불러 교정합니다.
  7. 검토 카드와 추적된 변경을 하나씩 보고 수락하거나 거절합니다.
예시
이 문서에 달린 댓글을 요약하고, Box에 있는 자료와 대조해서 사실관계가 틀린 부분을 표시해 줘
  • Pro, Max, Team, Enterprise 유료 플랜에 포함되어 있습니다.
  • 한 번에 다 맡기지 말고 요약 → 사실 확인 → 고쳐 쓰기 → 줄이기 순서로 나눠 요청하면 검토하기 쉽습니다.

4. Excel·PowerPoint를 한 대화로 잇기

Claude for Excel과 PowerPoint는 열려 있는 두 파일을 한 대화 안에서 함께 다룹니다. Excel에서 분석한 숫자를 그대로 슬라이드에 반영할 수 있어서, 데이터를 다시 설명하거나 탭을 오갈 필요가 없습니다.

  1. 작업할 Excel 파일과 PowerPoint 파일을 둘 다 엽니다.
  2. Excel에 가져올 데이터와 만들 표를 한 번에 요청합니다.
  3. Claude가 만든 표의 실제 셀 값을 확인합니다.
  4. 같은 대화에서 분석 요약을 PowerPoint 슬라이드에 넣어 달라고 요청합니다.
  5. 요약문까지 써 달라고 이어서 요청합니다.
  6. 잘 된 흐름은 Skills로 저장해 두고, 다음에는 한 번에 다시 실행합니다.
  • 유료 플랜 사용자라면 Mac·Windows 모두에서 쓸 수 있습니다.
  • 회사 정책상 필요하면 Amazon Bedrock, Google Cloud Vertex AI, Microsoft Foundry로도 이용할 수 있습니다.

5. Claude Code Projects로 큰 일 나누기

Project는 Claude가 여러 작업을 조율하는 하나의 대화입니다. 작업마다 스레드가 생기고, 각 스레드는 클라우드의 별도 브랜치에서 동시에 돌아갑니다. 노트북을 닫아도 일이 계속되므로, 여러 세션이나 저장소에 걸친 큰 목표에 알맞습니다.

  1. Claude Code에서 Project를 만들고, 이루려는 큰 목표를 설명합니다.
  2. 목표를 작업 단위로 나눠 스레드로 맡깁니다.
  3. 목업이나 디자인 명세처럼 모든 스레드가 함께 볼 자료는 library 탭에 올립니다.
  4. 코디네이터는 낮은 노력 수준으로 두고, 스레드는 작은 모델로 시작합니다.
  5. 복잡한 작업을 맡은 스레드만 더 큰 모델로 바꿉니다.
  6. 스레드가 함께 쓰는 메모리는 프로젝트 설정에서 확인하고 고칩니다.
  7. 진행 상황은 휴대폰으로 확인하고, 풀 리퀘스트 검토도 프로젝트 안에서 합니다.
  • Projects는 베타이며 Pro·Max 요금제에 차례로 열리고 있습니다.
  • 프로젝트 안에서 외부 서비스를 연결하거나 매일 도는 루틴을 설정할 수도 있습니다.
  • Projects 이전에는 같은 저장소에서 여러 세션을 동시에 돌릴 때 worktree를 따로 썼습니다(DoorDash 사례).

6. 루틴과 동적 워크플로 나눠 쓰기

에이전트에게 일을 맡길 때는 작업 성격에 맞는 방식을 고릅니다. 단계가 정해진 반복 업무는 루프·루틴으로, 단계를 미리 알 수 없는 탐색형 작업은 동적 워크플로로 맡깁니다. 결과 품질이 중요하면 기준표(루브릭)를 주고 그 기준을 넘을 때까지 반복시킵니다.

  1. 맡길 업무를 적고, 각 업무의 단계가 정해져 있는지 판단합니다.
  2. PR 관리, 코드 리뷰, 보고서 수집처럼 단계가 정해진 일은 루프·루틴으로 맡깁니다.
  3. 시스템 최적화처럼 단계를 미리 알 수 없는 일은 동적 워크플로로 맡깁니다.
  4. 품질이 중요한 결과물에는 합격 기준을 루브릭으로 적어 줍니다.
  5. Claude Managed Agents라면 Outcomes로 루브릭을 만족할 때까지 반복하게 합니다.
  6. 폭주하는 프로세스를 대비해 멈추는 조건(서킷 브레이커)을 미리 정합니다.
  • Ramp는 동적 워크플로를 쓴 뒤 CI 시간을 P50 기준 약 18분에서 6분으로 줄였습니다.
  • Managed Agents는 시작이 느린 콜드 스타트가 있고 비용 조절 수단이 적습니다. 어려운 작업에 쓰고, 그 밖의 일은 직접 만드는 쪽도 함께 검토하세요.
  • 지금 모델이 아니라 3~6개월 뒤 모델을 기준으로 설계하라는 조언이 있습니다.

7. 피드백으로 스스로 나아지는 스킬 만들기

사람이 고친 내용과 판단을 모아 스킬로 만들고, 새로 고친 내용을 계속 다시 반영해 에이전트가 점점 나아지게 하는 방식입니다. 교정, 지원서 검토처럼 팀의 판단 기준이 중요한 업무에 알맞습니다.

  1. 사람이 실제로 고친 기록이나 결정 기록을 모읍니다. 예를 들면 편집장이 과거에 수정한 내용입니다.
  2. 모은 기록으로 스킬을 만들고, 정해진 행동보다 어떻게 판단할지를 원칙 위주로 적습니다.
  3. 에이전트가 결과를 곧바로 확정하지 않고 제안으로 남기게 합니다. 예를 들면 Google Docs의 수정 제안입니다.
  4. 사람이 추가로 고친 내용을 추적합니다.
  5. 추적한 수정을 주기적으로 스킬에 반영합니다.
  6. 스킬을 바꿀 때는 코드처럼 제안하고, 검토하고, 병합하는 절차를 거칩니다.
  • 규칙을 하나하나 늘리기보다 원칙을 가르쳐야 새로운 상황에서도 잘 대응합니다.
  • 기준을 처음부터 고정하지 말고 사람의 결정에서 계속 배우게 하면, 선호가 바뀔 때마다 다시 만들 필요가 없습니다.
  • 피드백 루프를 매일 돌리면 팀의 판단이 자동으로 에이전트에 반영됩니다.

8. 팀 전체로 AI 활용 퍼뜨리기

몇 사람만 잘 쓰는 데서 그치지 않고 조직 전체가 AI를 업무에 쓰게 만드는 방법입니다. 도입 사례를 낸 회사들은 넉넉한 토큰 예산, 보안팀과의 협업, 공개된 곳에서 쓰는 프롬프트, 글로 남기는 공유를 공통으로 강조합니다.

  1. 경영진의 지원을 받고, IT·보안팀과 함께 사용 범위와 보안 기준을 정합니다.
  2. Cowork처럼 전 직원이 쓸 수 있는 도구를 열어 줍니다.
  3. 자유롭게 시험해 볼 수 있도록 넉넉한 토큰 예산을 줍니다.
  4. Slack 공개 채널처럼 동료가 볼 수 있는 곳에서 프롬프트를 쓰게 해, 잘 쓰는 사람의 방식이 퍼지게 합니다.
  5. 알게 된 요령과 결과는 글로 정리해 공유합니다.
  6. 사용량이 늘면 리뷰나 검증처럼 새로 막히는 지점을 찾아 AI 리뷰 에이전트 같은 자동화로 풉니다.
  • 글로 남긴 공유 자료는 동료뿐 아니라 에이전트가 읽을 자료도 됩니다.
