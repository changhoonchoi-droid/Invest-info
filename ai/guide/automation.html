1. Claude 시작하고 스킬로 보고서 양식 고정하기

Claude 채팅의 기본 사용법을 익히고, 자주 쓰는 보고서 양식을 스킬로 저장해 매번 같은 형식의 결과를 받는 방법입니다. 반복 문서 업무의 첫걸음으로 적합합니다.

  1. 구글 계정으로 Claude에 가입합니다.
  2. 평소 쓰는 보고서 양식 파일을 채팅에 첨부합니다.
  3. 이 보고서 형식을 분석해서 회사 보고서 만드는 스킬 제작해 줘. 답변은 한국어로 해 줘라고 요청합니다.
  4. 결과 화면에서 스킬 저장을 눌러 내 스킬로 저장합니다.
  5. 사용할 때는 /와 스킬 이름을 입력해 스킬을 고르고 주제를 적어 요청합니다.
  6. 저장된 스킬은 + 메뉴의 스킬에서 확인합니다.
예시
이 보고서 형식을 분석해서 회사 보고서 만드는 스킬 제작해 줘. 답변은 한국어로 해 줘
  • 원본이 워드 파일이면 결과도 워드 파일로 만들어집니다.
  • 스킬 대신 메모리에 형식을 저장해도 같은 포맷을 유지할 수 있습니다.
  • AI 티가 나는 문장은 별도 교정 스킬로 다듬되, 중요한 문서는 직접 읽고 고치세요.
  • 모델은 일상 작업엔 Sonnet, 복잡한 작업엔 상위 모델을 쓰고, 무료 플랜은 Sonnet까지입니다.

2. Cowork로 폴더 업무 통째로 맡기기

Cowork는 폴더 접근을 허용하면 Claude가 계획을 세우고 파일을 읽어 엑셀·워드 같은 결과물을 만들어 주는 기능입니다. 파일 정리, 자료 취합, 보고서 작성처럼 여러 단계 업무를 맡길 때 씁니다.

  1. Claude 데스크톱 앱을 열고 Cowork(협업)를 선택합니다.
  2. 하단 프로젝트 또는 폴더에서 작업할 폴더를 고르고 항상 허용을 누릅니다.
  3. 매출 데이터, 회의록, 메모 등 필요한 자료를 그 폴더에 넣습니다.
  4. 폴더 안의 자료를 읽고 원하는 결과물(예: 한 페이지 워드 보고서)을 만들어 달라고 요청합니다.
  5. Claude가 제안하는 계획을 확인하고 진행 상황을 지켜봅니다.
  6. 완성된 파일을 지정 폴더에서 열어 내용을 검토합니다.
예시
폴더 안의 회의록·엑셀·메모를 모두 읽고 이번 주 팀 현황을 한 페이지 워드 보고서로 정리해 줘. 핵심 요약, 진행 상황, 다음 주 할 일, 리스크 순으로 써 줘.
  • 엑셀 정리처럼 원본이 있는 작업은 원본은 그대로 두고 정리본은 새 파일로 저장이라고 꼭 적으세요.
  • 처음에는 폴더 정리처럼 범위가 분명한 작업부터 시작하세요.
  • 웹 버전은 로컬 파일 접근과 컴퓨터 조작이 안 되므로 데스크톱 앱에서 해야 합니다.
  • 설정의 협업 탭에서 글로벌 지침을 적어 두면 매번 자기소개를 반복하지 않아도 됩니다.

3. 커넥터로 메일 브리핑 예약 작업 만들기

Gmail·캘린더 같은 서비스를 Claude에 연결하고, 아침마다 메일과 일정을 요약해 주는 예약 작업을 등록하는 방법입니다. 매일 반복되는 확인 업무를 자동화할 때 씁니다.

  1. Claude 데스크톱에서 + → 커넥터 → 커넥터 추가 → 커넥터 둘러보기를 엽니다.
  2. Gmail 또는 Microsoft 365를 선택해 클로드에 연결하고 계정을 고릅니다.
  3. + → 커넥터에서 연결 표시(파란 불)를 확인합니다.
  4. 어제 오후 6시 이후 메일과 캘린더 일정으로 브리핑을 만들어 달라고 요청합니다.
  5. 같은 내용을 아침 7시 50분마다 실행하는 예약 작업으로 등록해 달라고 요청합니다.
  6. 좌측 예약됨에서 스케줄을 확인합니다.
예시
어제 오후 6시 이후 받은 메일과 오늘 캘린더 일정을 보고 오늘 할 일 브리핑을 만들어 줘. 그리고 이걸 매일 아침 7시 50분에 실행하는 예약 작업으로 등록해 줘.
  • 예약 작업은 유료 플랜에서만 쓸 수 있습니다.
  • 예전 방식: 예약 작업은 컴퓨터가 켜져 있고 데스크톱 앱이 열려 있어야 실행됐지만, 7월 업데이트 이후 클라우드에서 돌아 기기가 꺼져 있어도 실행됩니다.
  • 실행마다 새 세션으로 돌고, 설정해 둔 커넥터도 그대로 쓸 수 있습니다.
  • 예약 페이지에서 지난 실행 기록 확인, 지시문·주기 수정, 즉시 실행이 가능합니다.

4. 플러그인과 스킬로 직무 업무 자동화하기

Cowork의 플러그인은 스킬·커넥터·슬래시 명령을 묶은 직무별 패키지입니다. 회의 전 브리핑, 주간 리포트, 미팅 후 후속 처리처럼 매번 같은 절차를 반복하는 업무에 맞습니다.

  1. Cowork 메인 화면에서 + → 플러그인을 선택하고 플러그인 추가에서 직무에 맞는 것을 설치합니다.
  2. 플러그인 관리에서 제공되는 명령어와 스킬을 확인합니다.
  3. 설정에서 Gmail·Slack·캘린더·데이터 소스 등 필요한 커넥터를 연결합니다.
  4. Claude가 파일을 읽고 저장할 폴더를 지정합니다.
  5. 테스트용 데이터로 스킬을 먼저 실행해 결과를 보고 다듬습니다.
  6. 실제 사용 때는 /를 입력해 스킬을 고르고 고객사 이름이나 주제를 넣습니다.
  7. 발송이 필요한 결과는 승인 단계에서 내용을 확인한 뒤 보냅니다.
예시
/brief 제품 A의 이번 주 변경 내용을 짧게 정리해 줘
  • 스킬은 일반 텍스트 파일이라 언제든 열어 동작을 확인하고 회사 방식에 맞게 고칠 수 있습니다.
  • 숫자는 데이터 출처까지 추적되는지 검증하는 교정 스킬을 따로 두면 안전합니다.
  • 실행 후 배운 점을 스킬에 반영하도록 요청하면 다음 주에 더 나아집니다.
  • 이름으로 보내는 메일·답장은 근거를 원문에서 직접 확인하세요.

5. Gemini 스파크·Gems로 반복 업무 맡기기

제미나이 스파크는 구글 클라우드에서 상시 일하는 개인 에이전트이고, Gems는 역할과 지침을 저장해 두는 나만의 비서입니다. 구글 워크스페이스를 쓰는 직장인이 메일·일정·문서 업무를 자동화할 때 유용합니다.

  1. 제미나이를 실행하고 좌측 상단 스파크 베타 탭을 누릅니다.
  2. 프로필에서 설정을 열어 연결된 앱에서 구글 워크스페이스가 켜져 있는지 확인합니다.
  3. 이번 주 캘린더와 Gmail에서 답장 안 한 메일을 확인해 우선순위 브리핑 문서를 만들어 달라고 요청합니다.
  4. 정기 실행이 필요하면 프롬프트에 매주 월요일 오전 8시처럼 실행 시점을 적습니다.
  5. 좌측 일정 탭에서 등록된 일정을 확인합니다.
  6. 반복되는 글쓰기는 왼쪽 Gems의 새 잼에서 이름과 요청 사항을 적어 저장합니다.
예시
지난 7일간 Gmail의 뉴스레터·업무 보고 메일을 구글 시트에 정리하고, 핵심 요약 5개를 이메일 초안으로 작성해 줘. 발송은 하지 말고 초안으로만 남겨 줘. 매주 월요일 오전 8시에 실행해 줘.
  • 메일은 발송하지 말고 초안으로 남기게 하면 안전합니다.
  • 스파크는 구글 AI 프로 이상 구독이 필요합니다.
  • Gem의 요청 사항이 막막하면 제미나이에게 만들어 달라고 하고, 내 기존 글을 첨부해 말투를 분석시키세요.
  • 스킬에 내 문체와 규칙(인사말 한 줄, 본론 먼저 등)을 저장해 두면 여러 태스크에 공통 적용됩니다.

6. ChatGPT Work·Codex로 업무 자동화하기

ChatGPT 데스크탑 앱의 Work와 Codex로 회의록 정리, 웹 데이터 수집, 아침 브리핑 같은 업무를 맡길 수 있습니다. Claude 한도가 부담되거나 OpenAI 도구를 이미 쓰는 경우에 대안이 됩니다.

  1. ChatGPT 데스크탑 앱을 설치하고 메인 화면에서 Work 모드를 선택합니다.
  2. 회의록 파일을 첨부하고 실행 항목만 뽑아 담당자·할 일·마감 세 열의 스프레드시트로 만들어 달라고 요청합니다.
  3. 복잡한 작업은 입력창의 + 버튼에서 계획 모드를 켜고 Work가 던지는 질문에 답합니다.
  4. 정기 작업은 Codex의 플러그인 탭에서 Slack과 구글 캘린더를 먼저 연결합니다.
  5. 자동화 탭 → 채팅으로 만들기에서 일정을 가져와 Slack으로 브리핑하고 매일 오전 9시에 실행하도록 답합니다.
  6. 자동화가 액티브 상태로 생성됐는지 확인합니다.
예시
첨부한 회의록에서 실행 항목만 뽑아 담당자·할 일·마감 세 열의 스프레드시트로 만들어 줘.
  • 추론 수준은 미디엄에서 시작해 결과가 부족하면 올리세요.
  • 플러그인 연결을 먼저 해 두지 않으면 자동화가 동작하지 않습니다.
  • Record & Replay는 화면 녹화로 스킬을 만들어 주지만 현재 macOS에서만 가능합니다.
  • 채팅에서 가볍게 다듬은 대화는 Work로 가져와 마무리할 수 있습니다.

7. Claude Tag로 팀 채널에 Claude 두기

Claude Tag는 Slack 같은 팀 채널에 Claude를 추가해 대화를 따라가며 정보 정리, 문서 초안, 도구 수정까지 맡기는 기능입니다. 여러 사람이 한 스레드에서 함께 지시하며 채널별 규칙을 기억시킬 수 있습니다.

  1. Claude를 쓸 Slack 채널 하나에 Claude를 추가합니다.
  2. 필요한 도구를 Claude Tag에 연결합니다.
  3. 작업이 필요한 스레드에서 Claude를 태그해 요청합니다.
  4. 단계별 진행 상황을 채널에서 확인하고 다른 일을 합니다.
  5. 완료 또는 결정 요청 알림이 오면 확인하고 답합니다.
  6. 반복할 지침은 Remember for this channel: ... 형태로 말해 저장시킵니다.
예시
@Claude 최근 3일 스레드, Google Drive 회의록, Asana 열린 작업을 확인해서 이번 주 미결 액션 아이템 목록을 만들어 줘.
  • 처음에는 한 채널에서만 시작해 보세요.
  • Team·Enterprise 요금제에서 쓸 수 있고, 모든 변경과 요청자가 기록됩니다.

  • 프로젝트 상태를 추적하려면 공개 채널을 쓰는 것이 좋습니다.

8. n8n으로 노코드 자동화 워크플로우 만들기

n8n은 노드(작업 블록)를 연결해 자동화 시나리오를 만드는 도구이며, AI 빌더에 한국어로 요청하면 노드까지 자동 구성해 줍니다. 슬랙 알림 전달, 시트 리포트 발송, FAQ 챗봇처럼 정형화된 반복 작업에 알맞습니다.

  1. n8n 클라우드에 가입하고 Create Workflow로 새 워크플로우를 만듭니다.
  2. 가운데 빌드 위드 AI(또는 n8n AI)를 눌러 빌드를 선택합니다.
  3. 자동화할 내용을 트리거 시점과 처리 방식까지 구체적으로 적습니다.
  4. 만들어진 각 노드를 클릭해 설정을 확인합니다.
  5. 수정 요청을 입력창에 이어서 적습니다.
  6. API 키와 OAuth 인증 정보를 직접 연결합니다.
  7. 테스트 데이터로 실행해 동작을 확인한 뒤 실제로 사용합니다.
예시
슬랙 채널에 '긴급'이 들어간 메시지가 오면 노션에 저장하고 담당자에게 이메일을 보내는 워크플로우를 만들어 줘.
  • 프롬프트 한 번에 1크레딧이 들므로 여러 요구 사항을 한 번에 요청하면 아낄 수 있습니다.
  • API 키와 OAuth 인증은 보안상 AI가 설정해 주지 않아 직접 해야 합니다.
  • AI 빌더는 베타이며 n8n 클라우드에서만 쓸 수 있습니다.
  • FAQ 챗봇은 채팅 트리거, AI Agent, Simple Memory, 구글 시트 Tool을 엮어 만듭니다. 판단이 필요한 챗봇형은 OpenAI Agent Builder도 대안입니다.

9. AI로 콘텐츠 제작 파이프라인 자동화하기

기획·대본·음성·모션·검수·업로드 단계를 스킬로 만들어 라이브 한 편에서 롱폼과 쇼츠를 뽑는 방식입니다. 반복되는 콘텐츠 제작 업무를 줄이고 싶은 마케터와 1인 크리에이터에게 맞습니다.

  1. 콘텐츠를 시리즈로 나누고 시리즈마다 스킬을 하나씩 만들어 같은 지시로 같은 품질이 나오게 합니다.
  2. 기획·리서치 단계에서 관심 주제와 포맷을 조사시킵니다.
  3. 대본 단계에서 내 말투를 반영해 큰 틀과 스토리보드를 짜게 합니다.
  4. 남의 영상을 쓸 때는 Claude가 뽑은 질문에 말로 답하는 인터뷰로 내 해석을 더합니다.
  5. 검수 단계에서 Claude가 쓴 것은 다른 AI가 독립적으로 검증하게 합니다.
  6. 크레딧 상한을 정하고, 되돌리기 어려운 지점만 내 확인을 받도록 정합니다.
  7. 피드백을 줄 때마다 스킬이나 규칙으로 남깁니다.
예시
이 영상을 보고 시청자가 궁금해할 질문을 뽑아서 나를 인터뷰해 줘. 내 답변을 바탕으로 롱폼 대본을 만들어 줘.
  • 단순 번역과 자막만으로는 차별점이 생기지 않습니다.
  • 크레딧 상한 숫자(쇼츠 500, 롱폼 1,500)는 영상 제작자 본인의 값이므로 내 요금제에 맞게 정하세요.
  • 카드뉴스는 매일 아침 레퍼런스를 모아 기준을 넘긴 것만 제작하는 방식이 있으나, 업로드까지 자동화하지 않은 사례가 많습니다.
  • 검수 없이 올리지 말고 아는 지식 범위에서만 게시하세요.

10. 루틴과 하네스로 에이전트 설계하기

루프 엔지니어링은 시키지 않아도 AI가 돌아가게 만드는 설계 방식입니다. 일정·이벤트 기반 루틴, 상태 파일, 종료 조건을 정해 반복 업무를 에이전트에게 안전하게 맡길 때 씁니다.

  1. 루틴이 필요한 반복 업무를 하나 고릅니다.
  2. 트리거(언제), 컨텍스트(무엇을 알아야 하나), 조종(어떻게 바로잡나) 세 가지를 먼저 정합니다.
  3. 터미널에서 Claude Code를 실행하고 /schedule을 입력해 작업을 적습니다.
  4. Claude가 묻는 실행 시각, 알림 방식 등에 답합니다.
  5. 필요한 저장소와 커넥터를 컨텍스트로 연결합니다.
  6. 진행 상황을 적는 상태 파일을 두어 기억 장치로 씁니다.
  7. 누가 봐도 참/거짓을 판정할 종료 조건(검증 통과, 최대 반복 횟수, 시간·비용 한도)을 겹쳐 겁니다.
  8. 처음에는 결과를 직접 확인하고, 신뢰가 쌓이면 권한을 늘립니다.
예시
/schedule 매주 main에 병합된 변경을 문서 저장소와 비교해 바뀐 부분이 있으면 문서 수정 PR을 만들어 줘
  • 만드는 AI와 검사하는 AI를 분리하면 자기 결과에 관대해지는 문제를 줄입니다.
  • 루틴은 반복 업무에, 단계를 미리 알 수 없는 작업은 동적 워크플로에 맞습니다.
  • 비용이 한꺼번에 커지는 폭주에 대비해 서킷 브레이커나 상한을 두세요.
  • 개발 지식이 없는 직장인은 먼저 Cowork 예약 작업으로 충분히 연습한 뒤 접근하세요.

11. Managed Agents로 운영용 에이전트 만들기

Claude Managed Agents는 샌드박스, 자격 증명, 메모리, 재시도 같은 인프라를 대신 맡는 API 모음입니다. 에이전트를 직접 서비스에 넣으려는 개발 담당자나 팀이 대상이며, 비개발자는 개념을 이해하는 용도로 보면 됩니다.

  1. 에이전트(도구·페르소나)를 정의합니다.
  2. 패키지와 네트워크 제어를 설정한 환경(샌드박스)을 구성합니다.
  3. 내 앱에서 세션을 시작해 일을 맡깁니다.
  4. 이벤트 스트림으로 진행을 관찰합니다.
  5. 도구별로 자동 실행과 사용자 승인 권한을 나눕니다.
  6. outcome에 평가 기준(루브릭)을 주어 기준을 만족할 때까지 반복하게 합니다.
  7. 메모리 저장소를 붙여 세션이 끝나도 배운 내용을 이어 갑니다.
  • Outcomes·멀티 에이전트·메모리는 연구 프리뷰·베타 단계라 제공 범위를 확인하세요.
  • 드리밍은 세션 사이에 기록을 검토해 메모리의 중복을 합치고 낡은 항목을 지웁니다.
  • 비용 절감 수단이 적고 콜드 스타트 지연이 있어, 어려운 작업이 아니면 직접 구축도 고려하세요.
  • 새 모델이 나올 때마다 하네스가 얇아지는 추세라 정기적으로 구조를 다시 점검하세요.
