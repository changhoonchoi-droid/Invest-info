1. 자동화할 업무 절차 고르기

무엇을 AI에 맡길지 정하기 전에, 팀에서 가장 부담이 큰 업무나 회의 하나를 골라 지금도 필요한지 점검하는 방법입니다. 필요 없는 절차는 없애고, 남길 절차 중 Claude가 도울 부분을 찾아 자동화 후보로 삼습니다.

  1. 팀에서 가장 번잡하거나 모두가 꺼리는 업무 흐름 또는 회의 하나를 고릅니다.
  2. 그 절차가 원래 어떤 목적으로 생겼는지 적어 봅니다.
  3. 지금도 그 목적에 도움이 되는지 스스로 묻습니다.
  4. 도움이 되지 않으면 없애고, 필요하지만 비용이 크면 Claude가 도울 수 있는 부분을 찾습니다.
  5. 한 번에 한 단계씩 바꾸고 결과를 확인합니다.
  • 영상 속 사례에서는 50명이 참석하지만 다들 노트북만 보던 주간 리뷰를 '왜 하는가'라는 질문 하나로 취소했습니다.
  • 절차는 스스로 사라지지 않고 계속 쌓이므로 의식적으로 정리해야 합니다.
  • 모델이 좋아지면 검증 수준도 달라질 수 있으니 주기적으로 다시 점검합니다.

2. Cowork로 회의 준비 문서 만들기

Claude Cowork에 캘린더·Slack·이메일과 회의록 폴더를 연결해 두고, 회의 준비를 통째로 맡기는 방법입니다. 참석자 조사, 지난 대화 확인, 안건 작성까지 한 번에 처리해 작업 폴더에 문서로 남겨 줍니다.

  1. 캘린더, Slack, 이메일을 Claude에 연결합니다.
  2. 회의록이 있는 폴더를 Claude가 볼 수 있게 지정합니다.
  3. 회의 상대와 시간을 알려 주며 준비를 요청합니다.
  4. 캘린더 검색, 참석자 조사, Slack 스레드 확인, 이전 회의록 검토, 안건 작성을 요청하고 기존 문서 형식을 템플릿으로 따르라고 지시합니다.
  5. Claude가 세운 계획을 확인하고 작업이 진행되게 둡니다.
  6. 빠뜨린 출처가 있으면 작업 중에 추가로 요청합니다(예: 이메일도 확인).
  7. 완성된 안건 문서를 작업 폴더에서 열어 검토하고, 빠진 내용은 추가를 요청하거나 직접 고칩니다.
예시
Prep me for today's call with Acme Corp at 1PM.
  • 작업 도중 지시를 추가해도 처음부터 다시 만들지 않고 방향을 바꿔 이어갑니다.
  • 최종 문서의 책임과 수정은 사용자에게 있으니 꼭 읽어 보고 씁니다.

3. Cowork 예약 작업 만들기

매시간·매일·평일처럼 정해진 주기로 같은 일을 Cowork가 자동으로 하게 만드는 기능입니다. 아침마다 메일 정리, 매시간 공유 폴더 변경 요약, 일요일 저녁 주간 리포트 준비 같은 반복 업무에 씁니다.

  1. 반복할 일을 자연어로 설명합니다.
  2. Claude가 만든 예약 작업 프롬프트 초안을 검토합니다.
  3. 필요하면 주기를 매시간·매일·평일·수동 중에서 바꿉니다.
  4. 내용이 맞으면 제안을 수락합니다.
  5. 왼쪽 사이드바의 예약(scheduled) 페이지에 작업이 추가된 것을 확인합니다.
  6. 등록 후 한 번 바로 실행해 결과가 제대로 나오는지 확인합니다.
예시
매시간 공유 드라이브 폴더에서 새로 추가되거나 수정된 문서를 확인해서, 누가 바꿨는지 기록하고 내용을 요약한 뒤 클라이언트별로 묶어 문서로 저장해 줘.
  • 예약 작업은 컴퓨터가 켜져 있고 Claude 데스크톱 앱이 열려 있을 때만 실행됩니다. 꺼져 있어 놓친 작업은 복귀 후 바로 실행되고 지연됐다고 알려 줍니다.
  • 실행마다 새 세션으로 돌아 최신 파일과 도구 상태를 기준으로 하며, 설정해 둔 커넥터도 그대로 쓸 수 있습니다.
  • 예약 페이지에서 지난 실행 기록 확인, 지시문·주기 수정, 즉시 실행을 할 수 있습니다.
  • 대화 중 마음에 든 작업은 '매주 평일 오후 4시마다 이 작업을 해 달라'처럼 말로 예약을 맡길 수도 있습니다.

4. Slack 채널에서 Claude Tag 쓰기

Claude Tag는 Slack 같은 팀 채널에 Claude를 넣어 대화 맥락을 따라가며 일하게 하는 기능입니다. 채팅 창을 오가거나 맥락을 복사할 필요 없이 채널에서 바로 정리·초안 작성·도구 내 수정을 맡기고, 여러 사람이 함께 지시할 수 있습니다.

  1. Claude를 쓸 Slack 채널 하나에 Claude를 추가합니다.
  2. Google Drive·Asana 등 필요한 도구를 Claude Tag에 연결합니다.
  3. 작업이 필요한 스레드에서 Claude를 태그해 일을 요청합니다.
  4. Claude가 단계별로 진행하는 상황을 채널에서 확인하고, 그동안 다른 일을 합니다.
  5. 완료 알림이나 결정 요청이 오면 확인하고 답합니다.
  6. 반복할 지침은 Remember for this channel: ... 형태로 말해 채널에 저장합니다.
  7. 너무 자주 또는 드물게 끼어들면 개입 빈도를 조정해 달라고 말하고, 매번 태그가 번거로우면 항상 응답하도록 지시합니다.
예시
@Claude 최근 3일 스레드, Google Drive 회의록, Asana 열린 작업을 확인해서 이번 주 미결 액션 아이템 목록을 만들어 줘.
  • Team·Enterprise 요금제에서 쓸 수 있으며, 처음에는 한 채널에서만 시작해 보세요.
  • 스타일 가이드나 체크리스트 문서를 알려 주면 참고하고, 문서가 바뀌면 최신 내용을 따릅니다.
  • Claude는 자체 계정으로 일하며 모든 변경과 요청자를 기록하고, 사용자를 대신해 응답하거나 도구에 접근할 때는 권한을 묻습니다.
  • DM과 비공개 채널 내용은 그 안에만 남으니, 프로젝트 상태를 추적하려면 공개 채널을 쓰는 것이 좋습니다.

5. 발표 예상 질문과 답변 준비하기

Adobe Acrobat의 AI 기반 PDF 스페이스에 보고서·기사 링크를 모아 두고, 발표나 회의에서 나올 질문과 답변을 미리 정리하는 방법입니다. 답변마다 원문 출처가 붙어 근거를 바로 확인할 수 있습니다.

  1. Acrobat의 PDF 스페이스에 파일, 이미지, 웹 링크, 텍스트 등 자료를 넣습니다.
  2. AI 어시스턴트에 팀 회의에서 나올 만한 질문 세 개와 답변을 정리해 달라고 요청합니다.
  3. 각 답변에 붙은 출처 번호를 눌러 원문의 해당 부분을 확인합니다.
예시
이 자료를 바탕으로 팀회의에서 나올 만한 질문 세 개와 답변을 정리해 줘. 근거가 없는 내용은 '확인 필요'라고 표시해 줘.
  • PDF 스페이스에는 확장자와 관계없이 최대 100개 파일까지 넣을 수 있습니다.
  • 같은 자료로 프레젠테이션 초안도 만들 수 있고, Adobe Express에서 고친 뒤 PPTX·PDF 등으로 내려받습니다.

6. 스킬로 미팅 브리핑·후속 처리하기

Cowork에서 자주 하는 조사·정리 절차를 스킬 파일로 만들어 두고 /로 불러 쓰는 방법입니다. 미팅 전에는 CRM·이메일·Slack 등에 흩어진 정보를 브리핑 한 장으로, 미팅 후에는 녹취록에서 할 일과 후속 메시지를 만들게 합니다.

  1. Cowork 세션을 열고 미팅 전에 알고 싶은 내용을 설명해 스킬 파일 초안을 만듭니다.
  2. 설정에서 데이터 웨어하우스, Salesforce, 웹, 이메일, Slack 등 필요한 곳을 연결합니다.
  3. Claude가 파일을 읽고 수정하고 저장할 수 있는 폴더를 지정합니다.
  4. 테스트용 계정으로 스킬을 실행해 결과를 보고 다듬습니다.
  5. 미팅 전 /를 입력하고 계정 전략 스킬을 고른 뒤 고객사 이름을 입력합니다.
  6. Claude가 만든 브리핑을 계정 폴더에서 확인합니다.
  7. 미팅 후 같은 세션으로 돌아와 /를 입력하고 통화 녹취록 처리 스킬을 고릅니다.
  8. Claude가 만든 개인 할 일, 내부 Slack 메시지, 고객 후속 메시지를 하나씩 확인하고 승인한 뒤 발송합니다.
  • 스킬은 일반 텍스트 파일이라 언제든 열어서 동작을 확인하고 회사 방식에 맞게 고칠 수 있습니다.
  • 같은 방식으로 /brief처럼 과거 문서와 새 대화를 비교해 '무엇이 바뀌었는지' 알려 주는 스킬도 만들 수 있습니다.
  • 이름을 걸고 보내는 메시지이므로 브리핑이 가리키는 원문을 직접 열어 근거를 확인한 뒤 승인합니다.

7. 주간 지표 리포트 자동화하기

예약 작업과 여러 스킬을 묶어 매주 지표 리뷰를 자동으로 준비시키는 방법입니다. 숫자 수집과 검증은 Claude가, 이야기의 초점과 판단은 사람이 맡습니다.

  1. 리뷰 준비, 교정(숫자 출처 검증), 액션 아이템 관리용 스킬을 각각 만듭니다.
  2. 일요일 저녁에 실행되는 예약 작업을 설정해 지난 리뷰·회의록·Slack·데이터를 확인하게 합니다.
  3. 월요일 아침 Cowork를 열어 준비 결과와 제안된 집중 영역을 확인합니다.
  4. 분기 리뷰 문서를 넣고 이번 주 초점을 지시합니다.
  5. Claude가 데이터 불일치를 알리면 처리 방식을 알려 줍니다.
  6. 먼저 지표 표와 헤드라인만 있는 초안을 확인합니다.
  7. ship it이라고 말해 최종 문서와 Slack 메시지를 만듭니다.
  8. 같은 데이터로 리더십용 슬라이드 한 장을 만들도록 요청합니다.
  9. 이번 주 배운 점을 스킬에 반영하도록 요청합니다.
예시
ship it
  • 데이터가 맞지 않으면 Claude가 추측하지 않고 질문하도록 되어 있으니, 그때 기준을 정해 주세요.
  • 후속 조치는 Asana 작업으로 남겨 누락을 막습니다.
  • 스킬을 팀과 공유하면 누구나 같은 방식으로 같은 결과를 낼 수 있습니다.

8. /schedule로 Claude Code 루틴 만들기

루틴은 프롬프트·저장소·커넥터·트리거를 정해 두면 Anthropic 클라우드에서 Claude Code 세션을 자동으로 실행하는 기능입니다. 노트북을 닫아도 돌아가며, 일정 기반이나 GitHub 이벤트·웹훅 같은 이벤트 기반으로 시작할 수 있습니다.

  1. 터미널에서 Claude Code를 실행합니다.
  2. /schedule을 입력하고 원하는 작업을 적습니다.
  3. Claude가 묻는 질문에 답합니다(예: 매주 몇 시에 실행할지, 끝나면 Slack으로 알릴지).
  4. 작업에 필요한 저장소를 컨텍스트로 연결합니다.
  5. 만들어진 루틴을 웹의 Claude Code에서 확인합니다.
  6. 실행된 세션을 열어 결과를 보고, 필요하면 그 세션에서 이어서 지시합니다.
예시
/schedule 매주 main에 병합된 변경을 문서 저장소와 비교해서, 바뀐 부분이 있으면 문서 수정 PR을 만들어 줘.
  • 트리거(언제), 컨텍스트(무엇을 알아야 하나), 조종(어떻게 바로잡나) 세 가지를 먼저 정하세요.
  • Cowork 예약 작업과 달리 클라우드에서 돌아 PC가 꺼져 있어도 실행됩니다.
  • 처음에는 결과를 직접 확인하고, 신뢰가 쌓이면 더 많은 권한을 맡기세요.
  • Claude Code Projects(베타)에서는 매일 도는 루틴을 여러 작업 스레드와 함께 한 프로젝트 안에서 관리할 수 있습니다.

9. AI 인터뷰로 내 해석 더하기

남의 영상이나 글을 그냥 번역·요약하지 않고, Claude가 질문하고 내가 답하는 인터뷰로 내 의견을 더해 새 콘텐츠를 만드는 방법입니다. 누구나 만들 수 있는 요약물과 차별화하고 싶을 때 씁니다.

  1. 원본 영상이나 글을 직접 보고 듣습니다.
  2. Claude에 이 자료로 롱폼 콘텐츠를 만들어 보자고 제안합니다.
  3. 자료를 본 사람이 궁금해할 질문을 뽑아 나를 인터뷰하게 시킵니다.
  4. 질문마다 말로 소감과 의견을 풀어 답합니다.
  5. 그 인터뷰 내용을 바탕으로 대본이나 글을 만들게 합니다.
  6. 음성·자막·설명용 그래픽 등을 입혀 완성합니다.
예시
이 영상을 본 사람이 궁금해할 질문을 뽑아서 나를 인터뷰해 줘. 한 번에 한 질문씩 물어보고, 내 답을 모아 롱폼 대본으로 만들어 줘.
  • 번역기 수준의 자막 콘텐츠는 차별점이 없으니 내 해석이 들어가는 부분을 꼭 남깁니다.
  • 공개 후 반응 데이터(이탈 구간, 좋아요 많은 댓글)를 보고 다음 기획을 고칩니다.

10. 콘텐츠 자동화 파이프라인 만들기

기획부터 업로드까지 콘텐츠 제작 단계를 정해 두고 단계마다 AI에 맡기는 공통 파이프라인을 만드는 방법입니다. 반복되는 편집 규칙을 스킬로 만들어 두면 원본 하나만 넘겨도 여러 편이 만들어집니다.

  1. 기획·리서치 단계에서 사람들이 관심 갖는 주제와 포맷을 조사시킵니다.
  2. 대본 단계에서 내 말투를 반영해 큰 틀과 스토리보드를 짜게 합니다.
  3. 음성은 내 목소리를 씁니다.
  4. 모션 단계에서 HTML 코드로 영상을 만드는 Hyperframes 같은 도구를 씁니다.
  5. 검수 단계에서 Claude가 만든 것은 Codex가, Codex가 만든 것은 Claude가 따로 검증하게 합니다.
  6. 패키징 단계에서 썸네일과 제목을 만들고 업로드까지 맡깁니다.
  7. 컷 편집·모션 그래픽 규칙은 스킬로 저장해 다음부터 자동으로 적용되게 합니다.
  • 라이브 한 편을 통째로 넘기고 편수까지 맡겨 롱폼 5편·쇼츠 22편을 얻은 사례가 있습니다.
  • 남의 파이프라인 화면을 캡처해 Claude에 붙여 넣고 내 상황에 맞게 바꿔 달라고 하면 출발이 쉽습니다.
  • 서로 다른 AI가 교차 검증하면 한 모델이 놓친 실수를 잡기 쉽습니다.

11. 사람 확인 지점 설계하기

여러 자동화 작업을 동시에 돌릴 때 내가 병목이 되지 않도록, 에이전트에 맡길 권한과 사람이 꼭 확인할 지점을 미리 정하는 방법입니다(Human on the loop). 비용이 크게 나가거나 되돌리기 어려운 일만 확인하고 나머지는 맡깁니다.

  1. 피드백을 줄 때마다 그 내용을 스킬이나 규칙으로 남겨 같은 지적을 반복하지 않게 합니다.
  2. 에이전트에 가능한 한 많은 권한을 줍니다.
  3. 크레딧처럼 한 번에 크게 나가는 비용은 작업 종류별 상한을 정합니다.
  4. 되돌리기 어려운 지점(예: 캐릭터 생성, 외부 발송)은 실행 전에 내 확인을 받도록 정합니다.
  5. 결과를 보며 확인 지점이 너무 많거나 적으면 조정합니다.
  • 영상 속 상한 예시(쇼츠 500, 롱폼 1,500 크레딧)는 그 사람의 값이니 내 요금제에 맞게 정합니다.
  • 폭주하는 프로세스에 대비해 자동으로 멈추는 장치(서킷 브레이커)를 두라는 조언도 있습니다.
  • 처음에는 결과를 직접 확인하다가 믿을 만해지면 확인 지점을 줄여 갑니다.
