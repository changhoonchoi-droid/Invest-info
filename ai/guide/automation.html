1. Cowork로 첫 작업 맡기기

Cowork는 한 단계씩 대화하는 대신 작업 전체를 맡기는 방식으로, 내 컴퓨터의 파일과 Google Drive·Notion·Slack 같은 서비스까지 다룹니다. Claude가 계획을 먼저 제안하고 승인을 받은 뒤 실행하므로, 폴더 정리처럼 범위가 분명한 일부터 시작하기 좋습니다.

  1. Claude 데스크톱 앱(macOS·Windows)을 열고 Cowork 탭을 누릅니다.
  2. Claude가 작업할 폴더를 선택해 접근을 허용합니다.
  3. 필요하면 커넥터를 연결해 Google Drive·Notion·Slack 등에서 맥락을 가져오게 합니다.
  4. 할 일을 설명하고 파일을 바꾸기 전에 계획부터 보여 달라고 요청합니다.
  5. 제안된 계획을 확인하고, 삭제 후보 중 남길 파일은 검토 폴더로 옮기라는 식으로 수정을 지시합니다.
  6. 승인하면 Claude가 실제로 작업합니다. 오른쪽 위에서 진행 상황을 확인합니다.
예시
Organize my downloads folder. Scan the contents and propose a plan.
  • Pro, Max, Team, Enterprise 요금제에서 쓸 수 있고, Claude는 파일을 바꾸기 전에 권한을 묻습니다.
  • 작업 중에는 데스크톱 앱을 열어 두어야 하며 세션은 기기에 로컬로 저장됩니다.
  • Settings의 Cowork 탭에서 내 역할 설명이나 기본 파일 형식(예: Word 문서) 같은 전역 지침을 정해 둘 수 있습니다.
  • 브라우저 작업까지 맡기려면 Claude in Chrome을 따로 설정해야 합니다.

2. Cowork로 회의 준비 문서 만들기

캘린더·Slack·이메일과 이전 회의록을 Claude가 한꺼번에 살펴 회의 안건 문서를 만들어 줍니다. 고객 미팅이나 정기 회의 전에 흩어진 자료를 모으는 시간을 줄일 때 씁니다.

  1. 캘린더, Slack, 이메일을 Claude에 연결합니다.
  2. 회의록이 있는 폴더를 Claude가 볼 수 있게 지정합니다.
  3. 어떤 회의가 몇 시에 있는지 알려 줍니다.
  4. 캘린더 검색, 참석자 조사, Slack 스레드 확인, 이전 회의록 검토, 안건 작성을 요청하고 기존 문서 형식을 템플릿으로 따르라고 지시합니다.
  5. Claude가 세운 계획을 확인하고 작업이 진행되게 둡니다.
  6. 빠뜨린 출처가 있으면 작업 중에 추가로 요청합니다(예: 이메일도 확인).
  7. 완성된 안건 문서를 작업 폴더에서 열어 검토하고, 빠진 내용은 추가를 요청하거나 직접 고칩니다.
예시
Prep me for today's call with Acme Corp at 1PM.
  • 작업 도중 지시를 더해도 처음부터 다시 만들지 않고 방향을 바꿔 이어 갑니다.
  • 최종 문서의 책임과 수정은 사용자에게 있으니 꼭 직접 읽어 봅니다.

3. Cowork 예약 작업 만들기

매시간·매일·평일처럼 정해진 주기로 Cowork 작업을 자동 실행합니다. 아침 메일 정리, 주간 지표 준비, 공유 폴더 변경 요약처럼 매번 같은 방식으로 반복하는 일에 씁니다.

  1. 반복할 일을 자연어로 설명합니다. 한 번 해 보고 결과가 마음에 들면 '이 작업을 매주 평일 오후 4시마다 해 달라'처럼 요청해도 됩니다.
  2. Claude가 만든 예약 작업 프롬프트 초안을 검토합니다.
  3. 필요하면 주기를 매시간·매일·평일·수동 중에서 바꿉니다.
  4. 내용이 맞으면 제안을 수락합니다.
  5. 왼쪽 사이드바의 예약(scheduled) 페이지에 작업이 추가됐는지 확인합니다.
  6. 설정 후 한 번 바로 실행해 제대로 되는지 확인합니다.
예시
매시간 공유 드라이브 폴더에서 추가·수정된 문서를 확인해 누가 바꿨는지 기록하고, 내용을 요약해 클라이언트별로 묶어 문서로 저장해 줘.
  • 컴퓨터가 켜져 있고 Claude 데스크톱 앱이 열려 있어야 실행됩니다. 꺼져서 놓친 작업은 복귀 후 바로 실행되고 지연됐다고 알려 줍니다.
  • 실행마다 새 Cowork 세션으로 돌아 최신 파일·도구 상태를 기준으로 하며, 설정해 둔 커넥터도 그대로 씁니다.
  • 예약 페이지에서 지난 실행 기록 확인, 지시문·주기 수정, 즉시 실행을 할 수 있습니다.
  • 활용 예: 아침마다 Gmail을 확인해 오늘 할 일 정리, 일요일 저녁 주간 지표 리뷰 준비.

4. 스킬로 반복 업무 저장하기

스킬은 업무 방식을 적어 둔 텍스트 파일로, 저장해 두면 /로 불러 매번 같은 방식·같은 품질로 일을 시킬 수 있습니다. 계정 브리핑, 주간 리포트, 교정처럼 형식이 정해진 일을 팀과 함께 쓰고 싶을 때 씁니다.

  1. Cowork 세션을 열고 결과물에 무엇이 들어가야 하는지 설명해 스킬 파일 초안을 만들게 합니다.
  2. 설정에서 스킬이 쓸 데이터 출처(예: Salesforce, 데이터 웨어하우스, 이메일, Slack, 웹)를 연결합니다.
  3. Claude가 파일을 읽고 수정·저장할 폴더를 지정합니다.
  4. 테스트용 자료로 스킬을 실행해 결과를 보고 다듬습니다.
  5. 실제로 쓸 때는 Cowork에서 /를 입력하고 스킬을 고른 뒤 대상(예: 고객사 이름)을 입력합니다.
  6. 결과를 확인한 뒤 이번에 배운 점을 스킬에 반영해 달라고 요청합니다.
  • 스킬은 일반 텍스트 파일이라 언제든 열어서 동작을 확인하고 회사 방식에 맞게 고칠 수 있습니다.
  • 준비·교정·후속 관리처럼 역할별로 스킬을 나누면 관리가 쉽습니다. 교정 스킬에 '모든 숫자가 검증된 출처로 이어지는지 확인'을 넣는 식입니다.
  • 만든 스킬을 팀과 공유하면 누구나 같은 결과를 낼 수 있습니다.
  • 피드백을 줄 때마다 스킬에 남기면 점점 손댈 일이 줄어듭니다.

5. 미팅 후 후속 처리 맡기기

통화 녹취록을 Claude가 읽고 개인 할 일, 내부 Slack 메시지, 고객 후속 메시지를 한 번에 만들어 줍니다. 미팅 뒤 30분씩 걸리던 정리 작업을 몇 분으로 줄일 때 씁니다.

  1. 미팅이 끝나면 미팅 준비에 썼던 같은 Cowork 세션으로 돌아옵니다.
  2. /를 입력하고 통화 녹취록 처리 스킬을 고릅니다.
  3. Claude가 녹취록을 가져와 개인 할 일, 내부 Slack 메시지, 고객 후속 메시지를 만들게 합니다.
  4. 각 결과를 읽고 고칠 곳을 지시합니다.
  5. 내용이 맞으면 하나씩 승인해 발송합니다.
  • 발송 전에 승인 단계를 거치므로 내 이름으로 나가는 내용은 꼭 읽고 보냅니다.
  • 같은 세션을 쓰면 미팅 전 브리핑 맥락이 그대로 이어집니다.

6. Cowork 브리핑 근거 확인하기

Claude가 만든 브리핑이나 답장 초안이 원문과 맞는지 직접 대조하는 습관입니다. 이름을 걸고 보내는 답장이나 숫자가 들어간 보고서처럼 틀리면 곤란한 결과물에 꼭 거칩니다.

  1. 처리할 항목을 고르고 /brief처럼 정리용 스킬을 실행해 무엇이 바뀌었는지 브리핑을 받습니다.
  2. 브리핑이 가리키는 원문 단락을 열어 인용이 맞는지 직접 확인합니다.
  3. 데이터가 맞지 않는다고 Claude가 알려 오면 어떻게 처리할지 지시합니다.
  4. 확인이 끝나면 답장 초안을 요청하고 내용을 승인합니다.
  5. 남은 후속 조치(예: Jira 티켓 종료, Asana 작업 등록)는 Claude에게 맡깁니다.
  • Claude는 데이터가 맞지 않으면 추측하지 않고 질문하도록 할 수 있습니다. 근거가 없는 내용은 '확인 필요'로 표시해 달라고 요청하세요.
  • /brief는 Anthropic 법무팀 방식으로 만든 플러그인이며, 플러그인은 회사 플레이북에 맞게 고칠 수 있습니다.
  • 서사와 초점은 사람이 정하고, 숫자 수집·검증은 Claude에게 맡기는 식으로 역할을 나눕니다.

7. Slack 채널에서 Claude Tag 쓰기

Claude Tag는 Slack 채널에 Claude를 추가해 팀 대화를 따라가며 일하게 하는 기능입니다. 채팅 창을 오가거나 맥락을 복사할 필요 없이 채널에서 바로 정리·문서 초안·도구 내 수정을 맡기고, 여러 사람이 함께 지시할 수 있습니다.

  1. Claude를 쓸 Slack 채널 하나에 Claude를 추가합니다.
  2. 필요한 도구(예: Google Drive, Asana)를 Claude Tag에 연결합니다.
  3. 채널이나 스레드에서 Claude를 태그해 작업을 요청합니다.
  4. 기다리지 않고 다른 일을 하다가, 완료 또는 결정 요청 알림이 오면 확인하고 답합니다.
  5. 반복할 지침은 Remember for this channel: ... 형태로 말해 저장시킵니다.
  6. 매번 태그하기 번거로우면 항상 응답하라고 지시하고, 개입이 너무 잦거나 드물면 빈도를 조정해 달라고 말합니다.
예시
@Claude 최근 3일 스레드, Google Drive 회의록, Asana 열린 작업을 확인해서 이번 주 미결 액션 아이템 목록을 만들어 줘.
  • Team·Enterprise 요금제에서 베타로 제공됩니다. 처음에는 한 채널에서만 시작해 보세요.
  • Claude는 자기 계정으로 일하며 모든 변경과 요청자를 기록합니다. 사용자를 대신해 응답하거나 개별 도구에 접근할 때는 매번 권한을 묻습니다.
  • 채널별로 접근 범위가 나뉘고, DM·비공개 채널에서 배운 내용은 그 안에만 남습니다. 프로젝트 상태 추적은 공개 채널이 좋습니다.
  • 스타일 가이드나 체크리스트 문서를 알려 주면 참고하며, 문서가 바뀌면 기본적으로 최신 내용을 따릅니다.

8. /schedule로 클라우드 루틴 만들기

루틴은 프롬프트·저장소·커넥터·트리거만 정하면 Anthropic 클라우드에서 Claude Code 세션을 자동으로 돌리는 기능입니다. 노트북을 닫아도 돌아가므로, PC가 꺼져 있어도 매주 반복해야 하는 일에 맞습니다.

  1. 터미널에서 Claude Code를 실행합니다.
  2. /schedule을 입력하고 원하는 작업을 적습니다.
  3. Claude가 묻는 질문에 답합니다(예: 매주 몇 시에 실행할지, 끝나면 Slack 등으로 알릴지).
  4. 작업에 필요한 저장소와 커넥터를 컨텍스트로 연결합니다.
  5. 만들어진 루틴을 웹의 Claude Code에서 확인하고 실행 결과 세션을 열어 봅니다.
예시
/schedule 매주 main에 병합된 변경을 문서 저장소와 비교해서, 바뀐 부분이 있으면 문서 수정 PR을 만들어 줘
  • 트리거(언제), 컨텍스트(무엇을 알아야 하나), 조종(어떻게 바로잡나) 세 가지를 먼저 정하세요.
  • 트리거는 시간 기반(일정)과 이벤트 기반(GitHub 이벤트, 웹훅·API 호출) 두 가지입니다.
  • Cowork 예약 작업은 내 컴퓨터와 앱이 켜져 있어야 돌지만, 루틴은 클라우드에서 돕니다.
  • 처음에는 결과를 직접 확인하고, 신뢰가 쌓이면 더 많은 권한을 맡기세요.

9. 소모적인 업무 절차 점검하기

자동화할 대상을 고르기 전에, 팀에서 가장 부담스러운 회의나 업무 흐름이 아직 필요한지부터 따져 보는 방법입니다. 절차는 저절로 사라지지 않고 쌓이기만 하므로, 없앨 것과 Claude에게 맡길 것을 가려냅니다.

  1. 팀에서 가장 비용이 크거나 모두가 꺼리는 업무 흐름이나 회의 하나를 고릅니다.
  2. 그 절차가 원래 어떤 목적으로 생겼는지 묻습니다.
  3. 지금도 그 목적에 도움이 되는지 확인합니다.
  4. 도움이 되지 않으면 없애고, 필요하지만 비용이 크면 Claude가 도울 부분을 찾습니다.
  5. 한 번에 한 단계씩 바꿔 나갑니다.
  • 영상 사례에서는 50명이 참석하지만 다들 노트북만 보던 주간 리뷰를 '왜 하는가'라는 질문 하나로 취소했습니다.
  • 회의로 논쟁하기보다 Claude로 여러 버전의 결과물을 만들어 비교하면 결론이 빨라집니다.
  • 모델이 좋아지면 필요한 검증 수준도 달라지니 주기적으로 다시 점검합니다.

10. AI 인터뷰로 내 관점 더하기

남의 영상·글을 그대로 옮기지 않고, Claude가 던지는 질문에 내가 답한 내용을 바탕으로 새 콘텐츠를 만드는 방법입니다. 단순 번역·요약과 차별화된 결과물이 필요할 때 씁니다.

  1. 참고할 영상이나 글을 직접 보고 듣습니다.
  2. Claude에게 이 자료로 콘텐츠를 만들자고 제안합니다.
  3. 자료를 본 사람이 궁금해할 질문을 뽑아 나를 인터뷰하라고 시킵니다.
  4. 질문마다 소감과 의견을 말로 풀어 답합니다.
  5. 인터뷰 내용을 바탕으로 결과물을 만들게 하고 음성·자막·그래픽 등을 입힙니다.
  6. 공개 후 반응 데이터를 보고 다음 작업을 고칩니다.
  • 번역기 수준의 자막·요약은 누구나 만들 수 있어 차별점이 없습니다.
  • 영상 사례에서는 본인이 말하는 구간에서 시청자가 이탈한 것을 확인하고 다음 영상에 반영했습니다.
  • 좋아요 1위 댓글에 답하는 후속편처럼 반응에서 다음 기획을 얻을 수도 있습니다.

11. 업무 자동화 파이프라인 설계하기

기획부터 결과물 배포까지 이어지는 일을 단계로 나누고, 단계별 규칙을 스킬로 만들어 입력만 넣으면 돌아가게 하는 방법입니다. 같은 종류의 결과물을 많이, 일정한 품질로 내야 할 때 씁니다.

  1. 일을 단계로 나눕니다. 영상 예시는 기획·리서치 → 대본 → 음성 → 모션 → 검수 → 패키징 → 업로드입니다.
  2. 기획·리서치 단계에서 사람들이 관심 갖는 주제와 형식을 조사시킵니다.
  3. 작성 단계에서 내 말투를 반영해 큰 틀과 스토리보드를 짜게 합니다.
  4. 결과물을 하나씩 만들지 않고 시리즈로 묶고, 시리즈마다 스킬을 둡니다.
  5. 검수 단계에서는 Claude가 만든 것은 Codex가, Codex가 만든 것은 Claude가 독립적으로 검증하게 합니다.
  6. 마무리 단계(제목·썸네일·배포)까지 맡기고, 서너 번 손대지 않아도 잘 나오면 자동 실행으로 넘깁니다.
  • 남의 파이프라인 화면을 캡처해 Claude에 붙여 넣고 내 상황에 맞게 바꿔 달라고 하면 출발이 빠릅니다.
  • 컷 편집·디자인 같은 반복 규칙을 스킬로 만들어 두면 원본만 넣어도 돌아갑니다.
  • 어떤 결과가 좋은지 기준(루브릭)을 미리 적어 두면 검수와 개선이 쉬워집니다.

12. 사람 확인 지점 설계하기

여러 자동화를 동시에 돌릴 때 내가 병목이 되지 않도록, 사람이 꼭 봐야 할 지점만 남기고 나머지는 규칙으로 맡기는 'Human on the loop' 설계입니다. 비용 폭주나 되돌리기 어려운 실수를 막는 안전장치도 함께 정합니다.

  1. 피드백을 줄 때마다 그 내용을 스킬이나 규칙으로 남깁니다.
  2. 에이전트에 가능한 한 많은 권한을 줍니다.
  3. 크레딧처럼 한 번에 크게 나가는 것은 상한을 정합니다.
  4. 되돌리기 어려운 지점은 실행 전에 내 확인을 받도록 정합니다.
  5. 발송·게시처럼 바깥으로 나가는 작업은 승인 단계를 둡니다.
  • 영상의 상한(쇼츠 500, 롱폼 1,500 크레딧)은 알렉스의 값이므로 내 요금제에 맞게 정해야 합니다.
  • 폭주하는 프로세스에 대비해 자동으로 멈추는 장치(서킷 브레이커)를 두라는 조언도 있습니다.
  • 처음에는 확인 지점을 많이 두고, 결과를 믿을 수 있게 되면 하나씩 줄입니다.

13. 새 도구에서 아이디어만 가져오기

요즘 뜨는 GitHub 리포나 도구를 그대로 쓰지 않고, 에이전트에게 내 작업에 쓸 만한 부분을 분석시켜 아이디어만 가져오는 방법입니다. 새 도구가 쏟아질 때 쓸 것과 버릴 것을 가려낼 때 씁니다.

  1. 마음에 드는 리포에 스타를 눌러 모아 둡니다.
  2. 에이전트가 내 작업과 맥락을 알 수 있게 메모리나 프로젝트 지침을 갖춰 둡니다.
  3. 에이전트에게 이 리포를 어떻게 활용할 수 있을지 추천해 달라고 요청합니다.
  4. 내 프로젝트에 가져다 쓸 스킬이나 전략을 분석해 달라고 합니다.
  5. 그대로 가져다 쓰지 않고 아이디어만 뽑아 내 스킬·규칙을 업데이트합니다.
예시
이 리포를 우리가 어떻게 활용할 수 있을지 추천해 줘. 우리 프로젝트에 가져다 쓸 만한 스킬이나 전략도 분석해 줘.
  • 내 것과 맞지 않아 그대로 가져다 쓰는 경우는 거의 없다고 합니다.
  • 나만의 프로젝트와 방향이 있어야 쓸 것과 버릴 것을 가릴 수 있습니다.
