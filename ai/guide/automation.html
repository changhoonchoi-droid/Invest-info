1. Cowork로 폴더 정리 맡기기

Cowork는 단계별 대화 대신 작업 전체를 맡기는 방식으로, 허용한 폴더의 파일을 읽고 정리하고 결과물을 만들어 줍니다. 처음 써 볼 때는 다운로드 폴더 정리처럼 범위가 분명한 작업이 좋습니다.

  1. Claude 데스크톱 앱을 열고 Cowork 탭을 누릅니다.
  2. Claude가 작업할 폴더를 선택하고 접근을 허용합니다.
  3. 필요하면 커넥터를 연결해 Google Drive·Notion·Slack 등에서 맥락을 가져오게 합니다.
  4. 정리할 대상을 설명하고, 변경 전에 계획을 먼저 보여 달라고 요청합니다.
  5. 제안된 계획을 확인하고 남길 파일 등 수정할 점을 말합니다.
  6. 계획을 승인하면 Claude가 실제로 파일을 옮깁니다.
  7. 오른쪽 위에서 진행 상황을 확인하고 결과 폴더를 열어 봅니다.
예시
Organize my downloads folder. Scan the contents and propose a plan.
  • 처음에는 범위가 분명한 작업부터 시작하고 결과를 항상 검토합니다.
  • 작업 중에는 데스크톱 앱을 열어 두어야 하며 세션은 기기에 로컬로 저장됩니다.
  • 웹 버전은 로컬 파일 접근과 컴퓨터 직접 조작이 안 되므로 그런 작업은 데스크톱 앱에서 합니다.
  • 삭제 후보 중 남길 파일은 검토 폴더로 옮기라고 지시하면 안전합니다.

2. 글로벌 지침과 규칙 파일 정하기

매번 같은 설명을 반복하지 않도록 나와 작업 스타일을 한 번 적어 두는 설정입니다. Cowork에는 모든 세션에 적용되는 글로벌 지침이 있고, 폴더 기반 작업에서는 CLAUDE.md가 클로드가 가장 먼저 읽는 규칙 파일 역할을 합니다.

  1. 좌측 상단에서 Claude 설정을 엽니다.
  2. 협업 탭으로 이동합니다.
  3. 지침 항목의 편집 버튼을 누릅니다.
  4. 내가 어떤 사람인지, 작업 스타일, 선호 도구 환경을 적습니다.
  5. 저장을 누릅니다.
  6. 폴더 단위 규칙이 필요하면 그 폴더에 CLAUDE.md를 두고, 클로드에게 너는 어떻게 만들어져 있어?라고 물어 규칙이 읽히는지 확인합니다.
  • 글로벌 지침은 모든 코워크 세션에 적용되어 매번 설명하지 않아도 됩니다.
  • 역할 설명이나 결과 파일 형식(예: Word 문서) 같은 전역 지침도 Settings의 Cowork 탭에서 정할 수 있습니다.

3. 흩어진 자료로 주간 보고서 만들기

폴더에 모아 둔 회의록·엑셀·메모를 Cowork가 모두 읽고 한 페이지 보고서나 정리된 엑셀로 만들어 줍니다. 지저분한 데이터 정리나 경비 보고서처럼 매주 반복되는 문서 업무에 맞습니다.

  1. 데스크톱 앱에서 새로 생성을 누르고 입력창 하단에서 협업을 선택합니다.
  2. 프로젝트 또는 폴더에서 작업할 폴더를 고르고 항상 허용을 누릅니다.
  3. 매출 데이터, 슬랙 메모, 주간 회의록 등 자료를 폴더에 넣습니다.
  4. 폴더 안 자료를 모두 읽고 한 페이지 워드 보고서로 정리해 달라고 요청합니다.
  5. 계획과 실행 진행 상황을 지켜봅니다.
  6. 완성된 보고서를 열어 내용과 숫자를 확인합니다.
예시
폴더 안의 회의록·엑셀·메모를 모두 읽고 이번 주 팀 현황을 한 페이지 워드 보고서로 정리해 줘. 핵심 요약, 진행 상황, 다음 주 할 일, 리스크 순서로 써 줘.
  • 엑셀을 정리시킬 때는 날짜 형식·빈칸·중복 행 규칙을 적고 '원본은 그대로 두고 정리본은 새 파일로 저장'하라고 반드시 적습니다.
  • 영수증 이미지 폴더로 날짜 금액 카테고리를 포함한 경비 보고서 엑셀도 같은 방식으로 만들 수 있습니다.
  • 결과 파일은 지정한 폴더에서도 바로 확인할 수 있습니다.

4. 메일 브리핑을 예약 작업으로 받기

Gmail·캘린더를 연결하고 매일 정해진 시각에 브리핑을 만들게 하는 가장 대표적인 자동화입니다. 아침에 출근해 열어 보기만 하면 됩니다.

  1. 클로드 데스크톱에서 + → 커넥터 → 커넥터 추가 → 커넥터 둘러보기를 엽니다.
  2. Gmail 또는 Microsoft 365를 선택해 클로드에 연결하고 계정을 고릅니다.
  3. + → 커넥터에서 연결 표시(파란 불)를 확인합니다.
  4. 어제 오후 6시 이후 메일과 캘린더 일정으로 브리핑을 만들어 달라고 요청하고 결과를 확인합니다.
  5. 같은 내용을 아침 7시 50분마다 실행하는 예약 작업으로 등록해 달라고 요청합니다.
  6. 좌측 예약됨에서 스케줄을 확인합니다.
예시
어제 오후 6시 이후 받은 메일과 오늘 캘린더 일정을 바탕으로 오늘 아침 브리핑을 만들어 줘. 답장이 필요한 메일을 우선순위 순으로 알려 줘.
  • 최근 방식(7월 업데이트 이후)은 예약 작업이 클라우드에서 실행되어 기기가 꺼져 있어도 돕니다. 예전 방식: 컴퓨터가 켜져 있고 데스크톱 앱이 열려 있어야 실행됐고, 놓친 작업은 복귀 후 바로 실행됐습니다.
  • 예약 작업은 유료 플랜에서만 쓸 수 있습니다.
  • 예약 페이지에서 지난 실행 기록 확인, 지시문·주기 수정, 즉시 실행을 할 수 있습니다.

5. 스킬로 반복 업무 방식 고정하기

스킬은 '어떤 단계와 규칙으로 일할지'를 저장한 작업 지시서입니다. 보고서 양식, 말투, 회의 준비 순서를 스킬로 저장하면 매번 같은 품질의 결과가 나옵니다.

  1. 평소 쓰는 보고서 양식 파일을 채팅에 첨부합니다.
  2. 이 형식을 분석해 회사 보고서 만드는 스킬을 만들어 달라고 요청합니다.
  3. 결과에서 스킬 저장을 눌러 내 스킬로 저장합니다.
  4. 사용할 때는 /와 스킬 이름을 입력해 스킬을 선택하고 주제를 적어 요청합니다.
  5. 저장된 스킬은 + 메뉴의 스킬에서 확인합니다.
  6. 결과가 마음에 안 들면 배운 점을 스킬에 반영해 달라고 요청해 계속 고칩니다.
예시
이 보고서 형식을 분석해서 회사 보고서 만드는 스킬 제작해 줘. 답변은 한국어로 해 줘
  • 원본이 워드 파일이면 결과도 워드 파일로 만들어집니다.
  • AI 티가 나는 문장은 별도 스킬로 다듬되 본인 스타일에 맞게 고치고, 중요한 문서는 직접 읽고 고칩니다.
  • 스킬은 팀과 공유하면 누구나 같은 결과를 낼 수 있습니다.
  • 다른 도구에서도 같은 개념이 있습니다. 제미나이 스파크의 스킬, 제미나이 Gems도 지침을 저장해 두는 방식입니다.

6. 회의 준비와 후속 처리 자동화하기

캘린더·Slack·이메일·이전 회의록을 연결해 회의 전 안건 문서를 만들고, 회의 후 녹취록에서 할 일과 후속 메시지를 뽑습니다. 영업, 법무, 마케팅 운영 등 직무별 사례가 있습니다.

  1. 캘린더, Slack, 이메일을 Claude에 연결합니다.
  2. 회의록이 있는 폴더를 Claude가 볼 수 있게 지정합니다.
  3. 회의 이름과 시간을 알려 주고 준비 문서를 요청합니다.
  4. 캘린더 검색, 참석자 조사, Slack 스레드 확인, 이전 회의록 검토를 시키고 기존 문서 형식을 템플릿으로 따르라고 지시합니다.
  5. Claude가 세운 계획을 확인하고 작업이 진행되게 둡니다.
  6. 빠뜨린 출처가 있으면 작업 중에 추가로 요청합니다.
  7. 회의가 끝나면 같은 세션에서 녹취록을 처리해 개인 할 일, 내부 메시지, 고객 후속 메시지를 만들게 합니다.
  8. 각 결과를 확인하고 승인한 뒤 발송합니다.
예시
Prep me for today's call with Acme Corp at 1PM.
  • 작업 도중 지시를 추가해도 처음부터 다시 만들지 않고 방향을 바꿔 이어갑니다.
  • 발송 전에는 항상 승인 단계를 거치고, 이름을 걸고 보내는 답장은 근거를 직접 검증합니다.
  • 처음에는 테스트 계정으로 스킬을 돌려 보고 다듬은 뒤 실제 업무에 씁니다.
  • 최신 방식: Claude Meetings는 캘린더에서 회의에 Claude를 추가하면 참가자로 들어와 노트를 쓰고 문서·화이트보드를 만듭니다(Team·Enterprise 베타).

7. 주간 지표 리뷰 자동으로 준비하기

일요일 저녁 예약 작업이 지난 리뷰, 회의록, Slack, 데이터 웨어하우스를 확인해 월요일 아침 숫자를 준비해 두는 흐름입니다. 숫자 수집·검증은 Claude에게, 서사와 초점은 사람이 맡습니다.

  1. 리뷰 준비, 교정, 액션 아이템 관리용 스킬을 각각 만듭니다.
  2. 일요일 저녁에 실행되는 예약 작업을 설정합니다.

  6. 먼저 지표 표와 헤드라인만 있는 초안을 확인합니다.

8. ChatGPT Work·스파크로 업무 맡기기

Claude 외에도 ChatGPT Work와 제미나이 스파크가 파일·메일·캘린더를 다루며 예약 실행까지 지원합니다. 쓰는 구독에 맞는 도구를 골라 같은 방식으로 업무를 맡길 수 있습니다.

  1. ChatGPT 데스크탑 앱을 설치하고 메인 화면에서 Work 모드를 선택합니다.
  2. 회의록 파일을 첨부합니다.
  3. 실행 항목만 뽑아 담당자·할 일·마감 세 열의 스프레드시트로 만들어 달라고 요청합니다.
  4. 복잡한 작업은 입력창 + 버튼에서 계획 모드를 켜고, Work가 던지는 질문에 답합니다.
  5. 제미나이를 쓴다면 좌측 상단 스파크 베타 탭에서 설정의 연결된 앱에 구글 워크스페이스가 켜져 있는지 확인합니다.

  • 모호한 부분은 계획 모드에서 Work가 먼저 물어봐 더 구체적인 결과가 나옵니다.
  • 발송은 하지 말고 초안으로 남기게 하면 안전합니다.
  • 스파크는 구글 AI 프로 이상 구독이 필요하고, 데스크탑 앱은 현재 macOS만 지원합니다.
  • 추론 수준은 미디엄에서 시작해 결과가 부족하면 올립니다.

9. Slack 채널에서 Claude Tag 쓰기

Claude Tag는 팀 채널에 Claude를 추가해 대화를 따라가며 일하게 하는 기능입니다. 채널별로 지침을 기억하고 여러 사람이 함께 지시할 수 있어 팀 업무 자동화에 맞습니다.

  1. Claude를 사용할 채널 하나에 추가합니다.
  2. 필요한 도구를 Claude Tag에 연결합니다.
  3. 작업이 필요한 스레드에서 Claude를 태그해 일을 요청합니다.
  4. Claude가 단계별로 진행하는 상황을 채널에서 확인합니다.
  5. 완료 또는 결정 요청 알림이 오면 확인하고 답합니다.
  6. 반복할 지침은 Remember for this channel: ... 형태로 말해 저장시킵니다.
  7. 너무 자주 또는 드물게 개입하면 개입 빈도를 조정해 달라고 말합니다.
예시

  • Team과 Enterprise 요금제에서 베타로 제공됩니다.
  • Claude가 사용자를 대신해 응답하거나 개별 도구에 접근할 때는 매번 권한을 묻습니다.

11. n8n으로 자동화 워크플로 만들기

n8n은 노드(작업 블록)를 연결해 자동화 시나리오를 만드는 도구입니다. AI 빌더에 한국어로 요청하면 노드 구성까지 만들어 주고, FAQ 챗봇 같은 에이전트도 만들 수 있습니다.

  1. n8n 클라우드에 가입하고 새 워크플로우를 만듭니다.
  2. 가운데의 빌드 위드 AI를 클릭하고 빌드를 선택합니다.
  3. 자동화할 내용을 트리거 시점과 처리 방식까지 구체적으로 적어 실행합니다.
  4. 만들어진 각 노드를 클릭해 설정을 확인합니다.
  5. 수정 요청을 입력창에 적어 보완합니다.
  6. API 키와 OAuth 인증 정보를 직접 연결합니다.
  7. 테스트 데이터로 실행해 동작을 확인한 뒤 실제로 사용합니다.
예시
슬랙 채널에 긴급이 들어간 메시지가 오면 노션에 저장하고 담당자에게 이메일 발송
  • 프롬프트 한 번에 1크레딧이 들므로 여러 요구 사항을 한 번에 요청하면 아낄 수 있습니다.
  • 인증 정보는 보안상 AI가 설정해 주지 않아 직접 해야 하며, AI 빌더는 베타이고 n8n 클라우드에서만 쓸 수 있습니다.
  • 오류가 나면 /clear로 컨텍스트를 초기화한 뒤 다시 시도합니다.
  • 정형화된 반복 작업은 n8n, 판단이 필요한 챗봇형 작업은 OpenAI Agent Builder가 낫다는 비교가 있습니다.

12. 개입 지점을 설계해 병목 없애기

자동화를 여러 개 돌릴 때 내가 병목이 되지 않도록 권한, 상한, 확인 지점을 미리 정하는 에이전트 설계 요령입니다. 콘텐츠 제작 파이프라인 사례에서 나온 방식이지만 어떤 업무에도 적용됩니다.

  1. 피드백을 줄 때마다 그 내용을 스킬이나 규칙으로 남깁니다.
  2. 에이전트에 가능한 한 많은 권한을 줍니다.
  3. 크레딧처럼 한 번에 크게 나가는 것은 상한을 정합니다.
  4. 되돌리기 어려운 지점은 다음 단계로 가기 전에 내 확인을 받도록 정합니다.
  5. 만드는 AI와 검사하는 AI를 분리해 독립적으로 검증하게 합니다.
  6. 가장 번잡한 업무 흐름 하나를 골라 지금도 필요한지 점검하고 자동화하거나 없앱니다.
  • 상한 숫자는 영상 속 값(쇼츠 500, 롱폼 1,500)이므로 내 요금제에 맞게 정해야 합니다.
  • 예약 작업의 결과물은 발송 전 승인 단계를 두거나 초안으로만 남기게 합니다.
  • 종료 조건은 누가 봐도 참/거짓을 판정할 수 있게 쓰고, 최대 반복 횟수·시간·비용 한도를 겹쳐 겁니다.
  • 중요한 결과는 사람이 원문과 대조해 검수합니다.

13. Managed Agents로 에이전트 운영하기

Claude Managed Agents는 샌드박스, 자격 증명 보관, 메모리, 관측 같은 인프라를 대신 맡아 에이전트를 서비스로 운영하게 하는 개발자용 플랫폼입니다. 코딩 경험이 있는 팀이 에이전트를 직접 만들 때 참고하는 고급 주제입니다.

  1. 에이전트(도구·페르소나)를 정의합니다.
  2. 샌드박스 환경(패키지·네트워크 제어)을 구성합니다.
  3. 세션을 시작합니다.
  4. 이벤트 스트림을 관찰하며 동작을 확인합니다.
  5. 완료 기준을 루브릭으로 주는 outcome을 정해 기준에 맞을 때까지 반복하게 합니다.
  6. 도구별로 자동 실행과 사용자 승인을 나눠 권한을 설정합니다.
  7. 메모리 저장소를 붙이고 드리밍으로 잘못 굳은 기억을 주기적으로 정리합니다.
  • 메모리는 공개 베타, 드리밍은 연구 프리뷰이며 버전 관리와 감사 기록을 지원합니다.
  • 비용은 프롬프트 캐싱과, 강한 모델이 조정자가 되어 작은 모델에 일을 나누는 구성으로 관리합니다.
  • 모델이 좋아질수록 하네스는 얇아지므로 몇 달마다 기존 설계를 다시 점검합니다.
  • 비용 절감 수단이 적고 콜드 스타트 지연이 있어, 모든 작업에 맞지는 않는다는 의견이 있습니다.
