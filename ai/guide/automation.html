1. 자동화할 업무 하나 고르기

AI 자동화를 처음 시작할 때 무엇부터 맡길지 정하는 단계입니다. 팀에서 가장 소모적인 절차 하나를 골라 지금도 필요한지, AI로 줄일 수 있는지 점검합니다.

  1. 팀에서 가장 번잡하거나 모두가 꺼리는 업무 흐름이나 회의 하나를 고릅니다.
  2. 그 절차가 원래 어떤 목적으로 생겼는지 적어 봅니다.
  3. 지금도 그 목적에 도움이 되는지 확인합니다.
  4. 도움이 되지 않으면 없애고, 필요하지만 부담이 크면 Claude가 도울 수 있는 부분을 찾습니다.
  5. 한 번에 한 단계씩만 바꿔 나갑니다.
  • 작은 반복 업무부터 시작하세요. 광고 문구 변형처럼 30분 걸리던 일이 30초로 줄어든 사례가 있습니다.
  • 코딩 지식보다 해결할 문제를 명확하고 간결하게 설명하는 것이 중요합니다.
  • 50명이 참석하지만 다들 노트북만 보던 주간 리뷰를 '왜 하는가'라는 질문 하나로 취소한 사례도 있습니다.
  • 절차는 점검하지 않으면 계속 쌓이므로 주기적으로 다시 살펴봅니다.

2. Cowork에 폴더 작업 맡기기

Cowork는 단계마다 대화하는 대신 작업 전체를 맡기는 Claude의 사무용 기능으로, 내 컴퓨터 폴더의 파일을 직접 읽고 옮기고 만듭니다. 파일 정리처럼 범위가 분명한 일부터 맡겨 보세요.

  1. Claude 데스크톱 앱의 채팅 화면에서 코워크 버튼을 누릅니다.
  2. 입력창 하단의 프로젝트 또는 폴더에서 폴더 추가를 눌러 작업할 폴더를 엽니다.
  3. 폴더 접근 권한 창에서 항상 허용을 선택합니다.
  4. 할 일을 적고, 파일을 바꾸기 전에 계획부터 보여 달라고 요청합니다.
  5. 제안된 계획을 읽고 고칠 점을 지시합니다 (예: 삭제 후보 중 남길 파일은 검토 폴더로 옮기기).
  6. 계획을 승인하고 진행 상황과 결과 파일을 폴더에서 확인합니다.
예시
다운로드 폴더를 정리해 줘. 먼저 내용을 살펴보고 정리 계획을 제안해 줘. 파일을 옮기기 전에 계획부터 보여 줘.
  • 예전 방식: 5월 영상에서는 데스크톱 앱의 Cowork 탭을, 8월 초 영상에서는 새로 생성 → 협업을 눌러 시작했습니다.
  • 웹·모바일 버전은 로컬 파일 접근과 컴퓨터 조작이 안 되므로 내 폴더 작업은 데스크톱 앱에서 합니다.
  • Settings의 Cowork 탭에서 내 역할이나 결과 파일 형식(예: Word 문서) 같은 공통 지침을 정해 둘 수 있습니다.
  • Cowork는 프로 플랜(월 20달러) 이상에서 쓸 수 있습니다.

3. 여러 파일을 합쳐 보고서 만들기

흩어진 엑셀·회의록·메모를 한 폴더에 모아 두고 Cowork에게 합치기, 정리, 워드 보고서 작성까지 한 번에 맡기는 방법입니다. 주간 팀 현황 보고나 설문 결과 정리에 좋습니다.

  1. 작업용 새 폴더를 만들고 매출 데이터, 회의록, 메모 등 자료 파일을 복사해 넣습니다.
  2. Cowork에서 프로젝트 또는 폴더로 그 폴더를 열고 항상 허용을 누릅니다.
  3. 만들 결과물(합친 시트, 비교표, 워드 보고서)을 구체적으로 적어 요청합니다.
  4. 지저분한 데이터라면 날짜 형식·빈칸·중복 행 같은 정리 규칙도 함께 적습니다.
  5. 원본은 그대로 두고 결과는 새 파일로, 파일명에 날짜를 넣어 저장해 달라고 덧붙입니다.
  6. 계획·실행·검증 과정을 지켜본 뒤 폴더에서 엑셀과 워드 결과물을 열어 확인합니다.
예시
설문 응답 엑셀 세 개를 하나로 합치고, 채널 만족도 비교 시트와 불만 키워드 탑 10, 이를 바탕으로 한 워드 보고서를 만들어 줘. 원본은 그대로 두고 결과 파일명에는 날짜를 넣어 줘.
  • 원본 보존은 반드시 프롬프트에 적어 둡니다.
  • 영상 속 주간 보고서는 핵심 요약, 진행 상황, 다음 주 할 일, 리스크 순으로 정리되었습니다.
  • 고객 정보 같은 민감한 데이터는 빼고 먼저 하나만 시험해 보세요.

4. 커넥터로 회의 준비 문서 만들기

캘린더·Slack·이메일 같은 서비스를 Claude에 연결(커넥터)해 두면, 회의 이름과 시간만 알려 줘도 참석자 조사, 지난 대화 확인, 안건 작성을 한 번에 해 줍니다. 미팅 전 준비 시간을 크게 줄일 수 있습니다.

  1. 캘린더, Slack, 이메일을 Claude에 연결합니다.
  2. 이전 회의록이 있는 폴더를 Claude가 볼 수 있게 지정합니다.
  3. 준비할 회의와 시간을 알려 줍니다.
  4. 캘린더 검색, 참석자 조사, Slack 스레드 확인, 이전 회의록 검토, 안건 작성을 요청하고 기존 문서 형식을 템플릿으로 따르라고 지시합니다.
  5. Claude가 세운 계획을 확인하고 진행되게 둡니다.
  6. 빠뜨린 출처가 있으면 작업 중에 추가로 요청합니다 (예: 이메일도 확인해 줘).
  7. 완성된 안건 문서를 작업 폴더에서 열어 검토하고, 빠진 내용은 추가를 요청하거나 직접 고칩니다.
예시
Prep me for today's call with Acme Corp at 1PM.
  • 작업 도중 지시를 추가해도 처음부터 다시 만들지 않고 방향을 바꿔 이어 갑니다.
  • 미팅 후에는 같은 세션에서 녹취록으로 개인 할 일, 내부 Slack 메시지, 고객 후속 메시지까지 만들 수 있고, 발송 전에는 승인 단계를 거칩니다.
  • 최종 문서의 책임과 수정은 사용자에게 있으니 근거를 꼭 확인합니다.

5. Cowork 예약 작업으로 반복하기

매일·매주 같은 일을 정해진 시각에 Claude가 알아서 하게 만드는 기능입니다. 아침 메일 정리, 주간 지표 준비, 공유 폴더 변경 요약처럼 반복되는 일에 씁니다.

  1. 반복할 일을 자연어로 설명합니다.
  2. Claude가 만든 예약 작업 프롬프트 초안을 검토합니다.
  3. 필요하면 주기를 매시간·매일·평일·수동 중에서 바꿉니다.
  4. 내용이 맞으면 제안을 수락합니다.
  5. 왼쪽 사이드바의 예약(scheduled) 페이지에 작업이 추가됐는지 확인합니다.
  6. 예약 페이지에서 바로 한 번 실행해 결과가 제대로 나오는지 확인합니다.
예시
매시간 공유 드라이브 폴더에서 추가·수정된 문서를 확인해서 변경한 사람을 기록하고, 내용을 요약해 클라이언트별로 묶은 뒤 문서로 저장해 줘.
  • 예전 방식: 6월 영상에서는 컴퓨터가 켜져 있고 데스크톱 앱이 열려 있어야 실행됐지만, 7월 7일 업데이트 이후 클라우드에서 기기가 꺼져 있어도 실행됩니다.
  • 한 번 해 보고 결과가 마음에 든 작업을 '매주 평일 오후 4시마다 이 작업을 해 줘'처럼 그대로 예약하면 쉽습니다.
  • 실행마다 새 세션으로 돌아 최신 파일과 도구 상태를 기준으로 하며, 설정해 둔 커넥터도 쓸 수 있습니다.
  • 예약 페이지에서 지난 실행 기록 확인, 지시문·주기 수정, 즉시 실행을 할 수 있습니다.

6. ChatGPT Work로 회의록 정리하기

ChatGPT Work는 답 대신 결과물(문서·시트)을 만들어 주는 OpenAI의 업무 실행 에이전트입니다. 회의록을 넣으면 실행 항목 시트를 만들고, 복잡한 일은 계획 모드로 먼저 질문을 받은 뒤 처리합니다.

  1. ChatGPT 데스크탑 앱을 설치하고 메인 화면에서 Work 모드를 선택합니다.
  2. 작업이 복잡하면 입력창의 + 버튼을 눌러 계획 모드를 켭니다.
  3. 회의록 파일을 첨부합니다.
  4. 원하는 결과물과 형식을 적어 요청합니다.
  5. 계획 모드라면 Work가 던지는 질문에 답합니다.
  6. 만들어진 스프레드시트나 문서를 확인합니다.
예시
첨부한 회의록에서 실행 항목만 뽑아 담당자·할 일·마감 세 열의 스프레드시트로 만들어 줘.
  • 단순 작업은 기본 모드, 모호한 부분이 많은 복잡한 작업은 계획 모드가 더 구체적인 결과를 냅니다.
  • 파일·앱을 다루는 기능은 데스크탑 앱 전용입니다.
  • 채팅 모드에서 아이디어를 다듬은 뒤 Work의 새 프로젝트에서 컨텍스트 첨부로 이전 채팅을 불러와 이어 갈 수 있습니다.
  • 웹 데이터 수집처럼 추론이 필요한 작업은 추론 수준 미디엄에서 시작해 부족하면 올립니다 (높일수록 비용 증가).

7. 제미나이 스파크로 주간 업무 예약하기

제미나이 스파크는 구글 클라우드에서 상시 일하는 개인 AI 에이전트로, Gmail·캘린더·시트·드라이브를 별도 연결 없이 다룹니다. 프롬프트에 실행 시점을 적으면 정해진 때에 자동으로 실행됩니다.

  1. 제미나이를 실행하고 좌측 상단 스파크 베타 탭을 누릅니다.
  2. 좌측 하단 프로필에서 설정을 열고, 연결된 앱에서 구글 워크스페이스가 켜져 있는지 확인합니다.
  3. 프롬프트 맨 앞에 실행 시점을 적습니다 (예: 매주 월요일 오전 8시).
  4. 정리할 메일 범위와 저장할 곳(구글 시트)을 지시합니다.
  5. 메일은 발송하지 말고 초안으로만 남기라고 덧붙입니다.
  6. 좌측 일정 탭에서 등록된 일정을 확인합니다.
예시
매주 월요일 오전 8시에 지난 7일간 Gmail의 뉴스레터·업무 보고 메일을 구글 시트에 정리하고, 핵심 요약 5개를 이메일 초안으로 작성해 줘. 발송하지 말고 초안으로만 남겨 줘.
  • 구글 AI 프로 이상 구독이 필요하며 한국어를 공식 지원합니다.
  • 브라우저를 닫거나 폰을 잠가도 백그라운드에서 작업이 계속됩니다.
  • 발송 대신 초안으로 남기게 하면 실수로 메일이 나가는 일을 막을 수 있습니다.

8. 반복 업무를 스킬로 저장하기

스킬은 Claude에게 업무 매뉴얼을 저장해 두는 기능으로, 같은 지시로 매번 같은 품질의 결과를 냅니다. 브리핑 형식, 내 문체, 보고서 검수 규칙처럼 자주 쓰는 방식을 스킬로 만들어 두고 불러 씁니다.

  1. Cowork 세션을 열고 매번 원하는 결과와 순서를 설명해 스킬 초안을 만들어 달라고 합니다.
  2. 스킬에 필요한 커넥터(이메일, Slack 등)와 결과를 저장할 폴더를 지정합니다.
  3. 테스트용 자료로 스킬을 한 번 실행해 결과를 봅니다.
  4. 마음에 들지 않는 부분을 규칙으로 덧붙여 스킬을 다듬습니다.
  5. 실제로 쓸 때는 /를 입력하고 저장한 스킬을 고른 뒤 대상(예: 고객사 이름)을 적습니다.
  6. 실행 후 이번에 배운 점을 스킬에 반영해 달라고 요청합니다.
예시
내가 보낸 이메일을 분석해서 내 문체를 스킬로 저장해 줘. 규칙: 인사말은 한 줄, 본론 먼저, 세 문장 이내.
  • 피드백을 줄 때마다 그 내용을 스킬로 남기면 같은 지적을 반복하지 않아도 됩니다.
  • 결과물을 시리즈로 묶고 시리즈마다 스킬을 두면 같은 지시로 같은 품질이 나옵니다.
  • 스킬은 일반 텍스트 파일이라 언제든 열어 동작을 확인할 수 있고, 팀과 공유하면 누구나 같은 결과를 냅니다.
  • 스킬 저장 전후로 같은 프롬프트를 실행해 결과를 비교해 보세요.

9. Slack 채널에서 Claude Tag 쓰기

Claude Tag는 Slack 같은 팀 채널에 Claude를 추가해, 채널 대화와 공유 문서를 참고하며 팀원처럼 일하게 하는 기능입니다. 채팅 창으로 맥락을 복사해 갈 필요 없이 채널에서 바로 일을 맡깁니다.

  1. 사용할 Slack 채널 하나에 Claude를 추가합니다.
  2. 필요한 도구(Google Drive, Asana 등)를 Claude Tag에 연결합니다.
  3. 작업이 필요한 스레드에서 Claude를 태그해 일을 요청합니다.
  4. Claude가 단계별로 진행하는 동안 다른 일을 하다가, 완료나 결정 요청 알림이 오면 확인하고 답합니다.
  5. 반복할 지침은 Remember for this channel: ... 형태로 말해 채널 기억에 저장합니다.
  6. 너무 자주 또는 드물게 끼어들면 개입 빈도를 조정해 달라고 말합니다.
예시
@Claude 최근 3일 스레드, Google Drive 회의록, Asana 열린 작업을 확인해서 이번 주 미결 액션 아이템 목록을 만들어 줘.
  • Team·Enterprise 요금제에서 베타로 제공됩니다.
  • 처음에는 한 채널에서만 시작하고, 프로젝트 상태 추적에는 공개 채널이 좋습니다.
  • 채널별로 접근 권한이 나뉘며, Claude가 사용자를 대신해 응답하거나 개별 도구에 접근할 때는 매번 권한을 묻습니다.
  • 스타일 가이드나 체크리스트 문서를 알려 주면 참고하고, 문서가 바뀌면 최신 내용을 따릅니다.

10. Claude Code 루틴으로 정기 작업 맡기기

루틴은 프롬프트, 연결할 저장소, 커넥터, 실행 조건(트리거)을 정해 두면 Anthropic 클라우드에서 Claude Code 세션을 자동으로 실행하는 기능입니다. 노트북을 닫아도 돌아가며, 정해진 시간이나 GitHub 이벤트로 시작할 수 있습니다.

  1. 터미널에서 Claude Code를 실행합니다.
  2. /schedule을 입력하고 원하는 작업을 적습니다.
  3. Claude가 묻는 질문(실행 요일·시각, 끝난 뒤 Slack 등으로 알릴지)에 답합니다.
  4. 작업에 필요한 저장소를 컨텍스트로 연결합니다.
  5. 웹의 Claude Code에서 만들어진 루틴을 확인합니다.
  6. 실행 결과 세션을 열어 결과를 보고 필요하면 이어서 지시합니다.
예시
/schedule 매주 main에 병합된 변경을 문서 저장소와 비교해서, 바뀐 부분이 있으면 문서 수정 PR을 만들어 줘.
  • 루틴을 만들기 전에 트리거(언제), 컨텍스트(무엇을 알아야 하나), 조종(어떻게 바로잡나) 세 가지를 먼저 정하세요.
  • 처음에는 결과를 직접 확인하고, 신뢰가 쌓이면 더 많은 권한을 맡깁니다.
  • 10월 영상의 Claude Code Projects(베타, Pro·Max 순차 제공)에서도 한 프로젝트 안에서 매일 도는 루틴을 설정할 수 있습니다.

11. 사람이 확인할 지점 정하기

여러 자동화를 동시에 돌리면 사람이 일일이 승인하는 것이 병목이 됩니다. 맡길 것과 꼭 확인할 것을 미리 정해 두는 Human on the loop 설계로, 자주 묻지 않으면서도 큰 실수는 막습니다.

  1. 되돌리기 쉬운 일은 에이전트에 가능한 한 많은 권한을 줍니다.
  2. 크레딧·비용처럼 한 번에 크게 나가는 것은 작업별 상한을 정합니다.
  3. 되돌리기 어려운 단계는 진행 전에 내 확인을 받도록 정합니다.
  4. 메일 발송처럼 바깥으로 나가는 행동은 초안을 만든 뒤 승인을 받고 보내게 합니다.
  5. 피드백을 줄 때마다 그 내용을 스킬이나 규칙으로 남겨 다음부터 묻지 않게 합니다.
예시
되돌리기 어려운 단계(캐릭터 생성 등)를 하기 전에는 반드시 내 확인을 받아. 생성 크레딧은 쇼츠 500, 롱폼 1,500을 넘기지 마.
  • 예시의 상한 숫자(쇼츠 500·롱폼 1,500)는 영상 제작자 본인의 값이므로 내 요금제에 맞게 정합니다.
  • 폭주하는 작업에 대비해 멈추는 장치(서킷 브레이커)를 두라는 조언도 있습니다.
  • 처음에는 결과를 직접 확인하고 신뢰가 쌓이면 권한을 넓힙니다.

12. 검증 루프와 종료 조건 설계하기

AI가 시키지 않아도 스스로 돌아가게 하려면 무엇이 '완료'인지 판정하는 기준과, 결과를 검사해 다시 고치는 순환이 필요합니다. 만드는 AI와 검사하는 AI를 나누고 종료 조건을 겹쳐 걸어 품질과 비용을 함께 관리합니다.

  1. 완료 기준을 누가 봐도 참/거짓으로 판정할 수 있게 적습니다.
  2. 종료 조건을 겹쳐 겁니다: 검증 통과, 최대 반복 횟수, 시간·비용 한도, 진전 없으면 중단.
  3. 진행 상황을 적는 상태 파일을 두어 대화가 끝나도 이어서 일할 수 있게 합니다.
  4. 결과를 기준(원본·사양서)과 비교하게 하고, 다르면 고쳐서 다시 비교하게 합니다.
  5. 만드는 AI와 검사하는 AI를 분리합니다 (예: Claude가 쓰면 Codex가, Codex가 쓰면 Claude가 검증).
  6. 숫자가 들어간 결과는 모든 숫자가 출처로 추적되는지 검산하게 합니다.
예시
결과를 원본과 비교해서 다른 점이 있으면 고치고 다시 비교해 줘. 최대 3번까지 반복하고, 그래도 다르면 멈추고 다른 점을 보고해 줘.
  • 같은 AI가 자기 결과를 검사하면 관대해지기 쉬워 검사자를 따로 둡니다.
  • AI 채점기도 틀릴 수 있으니 자동 검사, 눈 검사, 숫자 검산처럼 여러 검사를 함께 씁니다.
  • AI가 만든 결과물도 공개 전에는 사람이 원문과 대조해 검수합니다.
  • 개발자용 Claude Managed Agents에서는 Outcomes 기능에 루브릭과 반복 횟수를 주면 기준을 만족할 때까지 스스로 고칩니다.
