업무 자동화·에이전트

이 분야에서는 Claude에게 일을 통째로 맡기는 방법을 다룹니다. 회의 준비, 정해진 시각에 도는 반복 작업, 팀 채널에서 함께 일하는 Claude, 스스로 결과를 점검하는 에이전트까지 할 수 있습니다. 먼저 자동화할 업무를 고르고 Cowork 위임과 예약 작업부터 익히세요. 그다음 Claude Tag와 Claude Code 루틴·Projects로 넓히고, 마지막에 스킬, 사람이 확인할 지점, Managed Agents로 나만의 에이전트를 설계하면 됩니다.

Cowork, 예약 작업, 반복 업무 자동화, 에이전트 설계, 실무 워크플로 · 영상 40개 기반 · 2026-10-25 갱신

최근 바뀐 점

  • Claude가 주의가 필요한 일을 먼저 알려 주고 폰을 내려놓은 뒤에도 계속 일하는 앱 Claude Duet이 연구 프리뷰로 공개되었습니다. 지금은 미국 Pro·Max 구독자만 대기자 명단으로 신청할 수 있습니다.
  • Claude Code에 Projects(베타)가 생겼습니다. 하나의 대화가 여러 스레드를 클라우드에서 병렬로 돌리며, 노트북을 닫아도 일이 계속됩니다. Pro·Max 요금제에 순서대로 제공되고 있습니다.
  • Claude Tag가 Team·Enterprise 계정에서 채널별 지침 기억(Remember for this channel: ...)을 지원합니다. 관리자는 채널마다 접근 범위와 자율성을 정할 수 있습니다.
  • Adobe Acrobat의 AI PDF 스페이스에 파일·링크를 최대 100개까지 넣어 요약하고, 발표 슬라이드 초안과 예상 질문·답변까지 만들 수 있습니다.

1. 자동화할 업무 하나 골라 점검하기

자동화를 시작하기 전에 팀에서 시간을 가장 많이 잡아먹는 절차 하나를 골라, 아직도 필요한지와 Claude가 줄일 수 있는지를 따져 보는 단계입니다. 무엇을 맡길지 정하지 않고 도구부터 켜면 효과가 작으므로 가장 먼저 해 보세요.

  1. 팀에서 가장 번잡하거나 부담이 큰 워크플로 또는 회의 하나를 고릅니다.
  2. 그 절차가 지금도 원래 목적에 맞게 돌아가는지 스스로 묻습니다.
  3. 비용이 크다면 Claude가 도울 수 있는 부분이 있는지 살펴봅니다.
  4. 매번 순서가 같은 반복 업무인지, 상황마다 단계가 달라지는 업무인지 나눕니다.
  5. 한 번에 한 단계씩 바꿔 나갑니다.
  • 절차는 문제를 풀려고 만들지만 시간이 지나면 점검 없이 방치되기 쉽습니다.
  • PR 관리나 코드 리뷰처럼 반복되는 일은 루프·루틴으로, 시스템 최적화처럼 단계를 미리 알 수 없는 일은 동적 워크플로로 맡기는 것이 맞습니다(Ramp 사례).
  • 기술 논쟁은 회의로 풀기보다 Claude로 여러 버전을 만들어 비교하면 효과적이라고 소개합니다.

2. Cowork로 회의 준비 문서 만들기

Claude Cowork에 캘린더·Slack·이메일과 회의록 폴더를 연결해 두고, 회의 준비를 통째로 맡기는 방법입니다. 참석자 조사, 지난 대화 확인, 안건 작성까지 한 번에 끝나서 회의 직전 준비 시간이 줄어듭니다.

  1. 캘린더, Slack, 이메일을 Claude에 연결합니다.
  2. 회의록이 있는 폴더를 Claude가 볼 수 있게 지정합니다.
  3. 준비할 회의와 시간을 알려 줍니다.
  4. 캘린더 검색, 참석자 조사, Slack 스레드 확인, 이전 회의록 검토, 안건 작성을 요청합니다. 형식은 기존 문서를 템플릿으로 따르라고 지시합니다.
  5. Claude가 세운 계획을 확인하고 작업이 진행되게 둡니다.
  6. 빠뜨린 출처가 있으면 작업 중에 추가로 요청합니다(예: 이메일도 확인).
  7. 작업 폴더에 저장된 안건 문서를 열어 검토하고, 빠진 내용은 추가를 요청하거나 직접 고칩니다.
예시
Prep me for today's call with Acme Corp at 1PM.
  • 작업 도중 지시를 더해도 처음부터 다시 만들지 않고 방향만 바꿔 이어갑니다.
  • 최종 문서의 책임과 수정은 사용자에게 있으니 꼭 직접 검토하세요.

3. Cowork 예약 작업 만들기

매시간·매일·평일처럼 정해진 주기로 같은 일을 Claude가 알아서 하게 만드는 기능입니다. 할 일을 말로 설명하면 Claude가 예약 작업 프롬프트 초안을 만들어 주고, 사용자는 주기를 확인한 뒤 승인만 하면 됩니다.

  1. 반복할 일을 자연어로 설명합니다.
  2. Claude가 만든 예약 작업 프롬프트 초안을 검토합니다.
  3. 필요하면 주기를 매시간·매일·평일·수동 중에서 바꿉니다.
  4. 내용이 맞으면 제안을 수락합니다.
  5. 왼쪽 사이드바의 예약(scheduled) 페이지에 작업이 추가됐는지 확인합니다.
  6. 한 번 바로 실행해 결과가 제대로 나오는지 확인합니다.
예시
매시간 공유 드라이브 폴더에서 새로 추가되거나 수정된 문서를 확인해 줘. 누가 바꿨는지 기록하고, 변경 내용을 요약해 클라이언트별로 묶은 다음 문서로 저장해 줘.
  • 예약 작업은 컴퓨터가 켜져 있고 Claude 데스크톱 앱이 열려 있을 때만 실행됩니다. 꺼져 있어서 놓친 작업은 다시 켜면 바로 실행되고, 늦어졌다고 알려 줍니다.
  • 실행할 때마다 새 Cowork 세션으로 돌아서 최신 파일과 도구 상태를 기준으로 하고, 연결해 둔 커넥터도 그대로 쓸 수 있습니다.
  • 예약 페이지에서 지난 실행 기록 확인, 지시문·주기 수정, 즉시 실행을 할 수 있습니다.
  • 한 번 해 보고 결과가 마음에 들면 대화 끝에 '매주 평일 오후 4시마다 이 작업을 해 달라'고 말해 예약으로 바꿀 수도 있습니다(Claude for Teachers 사례).

4. PDF 스페이스로 발표 자료 준비하기

Adobe Acrobat의 AI PDF 스페이스에 보고서와 기사 링크를 모아 넣고, 핵심 정리부터 발표 슬라이드 초안과 예상 질문 답변까지 만드는 방법입니다. 요약에 붙은 출처를 누르면 원문 위치가 보여서 근거를 바로 확인할 수 있습니다.

  1. PDF 스페이스에 파일, 이미지, 웹 링크, 텍스트 자료를 넣습니다.
  2. AI 어시스턴트에 핵심 내용을 정리해 달라고 요청합니다.
  3. 요약 속 숫자를 눌러 원문의 해당 부분을 확인합니다.
  4. 정리한 내용으로 프레젠테이션 초안을 만들게 합니다.
  5. Adobe Express 편집 화면에서 글자·배경·아이콘을 하나씩 고칩니다.
  6. JPG, PNG, PPTX, PDF 중 필요한 형식으로 내려받습니다.
  7. 팀 회의에서 나올 만한 예상 질문과 답변을 정리해 달라고 하고, 답변마다 붙은 출처를 눌러 확인합니다.
예시
팀 회의에서 나올 만한 질문 세 개와 답변을 정리해 줘. 근거가 없는 내용은 '확인 필요'라고 표시해 줘.
  • PDF 스페이스에는 확장자와 상관없이 최대 100개 파일까지 넣을 수 있습니다.
  • 근거 없는 내용은 '확인 필요'로 표시해 달라고 하면 검토가 쉬워집니다.

5. Slack 채널에서 Claude Tag 쓰기

Slack 같은 팀 워크스페이스 채널에 Claude를 추가해 두고, 팀 대화 속에서 바로 일을 맡기는 기능입니다. 채팅 창을 오가며 맥락을 복사해 붙일 필요가 없고, 채널별 지침을 기억해 며칠씩 걸리는 일도 이어서 처리합니다.

  1. Claude를 쓸 채널 하나에 Claude를 추가합니다.
  2. 필요한 도구(Google Drive, Asana 등)를 연결합니다.
  3. 작업이 필요한 스레드에서 Claude를 태그해 일을 맡깁니다.
  4. 기다리지 말고 다른 일을 하다가, 완료나 결정 요청 알림이 오면 확인하고 답합니다.
  5. 채널의 다른 사람도 같은 요청에 이어서 추가 지시를 할 수 있습니다.
  6. 반복할 지침은 Remember for this channel: ... 형태로 말해 저장시킵니다.
  7. 너무 자주 또는 너무 드물게 끼어들면 개입 빈도를 조정해 달라고 말합니다. 매번 태그하기 번거로우면 항상 응답하라고 지시합니다.
예시
@Claude 최근 3일 스레드, Google Drive 회의록, Asana 열린 작업을 확인해서 이번 주 미결 액션 아이템 목록을 만들어 줘.
  • Team·Enterprise 계정에서 쓸 수 있습니다. 처음에는 공개 채널 한 곳에서 시작하세요.
  • 스타일 가이드나 체크리스트 문서를 알려 주면 그 문서를 참고하고, 문서가 바뀌면 기본적으로 최신 내용을 따릅니다.
  • Claude는 자기 계정으로 일하고 모든 변경과 요청자를 기록합니다. DM과 비공개 채널 내용은 그 안에만 남습니다.
  • 사용자를 대신해 응답하거나 개별 도구에 접근할 때는 매번 권한을 묻습니다.

6. 인터뷰 방식으로 내 해석 더하기

남의 영상이나 글을 소재로 쓸 때, Claude가 나를 인터뷰하게 해서 내 의견을 더한 2차 콘텐츠를 만드는 방법입니다. 번역·자막만 단 결과물은 누구나 만들 수 있으므로, 내 해석을 넣어 차별점을 만듭니다.

  1. 원본 영상이나 글을 직접 보고 듣습니다.
  2. Claude에 이 자료로 롱폼 콘텐츠를 만들어 보자고 던집니다.
  3. 영상을 본 사람이 궁금해할 질문을 뽑아 나를 인터뷰하게 시킵니다.
  4. 질문마다 소감과 의견을 말로 풀어 답합니다.
  5. 그 인터뷰 내용을 바탕으로 콘텐츠를 만들게 합니다.
  6. 음성, 자막, 설명용 그래픽을 입혀 완성합니다.
예시
이 영상으로 롱폼을 만들어 보자. 단순 번역 말고, 이 영상을 본 사람이 궁금해할 질문을 뽑아서 나를 인터뷰해 줘. 내 답을 바탕으로 대본을 써 줘.
  • 반응 데이터를 보고 다음 콘텐츠를 고치세요. 알렉스는 본인이 말하는 구간에서 시청자가 빠져나간 것을 확인하고 수정했습니다.
  • 좋아요 1위 댓글에 답하는 후속편처럼, 반응에서 다음 기획을 얻을 수 있습니다.

7. /schedule로 Claude Code 루틴 만들기

루틴은 프롬프트, 저장소, 커넥터, 트리거만 정해 두면 Anthropic 서버에서 Claude Code 세션이 자동으로 돌아가는 기능입니다. 노트북을 닫아도 실행되며, 정해진 일정이나 GitHub 이벤트·웹훅을 계기로 시작할 수 있습니다.

  1. 터미널에서 Claude Code를 실행합니다.
  2. /schedule을 입력하고 원하는 작업을 적습니다.
  3. Claude가 묻는 질문(몇 시에 실행할지, 끝나면 Slack 등으로 알릴지)에 답합니다.
  4. 필요한 저장소(예: 소스 코드 저장소와 문서 저장소)를 컨텍스트로 연결합니다.
  5. 웹의 Claude Code에서 만들어진 루틴을 확인하고, 실행 결과 세션을 열어 봅니다.
예시
/schedule 매주 main에 병합된 변경을 문서 저장소와 비교해서, 바뀐 부분이 있으면 문서 수정 PR을 만들어 줘.
  • 트리거(언제 돌릴지), 컨텍스트(무엇을 알아야 하는지), 조종(어떻게 바로잡을지) 세 가지를 먼저 정하세요.
  • 모든 루틴은 웹·CLI·데스크톱에서 열어 지시를 더하고 이어 쓸 수 있는 일반 세션입니다.
  • Cowork 예약 작업은 PC가 켜져 있어야 하지만, 루틴은 Anthropic 인프라에서 돌아서 노트북이 꺼져 있어도 됩니다.
  • 처음에는 결과를 직접 확인하고, 믿을 만해지면 권한을 더 맡기세요.

8. Claude Code Projects로 병렬 작업하기

Project는 Claude가 여러 작업을 조율하는 하나의 지속적인 대화입니다. 작업마다 클라우드의 별도 브랜치에서 도는 스레드를 만들어 동시에 처리하므로, 여러 세션이나 저장소에 걸친 큰 목표에 알맞습니다.

  1. 여러 세션이나 저장소에 걸친 큰 목표 하나를 Project로 시작합니다.
  2. Claude가 작업마다 스레드를 만들어 병렬로 처리하게 둡니다.
  3. 목업이나 디자인 명세처럼 모든 스레드가 볼 자료는 library 탭에 추가합니다.
  4. 코디네이터는 낮은 노력 수준으로 두고, 스레드는 작은 모델로 돌리다 복잡한 작업에서만 바꿉니다.
  5. 노트북을 닫은 뒤에는 휴대폰으로 진행 상황을 확인합니다.
  6. 스레드가 함께 쓰는 메모리는 프로젝트 설정에서 확인하고 고칩니다.
  • 현재 베타이며 Pro·Max 요금제에 순서대로 제공되고 있습니다.
  • 한 프로젝트 안에서 PR 검토, 아티팩트 생성, 외부 서비스 연결, 매일 도는 루틴 설정까지 할 수 있습니다.
  • 스레드는 각자 클라우드 브랜치에서 도는 독립 세션이라 서로 작업을 덮어쓰지 않습니다.

9. 내 피드백을 스킬로 쌓아 두기

같은 지적을 반복하지 않도록, Claude에게 준 피드백과 업무 방식을 스킬로 저장해 두는 방법입니다. 스킬로 만든 워크플로는 Word·Excel 패널이나 Cowork에서 다시 불러 쓸 수 있어서, 쓸수록 에이전트가 내 기준에 가까워집니다.

  1. Claude에게 반복해서 주는 피드백과 수정 내용을 모읍니다.
  2. 자주 쓰는 기준을 Claude 계정에서 스킬로 만듭니다(예: /brand-guidelines).
  3. 스킬에는 '무엇을 하라'는 규칙보다 '어떻게 판단하라'는 원칙을 적습니다.
  4. Word나 Excel 패널 같은 작업 화면에서 스킬을 불러 씁니다.
  5. 스킬을 쓴 결과에 사람이 덧붙인 수정을 기록해 스킬에 다시 반영합니다.
  6. 팀에서 함께 쓸 스킬이면 공개하기 전에 소유자, 검토자, 폐기 기준, 테스트 방식을 정합니다.
  • Every는 편집장이 과거에 고친 3만 건으로 교정 스킬을 만들었고, 사람이 추가로 고친 내용을 추적해 계속 다듬습니다.
  • 맨 그룹은 파워 유저가 자기만 편하게 만든 스킬(비용센터 코드가 고정된 경비 스킬)로 문제를 겪었습니다. 그래서 모든 스킬을 보이게 하고 태그·평가를 붙이는 관리 방식을 도입했습니다.
  • Excel과 PowerPoint를 오가는 분석 작업도 스킬로 저장해 두면 한 번의 클릭으로 다시 실행할 수 있습니다.

10. 사람이 확인할 지점 설계하기

에이전트에 여러 일을 동시에 맡기면 매번 승인하는 내가 병목이 됩니다. 권한은 넉넉히 주되 돈이 크게 나가거나 되돌리기 어려운 지점에만 확인을 두는 방식(Human on the loop)으로 설계합니다.

  1. 에이전트가 할 일 가운데 되돌리기 쉬운 일과 어려운 일을 나눕니다.
  2. 되돌리기 쉬운 일은 에이전트에 가능한 한 많은 권한을 줍니다.
  3. 크레딧처럼 한 번에 크게 나가는 비용에는 상한을 정합니다.
  4. 되돌리기 어려운 지점(예: 캐릭터 생성, 대외 발송)은 실행 전에 내 확인을 받도록 정합니다.
  5. 피드백을 줄 때마다 그 내용을 스킬이나 규칙으로 남겨, 같은 확인이 다시 필요 없게 합니다.
  • 알렉스의 크레딧 상한(쇼츠 500, 롱폼 1,500)은 예시일 뿐이니 내 요금제에 맞게 정하세요.
  • Shopify CTO는 프로세스가 폭주할 때 멈춰 세울 서킷 브레이커가 필요하다고 강조합니다.
  • Managed Agents에서는 도구마다 자동 실행과 사용자 승인을 나눠 설정할 수 있습니다.
  • Claude Duet·Claude Tag도 사용자를 대신해 행동하기 전에 먼저 확인을 받는 방식으로 설계되어 있습니다.

11. 콘텐츠 자동화 파이프라인 만들기

기획부터 업로드까지 콘텐츠 제작 전 과정을 단계별로 나눠 에이전트에게 맡기는 방법입니다. 알렉스는 영상 하나에 30시간 걸리던 일을, 라이브 한 편으로 롱폼 5편과 쇼츠 22편을 만드는 구조로 바꿨습니다.

  1. 기획·리서치 단계에서 사람들이 관심 갖는 주제와 포맷을 조사시킵니다.
  2. 대본 단계에서 내 말투를 반영해 큰 틀과 스토리보드를 짜게 합니다.
  3. 음성은 내 목소리를 씁니다.
  4. 모션 단계에서는 HTML 코드로 영상을 만드는 Hyperframes 같은 도구를 씁니다.
  5. 검수 단계에서 Claude가 만든 것은 Codex가, Codex가 만든 것은 Claude가 따로 검증하게 합니다.
  6. 패키징 단계에서 썸네일과 제목을 만들고 업로드까지 맡깁니다.
  7. 컷 편집·모션 그래픽 규칙은 스킬로 만들어 둡니다.
  • 규칙을 스킬로 만들어 두면 라이브 영상만 넘겨도 편수까지 Claude가 정해 파이프라인이 돌아갑니다.
  • 다른 사람의 파이프라인 화면을 캡처해 Claude에 붙여 넣고 내 상황에 맞게 바꿔 달라고 하면 빨리 시작할 수 있습니다.
  • 서로 다른 AI끼리 교차 검수하면 한 모델이 놓친 실수를 잡기 쉽습니다.

12. Managed Agents로 업무 에이전트 띄우기

Claude Managed Agents는 호스팅, 샌드박스, 자격 증명 보관, 메모리, 재시도 같은 에이전트 인프라를 Anthropic이 대신 맡는 API 플랫폼입니다. 회의 브리프나 영업 보고처럼 회사 업무용 에이전트를 직접 만들어 운영하려는 사람에게 맞으며, API 키로 개발할 수 있어야 합니다.

  1. Claude API 키를 준비하고 개발자 콘솔을 엽니다.
  2. 에이전트(두뇌 역할의 템플릿)를 정의합니다.
  3. 에이전트가 일할 실행 환경(샌드박스 템플릿)을 구성합니다.
  4. 도구마다 자동 실행할지, 사용자 승인을 받을지 정합니다.
  5. 세션을 시작합니다. 필요하면 GitHub 저장소나 파일을 미리 불러옵니다.
  6. outcome 기능으로 좋은 결과의 기준(루브릭)과 반복 횟수를 정해, 기준을 만족할 때까지 스스로 점검하게 합니다.
  7. 이벤트 스트림과 콘솔에서 실행 과정을 실시간으로 지켜보며 디버깅합니다.
  8. 세션이 끝나도 배운 것을 기억하게 하려면 메모리 스토어를 붙입니다.
  • 비용을 줄일 수단이 적고 처음 시작할 때 지연(콜드 스타트)이 있습니다. 그래서 어려운 작업에 잘 맞고, 그 밖의 작업은 직접 만드는 선택도 검토하라고 합니다.
  • 메모리가 쌓여 어지러워지면 드리밍(과거 세션을 분석해 메모리를 정리·보강하는 백그라운드 작업)을 씁니다.
  • 자격 증명은 Vaults에 암호화해 보관하고 사용자·세션별로 관리합니다.
  • 모델이 좋아질수록 업무 절차 틀(하네스)은 얇아지므로, 주기적으로 기존 설계를 다시 점검하세요.
