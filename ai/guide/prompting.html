1. AI에게 첫 대화 시작하기

AI를 처음 쓰는 사람이 설치나 복잡한 설정 없이 말로 시작하는 방법입니다. 핵심은 AI에게 나에 대한 맥락을 주는 것이며, 무료로 시작해 한도에 막힐 때 유료로 넘어가면 됩니다.

  1. 완전 처음이라면 ChatGPT 앱의 보이스 모드로 말하듯 질문합니다.
  2. 어느 정도 써 봤다면 Claude 데스크톱 앱에서 컴퓨터 속 파일을 보여 주며 나를 파악하게 합니다.
  3. 무료 플랜으로 먼저 씁니다.
  4. 하루 30분, AI에게 질문하고 AI가 나에게도 질문하도록 유도하는 습관을 만듭니다.
  5. 무료 한도에 자주 막힐 때 유료로 넘어갑니다.
  • 보이스 모드는 한 시간 제한이 있다고 합니다.
  • 늦게 시작해도 마인드셋이 더 중요하므로 따라잡을 수 있습니다.

2. 회사 일 전에 학습 사용 끄기

ChatGPT에서 내 대화가 모델 학습에 쓰이지 않도록 설정하는 방법입니다. 회사 업무에 AI를 쓰기 전에 가장 먼저 해 둘 일입니다.

  1. ChatGPT 설정(Settings)에서 Data controls로 들어갑니다.
  2. Improve the model for everyone 항목을 끕니다.
  • 회사 일에 쓰기 전에 반드시 먼저 끕니다.
  • 개인정보와 기밀 정보는 입력하지 않습니다.

3. 구체적으로 질문해 원하는 답 얻기

상황·목표·형식·조건을 구체적으로 주고 예시를 곁들여 원하는 결과에 가까운 답을 받는 기본 프롬프트 작성법입니다. 처음 만난 똑똑한 친구에게 설명하듯 말하면 됩니다.

  1. AI에게 역할을 정해 줍니다 (예: 너는 중학교 교사야).
  2. 내 상황과 해야 할 일, 목표를 적습니다.
  3. 답변 형식을 지정합니다 (표, 요약, 슬라이드 등).
  4. 말투·분량·난이도 같은 추가 조건을 적습니다.
  5. 원하는 결과의 예시를 두세 개 붙입니다.
  6. 추가 정보가 필요하면 요청해라고 덧붙입니다.
  7. 답이 아쉬우면 '지금보다 두 배로 길게'처럼 이어서 고쳐 달라고 합니다.
예시
너는 중학교 교사야. 학부모에게 보낼 가정통신문 초안을 써 줘. 형식은 인사말·안내 사항·문의처 세 단락, 말투는 정중하게, 분량은 400자 안팎. 추가 정보가 필요하면 먼저 물어봐.
  • 예시 없이 질문만 하는 것(제로샷)보다 예시를 주는 것(퓨샷)이 원하는 결과에 가깝습니다.
  • 원치 않는 표현은 '이렇게는 쓰지 마'라고 알려 줍니다.
  • AI가 되묻는 질문에는 성실히 답해 줍니다.

4. 말로 프롬프트 쓰고 다듬기

타이핑 대신 음성 입력으로 길게 말해 맥락을 충분히 주는 방법입니다. 음성 입력 도구 Typeless는 군더더기를 지우고 정리된 문장으로 입력해 주며, 그 문장을 다시 프롬프트로 다듬을 수도 있습니다.

  1. Typeless로 두서없이 하고 싶은 요청을 말해 입력합니다.
  2. 입력된 문장을 드래그로 선택합니다.
  3. Ask Anything 단축키를 누릅니다.
  4. 무엇이든 물어보세요 칸에 '더 잘 알아듣는 프롬프트로 다듬어 줘. 타겟·톤·결과물 형식을 구체적으로 넣어 줘'라고 말합니다.
  5. 약 3초 후 나온 프롬프트를 필요하면 고쳐서 AI에 입력합니다.
예시
더 잘 알아듣는 프롬프트로 다듬어 줘. 타겟·톤·결과물 형식을 구체적으로 넣어 줘.
  • 무료 사용량은 주당 8,000단어입니다.
  • 전문 용어는 가끔 틀릴 수 있어 확인이 필요합니다.
  • '더 짧게', '더 친근하게' 같은 수정도 같은 방식으로 요청할 수 있습니다.
  • 음성 받아쓰기는 ChatGPT가 가장 정확하다는 의견도 있습니다.

5. 영어 메일을 현지 직원처럼 쓰기

번역기처럼 문장만 바꾸는 대신, 맥락을 바꿔 현지 직원이 쓴 듯한 영어 메일을 받는 요령입니다. 받는 사람과 상황을 알려 주는 것이 핵심입니다.

  1. 받는 사람의 직급을 프롬프트에 적습니다.
  2. 나와 받는 사람의 관계를 적습니다.
  3. 메일이 끝난 뒤 무엇이 일어나야 하는지를 적습니다.
예시
받는 사람은 거래처 부사장이고, 나와는 두 번 미팅한 사이야. 이 메일을 보내고 나면 다음 주 안에 견적 회신을 받고 싶어. 이 내용을 현지 직원이 쓴 것처럼 자연스러운 영어 메일로 써 줘.
  • 번역기는 문장을 바꾸고, 현지 직원은 맥락을 바꿉니다.

6. AI 답변 검증하며 쓰기

AI는 그럴듯하지만 사실이 아닌 내용(환각)을 만들거나 사용자에게 맞춰 동의(아첨)할 수 있습니다. 질문의 중요도에 따라 확인 강도를 조절하는 방법입니다.

  1. 틀렸을 때 어떤 일이 생기는지 스스로 묻고 확인 강도를 정합니다.
  2. 미리 모르면 모른다고 말해 달라고 허용합니다.
  3. AI에게 근거가 되는 출처를 요청합니다.
  4. 제시된 출처를 직접 열어 실제로 그 내용이 있는지 확인합니다.
  5. 원하는 답을 흘리지 말고 중립적으로 질문합니다.
  6. 의심스러우면 얼마나 확신하는지, 틀릴 만한 부분이 있는지 묻습니다.
  7. 새 대화를 열어 그 답변의 오류를 찾고 출처가 맞는지 확인해 달라고 합니다.
  8. 중요한 작업은 믿을 만한 자료와 교차 확인하거나 다른 AI로 검증합니다.
예시
이 결정에 대한 가장 강력한 찬성과 반대 논거는 무엇인가요? 모르는 부분은 모른다고 말해 줘도 괜찮아요.
  • 숫자·날짜·인용은 특히 다시 확인합니다.
  • AI가 실제로 없는 출처를 그럴듯하게 만들어 낼 수도 있습니다.
  • 자신 있는 말투나 깔끔한 문단·그래픽은 정확성의 증거가 아닙니다.
  • 가격·뉴스 등 최신 정보는 웹 검색을 했는지 직접 물어봅니다.

7. AI 리서치를 내 이해로 바꾸기

AI가 만든 긴 보고서를 그대로 전달하면 내가 줄 가치가 없습니다. 리서치는 AI에게 많이 맡기되, 최종 문서는 빈 문서에서 AI와 한 줄씩 쓰며 이해를 확보하는 방법입니다.

  1. 에이전트를 많이 돌려 관련 자료를 모읍니다.
  2. 여러 AI로 자료를 검증해 핵심만 추립니다.
  3. AI에게 프로포절을 쓰게 하고 다시 검증합니다.
  4. 완성된 보고서는 그대로 두고 빈 문서를 새로 엽니다.
  5. 문제 정의, 해결안, 검증 등 섹션 양식을 정합니다.
  6. AI가 한 문단 쓰면 읽고 모르는 부분을 질문하며 한 줄씩 채웁니다.
  • 30장 보고서를 그대로 전달하면 내가 줄 가치가 없습니다.
  • 다 쓸 때쯤 자신이 쓴 부분은 거의 이해하게 된다고 합니다.

8. AI를 과외 선생님으로 쓰기

새 분야를 배울 때 AI에게 과외 선생님 역할을 맡겨 커리큘럼을 만들게 하고 질문을 이어 가는 방법입니다. 답을 이해하며 쓰는 것이 핵심입니다.

  1. 배우고 싶은 분야를 말합니다 (예: 에이전트 메모리).
  2. 네가 앞으로 과외 선생님으로서 나를 공부할 수 있도록 도와줘라고 요청합니다.
  3. AI가 만들어 주는 커리큘럼을 받습니다.
  4. 답변을 이해하면서 질문과 문제를 이어 갑니다.
예시
네가 앞으로 과외 선생님으로서 나를 공부할 수 있도록 도와줘. 배우고 싶은 분야는 엑셀 데이터 분석이야. 먼저 커리큘럼부터 만들어 줘.
  • 답변을 이해하지 않고 복사·붙여 넣기만 하면 실력이 늘지 않습니다.
  • 책을 읽은 뒤 AI에게 저자 역할을 시켜 질문해 볼 수 있습니다.

9. 에이전트 추천에 휘둘리지 않기

Anthropic 연구에서 분석가들은 에이전트가 기운 쪽을 86% 따랐습니다. AI가 고른 안을 그대로 받아들이지 않고 내 기준으로 결정하게 하는 방법입니다.

  1. 에이전트가 방법을 추천하기 전에 내 우선순위부터 묻게 합니다.
  2. 결정이 어려우면 작고 저렴한 모델로 여러 버전의 프로토타입을 병렬로 만듭니다.
  3. 프로토타입을 보고 내가 결정한 뒤 프로토타입은 버립니다.
  4. 결정한 내용을 에이전트에게 전달합니다.
  5. 에이전트가 고른 안(A)에 대해 "What would change your advice?"라고 묻습니다.
  6. 답을 보고 안(B)이 최적이 되는 조건이 현재 상황에 해당하는지 판단합니다.
예시
추천하기 전에 내 우선순위부터 물어봐 줘. 그리고 네가 고른 안에 대해 What would change your advice?
  • 추천 답을 그대로 선택하는 습관이 가장 쉬운 함정입니다.
  • 프로토타입은 결정용이므로 최고 모델을 쓸 필요가 없습니다.

10. 프롬프트를 확인하며 수정하기

결과물을 바로 만들지 않고 먼저 프롬프트를 확인한 뒤, 바꿀 부분과 유지할 부분을 분명히 말해 수정하는 방법입니다. 이미지·영상 생성처럼 크레딧이 드는 작업에서 낭비를 줄입니다.

  1. 이미지를 바로 만들지 말고 먼저 프롬프트를 써 달라고 요청합니다.
  2. 영어로 나온 프롬프트를 읽거나 번역기로 확인합니다.
  3. 바꿀 부분만 지정하고 나머지는 바꾸지 말라고 요청합니다.
  4. 만족하면 원하는 모델과 개수를 지정해 생성을 요청합니다.
  • 바꾸지 않을 부분을 말하지 않으면 다른 부분도 함께 바뀔 수 있습니다.
  • 큰 장면 변화가 있으면 이미지를 먼저 만든 뒤 영상으로 만드는 편이 크레딧 낭비가 적습니다.

11. Claude Code 컨텍스트 아끼기

컨텍스트는 Claude의 작업 기억이며 읽은 파일, 명령, 메시지가 모두 공간을 차지합니다. 한도에 가까워지면 자동 압축되지만 세부 내용이 사라질 수 있어 직접 관리하는 요령입니다.

  1. 같은 기능 작업을 이어갈 때는 /compact를 씁니다.
  2. 새 기능을 시작할 때는 /clear를 씁니다.
  3. 요청을 구체적으로 해서 불필요한 탐색을 줄입니다.
  4. 관련 없는 MCP 서버는 끕니다.
  5. 답만 필요한 조사는 서브에이전트에 맡깁니다.
  • MCP 서버는 기본적으로 모든 도구를 컨텍스트에 올립니다.
  • 스킬은 전체를 컨텍스트에 올리지 않아 MCP보다 가볍습니다.
  • 서브에이전트는 별도 컨텍스트 창을 쓰고 요약만 돌려줍니다.
  • 최신 모델에서는 컨텍스트를 최소한만 주고 모델이 알아서 찾게 하는 방식이 권장됩니다.

12. Claude에게 인터뷰시켜 스펙 만들기

결과를 과하게 지정하는 대신 Claude가 질문해 요구사항을 끌어내게 하는 방법입니다. 모델이 강력해질수록 제약을 줄이는 쪽이 낫습니다.

  1. Shift+Tab으로 auto mode로 전환합니다.
  2. /effort로 노력 수준을 설정합니다(권장 X high).
  3. 프롬프트에서 만들 앱의 관심 영역(예: 대상 사용자)만 주고 결과는 과하게 지정하지 않습니다.
  4. 프롬프트에 ask user question 도구를 쓰라고 명시합니다.
  5. Claude가 띄우는 질문에 차례로 답합니다.
  6. 답변이 끝나면 Claude가 작성하는 스펙을 확인합니다.
  • '더 좋게 만들어', '실수 없이 만들어' 같은 프롬프트는 피합니다.
  • 빠르게 스펙을 반복할 때는 /fast 모드가 유용합니다.
  • 실수가 나오면 다시 시키지 말고 CLAUDE.md나 스킬에 적어 같은 실수를 막습니다.

13. 작업별 모델과 노력 수준 고르기

작업 비용은 모델, effort(추론 노력), 캐시 세 가지로 정해집니다. 작업 성격에 맞는 모델과 effort로 품질을 지키면서 비용과 사용량을 줄이는 방법입니다.

  1. 작업이 열린 작업(심층 조사, 복잡한 분석)인지 반복 작업(요약, 메일 초안)인지 구분합니다.
  2. 기본은 중간 노력 수준의 Opus 5.5로 시작합니다.
  3. 결과가 부족하면 모델을 바꾸기 전에 effort를 먼저 단계적으로 올립니다.
  4. 크고 모호한 장기 작업은 Fable 5.2, 범위가 분명한 작업은 Sonnet을 씁니다.
  5. 요약·분류 같은 대량 작업은 Haiku를 씁니다.
  6. 서브에이전트는 저렴한 모델부터 적용합니다.
  • Fable은 토큰당 가격이 Opus의 두 배, Sonnet은 절반입니다.
  • 토큰 단가가 아니라 작업당 비용으로 비교합니다.
  • 여러 파일에 걸친 수정에는 effort high가 필요합니다.
  • 예전 방식: Fable 5.1을 medium으로 시작하라는 안내였으나, 최근 영상은 Opus 5.5 중간 노력 수준을 시작점으로 권합니다.

14. AI 구독 플랜 정하기

AI 구독료의 기준은 금액이 아니라 쓰다가 한도에 막히는지 여부입니다. 어떤 시점에 유료로 넘어갈지 판단하는 방법입니다.

  1. 무료로 먼저 쓰며 불편이 없으면 그대로 씁니다.
  2. 한도에 막혀 일이 끊기면 유료 플랜으로 올립니다.
  3. 쓴 만큼 돈·시간·성과가 나는지 따져 봅니다.
  4. 이미지 생성이 필요하면 ChatGPT, 코딩이 많으면 토큰이 더 싼 Claude를 고려합니다.
  5. 유료로 바꾼 뒤 한 달만 써 보고 계속할지 결정합니다.
  • 유료 플랜은 무료보다 한도가 최소 5배 이상 많다고 안내됩니다.
  • 진행자는 월 200달러 플랜 5개를 쓰지만, 입문자에게 맞는 기준은 아닙니다.
