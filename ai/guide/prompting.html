1. 구체적으로 질문해 원하는 답 얻기

AI를 처음 만난 똑똑한 친구처럼 생각하고 상황·대상·조건을 구체적으로 말하면 답의 정확도가 크게 올라갑니다. 막연한 질문 대신 내 상황을 먼저 알려 주는 습관을 들이는 첫걸음입니다.

  1. 내 상황과 대상을 구체적으로 적습니다(예: 70대 부모님과 2박 3일 서울여행, 조용하고 걷기 편한 곳).
  2. 표로 정리해 줘처럼 원하는 형식을 말합니다.
  3. 말투나 대상을 정합니다(예: 엄마가 딸에게 말하듯 따뜻하게).
  4. AI가 되묻는 질문이 있으면 하나씩 답해 줍니다.
  5. 답을 받은 뒤 이어서 질문해 내용을 고치거나 추가합니다.
  6. 지금보다 두 배로 답변해 줘, 사투리는 빼고 정중하게처럼 길이·말투를 이어서 조정합니다.
  7. 마지막에 이거 최신 내용 맞아? 출처가 어디야로 점검합니다.
예시
70대 부모님과 2박 3일 서울 여행을 가려고 해. 조용하고 걷기 편한 곳 위주로 일정을 표로 정리해 줘. 추가 정보가 필요하면 먼저 물어봐 줘.
  • 타이핑이 귀찮으면 음성 입력을 쓰고, 체크 표시 후 전송합니다.
  • 의료·법률·금융 정보는 틀릴 수 있으니 반드시 다른 자료로 재확인합니다.

2. POWER 5원칙으로 프롬프트 쓰기

프롬프트를 페르소나·아웃컴·와이(이유)·예시·제한 사항으로 나누어 쓰는 틀입니다. 막연하게 물을 때 나오는 뻔한 답을 피하고 한 번에 원하는 결과에 가깝게 얻을 수 있습니다.

  1. P(페르소나): AI에게 역할을 줍니다. 예: '너는 10년 경력의 영양사이자 개인 트레이너야'
  2. O(아웃컴): 원하는 결과를 구체적으로 씁니다. 예: 주간 식단 계획, 저녁 운동 루틴, 체크표
  3. W(왜): 필요한 이유와 내 상황·목표를 알립니다. 예: 30대 직장인, 두 달 동안 5kg 감량
  4. E(예시): 원하는 형식의 예시를 주거나 붙여 넣습니다. 없으면 생략합니다.
  5. R(제한 사항): 피할 것을 알립니다. 예: '전문 용어는 빼 줘', '200자를 넘기지 마'
  6. 작성한 내용을 한 번에 요청하고 결과를 확인합니다.
예시
너는 10년 경력의 영양사이자 개인 트레이너야. 30대 직장인이 두 달 동안 5kg을 빼려고 해. 저녁에만 운동할 수 있어. 주간 식단 계획과 저녁 운동 루틴, 진행 체크표를 만들어 줘. 전문 용어는 빼고 쉬운 말로 써 줘.
  • 다섯 가지를 모두 쓸 필요는 없고 두세 가지만 포함해도 좋습니다.
  • 예시를 구체적으로 줄수록 원하는 결과가 나올 가능성이 높습니다.
  • AI가 틀린 정보를 자신 있게 말할 수 있어 이거 정말 맞아? 다시 확인해 봐라고 되묻는 습관이 도움이 됩니다.

3. 대화로 결과를 단계적으로 다듬기

한 번에 완벽한 프롬프트를 쓰기 어려울 때, 역할 → 요청 → 수정 순으로 대화하듯 나눠 요청하는 방법입니다. 긴 글은 구조를 먼저 확정한 뒤 본문을 쓰게 하면 흐름을 통제하기 쉽습니다.

  1. 역할을 먼저 말합니다. 예: '너는 10년차 주부야'
  2. 다음 메시지에 결과물을 요청합니다. 예: 10명 집들이, 3시간 안에 끝낼 요리 5가지
  3. 마음에 들지 않는 부분은 제한 사항으로 바꿉니다. 예: '잡채는 요리하기 싫어'
  4. 긴 글은 구조를 먼저 만들어줘라고 요청하고 순서가 마음에 안 들면 바꿔 달라고 합니다.
  5. 구조가 확정되면 대본으로 만들어 줘라고 요청합니다.
  6. 마지막에 지금까지 내용을 한 번에 정리해 줘라고 요청해 최종본을 받습니다.
예시
제미나이를 주제로 유튜브 영상을 만들고 싶어. 먼저 구조만 만들어 줘. 구조가 확정되면 그때 대본으로 써 달라고 할게.
  • 분량이나 글자 수를 지정하면 결과가 더 맞게 나옵니다.
  • 이게 최적의 동선이 맞아?처럼 다시 점검을 요청해 수정할 수도 있습니다.

4. AI에게 내 맥락 알려 주기

AI는 내가 누구이고 무엇을 하는지 알수록 답이 좋아집니다. 완벽한 프롬프트보다 상황과 기준을 충분히 알려 주는 것이 핵심입니다.

  1. 내가 누구이고 무슨 작업 중인지, 좋은 결과가 어떤 것인지 알려 줍니다.
  2. 파일·캡처 같은 자료를 가능한 한 많이 함께 붙입니다.
  3. 타이핑 대신 음성 입력으로 길게 말해 상황을 풀어 줍니다.
  4. 작업별로 프로젝트를 나눠 쓰고, 새 채팅에서는 이전 내용을 가져오라고 요청합니다.
  5. 하루 30분, AI에게 질문하고 AI가 나에게도 질문하도록 유도하는 습관을 들입니다.
  6. AI의 답은 직접 읽고 판단합니다.
예시
나는 중소기업 마케팅 팀 대리야. 지금 신제품 소개 메일을 쓰고 있어. 좋은 결과는 3문단 이내에 핵심 혜택이 먼저 나오는 글이야. 필요한 정보가 있으면 먼저 나한테 물어봐 줘.
  • 음성 받아쓰기는 ChatGPT가 가장 정확하다고 소개됩니다.
  • 중요한 것은 맥락을 많이 주는 것과 결과를 판단하는 능력입니다.
  • 무료로 시작해 한도에 막힐 때 유료로 넘어가면 됩니다.

5. 반복 업무 프롬프트 저장해 쓰기

대본·이메일·보고서처럼 반복되는 작업은 역할과 지침을 한 번 저장해 두면 매번 긴 프롬프트를 쓰지 않아도 됩니다. ChatGPT의 프로젝트와 제미나이의 Gems가 대표적입니다.

  1. 반복하는 작업(예: 업무 이메일 쓰기)을 하나 정합니다.
  2. ChatGPT에서는 프로젝트를, 제미나이에서는 Gems를 새로 만듭니다.
  3. 지침에 역할·목표·형식·말투 같은 조건을 적습니다.
  4. 원하는 결과의 예시를 두세 개 붙입니다.
  5. 제미나이는 내 기존 글을 예시 파일로 주면 말투까지 분석해 지침을 만들어 줍니다.
  6. 새 채팅에서 주제만 입력해 같은 형식으로 나오는지 확인합니다.
  7. 원치 않는 표현이 나오면 '이렇게는 쓰지 마'를 지침에 추가합니다.
예시
너는 10년차 비서야. 내가 주제를 주면 정중하고 간결한 업무 이메일을 써 줘. 제목, 본문 3문단 이내, 마무리 인사 순서로 쓰고, 지나치게 격식 있는 표현은 쓰지 마.
  • 예시 없이 묻는 제로샷보다 예시를 주는 퓨샷이 원하는 결과에 가깝습니다.
  • ChatGPT 프로젝트는 유료 버전에서 쓸 수 있고, Gems는 무료 계정으로도 만들 수 있습니다.

6. 영어 메일 현지 직원처럼 쓰기

번역기는 문장만 바꾸지만 맥락을 알려 주면 현지 직원이 쓴 듯한 영어 메일이 나옵니다. 해외 거래처에 보내는 메일의 톤을 맞출 때 씁니다.

  1. 받는 사람의 직급을 프롬프트에 적습니다.
  2. 나와 받는 사람의 관계를 적습니다.
  3. 메일이 끝난 뒤 무엇이 일어나야 하는지를 적습니다.
  4. 전달할 핵심 내용과 함께 요청합니다.
예시
받는 사람은 거래처 부사장이고, 우리는 3년째 거래 중이야. 이 메일이 끝나면 다음 주까지 견적서 회신을 받아야 해. 현지 직원이 쓴 것처럼 자연스러운 영어 메일을 써 줘. 내용: 납기 일주일 연장 요청.
  • 번역기는 문장을 바꾸고, 현지 직원은 맥락을 바꾼다는 점을 기억하세요.

7. AI 답변 검증하며 쓰기

AI는 그럴듯하지만 사실이 아닌 내용(환각)을 만들거나 내가 듣고 싶은 말에 맞추는 경향(아첨)이 있습니다. 질문의 중요도에 따라 확인 강도를 조절하는 방법입니다.

  1. 틀렸을 때 어떤 일이 생기는지 스스로 묻고 확인 강도를 정합니다.
  2. 미리 모르면 모른다고 말해 달라고 알려 줍니다.
  3. AI에게 주장마다 근거가 되는 출처를 요청합니다.
  4. 제시된 출처를 직접 열어 실제로 그 내용이 있는지 확인합니다.
  5. 원하는 답을 흘리지 말고 이 결정에 대한 가장 강력한 찬성과 반대 논거는 무엇인가요?처럼 중립적으로 질문합니다.
  6. 의심스러우면 얼마나 확신하는지, 틀릴 만한 부분이 있는지 묻습니다.
  7. 새 대화를 열어 그 답변의 오류를 찾고 출처가 맞는지 확인해 달라고 합니다.
예시
아래 답변에서 주장마다 근거가 되는 출처를 찾아 줘. 확실하지 않은 부분은 모른다고 말해도 괜찮아. 틀릴 가능성이 있는 부분도 알려 줘.
  • 숫자·날짜·인용·최신 사건은 특히 다시 확인합니다.
  • AI가 실제로 없는 출처를 그럴듯하게 만들어 낼 수도 있습니다.
  • 깔끔한 문단이나 자신 있는 말투가 정확성의 증거는 아닙니다.
  • 회사 일에 쓰기 전 Settings의 Data controls에서 Improve the model for everyone을 끄고, 개인정보·기밀은 입력하지 않습니다.

8. AI 조언에 휘둘리지 않고 결정하기

Anthropic 연구에서 분석가들은 에이전트가 기운 쪽을 86% 따랐고, 스스로 결정했다고 착각하기 쉬웠습니다. AI의 추천을 그대로 고르는 함정을 피하는 방법입니다.

  1. AI가 방법을 추천하기 전에 내 우선순위부터 묻게 합니다.
  2. 결정이 어려우면 작고 저렴한 모델로 여러 버전의 프로토타입을 병렬로 만들게 합니다.
  3. 프로토타입을 보고 내가 결정한 뒤 프로토타입은 버립니다.
  4. 결정한 내용을 AI에게 전달합니다.
  5. AI가 고른 안(A)에 대해 What would change your advice?라고 묻습니다.
  6. 답을 보고 다른 안(B)이 최적이 되는 조건이 현재 상황에 해당하는지 판단합니다.
예시
추천안을 말하기 전에, 내 우선순위가 무엇인지 먼저 질문해 줘.
  • 추천 답을 그대로 선택하는 습관이 가장 쉬운 함정입니다.
  • 프로토타입은 결정용이므로 최고 모델을 쓸 필요가 없습니다.

9. AI 결과를 내 이해로 바꾸기

AI 답을 복사해 전달만 하는 상태는 누구나 할 수 있어 가치가 낮습니다. 리서치는 AI에 맡기되 문서는 한 줄씩 질문하며 함께 써서 내용을 내 것으로 만드는 방법입니다.

  1. 에이전트를 많이 돌려 관련 자료를 모읍니다.
  2. 여러 AI로 자료를 검증해 핵심만 추립니다.
  3. AI에게 프로포절을 쓰게 하고 다시 검증합니다.
  4. 완성된 보고서는 그대로 두고 빈 문서를 새로 엽니다.
  5. 문제 정의, 해결안, 검증 등 섹션 양식을 정합니다.
  6. AI가 한 문단 쓰면 읽고 모르는 부분을 질문하며 한 줄씩 채웁니다.
예시
빈 문서에서 제안서를 같이 쓰자. 섹션은 문제 정의, 해결안, 검증 세 개야. 한 번에 한 문단만 쓰고, 내가 질문하면 이유를 설명해 줘.
  • 30장 보고서를 그대로 전달하면 내가 줄 가치가 없습니다.
  • 다 쓸 때쯤이면 자신이 쓴 부분은 거의 이해하게 된다고 합니다.

10. AI를 과외 선생님으로 쓰기

새 분야를 배울 때 AI에게 과외 선생님 역할을 맡겨 커리큘럼을 만들게 하는 방법입니다. 답을 복사만 하지 않고 이해하며 이어 가는 것이 핵심입니다.

  1. 배우고 싶은 분야를 말합니다(예: 에이전트 메모리).
  2. 네가 앞으로 과외 선생님으로서 나를 공부할 수 있도록 도와줘라고 요청합니다.
  3. AI가 만들어 주는 커리큘럼을 받습니다.
  4. 답변을 이해하면서 질문과 문제를 이어 갑니다.
예시
네가 앞으로 과외 선생님으로서 나를 공부할 수 있도록 도와줘. 배우고 싶은 분야는 재무제표 읽기야. 커리큘럼부터 만들어 줘.
  • 답변을 이해하지 않고 복사·붙여 넣기만 하면 실력이 늘지 않습니다.
  • 책을 읽은 뒤 AI에게 저자 역할을 시켜 질문해 볼 수 있습니다.
  • AI가 거꾸로 질문하게 하려면 이걸 너한테 맡기려면 내가 뭘 알려주면 되는지 먼저 물어봐 줘라고 요청합니다.

11. 음성으로 말해 프롬프트 다듬기

음성 입력 도구 Typeless로 두서없이 말한 내용을 정리된 문장으로 입력하고, 이를 더 잘 알아듣는 프롬프트로 다듬는 방법입니다. 긴 맥락을 빠르게 전달할 때 유용합니다.

  1. Typeless로 두서없이 하고 싶은 요청을 말해 입력합니다.
  2. 입력된 문장을 드래그로 선택합니다.
  3. Ask Anything 단축키를 누릅니다.
  4. 무엇이든 물어보세요 칸에 '더 잘 알아듣는 프롬프트로 다듬어 줘. 타겟·톤·결과물 형식을 구체적으로 넣어 줘'라고 말합니다.
  5. 약 3초 후 나온 프롬프트를 필요하면 고쳐서 AI에 입력합니다.
예시
더 잘 알아듣는 프롬프트로 다듬어 줘. 타겟·톤·결과물 형식을 구체적으로 넣어 줘.
  • 같은 방식으로 '더 짧게', '더 친근하게' 같은 수정도 요청할 수 있습니다.
  • 무료 사용량은 주당 8,000단어이고 전문 용어는 가끔 틀릴 수 있어, 개인 사전에 등록하면 인식률이 올라갑니다.

12. 작업별 모델과 노력 수준 고르기

작업 비용은 모델, effort(추론 노력), 캐시로 정해집니다. 작업 성격에 맞춰 모델과 노력 수준을 고르면 품질은 지키면서 한도와 비용을 아낄 수 있습니다.

  1. 작업이 열린 작업(심층 조사, 복잡한 분석, 장시간 에이전트)인지 반복 작업(요약, 메일 초안, 데이터 추출)인지 구분합니다.
  2. 기본 시작점으로 중간(medium) 노력 수준의 Opus 5.5를 고릅니다.
  3. 결과가 부족하면 모델을 바꾸기 전에 노력 수준을 먼저 올립니다.
  4. 크고 모호한 장기 작업은 Fable, 범위가 분명한 작업은 Sonnet, 요약·분류 같은 대량 작업은 Haiku를 고릅니다.
  5. 여러 파일에 걸친 수정에는 high를 씁니다.
  6. 서브에이전트는 탐색 같은 특정 작업만 맡으므로 저렴한 모델부터 적용합니다.
  • 토큰 단가가 아니라 작업당 비용으로 비교합니다. 더 똑똑한 모델이 적은 단계로 끝내 총비용이 낮을 수 있습니다.
  • Fable은 토큰당 가격이 Opus의 두 배이고, Sonnet은 Opus보다 빠르며 가격이 절반입니다.
  • 가용성과 사용 한도는 요금제마다 다릅니다.
  • 예전 방식: 9월 영상에서는 열린 작업에 Fable 5.1을 medium으로 시작하라고 했으나, 11월 영상은 Opus 5.5 중간 노력을 기본으로 권합니다.

13. 컨텍스트 아끼며 Claude Code 쓰기

컨텍스트는 Claude의 작업 기억으로, 읽은 파일·명령·메시지가 모두 공간을 차지합니다. 한도에 가까워지면 자동 압축되며 세부 내용이 사라질 수 있어 직접 관리하면 품질을 지킬 수 있습니다.

  1. 같은 기능 작업을 이어갈 때는 /compact로 대화를 압축합니다.
  2. 새 기능을 시작할 때는 /clear로 컨텍스트를 비웁니다.
  3. 요청은 구체적으로 해서 불필요한 파일 탐색을 줄입니다.
  4. 관련 없는 MCP 서버는 끕니다.
  5. 답만 필요한 조사는 서브에이전트에 맡깁니다.
  6. 같은 실수가 반복되면 다시 시키지 말고 CLAUDE.md나 스킬에 적어 둡니다.
  • MCP 서버는 기본적으로 모든 도구를 컨텍스트에 올립니다. 스킬은 필요할 때만 불러와 컨텍스트를 아낍니다.
  • 서브에이전트는 별도 컨텍스트 창을 쓰고 요약만 돌려줍니다.
  • 최신 모델에서는 컨텍스트를 최소한만 주고 모델이 알아서 찾게 하는 방식이 권장됩니다.
