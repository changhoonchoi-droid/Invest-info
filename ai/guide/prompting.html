프롬프트·활용 요령

이 페이지는 AI에게 질문하는 기본기, 맥락 주는 법, 답변 검증, 컨텍스트와 비용 관리까지 다룹니다. 앞의 1~6번은 ChatGPT·Gemini·Claude 어디서나 쓸 수 있는 기본기이고, 7번 이후는 구독료·모델 선택·컨텍스트처럼 쓰는 양이 늘 때 필요한 내용입니다. 순서대로 따라 하되, 이미 익숙한 부분은 건너뛰어도 됩니다.

1. 구체적으로 질문해 원하는 답 얻기

AI는 처음 만난 똑똑한 친구처럼, 상황을 구체적으로 알려 줄수록 정확한 답을 줍니다. 막연한 질문에서 벗어나 상황·형식·말투를 정해 묻고, 이어서 고쳐 가는 방법입니다.

  1. 내 상황과 대상을 먼저 적습니다 (예: 70대 부모님과 2박 3일 서울 여행, 조용하고 걷기 편한 곳).
  2. 원하는 결과를 한 번에 요청합니다 (추천, 방법, 주의점 등).
  3. 표로 정리해 줘처럼 원하는 형식을 말합니다.
  4. 말투나 대상을 정합니다 (예: 엄마가 딸에게 말하듯 따뜻하게).
  5. AI가 되묻는 질문이 있으면 답해 줍니다.
  6. 받은 답에 이어서 지금보다 두 배로 길게, 사투리는 빼고 정중하게처럼 고쳐 달라고 합니다.
  7. 마지막에 이거 최신 내용 맞아? 출처가 어디야로 점검합니다.
예시
70대 부모님과 2박 3일 서울 여행을 가려고 해. 조용하고 걷기 편한 곳 위주로 일정을 표로 정리해 줘. 말투는 딸이 부모님께 설명하듯 따뜻하게 써 줘.
  • 타이핑이 번거로우면 음성 입력을 쓸 수 있습니다. 말한 뒤 확인 표시를 누르고 전송합니다.
  • 의료·법률·금융 정보는 틀릴 수 있으니 참고용으로만 쓰고 다른 자료로 확인합니다.
  • 예전 방식: 처음부터 한 번에 완벽한 질문을 쓰려 했지만, 지금은 대화하듯 나눠 요청해도 됩니다.

2. POWER 5원칙으로 프롬프트 쓰기

페르소나·아웃컴·와이(이유)·예시·제한 사항의 앞글자를 딴 프롬프트 작성 틀입니다. '다이어트 방법 알려 줘' 같은 막연한 질문 대신 이 틀을 쓰면 한 번에 쓸 만한 답을 얻기 쉽습니다.

  1. P(페르소나): AI에게 역할을 줍니다. 예: 너는 10년 경력의 영양사이자 개인 트레이너야.
  2. O(아웃컴): 원하는 결과를 구체적으로 씁니다. 예: 주간 식단 계획, 저녁 운동 루틴, 진행 체크표.
  3. W(왜): 필요한 이유와 내 상황·목표를 알립니다. 예: 30대 직장인, 두 달 동안 5kg 감량, 저녁에만 운동 가능.
  4. E(예시): 원하는 형식의 예시를 붙여 줍니다. 없으면 생략합니다.
  5. R(제한 사항): 피할 것을 알립니다. 예: 전문 용어는 빼 줘, 200자를 넘기지 마.
  6. 한 번에 요청하고 결과를 확인합니다.
  7. 마음에 들지 않으면 제한 사항을 바꾸거나 지금까지 내용을 한 번에 정리해 줘로 최종본을 받습니다.
예시
너는 10년 경력의 영양사이자 개인 트레이너야. 30대 직장인이 두 달 동안 5kg을 빼려고 해. 저녁에만 운동할 수 있어. 주간 식단 계획과 저녁 운동 루틴, 진행 체크표를 만들어 줘. 전문 용어는 빼고 쉬운 말로 써 줘. 추가 정보가 필요하면 먼저 물어봐.
  • 다섯 가지를 모두 쓸 필요는 없고 두세 가지만 포함해도 좋습니다.
  • 예시를 구체적으로 줄수록 원하는 결과에 가깝습니다. 예시 없이 묻는 것을 제로샷, 예시를 주는 것을 퓨샷이라 합니다.
  • 결과가 아쉬우면 이게 최적이 맞아?처럼 다시 점검을 요청합니다.
  • 원치 않는 표현은 이렇게는 쓰지 마라고 추가합니다.

3. AI에게 나의 맥락 알려 주기

AI를 잘 쓰는 핵심은 완벽한 프롬프트보다 나의 상황과 기준을 충분히 알려 주는 것입니다. 맥락을 쌓는 습관과, 회사 일에 쓰기 전에 꼭 해야 할 설정을 함께 다룹니다.

  1. AI에게 내가 누구이고 무슨 일을 하는지, 이번 작업의 목적이 무엇인지 알려 줍니다.
  2. 관련 파일이나 화면 캡처를 많이 붙여 넣습니다.
  3. 회사 일에 쓰기 전에 ChatGPT 설정(Settings)의 Data controls로 들어갑니다.
  4. Improve the model for everyone 항목을 끕니다.
  5. 하루 30분 정도 AI에게 질문하고, AI가 나에게도 질문하도록 유도하는 습관을 들입니다.
  6. 무료로 시작해 한도에 막힐 때 유료로 넘어갑니다.
예시
나는 중견 제조사 영업팀 3년 차 대리야. 이번 주 금요일 팀장님께 올릴 분기 실적 보고서를 쓰려고 해. 필요한 정보가 있으면 내게 먼저 질문해 줘.
  • 개인정보와 기밀 정보는 입력하지 않습니다.
  • 영어 메일은 받는 사람의 직급, 나와의 관계, 메일 뒤에 일어나야 할 일을 적으면 번역기보다 현지 직원 같은 메일이 나옵니다.
  • AI가 쓴 결과는 직접 읽고 판단합니다. 맥락을 많이 줘도 검증은 내 몫입니다.

4. 말로 입력해 프롬프트 다듬기

길게 설명할수록 AI가 잘 알아듣지만 타이핑은 번거롭습니다. 음성 입력 도구로 두서없이 말한 뒤, AI로 프롬프트를 다듬는 방법입니다.

  1. Typeless 같은 음성 입력 도구로 하고 싶은 요청을 두서없이 말해 입력합니다.
  2. 입력된 문장을 드래그로 선택합니다.
  3. Ask Anything 단축키를 누릅니다.
  4. 무엇이든 물어보세요 칸에 더 잘 알아듣는 프롬프트로 다듬어 달라고, 타겟·톤·결과물 형식을 구체적으로 넣어 달라고 말합니다.
  5. 약 3초 뒤 나온 프롬프트를 필요하면 고칩니다.
  6. 고친 프롬프트를 AI에 입력합니다.
예시
더 잘 알아듣는 프롬프트로 다듬어 줘. 타겟·톤·결과물 형식을 구체적으로 넣어 줘.
  • 더 짧게, 더 친근하게 같은 수정도 같은 방식으로 요청할 수 있습니다.
  • Typeless 무료 사용량은 주당 8,000단어이고, 전문 용어는 가끔 틀릴 수 있습니다.
  • 개인 사전에 전문 용어를 등록하면 인식률을 높일 수 있습니다.
  • ChatGPT에도 음성 입력이 있고, 받아쓰기 정확도가 가장 좋다는 평가가 있습니다.

5. 반복 업무 프롬프트를 저장해 쓰기

대본, 이메일, 보고서처럼 매번 비슷한 요청을 한다면 지침과 예시를 한 번 저장해 두고 주제만 넣으면 됩니다. ChatGPT의 프로젝트와 제미나이의 Gems가 이런 기능입니다.

  1. 반복하는 작업 하나를 정합니다 (예: 업무 이메일 쓰기).
  2. ChatGPT에서는 프로젝트를, 제미나이에서는 Gems를 새로 만듭니다.
  3. 역할, 목표, 형식, 말투 같은 지침을 적습니다. 직접 쓰거나 AI에게 만들어 달라고 해도 됩니다.
  4. 원하는 결과의 예시를 두세 개 붙입니다. 내가 쓴 기존 글을 파일로 주면 말투까지 분석해 지침을 만들어 줍니다.
  5. 새 채팅에서 주제만 입력해 같은 형식으로 나오는지 확인합니다.
  6. 마음에 들지 않는 표현은 이렇게는 쓰지 마로 지침에 추가합니다.
  • ChatGPT 프로젝트는 유료 버전에서 쓸 수 있고, 제미나이 Gems는 무료 계정으로도 만들 수 있습니다.
  • 보고서 형식은 스킬이나 메모리로 굳혀 두면 매번 같은 포맷이 나옵니다.
  • 긴 글은 구조를 먼저 만들게 한 뒤 대본으로 만들어 달라고 단계별로 요청하면 더 잘 나옵니다.

6. AI 답변 검증하며 쓰기

AI는 그럴듯하지만 사실이 아닌 내용(환각)을 만들거나, 내가 듣고 싶은 말에 맞춰 동의(아첨)할 수 있습니다. 질문의 중요도에 따라 확인 강도를 조절하는 방법입니다.

  1. 틀렸을 때 어떤 일이 생기는지 스스로 묻고 확인 강도를 정합니다.
  2. 미리 모르면 모른다고 해도 괜찮다고 알려 줍니다.
  3. 주장마다 근거가 되는 출처를 요청합니다.
  4. 제시된 출처를 직접 열어 그 내용이 실제로 있는지 확인합니다.
  5. 원하는 답을 흘리지 말고 이 결정에 대한 가장 강력한 찬성과 반대 논거는 무엇인가요?처럼 중립적으로 묻습니다.
  6. 의심스러우면 얼마나 확신하는지, 틀릴 만한 부분이 있는지 묻습니다.
  7. 중요한 작업은 새 대화를 열어 오류를 찾게 하거나 다른 AI로 교차 검증합니다.
예시
이 결정에 대한 가장 강력한 찬성 논거와 반대 논거는 무엇인가요? 모르는 부분은 모른다고 말해도 괜찮고, 주장마다 근거 출처를 붙여 줘.
  • 숫자·날짜·인용·최근 사건·마이너한 주제는 특히 틀리기 쉽습니다.
  • AI가 없는 출처를 그럴듯하게 만들어 낼 수도 있어 링크를 직접 열어야 합니다.
  • 깔끔한 문단이나 자신 있는 말투는 정확성의 증거가 아닙니다.
  • 브레인스토밍은 느슨하게 써도 되지만 상사에게 보일 통계는 반드시 검증합니다.

7. AI 구독료, 한도 기준으로 정하기

AI 구독은 금액보다 쓰다가 한도에 막히는지가 기준입니다. 무료로 시작해 필요할 때만 올리는 판단 순서를 정리합니다.

  1. 무료 플랜으로 업무에 써 봅니다.
  2. 불편 없이 쓰면 무료를 계속 씁니다.
  3. 한도에 막혀 일이 끊기면 한 단계 위 플랜으로 올립니다.
  4. 쓴 만큼 돈·시간·성과가 나는지 따져 봅니다.
  5. 이미지 생성이 필요하면 ChatGPT, 코딩이 많으면 토큰이 더 싼 Claude를 고려합니다.
  6. 유료를 쓸 때는 한 달만 써 보고 계속할지 결정합니다.
  • 강의에서 진행자는 월 200달러 플랜을 여러 개 쓰지만, 이는 일반 직장인의 기준이 아니라 본인 작업량 기준입니다.
  • 무료 버전은 이미지 생성이 하루 3개까지로 제한된 경우가 있습니다.

8. AI 답을 내 이해로 바꿔 쓰기

AI 결과를 복사해 전달만 하면 누구나 할 수 있는 일이라 내 가치가 없습니다. AI를 과외 선생님처럼 쓰고, 빈 문서에서 한 줄씩 써 가며 내용을 이해하는 방법입니다.

  1. 배우고 싶은 분야를 말합니다.
  2. 네가 앞으로 과외 선생님으로서 나를 공부할 수 있도록 도와줘라고 요청합니다.
  3. AI가 만들어 주는 커리큘럼을 받습니다.
  4. 답변을 이해하면서 질문과 문제를 이어 갑니다.
  5. 보고서나 제안서가 필요하면 먼저 AI로 자료를 모으고 여러 AI로 검증해 핵심만 추립니다.
  6. 완성된 보고서는 두고 빈 문서를 새로 열어 문제 정의, 해결안, 검증 같은 섹션 양식을 정합니다.
  7. AI가 한 문단 쓰면 읽고 모르는 부분을 질문하며 한 줄씩 채웁니다.
예시
네가 앞으로 과외 선생님으로서 내가 에이전트 메모리를 공부할 수 있도록 도와줘. 먼저 커리큘럼부터 만들어 줘.
  • 답변을 이해하지 않고 복사·붙여 넣기만 하면 실력이 늘지 않습니다.
  • 30장 보고서를 그대로 전달하면 내가 줄 수 있는 가치가 없습니다.
  • 책을 읽은 뒤 AI에게 저자 역할을 시켜 질문해 볼 수도 있습니다.
  • 다 쓸 때쯤이면 내가 쓴 부분은 거의 이해하게 된다고 합니다.

9. AI 에이전트에 휘둘리지 않고 결정하기

Anthropic 연구에서 분석가들은 에이전트가 기운 쪽을 86% 따랐고, 자기 의견이 있던 사람도 에이전트가 반대하면 60%가 바꿨습니다. 에이전트의 추천에 끌려가지 않고 내 기준으로 결정하는 방법입니다.

  1. 에이전트가 방법을 추천하기 전에 내 우선순위부터 묻게 합니다.
  2. 결정이 어려우면 작고 저렴한 모델로 여러 버전의 프로토타입을 병렬로 만듭니다.
  3. 프로토타입을 보고 내가 결정한 뒤 프로토타입은 버립니다.
  4. 결정한 내용을 에이전트에게 전달합니다.
  5. 에이전트가 고른 안(A)에 대해 What would change your advice?라고 묻습니다.
  6. 답을 보고 다른 안(B)이 최적이 되는 조건이 지금 상황에 해당하는지 판단합니다.
예시
추천하기 전에 내 우선순위부터 질문해 줘. 그리고 네가 고른 안에 대해 What would change your advice?
  • 추천 답을 그대로 선택하는 습관이 가장 쉬운 함정입니다.
  • 프로토타입은 결정용이라 최고 모델을 쓸 필요가 없습니다.
  • 이 연구는 한 분야·한 과제·한 모델만 다뤘다는 한계가 있습니다.

10. Claude Code 컨텍스트 아껴 쓰기

컨텍스트는 Claude의 작업 기억으로, 읽은 파일, 실행한 명령, 주고받은 메시지가 모두 공간을 차지합니다. 한도에 가까워지면 자동 압축되지만 세부 내용이 사라질 수 있어 직접 관리하는 요령이 필요합니다.

  1. 같은 기능 작업을 이어갈 때는 /compact로 대화를 압축합니다.
  2. 새 기능을 시작할 때는 /clear로 컨텍스트를 비웁니다.
  3. 요청은 구체적으로 해서 불필요한 탐색을 줄입니다.
  4. 관련 없는 MCP 서버는 끕니다. MCP 서버는 기본적으로 모든 도구를 컨텍스트에 올립니다.
  5. 답만 필요한 조사는 서브에이전트에 맡깁니다. 서브에이전트는 별도 컨텍스트 창을 쓰고 요약만 돌려줍니다.
  6. 같은 실수가 반복되면 다시 시키지 말고 CLAUDE.md나 스킬에 규칙으로 적어 둡니다.
  • 스킬은 MCP와 비슷하지만 전체를 컨텍스트에 올리지 않고, 요청이 맞을 때만 불러옵니다.
  • 최신 모델에서는 최소한의 지침과 도구만 주고 필요한 컨텍스트는 Claude가 찾게 하는 방식이 권장됩니다.
  • API를 쓴다면 프롬프트 캐싱으로 비용을 줄일 수 있습니다.

11. 작업별로 모델과 노력 수준 고르기

작업 비용은 모델, effort(추론 노력), 캐시가 정합니다. 무조건 비싼 모델을 쓰지 않고, 작업 성격에 맞게 고르면 사용 한도와 비용을 아낄 수 있습니다.

  1. 기본으로 중간 노력 수준(medium)의 Opus 5.5에서 시작합니다.
  2. 결과가 부족하면 모델을 바꾸기 전에 먼저 /effort로 노력 수준을 올립니다.
  3. 여러 파일에 걸친 수정이나 프로젝트 전체를 바꾸는 작업에는 high를 씁니다.
  4. 크고 모호한 장기 작업은 Fable, 범위가 분명한 작업은 Sonnet을 씁니다.
  5. 요약·분류 같은 대량 작업은 Haiku를 씁니다.
  6. 파일 탐색만 하는 서브에이전트에는 작은 모델을 지정합니다.
  7. 토큰 단가가 아니라 작업 하나당 비용으로 비교합니다.
  • Fable은 토큰당 가격이 Opus의 두 배이고, Sonnet은 Opus보다 빠르고 가격이 절반입니다.
  • Opus 5.5는 Opus 5보다 토큰당 20% 저렴하고, Pro·Max·Team 요금제 한도는 25% 더 갑니다.
  • /claude-api prompt-audit로 CLAUDE.md와 스킬 지침을 Opus 5.5에 맞게 다듬을 수 있습니다.
  • 예전 방식: 9월 영상에서는 열린 작업에 Fable 5.1을 medium으로 시작하라고 했지만, 11월 영상은 Opus 5.5를 기본 시작점으로 안내합니다.
  • 가용성과 사용 한도는 요금제마다 다릅니다.

12. 평가로 프롬프트와 모델 개선하기

프롬프트를 고칠 때 느낌에 의존하면 한 곳을 고치다 다른 곳이 망가져도 모릅니다. 작은 테스트 세트(평가)를 만들어 고치기 전후를 비교하는 방법입니다.

  1. 입력과 성공 기준을 가진 테스트 작업을 모읍니다. 통제 사례, 이전에 실패한 엣지 케이스, 사람에게 넘기거나 거절해야 할 사례를 포함합니다.
  2. 예시가 한두 개뿐이면 Claude에게 상황을 설명하고 더 늘려 달라고 요청합니다.
  3. 현재 프롬프트로 평가를 돌려 실패 유형을 확인합니다.
  4. 사실과 다른 역할 설명과 불필요하게 복사된 내용을 지웁니다.
  5. XML 태그로 역할·가이드라인·정책·말투를 구분하고 출력 형식도 명시합니다.
  6. 평가를 다시 돌려 실패 유형을 하나씩 고치며 결과를 비교합니다.
  7. 모델이나 effort를 바꿀 때도 같은 평가로 통과율, 토큰, 비용, 지연 시간을 비교합니다.
예시
내가 만들려는 고객 문의 답변 봇의 상황은 이렇고, 테스트 케이스 예시는 아래 두 개야. 비슷한 형식으로 테스트 케이스를 50개로 늘려 줘.
  • 공개 벤치마크는 방향만 알려 주므로 내 용도의 작은 평가가 더 중요합니다.
  • 실행마다 편차가 있으니 한 번의 결과로 단정하지 않습니다.
  • 평가를 모델이 채점할 때도 틀릴 수 있어 코드 기반 검사와 함께 씁니다.
  • 토큰당 가장 싼 모델이 아니라 성공 한 건당 가장 싼 모델을 고릅니다.
  • 금지 항목을 길게 나열하는 방식은 피합니다.
