프롬프트·활용 요령

이 분야에서는 AI에게 원하는 답을 받아 내는 질문법, 답을 믿어도 되는지 확인하는 법, 작업에 맞는 모델과 노력 수준(effort)을 골라 비용을 줄이는 법을 배웁니다. 처음이라면 '더 나은 답 얻기'와 '답변 검증하기'부터 익히세요. 그다음 모델·effort 고르기와 CLAUDE.md 다듬기로 비용과 품질을 함께 관리하고, 마지막으로 내 사용 습관에 맞춘 모드 추천으로 넘어가면 됩니다.

프롬프트 작성법, 컨텍스트 관리, 결과 품질 높이기, 비용·사용량 관리 · 영상 11개 기반 · 2026-10-22 갱신

최근 바뀐 점

  • Claude Code의 작업 환경 자체를 바꾸는 '모드(Mods)'가 2026년 10월 1일 공식 발표되었고, 세션 로그를 바탕으로 나에게 맞는 모드를 추천받을 수 있습니다.
  • Opus 5.5는 Opus 5보다 토큰당 20% 저렴하고 Pro·Max·Team 요금제에서 한도가 25% 더 늘어나, 작업 하나당 비용이 약 40% 낮습니다.
  • Opus 5.5의 기본 effort는 medium이며, 여러 파일이나 프로젝트 전체를 고치는 작업에만 high를 쓰면 됩니다.
  • Claude Code에서 /claude-api prompt-audit를 실행하면 CLAUDE.md와 스킬 지침이 Opus 5.5에 맞게 조정됩니다.

1. AI에게 더 나은 답 얻기

AI는 내 메시지, 올린 문서, 대화 기록을 모두 참고해서 답을 새로 써 냅니다. 그래서 상황을 자세히 알려 주고 여러 버전을 받아 볼수록 결과가 좋아집니다. 메일 초안이나 보고서 문장처럼 결과물을 다듬어야 할 때 씁니다.

  1. 내가 누구인지, 지금 무슨 작업을 하는지 첫 메시지에 적습니다.
  2. 좋은 결과가 어떤 모습인지(분량, 어조, 형식)를 함께 적습니다.
  3. 가격이나 뉴스 같은 최신 정보가 필요하면 웹 검색을 해 달라고 요청합니다.
  4. 검색했다면 AI가 제시한 출처를 열어 내용이 맞는지 확인합니다.
  5. 초안을 여러 버전으로 받거나 다른 어조로 다시 써 달라고 요청합니다.
  6. 틀리면 곤란한 사실은 직접 다시 확인합니다.
예시
저는 마케팅팀 대리이고, 다음 주 거래처 미팅 일정을 조율하는 메일을 쓰려고 합니다. 정중하지만 간결한 어조로, 5문장 이내 초안을 서로 다른 버전으로 3개 써 주세요.
  • AI는 훈련 시점 이후의 사실을 검색 없이는 확실히 알지 못합니다. 웹 검색을 했다고 단정하지 말고 직접 물어보세요.
  • 정해진 답을 꺼내는 게 아니라 그때그때 새로 쓰기 때문에, 같은 요청으로도 여러 버전을 받을 수 있습니다.
  • 말투가 자신 있거나 결과물이 깔끔하다고 해서 내용이 정확하다는 뜻은 아닙니다.

2. AI 답변 검증하며 쓰기

AI는 그럴듯하지만 사실이 아닌 내용을 지어내기도 하고(환각), 사용자가 듣고 싶은 말에 맞춰 동의하기도 합니다(아첨). 질문이 얼마나 중요한지에 따라 확인 강도를 조절하는 방법입니다. 숫자·출처·건강·법률·금전과 관련된 답에는 꼭 씁니다.

  1. 이 답이 틀리면 어떤 일이 생기는지 스스로 묻고 확인 강도를 정합니다.
  2. 질문하기 전에 모르면 모른다고 말해 달라고 미리 알려 둡니다.
  3. 원하는 답을 흘리지 말고 중립적으로 질문합니다.
  4. AI에게 답의 근거가 된 출처를 요청합니다.
  5. 제시된 출처를 직접 열어 그 내용이 실제로 있는지 확인합니다.
예시
이 결정에 대한 가장 강력한 찬성과 반대 논거는 무엇인가요? 확실하지 않은 부분은 모른다고 말해 주시고, 근거가 된 출처도 함께 알려 주세요.
  • 파티 주제 브레인스토밍은 크게 검증할 필요가 없지만, 상사에게 보여 줄 슬라이드의 통계는 반드시 검증합니다.
  • 잘 알려진 주제는 비교적 정확하지만, 세부 사항·최근 사건·비공개 정보는 틀리거나 지어낼 가능성이 높습니다.
  • AI가 실제로 없는 출처를 그럴듯하게 만들어 낼 수도 있으니 링크를 꼭 열어 보세요.
  • 법률처럼 판단이 중요한 업무는 AI가 자료를 정리하더라도 최종 판단과 검토는 사람이 맡습니다.

3. 음성 메모로 발표 자료 만들기

빈 슬라이드 앞에서 막막할 때, 하고 싶은 말을 먼저 말로 녹음해 두고 그 내용을 Claude에게 넘겨 발표 자료로 만드는 방법입니다. 폰트나 템플릿 같은 서식 작업을 줄이고 내용에 집중하고 싶을 때 좋습니다.

  1. 산책하거나 이동하면서 휴대폰 음성 메모로 하고 싶은 말을 모두 녹음합니다.
  2. 녹음을 받아 적은 글을 준비합니다.
  3. 받아 적은 글을 Claude에게 보내고 발표 자료로 만들어 달라고 요청합니다.
  4. 결과물에서 작은 부분은 직접 고칩니다.
  5. 큰 수정이 필요한 부분은 댓글로 Claude에게 요청합니다.
예시
아래는 제가 음성 메모로 녹음한 내용을 받아 적은 글입니다. 이 내용을 바탕으로 발표 자료를 만들어 주세요.
  • 영상에서는 Claude가 회사 브랜드 스타일을 이미 알고 있어서 폰트나 템플릿을 찾을 필요가 없었습니다.
  • 말로 먼저 풀어 놓으면 서식보다 아이디어 자체에 시간을 쓸 수 있습니다.

4. 작업에 맞는 모델과 effort 고르기

작업 비용은 모델, effort(추론 노력), 캐시 세 가지로 정해집니다. 작업 종류에 맞춰 모델과 effort를 고르면 품질은 지키면서 비용과 사용 한도를 아낄 수 있습니다.

  1. 할 일이 열린 작업(심층 조사, 복잡한 분석, 오래 걸리는 에이전트 작업)인지 반복 작업(문서 요약, 메일 초안, 보고서 데이터 추출)인지 구분합니다.
  2. 반복 작업이면 Opus나 Sonnet을 기본으로 씁니다.
  3. 열린 작업이면 Fable 5.1을 고르고 effort를 medium으로 시작합니다.
  4. 결과가 부족하면 effort를 한 단계씩 올립니다.
  5. 여러 파일이나 프로젝트 전체를 고치는 작업에는 effort를 high로 올립니다.
  6. 탐색처럼 정해진 일만 하는 서브에이전트는 저렴한 작은 모델부터 적용합니다.
  • 토큰 단가가 아니라 작업 하나당 비용으로 비교하세요. 더 똑똑한 모델은 적은 단계로 끝내서 총비용이 오히려 낮을 수 있습니다.
  • Opus 5.5는 Opus 5보다 토큰당 20% 저렴하고 같은 버그 수정에서 약 30% 빨랐으며, 기본 effort medium이면 대부분의 작업에 충분합니다.
  • Fable 5.1은 Fable 5와 토큰 단가는 같지만 캐시 읽기 비용이 75% 낮아, 긴 에이전트 작업에서 최대 약 45%까지 비용이 줄어듭니다.
  • 관리자는 조직 설정에서 쓸 수 있는 모델, effort 상한, 기본값을 정할 수 있습니다.

5. CLAUDE.md를 새 모델에 맞게 다듬기

CLAUDE.md와 스킬에 적어 둔 지침은 이전 모델 기준으로 쓰였을 수 있습니다. 명령 하나로 이 지침들을 Opus 5.5에 맞게 조정해, 모델을 바꾼 뒤에도 결과 품질을 유지할 수 있습니다.

  1. CLAUDE.md가 있는 프로젝트에서 Claude Code를 엽니다.
  2. /claude-api prompt-audit를 실행합니다.
  3. CLAUDE.md와 스킬의 지침이 Opus 5.5에 맞게 조정되었는지 확인합니다.
예시
/claude-api prompt-audit
  • API를 쓰지 않고 Claude Code만 써도 사용할 수 있습니다.

6. 사용 패턴으로 모드 추천받기

모드(Mods)는 Claude Code의 모습과 행동 방식을 바꾸는 작은 프로그램입니다. Claude가 작업할 때 나오는 신호를 듣고, 지켜보거나 살짝 고치거나 대신 처리합니다. 내 세션 로그를 분석시켜 흐름을 돕고 비용을 아껴 줄 모드를 추천받을 수 있습니다.

  1. Claude Code에서 세션 로그를 최대한 훑어 내가 자주 반복하는 말과 작업을 파악해 달라고 요청합니다.
  2. 흐름을 돕고 비용을 아끼며 집중하게 해 줄 모드 다섯 개를 추천해 달라고 요청합니다.
  3. 추천 목록과 함께 나온 패턴·근거를 읽어 봅니다.
  4. 마음에 드는 번호를 골라 그 모드를 만들어 달라고 요청합니다.
예시
내 Claude Code 세션 로그를 최대한 훑어서 내가 자주 반복하는 말과 작업을 파악해 줘. 그걸 바탕으로 흐름을 돕고, 비용을 아끼고, 집중하게 해 줄 모드 다섯 개를 근거와 함께 추천해 줘.
  • 스킬·MCP가 바깥에서 지식과 도구를 건네주는 방식이라면, 모드는 작업 환경 자체를 바꿉니다.
  • 창이나 버튼 같은 화면 요소는 모드로만 만들 수 있습니다.
  • 영상에서는 데스크톱 앱에서 토큰 사용량 표시, 다음 작업 추천 같은 모드도 만들어 봅니다.
