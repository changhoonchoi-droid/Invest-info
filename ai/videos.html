Claude Code 클라우드 세션으로 외출 중에도 코딩하기

Claude (공식) · 2026-10-13 · Claude Code 고급 · Claude Code 기본

노트북을 닫아도 계속 일하는 클라우드 세션을 설정하고 쓰는 법을 배웁니다.

요약·따라하기 보기

클라우드 세션은 내 컴퓨터가 아닌 클라우드의 가상 머신에서 실행되는 Claude Code 작업입니다. GitHub 저장소를 복제해 별도 브랜치에서 작업하므로 노트북을 닫아도 계속 진행되고, 휴대폰에서 질문에 답하거나 방향을 바꿀 수 있습니다. 여러 세션을 동시에 돌릴 수 있어 큰 리팩터링이나 마이그레이션, 퇴근 전 맡겨 두는 작업에 알맞습니다. 작업이 끝나면 변경 내용을 검토하고 PR을 만들 수 있습니다.

  • 클라우드 세션은 Pro, Max, Team 플랜과 프리미엄 좌석 또는 Chat + Claude Code 좌석의 Enterprise 사용자가 쓸 수 있습니다.
  • 플랜 한도에 로컬 세션과 함께 합산되며 가상 머신 비용은 따로 없습니다.
  • 데스크톱 앱, 브라우저, 터미널, 휴대폰, Slack에서 시작할 수 있습니다.
  • Remote Control은 내 컴퓨터에서 실행 중인 세션에 연결하는 방식이라 컴퓨터가 켜져 있어야 합니다.

클라우드 세션 시작하고 PR 만드는 법

  1. GitHub 계정을 연결하고 GitHub에서 접근을 승인합니다.
  2. Claude GitHub App을 설치하고 접근을 허용할 저장소를 고릅니다.
  3. 데스크톱 앱에서 Local 대신 Cloud를 선택합니다.
  4. 저장소, 환경, 시작할 브랜치를 고릅니다.
  5. Claude에게 작업을 맡기고 노트북을 닫습니다.
  6. 휴대폰 Claude 앱의 Code 탭에서 질문에 답하거나 방향을 조정합니다.
  7. 변경 내용(diff)을 검토합니다. 남긴 코멘트는 다음 메시지와 함께 Claude에게 전달됩니다.
  8. 문제가 없으면 Create PR을 눌러 GitHub에서 풀 리퀘스트를 엽니다.
  • 비공개 저장소는 Claude GitHub App이 접근할 수 있어야 목록에 나타납니다.
  • 세션은 저장소를 새로 복제해 시작하므로 커밋·푸시한 내용만 쓸 수 있습니다. 개인 설정, 스킬, 플러그인이 필요한 작업은 로컬에서 실행합니다.
  • 터미널에서 teleport 플래그를 붙여 claude를 실행하면 클라우드 세션을 내 컴퓨터로 가져와 이어갈 수 있습니다.

클라우드 세션 환경 맞춤 설정하는 법

  1. 기본 환경에는 주요 언어 런타임, 빌드 도구, 데이터베이스가 미리 설치되어 있음을 확인합니다.
  2. 더 필요하면 사용자 지정 환경을 만듭니다.
  3. 네트워크 접근 범위를 설정합니다.
  4. 환경 변수를 추가합니다.
  5. 저장소에 필요한 것을 설치하는 설정 스크립트를 작성합니다.
  • Team·Enterprise 플랜은 조직의 자체 인프라에서 클라우드 세션을 실행할 수 있습니다.

Claude Code Projects 시작하기

큰 목표를 맡기면 Claude가 스레드로 나눠 병렬로 처리하는 Projects 사용법.

요약·따라하기 보기

Claude Code의 Project는 Claude가 작업을 조율하는 하나의 지속적인 대화입니다. 작업마다 클라우드의 별도 브랜치에서 도는 스레드를 만들어 병렬로 처리하므로, 노트북을 닫아도 일이 계속되고 휴대폰으로 확인할 수 있습니다. 여러 세션이나 저장소에 걸친 큰 목표에 적합합니다. 풀 리퀘스트 검토, 아티팩트 생성, 외부 서비스 연결, 매일 도는 루틴 설정까지 한 프로젝트 안에서 할 수 있습니다. 현재 베타이며 Pro와 Max 요금제에 점진적으로 제공됩니다.

  • 스레드는 클라우드의 자체 브랜치에서 실행되는 독립 세션입니다.
  • library 탭은 아티팩트와 직접 추가한 파일(목업, 디자인 명세)을 모든 스레드가 공유하는 폴더입니다.
  • 코디네이터는 낮은 노력 수준으로 두고, 스레드는 작은 모델을 기본으로 쓰다 복잡한 작업에서만 바꾸는 것을 권장합니다.
  • 스레드는 메모리를 공유하며 프로젝트 설정에서 편집할 수 있습니다. Projects는 베타이며 Pro·Max에 순차 제공됩니다.

새 프로젝트를 만들어 작업 맡기는 법

  1. 데스크톱 앱 또는 웹 앱에서 Claude 탭을 엽니다.
  2. 새 프로젝트를 만들고 프로젝트 이름, Claude가 달성할 목표, 관련 저장소나 폴더를 입력합니다.
  3. 프로젝트가 만들어지면 열리는 메인 대화에서 코드베이스 탐색과 개선안 제안을 요청합니다.
  4. Claude가 찾은 내용을 보고 진행할 작업에 합의합니다.
  5. Claude가 작업마다 만든 스레드 카드를 눌러 진행 상황을 확인하고, 필요하면 스레드에서 말을 걸어 방향을 바꾸거나 중단합니다.
  6. threads 탭에서 사용자를 기다리는 스레드를 확인합니다.
  • 로컬 파일이나 도구가 필요한 작업은 해당 스레드를 내 컴퓨터에서 실행하도록 요청합니다.
  • 대부분은 스레드를 Claude에게 맡겨도 됩니다.

PR 검토와 매일 점검 루틴 설정하는 법

  1. 수정 사항이 준비된 스레드가 스스로, 또는 요청 시 풀 리퀘스트를 열게 합니다.
  2. 스레드가 PR을 계속 지켜보며 CI 실패 시 수정을 푸시하고 리뷰 코멘트를 반영하는 것을 확인합니다.
  3. overview의 pull requests 탭에서 모든 PR과 상태를 봅니다.
  4. 병합할 준비가 되면 Claude에게 병합을 요청합니다.
  5. 모니터링 서비스를 Claude에 연결해 실제 사용자 지표를 직접 확인하게 합니다.
  6. 매일 성능 저하를 점검하는 루틴을 만들어 달라고 요청합니다.
  • 루틴이 저하를 발견하면 조사 스레드를 열어 프로젝트에서 기다립니다.

  • Docs, Slides, Design은 모든 유료 요금제에서 쓸 수 있습니다.
  • Claude Docs에서는 코멘트에서 Claude를 멘션해 수정을 요청할 수 있습니다.

Claude Code 모드로 동작 바꾸기

Claude (공식) · 2026-10-05 · Claude Code 고급

모드(mod)로 Claude Code의 화면, 프롬프트, 도구 호출을 직접 바꾸는 법.

요약·따라하기 보기

모드는 Claude Code가 무엇을 그리고, 프롬프트에 무엇을 넣고, 어떤 도구를 호출하는지 바꾸는 함수입니다. 모드는 플러그인이며, hook.json에 modules 키를 추가해 TypeScript 파일을 가리키게 합니다. 이 파일의 함수를 Claude Code 내부 이벤트에 등록하면 Express의 미들웨어처럼 이벤트마다 실행됩니다. 영상은 마우스를 올릴 때만 이메일 주소를 보여 주는 모드를 처음부터 만듭니다.

  • 모드의 함수는 $send 객체(Claude Code와의 연결), 이벤트, next 세 값을 받습니다.
  • next에 넘긴 값이 Claude Code가 실제로 수행하는 내용이며, 호출하지 않고 반환하면 내가 이벤트를 처리합니다.
  • 모드는 자체 샌드박스에서 실행되고 Claude Code가 노출한 이벤트만 볼 수 있습니다.
  • 모드는 플러그인이라 마켓플레이스 저장소에 올려 공유할 수 있습니다.

이메일을 숨기는 모드 만드는 법

  1. 플러그인의 hook.json에 modules 키를 추가하고 TypeScript 파일을 가리키게 합니다.
  2. 그 파일에서 렌더 이벤트(render)에 함수를 등록합니다.
  3. 이벤트 데이터로 들어오는 답변 텍스트에서 이메일 주소를 찾습니다.
  4. 각 주소마다 $send 객체로 마우스를 올릴 때만 텍스트가 보이는 블록을 만듭니다.
  5. next를 호출하지 않고 그 결과를 직접 반환해 Claude Code가 내 버전을 그리게 합니다.
  6. plugin dir 플래그로 해당 폴더를 지정해 Claude Code를 시작하거나, 데스크톱 앱은 글로벌 설정 파일에 폴더를 추가합니다.
  • 폴더를 감시하므로 파일을 저장하면 현재 세션에 바로 반영됩니다.
  • 렌더 변경은 화면만 바꾸므로 모델은 실제 이메일 주소를 그대로 씁니다.

  • 잘 알려진 주제는 비교적 정확하고, 마이너한 세부 사항·최근 사건·비공개 정보는 틀리거나 지어낼 가능성이 높습니다.
  • AI는 자신의 불확실성을 항상 알려 주지 않으므로 판단은 사용자 몫입니다.

AI 답변을 검증하며 쓰는 법

  • 파티 주제 브레인스토밍은 검증할 필요가 적지만, 상사에게 보일 슬라이드의 통계는 반드시 검증합니다.
  • AI가 실제로 없는 출처를 그럴듯하게 만들어 낼 수도 있습니다.
  • 깔끔한 문단이나 그래픽 때문에 맞는 내용이라고 착각하지 않도록 주의합니다.
